AI Control & Sandbox Security

A research loop gives an agent a box, a key and a number to raise. This course is about the walls that keep that number honest: the evaluator outside the agent's write boundary, checker code the proposer never sees, tool results that are typed and signed so an agent cannot author a “tests passed” log, egress that is denied by default, and an offline monitor that reads what the loop did. These are the walls of Artifact 3, the evaluator-hardening kit. Its lab signs and monitors a small loop, its workbench locks one in a real sandbox on the lab VM, and its case study reads the July 2026 incident in which agents left an evaluation and reached Hugging Face.

How to use this course

🧱 Walls before watchers

Make cheating fail first (a separate evaluator, a deny-by-default network, signed results), then add monitoring to see who tried.

📓 Evidence the agent cannot write

Hash-chained logs, an anchor kept out of reach and an audit budget: how to know afterwards what a loop did and who should read it.

🔧 For Artifact 3

The lab builds the attested-result and monitor parts of the kit; the workbench puts a real research loop behind a separate user, a namespace sandbox and an allowlisting proxy, and times it.

Chapters are tagged Deep dive, Core or Quick intro so you know where to spend effort. The lab uses Python's standard library and fixture transcripts, so python3 check.py runs offline, for free, and gives the same answer every time. The workbench runs on the lab VM and needs no API calls.
