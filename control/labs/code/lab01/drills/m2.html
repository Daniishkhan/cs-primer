A signature is only as safe as its key, and a key in the same process as the code being scored can be read, used or bypassed by that code. So the evaluator runs as its own process and holds the key and the expected answers; the code under test sees only inputs, whatever it prints is data to ignore, and the verdict is a signed envelope.

run_evaluation is the harness's side of that conversation. Start the evaluator as a child process, send the request as JSON on its standard input, give it the key and nothing else in its environment, then verify reply["envelope"] with the sequence number you sent. A valid signature is not enough: a genuine signed pass for another task or source is a lie if accepted as the answer to this one, so compare the payload's task and solution_sha256 with what you sent. Never decide from diagnostics, which is unsigned.

signed reply says task t1000, you sent t1001            -> "task"
signed reply, right task, hash of some other source     -> "solution"
