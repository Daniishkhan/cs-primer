From Five Rides to a Learning Loop

Five real New York taxi rides and a guess at the fare. That is the whole starting point. Over twenty steps the guess becomes a model, the model learns its own knobs, the knobs are learnt by a gradient that an autograd engine you wrote computes, the model grows a hidden layer, and the program ends as a loop that proposes changes to itself, measures them honestly and keeps only the real improvements. Every step adds one function, written by you and checked on the real rides. Nothing is read in advance.

How a step works

🧱 The wall

Each step starts from the program as it stands and the real rides, and shows the one thing it cannot yet do, with a number.

✍️ Your move

One idea, then one function. You write it in the page; the checker runs it on the real rides and prints real numbers. A pass marks the step done.

📚 The library way

A collapsed box shows the same step in PyTorch, run on the lab machine, so the library is never a mystery: you built the thing it wraps.

The program is project.py, a single standard-library file that grows from 47 lines at step 1 to about 500 at step 20. Each step's file already contains every earlier step, written the reference way, so a slip never blocks you. Stuck on a step? Every one has hints and the solution behind a spoiler, and the courses below are the long version of each idea, linked from the step that needs them.

The data is rides.csv: 6,367 yellow-cab rides from March 2019, the seaborn sample of the public Taxi and Limousine Commission record, trimmed to pickup and dropoff times, passengers, distance, fare and borough. Browser Python is two to three times slower than python3, so every check is sized to finish in a few seconds in the page.
