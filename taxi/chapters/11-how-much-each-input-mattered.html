How Much Each Input Mattered

A Value knows what it was made from, but not how much each parent mattered. For every operation that is one small, exact number per parent: if this parent rises a little, how much does the result rise? Three short rules cover everything the leg builds.

Where we are

Step 10's check passed with 2 + 3 = 5 and 2 × 3 = 6, each remembering its parents, and relu(−2) = 0 and relu(1.5) = 1.5. Every Value now holds its data, its parents and its op, and its grad is still 0. Below is a stand-in for your class, with only the pieces the graph needs, building a * b + a at a = 2 and b = 3 and printing what each node remembers. Run it, then change 3.0 to 4.0 and run it again.

class Value:
    def __init__(self, data, parents=(), op=""):
        self.data, self.parents, self.op = data, parents, op

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), "+")

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), "*")


a, b = Value(2.0), Value(3.0)
product = a * b
out = product + a                              # a is used twice

The wall

The record says what out was made from, and nothing about how much each parent mattered. Step 7 needed exactly that for ride 4: the slope of its loss toward the per-mile knob was 2 × miss × 7.7, a factor of 2 × (−9.10) from the square multiplied by a factor of 7.7 from the product. Each factor is a fact about one operation, true wherever that operation appears, and the program has nowhere to keep it. Every operation needs a rule for how much its result moves when each of its parents does. Without one the program can describe a computation and still cannot differentiate it.

The idea

The local gradient of an operation toward one of its parents is how much the result moves for each unit that parent moves, with the other inputs held still. It is the slope of that one operation, ignoring the rest of the graph, and it is written with a curly d: ∂v/∂p for a Value v and its parent p. Each operation has a short rule.

∂(a + b) / ∂a = 1,     ∂(a · b) / ∂a = b

Addition passes a change straight through: slope 1 toward each side. A product moves by the other factor for each unit this one moves, so toward a the slope is b and toward b it is a. That is step 7's 7.7: the per-mile knob enters through the product 2.0 × 7.7, so its slope is the other factor. A square is a product of a number with itself, so both of its slopes are that number, and since they reach the same parent they add up to step 7's 2 × miss. relu either passes its input unchanged (slope 1, when the input is positive) or blocks it (slope 0, otherwise). Division, which the given __truediv__ builds from a product with a reciprocal, records the reciprocal as op "inv", and its slope is −1/x².

These are one-step slopes. Step 12 chains them, one operation at a time, into the slope of a whole result.

Your move

One function. Given a Value that an operation made, return its local gradients as a list, one per parent, in the order of v.parents. A leaf has no parents, so it returns an empty list.

def local_grads(v):
    """For a Value made by an operation, the derivative of v with respect
    to each parent, as a list in parent order:
      "+"    -> [1, 1]
      "*"    -> [other.data, self.data]  (each parent's partner)
      "relu" -> [1 if v.data > 0 else 0]
      "inv"  -> [-1 / parent.data ** 2]
    A Value with no parents (a leaf) returns []."""

Solution spoiler 
def local_grads(v):
    a = v.parents
    if v.op == "+":
        return [1.0, 1.0]
    if v.op == "*":
        return [a[1].data, a[0].data]
    if v.op == "relu":
        return [1.0 if v.data > 0 else 0.0]
    if v.op == "inv":
        return [-1.0 / a[0].data ** 2]
    return []

The library way

The same step in PyTorch run on the lab VM

torch.autograd.grad(output, inputs) returns the slope of one tensor toward others. Asked about one operation at a time, it returns that operation's local gradients: the numbers your function returns.

import torch


def local(fn, *inputs):
    """The slope of fn's result toward each input, at these input values."""
    xs = [torch.tensor(v, dtype=torch.float64, requires_grad=True)
          for v in inputs]
    grads = torch.autograd.grad(fn(*xs), xs)
    return [g.item() for g in grads]


print("a + b      at (2, 3):", local(lambda a, b: a + b, 2.0, 3.0))
print("a * b      at (2, 3):", local(lambda a, b: a * b, 2.0, 3.0))
print("relu(x)    at 1.5:   ", local(torch.relu, 1.5))
print("relu(x)    at -1.5:  ", local(torch.relu, -1.5))
print("relu(x)    at 0:     ", local(torch.relu, 0.0))
print("1 / x      at 4:     ", local(lambda x: 1 / x, 4.0))
a + b      at (2, 3): [1.0, 1.0]
a * b      at (2, 3): [3.0, 2.0]
relu(x)    at 1.5:    [1.0]
relu(x)    at -1.5:   [0.0]
relu(x)    at 0:      [0.0]
1 / x      at 4:      [-0.0625]

The same numbers: 1 and 1 for add, the partners 3 and 2 for multiply, 1 or 0 for relu, and −0.0625 for the reciprocal at 4, which is the −1/x² of your "inv" rule. At exactly 0 the library gives relu a slope of 0, the same choice as your v.data > 0. Every operation the library ships has a rule like these, written once by hand, and every gradient it computes is those rules chained together.

What you have now

  • local_grads(v): the slope of a Value's result toward each of its parents. Yours.

Every Value can now say how much it moves when each parent does: add gives 1 and 1, multiply gives the partners, relu gives 1 or 0. These are one-step slopes, and they say nothing yet about the slope of a final result toward an input many steps back. The long version of the idea is the courses' chapter on derivatives and the chain rule. Next step: chain the local slopes backwards through the graph, so every input learns its slope toward the result.
