A Small Network

A line charges the same for every minute. A network with one hidden layer can bend, so it can charge for minutes only when the cab is slow. It is built from the Values you already have, and has 21 knobs instead of three.

Where we are

Step 14 gave the line an honest score: 9.32 on the 1,274 held-out rides, a typical miss of about $3. On those rides the average of fare minus prediction was +0.42 for rides under five minutes and −0.20 for rides over thirty, so the line charged the short ones too little and the long ones too much. A line has three knobs, so the obvious next move is more knobs. Every model so far is one weighted sum, and nothing stops you feeding weighted sums into another weighted sum. Try it on ride 4, with made-up weights:

x = [1.0, 7.7, 25.9]                 # ride 4: the constant 1, miles, minutes
W1 = [[0.5, 0.2, 0.1],               # first layer: two weighted sums of x
      [0.0, 0.1, 0.3]]
W2 = [1.0, 2.0]                      # second layer: a weighted sum of those


def dot(a, b):
    return sum(p * q for p, q in zip(a, b))


hidden = [dot(row, x) for row in W1]
print(f"two layers of sums: {dot(W2, hidden):.2f}")

# One weighted sum, with the weights multiplied out, makes the same guess.
w = [W2[0] * W1[0][j] + W2[1] * W1[1][j] for j in range(3)]
print(f"one weighted sum:   {dot(w, x):.2f}")
print("its weights:", [round(v, 2) for v in w])
two layers of sums: 21.71
one weighted sum:   21.71
its weights: [0.5, 0.4, 0.7]

Change any weight in W1 or W2 and run it again. The two guesses always agree.

The wall

Two layers of weighted sums, and one line's worth of model: a single weighted sum with the weights [0.5, 0.4, 0.7] makes the same prediction as the pair. A weighted sum of weighted sums is a weighted sum, so ten layers fold into one line and more knobs buy nothing. A line charges the same for every extra minute whatever else is true of the ride, but the meter does not: step 2's rate card adds its 50 cents a minute only while the cab is stuck below 12 miles an hour. The held-out rides of step 14 hint at the same thing, with the line too low at one end and too high at the other. The model needs something between its weighted sums that is not itself a weighted sum: a bend.

The idea

The bend is step 10's relu: relu(z) = max(0, z). It passes positive numbers through and turns negative ones into zero, so its graph is flat, then rises, with a corner at zero. Value has had a relu method since step 10, but nothing has used it yet. Put one between two weighted sums and the stack no longer folds into a line. A hidden unit is a weighted sum of the ride's numbers followed by a relu. A hidden layer is several of them reading the same numbers with different weights, and the output is one more weighted sum of what they say:

h = relu(W1 x + b1),   f̂ = w2 · h + b2

Here x is the ride's three numbers and W1 holds one row of three weights per hidden unit. The bias b1 adds a knob to each unit's sum that moves where its bend sits; w2 and b2 turn the hidden values into a fare. Four hidden units give 12 + 4 + 4 + 1 = 21 knobs, which a network calls its parameters: a 3-4-1 network, for three numbers in, four hidden units, one number out.

What can a bend do for fares? Take the raw miles and minutes. A hidden unit with weights [0, −5, 1] computes max(0, minutes − 5 × miles): the minutes a ride took beyond what 12 miles an hour would take, and zero for any ride faster than that. That is the shape of the slow-traffic charge, and no line can make it. Training picks its own weights, so the network will not find that unit exactly, but the shape is available to it. Step 16 trains it.

Your move

One function. init_mlp and parameters are given: init_mlp(3, 4, 0) builds the 21 parameters of a 3-4-1 network as Values (small random weights from a seeded generator, zero biases) in a dict with the keys W1, b1, W2 and b2, and parameters flattens that dict into one list. You write mlp_forward: one ride in, one Value out.

def mlp_forward(x, params):
    """One ride through the network: for each hidden unit h, take
    dot(W1[h], x) + b1[h] and apply relu; the output is the dot of those
    hidden values with W2, plus b2. Returns a Value."""

Solution spoiler 
def mlp_forward(x, params):
    hidden = []
    for row, b in zip(params["W1"], params["b1"]):
        h = b
        for wj, xj in zip(row, x):
            h = h + wj * xj
        hidden.append(h.relu())
    out = params["b2"]
    for hv, wo in zip(hidden, params["W2"]):
        out = out + hv * wo
    return out

The library way

The same step in PyTorch run on the lab VM

In PyTorch the same network is nn.Sequential(nn.Linear(3, 4), nn.ReLU(), nn.Linear(4, 1)). The first layer holds your W1 and b1 as one (4, 3) weight matrix and one bias vector, nn.ReLU() is your .relu(), and the last layer holds W2 and b2. The library draws its own starting numbers, so the script loads the ones init_mlp(3, 4, 0) draws, to make the two comparable.

import random

import torch
from torch import nn

torch.manual_seed(0)
net = nn.Sequential(nn.Linear(3, 4), nn.ReLU(), nn.Linear(4, 1)).double()
print("parameters:", sum(p.numel() for p in net.parameters()))
for name, p in net.named_parameters():
    print(f"  {name:9s} shape {tuple(p.shape)}")

# Start where init_mlp(3, 4, 0) starts, so both networks hold the same numbers.
rng, s = random.Random(0), 3 ** -0.5          # s is 1 / sqrt(3)
with torch.no_grad():
    for layer in (net[0], net[2]):
        w = layer.weight
        w.copy_(torch.tensor([[rng.uniform(-s, s) for _ in w[0]] for _ in w]))
        layer.bias.zero_()

x = torch.tensor([1.0, 0.5, -0.5], dtype=torch.float64)    # one ride
out = net(x)
out.backward()
print(f"one ride through the network: {out.item():.4f}")
print("gradients filled in:", sum(p.grad.numel() for p in net.parameters()))
parameters: 21
  0.weight  shape (4, 3)
  0.bias    shape (4,)
  2.weight  shape (1, 4)
  2.bias    shape (1,)
one ride through the network: -0.2130
gradients filled in: 21

The count is 21, as in your network, and the ride gives −0.2130, the number your check printed: the same weights in, the same number out. The library stores the weights as matrices, runs your two loops as two matrix products and a bend, and fills .grad on all 21 parameters with one .backward().

What you have now

  • init_mlp(d_in, hidden, seed): the parameters of a one-hidden-layer network, as Values in a dict. Given.
  • mlp_forward(x, params): one ride through the network: a weighted sum and a relu per hidden unit, then a weighted sum of those. Yours.
  • parameters(params): every parameter Value as one flat list. Given.

A 3-4-1 network on one ride gives −0.2130, and backward fills the gradient of all 21 parameters. The number means nothing yet, since the weights are random: the network cannot be judged until it is trained.
