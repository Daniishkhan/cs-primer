The Linear Model, Rebuilt on Value

Step 7 found the slope of the loss with a formula you derived by hand for one model. Build the loss out of Values instead and backward finds the same slope with no derivation, for any model written the same way.

Where we are

Two machines have been built, and they have never met. Step 7's grad_mse_linear is an exact, cheap formula for the slope of the loss, for a weighted sum scored by mean squared error and nothing else. Steps 10 to 12 built Value and backward, which find the slope of anything made from Values, but so far only on small expressions such as (w0 w1 + w0)(w0 − 1), where autograd and nudging both gave −0.120000. Here is the formula on the five rides at step 4's knobs, first for ride 4 alone, then for all five.

RIDES5 = [(1.60, 6.2, 1, 7.0), (0.79, 7.1, 1, 5.0), (1.37, 7.4, 1, 7.5),
          (7.70, 25.9, 1, 27.0), (2.16, 9.5, 3, 9.0)]
w = [2.5, 2.0, 0.0]                  # base, per mile, per minute


def hand_gradient(rides, w):
    """Step 7's formula on plain floats: (2/n) * sum of miss * x."""
    grad = [0.0, 0.0, 0.0]
    for d, m, _, fare in rides:
        x = [1.0, d, m]
        miss = sum(a * b for a, b in zip(x, w)) - fare
        for j in range(3):
            grad[j] += 2 * miss * x[j] / len(rides)
    return grad


print("ride 4 alone:", [round(g, 2) for g in hand_gradient(RIDES5[3:4], w)])
print("five rides:  ", [round(g, 3) for g in hand_gradient(RIDES5, w)])
ride 4 alone: [-18.2, -140.14, -471.38]
five rides:   [-6.304, -32.273, -115.086]

Each number is the slope of the loss along one knob. All are negative, so raising any knob lowers the loss: every guess is too low. Change 2.0 to 3.0 and run it again: the five-ride gradient shrinks, because the guess is now close.

The wall

The formula works, and it is no use for the next step. It was derived for one model, a weighted sum, and one loss, and every other model needs its own derivation: the network of step 15 has 21 knobs and a bend. backward works for any model made of Values, but loss(X, y, w) hands it nothing to work with. matvec and mse compute on plain floats, w is a list of floats, and a float does not remember how it was made. The five-ride numbers above came out of a formula; there is no way yet to get them out of backward. The gradient has to come out of the code that computes the loss, not out of a derivation written beside it.

The idea

Run step 4's computation again with one change: the weights are Values, and the data stay plain numbers. Every + and * on a Value records itself as it runs, so by the time the loss exists, the chain from each weight to the loss exists with it. Running the loss is the forward pass, from the weights up to the loss; backward is the pass in reverse. For weight wj it finds one path per ride, and along each path the local gradients of step 11 multiply:

∂L / ∂wj = ∑i (1 / n) · 2di · xij

Here di is the miss on ride i (guess minus fare) and xij is that ride's j-th number. Going back from the loss, the gradient is multiplied by 1/n at the mean, by 2di at the square and by xij at the product with the data; the sums and the subtraction pass it through unchanged, and the paths of the different rides add. That is step 7's formula, term by term, and this time nobody wrote it down: backward found it, and would find the matching one for any model built the same way. Steps 15 and 16 lean on exactly that.

Solution spoiler 
def mse_value(X, y, w):
    total = Value(0.0)
    for row, t in zip(X, y):
        pred = Value(0.0)
        for xj, wj in zip(row, w):
            pred = pred + wj * xj
        diff = pred - t
        total = total + diff * diff
    return total * (1.0 / len(y))

The library way

The same step in PyTorch run on the lab VM

PyTorch tensors record how they were made, as your Values do. Set requires_grad=True on the weights, compute the loss with ordinary tensor expressions, and .backward() fills in w.grad. The record is grad_fn, the library's version of your op and parents. The last line below is step 7's formula as one matrix product.

import torch
from common import design_matrix, load_rides, targets

rides = load_rides()[:200]                  # the same 200 rides as the check
X, y = design_matrix(rides), targets(rides)

w = torch.tensor([2.5, 2.0, 0.0], dtype=torch.float64, requires_grad=True)
loss = ((X @ w - y) ** 2).mean()            # built from tensors that remember
loss.backward()                             # walk the graph in reverse
print(f"loss {loss.item():.2f}; the last operation recorded: "
      f"{type(loss.grad_fn).__name__}")
print("autograd gradient:", [round(g, 4) for g in w.grad.tolist()])

with torch.no_grad():
    hand = 2 * X.T @ (X @ w - y) / len(y)   # step 7's formula, one product
print("hand gradient:    ", [round(g, 4) for g in hand.tolist()])
loss 27.28; the last operation recorded: MeanBackward0
autograd gradient: [-8.2595, -39.1502, -178.327]
hand gradient:     [-8.2595, -39.1502, -178.327]

The same three numbers, from a loss written as one line with no loop and no derivation. The library recorded the graph while the loss ran and walked it backwards when asked. Its graph is also far smaller than yours: you hold a Value for every number that went through the loss, the library one node for each whole-array operation (a product, a subtraction, a square, a mean). That is why a loss over a million rides is no harder to write than one over five.

What you have now

  • mse_value(X, y, w): step 4's loss built from Values, so backward can reach every weight. Yours.
  • grad_by_autograd(X, y, w): the gradient of the loss at w, by building the graph and calling backward. Given.

On 200 rides at w = [2.5, 2.0, 0.0] autograd and the hand formula both give [−8.2595, −39.1502, −178.327], so the engine of steps 10 to 12 is right, and the gradient of anything built from Values is now one call away.
