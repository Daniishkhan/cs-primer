Many Rides Are a Matrix

Five rides is a toy. The file has 6,367. Predict them all at once by stacking the rides as the rows of a matrix, and meet the shape: the one thing every tensor library checks before it does anything.

Where we are

Three given functions open the file. load_rides reads rides.csv and turns each row into the same tuple as RIDES5, computing the minutes from the pickup and dropoff timestamps (so ride 1 is 6.25 minutes here; RIDES5 rounded it to 6.2). design_matrix calls features on every ride and collects the results: one row per ride, three numbers per row. targets collects the fares. The first three rows, by hand:

RIDES3 = [(1.60, 6.2, 1, 7.0), (0.79, 7.1, 1, 5.0), (1.37, 7.4, 1, 7.5)]

X = [[1.0, d, m] for d, m, _, _ in RIDES3]   # one row per ride
w = [2.5, 2.0, 0.0]                           # base, per mile, per minute

print("X has", len(X), "rows of", len(X[0]), "numbers; w has", len(w))
for row in X:
    print(row, "->", sum(a * b for a, b in zip(row, w)))

The wall

predict handles one ride. The leg needs every ride's prediction, again and again: to score the knobs in step 4, to find the slope in step 7, and at every one of the hundreds of steps of training in step 8. Looping over rides each time would work, and in Python it is what you will write. But the thing being computed deserves a name and a shape, because the shape is what every library checks and what every error message is about. Once you can say "X is 6,367 by 3 and w has length 3, so the predictions have length 6,367", you can read any tensor code in any library.

The idea

A matrix is a list of rows, every row the same length. Stacking the rides gives X with shape (6367, 3): 6,367 rows, 3 columns. The matrix-vector product X w is one dot product per row:

(X w)i = xi · w = ∑ Xij wj, and (n, d) @ (d,) → (n,)

Read the shape rule on the right as a contract: a matrix with n rows and d columns, times a vector of length d, gives a vector of length n. The inner d must match (that is dot's length check, once per row) and the outer n survives. A tensor is exactly this idea generalised: an array of numbers with a shape, and operations that check shapes before they compute. A vector is a tensor with one dimension, a matrix has two, and a batch of images has four.

The library way

The same step in PyTorch run on the lab VM

The same three given functions, returning tensors instead of lists, and then X @ w is your matvec. The library prints shapes as tuples, which is the contract above written down, and its error for a mismatched w names the three shapes involved.

import torch
from common import design_matrix, load_rides, targets

rides = load_rides()
X, y = design_matrix(rides), targets(rides)
print("X.shape =", tuple(X.shape), " y.shape =", tuple(y.shape))
print("first three rows of X:\n", X[:3])

w = torch.tensor([2.5, 2.0, 0.0], dtype=torch.float64)
pred = X @ w                                    # (6367, 3) @ (3,) -> (6367,)
print("pred.shape =", tuple(pred.shape))
print(f"first prediction ${pred[0]:.2f}; mean predicted ${pred.mean():.2f}; real mean ${y.mean():.2f}")
try:
    X @ torch.tensor([2.5, 2.0])
except RuntimeError as e:
    print("shape error:", str(e).splitlines()[0])

On the lab VM this product over 6,367 rides takes microseconds; your list comprehension takes a few milliseconds. The gap is why the loop lives inside the library, and why the shapes have to be right before it runs: compiled code cannot stop halfway to ask.

What you have now

  • load_rides(path): the file as a list of ride tuples. Given.
  • design_matrix(rides): the rides as X, shape (n, 3). Given.
  • targets(rides): the fares as y, length n. Given.
  • matvec(X, w): every prediction at once. Yours.

The numbers the check printed are the first real result of the leg: with step 1's knobs the model predicts a mean fare of $8.60 and the real mean is $13.03. The knobs are wrong, and now there are 6,367 rides to say exactly how wrong. The long version of the shape rule is the courses' chapter on matrices as functions.
