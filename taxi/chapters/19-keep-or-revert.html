Keep or Revert

A search that keeps whatever scores lower keeps luck as often as ideas. The fix is one comparison with a margin: keep a candidate only if it beats the best by more than the noise floor, and otherwise leave the best alone.

Where we are

After step 18 a run is a line in a file and the noise floor is a number: the linear model's held-out loss moves by 0.58 on its own (step 17), and two runs of one configuration sit under one hash (step 18). What the program cannot do is decide. Here is the rule everyone writes first, applied to step 17's five runs. The best so far starts as seed 0, and each later run is kept if its held-out loss is lower. Run it, then change held < best to held < best - 0.82 and run it again.

# held-out losses of step 17's five runs: one recipe, seeds 0 to 4
LOSSES = [1.08, 0.36, 2.06, 0.79, 1.45]

best = LOSSES[0]                      # the first run is the best so far
for seed, held in enumerate(LOSSES[1:], start=1):
    if held < best:
        print(f"seed {seed}: {held:.2f} beats {best:.2f} "
              f"by {best - held:.2f}: keep")
        best = held
    else:
        print(f"seed {seed}: {held:.2f} does not beat {best:.2f}: revert")

The wall

Every line above is the same recipe on a different shuffle, and the rule still reports an improvement: seed 1 "beats" seed 0 by 0.72, which is more than step 17's whole spread of 0.58. Worse, the bar is now 0.36, a lucky number that an honest run of this recipe will seldom reach again, so a real improvement could be turned away later. A research loop makes this decision about a hundred times a night. You need a rule for “better” that a lucky run cannot pass.

The idea

Keep a candidate only if its loss is below the best's loss minus the floor, the margin it has to clear. Otherwise revert: throw the candidate away and carry on with the best. A tie is a revert, and so is any gain smaller than the floor.

keep ⇔ Lcand < Lbest − f

Here L is the held-out loss and f is the floor. The floor comes from step 17, and it is a dial. The smallest sensible setting is the spread itself, 0.58. But a gain is the difference of two runs, both noisy, so it wobbles about √2 times as much as one run: 0.58 × 1.41 is 0.82, the number in the edit above. The research course's lab goes further and asks for 1.96 times that, about 1.6: a gap that two runs of the same recipe exceed one time in twenty. A higher floor keeps less luck and throws away more real gains. Choose it before the loop runs, not after. Step 20 calls the rule once for every candidate.

Your move

One function. A run is the dict that log_run returns. What matters here is its "held" score, and lower is better.

def keep_or_revert(best, candidate, floor):
    """Decide whether a candidate run replaces the best so far. Lower
    held-out score is better. Keep the candidate only if it beats the
    best by more than `floor` (the noise); otherwise keep the best.
    Returns (winner, kept) where kept is True when the candidate won."""

def keep_or_revert(best, candidate, floor):
    if candidate["held"] < best["held"] - floor:
        return candidate, True
    return best, False

The library way

The real thing how Artifact 1's loop decides

autoresearch's own rule is the bare one: if val_bpb went down, keep the commit and advance the branch, and if it is equal or higher, reset to where the branch started. Chapter 1 of the research course names the weak point. The rule compares two noisy numbers, so when the true change is zero, half of all candidates beat the baseline by luck at the first comparison, and the bar then moves to the lucky value. That is the cell at the top of this page.

Artifact 1 replaces the single comparison with a paired test, built in Lab 1. The best and the candidate run on the same seeds, and the candidate is kept only if the mean gain over seeds is positive and its t statistic clears the critical value of Student's t (2.776 for five seeds). Pairing cancels the luck that both runs of a seed share: the lab's check keeps a change with no effect 2.5% of the time, against 48% on a single comparison. The decision uses the proxy score only, and the held-out score is logged and never decides. Your floor is the cheap version of the same idea. The lab keeps the noise floor too, as the yardstick for whether a significant change is worth keeping.

What you have now

  • keep_or_revert(best, candidate, floor): keep the candidate only if it beats the best by more than the floor, otherwise keep the best. Yours.

One rule now says whether a run counts as progress: 29.0 beats 30.0 and is kept at a floor of 0.5, and is reverted at a floor of 1.5.
