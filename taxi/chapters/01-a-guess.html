A Guess, and How Wrong It Is

Five real taxi rides, each with the fare the meter charged. Before any mathematics: guess the fare from the distance, and put one number on how wrong the guess is. That number is what the next nineteen steps drive down.

The rides

These are the first five rides in rides.csv: 6,367 yellow-cab rides from March 2019, the seaborn sample of the public record kept by New York's Taxi and Limousine Commission. Distance is in miles, time is the minutes between pickup and dropoff, and the fare is what the meter showed, before tips and tolls.

A fare guess needs two numbers: what the meter shows before the car moves (the flag-drop, called the base from here on) and what it adds for every mile. Try a base of $2.50 and $2.00 a mile. The script prints each ride's guess, the fare, and the miss. Run it, then change 2.0 to 3.0 and run it again.

RIDES5 = [            # distance, minutes, passengers, fare
    (1.60, 6.2, 1, 7.0),
    (0.79, 7.1, 1, 5.0),
    (1.37, 7.4, 1, 7.5),
    (7.70, 25.9, 1, 27.0),
    (2.16, 9.5, 3, 9.0),
]
BASE, PER_MILE = 2.5, 2.0

total = 0.0
for d, m, p, fare in RIDES5:
    guess = BASE + PER_MILE * d
    miss = abs(guess - fare)
    total += miss
    print(f"{d:5.2f} miles {m:5.1f} min  guess ${guess:5.2f}  "
          f"meter ${fare:5.2f}  miss ${miss:4.2f}")
print(f"total miss ${total:.2f}")

The wall

Every guess is too low, and ride 4 is $9.10 short. So $2.00 a mile is too cheap. Is $3.00 right? $2.80? Ride 2 wants about $3.16 a mile, ride 4 about $3.18, ride 1 about $2.81: each ride argues for its own price, and five rides give five arguments. Nothing can improve until "better" means something. You need one number for how wrong a guess is over all the rides, so that two guesses can be compared and the better one kept. Everything that follows, from the training loop of step 8 to the search of step 20, is a way of driving one such number down.

The idea

Add up the misses. For each ride take the guess minus the fare, drop the sign (a $2 overcharge is as wrong as a $2 undercharge), and sum over the rides:

E(b, m) = ∑ | b + m di − fi |

Here b is the base, m the price per mile, di the distance of ride i and fi its fare. E is zero only when every ride is predicted exactly, and it grows with every dollar of error. For the guess above it is $15.76. Change m to $3.00 and it drops to $2.74: a better guess, decided by one number, no argument. Step 4 swaps the absolute value for a square, for a reason that needs the slope of step 6; the shape of the idea stays the same.

Your move

Two functions. The first turns the base and the price per mile into a guess for one ride. The second adds up the misses over a list of rides, where each ride is a tuple of distance, minutes, passengers and fare, in that order.

def total_error(rides, base, per_mile):
    return sum(abs(guess(d, base, per_mile) - fare) for d, _, _, fare in rides)

The library way

The same step in PyTorch run on the lab VM

PyTorch does the arithmetic you did, on all five rides at once. The five rides become one tensor: a table of numbers with a shape, here 5 rows by 4 columns. Picking a column gives five distances, and 2.5 + 2.0 * distance computes five guesses in one expression. The absolute value and the sum are each one call. The next two steps build exactly this: a ride as a vector, the rides as a matrix.

import torch
from common import RIDES5

rides = torch.tensor(RIDES5)          # shape (5, 4): one row per ride
distance, fare = rides[:, 0], rides[:, 3]
print("distance:", distance)
print("fare:    ", fare)

for per_mile in (2.0, 3.0):
    guess = 2.5 + per_mile * distance   # five guesses at once
    total_error = (guess - fare).abs().sum()
    print(f"$2.50 + ${per_mile:.2f} a mile: total error ${total_error:.2f}")
distance: tensor([1.6000, 0.7900, 1.3700, 7.7000, 2.1600])
fare:     tensor([ 7.0000,  5.0000,  7.5000, 27.0000,  9.0000])
$2.50 + $2.00 a mile: total error $15.76
$2.50 + $3.00 a mile: total error $2.74

Same numbers, no loop. The loop did not disappear: it moved into compiled code inside the library, which is why the same line would be as short for six million rides as for five.

What you have now

  • RIDES5: five real rides as tuples.
  • guess(distance, base, per_mile): a fare from a distance and two knobs. Yours.
  • total_error(rides, base, per_mile): one number for how wrong the knobs are. Yours.

A guess with two knobs and a score that says how wrong it is. Ride 4, the slow 25.9-minute one, is still the big miss, and distance alone cannot fix it: the meter charges for time in traffic as well as for miles. Next step: a ride as a list of numbers, so the guess can read minutes too.
