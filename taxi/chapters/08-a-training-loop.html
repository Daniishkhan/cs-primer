A Training Loop

A gradient and a step, over and over, with the loss written down before each step: that is a training loop. On 500 real rides it takes the loss from 239.2 to 9.0 in 200 steps. Make the learning rate a hundred times bigger and the same loop explodes.

Where we are

Step 7 gave the program an exact gradient: on 500 rides at w = [2.5, 2.0, 0.0] it is [−8.027, −39.779, −171.253], the same as nudging gave. With step 6's gd_step that makes one step downhill, and a loop is that pair repeated. Here it is by hand on the five rides, from all-zero knobs, printing the loss before each step. Run it, then change the learning rate 0.001 to 0.01 and run it again.

RIDES5 = [            # distance, minutes, passengers, fare
    (1.60, 6.2, 1, 7.0),
    (0.79, 7.1, 1, 5.0),
    (1.37, 7.4, 1, 7.5),
    (7.70, 25.9, 1, 27.0),
    (2.16, 9.5, 3, 9.0),
]
X = [[1.0, d, m] for d, m, _, _ in RIDES5]     # one row per ride
y = [fare for _, _, _, fare in RIDES5]

def predictions(w):
    return [sum(a * b for a, b in zip(row, w)) for row in X]

def loss(w):
    return sum((p - t) ** 2 for p, t in zip(predictions(w), y)) / len(y)

def gradient(w):                               # step 7's formula
    g = [0.0] * len(w)
    for row, p, t in zip(X, predictions(w), y):
        for j, xj in enumerate(row):
            g[j] += 2 * (p - t) * xj / len(y)
    return g

w, lr = [0.0, 0.0, 0.0], 0.001
for step in range(8):
    print(f"step {step}: loss {loss(w):12,.1f}")
    w = [wi - lr * gi for wi, gi in zip(w, gradient(w))]    # step 6's step
print(f"after 8 steps: loss {loss(w):,.2f}")

The wall

Step 6's walk used a learning rate of 0.1 and landed on the bottom of the bowl. The edit above sets the rate to 0.01, ten times the cell's, and on five rides the loss grows about eightfold at every step. On the real rides, a tenth of the bowl's rate is already too big: the check below runs 0.01, and the loss reaches 3.68e+28 by step 20. A learning rate that suits one problem breaks another, and the quickest way to find out is to watch the loss. You need the pair repeated inside a function that writes down the loss before every step, so that falling, flat and exploding can be told apart at a glance.

The idea

A training loop is two lines repeated: take the gradient at the current weights, then step against it with gd_step. Write the loss down before each step. That list is the training curve: falling means learning, flat means done or stuck, and rising means the learning rate is too big.

The learning rate decides which. Near the bottom the loss is a bowl, and along each direction of it one step multiplies the distance to the bottom by 1 − lr × λ, where λ is the sharpness of the bowl in that direction:

dt+1 = (1 − lr · λ) dt

Here d is the distance to the bottom along that direction and t counts the steps. Check it on step 6's bowl. At lr = 0.1 the first step went from (0, 0) to (0.6, −0.4), so the distance to the bottom at (3, −1) went from 3 to 2.4 along w0 and from 1 to 0.6 along w1. Those are factors of 0.8 and 0.6, which is 1 − 0.1 × 2 and 1 − 0.1 × 4: the sharpness λ is 2 along w0 and 4 along w1. A factor between 0 and 1 glides in. A factor between −1 and 0 overshoots but still closes in. Below −1 each overshoot is bigger than the last, the loss grows, and the loop diverges. That happens when lr is above 2 / λ for the sharpest direction.

On the real rides the sharpest direction is mostly the minutes weight, because minutes are the biggest numbers in the data, and it caps the rate for all three weights. Step 9 puts the columns on one scale so that one rate suits all three.

The library way

The same step in PyTorch run on the lab VM

An optimiser holds the weights and updates them from their gradients, and torch.optim.SGD is the plain one: opt.step() is your gd_step. A PyTorch training loop is these lines in this order. Compute the loss and write it down. Clear the old gradient with zero_grad(), because backward() adds to w.grad instead of replacing it. Call backward(), then step().

import torch
import torch.nn.functional as F
from common import design_matrix, load_rides, targets

rides = load_rides()[:500]                 # the same 500 rides as the check
X, y = design_matrix(rides), targets(rides)

def train(lr, steps):
    w = torch.zeros(3, dtype=torch.float64, requires_grad=True)
    opt = torch.optim.SGD([w], lr=lr)
    losses = []
    for _ in range(steps):
        loss = F.mse_loss(X @ w, y)        # the loss at the current w
        losses.append(loss.item())         # written down before the step
        opt.zero_grad()                    # forget the last step's slope
        loss.backward()                    # the exact gradient, in w.grad
        opt.step()                         # w <- w - lr * w.grad
    return losses

def show(x):                               # 239.2, 9.0 or 3.68e+28
    return f"{x:.1f}" if x < 1000 else f"{x:.3g}"

for lr, steps in ((1e-4, 200), (1e-2, 20)):
    losses = train(lr, steps)
    print(f"lr {lr}: loss {show(losses[0])} -> {show(losses[-1])}"
          f" by step {steps}")
lr 0.0001: loss 239.2 -> 9.0 by step 200
lr 0.01: loss 239.2 -> 3.68e+28 by step 20

Both lines match the check: 239.2 to 9.0 by step 200 at the small rate, and 239.2 to 3.68e+28 by step 20 at the large one. The library supplied the gradient and the update. The loop itself, and the choice of learning rate, are still yours.
