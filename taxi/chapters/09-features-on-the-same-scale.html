Features on the Same Scale

Step 8's loop stays alive only with a tiny learning rate, and then it crawls. The columns are the trouble: miles and minutes sit on different scales, so no single learning rate suits both. Put every feature on one scale first, and a rate a thousand times larger converges.

Where we are

Step 8's loop works on the first 500 rides at a learning rate of 0.0001: the loss falls from 239.2 to 9.0 in 200 steps, and is still falling. At 0.01 it explodes to 3.68e+28 within 20 steps. Step 8 explained why: a step overshoots once the learning rate passes 2 divided by the sharpness of the loss along its sharpest direction. Below is that sharpness along each of the three knobs on the five rides, with the biggest rate each knob could take if it were the only one moving. Run it, then change [1.0, d, m] to [1.0, d, m / 10], which counts minutes in tens of minutes, and run it again.

X = [[1.0, d, m] for d, m, _, _ in RIDES5]   # constant, miles, minutes

print("knob        sharpness   biggest safe rate")

    # how sharply the loss curves along this knob: (2 / n) * sum of x_j^2
    sharpness = 2 * sum(row[j] ** 2 for row in X) / n
    print(f"{name:<10} {sharpness:10.1f} {2 / sharpness:19.4f}")

The wall

The three limits are far apart, and they follow the units: count minutes in tens of minutes and the minutes limit stops being the smallest. The reason is the size of the feature each knob multiplies. The base multiplies a 1, and the price per minute multiplies numbers up to 25.9: nudge each knob by 0.1 and ride 4's guess moves by $0.10, $0.77 and $2.59. A learning rate is one number, so it must stay under the smallest limit, 0.0055 on these rides, while the base could take one about 180 times bigger. That is step 8 on the real rides: 0.01 explodes, and 0.0001 is safe but crawls. One learning rate can suit every knob only if every feature arrives on the same scale.

The idea

Give every feature, every column of X, the same scale before the loop sees it. Subtract the column's mean so it is centred on 0, then divide by its standard deviation, the typical distance of a value from the mean, so that a typical value lands about 1 away from 0. That is called standardising the column. For feature j of ride i:

zij = (xij − μj) / σj,   σj = √( (1 / n) ∑ (xij − μj)2 )

Here z is the standardised value, x the raw one, μ the column's mean and σ its standard deviation: the square root of the average squared distance from the mean, in the column's own units. Divide by n, the number of rides, not by n − 1; the check wants that version. Every column ends with mean 0 and standard deviation 1, whatever it was measured in, so a nudge to any knob moves the guesses by a comparable amount and one learning rate can suit all three.

The constant 1 is the exception: its standard deviation is 0, so dividing by it would fail, and it needs no scaling. standardise gives that column a mean of 0 and a standard deviation of 1, so the same formula leaves it alone. It also returns the means and standard deviations it used, because a ride the model meets later must be scaled by the same numbers. Every model from here on trains on standardised features: the fits of step 14, the network of step 16 and the search of step 20.

Your move

One function: take the design matrix of step 3 and return the standardised matrix, with the means and standard deviations it used.

def standardise(X):
    """Put every feature column except the first (the constant 1) on the
    same scale: subtract the column's mean, divide by its standard
    deviation (the population one: divide by n, not n - 1). Returns
    (new matrix, means, stds); means[0] is 0 and stds[0] is 1 so the
    constant column is untouched."""

def standardise(X):
    n, d = len(X), len(X[0])
    means = [0.0] + [sum(row[j] for row in X) / n for j in range(1, d)]
    stds = [1.0] + [math.sqrt(sum((row[j] - means[j]) ** 2 for row in X) / n)
                    for j in range(1, d)]
    Xs = [[(row[j] - means[j]) / stds[j] for j in range(d)] for row in X]
    return Xs, means, stds

The library way

The same step in PyTorch run on the lab VM

A tensor's mean and std take the dimension to work along, and 0 is down each column. Subtracting a vector of three numbers from a matrix of 500 rows subtracts it from every row: the broadcasting of step 5. Its std divides by n − 1 unless you pass unbiased=False. The loop is step 8's, with torch.optim.SGD taking the step.

import torch
import torch.nn.functional as F
from common import design_matrix, load_rides, targets

rides = load_rides()[:500]                 # the check's first 500 rides
X, y = design_matrix(rides), targets(rides)

mean = X.mean(0)                           # one number per column
std = X.std(0, unbiased=False)             # divide by n, as the check does
mean[0], std[0] = 0.0, 1.0                 # leave the constant column alone
Z = (X - mean) / std                       # (500, 3) minus (3,): every row
print("means:", [round(v, 2) for v in mean.tolist()])
print("stds: ", [round(v, 2) for v in std.tolist()])

w = torch.zeros(3, dtype=torch.float64, requires_grad=True)
opt = torch.optim.SGD([w], lr=0.1)
losses = []
for _ in range(200):
    loss = F.mse_loss(Z @ w, y)
    losses.append(loss.item())             # the loss before this step
    opt.zero_grad()                        # backward adds into .grad
    loss.backward()
    opt.step()
print(f"lr 0.1: loss {losses[0]:.1f} -> {losses[-1]:.1f} in 200 steps")
print(f"base      ${w[0]:.2f}  (the mean fare is ${y.mean():.2f})")
print(f"distance  ${w[1]:.2f} per standard deviation ({std[1]:.2f} miles)")
print(f"time      ${w[2]:.2f} per standard deviation ({std[2]:.1f} minutes)")
print(f"in raw units: ${w[1] / std[1]:.2f} a mile, "
      f"${w[2] / std[2]:.2f} a minute")
