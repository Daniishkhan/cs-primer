The Loss Surface

Turn one knob and the loss moves. Draw the loss against that knob and you get a curve with a bottom, and the bottom is the best setting. This step builds the function that gives the curve's points, and sets the job of every step after it: find the bottom.

Where we are

Step 4 left the program able to score any knobs with one number. On all 6,367 rides, with a $2.50 base and nothing per minute, $2.00 a mile scores 41.13 and $2.50 a mile scores 21.84. Lower is better, so the price should go up, but how far? Here is the question on the five rides, with the price per mile turned by hand: run it, then add 3.2 to the list of prices and run it again.

RIDES5 = [            # distance, minutes, passengers, fare
    (1.60, 6.2, 1, 7.0),
    (0.79, 7.1, 1, 5.0),
    (1.37, 7.4, 1, 7.5),
    (7.70, 25.9, 1, 27.0),
    (2.16, 9.5, 3, 9.0),
]

def loss5(base, per_mile, per_minute):
    """Mean squared miss of the three-knob guess over the five rides."""
    total = 0.0
    for d, m, _, fare in RIDES5:
        miss = base + per_mile * d + per_minute * m - fare
        total += miss ** 2
    return total / len(RIDES5)

# Turn one knob, the price per mile, and hold the other two still.
for per_mile in (2.0, 2.5, 3.0, 3.5, 4.0):
    print(f"${per_mile:.2f} a mile: loss {loss5(2.5, per_mile, 0.0):6.2f}")

The wall

That loop is welded to five rides and one knob. Every step from here needs the same table for any knob, on any rides, with the other knobs wherever they happen to be. And one table does not settle the question. On the real rides $2.00 a mile scored 41.13 and $2.50 scored 21.84, which says "go up" and nothing about how far, while the table above shows what happens when you go too far. What you need is the loss at as many values of a knob as you like, on any rides, without rewriting the loop.

The idea

Let one knob run and hold the rest still. The loss becomes a function of one number, and a function of one number can be drawn: the loss curve of that knob. With m the price per mile that runs, b the base, p the price per minute, di, ti and fi the distance, minutes and fare of ride i, and n the number of rides:

L(m) = (1 / n) ∑ (b + m di + p ti − fi)2

Each miss is a straight line in m, and squaring a straight line gives a parabola, a cup-shaped curve. The average of such cups is a cup too, so the curve falls to one lowest point and rises again, with no other dips. That point is the best price per mile for the other two knobs as they stand.

Let two knobs run and the loss is a height above a plane, like the ground on a map; here it is one smooth bowl. Let all three run and it is the same landscape in a space you cannot draw. That landscape is the loss surface, and the table you made by hand, a sweep of one knob, is one slice through it. Finding its lowest point is the job of the rest of the leg. A sweep does it by trying values; step 6 finds it without trying them all.

Your move

One function. sweep takes the data, the knobs as they stand, the index of the knob to turn and the values to try. It returns the loss for each value as a (value, loss) pair, and it must leave the knobs you pass in untouched, so copy w before you change it.

def sweep(X, y, w, index, values):
    """Vary one weight and watch the loss: for each value, set w[index]
    to it (leaving the others as they are) and record (value, loss).
    Returns the list of pairs, in the order given."""

The library way

The same step in PyTorch run on the lab VM

PyTorch can score every price at once. Stack the knob settings as the rows of a matrix W, one row per price, so W has shape (7, 3) and X @ W.T has shape (6367, 7): a column of predictions per price. Subtracting the fares needs y as a column, so y[:, None] makes one, and the library stretches it across all seven. That stretching is called broadcasting.

import torch
from common import design_matrix, load_rides, targets

rides = load_rides()
X, y = design_matrix(rides), targets(rides)

def sweep_losses(prices):
    """The loss at each price per mile: $2.50 base, nothing per minute."""
    W = torch.zeros(len(prices), 3, dtype=torch.float64)  # a row per price
    W[:, 0] = 2.5
    W[:, 1] = prices
    pred = X @ W.T                      # (6367, 3) @ (3, k) -> (6367, k)
    miss = pred - y[:, None]            # y becomes a column, then stretches
    return (miss ** 2).mean(dim=0)      # mean over the rides -> (k,)

grid = torch.tensor([1.0, 1.5, 2.0, 2.5, 3.0, 3.5, 4.0], dtype=torch.float64)
losses = sweep_losses(grid)
for price, loss in zip(grid, losses):
    print(f"${price:.2f} a mile: loss {loss:.2f}")
best = losses.argmin()
print(f"best on the grid: ${grid[best]:.2f} (loss {losses[best]:.2f})")

fine = torch.linspace(1.0, 4.0, 301, dtype=torch.float64)    # 301 prices
fine_losses = sweep_losses(fine)
best = fine_losses.argmin()
print(f"a cent apart: best ${fine[best]:.2f} (loss {fine_losses[best]:.2f})")

The first seven lines are the check's grid, with its best, $3.00 at 14.54. The last line shows what the broadcast buys: 301 prices, a cent apart, scored in one expression instead of a loop. They find $3.05 at 14.47, a little to the right of the grid's best, where the drawn curve bottoms out. Over three knobs the same trick would need more than 27 million settings, and there grids stop being an answer.
