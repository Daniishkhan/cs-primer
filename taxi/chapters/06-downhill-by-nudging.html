Downhill by Nudging

From any point on a loss curve, the slope says which way is down. Measure it by nudging each knob a hair up and a hair down, step the other way, and repeat. That is gradient descent, built from nothing but the loss function.

Where we are

Step 5 left the program able to draw the loss one knob at a time: on the real rides, with a $2.50 base and nothing per minute, the best of seven prices per mile is $3.00, at a loss of 14.54. But the price per minute was held at zero, and step 2 showed that minutes matter. RIDES5 = [            # distance, minutes, passengers, fare
    (1.60, 6.2, 1, 7.0),
    (0.79, 7.1, 1, 5.0),
    (1.37, 7.4, 1, 7.5),
    (7.70, 25.9, 1, 27.0),
    (2.16, 9.5, 3, 9.0),
]
PRICES = [1.0, 1.5, 2.0, 2.5, 3.0, 3.5, 4.0]   # per-mile prices to try

def loss5(base, per_mile, per_minute):
    """Mean squared miss of the three-knob guess over the five rides."""
    total = 0.0
    for d, m, _, fare in RIDES5:
        miss = base + per_mile * d + per_minute * m - fare
        total += miss ** 2
    return total / len(RIDES5)

# Sweep the price per mile twice, holding a different price per minute.
for per_minute in (0.0, 0.5):
    scores = [(loss5(2.5, price, per_minute), price) for price in PRICES]
    best_loss, best_price = min(scores)
    print(f"${per_minute:.2f} a minute: best price per mile "
          f"${best_price:.2f}, loss {best_loss:.2f}")

The wall

The best price per mile moved from $3.00 to $1.50 when the price per minute went from nothing to 50 cents. Knobs depend on each other, so you cannot settle one and then the next. The honest search is a grid over all three at once: seven values per knob is 7 × 7 × 7 = 343 scores, and each score is a pass over all 6,367 rides. A dozen knobs would need nearly 14 billion. What you need is the direction that is downhill from where you stand, found without visiting everywhere else.

The idea

Stand on a loss curve and ask which way is down. The slope tells you: if the loss rises as the knob rises, lower the knob, and if it falls, raise it. Measure the slope with the loss function alone: nudge the knob a hair up and a hair down, and divide the change in the loss by the width of the two nudges. Do this for every knob in turn, the others held still, and the list of slopes is the gradient. Then move each knob a step against its slope, scaled by the learning rate:

gj ≈ (L(wj + ε) − L(wj − ε)) / 2ε
wj ← wj − lr · gj

Here wj is knob j (the code calls the knobs weights), gj is its slope, ε is a tiny nudge such as 0.000001, and lr is the learning rate, which scales the step. A steep slope gives a long step, and near the bottom the slope flattens, so the steps shrink on their own. Nudge, step, nudge, step: that walk downhill is gradient descent. Step 7 gives the same slope as a formula, and step 8 repeats the step a set number of times, writing down the loss each time.

Your move

Two functions. numeric_grad takes any function f of a list of weights, such as lambda w: loss(X, y, w), and returns its slope for every weight, by nudging. gd_step takes the weights, a list of slopes and a learning rate, and returns the weights one step downhill.

def numeric_grad(f, w, eps=1e-6):
    """The slope of f at w in every direction, by nudging: for each
    weight, (f(w + eps there) - f(w - eps there)) / (2 * eps).
    Returns a list the length of w."""

def gd_step(w, grad, lr):
    """One step downhill: each weight moves against its slope, scaled
    by the learning rate lr. Returns the new list, w unchanged."""

  • In numeric_grad, make two copies of w for each weight, up and down, and nudge entry i by +eps in one and -eps in the other. Never nudge w itself: the next weight's nudge would start from a moved point.
  • The slope for weight i is (f(up) - f(down)) / (2 * eps). Collect one per weight, in order, in a list.
  • gd_step is one list comprehension over zip(w, grad). It subtracts, because the slope points uphill, and it returns a new list, so the caller's w is unchanged.
Solution spoiler 
def numeric_grad(f, w, eps=1e-6):
    grad = []
    for i in range(len(w)):
        up, down = list(w), list(w)
        up[i] += eps
        down[i] -= eps
        grad.append((f(up) - f(down)) / (2 * eps))
    return grad


def gd_step(w, grad, lr):
    return [wi - lr * gi for wi, gi in zip(w, grad)]

The library way

The same step in PyTorch run on the lab VM

torch.optim.SGD is gd_step: opt.step() does w -= lr * w.grad for every weight it was given. It reads the slope from w.grad, and here the slope comes from nudging, written for tensors as your numeric_grad is for lists (step 7 has the library fill w.grad itself). The last line is torch.autograd.gradcheck, the library's version of step 7's check: it nudges every input and compares the result with the gradient that autograd computes.

import torch

def bowl(w):                           # the toy bowl, lowest at (3, -1)
    return (w[0] - 3) ** 2 + 2 * (w[1] + 1) ** 2

def nudged_slope(f, w, eps=1e-6):      # numeric_grad, on tensors
    slope = torch.zeros_like(w)
    for i in range(len(w)):
        nudge = torch.zeros_like(w)
        nudge[i] = eps
        slope[i] = (f(w + nudge) - f(w - nudge)) / (2 * eps)
    return slope

w = torch.zeros(2, dtype=torch.float64, requires_grad=True)
opt = torch.optim.SGD([w], lr=0.1)
s = nudged_slope(bowl, w.detach())
print(f"slope at (0, 0): ({s[0]:.4f}, {s[1]:.4f})")
for step in range(200):
    w.grad = nudged_slope(bowl, w.detach())    # where opt.step() looks
    opt.step()                                 # w <- w - lr * w.grad
    if step == 0:
        print(f"after 1 step: ({w[0]:.4f}, {w[1]:.4f})")
print(f"after 200 steps: ({w[0]:.4f}, {w[1]:.4f})")

start = torch.zeros(2, dtype=torch.float64, requires_grad=True)
print("gradcheck, nudging against autograd:",
      torch.autograd.gradcheck(bowl, (start,)))
slope at (0, 0): (-6.0000, 4.0000)
after 1 step: (0.6000, -0.4000)
after 200 steps: (3.0000, -1.0000)
gradcheck, nudging against autograd: True

The numbers are the check's, and the first step lands at (0.6, −0.4), as in the figure. Nothing here is random, so SGD is plain gradient descent. The S stands for stochastic, which means random batches of rides, and step 16 adds that. What the library did for you is the bookkeeping of the step. The slope was still yours.

What you have now

  • numeric_grad(f, w, eps): the slope of any function at w, found by nudging each weight. Yours.
  • gd_step(w, grad, lr): one step against a slope. Yours.

On the toy bowl, 200 nudged steps from (0, 0) land at (3.0000, −1.0000), the minimum, using nothing but the function's values.
