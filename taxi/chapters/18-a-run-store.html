A Run Store

After a day of runs nobody remembers which configuration produced which number. This step writes every run down as one line: the configuration, a short name for it, the seed and both scores, in a file you only ever add to.

Where we are

Step 17 measured the linear model's held-out loss over five splits of 1,500 rides: 1.15, give or take 0.58. It printed that and forgot the five losses behind it. Each came from a run with a seed and two scores, the loss on the rides it learnt from and the loss on the rides held out, and all five used one configuration: distance and minutes, a learning rate of 0.1, 100 steps. Here are those runs as a log should keep them, one line of JSON each. Run it, then move "steps" to the front of CONFIG and run it again: nothing changes.

import hashlib
import json

CONFIG = {"features": "both", "lr": 0.1, "steps": 100}
RUNS = [                       # seed, train loss, held-out loss: step 17's runs
    (0, 1.08, 1.08), (1, 1.25, 0.36), (2, 0.83, 2.06),
    (3, 1.15, 0.79), (4, 1.00, 1.45),
]

# a short, stable name for the configuration: sorted keys, no spaces, hashed
text = json.dumps(CONFIG, sort_keys=True, separators=(",", ":"))
name = hashlib.sha256(text.encode()).hexdigest()[:10]

for seed, train, held in RUNS:
    line = {"hash": name, "config": CONFIG, "seed": seed,
            "train": train, "held": held}
    print(json.dumps(line, sort_keys=True))

The wall

Those five lines exist only in the cell above. In step 17 the losses were printed, summarised and gone, and nothing recorded which seed or settings made them. Step 20's search will run nine fits, and the research loop behind it about a hundred in a night. After a day of that you cannot say which configuration made which number, or whether two of them were the same recipe. A number you cannot trace is a rumour. Every run has to leave a record that names its configuration, its seed and both of its scores.

The idea

A run is one training of one configuration under one seed. Write each run as one line of JSON in a file that is only ever added to (the format is called JSON Lines): the configuration, the seed and both scores. The configuration also gets a short name, its hash: a fixed-length fingerprint computed from its text, here with SHA-256, a standard hash function. The same configuration always gets the same hash and a changed learning rate gets another, provided the text is canonical: sort the keys and drop the spaces, and the name no longer depends on the order you typed them in.

run = (h(c), c, seed, Ltrain, Lheld)     h(c) = first 10 hex digits of sha256(json(c))

Here c is the configuration and L the loss on the rides named. Step 19 compares runs like these, and step 20 adds a line to the file on every pass.

def log_run(path, config, seed, train_score, held_score):
    entry = {"hash": config_hash(config), "config": config, "seed": seed,
             "train": train_score, "held": held_score}
    with open(path, "a") as fh:
        fh.write(json.dumps(entry, sort_keys=True) + "\n")
    return entry

The library way

The real thing how Artifact 1 keeps its log

No library writes this file: the log is the part of a research loop that you own. Karpathy's autoresearch, which chapter 1 of the research course reads closely, keeps a results.tsv beside a git history, one line per experiment: the commit, val_bpb, memory in GB, a status of keep, discard or crash, and a short description. It stays out of git so that a reset cannot erase it. Lab 1 of the research course calls that a good habit and a thin record, since nothing stops a line being edited. The run store it builds for Artifact 1 is your log_run with the guards added:

  • Append-only JSON Lines, as yours is. A run is keyed by its configuration's hash and its seed (SHA-256, 12 hex characters there against 10 here). A key already in the file is refused, and a repeat is served from the file instead of being trained again.
  • A half-written last line, left by a crash, is dropped when the file is read.
  • A record holds nothing that a clock or a host could change, so the whole log can be replayed and must come out byte for byte the same.
  • Every experiment logs two scores: the proxy the loop decides on and a held-out score it never reads. The gap between them is Artifact 1's extension.

The Rust runner of chapter 5 rewrites that store with the same record shapes.

What you have now

  • config_hash(config): a short, stable name for a configuration. Given.
  • log_run(path, config, seed, train_score, held_score): one more line in the file. Yours.
  • load_runs(path): every logged run, oldest first. Given.

Two runs of one configuration now sit in a file under one hash, 2d7339d888, and reading it back gives both.
