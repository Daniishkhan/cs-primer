Backward

Local gradients say how each operation reacts to its parents, one step back. The slope of the final result toward every input comes from chaining them: start at the result, walk the graph backwards, multiply by each local gradient on the way and add where routes meet. That walk is backward, the method behind loss.backward().

Where we are

Step 11's check passed with a slope of 1 toward each side of an addition, each parent's partner for a product, and a relu slope of 1 at 1.5 and 0 at −1.5. Every Value can say how much it moves when each parent does. Below is the same graph, a * b + a at a = 2 and b = 3, with the local gradients of each operation printed. Run it, then change 3.0 to 4.0 and run it again.

class Value:
    def __init__(self, data, parents=(), op=""):
        self.data, self.parents, self.op = data, parents, op

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), "+")

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), "*")


def local_grads(v):
    p = v.parents
    if v.op == "+":
        return [1.0, 1.0]
    if v.op == "*":
        return [p[1].data, p[0].data]
    return []


a, b = Value(2.0), Value(3.0)
product = a * b
out = product + a

for name, toward, v in (("out", "(a * b, a)", out),
                        ("a * b", "(a, b)", product)):
    print(f"{name:6} toward {toward:10} {local_grads(v)}")
out    toward (a * b, a) [1.0, 1.0]
a * b  toward (a, b)     [3.0, 2.0]

The wall

The slope we want runs from out back to each input, and local gradients reach only one step. Here a reaches out by two routes: directly, with slope 1, and through a * b, with slopes 3 and then 1. The answer has to combine both; the check below says it is 4. Real graphs are worse. In the loss over the 500 rides each weight is used 500 times, once per ride, so it reaches the loss by 500 routes (step 7's inner loop adds those 500 contributions). The program has to turn one-step slopes into whole-graph slopes by itself, visiting each Value once and adding up every route that reaches it.

The idea

Work from the result backwards. The result's slope toward itself is 1. Each Value hands its slope back to its parents, multiplied by the local gradient toward each one, and a parent with several children collects a share from each. The shares add up to its slope toward the result. This is the chain rule of step 7 with one addition: step 7's chain had links in a row, whose slopes multiply, and a graph also has routes side by side, whose slopes add. A Value's grad holds exactly that total.

∂out / ∂p = ∑ (∂out / ∂v) · (∂v / ∂p), over every v made from p

Read the sum like this: for every Value v made from p, take v's slope toward the result (v.grad, already known) times v's local gradient toward p (step 11), and add them up. It works only if a Value hands its slope back after all of its children have. So order the graph first, each Value after its parents: a topological order. Then walk it in reverse, and every Value's grad is complete when its turn comes.

The order comes from a depth-first walk: visit each parent, then add the Value, and remember what you have seen so that a shared Value is added once. Step 13 uses backward on the loss over the rides, to get the gradient that step 7 worked out by hand.

Your move

One function. It takes the Value at the top of a graph and fills in grad on every Value the graph was built from, using local_grads from step 11. The ordering is yours to build inside it; the file has no helper for that.

def backward(out):
    """Fill in .grad on every Value that out depends on: d out / d value.
    Order the graph so each Value comes after its parents, the Values
    that feed it (a topological order), set out.grad to 1, then walk
    the order in reverse, adding grad * local gradient to each parent."""

Solution spoiler 
def backward(out):
    order, seen = [], set()

    def visit(v):
        if id(v) in seen:
            return
        seen.add(id(v))
        for p in v.parents:
            visit(p)
        order.append(v)
    visit(out)
    for v in order:
        v.grad = 0.0
    out.grad = 1.0
    for v in reversed(order):
        for p, g in zip(v.parents, local_grads(v)):
            p.grad += v.grad * g

The library way

The same step in PyTorch run on the lab VM

.backward() on a tensor does what your function does. It walks the recorded graph from that tensor back to the leaves, applies each operation's local rule on the way, and adds the result into each leaf's .grad. Here are the check's expressions on tensors, and one more thing to see at the end.

import torch

a = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(3.0, requires_grad=True)
(a * b + a).backward()
print(f"d(ab + a)/da = {a.grad.item():.0f}, d/db = {b.grad.item():.0f}")

x = torch.tensor(1.5, requires_grad=True)
((x * x + x).relu() * 3).backward()          # x is used three times
print(f"through relu and reuse of x: {x.grad.item():.0f}")

x2 = torch.tensor(-0.4, requires_grad=True)
((x2 * 2).relu() + x2).backward()            # the relu is off
print(f"relu off, only the direct path: {x2.grad.item():.0f}")

w = torch.tensor([0.7, -1.3], dtype=torch.float64, requires_grad=True)
f = (w[0] * w[1] + w[0]) * (w[0] - 1)
f.backward()
print(f"(w0 w1 + w0)(w0 - 1) at (0.7, -1.3): {w.grad[0]:.6f}, {w.grad[1]:.6f}")

(a * b).backward()                           # a second backward, on a * b
print(f"a second backward adds b = 3: a.grad is now {a.grad.item():.0f}")
d(ab + a)/da = 4, d/db = 2
through relu and reuse of x: 12
relu off, only the direct path: 1
(w0 w1 + w0)(w0 - 1) at (0.7, -1.3): -0.120000, -0.210000
a second backward adds b = 3: a.grad is now 7

The same gradients: 4 and 2, 12, 1, and −0.120000 for w0, as the check printed. The last line shows a difference: PyTorch adds into .grad on every backward() call, so a second graph raised a.grad from 4 to 7. A training loop therefore clears the slopes first, which is what opt.zero_grad() did in step 8's box. The library recorded the graph as you computed, ordered it, applied each local rule and kept the sums: the whole of this step.

What you have now

The program now has autograd. Build any expression from +, * and relu (and what the given operators make of them), call backward on the result, and every input holds its exact slope: on (w0 w1 + w0)(w0 − 1) at (0.7, −1.3) autograd gave −0.120000 and nudging gave −0.120000.
