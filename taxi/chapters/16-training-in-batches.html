Training in Batches

A network needs a training loop that works for any model built from Values, and that moves after looking at a few rides rather than all of them. Shuffle the rides, cut them into batches, take a step after each batch: it is the loop every library runs.

Where we are

Step 15 ended with a 3-4-1 network that takes one ride and returns a number (−0.2130 for the check's made-up ride), and whose 21 parameters all receive a gradient from backward. Step 8's loop cannot train it: train_linear takes its gradient from grad_mse_linear, a formula for a line, and reads every ride before each step. With step 14's 5,093 training rides that is 5,093 passes through the model before one knob moves, and a rough slope from a few rides might do. Here is the slope of the five rides' loss, and of each small batch of them, at a guess that is nearly right:

def gradient(rides, w):
    """(2/n) * sum of miss * x: step 7's formula on plain floats."""
    grad = [0.0, 0.0, 0.0]
    for d, m, _, fare in rides:
        x = [1.0, d, m]
        miss = sum(a * b for a, b in zip(x, w)) - fare
        for j in range(3):
            grad[j] += 2 * miss * x[j] / len(rides)
    return grad


def show(label, g):
    print(f"{label:<17}", [round(v, 3) for v in g])

The wall

Each batch's slope is a rough guide: rides 1 and 2 point the wrong way, rides 3 and 4 point the right way but about two and a half times too far, and ride 5 hardly moves the knobs. Yet weighted by batch size the batch slopes average to the full slope exactly, as the last line shows. So a batch is a noisy but honest sample of the full gradient, and a pass over the rides buys either one exact step or many noisy ones for the same cost. The program has no loop that takes the second, and no loop at all that trains a network. It needs a loop that takes its gradient from backward, whatever the model, and steps after each small batch of shuffled rides.

The idea

One pass over all the rides is an epoch. Within an epoch, shuffle the rides, walk through them in groups, and for each group take one step using that group's own loss. A group is a batch, and stepping on batches is stochastic gradient descent: stochastic because which rides land in a batch is down to a shuffle. The step is step 6's, with one change: the slope comes from a batch B rather than from every ride.

w ← w − lr · ∇LB(w),   LB(w) = (1 / |B|) ∑i in B (f̂i − fi)2

The batch loss is built as a Value, as in step 13, so backward gives the gradient of every parameter at once. Shuffle again every epoch, with the seed plus the epoch number, so batches differ from pass to pass and a run still repeats. Zero every parameter's .grad before each backward, so a batch's gradient is only that batch's. Then move each parameter's .data, the plain number inside the Value, by −lr times its .grad: gd_step, applied in place. The loop reports one number per epoch, the mean of its batch losses, and step 17 asks how much that number moves when only the seed changes.

Your move

One function, and it is the whole loop. forward is the model's forward function (mlp_forward today), params its parameter dict, and the rest are the numbers of the loop. It returns one loss per epoch.

def train(forward, params, X, y, lr, epochs, batch, seed):
    """Minibatch gradient descent. Each epoch, shuffle the row indexes
    with random.Random(seed + epoch), walk them in groups of `batch`, and
    for each group: build the mean squared error of forward(x, params)
    over the group as a Value, zero every parameter's grad, call
    backward, and move each parameter by -lr * grad. Returns the list of
    epoch losses (the mean of the group losses in that epoch)."""

Solution spoiler 
def train(forward, params, X, y, lr, epochs, batch, seed):
    ps = parameters(params)
    losses = []
    for epoch in range(epochs):
        idx = list(range(len(X)))
        random.Random(seed + epoch).shuffle(idx)
        group_losses = []
        for start in range(0, len(idx), batch):
            group = idx[start:start + batch]
            total = Value(0.0)
            for i in group:
                diff = forward(X[i], params) - y[i]
                total = total + diff * diff
            total = total * (1.0 / len(group))
            for p in ps:
                p.grad = 0.0
            backward(total)
            for p in ps:
                p.data -= lr * p.grad
            group_losses.append(total.data)
        losses.append(sum(group_losses) / len(group_losses))
    return losses

The library way

The same step in PyTorch run on the lab VM

A DataLoader does the shuffling and batching, with a seeded torch.Generator so a run repeats; an optimiser, here torch.optim.SGD, does the update over every parameter. The loop calls the same three methods every time: zero_grad() to clear old gradients, backward() to fill in new ones, step() to move. The script uses the same 200 rides as the check and the same starting weights as init_mlp(3, 4, 0).

import random

import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset
from common import design_matrix, load_rides, targets

rides = load_rides()
X, y = design_matrix(rides), targets(rides)
rows = list(range(len(y)))
random.Random(0).shuffle(rows)               # the cut split(R, 0.8, 0) makes
tr, he = rows[:200], rows[5093:5293]         # 200 rides on each side of it
mean, std = X[tr].mean(0), X[tr].std(0, unbiased=False)
mean[0], std[0] = 0.0, 1.0                   # the constant 1 stays 1
Xtr, Xhe = (X[tr] - mean) / std, (X[he] - mean) / std

torch.manual_seed(0)
net = nn.Sequential(nn.Linear(3, 4), nn.ReLU(), nn.Linear(4, 1)).double()
rng, s = random.Random(0), 3 ** -0.5         # init_mlp(3, 4, 0)'s start
with torch.no_grad():
    for layer in (net[0], net[2]):
        w = layer.weight
        w.copy_(torch.tensor([[rng.uniform(-s, s) for _ in w[0]] for _ in w]))
        layer.bias.zero_()
opt = torch.optim.SGD(net.parameters(), lr=0.01)
loader = DataLoader(TensorDataset(Xtr, y[tr]), batch_size=20, shuffle=True,
                    generator=torch.Generator().manual_seed(0))
for epoch in range(5):
    losses = []
    for xb, yb in loader:
        loss = ((net(xb).squeeze(1) - yb) ** 2).mean()   # the batch's loss
        opt.zero_grad()                                  # clear old gradients
        loss.backward()                                  # fill in new ones
        opt.step()                                       # p -= lr * grad
        losses.append(loss.item())
    print(f"epoch {epoch + 1}: loss {sum(losses) / len(losses):.1f}")
held = ((net(Xhe).squeeze(1) - y[he]) ** 2).mean().item()
print(f"on {len(he)} held-out rides: {held:.1f}")

The same loop and the same story: a loss near 280 falls to about 2 in five epochs. The numbers are close to yours but not equal (yours went from 284.4 to 1.6), because the library's shuffle differs from random.Random(seed + epoch). The held-out score moved more, from 1.9 to 0.8, between two runs that differ only in the shuffle: a first look at the noise step 17 measures. zero_grad() is your zeroing, step() is your update, and every optimiser in the library is this loop with a different update rule.
