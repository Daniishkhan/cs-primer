A Number That Remembers How It Was Made

Every number in the program so far is a plain float, with no memory of where it came from. Give each one a record of the operation that made it and the numbers that went in, and a program can walk the records backwards to find any slope. This step builds the record.

The wall

Count what survives. The computation made six numbers, and the loss function hands back one, 82.81. It is a float: nothing in it says that it is the square of −9.10, which is a sum of three products, or that the per-mile knob entered through one of them. Step 7 worked that out on paper, for this one chain, and wrote the result down as a formula. The program cannot read it off the number, because a float has no history. Each number has to carry a record of the operation that made it and the numbers that went in, so that the chain can be recovered from the result, for any computation, without anyone working it out first.

The idea

A Value is a number that carries its own history. It holds data, the number; parents, the Values the operation was applied to; op, the operation as a string; and grad, a slot for a slope that starts at 0 and is filled in two steps from now. A Value that no operation made, such as an input or a knob, has no parents and is called a leaf. The Values made from a Value are its children. Three operations are enough for this leg: +, * and relu, the bend that lets a network draw curves. Here is what a sum records, and what relu computes:

c = a + b → (data 5, parents (a, b), op +)     relu(x) = max(0, x)

Chain operations and the Values link into a computation graph: leaves at the bottom, the result at the top, each node pointing back at its parents. Below is a * b + a at a = 2 and b = 3. A plain number beside a Value is wrapped in a Value first, so a + 1 works.

Negation, subtraction and division follow from those three operations and are given. Step 11 attaches to each operation the slope it needs; step 12 walks the graph backwards with them.

Your move

Three methods of the Value class. The class is given, with __init__ storing the four fields, and negation, subtraction, division and 2 * a are written for you from these three.

class Value:
    def __add__(self, other):
        """self + other, where other may be a Value or a plain number.
        The result's parents are (self, other) and its op is "+"."""

    def __mul__(self, other):
        """self * other, parents (self, other), op "*"."""

    def relu(self):
        """max(0, self): the bend that lets a network draw curves.
        One parent (self), op "relu"."""

Solution spoiler 
class Value:
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data + other.data, (self, other), "+")

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data * other.data, (self, other), "*")

    def relu(self):
        return Value(self.data if self.data > 0 else 0.0, (self,), "relu")

The library way

The same step in PyTorch run on the lab VM

A tensor made with requires_grad=True is the library's Value. Each operation on it records itself as the result's grad_fn, and the operations that made its inputs as grad_fn.next_functions: your op and parents. A leaf shows up as an AccumulateGrad node, where a slope will later be added into .grad.

import torch

a = torch.tensor(2.0, requires_grad=True)   # a leaf: no operation made it
b = torch.tensor(3.0, requires_grad=True)
c = a + b                                   # each result records its maker
d = a * b
r = torch.relu(torch.tensor(-2.0, requires_grad=True))
for name, t in (("a + b", c), ("a * b", d), ("relu(-2)", r)):
    print(f"{name:9} = {t.item():4.1f}   made by {type(t.grad_fn).__name__}")
print("a leaf's grad_fn:", a.grad_fn)


def show(fn, depth=0):
    """Print the recorded graph: each node's parents indented below it."""
    print("  " * depth + type(fn).__name__)
    for parent, _ in fn.next_functions:
        if parent is not None:              # a plain number is not recorded
            show(parent, depth + 1)


print("\nthe graph of a * b + a:")
show((a * b + a).grad_fn)
print("\nthe graph of a + 1:")
show((a + 1).grad_fn)

The tree prints a twice because a * b + a uses it twice. Unlike your class, the library never records the 1 in a + 1: nobody needs the slope of a constant. And one tensor holds a whole array, so one record can cover a million multiplications where yours covers one.

What you have now

  • Value(data, parents, op): a number with its history, and a grad slot that is still 0. Given.
  • __repr__, __neg__, __sub__, __radd__, __rmul__, __rsub__, __truediv__: the rest of the arithmetic, built from the three below. Given.
  • Value.__add__, Value.__mul__, Value.relu: each records its result's data, parents and op. Yours.

Every number made from Values now remembers how it was made: 2 + 3 is 5 with parents 2 and 3 and op +. Nothing reads the record yet.
