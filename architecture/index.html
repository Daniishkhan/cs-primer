Software Architecture & Design

You now know how machines talk, how programs run and how data is stored. This course is about structure: how to arrange code, modules and services so that a system stays understandable and changeable as it grows, people come and go, and requirements shift. Architecture is mostly about the decisions that are expensive to undo. We'll learn to spot them, make them on purpose, and write down why, from a single module up to APIs, services, events and sagas.

How to use this course

🔗 Mechanisms first, patterns second

Every pattern here solves a problem you've already met: partial failure, backpressure, isolation, dual writes. Links point back whenever a pattern rests on an earlier idea.

🎯 Depth is labelled

Deep dive chapters (complexity, coupling, hexagonal design, API design, microservices, events, sagas, resilience) are the core of most design discussions. Quick intro chapters map the rest.

🧪 Refactor, don't just read

The labs start from tangled code and make you untangle it, then build the moving parts of service architectures yourself: an API, a boundary checker, a saga, an event store, a circuit breaker.
