The Lab Machine

Chapters, quizzes and labs run in your browser. Everything else, every workbench and every artifact run, happens on one rented machine: the lab VM. Nothing runs on your own computer except the browser and an SSH client. This page sets the VM up, says what it costs, and explains the GPU box that comes later.

Why a rented machine instead of your laptop?

Three reasons. Results are comparable, because every reader's workbench output comes from the same kind of machine. The artifacts need many hours of unattended runs, which a laptop cannot give you while you use it. And research loops run code a model wrote: that code belongs in a box you can wipe, not on the computer that holds your keys and your email.

The lab VM

The lab VM is one large CPU machine on Amazon Web Services (AWS) EC2: 16 to 32 cores, 64 to 128 GB of memory, a 500 GB disk, Ubuntu 24.04. Its first boot installs a Python 3.12 environment at ~/lab with PyTorch (CPU build), Hugging Face transformers and datasets, tiktoken, scikit-learn and JupyterLab, and Ollama for small local language models. Sixteen cores are enough for every workbench marked The lab VM: models up to a few hundred million parameters, tokenisers, embedders, small training runs and API-driven agents.

  1. Account and safety first. An AWS account with the command-line tool installed and logged in (aws sts get-caller-identity prints your account). Turn on a billing alert before anything else.
  2. Create the VM with the site's helper. It makes a dedicated SSH key, a security group that admits SSH from your current IP address only, an Elastic IP so the address survives restarts, and a CloudWatch alarm that stops the VM after an hour under 5% CPU. 
    $ workbench/vm create     # m7i.4xlarge by default; WB_VM_TYPE changes it
$ workbench/vm ssh        # ls ~/SETUP_DONE says the first-boot setup has finished
$ workbench/vm sync       # copy this site's code to ~/zts on the VM
  3. Run a workbench in a shell on the VM (cd ~/zts/<course>/workbench/code/wNN && python script.py), or open the paired notebook in JupyterLab: workbench/vm jupyter forwards it to http://localhost:8888 in your browser. Long runs go inside tmux, so they survive a dropped connection.
  4. Stop it when you are done: workbench/vm stop. The disk, with your environment, models and results, is kept; workbench/vm start brings it back in about a minute. If your IP address changes, workbench/vm ip lets the new one in.

Workbenches that call a hosted model (the A10 and A12 agents) read an API key from the environment on the VM. Keep keys in a file only you can read on the VM (chmod 600), never in the repository, and give each artifact its own key with a spending limit.

State of play, October 2026: what the VM costs

An m7i.4xlarge (16 cores, 64 GB) in us-east-1 costs roughly a dollar an hour on demand, and an m7i.8xlarge (32 cores, 128 GB) roughly twice that; check the EC2 pricing page, because prices differ by region and change. A stopped VM costs only its disk (a 500 GB gp3 volume is a few dollars a week). Most accounts start with a small limit on running cores; ask for more under Service Quotas, "Running On-Demand Standard instances", before resizing with workbench/vm resize m7i.8xlarge.

Later: a rented GPU

A few workbenches, and the artifacts' full-size runs, need an NVIDIA GPU. They are badged A GPU box and are marked "later": the course does not need one yet, and nothing in it assumes you have one.

The GPU pages are written for one 24 GB card such as an RTX 4090. That is the reference card the LLM Training course sizes its examples for: enough for a 7B model in 16 bits, or LoRA on a 7B model in 4 bits. The site's helper script, workbench/wb, uses RunPod, which rents single GPUs by the second; the same steps work on any provider that gives you SSH into a GPU machine. A free Colab or Kaggle notebook can run the smaller GPU exercises too, with less memory and time limits.

  1. Account and safety first. Create a RunPod account, add a small amount of credit rather than an open-ended card, and turn on a spending alert. Add your SSH public key (~/.ssh/id_ed25519.pub) under Settings. Create an API key and keep it out of the repository: put export RUNPOD_API_KEY=… in ~/.config/wb.env.
  2. A network volume (Storage, about 50 GB, in a data centre that has RTX 4090s). It holds the Python environment, model weights and datasets, and outlives every pod, so a new pod starts in a minute instead of re-downloading 15 GB. Put its id in ~/.config/wb.env as WB_VOLUME_ID.
  3. Start a pod and connect: 
    $ workbench/wb up       # an RTX 4090 pod with your volume at /workspace
$ workbench/wb sync     # copy the workbench code to /workspace/zts
$ workbench/wb ssh
root@pod$ sh /workspace/zts/workbench/setup-pod.sh   # first time only
    You can also open JupyterLab from the pod's page in the console and run the workbench notebooks (.ipynb) there, or connect VS Code with its Remote-SSH extension.
  4. Stop it when you are done: workbench/wb down. As a safety net, setup-pod.sh starts a watchdog that stops the pod after 30 minutes with the GPU idle and nobody logged in (WB_IDLE_MIN changes it).

State of play, October 2026: what it costs

GPU prices change month to month and differ between RunPod's Secure and Community clouds, so check the price the console shows when you create a pod; wb status prints it too. RunPod bills pods by the second. Storage keeps costing money when the pod is stopped: RunPod's pricing page lists network volumes at $0.07 per GB per month (under 1 TB), so a 50 GB volume is about $3.50 a month. Delete the volume when you finish the courses.

Common misconception

"Serverless" is not the cheap way to do these exercises. RunPod Serverless runs a handler you package as a container, once per request, and scales to zero: right for deploying a model behind an API, wrong for an interactive session. For SSH and Jupyter you want a pod.

Key takeaways

  • Nothing runs on your own computer: the browser for reading and labs, the lab VM for everything with real tools.
  • workbench/vm creates, starts, stops and connects to the VM; SSH is open to your IP address only, and an alarm stops a forgotten VM.
  • Rent a 24 GB GPU only for pages marked "A GPU box", later; keep the environment and models on a network volume.
  • Billing alert first, SSH keys only, and stop the machine when you finish.
