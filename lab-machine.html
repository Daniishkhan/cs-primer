Your Lab Machine

Every chapter, lab and quiz runs in your browser or on your laptop. The Workbench pages go further, using the real tools (PyTorch, Hugging Face, TRL, vLLM), and a few of them need an NVIDIA GPU with more memory than a laptop has. This page sets up both: your laptop first, then a GPU rented by the hour.

Do I need this?

Not to start. Labs use the Python standard library and run in the page or with python3 check.py. Set up the laptop environment when you reach your first Workbench page, and rent a GPU only for the pages badged A GPU box.

Your laptop, then a GPU box

The Workbench pages repeat a chapter's idea with the real tools: PyTorch, Hugging Face models, TRL, vLLM. Most of them run on your laptop. A few train or serve models that need an NVIDIA GPU with a lot of memory, and for those you rent one by the hour. Each workbench page says which machine it needs, with a badge at the top.

First, your laptop

One virtual environment serves every laptop workbench. On a Mac with Apple silicon, PyTorch uses the GPU inside the chip (called MPS), which is plenty for models up to a few hundred million parameters.

$ python3 -m venv ~/.venvs/zts
$ ~/.venvs/zts/bin/pip install -r workbench/requirements.txt
$ source ~/.venvs/zts/bin/activate

For the workbenches that talk to a local language model, install Ollama and pull a small model; the page names which.

Then, a rented GPU

The GPU pages are written for one 24 GB card such as an RTX 4090. That is the reference card the LLM Training course sizes its examples for: enough for a 7B model in 16 bits, or LoRA on a 7B model in 4 bits. The site's helper script, workbench/wb, uses RunPod, which rents single GPUs by the second; the same steps work on any provider that gives you SSH into a GPU machine. A free Colab or Kaggle notebook can run the smaller GPU exercises too, with less memory and time limits.

  1. Account and safety first. Create a RunPod account, add a small amount of credit rather than an open-ended card, and turn on a spending alert. Add your SSH public key (~/.ssh/id_ed25519.pub) under Settings. Create an API key and keep it out of the repository: put export RUNPOD_API_KEY=… in ~/.config/wb.env.
  2. A network volume (Storage, about 50 GB, in a data centre that has RTX 4090s). It holds the Python environment, model weights and datasets, and outlives every pod, so a new pod starts in a minute instead of re-downloading 15 GB. Put its id in ~/.config/wb.env as WB_VOLUME_ID.
  3. Start a pod and connect: 
    $ workbench/wb up       # an RTX 4090 pod with your volume at /workspace
$ workbench/wb sync     # copy the workbench code to /workspace/zts
$ workbench/wb ssh
root@pod$ sh /workspace/zts/workbench/setup-pod.sh   # first time only
    You can also open JupyterLab from the pod's page in the console and run the workbench notebooks (.ipynb) there, or connect VS Code with its Remote-SSH extension.
  4. Stop it when you are done: workbench/wb down. As a safety net, setup-pod.sh starts a watchdog that stops the pod after 30 minutes with the GPU idle and nobody logged in (WB_IDLE_MIN changes it).

State of play, October 2026: what it costs

GPU prices change month to month and differ between RunPod's Secure and Community clouds, so check the price the console shows when you create a pod; wb status prints it too. RunPod bills pods by the second. Storage keeps costing money when the pod is stopped: RunPod's pricing page lists network volumes at $0.07 per GB per month (under 1 TB), so a 50 GB volume is about $3.50 a month. Delete the volume when you finish the courses.

Common misconception

"Serverless" is not the cheap way to do these exercises. RunPod Serverless runs a handler you package as a container, once per request, and scales to zero: right for deploying a model behind an API, wrong for an interactive session. For SSH and Jupyter you want a pod.

Key takeaways

  • Start on your laptop: one virtual environment from workbench/requirements.txt covers every laptop workbench.
  • Rent a 24 GB GPU by the hour only for the pages marked "A GPU box"; keep the environment and models on a network volume.
  • Billing alert first, SSH keys only, and stop the pod when you finish (the idle watchdog is a safety net, not a plan).
