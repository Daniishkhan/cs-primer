Workbench 1: Real Embedders and a Reranker

Chapters 7 and 8 explained two kinds of model for search. An embedder turns a text into a list of numbers, so that texts with similar meaning get similar lists. A reranker reads a query and one passage together and gives the pair a relevance score. The labs used stand-ins, which are simple programs that mimic the idea. Here you swap in the real models on the same 378 passages and 60 queries, and measure two scores: nDCG@10 (how well the first ten results are ordered) and recall@20 (how many of the relevant passages appear in the first twenty). You say which system should win each kind of query before you look.

Why measure it

It is easy to believe that a trained neural model beats a keyword scorer everywhere. It does not, and the places where it loses decide how you build a search system. This workbench gives you the evidence on a collection small enough to inspect by hand. You see where exact words still win, where meaning wins, and what a reranker can and cannot repair. Write down which system should win each kind of query, then measure. When a prediction fails, you have found a fact about your data.

What you need

  • Your laptop, no GPU needed. Python 3.10 or later and the workbench environment (below). The first run downloads three small models from Hugging Face: all-MiniLM-L6-v2 (87 MB), bge-small-en-v1.5 (136 MB) and the cross-encoder ms-marco-MiniLM-L-6-v2 (87 MB). Apple's GPU (MPS) is used if present, otherwise the CPU.
  • The course folder. The script imports the corpus, the BM25 index and the stand-in embedder from retrieval/labs/code/lab03 (the collection of lab 3).
  • Time. The script runs in about two minutes. Allow an hour with the experiments.

Predict before you run

The collection is lab 3's. It has 378 short passages and 60 queries, with graded judgements for each query. The queries come in four kinds, and each kind is built to stress a different weakness:

  • code (14 queries): contains an exact identifier, such as E4021 payment gateway.
  • variant (18): misspellings and word endings, such as reimbursment for damagd parcels.
  • plain (16): ordinary questions, such as how long does standard delivery take.
  • order (12): the direction matters, such as move money from checking to savings, where a passage about savings to checking is wrong.

An embedder scores a passage by the angle between two vectors, the cosine (chapter 7; the training loss is what teaches the model which angles to make small):

cos(q, p) = q · p / (‖q‖ ‖p‖)

Each passage is embedded once, offline, and each query once, online. A cross-encoder cannot do that, because it needs the pair. So count the model runs. The corpus has N = 378 passages and Q = 60 queries. An embedder runs N + Q = 438 times. A cross-encoder reranking the top d = 30 candidates for every query runs Q × d = 1,800 times for each first stage you give it. Its cost grows with the number of queries, and the embedder's cost does not. That is the trade in chapter 8.

Your prediction

Before reading on, fill in the table of the best system for each kind: BM25, the stand-in, a real embedder, or a real embedder followed by the cross-encoder. Then answer two more. Does a trained embedder beat the stand-in overall? And if BM25 finds only 63% of the relevant passages in its top 30, what is the most recall the cross-encoder can reach after reordering them?

The predictions I wrote down

The script prints these before it measures anything. code: BM25, because an exact token like E4021 either matches or does not, and vectors blur it. variant: a dense model, because misspellings and endings still share word pieces or letter groups, where BM25 sees a different word. plain: a real embedder, because it was trained on paraphrase and the stand-in was not. order: every dense first stage should score lower here than on plain queries, since one vector for a passage holds "from A to B" and "from B to A" almost alike, and the cross-encoder should lift the score. Overall: real embedders beat the stand-in, reranking helps, and recall@20 after reranking cannot exceed the first stage's recall at the depth it was handed. For BM25 that ceiling is the 63% in the question: a reranker reorders, it never adds.

Run it

Set up once

One virtual environment serves every workbench page. From the site's folder:

$ python3 -m venv ~/.venvs/zts
$ ~/.venvs/zts/bin/pip install -r workbench/requirements.txt
$ source ~/.venvs/zts/bin/activate

The script is code/w01/real_embedders.py, and the same code split into cells is real_embedders.ipynb for Jupyter.

The idea

  1. load lab 3's collection, BM25 index and trigram stand-in; print the predictions
  2. embed all passages with all-MiniLM-L6-v2 and bge-small-en-v1.5 (unit-length vectors, so a dot product is the cosine)
  3. rerank the top 30 of BM25 and of bge-small with the cross-encoder
  4. score every system with lab 3's own nDCG@10 and recall@20, overall and per kind of query
  5. compare the first stage's recall at depth 30 with the recall after reranking; look at one query in detail
"""Real embedders and a reranker, measured on the retrieval labs' corpus:
378 passages, 60 queries of four kinds, graded judgements. Predict which
system wins each kind of query, then measure nDCG@10 and recall@20.

    python real_embedders.py
    python real_embedders.py --depth 50

Needs: sentence-transformers (workbench/requirements.txt) and the course
folder (it imports retrieval/labs/code/lab03). Downloads about 87 MB
(all-MiniLM-L6-v2), 136 MB (bge-small-en-v1.5) and 87 MB (the
cross-encoder ms-marco-MiniLM-L-6-v2) the first time."""
import argparse
import sys
import time
from pathlib import Path

import numpy as np
import torch
from sentence_transformers import CrossEncoder, SentenceTransformer

# ── 1. Settings and the lab's own code ───────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--lab", default=None)     # folder holding corpus.json
ap.add_argument("--depth", type=int, default=30)    # candidates reranked
ap.add_argument("--no-prefix", action="store_true")  # bge: skip the prefix
args, _ = ap.parse_known_args()        # notebooks pass their own flags


def find_lab():
    if args.lab:
        return Path(args.lab)
    try:
        here = Path(__file__).resolve()
    except NameError:                  # inside a notebook
        here = Path.cwd().resolve()
    for base in [here, *here.parents]:
        for rel in ("retrieval/labs/code/lab03", "labs/code/lab03"):
            if (base / rel).is_dir():
                return base / rel
    raise SystemExit("cannot find retrieval/labs/code/lab03; pass --lab")


LAB = find_lab()
sys.path.insert(0, str(LAB))
from bm25 import Bm25Index                       # noqa: E402
from embedder import TrigramEmbedder             # noqa: E402
from evalkit import (grades_for, load_collection,  # noqa: E402
                     ndcg_at_k, recall_at_k)

if torch.cuda.is_available():
    DEVICE = "cuda"
elif torch.backends.mps.is_available():
    DEVICE = "mps"
else:
    DEVICE = "cpu"
torch.manual_seed(0)
coll = load_collection(str(LAB))
ids = list(coll.docs)
texts = [coll.docs[d] for d in ids]
kinds = sorted({q["kind"] for q in coll.queries})
counts = {k: sum(q["kind"] == k for q in coll.queries) for k in kinds}
print(f"{len(ids)} passages, {len(coll.queries)} queries {counts}; "
      f"device {DEVICE}")

# ── 2. Predict, before measuring (chapters 7 and 8) ──────────────────────
print("""
predicted winners (nDCG@10), from the chapters' reasoning
  code     BM25: an exact token like E4021 matters, and vectors blur it
  variant  a dense model: typos and inflections share word pieces or
           letter groups, which BM25's exact terms miss
  plain    a real embedder: it was trained on paraphrase, the stand-in was not
  order    below plain for every dense first stage (one vector per
           passage holds "from A to B" and "from B to A" almost alike),
           and the cross-encoder lifts it
  overall  real embedders beat the stand-in; reranking helps; recall@20
           after reranking cannot exceed recall at the depth it was given""")

# ── 3. Build the five first stages ───────────────────────────────────────
bm25 = Bm25Index(coll.docs)
stand = TrigramEmbedder(coll.docs)
stand_vecs = np.array([stand.embed(t) for t in texts])
BGE_PREFIX = "Represent this sentence for searching relevant passages: "
MODELS = {
    "MiniLM": ("sentence-transformers/all-MiniLM-L6-v2", ""),
    "bge-small": ("BAAI/bge-small-en-v1.5",
                  "" if args.no_prefix else BGE_PREFIX),
}
dense = {"stand-in": (stand_vecs, stand.embed)}
for name, (hf_id, prefix) in MODELS.items():
    model = SentenceTransformer(hf_id, device=DEVICE)
    t0 = time.perf_counter()
    vecs = model.encode(texts, normalize_embeddings=True, batch_size=64)
    secs = time.perf_counter() - t0
    print(f"{name}: {vecs.shape[1]} numbers per passage, "
          f"{len(texts) / secs:.0f} passages/s (encoding only)")
    dense[name] = (vecs, lambda q, m=model, p=prefix:
                   m.encode(p + q, normalize_embeddings=True))


def top_dense(name, query, k):
    vecs, embed = dense[name]
    scores = vecs @ np.asarray(embed(query))
    order = np.argsort(-scores, kind="stable")[:k]
    return [(ids[i], float(scores[i])) for i in order]


SEARCH = {"BM25": bm25.search}
for name in dense:
    SEARCH[name] = lambda q, k, n=name: top_dense(n, q, k)

# ── 4. The cross-encoder reranks a first stage's top candidates ──────────
ce = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2", device=DEVICE)


def reranked(first):
    def run(query, k):
        cands = [d for d, _ in SEARCH[first](query, args.depth)]
        s = ce.predict([(query, coll.docs[d]) for d in cands],
                       batch_size=64)
        order = np.argsort(-s, kind="stable")[:k]
        return [(cands[i], float(s[i])) for i in order]
    return run


for first in ("BM25", "bge-small"):
    SEARCH[f"{first}+rerank"] = reranked(first)

# ── 5. Measure ───────────────────────────────────────────────────────────


def evaluate(fn):
    nd, rc = {}, {}
    for q in coll.queries:
        qrel = coll.qrels[q["qid"]]
        got = [d for d, _ in fn(q["text"], 20)]
        g = grades_for(got, qrel)
        nd[q["qid"]] = ndcg_at_k(g, 10, list(qrel.values()))
        rc[q["qid"]] = recall_at_k(g, 20, coll.n_relevant(q["qid"]))
    return nd, rc


results = {name: evaluate(fn) for name, fn in SEARCH.items()}


def mean(d, kind=None):
    vals = [v for q in coll.queries if kind in (None, q["kind"])
            for v in [d[q["qid"]]]]
    return sum(vals) / len(vals)


print(f"\nnDCG@10 and recall@20 over all queries (rerank depth "
      f"{args.depth})")
print(f"  {'system':18}{'nDCG@10':>9}{'recall@20':>11}")
for name, (nd, rc) in results.items():
    print(f"  {name:18}{mean(nd):>9.3f}{mean(rc):>11.3f}")

print("\nnDCG@10 by kind of query")
print(f"  {'system':18}" + "".join(f"{k:>9}" for k in kinds))
for name, (nd, _) in results.items():
    print(f"  {name:18}" + "".join(f"{mean(nd, k):>9.3f}" for k in kinds))
print("  best first stage and best system overall, per kind:")
firsts = ["BM25", "stand-in", "MiniLM", "bge-small"]
for k in kinds:
    a = max(firsts, key=lambda n: mean(results[n][0], k))
    b = max(results, key=lambda n: mean(results[n][0], k))
    print(f"    {k:9}{a:>10}   {b}")

# ── 6. The recall ceiling: a reranker cannot add a document ──────────────
print(f"\nrecall ceiling: first stage at depth {args.depth} against "
      f"recall@20 after reranking")
for first in ("BM25", "bge-small"):
    ceil = []
    for q in coll.queries:
        got = [d for d, _ in SEARCH[first](q["text"], args.depth)]
        g = grades_for(got, coll.qrels[q["qid"]])
        ceil.append(recall_at_k(g, args.depth, coll.n_relevant(q["qid"])))
    after = mean(results[f"{first}+rerank"][1])
    print(f"  {first:10} first stage recall@{args.depth} "
          f"{sum(ceil) / len(ceil):.3f}   after rerank recall@20 "
          f"{after:.3f}")

# ── 7. One query where direction matters ─────────────────────────────────
q = next(x for x in coll.queries if x["kind"] == "order")
qrel = coll.qrels[q["qid"]]
print(f"\nquery {q['qid']}: {q['text']!r}")
for name in ("bge-small", "bge-small+rerank"):
    top = SEARCH[name](q["text"], 3)
    print(f"  {name}")
    for d, s in top:
        print(f"    grade {qrel.get(d, 0)}  {s:7.3f}  {coll.docs[d][:70]}")

What you should see

  • The overall table. BM25 scores 0.693 nDCG@10. The stand-in does better (0.786), MiniLM better again (0.832), and bge-small is lower than the stand-in on nDCG (0.762) although higher on recall@20 (0.850 against 0.792). So the prediction that real embedders beat the stand-in holds for MiniLM and fails for bge-small on ordering. I did not find the cause. The no-prefix experiment below rules out one candidate. A possible one, which I did not test, is that this synthetic collection has many near-identical template passages where one word decides relevance.
  • code: BM25 wins, 0.880 against 0.632 for the best embedder. The prediction held. Exact identifiers are what a term index is for. The stand-in's 0.601 and bge-small's 0.516 show it is not a quirk of one model.
  • variant: BM25 collapses (0.431) and every dense model recovers (0.82 to 0.89). MiniLM is best at 0.892, as predicted. But the stand-in is at 0.875, close behind. Chapter 7 warned that its letter-group vectors are robust to typos, and it is. A trained model adds only a little on this kind.
  • plain: MiniLM 0.931, the stand-in 0.919, BM25 0.831. A real embedder wins, as predicted. But 0.012 over the stand-in on 16 queries is noise. Chapter 5 says why a few queries cannot rank two close systems.
  • order: dense first stages fall below their plain scores (MiniLM 0.843 against 0.931, bge-small 0.770 against 0.907, the stand-in 0.693 against 0.919; BM25 0.683 against 0.831), as predicted. The cross-encoder lifts it: BM25 from 0.683 to 0.818 and bge-small from 0.770 to 0.874.
  • Reranking cannot add passages. BM25 plus the cross-encoder gains only 0.049 nDCG overall (0.693 to 0.742) and only 0.045 on variant (0.431 to 0.476). Much of what the cross-encoder could have helped was not in BM25's thirty candidates, so there was nothing to reorder. The recall block says it directly: BM25 reaches 0.633 at depth 30, and the reranked list reaches 0.633. For bge-small the ceiling is 0.892 and the reranked list reaches 0.867. Both are at or below the ceiling, as they must be.
  • The cross-encoder is not better at everything. On code queries, BM25 alone scores 0.880 and BM25 followed by the cross-encoder scores 0.858. A reranker trained on natural questions is not an exact-match specialist. The best system overall is bge-small followed by the cross-encoder (0.888). It recovers code to 0.863, probably because bge-small's thirty candidates contain the right passages and the cross-encoder puts them on top. I did not check this query by query.
  • The last block, query q33. The right passage is first in both lists. But the reversed passage (savings to checking, grade 0) is right behind it: 0.880 against 0.869 for bge-small, 9.42 against 9.00 for the cross-encoder. The third passage in each list is unrelated, and scores far below: 0.645 for bge-small and −10.69 for the cross-encoder. Both models see the reversed page as almost as good as the right one. This is one query, so it is an illustration and not a measurement. The twelve order queries are the measurement.

Break it

  • Drop the instruction prefix for bge. The script gives bge-small a query prefix, Represent this sentence for searching relevant passages: . Its model card calls the prefix optional for version 1.5. Predict first: does removing it change the ranking a lot? Run python real_embedders.py --no-prefix. The bge-small rows became: 
    nDCG@10 and recall@20 over all queries (rerank depth 30)
  system              nDCG@10  recall@20
  bge-small             0.770      0.883
  bge-small+rerank      0.889      0.867
    The prefix is not the reason for bge-small's low nDCG: without it the score is 0.770 against 0.762, a difference too small to matter.
  • Change the rerank depth. The ceiling argument predicts that depth 10 caps recall@20 at the first stage's recall@10, and depth 100 lifts it towards the first stage's recall@100. Run --depth 10 and --depth 100. The relevant lines:

Past some depth the extra candidates are almost all wrong, and chapter 8 says the bill grows with them.
  • Break the cross-encoder with a long passage. Concatenate two unrelated passages into one and judge it for a query that matches only the first. Predict whether the score drops, then measure with ce.predict([(query, long_text)]). This cross-encoder reads at most 512 tokens of the pair, so passage length matters too (chapter 14, on chunking).
  • Add a hybrid. No single first stage won every kind. Lab 3 fuses BM25 and the stand-in with reciprocal rank fusion. Write the same fusion over BM25 and MiniLM and predict which of the four kinds it improves most over the better of the two. Chapter 10 has the details.

Key takeaways

  • No retriever won every kind of query. BM25 won code by 0.25 nDCG, and the trained embedders won variant, plain and order.
  • A real embedder is not automatically better than a cheap stand-in. MiniLM beat it and bge-small did not, on nDCG, on this collection. Measure on your own queries before choosing.
  • The cross-encoder lifted ordering, most for the first stage that had already fetched the passages. It cannot recover passages the first stage missed. Recall after reranking never exceeded the first stage's recall at the same depth.
  • Depth is a trade between that ceiling and the cost: 1,800 pair reads per first stage at depth 30, and more than three times that at depth 100.
  • With 60 queries, differences of a few hundredths are noise. Trust the large gaps and the patterns by kind.
