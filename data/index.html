Data Systems

Almost every system you will ever design is, underneath, a way of storing data and getting it back. When you write SELECT * FROM orders WHERE user_id = 42, what actually happens? How does a database find one row among a billion in a few milliseconds, survive a power cut halfway through a payment, and stop two people from booking the same seat? This course opens the database up: storage engines, indexes, transactions, caches, replicas and streams, built from the files, memory and locks you met in How Programs Run.

How to use this course

🔗 It builds on both earlier courses

Storage engines rest on the memory hierarchy and durability; isolation is race conditions with a new name; replication and sharding deepen networking ch. 18 and 19.

🎯 Depth is labelled

Deep dive chapters (storage engines, indexes, isolation, caching, replication, streams) come up in nearly every system-design discussion. Quick intro chapters map the rest.

🧪 Build a database

The labs have you write the core of a real storage engine (a log, an LSM tree, a B-tree), tune real queries in SQLite and implement snapshot isolation yourself.
