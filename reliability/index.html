Reliability & Operations

Everything so far has been about building systems. This course is about running them: deciding how reliable is reliable enough, seeing inside a live system, keeping it upright when demand outruns capacity, changing it many times a day without breaking it, and responding well when it breaks anyway. You'll learn the arithmetic of nines and error budgets, the queueing maths behind the latency knee, and the human practices of on-call, incidents and blameless postmortems.

How to use this course

🔗 Numbers, not vibes

Reliability starts with arithmetic: how availabilities compose, how fast a budget burns, how latency explodes near full utilization. Every rule of thumb here is derived, so you can re-derive it for your own system.

🎯 Depth is labelled

Deep dive chapters (availability, SLOs, metrics, tracing, queueing, tail latency, overload, deploys, blast radius) carry most of the weight. Quick intro chapters map the rest.

🧪 Measure, then break it

Labs build a burn-rate alerter, a metrics library, a tracer, a queueing simulator, a load shedder and a canary judge. Studios include a full incident you run as incident commander.
