Zero to Systems

How do big software systems actually work, and how do the engineers who design them think? This path starts from first principles, one layer at a time: how computers talk, how a single machine runs programs, how data is stored, how software is structured, and how many machines act as one. It ends with designing complete systems and explaining the trade-offs.

    Zero to AI Systems

    A second path, in nine courses, from school mathematics to designing, training, evaluating and delivering AI systems: machine learning and deep learning from first principles, how large language models are trained, post-trained and served, agents and their protocols, retrieval and document understanding, evaluation and guardrails, open-ended search and self-improving agents, and a capstone of take-home-style delivery studios. It leans on the first path for the engineering underneath (networks, processes, data stores, reliability and security) and links back to those chapters instead of repeating them.

    🧮 Build the maths into code

    Every idea is implemented by hand before a library does it for you: autograd, a GPT, BM25, HNSW, PPO, an MCP server, MAP-Elites.

    🧪 Measure first

    Evaluation runs through every course. Labs ship with checkers, projects end with an error-analysis memo, and claims come with error bars.

    🔌 Runs offline

    Labs use the standard library and scripted stand-in models, so every check is free and repeatable. Plug in a real model when you want to.

      Why this order?

      Each course explains the machinery the next one takes for granted. Networking shows how two computers exchange bytes. How Programs Run looks inside one computer: processes, memory, files, threads and event loops, the parts every server and database is built from. Data Systems uses those parts to build storage engines and transactions. Architecture is about structuring the code and services around them. Distributed Systems, Deep and Reliability make many of those machines dependable together. Security Engineering keeps them dependable when someone is actively trying to break them. The System Design Studio brings it all together.

      📚 Understanding first

      Every course explains mechanisms from first principles before patterns or buzzwords. If you can explain why a design works, you can adapt it.

      🛠️ Build it

      Hands-on Python labs in every course: a chat server, a DNS resolver, a toy Raft, a shell, a crash-safe log, your own event loop.

      📐 Design it

      Each course ends with design studios: interview-style problems where you sketch your own answer before comparing it with a worked one.

      Every course also has a 🧰 toolbox of real tools to watch the ideas happen (Wireshark, tcpdump, strace, perf and more), each with a short guided exercise. A few experiments need Linux; Your lab machine shows how to get one, either free on your laptop or as a small cloud server.
