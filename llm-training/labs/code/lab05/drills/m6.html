Choosing merge settings by their score on a set of examples is selection on that set, so the winner's score there is biased upwards. The honest protocol makes every decision on a search split (the examples the search may use), reports on a held-out split (examples it never sees) and gives every method the same treatment.

compare_methods returns a dict {name: (search score, held-out score)} in the order of METHODS. The names are "base"; "oracle" (each fine-tune scored on its own task only, as if you always picked the right one); "average" (the plain mean of the fine-tunes); "task arithmetic" (lambda from best_global_lambda); "TIES" (lambda from LAMBDA_GRID by search score, first best on ties); and "evolved" (search_recipe). Every choice uses world.search alone. optimism(table, name) is search minus held-out for one row, and mean_table averages tables over worlds, name by name.
