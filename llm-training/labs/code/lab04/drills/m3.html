Learning from preferences needs pairs of answers where one is better. A verifier (a program that checks answers) can build them: sample two answers from the reference policy (the starting model), score both, and keep the pair only if the scores differ.

make_pairs follows the docstring's recipe, and the order of random draws matters: first rng.randrange for the question, then sample_index for answer a, then for b. Ties are thrown away, so many draws are wasted; stop at n pairs or max_attempts draws. train_dpo is plain gradient descent on the last milestone's loss. It copies the reference logits first (task.ref must never change), records dpo_loss before each update, gets dpo_grads and moves every logit downhill by lr times its gradient. It returns (z, losses).

reference right with probability p: usable pair on 2p(1 - p) of draws
p = 0.6 gives 0.48; p = 0.015 gives only 0.03
