In a sequence of decisions, an action can only affect later rewards. So each action is credited with its return-to-go: the rewards from that step on, added up, each shrunk by a discount factor per step of delay.

returns_to_go works backwards from the last step, adding gamma (the discount) times the return of the next one. run_episode plays one episode (a run to the end), recording each state before its action so the three lists have equal length, with sample_action on the softmax of the state's row. reinforce_grid_gradient adds (G - V[s]) * grad_log_prob to the row of the state where each step happened (V[s], the average return seen from that state, is the baseline), then divides by the number of episodes, not steps. update_values moves V[s] a fraction alpha towards each return, in step order, in place. train_reinforce_grid takes the policy step first and updates V afterwards, so the baseline never sees the batch it weights.
