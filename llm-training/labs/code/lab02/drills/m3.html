In a sequence of decisions an action can only affect the rewards that come after it, so each action is credited with the discounted sum of the rewards from that step on, its return-to-go. A table holding the average return seen from each state serves as the baseline.

returns_to_go works backwards from the last step, adding gamma times the return of the next one. run_episode records each state before its action, so the three lists have equal length, and uses sample_action on the softmax of the state's row. reinforce_grid_gradient adds (G - V[s]) * grad_log_prob to the row of the state where each step happened, then divides by the number of episodes, not steps. update_values moves V[s] a fraction alpha towards each return, in step order, in place. train_reinforce_grid takes the policy step first and updates V afterwards, so the baseline never sees the batch it weights.
