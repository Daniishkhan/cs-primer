Bandits & Markov Decision Processes

Reinforcement learning is learning to act from a score rather than from examples. This chapter builds its vocabulary in two steps: the bandit, where one choice earns one reward and the only hard problem is exploration, and the Markov decision process, where choices change the situation and rewards add up over time. Then it shows how a language model fits both.

Why this matters

Part 1 was about building a base model by predicting text. Everything that makes a model follow instructions, refuse unsafe requests or solve maths problems with long reasoning is trained with a signal that says "this answer was better than that one", not with a target to copy. That is reinforcement learning (RL), and its algorithms are written in a small vocabulary: policy, reward, return, value. This chapter teaches that vocabulary with examples you can run, so that policy gradients, PPO and GRPO read as consequences rather than incantations. You need basic probability (expectation and sampling); no earlier RL.

Learning from a score

Supervised learning (chapter 10 will use it for instruction tuning) says: here is an input and the right output; make your output match. Often nobody knows the right output, but somebody can say how good an attempt was. A reader can rate a summary; a unit test can pass or fail a program; a checker can confirm that 17 × 23 = 391. A number that scores an attempt is a reward, and learning to produce attempts that earn more of it is reinforcement learning.

Four words describe every RL problem. The agent is the learner. The environment is everything else, including the world's response to what the agent does. At each moment the agent observes the situation, picks an action, and the environment returns a reward and a new situation. The rule the agent uses to pick actions is its policy, written π(a | s): the probability of action a in situation (state) s. Training changes the policy to earn more reward.

The bandit: one choice, one reward

The simplest RL problem has no state at all. A multi-armed bandit (named after slot machines, "one-armed bandits") offers K actions, called arms. Each pull of arm a pays a random reward with some fixed average q*(a) that you do not know. You get T pulls and want the largest total reward.

The problem is realistic. Pick which of four prompt templates to use for a support assistant, judged by thumbs-up rate. Pick which of five candidate answers to show. Pick which ranking function to serve in an online experiment. Each is a bandit as long as the choice does not change the next situation. (Ordinary A/B tests, as in From Model to Value, split traffic evenly and decide at the end; a bandit shifts traffic toward the winner while it is still learning.)

The difficulty is that you must learn which arm is best by pulling arms, and every pull of a poor arm costs reward. This is the exploration-exploitation trade-off: exploit what you currently believe to be best, or explore to find out if something else is better. To score a strategy we use regret: the reward you would have earned by always pulling the best arm, minus the reward you actually earned. Regret is zero for an agent that knew the answer from the start.

Estimating arm values

Keep for each arm the sample average of the rewards it paid so far, Q(a). You do not need to store the history, because a running average can be updated one reward at a time:

Qn+1 = Qn + (1 / n) (rn − Qn)

Read it as "new estimate = old estimate + step size × error". The same shape appears in every RL algorithm and in gradient descent: move the estimate a fraction of the way toward what you just saw. With step size 1/n it is exactly the average; with a constant step size it forgets old rewards, which suits arms that drift over time.

Three ways to choose

  • Greedy. Always pull the arm with the highest Q. It exploits and never explores. If the first lucky pull of a mediocre arm gives it a high estimate, greedy keeps pulling it and never learns that the others are better.
  • ε-greedy. With probability ε (say 0.1) pull a random arm, otherwise the greedy one. Simple and robust. The cost is that it keeps exploring at the same rate forever, including arms it already knows are bad.
  • Upper confidence bound (UCB). Pull the arm with the highest Q(a) + c√(2 ln t / na), where na is how often arm a was pulled and t the total pulls. The extra term is an optimism bonus that shrinks as an arm is tried more, so uncertain arms get another look. Auer, Cesa-Bianchi and Fischer (2002, "Finite-time Analysis of the Multiarmed Bandit Problem") proved logarithmic regret for it with c = 1.
  • Thompson sampling. Keep a probability distribution over each arm's true value, draw one sample from each, and pull the arm with the best sample (Thompson, 1933). Uncertain arms produce widely spread samples and so win sometimes; well-known arms win only if they are good.

The script runs all four on 300 random 10-armed problems, where each arm pays 1 with a hidden probability between 0.05 and 0.6, and 1,000 pulls each. The UCB constant is set to c = 0.5, because the textbook value over-explores at this short horizon; that is a tuning choice and the results are sensitive to it.

import math, random

K, STEPS, RUNS = 10, 1000, 300
C_UCB = 0.5                              # exploration constant; UCB1's textbook sqrt(2) over-explores at this horizon
def make_arms(rng):                       # 10 arms, each a coin with its own success probability
    return [rng.uniform(0.05, 0.6) for _ in range(K)]

def play(policy, seed):
    rng = random.Random(seed)
    p = make_arms(random.Random(1000 + seed))
    best = max(p)
    n, q = [0] * K, [0.0] * K
    a_s, b_s = [1] * K, [1] * K           # Beta(1,1) prior per arm for Thompson sampling
    total, regret, optimal = 0, 0.0, 0
    curve = []
    for t in range(1, STEPS + 1):
        if policy == "greedy":
            a = max(range(K), key=lambda i: (q[i], rng.random()))   # pure exploitation, ties broken at random
        elif policy == "eps0.1":
            a = rng.randrange(K) if rng.random() < 0.1 else max(range(K), key=lambda i: (q[i], rng.random()))
        elif policy == "ucb":
            a = max(range(K), key=lambda i: 1e9 if n[i] == 0 else q[i] + C_UCB * math.sqrt(2 * math.log(t) / n[i]))
        else:                              # thompson
            a = max(range(K), key=lambda i: rng.betavariate(a_s[i], b_s[i]))
        r = 1 if rng.random() < p[a] else 0
        n[a] += 1; q[a] += (r - q[a]) / n[a]          # incremental mean: Q <- Q + (r - Q)/n
        a_s[a] += r; b_s[a] += 1 - r
        total += r; regret += best - p[a]; optimal += (p[a] == best)
        if t % 100 == 0: curve.append(regret)
    return total / STEPS, regret, optimal / STEPS, curve

CURVES = {}
print(f"{K} arms, {STEPS} pulls, averaged over {RUNS} random problems")
print(f"{'policy':<10}{'mean reward':>12}{'regret':>9}{'best arm pulled':>17}")
for pol in ("greedy", "eps0.1", "ucb", "thompson"):
    rs = [play(pol, s) for s in range(RUNS)]
    m = lambda i: sum(r[i] for r in rs) / RUNS
    print(f"{pol:<10}{m(0):>12.3f}{m(1):>9.1f}{100*m(2):>16.0f}%")
    CURVES[pol] = [sum(r[3][j] for r in rs) / RUNS for j in range(10)]
print()
print("cumulative regret after 100, 200, ... 1000 pulls")
for pol, c in CURVES.items():
    print(f"{pol:<10}" + " ".join(f"{v:6.1f}" for v in c))

Greedy's mean reward (0.395) is 0.09 below the others, and it pulled the best arm in only 17 percent of its pulls. ε-greedy, UCB and Thompson sampling all end within about 11 units of regret of each other here; differences among them depend on the problem and on tuning, so do not read this table as a ranking for all bandits. The robust finding is the shape: exploration that tapers is better than none, and no exploration is far worse.

Common misconception

"The arm with the best average so far is the best arm." After three pulls, an average is mostly noise: a 0.3-probability arm shows three successes in a row about 3 percent of the time (0.33 = 0.027), and a greedy agent will then treat it as the winner indefinitely. An estimate is a number with an uncertainty, and exploration is how you pay to shrink it. The same issue returns when an RL-trained language model collapses onto one style of answer: a policy that stops exploring stops improving.

Bandits get a longer treatment in the context of search in Tree Search, Bandits & MCTS in A7, where UCB drives the choice of which branch to expand. Here we need the idea of trading exploration for reward, and the incremental-update form, and we now add what bandits leave out: situations.

Adding state: contextual bandits and MDPs

In a contextual bandit the agent sees a context before each choice (a user's profile, a customer's prompt) and picks an action; the reward depends on both. Each round is independent: the action does not affect the next context. A recommendation system that picks an item per request is a contextual bandit.

A Markov decision process (MDP) removes that independence: actions change the state, so a choice now alters what choices are available later. Formally it is a tuple of five things.

  • a set of states S, the situations the agent can be in;
  • a set of actions A;
  • a transition rule P(s' | s, a), the probability of landing in state s' after taking action a in state s;
  • a reward r(s, a, s');
  • a discount factor γ between 0 and 1, explained below.

The word "Markov" is a promise about the state: it contains everything relevant to the future. Given the current state, the history before it adds nothing, so P depends only on (s, a). If your state leaves something out (a chess position without whose turn it is), the problem stops being Markov and you must enlarge the state until it is.

Returns and discounting

An agent in an MDP acts for many steps, so the thing to maximise is not one reward but the sum of the rewards to come, the return:

Gt = rt+1 + γ rt+2 + γ2 rt+3 + … = ∑k≥0 γk rt+k+1

Discounting by γ does two jobs. It keeps the sum finite when a task could run forever (if rewards are bounded by R and γ < 1, the return is bounded by R/(1 − γ)). And it expresses a preference for sooner reward over later, which is also a hedge against a future that is more uncertain than the model admits. A reward of 10 that arrives after three steps of nothing is worth 10γ3: 10 at γ = 1, 7.29 at γ = 0.9, 1.25 at γ = 0.5. The last line of the script below prints these. A task that always ends after a fixed number of steps, such as writing one answer, can use γ = 1, and most RL for language models does exactly that.

Two functions turn the return into something an agent can reason about. The state value Vπ(s) is the expected return starting in state s and following policy π afterwards. The action value Qπ(s, a) is the expected return if you take action a first and then follow π. Because the future after one step looks like the original problem, they satisfy a recursion due to Bellman (1957):

Vπ(s) = ∑a π(a | s) ∑s' P(s' | s, a) [ r + γ Vπ(s') ]

The value of a state is the average, over what the policy does and what the world does, of the immediate reward plus the discounted value of where you land. The optimal value V* replaces the average over actions by a maximum, and the best policy is the one that is greedy with respect to it. Two iterative methods follow directly: policy evaluation applies the first equation repeatedly to a fixed policy until the values stop changing, and value iteration applies the maximum version.

A grid you can solve

The script below defines a 4 × 4 grid. The top-right square is a goal worth +10 and the square below it is a pit worth −10; both end the episode. Moves are unreliable: the intended move happens 80 percent of the time and the agent slips to each side 10 percent of the time. It computes V for a random policy, then V* and the greedy policy.

GAMMA = 0.9
N = 4                                           # 4x4 grid, state = (row, col)
GOAL, PIT = (0, 3), (1, 3)                      # goal +10 and pit -10 are terminal
MOVES = {"U": (-1, 0), "D": (1, 0), "L": (0, -1), "R": (0, 1)}
SIDE = {"U": "LR", "D": "LR", "L": "UD", "R": "UD"}
STATES = [(r, c) for r in range(N) for c in range(N)]

def step(s, move):
    r, c = s[0] + MOVES[move][0], s[1] + MOVES[move][1]
    return (r, c) if 0 <= r < N and 0 <= c < N else s       # bumping a wall: stay put

def transitions(s, a):
    """P(s'|s,a): 80% intended move, 10% each perpendicular. Returns [(prob, s', reward)]."""
    out = []
    for move, p in [(a, 0.8), (SIDE[a][0], 0.1), (SIDE[a][1], 0.1)]:
        s2 = step(s, move)
        out.append((p, s2, 10.0 if s2 == GOAL else -10.0 if s2 == PIT else 0.0))
    return out

def sweep(V, policy):
    """One Bellman backup per state. policy(s) -> {action: prob}, or None for 'take the best action'."""
    new = {}
    for s in STATES:
        if s in (GOAL, PIT): new[s] = 0.0; continue
        q = {a: sum(p * (r + GAMMA * V[s2]) for p, s2, r in transitions(s, a)) for a in MOVES}
        new[s] = max(q.values()) if policy is None else sum(pr * q[a] for a, pr in policy(s).items())
    return new

def show(V):
    for r in range(N):
        print("  " + " ".join("  goal" if (r, c) == GOAL else "   pit" if (r, c) == PIT else f"{V[(r,c)]:6.2f}" for c in range(N)))

V = {s: 0.0 for s in STATES}
for _ in range(200): V = sweep(V, lambda s: {a: 0.25 for a in MOVES})
print("V for the uniformly random policy (policy evaluation, gamma=0.9):"); show(V)

Vstar = {s: 0.0 for s in STATES}
for _ in range(200): Vstar = sweep(Vstar, None)
print("\nV* (value iteration):"); show(Vstar)

print("\ngreedy policy from V*:")
for r in range(N):
    row = []
    for c in range(N):
        s = (r, c)
        if s in (GOAL, PIT): row.append("*"); continue
        row.append(max(MOVES, key=lambda a: sum(p * (rw + GAMMA * Vstar[s2]) for p, s2, rw in transitions(s, a))))
    print("  " + " ".join(row))

print("\nReturn of rewards [0, 0, 0, 10] for different gamma:")
for g in (1.0, 0.9, 0.5):
    print(f"  gamma={g}: G = {sum(g**k * r for k, r in enumerate([0, 0, 0, 10])):.3f}")

Read the two tables as a pair. Under the random policy the values are small and many are negative, because wandering leads into the pit as often as to the goal; the squares next to the pit are worst. The policy printed below them says "go around": the square just left of the pit points up (away from it), and the square below the pit (row 2, column 3) heads down and then left rather than risking a slip into the pit. A policy can be read off the values with no extra search, which is the idea behind value functions and advantage in chapter 09.

A language model is a policy

A language model, as defined in A2 chapter 14, outputs for a given text a probability distribution over the next token. That is a policy πθ(a | s), where θ are the weights, the state s is the prompt plus the tokens generated so far, and the action a is one of the V tokens in the vocabulary. Generating a response of T tokens is an episode of T actions. The transition is deterministic (append the token). The reward is typically zero until the end and then a score for the whole response: a reward model's output for RLHF (chapter 12), pass or fail from a checker for verifiable rewards (chapter 14). Rewards that arrive only at the end are called sparse, and one of the main difficulties of the next chapters is deciding which of the T tokens deserves the credit.

There are two ways to look at this, and both are in use. In the token-level MDP view each token is an action and the state grows. In the bandit view the whole response is one action: the prompt is the context, a sampled response is the arm, and the reward arrives immediately. OpenAI's InstructGPT work (Ouyang et al., 2022) describes its PPO setup in just this way: the environment is a bandit environment that presents a random prompt, expects a response, produces a reward and ends the episode. The two views agree on the objective. The probability of a response is the product of its token probabilities, so the expected reward is the same however you count the actions. The script verifies this on a toy model with 3 tokens and 3-token responses, small enough to enumerate every response.

import itertools, math

V, T = 3, 3                                     # vocabulary {0,1,2}, responses of exactly 3 tokens
def policy(prefix):
    """pi(a | state): a toy 'language model'. The state is the prompt plus tokens so far (here, the prefix)."""
    logits = [0.5 * (prefix.count(a) == 0) + 0.3 * a for a in range(V)]   # likes new tokens, likes bigger ids
    z = [math.exp(x) for x in logits]
    return [x / sum(z) for x in z]

def reward(seq):                                # sparse: only the finished response is scored
    return 1.0 if len(set(seq)) == 3 and seq[-1] == 2 else 0.0

# View 1: a bandit whose arms are whole responses. Probability of an arm = product of token probabilities.
exp_bandit, total_p = 0.0, 0.0
for seq in itertools.product(range(V), repeat=T):
    p = math.prod(policy(seq[:t])[seq[t]] for t in range(T))
    exp_bandit += p * reward(seq); total_p += p
print(f"{V**T} possible responses, probabilities sum to {total_p:.6f}")
print(f"bandit view: expected reward = {exp_bandit:.6f}")

# View 2: an MDP with one decision per token and reward only at the last step (gamma = 1).
def value(prefix):                              # V^pi(state) by the Bellman expectation equation
    if len(prefix) == T: return reward(prefix)
    return sum(p * value(prefix + (a,)) for a, p in enumerate(policy(prefix)))
print(f"MDP view:    V^pi(start)     = {value(()):.6f}")
print(f"size of the real thing: V=128,000 tokens, T=500 gives 10^{500*math.log10(128000):.0f} responses")

Both views give 0.097911. The first sums over all 27 responses, weighting each reward by the product of token probabilities; the second walks the Bellman equation token by token. The last line is why nobody does this by enumeration for real: with a 128,000-token vocabulary (an illustrative size) and 500-token responses, there are about 102554 responses. We can only sample, which is why the algorithms in the next chapters estimate gradients from samples rather than computing them.

Three differences from the textbook setting are worth stating now, because they shape the algorithms.

  1. The action space is huge. There are V actions at every step, and the number of possible full responses grows exponentially with length, so value tables are out of the question and the policy is a neural network.
  2. The reward is a proxy. A reward model is a learned approximation of what people prefer (chapter 13). Pushing a policy hard against an imperfect reward finds its flaws.
  3. The starting policy is already good. RL begins from a pretrained, usually fine-tuned, model, not a random one. That is why a KL penalty that keeps the new policy near the old one is standard (chapter 8), and why exploration here means sampling varied responses at a reasonable temperature (decoding strategies) rather than random wandering.

Systems connection

The loop of act, observe, update is the feedback loop of any production system with monitoring. A recommender that learns from clicks, a cache that adapts its eviction policy, a load balancer that shifts traffic toward faster replicas: each is a bandit or MDP with a reward you can name. The engineering questions are the familiar ones from SLIs and SLOs: is the reward measuring what you actually care about, and what does exploring cost your users while you learn?

Analogy: choosing a restaurant in a new city

On a visit to a city you dine out each evening. Going back to the best place so far is exploitation; trying somewhere new is exploration. The best strategy explores early, when you know little and have many evenings left, and exploits more as the trip ends. That is why the UCB bonus shrinks with the number of visits, and why ε is often decayed over time.

Where it breaks down: a restaurant's quality is fairly stable and your reward is yours alone. A language model's training reward can be gamed, drifts as the model changes, and the "restaurants" being explored are generated by the agent itself.

State of play, October 2026

Whether to model language-model RL as a bandit over whole responses or as a token-level MDP is a design choice, and recent practice leans on the simpler view where the reward is only for the final answer, as in verifiable-reward training (chapter 14). Token-level credit assignment (rewarding intermediate reasoning steps) remains an active research area. The vocabulary in this chapter is stable; which algorithm is in fashion is not.

Key takeaways

  • RL learns a policy π(a | s) from scores, not examples. The loop is: observe state, act, receive reward and next state.
  • A bandit has no state; its one problem is exploration versus exploitation, measured by regret. Pure greedy has regret that grows in a straight line; tapering exploration does far better.
  • An MDP adds states and transitions. The return sums discounted rewards; value functions satisfy the Bellman recursion.
  • A language model is a policy over tokens: state is the text so far, action is the next token, reward is usually sparse and arrives at the end.
  • Counting the whole response as one action (bandit view) or each token as an action (MDP view) gives the same expected reward; the choice affects credit assignment and algorithm design.

Check your understanding

A bandit agent always pulls the arm with the highest current estimate and never explores. Its cumulative regret plot is a straight line rising with the number of pulls. What does that tell you?

  1. It is learning steadily and will soon flatten
  2. The rewards are too noisy to learn from
  3. It locked onto a suboptimal arm early and loses a roughly constant amount of reward on every pull
  4. It is exploring too much
A straight line means constant regret per pull: it keeps choosing an arm that is worse than the best by a fixed amount. Learning agents flatten as they stop picking poor arms. Over-exploration would also raise regret, but it would show as a gentle slope tied to the exploration rate, not early lock-in.

An episode's rewards are 0, 0, 0, 10, then it ends. With γ = 0.9, the return from the start is closest to:

  1. 7.3
  2. 6.6
  3. 9.0
  4. 10.0
The 10 is the fourth reward, so it is discounted by γ3 = 0.729, giving 7.29. The tempting 6.6 applies four discount factors (0.94 = 0.656), which would be right only if the first reward were itself discounted; 9.0 applies one discount; 10.0 ignores discounting.

What does the "Markov" property say about the state in an MDP?

  1. The state never changes
  2. Rewards are always positive
  3. The agent can see the complete state of the whole world
  4. The state summarises everything about the past that matters for the future, so the next state and reward depend only on the current state and action
Markov is a statement about sufficiency of the state, not about visibility or reward sign. If something relevant to the future is missing from the state (whose turn it is), the problem is not Markov and the state must be enlarged.

In the toy language model script, the bandit-view expected reward and the MDP-view value are both 0.097911. Why must they agree?

  1. Because the toy vocabulary is small
  2. Because the probability of a whole response is the product of its token probabilities, so both views compute the same expectation of the same reward
  3. Because the reward is zero for most responses
  4. Because γ is less than 1
Both compute the average reward over responses drawn from the policy, one by summing over complete responses and one recursively token by token. Size and sparsity of the reward are irrelevant to the identity, and the example uses γ = 1.

Which feature most distinguishes RL for a language model from the textbook gridworld?

  1. The environment has no reward
  2. The agent knows the transition probabilities
  3. The action space is a vocabulary of tens of thousands of tokens, the reward is usually sparse and a learned proxy, and the policy starts from an already capable model
  4. The agent can only act once
These three properties drive the design of PPO, GRPO and the KL penalty. In a language model the transitions are known (append the token), so the second option has it backwards, and the reward exists but arrives late.

An online experiment shifts traffic toward the better of two ranking functions while it is still collecting data. Which description fits?

  1. A bandit with two arms, trading exploration for reward during the run
  2. A fixed A/B test, because the arms are compared
  3. An MDP, because the arms are compared repeatedly
  4. Supervised learning, because there are two classes
Adjusting allocation as evidence arrives is the bandit trade-off. A classical A/B test keeps the split fixed and decides at the end. It is not an MDP because the choice for one request does not change the next request's situation, and nothing is being fitted to labels.
