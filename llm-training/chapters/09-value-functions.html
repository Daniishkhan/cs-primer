Value Functions & Advantage

The method of chapter 8 multiplies every token's probability ratio by an advantage. The advantage is how much better than expected that token turned out to be. Where does the "expected" come from? This chapter introduces the value function, which is a learned prediction of future reward. It introduces the temporal-difference error that trains the value function. Then it introduces generalised advantage estimation (GAE), a dial that trades bias for variance.

Why this matters

In chapter 7 a baseline reduced the variance of the policy gradient. In chapter 8 proximal policy optimisation (PPO) used advantages without asking how they were made. A poor advantage estimate is the most common quiet failure of reinforcement learning fine-tuning. The loss looks fine, and the policy learns the wrong thing or learns slowly. It is also the reason modern reasoning-model recipes (chapter 14) drop the learned critic altogether. You can only judge that trade if you know what the critic was doing. After this chapter you will be able to compute these advantages by hand and explain what λ and γ control. You will also be able to describe what a value head is and why it is hard to train for language models.

Return, value and advantage

A reinforcement learning (RL) agent collects rewards as it acts. The return from step t is the sum of all rewards from then on. Each reward can optionally be shrunk by a discount factor γ between 0 and 1 for every step of delay:

Gt = rt + γ rt+1 + γ2 rt+2 + …

With γ = 1 the return is a plain sum. That means no discounting, which is the usual choice for language models. Their episodes are finite and their reward is about the whole response. Chapter 6 introduced returns and discounting. Here we need three quantities built from them.

Value V(s)
The expected return if you are in state s and then follow the current policy: V(s) = E[Gt | st = s]. A prediction of how well things will go from here.
Action value Q(s,a)
The expected return if you are in s, take action a now, and follow the policy afterwards.
Advantage A(s,a)
Q(s,a) − V(s). How much better than the policy's average this particular action is. Positive: better than usual. Negative: worse. Zero on average, by construction.

The advantage is the right quantity to multiply a gradient by. The policy gradient says "make the sampled action more likely in proportion to how good it was". "Good" should mean good relative to what was typical in this state. A reward of 5 is a triumph in a state where most actions earn 1. It is a disappointment where most earn 9. Subtracting V(s) is exactly the baseline of chapter 7. Among baselines that depend only on the state, V(s) has the lowest variance.

The language-model reading

Take a six-token response to a prompt. The state at position t is the prompt plus the first t tokens. The value V(st) is a prediction of the final reward-model score given the text so far. Before writing anything it is the average score of responses to this prompt. After a confident, correct first sentence it should rise. After a refusal to answer a plainly harmless question it should fall. The advantage of the token chosen at position t is the amount by which that choice moved the prediction. That reading makes the next idea natural.

Analogy: the win-probability commentator

Watch a football match with a live win-probability graph. Before kick-off the graph says 50%. A goal moves it to 80%. A red card for the same team moves it to 55%. The change at each moment is the sport's version of an advantage. It credits the play that caused the shift and ignores the history that was already priced in. The graph itself is a value function. The length of each jump is a temporal-difference error, defined next.

Where it breaks down: the commentator's model was fitted on thousands of finished matches by someone else. A critic in RL is learning at the same time as the policy it is judging changes. So its target keeps moving, and early in training it knows almost nothing.

The Bellman equation and the TD error

A return can be split into the next reward and the return from the next state: Gt = rt + γ Gt+1. Taking expectations gives the Bellman equation for the value function:

V(st) = E [ rt + γ V(st+1) ]

The value of a state is the reward you expect next plus the discounted value of where you expect to land. This is a statement about consistency. Suppose our estimate Vφ were exactly right. Then for every transition rt + γ Vφ(st+1) − Vφ(st) would average to zero. When it does not, the difference is an error signal. It is called the temporal-difference (TD) error:

δt = rt + γ Vφ(st+1) − Vφ(st)

Read it as "what I just saw (the reward, plus my estimate of what comes next) minus what I had predicted". It is the commentator's jump in the win-probability graph. A positive δ means the step went better than the critic expected. Two uses follow, and they are the two halves of this chapter:

  • Training the critic. Nudge Vφ(st) towards rt + γ Vφ(st+1). This is TD learning, and because it targets an estimate rather than a final outcome it is called bootstrapping.
  • Estimating the advantage. The sampled action's contribution is rt + γV(st+1) − V(st) = δt: a one-step advantage estimate.

Monte Carlo against TD, with numbers

There are two ways to learn V. The first is Monte Carlo (MC). Wait for the episode to end, then move every visited state's value towards the actual return. It is unbiased, because the target is a real outcome. But it is noisy, because a whole episode of luck lands in one number. The second is TD(0). After each step, move the value towards the one-step target. It is biased, because the target uses the current, imperfect estimate of the next state. But it is much less noisy, since it contains only one real reward and everything else is the critic's smoothed opinion.

The classic test is the five-state random walk (Sutton and Barto, 2018). An agent starts in the middle state C and steps left or right with equal probability. Leaving the right end pays 1 and leaving the left end pays 0. The true values are 1/6, 2/6, 3/6, 4/6 and 5/6. We run both learners with the same step size. We measure the root-mean-square error of the five estimates, averaged over 300 independent runs.

import numpy as np
# 5-state random walk (Sutton & Barto): start in C, step left/right with prob 1/2.
# Falling off the right end pays 1, the left end 0. True values are 1/6 ... 5/6.
true_v = np.arange(1, 6) / 6
def episode(rng):
    s, states = 2, [2]
    while 0 <= s <= 4:
        s += rng.choice((-1, 1))
        if 0 <= s <= 4: states.append(s)
    return states, float(s == 5)          # reward only at the end

def run(method, alpha, seed, n_ep=100):
    rng = np.random.default_rng(seed)
    v = np.full(5, 0.5); errs = []
    for _ in range(n_ep):
        states, G = episode(rng)
        if method == "mc":                 # move every visited state towards the final return
            for s in states: v[s] += alpha * (G - v[s])
        else:                              # TD(0): bootstrap from the next state's estimate
            for i, s in enumerate(states):
                nxt = v[states[i + 1]] if i + 1 < len(states) else G
                v[s] += alpha * (nxt - v[s])
        errs.append(np.sqrt(np.mean((v - true_v) ** 2)))
    return np.array(errs)

print("RMS error of the 5 value estimates, mean of 300 runs, alpha = 0.05")
print(f"{'episode':>8} {'Monte Carlo':>12} {'TD(0)':>8}")
mc = np.mean([run("mc", 0.05, s) for s in range(300)], axis=0)
td = np.mean([run("td", 0.05, s) for s in range(300)], axis=0)
for e in (1, 5, 10, 25, 50, 100):
    print(f"{e:8d} {mc[e-1]:12.3f} {td[e-1]:8.3f}")

Bias and variance: the dial between TD and Monte Carlo

The same trade-off appears when we estimate advantages instead of values. Using the critic for one step gives δt. Using it after n steps gives the n-step advantage:

A(n)t = rt + γ rt+1 + … + γn−1 rt+n−1 + γn V(st+n) − V(st)

and using it never (run to the end of the episode) gives the Monte Carlo advantage Gt − V(st). The ends of the range behave like this:

One step: δt

Low variance: one real reward, everything else from the critic. Biased to the extent the critic is wrong, and early in training it is very wrong. Credit travels only one step per update, so a reward at the end of a long response reaches early tokens slowly.

Whole episode: Gt − V(st)

Unbiased: the target is what actually happened. High variance: every random sampled token and reward after step t adds noise, and the sum grows with the length of the response.

Generalised advantage estimation

Schulman et al. (2016, "High-Dimensional Continuous Control Using Generalized Advantage Estimation") blended all the n-step estimators with exponentially decaying weights. One parameter λ between 0 and 1 controls the decay. The result has a compact form, a discounted sum of future TD errors:

Plug in numbers. A four-step episode with the reward at the end and made-up critic values. Each row compares a different λ, and the last row checks that λ = 1 matches the plain return minus the critic's guess.

The idea

  1. delta[t] ← reward[t] + gamma × V[t+1] − V[t]
  2. A[t] ← sum over l of (gamma × lambda)^l × delta[t+l]
  3. compare lambda = 0, 0.5, 0.95, 1; check lambda = 1 against G − V
"""Generalised advantage estimation, by hand, for a 4-step episode.
Rewards and critic values are made up."""

GAMMA = 1.0                               # discount (RLHF usually uses 1)
REWARD = [0.0, 0.0, 0.0, 1.0]             # r_t: paid at the last step only
VALUE = [0.4, 0.5, 0.6, 0.8, 0.0]         # V(s_t); 0 after the episode ends

# ── 1. TD errors: reward + discounted next value - this value ────────────
T = len(REWARD)
delta = [REWARD[t] + GAMMA * VALUE[t + 1] - VALUE[t] for t in range(T)]
print("delta_t      ", " ".join(f"{d:+.2f}" for d in delta))


def gae(lam):
    """A_t = sum over l of (gamma * lam)^l * delta_{t+l}  (steps 2 and 3)."""
    out = []
    for t in range(T):
        total, weight = 0.0, 1.0
        for l in range(T - t):            # sum to the end of the episode
            total += weight * delta[t + l]
            weight *= GAMMA * lam         # each step further: x gamma*lam
        out.append(total)
    return out


# ── 2. Blend them: lambda = 0 is one step, lambda = 1 is Monte Carlo ─────
for lam in (0.0, 0.5, 0.95, 1.0):
    print(f"A_t, lam={lam:<4}", " ".join(f"{a:+.2f}" for a in gae(lam)))

# ── 3. Check the two ends against their definitions ──────────────────────
G = [sum(GAMMA ** k * REWARD[t + k] for k in range(T - t)) for t in range(T)]
mc = [G[t] - VALUE[t] for t in range(T)]
print("G_t - V(s_t) ", " ".join(f"{a:+.2f}" for a in mc))

Go deeper why the weighted n-step mixture is this sum

Write the n-step advantage as a sum of TD errors. The value terms telescope: V(st+1) added by δt is cancelled by the −V(st+1) in γδt+1, and so on, leaving

A(n)t = δt + γ δt+1 + … + γn−1 δt+n−1.

Now average the n-step advantages with weights (1 − λ) λn−1, which sum to 1:

(1 − λ) ∑n≥1 λn−1 A(n)t.

The error δt+l appears in every A(n) with n > l, with coefficient γl. Its total weight is therefore γl (1 − λ) ∑n>l λn−1 = γl λl. This uses the geometric series ∑n>l λn−1 = λl / (1 − λ). That is the formula above. At the extremes, λ = 0 keeps only δt. At λ = 1 the sum gives ∑ γl δt+l, which telescopes to the Monte Carlo advantage Gt − V(st).

The two parameters have different jobs. γ is part of the problem definition. It sets how much a later reward matters. λ is a purely statistical knob. It sets how far to trust the critic. λ = 0 uses only δt, which gives low variance and critic bias. λ = 1 is Monte Carlo, which gives no critic bias and high variance. Typical settings for reinforcement learning from human feedback (RLHF) are γ = 1 and λ = 0.95. This is also the PPO default in Hugging Face's Transformer Reinforcement Learning (TRL) library (see the dated note).

Computing it: a backwards recursion

Computing the infinite sum directly is wasteful. Because At = δt + γλ At+1, one backwards pass over the response does it in O(T). Below, a six-token response has a tiny Kullback-Leibler (KL) penalty on every token, as in chapter 8. A reward-model score of 1.8 is added at the last token. The critic's predictions are roughly right but not exact.

import numpy as np
# GAE for one rollout, computed backwards:  A_t = delta_t + gamma*lam*A_{t+1}
def gae(rewards, values, gamma=1.0, lam=0.95):
    T = len(rewards)
    values = np.append(values, 0.0)              # the value after the last token is 0 (episode over)
    adv = np.zeros(T); running = 0.0
    for t in reversed(range(T)):
        delta = rewards[t] + gamma * values[t + 1] - values[t]
        running = delta + gamma * lam * running
        adv[t] = running
    return adv, adv + values[:-1]                # advantages and value targets (returns)

# A 6-token response: tiny KL penalties on every token, reward-model score 1.8 on the last.
rewards = np.array([-0.01, -0.02, -0.01, -0.03, -0.01, 1.77])
values  = np.array([ 0.40,  0.45,  0.50,  0.40,  0.80, 1.10])   # a critic that is roughly right
mc_return = np.cumsum(rewards[::-1])[::-1]
print("MC return-to-go  :", np.round(mc_return, 2))
print("critic V(s_t)    :", values)
for lam in (0.0, 0.5, 0.95, 1.0):
    a, _ = gae(rewards, values, lam=lam)
    print(f"GAE lambda={lam:<4}  :", np.round(a, 2))
print("(lambda=1 equals return-to-go minus V:", np.round(mc_return - values, 2), ")")

Read the rows. The return-to-go is about 1.7 at every position, because nearly all the reward arrives on the last token. At λ = 1 the advantage at token 1 is 1.29. That says "this whole response ended up 1.29 better than the critic expected at the start". At λ = 0 it is 0.04. The first token's one-step surprise is almost nothing, because the critic's prediction barely changed between positions 1 and 2. The news of the high score has not propagated back. At λ = 0.95 the news has travelled most of the way (1.04). The last token has advantage 0.67 at every λ, since there is nothing after it to bootstrap from: 1.77 − 1.10.

Now the trade-off itself, measured. The simulation below builds an environment where the answer is known. A flag chosen at step 0 changes nothing immediately. It adds 0.2 to the reward at each of steps 1 to 5. So the true advantage gap between flag = 1 and flag = 0 is exactly 1.0. Rewards carry unit-variance noise over 40 steps. The critic understands the flag but undervalues its effect by 40%, so it predicts 0.6 of the true value. This stands in for an imperfect learned critic. For each λ we estimate the advantage at step 0. We report the gap it implies, how far that is from 1.0, and the spread of the estimate.

import numpy as np
rng = np.random.default_rng(0)
T, SIGMA, KAPPA, EPISODES = 40, 1.0, 0.6, 20000
# Step 0 picks a flag f in {0,1}. It changes nothing immediately, but adds +0.2 to the reward at
# each of steps 1..5, so the true advantage gap between f=1 and f=0 is 5 * 0.2 = 1.0.
# Rewards carry N(0, 1) noise. The critic knows the flag but under-values it: V_hat = 0.6 * V.
def remaining(t): return max(0, 6 - t) if t >= 1 else 5      # rewards at steps >= t that depend on f
def v_hat(t, f):
    if t >= T: return 0.0
    return KAPPA * 0.2 * remaining(t) * (f if t >= 1 else 0.5)  # at step 0 the flag is not yet chosen

def adv0(f, lam, noise):
    r = noise.copy()
    r[1:6] += 0.2 * f
    delta = np.array([r[t] + v_hat(t + 1, f) - v_hat(t, f) for t in range(T)])
    w = lam ** np.arange(T)
    return float(np.dot(w, delta))                               # GAE at t = 0 with gamma = 1

print(f"{'lambda':>7} {'gap f=1 minus f=0':>18} {'bias':>6} {'std of estimate':>16}")
for lam in (0.0, 0.5, 0.9, 0.95, 0.99, 1.0):
    est = {0: [], 1: []}
    for _ in range(EPISODES // 2):
        noise = rng.normal(0, SIGMA, T)           # same noise for both flags, so the gap is exact
        for f in (0, 1):
            est[f].append(adv0(f, lam, noise))
    gap = np.mean(est[1]) - np.mean(est[0])
    sd = np.std(est[1])
    print(f"{lam:7.2f} {gap:18.3f} {gap-1.0:6.3f} {sd:16.3f}")

The pattern is the one the theory predicts. At λ = 0 the gap is 0.600. That is a 40% shortfall, exactly the critic's undervaluation. But the estimate is tight (spread 1.0). At λ = 1 the gap is exactly right, but the estimate is six times noisier. In between, λ = 0.95 recovers 94% of the signal at half the noise. These numbers describe this toy, not a law. The best λ depends on how good your critic is and how noisy your reward is.

Common misconception

"The advantage is just the reward, or the reward minus the average reward of the batch." Subtracting a batch mean is a baseline, but it is the same number for every token. A learned value function varies by state. It knows that a reward of 1 would be good news in the middle of a response that has already gone wrong. It knows that the very first token of an easy prompt starts from a high expectation. That state-dependent baseline removes variance that a batch average cannot. A critic-free method has to replace it some other way. Chapter 14 uses the average over several answers to the same prompt.

Value models for language models

In an LLM the critic is usually a copy of the language model with its output layer swapped. The value head is a single linear layer. It maps each position's final hidden state (C numbers, in A2's notation) to one number, V(st). The original output layer maps it to V logits over the vocabulary instead. One forward pass over a B×T batch yields B×T values.

The critic is trained with a squared error against a target. This is the value target Vttarget = At + Vold(st). It is the GAE advantage added back to the value that was predicted when the data was collected. The code above returns it as the second output of gae. PPO implementations also clip the value update, with the same logic as the policy clip, using cliprange_value.

Why critics are hard for language models

  • Sparse, late reward. Nearly all reward arrives on the final token. The value of an early token is a prediction of a score that depends on hundreds of later choices not yet made. Early-position values are therefore close to "the average score for this prompt", and the critic's useful signal is concentrated near the end.
  • Cost. A full-size critic doubles the trained-model memory. It is trained on the same batch, so it also adds to the time per iteration.
  • Accuracy on reasoning. Kazemnejad et al. (2024, "VinePPO") report that PPO's value networks produce poor estimates of expected return on reasoning-heavy tasks. When comparing alternative reasoning steps, they barely beat a random baseline. If the critic's ranking of steps is that weak, the advantage it produces carries little credit-assignment information beyond the final outcome.
  • Moving target. The critic estimates the value of the current policy, which changes every iteration. A critic that lags behind produces biased advantages.

These problems motivate the simplest alternative. Skip the critic and use the average reward of several samples for the same prompt as the baseline. Ahmadian et al. (2024, "Back to Basics") argue that for RLHF, simpler REINFORCE-style methods of this kind outperform PPO. Many of PPO's design choices matter less when the policy starts from a strong pretrained model. Chapter 14 develops one such method in full, group relative policy optimisation (GRPO). Everything in this chapter still applies there. The baseline is still an estimate of V(s), only produced by sampling instead of by learning.

Systems connection

Estimating a value from samples is the same statistical problem as estimating a latency percentile or an error rate from a trace sample. The estimator's variance falls only as 1/n. So you buy accuracy with more samples or with structure, and a critic is structure. That is why both service metrics and RL training logs reward looking at distributions rather than single numbers. The memory price of a critic is the ledger of chapter 2.

State of play, October 2026

TRL's experimental PPOTrainer takes a separate value_model. It defaults to gamma=1.0, lam=0.95, vf_coef=0.1 and cliprange_value=0.2 (TRL documentation, fetched October 2026). According to secondary coverage of TRL v1.0, the critic-free trainers are the stable RL trainers in the same library. They are GRPO and leave-one-out REINFORCE (RLOO). Whether a learned critic returns to favour for long-horizon agentic tasks is an open question in the literature, not a settled one. In those tasks responses are very long and rewards sparser.

Key takeaways

  • Value V(s) is the expected future return from a state; advantage A = Q − V says how much better than usual an action was. Policy gradients should be weighted by advantages, not raw returns.
  • The TD error δt = rt + γV(st+1) − V(st) is the critic's surprise. It trains the critic and is a one-step advantage estimate.
  • Monte Carlo targets are unbiased and noisy; bootstrapped targets are biased and smooth. In the random walk, TD(0) reached an error of 0.036 while Monte Carlo stalled at 0.116.
  • GAE = ∑(γλ)lδt+l, computed with one backwards pass. λ sets the bias-variance balance. 0 trusts the critic, 1 trusts the sampled outcome, and 0.95 is the usual compromise.
  • For an LLM the critic is a value head giving one number per token. It is costly, slow to become accurate with sparse terminal rewards, and a reason many recent recipes replace it with a group baseline.

Check your understanding

A critic predicts a value of 0.40 for the state before a token, and 0.45 for the state after it. The token earned no immediate reward and γ = 1. What is the TD error and what does it say?

  1. 0.40: the token was worth 0.40
  2. −0.05: the token made things slightly worse than expected
  3. +0.05: the token left the prospects slightly better than the critic had predicted
  4. 0.85: the sum of the two values
δ = r + γV(s') − V(s) = 0 + 0.45 − 0.40 = +0.05. The sign convention is "after minus before". Option 2 reverses it. Option 4 adds values, which has no meaning here.

Why does TD(0) reach a lower error than Monte Carlo in the random-walk experiment at a fixed step size?

  1. Its target uses one real reward plus the critic's smoothed estimate, so it carries much less random noise than a whole-episode return
  2. It is unbiased, while Monte Carlo is biased
  3. It sees more data per episode than Monte Carlo does
  4. It uses a larger effective step size
The two methods see the same episodes and use the same step size. TD(0) is the biased one (option 2 has it backwards), and it wins at a fixed step size because its low-noise target avoids the constant jostling that keeps Monte Carlo's error up.

In GAE, setting λ = 1 gives which estimator, and what is its main weakness?

  1. The one-step TD error; it is biased by the critic
  2. The Monte Carlo advantage Gt − V(st); its variance grows with the length of the rest of the episode
  3. The batch-mean baseline; it ignores state
  4. The Q-function; it needs a second network
With λ = 1 the TD errors telescope into the full return minus the starting value. It has no critic-induced bias beyond the baseline, but every later random reward adds noise. Option 1 is λ = 0. In the simulation the standard deviation went from 1.0 at λ = 0 to 6.3 at λ = 1.

A 40-token response gets a single reward on the last token. With λ = 0, how quickly does that reward influence the advantage of the first token in one iteration?

  1. Fully, because the reward is the only signal
  2. Fully, because advantages are always computed over the whole episode
  3. Not at all, because rewards are never used for earlier tokens
  4. Only through the critic: the first token's advantage depends on r0 and the change in predicted value, so the news travels backwards one step per iteration as the critic learns
λ = 0 uses only δ0 = r0 + γV(s1) − V(s0). The terminal reward reaches it only after the critic has learned to predict it at positions 1 and 0. A λ close to 1 carries the news directly through the sum of later errors, which is why 0.95 is popular for sparse rewards.

  1. The baseline is no longer an estimate of V(s)
  2. The policy gradient becomes biased, because the baseline depends on the samples
  3. It is still an estimate of the prompt's value; it removes the critic's memory and training cost but gives one number per prompt, not per token
  4. It removes all variance from the gradient
The group mean estimates the expected reward for the prompt, i.e. V of the starting state. Because it is one number per response, every token in a response shares the same advantage: credit assignment inside the response is lost. The baseline is mildly correlated with each sample (leave-one-out versions fix that), but the main cost is coarse credit assignment, not bias. Variance is reduced, not removed.

In the GAE-trade-off simulation, what happens to the bias column if the critic is made perfect (KAPPA = 1.0)?

  1. Every λ becomes unbiased and λ = 0 becomes the best choice, with the lowest noise
  2. Only λ = 1 is unbiased, as before
  3. The bias becomes positive for small λ
  4. Nothing changes, because bias comes from the reward noise
The bias at small λ came entirely from the critic undervaluing the flag. With an exact critic, the one-step TD error already has the right expectation, so the extra terms at larger λ add only noise. A better critic moves the optimum λ down.
