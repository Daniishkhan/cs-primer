RL with Verifiable Rewards & GRPO

When a program can check an answer, you do not need a learned reward model or a critic. You sample several answers to the same question, check each one, and push the model towards the ones that passed. This chapter explains the verifiable-reward recipe, derives Group Relative Policy Optimisation (GRPO) and its advantage, shows where it is biased and where it has no signal, and describes how it produced the first open reasoning models.

Why this matters

Chapter 13 ended on a problem: learned rewards get exploited. The answer that dominates current practice for maths, code and other checkable tasks is to remove the learned reward altogether and use a verifier, then train with the cheapest algorithm that works. That combination is behind the reasoning models that think for thousands of tokens before answering. If you understand the group advantage, you can read a GRPO training log, spot the groups that teach nothing, choose between its variants (library defaults differ from the original paper), and say what RL on verifiable tasks does and does not add to a model. After this chapter you will be able to write a reward function and its failure cases, derive and compute the group-relative advantage, state its bias, estimate whether a run fits on one 24 GB card, and explain the pass@k debate.

Rewards a program can check

A verifiable reward is one computed by a program that checks the answer against ground truth, not a network that predicts what a person would think. The training method that uses it is called RLVR, reinforcement learning with verifiable rewards, a name introduced by the Tülu 3 paper (Lambert et al., 2024), which describes it as an RL stage that obtains a constant reward when a completion is successful. Their reward is v(x, y) = α if the answer is correct and 0 otherwise, with α = 10 chosen from pilot experiments and not tuned further, inside the same KL-regularised objective as in chapter 8:

maximise Ey∼πθ(·|x) [ v(x, y) − β KL( πθ(y|x) ‖ πref(y|x) ) ]

Tülu 3 optimised this with PPO over about 30,000 prompts with ground-truth answers drawn from three sources: GSM8K and MATH (maths word problems with a final number or expression to compare) and prompts with precise instruction-following constraints, each of which has its own checking function. Which tasks qualify? Anything with a cheap, mostly unambiguous check:

  • Maths with a final answer. Extract the answer from a marked place (a \boxed{}, an "Answer:" line) and compare.
  • Code with tests. Run the program on unit tests and reward the fraction that pass. A compiler gives feedback on predefined test cases, as DeepSeek-R1's paper puts it for LeetCode-style problems.
  • Format and constraints. "Answer in under 50 words", "include three bullet points", "output valid JSON matching this schema": a parser decides.
  • Games, puzzles and simulators. Sudoku, a unit-conversion task, a SQL query whose result set can be compared with the expected one.

The DeepSeek-R1 paper (DeepSeek-AI, 2025) used exactly this for its first model, R1-Zero: an accuracy reward (is the final answer correct? for code, do the tests pass?) plus a format reward that required the reasoning to be inside <think> tags. They state they used no outcome or process neural reward model, because they found a neural reward model may suffer from reward hacking in large-scale RL and because retraining it complicates the pipeline. The reward is only a few lines of code.

Writing the verifier is the work

A verifier is a specification, and a specification can have loopholes. The policy is a search procedure aimed at the loopholes (chapter 13's adversarial Goodhart), so the verifier must be tested as hard as the model. Here are two reward functions for the question "17 × 23", whose answer is 391, scored on six hand-written completions:

import re

def strict_reward(completion: str, gold: str) -> float:
    """Reward 1.0 only if the LAST \\boxed{...} holds exactly the gold answer."""
    boxes = re.findall(r"\\boxed\{([^{}]*)\}", completion)
    return 1.0 if boxes and boxes[-1].strip() == gold else 0.0

def lazy_reward(completion: str, gold: str) -> float:
    """A tempting shortcut: reward any completion that mentions the gold answer."""
    return 1.0 if gold in completion else 0.0

gold = "391"                      # 17 * 23
completions = {
    "correct":            "17*23 = 17*20 + 17*3 = 340 + 51 = 391. \\boxed{391}",
    "wrong":              "17*23 = 17*20 + 17*3 = 340 + 41 = 381. \\boxed{381}",
    "right, no box":      "The product is 391.",
    "shotgun":            "It could be 381, 389, 391, 393 or 401.",
    "changed mind":       "First I got 391, but I slipped on the carry. \\boxed{381}",
    "box mentions answer": "\\boxed{3910}",
}
print(f"{'completion':22} {'strict':>6} {'lazy':>5}")
for name, c in completions.items():
    print(f"{name:22} {strict_reward(c, gold):6.1f} {lazy_reward(c, gold):5.1f}")

The lazy verifier rewards four completions that should not be rewarded. The "shotgun" completion lists five candidate answers, one of which is right: a model that learns to hedge this way scores 1.0 on every problem whose answer it can bracket, and learns nothing about arithmetic. "Changed mind" mentions the right number and then commits to the wrong one. The strict verifier fixes these by reading only the last boxed value and requiring an exact match, and it has its own cost: the correct completion without a box gets 0, which is deliberate (the format is part of the contract, and the format reward in R1-Zero exists to teach it), but the penalty falls on correct content. Real verifiers need more: normalise equivalent forms (1/2 and 0.5), apply a timeout, and, for code, run the program in a sandbox, because it is untrusted code written by a model that is being rewarded for passing your tests (it can special-case the test inputs, read the test file or call out over the network).

Systems connection

A code-execution reward is a service that runs arbitrary code from a source you are deliberately training to be inventive. The controls are the ones from container isolation and least privilege: no network, no host filesystem, CPU, memory and wall-clock limits, a fresh sandbox per sample, and held-out tests the policy never sees. It is also a throughput problem: tens of thousands of executions per training step, which makes the verifier fleet a capacity-planning item alongside the GPUs.

What PPO's critic was for, and why to drop it

PPO needs advantages (chapter 9): for each token, how much better was this than expected? Expected is supplied by a learned value model, a second network as large as the policy. Chapter 12's memory table priced PPO at 36 bytes per parameter across its four models. For language models the critic is also hard to train (chapter 9): it must predict final reward from a half-written answer, and early on it is wrong about nearly everything.

Chapter 7 showed that a baseline does not need to be a learned function of the state. It needs only to be something that does not depend on the action being scored. For a verifiable task there is an obvious candidate: sample several answers to the same question and use their average reward as the baseline. Shao et al. (2024, "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models") introduced this as Group Relative Policy Optimisation, a variant of PPO that improves mathematical reasoning while reducing PPO's memory use; their DeepSeekMath 7B reached 51.7 percent on the MATH benchmark without tools or voting, and 60.9 percent with self-consistency over 64 samples.

Analogy: comparing your own attempts

You are practising a puzzle with an answer key at the back. You attempt it eight different ways, check each against the key, and notice that two worked. You do not need a coach telling you how hard the puzzle is in general; the attempts themselves set the bar. Attempts better than your average on this puzzle get repeated, the rest get dropped. GRPO is that loop: the baseline is how your other attempts at the same question did.

Where it breaks down: you know why an attempt worked and carry the idea to the next puzzle. The model only shifts probability towards the token sequences that were in the winning attempts, and on a puzzle where all eight attempts fail, you would at least change your approach, while GRPO's update for that group is exactly zero.

The GRPO objective

For each question q in a batch, sample a group of G answers o1, …, oG from the current ("old") policy and score each with the verifier to get rewards r1, …, rG. The advantage of answer i is its reward standardised within the group (equation 3 of the DeepSeek-R1 paper):

Âi = ( ri − mean(r1, …, rG) ) / std(r1, …, rG)

Every token of answer i receives the same advantage Âi: the verifier judges the whole answer, and GRPO does not try to say which tokens were responsible. The policy update is then PPO's clipped objective from chapter 8, with ratio ρi,t = πθ(oi,t | q, oi,<t) / πold(oi,t | q, oi,<t) for token t of answer i, plus a KL penalty to the reference, now written as a term in the loss and not folded into the reward:

Plug in numbers. One question, a group of G = 4 answers (two correct), ratios and probabilities made up for each token. The script follows the steps: standardise the rewards, then for each answer clip, subtract the KL fee and average over its tokens, then average over the group.

The idea

  1. A_i ← (reward_i − mean) / std over the group of 4
  2. per token: surrogate ← min(rho × A, clip(rho, 0.8, 1.2) × A)
  3. per token: k3 ← q − log q − 1; score ← surrogate − beta × k3
  4. per answer: average its token scores; J ← average over the group
"""The GRPO objective, by hand: one question, a group of G = 4 answers.
Ratios and probabilities are made up; a real run gets them from the model."""
import math
import statistics

EPS, BETA = 0.2, 0.04                     # clip range; KL weight

# ── 1. A group: verifier reward, then each token's ratio and KL inputs ───
# Per token: (rho = pi_theta / pi_old,  pi_ref / pi_theta)
GROUP = [
    (1.0, [(1.30, 0.9), (0.95, 1.0)]),              # correct, 2 tokens
    (0.0, [(0.85, 1.1), (1.05, 1.0), (1.10, 0.9)]), # wrong, 3 tokens
    (0.0, [(0.70, 1.2), (1.00, 1.0)]),              # wrong, 2 tokens
    (1.0, [(1.10, 1.0), (1.00, 1.0), (0.90, 1.1)]), # correct, 3 tokens
]

# ── 2. Advantage: reward standardised within the group ───────────────────
rewards = [g[0] for g in GROUP]
mean, std = statistics.fmean(rewards), statistics.pstdev(rewards)
adv = [(r - mean) / std for r in rewards]
print(f"mean {mean:.2f}  std {std:.2f}  advantages",
      " ".join(f"{a:+.2f}" for a in adv))


def clip(x, lo, hi):
    """Force x into [lo, hi]."""
    return max(lo, min(hi, x))


# ── 3. Per token: clipped term minus beta * KL, averaged within answer ───
print()
print("answer  tokens  mean over tokens")
total = 0.0
for i, ((_, tokens), A) in enumerate(zip(GROUP, adv)):
    per_token = []
    for rho, q in tokens:
        surrogate = min(rho * A, clip(rho, 1 - EPS, 1 + EPS) * A)
        k3 = q - math.log(q) - 1          # >= 0 estimate of the KL
        per_token.append(surrogate - BETA * k3)
    answer = sum(per_token) / len(per_token)        # the 1/|o_i| sum
    total += answer
    print(f"  {i + 1}       {len(tokens)}      {answer:+.4f}")

# ── 4. Average over the group: the 1/G sum ───────────────────────────────
print()
print(f"J = {total / len(GROUP):+.4f}")

with the KL estimated per token by DKL = πref/πθ − log(πref/πθ) − 1, which is the always-non-negative estimator "k3" that chapter 8 compared with k1 and k2. (The R1 paper writes the ratio at the level of whole answers; the DeepSeekMath paper and most libraries use the per-token form above, and TRL lets you choose between token-level and sequence-level ratios.) Four things to notice.

  1. The baseline is free. There is no value network to train, store or update. The only extra cost is generating G answers per question and not one.
  2. It is relative. The same absolute reward is a good outcome in a hard group and an ordinary one in an easy group. The advantage encodes "better than my other attempts at this question".
  3. Zero when everyone ties. If all G answers get the same reward, every Âi is 0: the whole group contributes no gradient. (Division by a zero standard deviation is guarded in implementations, usually by a small constant.)
  4. The KL term can be dropped. TRL's GRPOConfig defaults to beta=0.0, and documents that in that case the reference model is not even loaded, which saves memory. The PPO clip still limits each step.
Step through

One GRPO iteration for one question

  1. One question, one policy. Take a prompt with a checkable answer and the current policy (the "old" policy, frozen for this iteration). Real runs use G = 8 or more answers; four fit the picture.
  2. Sample a group. Generate G answers to the same prompt at a non-zero temperature, so that they differ. This is the expensive step, and it is why a serving engine sits inside a GRPO trainer.
  3. Check each answer. The verifier returns a reward per answer: here 1 for a correct boxed answer and 0 otherwise. No model is involved.
  4. Compare with the group. Two of four were correct, so the mean is 0.5 and the standard deviation 0.5.
  5. Standardise. Correct answers get advantage +1, wrong ones −1. Had only one answer been correct, it would have received +1.73 and each wrong one −0.58: the rare event stands out.
  6. Update. Each token of each answer is weighted by its answer's advantage in PPO's clipped objective. Tokens of correct answers become likelier, tokens of wrong ones less likely, and the next iteration samples from the improved policy.

Is the group mean a valid baseline?

Chapter 7's guarantee was that subtracting a baseline b leaves the gradient unbiased if b does not depend on the sampled action. The group mean does: it contains ri itself. The effect can be computed.

Go deeper the (G−1)/G factor

Consider the contribution of answer i with advantage ri − r̄, where r̄ is the mean of all G rewards. Split the mean: r̄ = ri/G + (1/G) ∑j≠i rj. Then

E[ (ri − r̄) ∇ log π(oi) ] = (1 − 1/G) E[ ri ∇ log π(oi) ] − (1/G) ∑j≠i E[ rj ] · E[ ∇ log π(oi) ].

The second term vanishes because the other answers are independent of oi and E[∇ log π(o)] = 0 (the identity behind every baseline argument in chapter 7). What remains is (G−1)/G times the true policy gradient. The direction is right and the size is too small by 1/G: for G = 8, 12.5 percent. The fix is the leave-one-out baseline, where answer i is compared with the mean of the other G−1: then the baseline is independent of oi and the gradient is exactly unbiased, at the price of advantages that are larger by G/(G−1). This is the baseline of RLOO (Ahmadian et al., 2024), the REINFORCE-style method in chapter 12's table.

What dividing by the standard deviation does

The standard deviation is not a baseline: it is a positive scale applied to one prompt's whole group, so it never changes which answers are pushed up or down, only how hard the prompt pulls compared with the others in the batch. For binary rewards with a fraction p of correct answers, the standard deviation is √(p(1−p)). The first table above shows the effect: with the std, a single correct answer in eight gets an advantage of +2.65 and the total pull of the group, the sum of |A|, is 5.29, close to the 8.00 of a 50-50 group; without it, the correct answer would get only +0.875. Prompts near the extremes, which the model almost always fails or almost always passes, are boosted relative to the mean-only version. Liu et al. (2025, "Understanding R1-Zero-Like Training: A Critical Perspective") argue that GRPO has an optimisation bias that artificially increases response length, especially for incorrect outputs, and propose Dr. GRPO, which removes these normalisation terms (their abstract names the length effect; their analysis also covers the std term). Their length argument concerns the 1/|oi| factor in the objective above: averaging over tokens within an answer means each token of a long wrong answer is penalised less than each token of a short wrong one.

Where there is no signal

Every advantage in a group is zero when every answer has the same reward. For a prompt on which the model's success probability is p, the chance that all G answers fail is (1 − p)G and the chance that all succeed is pG. With G = 8 and p = 0.05 (a hard problem), 66 percent of groups are all wrong; with p = 0.9 (an easy one), 43 percent are all right. Either way the prompt teaches nothing that step, yet its answers still had to be generated, which is the most expensive part of the run. A prompt set must therefore be matched to the model: mostly problems the model solves sometimes, neither always nor never. The DAPO paper (Yu et al., 2025, "DAPO: An Open-Source LLM Reinforcement Learning System at Scale") makes this explicit with dynamic sampling, which keeps sampling until the batch is full of prompts with non-zero advantage; its other named changes are a higher upper clip bound (clip-higher), a token-level loss and shaping for over-long answers. With a Qwen2.5-32B base model they report 50 points on AIME 2024, and they released their training code (built on the verl framework) and a processed dataset.

A small experiment makes the weighting visible. There are 48 prompts, each with a tabular softmax over eight candidate answers of which exactly one is correct, with starting success probabilities from 0.01 (hard) to 0.90 (easy). Each step samples 16 prompts, draws a group of 8 answers per prompt, and updates the logits by the advantage rule under test (one gradient step per batch, so the PPO ratio is 1 and the clip never fires). We compare REINFORCE with no baseline, the group mean alone, and the group mean divided by the std, averaged over 20 seeds and measured after 60 steps.

import numpy as np
K, G, B, STEPS, LR = 8, 8, 16, 60, 0.5          # answers per prompt, group size, prompts per step, steps, learning rate
NP = 48                                           # prompts in the training set

def softmax(z): e = np.exp(z - z.max(axis=-1, keepdims=True)); return e / e.sum(axis=-1, keepdims=True)

def make_policy(rng):
    # prompt i starts with probability p0 on its single correct answer (answer 0), from hard (0.01) to easy (0.9)
    p0 = np.linspace(0.01, 0.9, NP)
    z = np.zeros((NP, K)); z[:, 0] = np.log(p0 / (1 - p0) * (K - 1))
    return z, p0

def advantages(r, mode):
    mu, sd = r.mean(1, keepdims=True), r.std(1, keepdims=True)
    if mode == "none":  return r                                   # plain REINFORCE, no baseline
    if mode == "mean":  return r - mu                              # group mean only (Dr. GRPO-style)
    if mode == "grpo":  return np.where(sd > 0, (r - mu) / np.maximum(sd, 1e-8), 0.0)

def run(mode, seed):
    rng = np.random.default_rng(seed)
    z, p0 = make_policy(rng)
    dead0 = None
    for step in range(STEPS):
        idx = rng.choice(NP, size=B, replace=False)
        pi = softmax(z[idx])                                       # (B, K)
        a = np.array([rng.choice(K, size=G, p=pi[b]) for b in range(B)])      # (B, G) sampled answers
        r = (a == 0).astype(float)                                 # verifiable reward: answer 0 is the correct one
        if step == 0: dead0 = np.mean(r.std(1) == 0)
        A = advantages(r, mode)
        grad = np.zeros_like(pi)
        for b in range(B):
            for g in range(G):
                grad[b] += A[b, g] * (np.eye(K)[a[b, g]] - pi[b])
        z[idx] += LR * grad / G
    p = softmax(z)[:, 0]
    return p, dead0

print(f"{NP} prompts, G={G}, {B} prompts per step, {STEPS} steps, mean over 20 seeds")
print(f"{'advantage':22} {'mean P(correct)':>16} {'hard third':>11} {'middle':>8} {'easy third':>11}")
for mode, name in (("none", "no baseline"), ("mean", "group mean"), ("grpo", "group mean / std")):
    res = np.array([run(mode, s)[0] for s in range(20)]).mean(0)
    t = NP // 3
    print(f"{name:22} {res.mean():16.3f} {res[:t].mean():11.3f} {res[t:2*t].mean():8.3f} {res[2*t:].mean():11.3f}")
p0 = make_policy(None)[1]; t = NP // 3
print(f"{'start':22} {p0.mean():16.3f} {p0[:t].mean():11.3f} {p0[t:2*t].mean():8.3f} {p0[2*t:].mean():11.3f}")

Read it with care. At step 0, 20 percent of all groups were dead (all right or all wrong). Standardising by the std learned fastest, especially on the hard third (0.15 to 0.76 against 0.47 to 0.51 for the others), because a rare success there carries an advantage of +2.65 against +0.875 without the division. But this is partly a larger effective learning rate (the std-scaled advantages are larger, with the learning rate held fixed) and the toy has no generalisation between prompts, so it shows how the weighting redistributes effort, not that one rule is better. Real runs differ, which is why libraries expose all of these as options.

Common misconception

"GRPO is a different algorithm from PPO." It is PPO's clipped objective with a different way to get the advantage: no critic, one scalar per answer from the group, and the KL moved from the reward into the loss (often set to zero). The pieces you learned in chapters 7 and 8 (policy gradient, baselines, ratio, clip, KL) are all still here. The things that are new are the sampling of a group, the group-relative advantage, and the particular failure modes that follow from them: dead groups and the length and difficulty weightings above.

Running GRPO: what fits, and what to set

The extra cost is generation. Each iteration decodes B × G answers, and they are long: a reasoning model may think for thousands of tokens. Decoding is memory-bound and the KV cache for G simultaneous answers grows with their length (chapter 18). The estimate below adds that cache to the LoRA accounting of chapter 11 for a 7B Llama 2 shape, which has no grouped-query attention and so a large cache: 0.52 MB per token. Training micro-batches are two sequences. All values are estimates.

# Does a GRPO run fit on a 24 GB card?  Llama-2-7B shape, rank-16 LoRA on all linear layers (estimates).

    return (L * 2 * seq * seqs * H + 34 * seq * seqs * H + 4 * seq * seqs * V) / GB

A 7B model with a 4-bit base fits a 24 GB card for groups of 8 up to 2,048 tokens per prompt-plus-answer, and a bf16 base fits for G = 8 only at 1,024 tokens. At 4,096 tokens (modest for a reasoning model) the cache alone pushes even the 4-bit case over for G = 8. The usual responses are a smaller model, a shorter maximum completion, fewer concurrent answers, a serving engine that stores the cache more efficiently (chapter 20), or a bigger GPU. GPU capacities are NVIDIA's (24 GB for the RTX 4090, 80 GB for the A100 and H100 SXM; see chapter 2).

In TRL, a GRPO run needs a dataset with a prompt column, a reward function, and a config. This listing is adapted from the library's documentation and is not run here (it needs PyTorch, a GPU and a model download). The reward function receives the generated completions plus any dataset columns by name, and returns one float per completion.

import re
from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

def reward_func(completions, ground_truth, **kwargs):
    """1.0 if the content of the last \boxed{...} equals the dataset's ground_truth, else 0.0."""
    out = []
    for c, gt in zip(completions, ground_truth):
        boxes = re.findall(r"\\boxed\{(.*?)\}", c)
        out.append(1.0 if boxes and boxes[-1].strip() == gt else 0.0)
    return out

dataset = load_dataset("my-org/math-prompts", split="train")   # columns: prompt, ground_truth

args = GRPOConfig(
    output_dir="grpo-out",
    num_generations=8,        # G: answers per prompt
    max_completion_length=1024,
    beta=0.0,                 # no KL term, so the reference model is not loaded
    epsilon=0.2,
    loss_type="dapo",         # the library default; "dr_grpo" removes length and std terms
    scale_rewards="group",    # divide by the group std (False: mean only)
    use_vllm=True,            # generate with vLLM (colocated by default in TRL v1)
)
trainer = GRPOTrainer(model="Qwen/Qwen2.5-0.5B-Instruct", args=args,
                      reward_funcs=reward_func, train_dataset=dataset)
trainer.train()

Read the loss definition in your version before comparing runs. Libraries such as verl and others implement the same ideas with different defaults.

What reinforcement learning on verifiable rewards produced

DeepSeek-R1-Zero (DeepSeek-AI, 2025) applied GRPO directly to a pretrained base model, with no SFT stage and the two rule-based rewards above. The paper reports that its average pass@1 on the AIME 2024 competition problems rose during RL from 15.6 percent to 71.0 percent, and to 86.7 percent with majority voting over samples. It reports that the model learned, unprompted, to allocate more thinking time by re-evaluating its earlier steps, and shows an intermediate checkpoint that stops mid-solution with "Wait, wait. Wait." which the authors call an "aha moment". R1-Zero also had poor readability and mixed languages, so the released DeepSeek-R1 added a small cold-start SFT stage on thousands of long chain-of-thought examples, a multi-stage pipeline, and finally distillation of the reasoning ability into smaller dense models. The paper was later published in Nature (2025). Case study C2 goes through it, and chapter 15 covers the distillation step.

Does RL teach new skills, or sharpen old ones?

Pass@1 is the chance that one sample is right. Pass@k is the chance that at least one of k samples is right: it measures what the model can do given many attempts, not what it does on the first. The unbiased estimator (Chen et al., 2021) from n samples with c correct is 1 − C(n−c, k)/C(n, k). Yue et al. (2025, "Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?") report that RLVR-trained models beat their base models at k = 1 but that base models reach higher pass@k when k is large, and conclude that the observed reasoning is bounded by the base model and that the training setups did not elicit fundamentally new reasoning patterns; they find that distillation from a teacher can. That is one study's reading, and others have argued the opposite with longer training or different data, so treat it as an open question, not a settled one.

The mechanism in the claim is easy to simulate. Take 2,000 prompts whose base success probabilities are spread out (many small but not zero). Model "RL" as sharpening: each prompt's log-odds are doubled and shifted up. This is a deliberately crude toy with no claim to represent any real model: it only shows how pass@1 and pass@k can disagree.

import numpy as np
from math import comb
rng = np.random.default_rng(0)

def pass_at_k(n, c, k):                 # unbiased estimator of Chen et al. (2021): 1 - C(n-c, k) / C(n, k)
    return 1.0 if n - c < k else 1.0 - comb(n - c, k) / comb(n, k)

# 2,000 prompts; base-model success probabilities are spread out, many small but not zero
p_base = rng.beta(0.35, 0.9, size=2000)
logit = lambda p: np.log(p / (1 - p))
# toy "RL sharpening": push each prompt's log-odds away from the middle (scale 2.0, shift +2.0)
# prompts the model solves sometimes get solved more often; prompts at p ~ 1e-4 stay unsolved
p_rl = 1 / (1 + np.exp(-(2.0 * logit(np.clip(p_base, 1e-9, 1 - 1e-9)) + 2.0)))

print(f"{'k':>4} {'base pass@k':>12} {'RL pass@k':>10}")
for k in (1, 4, 16, 64, 256, 1024):
    b = np.mean(1 - (1 - p_base) ** k); r = np.mean(1 - (1 - p_rl) ** k)
    print(f"{k:4d} {b:12.3f} {r:10.3f}")

# the estimator on real samples: n = 256 draws per prompt, c correct
n = 256
c = rng.binomial(n, p_base[:300])
est = np.mean([pass_at_k(n, ci, 16) for ci in c]); exact = np.mean(1 - (1 - p_base[:300]) ** 16)
print(f"\nunbiased pass@16 from {n} samples on 300 prompts = {est:.3f}   (exact for those prompts: {exact:.3f})")

Which metric you care about depends on the use. A product that makes one attempt wants pass@1, and sharpening is exactly what it needs. A system that can sample many candidates and verify them (best-of-n with a checker, test-time search) benefits from the base model's breadth. The honest summary is that RLVR reliably improves single-attempt reliability on the kinds of tasks it trains on; whether it also extends what the model can solve at all is contested.

Failure modes to watch

  • Verifier loopholes. See the shotgun answer. Audit the reward by sampling high-reward completions and reading them, and keep a held-out checker the policy cannot see.
  • Format without substance. A format reward is easy to earn. If it is weighted too heavily, or if the base model already follows the format, reward rises while accuracy does not. Log the two components separately.
  • Length drift. Average completion length growing steadily can be real (more thinking), a bias in the loss normalisation (the Dr. GRPO critique), or an artefact of truncation. Track length by correct and incorrect answers separately.
  • Collapse of diversity. As the policy sharpens, its answers become alike, groups become dead, and exploration stops. The DAPO authors motivate raising the upper clip bound (epsilon_high) as a way to let low-probability tokens grow; watch the policy's entropy in the logs.
  • The wrong prompts. A dataset that is too easy or too hard gives mostly dead groups. Log the fraction of groups with non-zero reward variance and filter your prompts by measured base-model pass rate before you start.
  • Training on the test. Prompts from public benchmarks contaminate later evaluation. Keep evaluation sets out of the training pool (chapter 23).

Key takeaways

  • A verifiable reward is computed by a program (answer match, unit tests, format check). RLVR (Tülu 3) and R1-Zero use such rewards instead of a learned reward model, partly to avoid the reward hacking of chapter 13.
  • The verifier is a specification with loopholes: test it against shotgun answers, changed minds and format tricks, and sandbox code execution.
  • GRPO replaces PPO's value model with a baseline from a group of G answers to the same prompt: Ai = (ri − mean) / std, the same for every token of answer i, inside PPO's clipped objective with an optional KL term.
  • With binary rewards, a lone success in eight gets +2.65 with the std division and +0.875 without; a group with identical rewards gets exactly zero and teaches nothing (66 percent of groups at p = 0.05, G = 8).
  • The group mean includes the sample, so the gradient is (G−1)/G of the truth (checked numerically); leave-one-out (RLOO) removes the bias. Dr. GRPO and DAPO adjust the length and std normalisation.
  • R1-Zero went from 15.6 to 71.0 percent pass@1 on AIME 2024 with rule-based rewards. Whether RLVR adds new capability or sharpens existing capability (pass@k) is debated.
  • Cost is generation: KV cache for G long answers sets the limit on a 24 GB card long before the optimiser does.

Check your understanding

A group of 8 answers has exactly one correct answer (reward 1) and seven wrong ones (reward 0). Using (r − mean) / std with the population standard deviation, what advantage does the correct answer get?

  1. About 0.88
  2. Exactly 1.0
  3. About 2.65
  4. About 7.0
The mean is 1/8 = 0.125 and the standard deviation is √(0.125 × 0.875) = 0.331, so A = (1 − 0.125) / 0.331 = 2.65. The value 0.875 (rounded to 0.88) is the advantage without the std division. The seven wrong answers each get −0.38.

On a hard prompt, all 8 sampled answers are wrong. What does GRPO learn from this group in this step, and what helps?

  1. Nothing, since every advantage is zero; filter such prompts, or choose prompts the model solves sometimes
  2. It pushes all eight answers down equally, which is useful
  3. It pushes the most likely answer up
  4. It raises the KL penalty automatically
All rewards equal the group mean, so each advantage is zero and the group contributes no gradient (apart from any KL term, if used). The cost of generating the eight answers is still paid. Matching the prompt set to the model's ability, or dynamic sampling that skips dead groups, recovers the lost efficiency.

With the group mean (including the sample itself) as the baseline and G = 4, the expected gradient is what fraction of the true policy gradient?

  1. 1.0, since any baseline is unbiased
  2. 0.75
  3. 0.5
  4. 0.25
The factor is (G−1)/G = 3/4. A baseline is unbiased only if it does not depend on the sample being scored, and the group mean contains it. The simulation gave 0.747 for G = 4. Leave-one-out brings the factor back to 1.

Which component of PPO-based RLHF does GRPO remove, and what replaces it?

  1. The reference model, replaced by the old policy
  2. The clip, replaced by a larger learning rate
  3. The value model (critic), replaced by a baseline from the rewards of other answers to the same prompt
  4. The policy, replaced by the reward model
GRPO estimates the baseline from group scores and so avoids a critic as large as the policy. The clip stays, and the reference model is optional (beta=0 in TRL by default), but that is a setting, not what defines GRPO.

Your maths reward gives 1.0 whenever the gold answer string appears anywhere in the completion. After a few hundred steps average reward is 0.9 but held-out accuracy is flat. What most likely happened?

  1. The KL penalty is too large
  2. The group size is too small
  3. The model forgot how to do arithmetic
  4. The policy learned to list many candidate answers so that the gold one appears, which the lazy verifier rewards
A containment check can be satisfied by hedging, as the "shotgun" completion shows. The proxy rises while the true skill does not. Use an exact match on a marked final answer, test the verifier against adversarial completions, and track a held-out strict score.

After RLVR training, a model has higher pass@1 than its base but lower pass@256 on the same problems. Which interpretation is best supported?

  1. RL concentrated probability on solutions the base could already produce, improving single-attempt reliability while narrowing coverage; which metric matters depends on whether you can sample and verify many attempts
  2. RL taught the model entirely new capabilities, so pass@256 must be a measurement error
  3. The verifier was too strict
  4. Pass@k is meaningless for reasoning models
This pattern is what sharpening predicts, and it is the pattern reported by Yue et al. (2025), though whether it is general is debated. It does not show RL adds nothing: for a one-attempt product, higher pass@1 is the gain you want. Pass@k is well defined and informative about coverage.
