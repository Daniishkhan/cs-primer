Workbench 5: GRPO on a Verifiable Task

Some tasks can be graded by a program, such as sums, unit tests or exact-match questions. A program that grades an answer is a verifier, and its score is a verifiable reward. GRPO (group relative policy optimisation) trains a model on that reward. For each prompt it samples a group of answers, scores them, and pushes up the ones that beat their own group's average. Here you compute that push by hand for one group, check it against TRL, and then break the setup on purpose: reward the answer's format alone and watch the reward climb while the model stops being right.

Why measure it

Chapter 14 makes two claims that sound abstract. One is that a group needs no separate critic model, only its own mean and spread. The other is that a reward is a specification with loopholes. Both are easy to check on a task small enough to run on a laptop. You will see the group numbers match a hand calculation, with one surprise in the standard deviation. You will also see a reward curve that goes up while the thing you care about does not. Write the prediction down, then measure.

What you need

  • Part 1, your laptop: the workbench venv (see workbench 1) with trl installed, and about 260 MB of disk for SmolLM2-135M-Instruct. Each run took between two and five minutes on a MacBook, depending on what else the machine was doing.
  • Part 2, a GPU box (optional): one 24 GB card, about 2 GB of disk for Qwen2.5-0.5B-Instruct, and about three hours with the experiments. Setting one up is in Your lab machine, Option C.

Predict before you run

Recall the advantage from chapter 14. For a group of G answers with rewards r1 to rG:

Âi = ( ri − mean(r1, …, rG) ) / std(r1, …, rG)

The task is addition: What is 9 + 13? The reward is 1 if the last number in the reply is the true sum, and 0 if not. Each step samples G = 8 answers to each of four prompts. Suppose one answer in a group of eight is right and seven are wrong.

Your prediction

Work out the advantage of the lone right answer and of each wrong one, using the chapter's formula with the standard deviation taken over the eight rewards. Then guess: will TRL print the same numbers? Finally, if the model is right 17 percent of the time on a random problem, what share of groups of eight would you expect to have all eight rewards equal, and so teach nothing?

Check your arithmetic

The mean reward is 1/8 = 0.125. The standard deviation, dividing by G as the chapter does, is √(0.125 × 0.875) = 0.3307. The right answer gets (1 − 0.125) / 0.3307 = +2.646. Each wrong one gets −0.125 / 0.3307 = −0.378. This is the +2.65 in the chapter's table.

TRL does not print those. Its code computes the standard deviation with Bessel's correction, which divides by G − 1 and is the usual sample standard deviation. It then adds 10−4 to the divisor so that a group of equal rewards does not divide by zero. That makes the spread 0.3307 × √(8/7) = 0.3536 and every advantage smaller by about 6.5 percent: +2.474 and −0.353. The direction is the same and the size is not. This is one more reason to read the loss definition in your library before comparing runs with a paper's.

All eight rewards are equal when all are right or all are wrong: (1 − p)G + pG = 0.838 + 0.178 = 0.225. About a fifth of groups would teach nothing. The real share will be higher, because the sums differ in difficulty and p is not 0.17 for every prompt.

Part 1: on your laptop

Set up once

$ source ~/.venvs/zts/bin/activate
$ pip install trl datasets

The script is code/w05/grpo_arith.py, and the same code split into cells is grpo_arith.ipynb. It makes its own sums from a fixed seed, so there is nothing else to download.

The idea

  1. make 400 training sums and 100 held-out sums; the verifier is plain Python: is the last number the true sum?
  2. measure the model before training on the held-out sums, greedy and sampled
  3. train 30 steps with TRL's GRPOTrainer: 4 prompts per step, 8 answers each, reward = correct
  4. measure again; print the reward, length and dead-group share in windows of 5 steps
  5. take one group from training and compute its advantages by hand next to the trainer's

The script scores two things on every answer. correct is the exact-match check. formatted asks only whether the reply ends in Answer: <number>, right or wrong. A setting called reward_weights decides which one is optimised. Weight 0 means that TRL still logs the score but does not train on it. That lets you watch a quantity you are not rewarding, which the second half of this page needs. The same Triton gap as in workbench 4 applies on a Mac, and the script carries the same short stand-in.

"""GRPO on a task a program can check: addition. Train with TRL's
GRPOTrainer, compute one group's advantages by hand next to the trainer's
own, then reward the format alone and watch the reward climb while the
accuracy does not.

Laptop (SmolLM2-135M-Instruct, about 5 minutes per run):
    python grpo_arith.py                    # reward = correct answers
    python grpo_arith.py --reward format    # reward = the format only
GPU box (a 0.5B model, bigger groups, 24 GB card):
    python grpo_arith.py --model Qwen/Qwen2.5-0.5B-Instruct --group 16 \
        --prompts 8 --steps 200 --max-digits 3

Memory prediction only (reads config.json, downloads no weights):
    python grpo_arith.py --model Qwen/Qwen2.5-0.5B-Instruct --group 16 \
        --prompts 8 --max-completion 256 --predict-only

Needs: torch, transformers, trl, datasets (workbench/requirements.txt)."""
import argparse
import random
import re
import statistics

import torch
from datasets import Dataset
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer
from transformers import TrainerCallback
from transformers.trainer_callback import PrinterCallback
from trl import GRPOConfig, GRPOTrainer
from trl.trainer import utils as trl_utils

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--model", default="HuggingFaceTB/SmolLM2-135M-Instruct")
ap.add_argument("--reward", default="correct",
                choices=["correct", "format"])     # what is optimised
ap.add_argument("--steps", type=int, default=30)
ap.add_argument("--group", type=int, default=8)    # G: answers per prompt
ap.add_argument("--prompts", type=int, default=4)  # prompts per step
ap.add_argument("--lr", type=float, default=2e-5)
ap.add_argument("--max-digits", type=int, default=2)
ap.add_argument("--max-completion", type=int, default=48)  # tokens
ap.add_argument("--eval-n", type=int, default=100)
ap.add_argument("--predict-only", action="store_true")
args, _ = ap.parse_known_args()        # notebooks pass their own flags

if torch.cuda.is_available():
    DEVICE = "cuda"
elif torch.backends.mps.is_available():
    DEVICE = "mps"
else:
    DEVICE = "cpu"
random.seed(0)
torch.manual_seed(0)


class PlainLogProb:
    """Stand-in for TRL's Triton kernel (Linux + CUDA only). Same sums in
    ordinary PyTorch, for a Mac. Not used where the real kernel exists."""

    @staticmethod
    def apply(hidden, weight, bias, targets, temperature, chunk, softcap,
              scale, outputs):
        z = hidden @ weight.t()
        z = (z if bias is None else z + bias).float() * scale / temperature
        lse = torch.logsumexp(z, -1)
        logp = z.gather(1, targets[:, None])[:, 0] - lse
        p = z.softmax(-1)
        entropy = lse - (p * z).sum(-1) if "entropy" in outputs else None
        return logp, entropy, None, None, None


if trl_utils._ChunkedLogProbFunction is None:      # no Triton here
    trl_utils._ChunkedLogProbFunction = PlainLogProb

# ── 2. The task and its verifier: plain Python, no model involved ────────
HI = 10 ** args.max_digits - 1


def make_problems(n, seed):
    rng = random.Random(seed)
    out = []
    for _ in range(n):
        a, b = rng.randint(2, HI), rng.randint(2, HI)
        q = (f"What is {a} + {b}? "
             f"End your reply with 'Answer: <number>'.")
        out.append({"prompt": [{"role": "user", "content": q}],
                    "answer": str(a + b)})
    return out


def text_of(completion):
    return completion[0]["content"] if isinstance(completion, list) \
        else completion


def is_correct(text, answer):
    """The last whole number in the reply equals the true sum."""
    nums = re.findall(r"-?\d+", text)
    return bool(nums) and nums[-1] == answer


def is_formatted(text):
    """The reply ends with 'Answer: <number>', right or wrong."""
    return re.search(r"Answer:\s*-?\d+\s*$", text) is not None


def correct(completions, answer, **kwargs):
    """Reward 1.0 for a correct final number, else 0.0."""
    return [float(is_correct(text_of(c), a))
            for c, a in zip(completions, answer)]


def formatted(completions, **kwargs):
    """Reward 1.0 for the 'Answer: N' shape, whatever N is."""
    return [float(is_formatted(text_of(c))) for c in completions]


train = Dataset.from_list(make_problems(400, seed=1))
held = make_problems(args.eval_n, seed=2)
tok = AutoTokenizer.from_pretrained(args.model)
tok.padding_side = "left"


# ── 3. Predict memory from the config alone (chapters 14, 18) ────────────
def gib(n):
    return f"{n / 2**30:,.2f} GiB"


cfg = AutoConfig.from_pretrained(args.model)
with torch.device("meta"):                  # shapes only: no memory used
    shell = AutoModelForCausalLM.from_config(cfg)
N = sum(p.numel() for p in shell.parameters())
L, h, a = cfg.num_hidden_layers, cfg.hidden_size, cfg.num_attention_heads
d_head = getattr(cfg, "head_dim", None) or h // a
prompt_len = len(tok.apply_chat_template(
    make_problems(1, 0)[0]["prompt"], add_generation_prompt=True,
    return_dict=False))
seqs = args.group * args.prompts            # answers decoded together
tokens = prompt_len + args.max_completion   # longest sequence
states = 16 * N                             # fp32 weights, grads, Adam (no
#                                             reference model: beta = 0)
kv = seqs * tokens * 2 * L * cfg.num_key_value_heads * d_head * 2
acts = seqs * tokens * L * h * 2            # checkpointing: layer inputs
print(f"model {args.model}: {N:,} parameters; {seqs} sequences of up to "
      f"{tokens} tokens ({prompt_len} prompt + {args.max_completion})")
print(f"predicted memory: states {gib(states)} + KV cache {gib(kv)} "
      f"+ activations {gib(acts)} = {gib(states + kv + acts)}")
if args.predict_only:
    raise SystemExit


# ── 4. Held-out check, outside the trainer: greedy and sampled ───────────


def evaluate(model, sample):
    texts = [tok.apply_chat_template(p["prompt"], add_generation_prompt=True,
                                     tokenize=False) for p in held]
    enc = tok(texts, return_tensors="pt", padding=True).to(model.device)
    torch.manual_seed(0)
    with torch.no_grad():
        out = model.generate(**enc, max_new_tokens=args.max_completion,
                             do_sample=sample, temperature=1.0, top_k=0,
                             top_p=1.0, pad_token_id=tok.pad_token_id)
    replies = tok.batch_decode(out[:, enc.input_ids.shape[1]:],
                               skip_special_tokens=True)
    acc = sum(is_correct(r, p["answer"]) for r, p in zip(replies, held))
    fmt = sum(is_formatted(r) for r in replies)
    return acc / len(held), fmt / len(held), replies


class Snapshot(TrainerCallback):
    """After each step, keep the rewards and advantages TRL just used."""
    rows = []

    def on_step_end(self, a, state, control, **kw):
        logs = trainer._logs
        self.rows.append((state.global_step,
                          list(logs["rewards"]["correct"]),
                          list(logs["advantages"]),
                          list(logs["completion"])))


# ── 5. Train with TRL ────────────────────────────────────────────────────
G = args.group
cfg = GRPOConfig(
    output_dir="grpo-out", num_generations=G,
    per_device_train_batch_size=G * args.prompts,   # whole groups only
    max_steps=args.steps, learning_rate=args.lr,
    max_completion_length=args.max_completion, temperature=1.0, beta=0.0,
    reward_weights=[1.0, 0.0] if args.reward == "correct" else [0.0, 1.0],
    logging_steps=1, report_to="none", save_strategy="no",
    bf16=(DEVICE == "cuda"), seed=0, data_seed=0, disable_tqdm=True)
trainer = GRPOTrainer(model=args.model, reward_funcs=[correct, formatted],
                      args=cfg, train_dataset=train, processing_class=tok,
                      callbacks=[Snapshot()])
trainer.remove_callback(PrinterCallback)
policy = trainer.model.eval()
print(f"reward optimised: {args.reward}; G={G}, "
      f"{args.prompts} prompts per step, {args.steps} steps")
g0, f0, _ = evaluate(policy, False)
s0, sf0, _ = evaluate(policy, True)
print(f"before: greedy accuracy {g0:.2f} format {f0:.2f}  |  "
      f"sampled accuracy {s0:.2f} format {sf0:.2f}")
trainer.train()
log = [r for r in trainer.state.log_history if "reward" in r]

print(f"\n{'steps':>7} {'reward':>7} {'correct':>8} {'format':>7} "
      f"{'len':>5} {'dead':>5}")      # mean over windows of 5 steps
for k in range(0, len(log), 5):
    w = log[k:k + 5]

    def avg(key):
        return statistics.fmean(r[key] for r in w)
    print(f"{k + 1:>3}-{k + len(w):<3} {avg('reward'):7.3f} "
          f"{avg('rewards/correct/mean'):8.3f} "
          f"{avg('rewards/formatted/mean'):7.3f} "
          f"{avg('completions/mean_length'):5.1f} "
          f"{avg('frac_reward_zero_std'):5.2f}")

policy.eval()
g1, f1, replies = evaluate(policy, False)
s1, sf1, _ = evaluate(policy, True)
print(f"\nafter:  greedy accuracy {g1:.2f} format {f1:.2f}  |  "
      f"sampled accuracy {s1:.2f} format {sf1:.2f}")
for p, r in list(zip(held, replies))[:3]:        # what it writes now
    print(f"  {p['prompt'][0]['content'][:16]:<16} true {p['answer']:>3}"
          f"  reply {r!r}")

# ── 6. One group's advantages, by hand, beside the trainer's ─────────────
if args.reward == "correct":
    for step, rewards, adv, comps in Snapshot.rows:
        for k in range(0, len(rewards), G):
            grp = rewards[k:k + G]
            if 0 < sum(grp) < G:                     # a group with signal
                break
        else:
            continue
        m = statistics.fmean(grp)
        pop, sample = statistics.pstdev(grp), statistics.stdev(grp)
        print(f"\nstep {step}, one group of {G}: rewards {grp}")
        print(f"mean {m:.3f}  population std {pop:.3f}  "
              f"sample std {sample:.3f}")
        print(f"{'i':>2} {'reward':>6} {'chapter':>8} {'by hand':>8} "
              f"{'TRL':>8}")
        for i, r in enumerate(grp):
            print(f"{i + 1:>2} {r:6.1f} {(r - m) / pop:+8.3f} "
                  f"{(r - m) / (sample + 1e-4):+8.3f} "
                  f"{adv[k + i]:+8.3f}")
        break

What you should see

  • The reward rises from 0.19 to 0.64 in 30 steps. The held-out accuracy at the sampling temperature that training uses rises from 0.17 to 0.61. The greedy accuracy moves from 0.56 to 0.65, which with 100 sums is close to the noise (about ±0.05). The sampled number moves far more, and it is the one training acts on: GRPO has made the model's ordinary sampling more reliable. It has not much changed what its single best guess is. This is the sharpening-versus-new-skill question from chapter 14, on a very small scale.
  • The dead column is the share of answers in groups with equal rewards. It starts at 0.45 and stays between 0.2 and 0.55. My independent-prompts estimate was 0.23. The measured share is higher, because difficulty varies across the sums. Big sums are nearly always wrong, so their groups are all zeros. A group of equal rewards has advantage 0 for every answer and teaches nothing.
  • Replies get shorter, from 21.8 tokens to 13.1. The sample replies at the end are bare equations such as 9 + 13 = 22. The verifier never asked for Answer:, and the format column rises to 0.47 and then falls back to 0.19. The reward shapes only what it measures.
  • The group table matches the prediction. One right answer in eight. The chapter's formula (population std) gives +2.646 and −0.378. Applying TRL's own formula by hand (sample std plus 10−4) gives +2.474 and −0.353. The last column is the number TRL used in training, read from its logs. It equals the by-hand column to three places.

How much to trust this

One seed, 30 steps, 100 held-out sums. It shows the mechanism, not a benchmark result. A different seed will move the numbers. The qualitative picture (reward up, groups often dead, answers shorter) is what to expect. The advantage table is exact arithmetic and does not depend on the seed.

Part 2: a bigger model on a GPU

Qwen2.5-0.5B-Instruct is already good at small sums. In a quick check with a throwaway script (not the one on this page), it answered about 93 percent of sums up to 20 correctly with greedy decoding. With few wrong answers most groups are all right, and most groups are dead. On the GPU box, raise the difficulty with --max-digits 3 or 4 so that p sits in the middle again, and use a larger group.

Predict the memory first. Chapter 14 says the extra cost of GRPO is generation: the key-value cache for every answer decoded at once (chapter 18). The script's prediction mode reads config.json and downloads no weights:

$ python grpo_arith.py --model Qwen/Qwen2.5-0.5B-Instruct --group 16 --prompts 8 --max-completion 256 --predict-only
model Qwen/Qwen2.5-0.5B-Instruct: 494,032,768 parameters; 128 sequences of up to 305 tokens (49 prompt + 256)
predicted memory: states 7.36 GiB + KV cache 0.45 GiB + activations 1.56 GiB = 9.37 GiB

The arithmetic. Training states in 32-bit weights are 494,032,768 × 16 bytes = 7.36 GiB. There is no reference model, because the script sets the KL weight to 0. The cache holds 128 answers (16 per prompt, 8 prompts) of up to 305 tokens. Per token that is 2 (keys and values) × 24 layers × 2 key-value heads × 64 numbers × 2 bytes = 12,288 bytes, so 128 × 305 × 12,288 = 0.45 GiB. Activations with checkpointing keep each layer's input: 128 × 305 × 24 × 896 × 2 bytes = 1.56 GiB. The total is 9.37 GiB. The cache is small here because the model has only two key-value heads. The 7B Llama-shaped model in the chapter has none of that saving.

Break it

Reward the format alone

Now optimise formatted instead of correct. The reward asks only that the reply ends in Answer: <number>. Nothing checks the number. This is the failure mode chapter 14 calls format without substance: the reward is easy to earn, so it is earned. Predict first. The format reward should rise towards 1 within a dozen or so steps, since the model already writes it about one time in ten. Nothing in the reward protects the accuracy, so it is free to rise, stay or fall.

The reward climbs from 0.19 to 1.00, as predicted. But accuracy did not fall. The sampled accuracy rose from 0.17 to 0.57, and the replies show why: 9 + 13 = 22 then Answer: 22. This model's easiest way to end with Answer: N is to copy the number it has just worked out. Format and correctness travel together, so the loophole is not used. The correct column even rises (to 0.67), then falls back to 0.375 once every group is dead and nothing pushes any more. That is an honest result, and it is a warning: a hack that did not appear on one run is not a hack that cannot appear.

Same reward, same seed, a different path through the data, and a different ending. The reward reaches 1.00. The accuracy falls to 0.01 greedy and 0.00 sampled. What to take from the pair

Both runs rewarded exactly the same thing. In one the model satisfied it honestly, and in the other it did not. The reward cannot tell the two apart, and only the unrewarded correct column and the replies themselves can. Always log the components of a reward separately, read a sample of high-reward replies, and keep a held-out check the policy cannot optimise.

More experiments

  • Shrink the group. Run with --group 2 --prompts 16, which keeps 32 answers per step. Predict the dead share at the start: (1 − p)2 + p2 with p = 0.17 gives 0.72, against 0.23 for G = 8. A group of two compares a pair only, so it teaches very little when both go the same way. Check how the learning curve compares.
  • Make the sums harder. Use --max-digits 3 on the laptop. Predict the starting reward before running: the model will be right much less often, so most groups are dead and the reward should barely move in 30 steps.
  • Reward both. Set reward_weights to [1.0, 1.0] in the script. Predict whether the hack appears. The correct reward pays for the number being right, and the format reward pays for the shape, so the shortcut Answer: 13 earns only half the reward and the honest reply earns all of it.
  • Read the replies. After any run, print more than three of the final replies (the list is replies in the script). Do high-reward replies and correct replies look the same? The honest answer to that question is the real audit of a reward.

Key takeaways

  • A verifiable reward is a few lines of ordinary Python. The hard part is deciding what it should not allow.
  • A group's advantages are its rewards, centred and divided by their spread. For one success in eight the chapter's formula gives +2.646 and TRL gives +2.474, because TRL divides by G − 1 and adds a small constant. Read the loss definition of your library.
  • A group where every reward is equal gives zero advantage everywhere. In this task about half the answers sat in such groups, more than the independent-prompts formula says, because difficulty varies.
  • Thirty steps of GRPO lifted the sampled accuracy of a 135M model from 0.17 to 0.61 on sums. The gain was mostly in how reliably it answered.
  • A format-only reward rose to 1.00 in both runs. In one the model stayed honest, and in the other accuracy fell to 0.00. The reward could not tell the difference, so log the parts of a reward separately and read the replies.
