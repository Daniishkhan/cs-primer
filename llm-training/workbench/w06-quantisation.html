Workbench 6: Quantise and Measure Perplexity

Chapter 19 says a weight can be squeezed into 8 or 4 bits with one scale and a rounding step, and that the price is error. Here you write that rounding yourself, apply it to every linear layer of a real language model, and measure two things: the memory the packed weights would take, and the perplexity of the model on a fixed piece of text. The first is arithmetic. The second is the bill.

Why measure it

The chapter's toy experiments showed that granularity decides how much damage 4 bits does. A real model has a hundred or more weight matrices with different spreads, so whether the same ordering holds there is an empirical question. Doing the quantisation by hand, instead of calling a library, also shows how little machinery sits behind the word: a maximum, a division and a round.

What you need

  • Part 1, your laptop: the workbench venv, about 270 MB of disk for SmolLM2-135M and a few MB for WikiText-2. About 10 minutes on the CPU.
  • Part 2, a GPU box (optional): one 24 GB card, about 16 GB of disk for Qwen2.5-7B-Instruct, and about an hour and a half. Setting one up is in Your lab machine, Option C.

Predict before you run

The rule is the one from chapter 19:

s = max|w| / qmax,   q = round(w / s),   ŷ = q × s

with qmax = 127 for int8 and 7 for int4. Memory follows from how the numbers are packed: an int8 weight is 1 byte, two int4 weights share a byte, and every scale is a 16-bit number. Embeddings and the normalisation weights stay in 16 bits, and so does the output head (the script leaves lm_head alone; in SmolLM2 it is tied to the embedding, so it is the same tensor).

Your prediction

SmolLM2-135M has 134.5 million parameters, of which 106.2 million sit in linear layers (attention and MLP projections). Work out the packed size in MiB of the whole model at int8 with one scale per output row (a row is at most a few thousand weights, so its scale is negligible) and at int4 with a scale per 128 weights. Then predict the order of perplexity: which of int8, int4 with groups and int4 per channel costs the most, and is any of them free?

Check your arithmetic

The 28.3 million other parameters stay at 2 bytes: 54 MiB. 16-bit total: 134.5 million × 2 bytes = 256.6 MiB. int8: 106.2 million bytes (101.3 MiB) plus the 54 MiB plus a few thousand scales, about 155.6 MiB. int4 with groups: 106.2 million / 2 bytes = 50.7 MiB, plus 106.2 million / 128 scales × 2 bytes = 1.6 MiB, plus 54 MiB, about 106 to 108 MiB. The script prints 107.5 because 576 does not divide by 128 (see below), so some layers use groups of 64 and carry a few more scales.

Perplexity: chapter 19's table has int8 per channel nearly free and int4 per channel worse than int4 with groups. Whether 4 bits stays tolerable on a model this small is what you are about to find out. Small models have less redundancy to absorb the error than large ones.

Part 1: on your laptop

Set up once

One virtual environment serves every workbench page. From the site's folder:

$ python3 -m venv ~/.venvs/zts
$ ~/.venvs/zts/bin/pip install -r workbench/requirements.txt
$ source ~/.venvs/zts/bin/activate

The script is code/w06/quantise.py, and the same code split into cells is quantise.ipynb. The first run downloads the model and WikiText-2 from Hugging Face.

The idea

  1. take the first 4,096 tokens of the WikiText-2 test set, in eight windows of 512
  2. perplexity of the unmodified model = exp(mean negative log-probability of each next token)
  3. for each format: reload the model; for every linear layer split each row into groups, set s = max|w| / qmax, replace w by round(w / s) × s
  4. predict the packed size from the layout; measure perplexity of the damaged model
"""Quantise a model's linear layers yourself, then measure perplexity.

Absmax quantisation (chapter 19): s = max|w| / q_max, q = round(w / s).
int8 uses one scale per output row; int4 uses one scale per group of 128
weights along a row. We store nothing packed: each weight is quantised and
dequantised in place, so the model runs unchanged and perplexity shows
what the rounding cost. Memory is predicted from the packed layout.

Laptop (SmolLM2-135M, about 270 MB download, WikiText-2 test):
    python quantise.py
GPU box (a 7B model; add --tokens 16384):
    python quantise.py --model Qwen/Qwen2.5-7B-Instruct

Needs: torch, transformers, datasets (workbench/requirements.txt)."""
import argparse
import math

import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--model", default="HuggingFaceTB/SmolLM2-135M")
ap.add_argument("--tokens", type=int, default=4096)   # text to score
ap.add_argument("--window", type=int, default=512)    # tokens per window
ap.add_argument("--group", type=int, default=128)     # int4 group size
args, _ = ap.parse_known_args()        # notebooks pass their own flags

if torch.cuda.is_available():
    DEVICE = "cuda"          # a 7B model needs 16-bit compute to fit
elif torch.backends.mps.is_available():
    DEVICE = "mps"
else:
    DEVICE = "cpu"
COMPUTE = torch.bfloat16 if DEVICE == "cuda" else torch.float32
torch.manual_seed(0)


# ── 2. Absmax quantisation, written out ──────────────────────────────────
def absmax_quantise(w, bits, group=None):
    """Return (dequantised w, number of scales). Rows are output channels;
    group=None gives one scale per row, else one per `group` weights."""
    q_max = 2 ** (bits - 1) - 1                      # 127 or 7
    rows, cols = w.shape
    g = group or cols
    while cols % g:                  # 576 columns: 128 does not divide
        g //= 2                      # so fall back to 64
    blocks = w.float().reshape(rows, cols // g, g)   # maths in fp32
    s = blocks.abs().amax(dim=-1, keepdim=True) / q_max   # s = max|w|/qmax
    s = s.clamp(min=1e-12)
    q = torch.round(blocks / s).clamp(-q_max, q_max)      # q = round(w/s)
    return (q * s).reshape(rows, cols).to(w.dtype), s.numel()  # w_hat


def quantise_model(model, bits, group=None):
    """Quantise every nn.Linear except the output head. Returns the
    predicted packed size in bytes of the quantised layers."""
    packed = 0
    for name, mod in model.named_modules():
        if isinstance(mod, torch.nn.Linear) and "lm_head" not in name:
            w_hat, n_scales = absmax_quantise(mod.weight.data, bits, group)
            mod.weight.data = w_hat
            packed += mod.weight.numel() * bits // 8 + n_scales * 2
    return packed


# ── 3. Perplexity on a fixed sample ──────────────────────────────────────
tok = AutoTokenizer.from_pretrained(args.model)
text = "\n\n".join(load_dataset("Salesforce/wikitext", "wikitext-2-raw-v1",
                                split="test")["text"])
ids = tok(text, return_tensors="pt").input_ids[0][:args.tokens]
windows = ids[: len(ids) // args.window * args.window].view(
    -1, args.window).to(DEVICE)
print(f"{args.model} on {DEVICE}; {windows.numel()} WikiText-2 test tokens "
      f"in {len(windows)} windows of {args.window}")


@torch.no_grad()
def perplexity(model):
    nll, n = 0.0, 0
    for x in windows:
        logits = model(x[None]).logits[0, :-1].float()
        loss = torch.nn.functional.cross_entropy(logits, x[1:],
                                                 reduction="sum")
        nll, n = nll + loss.item(), n + len(x) - 1
    return math.exp(nll / n)


def fresh():
    m = AutoModelForCausalLM.from_pretrained(args.model, dtype=torch.bfloat16)
    return m.to(COMPUTE).to(DEVICE).eval()   # bf16 values; fp32 off-GPU


# ── 4. Predict, quantise, measure ────────────────────────────────────────
model = fresh()
lin = sum(m.weight.numel() for n, m in model.named_modules()
          if isinstance(m, torch.nn.Linear) and "lm_head" not in n)
total = sum(p.numel() for p in model.parameters())
other = total - lin                  # embeddings, norms: left in 16 bits
print(f"{total / 1e6:.1f}M parameters, {lin / 1e6:.1f}M in quantised "
      f"linear layers, {other / 1e6:.1f}M left in 16 bits")
print(f"\n{'format':<22}{'predicted MiB':>14}{'perplexity':>12}")
base = perplexity(model)
mib = (lin * 2 + other * 2) / 2**20
print(f"{'16-bit (bf16 values)':<22}{mib:>14.1f}{base:>12.3f}")
del model

for label, bits, group in (("int8, per channel", 8, None),
                           (f"int4, group {args.group}", 4, args.group),
                           ("int4, per channel", 4, None)):
    model = fresh()
    packed = quantise_model(model, bits, group)
    mib = (packed + other * 2) / 2**20
    ppl = perplexity(model)
    print(f"{label:<22}{mib:>14.1f}{ppl:>12.3f}   "
          f"({ppl / base:.3f}x the 16-bit perplexity)")
    del model
    if DEVICE == "cuda":
        torch.cuda.empty_cache()

On a MacBook CPU (32-bit arithmetic on the 16-bit values) this printed:

134.5M parameters, 106.2M in quantised linear layers, 28.3M left in 16 bits

format                 predicted MiB  perplexity
16-bit (bf16 values)           256.6      20.846
int8, per channel              155.6      20.993   (1.007x the 16-bit perplexity)
int4, group 128                107.5      29.784   (1.429x the 16-bit perplexity)

What you should see

  • Sizes match the arithmetic. 256.6 MiB falls to 155.6 at int8 and about 107 at int4. Not 4 times smaller: the 28.3 million embedding and norm parameters stay in 16 bits and are now half the model. On a 7B model the embeddings are a much smaller share.
  • int8 is almost free: perplexity rises from 20.85 to 20.99, under 1%. Rounding every weight to one of 255 levels, with a scale per row, barely moves what the model predicts.
  • int4 is not free on a model this small. With a scale per group of 128 the perplexity is 1.43 times the baseline; with a scale per row it is 2.22 times. The only difference is how many weights share the largest value, which is the chapter's whole argument about granularity, now measured on a trained network.
  • The group size is not always 128. SmolLM2's hidden size is 576, and 576 / 128 is not a whole number, so absmax_quantise halves the group until it divides (64). Real tools handle this the same way or pad.
  • The perplexity is on 4,096 tokens, so differences of a percent or two are within noise of the sample; the orderings above are far larger than that.

Break it

  • Shrink the group. Run --group 32 on the laptop. Predict first: smaller groups confine each outlier, so perplexity should fall, and the scales cost 16 / 32 = 0.5 bit per weight instead of 0.125.
  • Per-tensor scales. Change group=None so that one scale covers a whole matrix (use w.abs().amax()). Predict whether the model survives 8 bits, then 4. (Chapter 19's matrix experiment gave 0.81 relative error at 4 bits per tensor.)
  • Quantise the embedding too. Add the embedding matrix to quantise_model. Which costs more perplexity per MiB saved: the embedding or the MLP layers?

Key takeaways

  • Absmax quantisation is three lines: a maximum, a division and a rounding. Everything else is bookkeeping about where the scales live.
  • Memory follows the packed layout exactly; "4-bit" is about 4.1 bits per weight with group scales, and parts left in 16 bits count too.
  • On a real model, int8 is almost free and int4 is not, and the granularity of the scale decides how much it costs.
  • Perplexity measured here is one sample of 4,096 tokens: it ranks the formats, but compare task results before shipping anything.
