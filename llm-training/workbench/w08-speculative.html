Workbench 8: Speculative Decoding, Timed

Generating text is slow because each new token needs a full pass through the model, one after another. Speculative decoding (chapter 21) lets a small, fast draft model guess several tokens ahead, and the large target model checks all the guesses in a single pass. The share of guesses the target accepts is the acceptance rate. Here you run Hugging Face’s version of the idea, which it calls assisted generation, count the acceptance rate, and compare the speed-up with the chapter’s formula. The result on a laptop is not the one the formula first suggests, and finding out why is the point.

Why measure it

The chapter’s formula is neat: a high acceptance rate means several tokens per target pass. But the speed-up depends on two costs it treats as small: running the draft, and checking several tokens at once instead of one. Whether those are small depends on the hardware, and you cannot tell from the formula alone. The habit to practise is to measure each assumption separately, so that when the end-to-end number disappoints you can say which one failed.

What you need

  • Part 1, your laptop: Python 3.10+, the workbench venv (below) and about 1 GB of disk for SmolLM2-135M and SmolLM2-360M. About 10 minutes on a CPU.
  • Part 2, a GPU box (optional): one 24 GB card, about 16 GB of disk for Qwen2.5-7B-Instruct plus 1 GB for its 0.5B draft, and about an hour. Setting one up is in Your lab machine, Option C.

Predict before you run

The expected number of tokens produced per target pass is the formula of chapter 21:

E[tokens per round] = (1 − αk+1) / (1 − α)

where α is the chance that one drafted token is accepted and k is how many tokens the draft proposes per round. A round costs one target pass plus k draft steps. If one draft step costs a fraction c of a target step, and checking k+1 tokens in one pass costs about the same as one step, the speed-up is:

speed-up = E[tokens per round] / (1 + k c)

Decoding is limited by reading the weights from memory (chapter 18), so a first guess for c is the ratio of the two models’ sizes. SmolLM2-135M has 134.5 million parameters and SmolLM2-360M has 361.8 million, so c ≈ 0.37 (the script prints the exact ratio of bytes).

Your prediction

Suppose α = 0.9 and k = 4. How many tokens does a round produce, and what speed-up do you expect with c = 0.37? Then write down whether you believe it for this laptop, and why.

Check your arithmetic

(1 − 0.95) / (1 − 0.9) = (1 − 0.59049) / 0.1 = 4.10 tokens per round. The speed-up is 4.10 / (1 + 4 × 0.37) = 4.10 / 2.48 = 1.65 times. Whether it holds depends on the two assumptions above, which the script measures one by one: the real c, and the real cost of checking k+1 tokens.

Part 1: on your laptop

Set up once

One virtual environment serves every workbench page. From the site’s folder:

$ python3 -m venv ~/.venvs/zts
$ ~/.venvs/zts/bin/pip install -r workbench/requirements.txt
$ source ~/.venvs/zts/bin/activate

The script is code/w08/spec_decode.py, and the same code split into cells is spec_decode.ipynb. The first run downloads the two models from Hugging Face: 269 MB and 724 MB (their 16-bit files; the script loads them as 32-bit floats on a CPU). The two models share a tokeniser, which assisted generation needs.

The idea

  1. time plain greedy decoding on the target, and on the draft alone; c = draft time / target time
  2. time one target pass over 1 token and over k+1 tokens; v = how many times dearer the longer check is
  3. for each k: run assisted generation, record in every round how many drafts were accepted
  4. acceptance rate = accepted / tested (a rejected token counts as tested); tokens per round = accepted + 1
  5. compare with the formula, then with the formula using the measured v; check the text is identical to plain decoding
  6. print the same formula for a GPU pair, on paper
"""Speculative decoding, timed: Hugging Face assisted generation with a
small draft model, against chapter 21's expected-tokens formula.

Laptop (SmolLM2-135M drafts for SmolLM2-360M, about 0.7 GB in total):
    python spec_decode.py
GPU box (a 7B target, a 0.5B draft):
    python spec_decode.py --target Qwen/Qwen2.5-7B-Instruct \
        --draft Qwen/Qwen2.5-0.5B-Instruct --new 256

Needs: torch, transformers (workbench/requirements.txt)."""
import argparse
import time

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.generation import candidate_generator as cg

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--target", default="HuggingFaceTB/SmolLM2-360M")
ap.add_argument("--draft", default="HuggingFaceTB/SmolLM2-135M")
ap.add_argument("--new", type=int, default=96)        # tokens per answer
ap.add_argument("--ks", default="1,2,4,8")            # draft lengths
ap.add_argument("--gpu-target-bytes", type=int, default=15231233024)
ap.add_argument("--gpu-draft-bytes", type=int, default=988097824)
ap.add_argument("--device", default="")               # cuda, mps or cpu
args, _ = ap.parse_known_args()        # notebooks pass their own flags

if torch.cuda.is_available():
    DEVICE, DTYPE = "cuda", torch.bfloat16
elif torch.backends.mps.is_available():
    DEVICE, DTYPE = "mps", torch.float32
else:
    DEVICE, DTYPE = "cpu", torch.float32
if args.device:                              # force, for example cpu
    DEVICE = args.device
    DTYPE = torch.bfloat16 if DEVICE == "cuda" else torch.float32

PROMPTS = [
    "The history of the printing press began in the fifteenth century,",
    "def fibonacci(n):\n    \"\"\"Return the n-th Fibonacci number.\"\"\"\n",
    "Q: What is the capital of France?\nA: Paris\n"
    "Q: What is the capital of Italy?\nA: Rome\n"
    "Q: What is the capital of Spain?\nA:",
]
tok = AutoTokenizer.from_pretrained(args.target)
target = AutoModelForCausalLM.from_pretrained(args.target, dtype=DTYPE)
draft = AutoModelForCausalLM.from_pretrained(args.draft, dtype=DTYPE)
target, draft = target.to(DEVICE).eval(), draft.to(DEVICE).eval()
print(f"target {args.target}, draft {args.draft}, {DEVICE}, {DTYPE}")


def sync():
    if DEVICE == "cuda":
        torch.cuda.synchronize()
    elif DEVICE == "mps":
        torch.mps.synchronize()


def nbytes(m):
    return sum(p.numel() * p.element_size() for p in m.parameters())


# ── 2. Count what the verifier decides, round by round ───────────────────
rounds = []                          # (tokens drafted, tokens accepted)
_orig = cg.AssistedCandidateGenerator.update_candidate_strategy


def spy(self, input_ids, scores, num_matches):
    rounds.append((scores[0].shape[0] - 1, num_matches))
    return _orig(self, input_ids, scores, num_matches)


cg.AssistedCandidateGenerator.update_candidate_strategy = spy


def generate(prompt, k=None, model=None):
    """Greedy answer; k=None is plain decoding, k=int speculates."""
    model = model or target
    ids = tok(prompt, return_tensors="pt").to(DEVICE)
    kw = dict(max_new_tokens=args.new, do_sample=False,
              pad_token_id=tok.eos_token_id, min_new_tokens=args.new)
    if k:
        g = draft.generation_config
        g.num_assistant_tokens, g.num_assistant_tokens_schedule = k, "constant"
        g.assistant_confidence_threshold = 0.0     # always draft k tokens
        kw["assistant_model"] = draft
    sync()
    start = time.perf_counter()
    with torch.no_grad():
        out = model.generate(**ids, **kw)
    sync()
    return out[0, ids["input_ids"].shape[1]:], time.perf_counter() - start


# ── 3. Plain decoding: the baseline, and the draft's relative cost c ─────
generate(PROMPTS[0])                                     # warm-up
generate(PROMPTS[0], 4)
generate(PROMPTS[0], model=draft)
plain = {p: generate(p) for p in PROMPTS}
t_plain = sum(t for _, t in plain.values()) / len(PROMPTS)
t_d = sum(generate(p, model=draft)[1] for p in PROMPTS) / len(PROMPTS)
c = t_d / t_plain                       # one draft step / one target step
print(f"\nplain decoding: {1000 * t_plain / args.new:.1f} ms per token on "
      f"the target, {1000 * t_d / args.new:.1f} on the draft")
print(f"c = {c:.2f}  (the weights alone say "
      f"{nbytes(draft) / nbytes(target):.2f})")



def verify_cost(n, reps=15):
    """Cost of one target pass over n new tokens, relative to one token:
    chapter 21 assumes this is 1 (decode is memory-bound)."""
    ids = tok(PROMPTS[0] * 8, return_tensors="pt").to(DEVICE)["input_ids"]
    ids = ids[:, :64]
    new = torch.randint(0, 1000, (1, n), device=DEVICE)
    times = []
    with torch.no_grad():
        past = target(ids, use_cache=True).past_key_values
        for _ in range(reps):
            sync()
            start = time.perf_counter()
            target(new, past_key_values=past, use_cache=True)
            sync()
            times.append(time.perf_counter() - start)
            past.crop(64)                  # forget the n new entries
    return sorted(times)[reps // 2]


one = verify_cost(1)
V = {k: verify_cost(k + 1) / one for k in (1, 2, 4, 8)}
print("verifying k+1 tokens in one pass costs, relative to 1 token: " +
      ", ".join(f"k={k}: {v:.2f}" for k, v in V.items()))

# ── 4. Speculate: measure acceptance, tokens per round and speed-up ──────
print(f"\n{'k':>3} {'alpha':>6} {'tok/round':>10} {'formula':>8} "
      f"{'speedup':>8} {'formula':>8} {'with v':>7} {'extra ms':>9}  same")
for k in [int(x) for x in args.ks.split(",")]:
    rounds.clear()
    t_spec, same = 0.0, True
    for p in PROMPTS:
        out, t = generate(p, k)
        t_spec += t / len(PROMPTS)
        same &= bool(torch.equal(out, plain[p][0]))
    accepted = sum(m for _, m in rounds)
    tested = sum(m + (m < d) for d, m in rounds)   # a miss is a test too
    alpha = accepted / tested                      # per-token acceptance
    per_round = sum(m + 1 for _, m in rounds) / len(rounds)
    formula = (1 - alpha ** (k + 1)) / (1 - alpha)     # chapter 21
    step = 1000 * t_plain / args.new                  # ms per target step
    round_ms = 1000 * t_spec / (len(rounds) / len(PROMPTS))
    extra = round_ms - step * (k * c + V.get(k, 1))   # not in the model
    print(f"{k:>3} {alpha:>6.2f} {per_round:>10.2f} {formula:>8.2f} "
          f"{t_plain / t_spec:>7.2f}x {formula / (1 + k * c):>7.2f}x "
          f"{formula / (k * c + V.get(k, 1)):>6.2f}x "
          f"{extra:>9.0f}  {same}")

# ── 5. The GPU case, on paper (nothing here ran on a GPU) ────────────────
c_bytes = args.gpu_draft_bytes / args.gpu_target_bytes
print(f"\nGPU prediction, k=4: draft/target weights = {c_bytes:.3f}")
cs = [("c=bytes", c_bytes), ("c=0.2", 0.2), ("c=0.4", 0.4)]
print(f"{'alpha':>6} {'E[tok]':>7}  " + "  ".join(f"{n:>8}" for n, _ in cs))
for a in (0.6, 0.7, 0.8, 0.9):
    e = (1 - a ** 5) / (1 - a)
    print(f"{a:>6.1f} {e:>7.2f}  " +
          "  ".join(f"{e / (1 + 4 * x):>7.2f}x" for _, x in cs))

What you should see

  • alpha is about 0.9. The draft proposes the target’s own choice nine times in ten. The two models are the same family trained on similar text, and the three prompts (prose, code, a question-and-answer pattern) are predictable. Your own text will give a different rate.
  • Tokens per round matches the formula. Measured 4.17 against 4.20 at k = 4, 6.40 against 6.44 at k = 8. The chapter’s geometric-series model, which assumes each token is accepted independently, describes this run very well.
  • The last column is True. The assisted text is identical, token for token, to plain greedy decoding. That is the “lossless” claim of chapter 21, observed.
  • The speed-up is below 1. Speculation made this run slower: 0.78 to 0.90 times, where the first formula says 1.4 to 1.7. Two things explain most of it.
  • First assumption: the draft is cheap. It held. c = 0.36, almost exactly the 0.37 the weights predict.
  • Second assumption: checking k+1 tokens costs one step. It failed. It cost 1.6 to 2.1 times one token on this CPU. My reading is that a CPU turns arithmetic-limited as soon as more than one token is processed, but I only measured the cost, not the cause. Put the measured cost into the formula (the “with v” column divides tokens per round by k × c + v) and it falls from 1.4 to 1.7 down to 0.80 to 1.44.
  • The rest is bookkeeping. The “extra ms” column is the measured round time minus the model’s: from 2 ms at k = 1 to 142 ms at k = 8. Each round, Hugging Face compares the drafts with the target’s choices, trims the cache and hands control back to Python, and more drafted tokens means more of that work. I did not separate the parts.

The prediction table printed by the script uses three guesses for c at k = 4. The first is the ratio of weight sizes from the two models’ files: 988,097,824 bytes (the 0.5B draft) over 15,231,233,024 bytes (the 7B target) = 0.065. That would hold if decoding were purely a matter of reading weights, and it gives the largest speed-ups, 1.8 to 3.3 times for α between 0.6 and 0.9. It is an upper bound. The draft has 24 layers against the target’s 28, and a library that launches each layer’s operations one by one (as Hugging Face’s does) spends a fixed time per layer, so a small model is slower than its size suggests. The columns for c = 0.2 and 0.4 are illustrative assumptions for that case, not predictions from a source. At c = 0.4 and α = 0.6, speculation loses (0.89 times). Engines such as vLLM trim the fixed cost, which is why their c is nearer the first column.

Break it

  • Use a draft as big as the target. Pass --draft HuggingFaceTB/SmolLM2-360M, the same model as the target. It accepts every token (α = 1) but costs c = 1. Predict the speed-up at k = 4 from the formula first. (Answer: 5 tokens per round over 1 + 4 × 1 = 5 steps, so 1.0 at best, before any overhead.)
  • Change the text. Replace the three prompts with something unpredictable, such as a request for a list of random words. Predict the direction of α first, then use the formula to say what it does to tokens per round.
  • Push k. Run --ks 1,2,4,8,16. The formula says tokens per round keeps rising towards 1 / (1 − α) = 10 at α = 0.9, while the cost of the draft steps grows linearly. Where does your speed-up peak?

Key takeaways

  • Measured tokens per round agreed with chapter 21’s formula, and the speculative text was identical to plain decoding.
  • The speed-up is not just the acceptance rate. It also needs a cheap draft (small c) and a check of k+1 tokens that costs about one step (v near 1). On this laptop the check was not free and the bookkeeping was large, so speculation was slower.
  • Measure each assumption by itself. Here the draft was as cheap as predicted, the check was not free, and per-round bookkeeping took the rest.
  • Speculation pays when the target’s step is long, memory-bound and dominated by reading weights, which is the large-model GPU case, and when the draft is truly cheap. Predict that case from sizes, then measure it.
