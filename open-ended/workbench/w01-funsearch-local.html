Workbench 1: Program Evolution with a Real Model

In Lab 3 a scripted editor changed the bin-packing rule. It was a stand-in. Here a real language model writes the new rules. The loop around it is unchanged: pick a few good programs, show them to the model, take the program it writes, check it, score it, store it. You then judge the winner on instances the search never saw, as chapter 16 demands, and you find out whether a small model can beat the textbook rule at all.

Why measure it

Chapter 9 says a language model is a mutation operator that understands what it edits, and that the evaluator matters as much as the model. Both claims are easy to read and easy to believe too much. A real model is messy. Most of its replies will not even be valid for the evaluator. The ones that run are often no better than the starting rule. The point of this page is to see that mess, count it, and see how the loop still finds something, some of the time. A language model here means a program that continues text. An endpoint means a server that answers such requests over HTTP. Held-out means scored on data the search never looked at.

What you need

  • Your laptop: Python 3.9 or newer and nothing else to install. The script uses only the standard library.
  • A model behind an OpenAI-compatible endpoint. The default is Ollama serving qwen2.5-coder:7b (about 4.7 GB to download). Any server that speaks the same protocol works: vLLM, LM Studio, or transformers serve.
  • Time: about two hours with reading. A 100-call run takes 4 to 10 minutes with a 0.5B model on a laptop GPU. With a 7B model, expect 10 to 20 seconds a call, so 20 to 35 minutes.

Predict before you run

The task is the one from chapter 9: bins of 100 units, items of size 20 to 60 arriving one at a time, one function priority(item, rem) to evolve. No packing can use fewer bins than the total size divided by 100. We call the gap above that bound the excess:

excess = mean bins used − (total item size / 100)

The excess is the room an evolved rule has to improve. Best fit is the standard rule: put the item where it leaves the least space. First fit puts it in the earliest bin that has room.

Your prediction

The held-out test set has 30 instances of 300 items. Their mean total is about 12,020, so the bound is near 120.2 bins. Chapter 9 reports best fit at about 130.8 bins on this set. Work out the excess of first fit and best fit before you run anything. Then guess three things. What share of a 0.5B model’s replies will be a valid, runnable priority? Will the best rule it finds beat best fit on the held-out set? How many bins of excess could any evolved rule remove?

Check your arithmetic and my reasoning

The script computes the baselines before it touches a model, so you can check them at once. On the test set: lower bound 120.2, first fit 131.0 (excess 10.7), best fit 130.8 (excess 10.5). The two classic rules differ by only 0.2 bins. Both waste about 10 bins in 130, roughly 8 per cent.

My reasoning, written before the runs below. The evaluator is strict: one function, no loops, no imports, only abs, min and max may be called. A 0.5B model will break those rules often, so I expected well under a third of replies to be usable. Of those, most would be copies or near-copies of best fit. I expected the best rule to gain at most a bin or two, because chapter 9’s scripted search reached 129.1 on the same set, 1.7 bins under best fit. Whether a given run beats best fit at all I expected to be close to a coin flip. The runs below say how close.

Run it

Set up once

Start a model server. With Ollama:

$ ollama pull qwen2.5-coder:7b
$ ollama serve        # skip this if the Ollama app is already running

The files are in open-ended/workbench/code/w01/: evolve_llm.py (the loop, below), binpack.py (Lab 3’s problem, whitelist and fuel-limited evaluator, and island database, reflowed to 80 columns) and the notebook evolve_llm.ipynb. Keep binpack.py next to the script. Nothing here needs the workbench virtual environment.

binpack.py is where the vocabulary of the A0 chapters on programs as data and running candidates safely lives. A candidate is a string of Python nobody has read. validate parses it into a syntax tree and refuses any node type that is not on a whitelist. instrument adds a step counter (the fuel) so a loop that never ends runs out. evaluate is total: every candidate, good or bad, comes back as an Outcome with a status and never as an exception.

The idea

  1. compute the lower bound, first fit and best fit on three sets of instances: search (10), selection (10), test (30)
  2. for each of N calls: take one island, draw 2 programs from it, worst first, and build a best-shot prompt
  3. send the prompt to the endpoint; cut the first function out of the reply and rename it priority
  4. skip it if seen before; otherwise evaluate on the search set (the evaluator may refuse it) and store it by signature
  5. every 25 calls, replace the weakest islands by copies of the best
  6. take each island’s best as a finalist, pick one on the selection set, and score that one on the test set, once
"""Program evolution with a real model: Lab 3's loop, with a language model
writing the new priority() functions instead of a scripted editor.

The model is any OpenAI-compatible server. Ollama on a laptop (default):
    ollama pull qwen2.5-coder:7b
    python evolve_llm.py --model qwen2.5-coder:7b
vLLM on a GPU box, or `transformers serve` (any OpenAI-compatible server):
    python evolve_llm.py --base-url http://127.0.0.1:8000/v1 \\
        --model Qwen/Qwen2.5-0.5B-Instruct

Needs: Python 3.9+ and binpack.py next to this file. No other packages."""
import argparse
import ast
import json
import random
import re
import time
import urllib.request
from collections import Counter

from binpack import (SEED_SRC, FIRST_FIT_SRC, TRAIN_SEEDS, SELECT_SEEDS,
                     TEST_SEEDS, Database, canonical, evaluate, lower_bound,
                     make_instances)

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--base-url", default="http://localhost:11434/v1")
ap.add_argument("--model", default="qwen2.5-coder:7b")
ap.add_argument("--api-key", default="none")          # Ollama ignores it
ap.add_argument("--calls", type=int, default=100)      # model calls (budget)
ap.add_argument("--islands", type=int, default=4)
ap.add_argument("--shots", type=int, default=2)       # programs per prompt
ap.add_argument("--temperature", type=float, default=0.8)
ap.add_argument("--max-tokens", type=int, default=300)
ap.add_argument("--reseed-every", type=int, default=25)
ap.add_argument("--seed", type=int, default=0)
ap.add_argument("--log", default="evolve_llm.jsonl")
args, _ = ap.parse_known_args()        # notebooks pass their own flags

train = make_instances(TRAIN_SEEDS)    # the search set
select = make_instances(SELECT_SEEDS)  # picks among finalists, once
test = make_instances(TEST_SEEDS)      # reported once, at the very end

# ── 2. Predict: what the two classic rules score (no model involved) ─────
print(f"model {args.model} at {args.base_url}")
for name, sets in (("search", train), ("selection", select), ("test", test)):
    lb = sum(map(lower_bound, sets)) / len(sets)
    ff = evaluate(FIRST_FIT_SRC, sets).score
    bf = evaluate(SEED_SRC, sets).score
    print(f"{name:9s} ({len(sets):2d} instances)  lower bound {lb:6.1f}   "
          f"first fit {ff:6.1f} (+{ff - lb:4.1f})   "
          f"best fit {bf:6.1f} (+{bf - lb:4.1f})")


# ── 3. The sampler: one chat request, one reply ──────────────────────────
def chat(system, user):
    body = {"model": args.model, "max_tokens": args.max_tokens,
            "temperature": args.temperature,
            "messages": [{"role": "system", "content": system},
                         {"role": "user", "content": user}]}
    req = urllib.request.Request(
        args.base_url.rstrip("/") + "/chat/completions",
        data=json.dumps(body).encode(),
        headers={"content-type": "application/json",
                 "authorization": "Bearer " + args.api_key})
    with urllib.request.urlopen(req, timeout=300) as r:
        reply = json.loads(r.read())
    return reply["choices"][0]["message"]["content"]


SYSTEM = "You are an expert Python programmer. Reply with Python code only."
TASK = """\
Online bin packing. Bins hold 100 units. Items of size 20 to 60 arrive one
at a time. priority(item, rem) scores a bin that has rem units free; the
item goes into the feasible bin with the HIGHEST score. We want few bins.

Below are versions of priority, worst first, each with the mean number of
bins it used. Each is better than the one before. Write priority_v{k}: a
new version that should use fewer bins than the last one.

Rules: use only item, rem, numbers, + - * / // %, comparisons, if, abs,
min and max. No imports, no loops, no other functions.

{versions}

Reply with one Python code block that holds only the function
priority_v{k}(item, rem).
"""


def build_prompt(parents, scores):
    """Best-shot prompt (chapter 9): numbered versions, worst first."""
    shown = []
    for v, (src, score) in enumerate(zip(parents, scores)):
        body = src.replace("def priority(", f"def priority_v{v}(", 1)
        shown.append(f"# mean bins: {score:.1f}\n{body}")
    return TASK.format(k=len(parents), versions="\n".join(shown))


# ── 4. Turn a reply into a candidate (or say why not) ────────────────────
def extract(reply):
    """The first function named priority... in the reply, renamed to
    priority, docstring removed. Returns source text, or None."""
    fenced = re.findall(r"```(?:python)?\n(.*?)```", reply, re.S)
    code = fenced[0] if fenced else reply
    code = code[code.find("def priority"):] if "def priority" in code else ""
    lines = code.splitlines()
    for end in range(len(lines), 0, -1):        # longest prefix that parses
        try:
            tree = ast.parse("\n".join(lines[:end]))
        except SyntaxError:
            continue
        for node in tree.body:
            if isinstance(node, ast.FunctionDef):
                node.name = "priority"
                first = node.body[0]
                if (isinstance(first, ast.Expr)
                        and isinstance(first.value, ast.Constant)
                        and len(node.body) > 1):
                    node.body.pop(0)            # drop a docstring
                return ast.unparse(node)
        return None
    return None


# ── 5. The loop: sample, extract, evaluate, store ────────────────────────
rng = random.Random(args.seed)
seed_src = canonical(SEED_SRC)
seed_out = evaluate(seed_src, train)
db = Database(args.islands, seed_src, seed_out)
seen, tally, why = {seed_src}, Counter(), Counter()
better = 0                           # samples that beat best fit (search set)
log = open(args.log, "w")
t0 = time.time()
print(f"\n{args.calls} calls, {args.islands} islands, temperature "
      f"{args.temperature}; search-set best fit = {seed_out.score:.1f}")
for call in range(args.calls):
    isl = call % args.islands
    parents = db.islands[isl].sample(rng, args.shots)
    scores = [evaluate(p, train).score for p in parents]
    try:
        reply = chat(SYSTEM, build_prompt(parents, scores))
    except OSError as err:
        raise SystemExit(f"cannot reach the model server: {err}")
    src = extract(reply)
    if src is None:
        status, score = "no_code", None
    elif src in seen:
        status, score = "duplicate", None
    else:
        seen.add(src)
        out = evaluate(src, train)
        status, score = out.status, out.score if out.ok else None
        if not out.ok:
            why[out.detail.split(":")[0][:44]] += 1
        better += out.ok and out.score < seed_out.score
        db.islands[isl].add(src, out)
    tally[status] += 1
    log.write(json.dumps({"call": call, "island": isl, "status": status,
                          "score": score, "src": src,
                          "reply": reply[:600]}) + "\n")
    if (call + 1) % args.reseed_every == 0:
        db.reseed(rng)
    if (call + 1) % 10 == 0:
        print(f"  call {call + 1:3d}  best search score "
              f"{-db.best()[1]:6.2f}  {time.time() - t0:5.0f} s")
log.close()
print("outcomes of the model's samples:",
      ", ".join(f"{k} {v}" for k, v in sorted(tally.items())))
print("most common reasons a sample was refused or failed:")
for reason, n in why.most_common(4):
    print(f"  {n:3d}  {reason}")
print(f"samples that beat best fit on the search set: {better}")

# ── 6. Chapter 16: three sets. Finalists, then one winner, then test ─────
finalists = {}                       # best program of each island
for isl in db.islands:
    if isl.best():
        finalists[isl.best()[0]] = None
ranked = sorted(finalists, key=lambda p: evaluate(p, select).score)
winner = ranked[0]
print("\nfinalists on the selection set:")
for p in ranked:
    print(f"  {evaluate(p, select).score:6.2f}   "
          f"(search {evaluate(p, train).score:6.2f})   "
          f"{len(p):3d} chars{'   <- winner' if p == winner else ''}")
print("\nwinner:\n" + winner)

# The test set is touched once, for the winner and the two baselines.
lb = sum(map(lower_bound, test)) / len(test)
mine = evaluate(winner, test)
bf = evaluate(SEED_SRC, test)
ff = evaluate(FIRST_FIT_SRC, test)
print(f"\nheld-out test set (30 instances), lower bound {lb:.1f} bins:")
for name, o in (("first fit", ff), ("best fit", bf), ("evolved", mine)):
    print(f"  {name:10s} {o.score:6.2f} bins   +{o.score - lb:5.2f} over "
          f"the bound")
wins = sum(m < b for m, b in zip(mine.bins, bf.bins))
losses = sum(m > b for m, b in zip(mine.bins, bf.bins))
print(f"  against best fit, instance by instance: {wins} better, "
      f"{losses} worse, {len(test) - wins - losses} tied")
verdict = "beats" if mine.score < bf.score else "does not beat"
print(f"  the evolved program {verdict} best fit on held-out instances")

These numbers will not repeat exactly

The first four lines (the baselines) are exact and will match yours. Everything after them depends on what the model happens to write. The server takes no random seed, and the script’s own --seed only fixes which programs are drawn into each prompt. Expect different counts and, as the next section shows, sometimes a different verdict.

What you should see

  • The first three lines. They are the baselines on each set. Best fit is within 0.2 to 0.4 bins of first fit everywhere. The excess is about 10 bins.
  • The outcome line. Of 100 calls, 60 were rejected before running, 14 had no function to extract, 7 repeated a known program and 1 ran out of fuel. Only 18 were scored. The usual reasons are in the next block. The model was told not to loop, import or call other functions, and it often did anyway. The whitelist did its job: nothing it wrote ever ran unchecked.
  • “Samples that beat best fit on the search set: 0”. In this run, no candidate was better than the starting rule on the search set. The search score never moved from 130.30. The loop had nothing to build on.
  • Finalists and winner. With nothing better, the finalists are copies of best fit written differently, such as -(rem - item). On the selection set they tie. The test score of the winner is exactly best fit’s on every instance: 30 ties.
  • The verdict line is computed, not hoped for. It says “does not beat” unless the mean really is lower.

Did the small model ever beat best fit?

That was one run. Sampling is random, so I ran the same script again with different --seed values, and once with a larger code model. These are all real runs on the same laptop, using the same held-out test set. Best fit scores 130.77 on it.

My first trial, with 120 calls and an earlier setting of the island restart, also found a winner: 129.87 on the test set, 20 instances better and 1 worse. So the honest answer is yes, sometimes. Of the four runs of the 0.5B model (counting the first trial), three beat best fit on held-out instances, by 0.8 to 1.3 bins. One found nothing. The one run of the larger code model (1.5B) also won, by 0.6 bins, and 55 of its 100 samples were usable, against about 20 for the 0.5B model. The gain is real in the sense that it holds on 30 instances the search never saw. It is small: about 1 per cent of the bins, or a tenth of the excess.

Read the winners with care. The seed 2 winner is a rule a person would call odd:

def priority(item, rem):
    gap = rem - item
    if gap >= 20:
        return -gap // 20
    elif gap >= 40:
        return -gap // 40
    else:
        return -gap

The elif branch can never run, because every gap of 40 or more is already caught by the first test. The rule works anyway. It treats all gaps from 20 up as almost equal, so ties go to the earliest bin, which is first fit’s behaviour, while small gaps below 20 are still penalised heavily, the way best fit does it. That echoes the rule chapter 9 found: avoid leaving a gap of 1 to 19, because no item that small ever arrives. The model did not reason this out. The selection pressure found it among its noise.

One caution about this table, from chapter 16. Each run touched the test set only once. But I have now looked at that same test set after four runs. If you keep choosing between settings by what the test set says, you are using it as a selection set, and its numbers stop being honest. The gains here are small enough that you should not trust them to the second decimal place.

What a bigger local model should expect

A prediction, not a result

I did not run a 7B model for this page, so nothing below is measured. If you run qwen2.5-coder:7b through Ollama, here is what I expect, and why. A 7B code model follows instructions much better than a 0.5B one, so I expect the share of usable samples to rise from about 20 per cent to somewhere above half. The 1.5B code model already shows the direction: 55 usable samples in 100. The rest will still be refused now and then, for example when it imports math. I expect more of the usable samples to be genuinely different rules, not copies. That should make a run beat best fit on held-out instances in most seeds, which is only a little better than the three in four seen here. I would still expect the gain to stay around one bin, as in the table, because the room above the best online rule is small and the lower bound cannot be reached online. Treat a 7B run that gains three bins or more with suspicion. That is what the tripwire in the next workbench is for.

Break it

  • Make the sampler deterministic. Run with --temperature 0. Predict first: for the same parents the model writes the same reply, so the outcome line should show many more duplicates, and the search should stall sooner. Then check.
  • Show one program, not two. Run with --shots 1. Predict: the prompt now shows no improving sequence to continue, so the best-shot effect of chapter 9 should weaken. Count the “beat best fit” line over three seeds before you believe either way.
  • Skip the selection set. In section 6, set ranked by the search score instead. With four islands the winner may change. Predict how often the search winner would differ from the selection winner in your runs, and how far its test score would fall below its search score. The search set has only 10 instances, so the winner is partly lucky.
  • Loosen the evaluator. Add ast.For and range to the whitelist in binpack.py, so the “For is not allowed” refusals turn into runs. Predict what goes wrong: look at which node types instrument adds a step counter to, and at what a loop of a billion passes would do. Then fix it.

Key takeaways

  • A real model is a noisy mutation operator. In 100 calls, a 0.5B model gave about 20 programs the evaluator would run. The evaluator is what keeps the rest harmless.
  • The whitelist, the fuel and the total evaluator from the A0 chapters are what let you point an untrusted generator at your machine and sleep.
  • With three sets of instances, a lucky search score is separated from the number you report. Only the test score, touched once, is allowed to be believed.
  • A small model beat best fit on held-out instances in three of four runs, by about one bin, and failed in one. Report all of them, not the best.
  • For a 7B model the expectation above is a prediction. Measure it before you cite it.
