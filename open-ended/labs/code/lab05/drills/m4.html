The search loop seeds the archive with hand-written baselines, then repeats: ask a proposer for a design, check it, score it, store it. A proposal that fails validation is a repair, the stand-in for showing a model its error and asking again. A valid design already in the archive is a duplicate. After a fixed number of fruitless asks the iteration is skipped.

meta_search scores each seed design on the search questions and stores it with iteration 0 and no parent. In each iteration, ask the proposer up to MAX_REPAIRS + 1 times, counting repairs and duplicates in the SearchResult. Score the first valid new design with evaluate and store it with its parent's name and the iteration number. Pass random.Random(seed) to the proposer. Two traps show in the counts: a typo is not a new design, so it must never reach the archive or the evaluator; and the loop may touch only the search questions.
