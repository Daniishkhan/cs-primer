The check out == want lets the candidate answer for itself. Python asks the left-hand object, the candidate's output, whether it equals the right-hand one, and an object whose __eq__ always returns True agrees to everything. The repair is to compare only things the grader can trust, and to test the type before any comparison that could run the candidate's code.

strict_equal(out, want) is true only if out is exactly an int and equals want. Use type(out) is int, not isinstance(out, int): isinstance also accepts an int subclass whose __eq__ lies, and bool is such a subclass (True == 1). Put the type test first, so the == never runs on a stranger.

strict_equal(5, 5)     -> True
strict_equal(True, 1)  -> False
strict_equal(5.0, 5)   -> False
