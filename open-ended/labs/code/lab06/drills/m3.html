What a candidate can see matters as much as what it returns. If it runs in the same namespace as the grader's disk and clock, it can read the answer key from that disk, or overwrite the key with its own answer before the grader reads it back. The standard defence is a small trusted core and a narrow channel: each call gets a fresh world that holds nothing of the grader's, and only the return value crosses back.

run_isolated(source, xs, k) builds that world with load_world (already written), a throwaway Meter and no extras. It then calls solve in it on tuple(xs) and k. The tuple copy means the candidate cannot change the grader's list. Return what solve returns and let exceptions propagate: the harness decides that a crash earns nothing. Because the world is rebuilt for every call, nothing a candidate stored in a global survives to the next one.

a candidate that counts its calls in a global returns 1 every time
a candidate that reads FS fails with NameError
