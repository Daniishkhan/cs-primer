The leaky timer has three flaws. It runs each test three times in one warm namespace and keeps the fastest, so a program that remembers its answers (memoisation) pays once and is nearly free after. It starts the clock after loading, so work done at import time costs nothing. And the meter is a name the candidate can reach, so it can read the clock before the work and write the old value back after. One principle fixes all three: the grader owns the meter, and every measurement starts cold.

cold_ticks(source, xs, k) makes a Meter that only the grader holds, builds a new world with load_world and no extras (it already counts the load, through measure), then measures one call of solve on tuple(xs) and k against the same meter. No repeats, no reused namespace. Return meter.ticks: the load plus the call, as a fresh process would see it. Exceptions propagate.

def solve(xs, k):   # 1 tick when loaded
    return 0        # 1 tick when called: 2 in all
