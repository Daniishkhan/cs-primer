If the same eight tests are used on every evaluation, a search learns them: a lookup table of their answers beats every honest program. The cure is to generate tests inside the grader from a seed the candidate never sees, and to change them. A generator also writes the tests you forgot, so it puts the awkward cases first.

hidden_tests(seed, n) returns n pairs (xs, k) with 0 <= k <= len(xs). Draw everything in order from your own random.Random(seed), never the global generator, so a seed always gives the same tests and the first n tests are a prefix of any longer list. The docstring fixes the first four tests (k = 0, k = len(xs), many repeats, the empty list) and the ranges of the random ones. Redraw a test that equals one in VISIBLE.

xs = [3, 1, 2], k = 0: the answer is 0
sum(sorted(xs)[-k:]) gives 6, because [-0:] is the whole list
