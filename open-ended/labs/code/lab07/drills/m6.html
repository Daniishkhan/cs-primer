An improver can cheat at the meta level, so it needs auditing. An improver is a function that receives a scorer, and in one Python process it can also import the module and call meta_utility itself, with ten times the budget or on the held-out tasks. The defence is a tripwire: run the improver under a spy that records what it asks for.

audit snapshots BUDGET, TRAIN_TASKS and HELD_TASKS, then swaps the module's meta_utility for a spy with the same signature that records (task_seeds, budget) and calls the real one. Assigning module-level names needs global. Run the improver with make_scorer(). In a finally block, put the real function and the constants back, even if the improver crashes. Reasons come in the order "peeked", "budget", "tampered", each at most once. A tripwire is not a wall: a determined cheater in the same process could rebind the name.
