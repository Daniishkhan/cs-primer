Given a config (the settings of the evolver, the search that writes heuristics), how good is it? You cannot ask the config. You run the evolver with it and look at what comes out. Three rules make the number fair. The budget is fixed, so a config cannot win by running longer. Each task gets a fresh Budget, because a shared counter would let the first task use it all. And the heuristic found is scored on instances the evolver never saw, or a config that overfits its search instances would look best.

For each task seed t, build the search instances from seeds 1000*t + j and the scoring instances from 1000*t + 500 + j with make_instances (counts N_SEARCH and N_EVAL, sizes lo and hi). Run evolve(config, search, counter, random.Random(t)), then take utility of what it returns on the scoring instances. Return the mean over tasks. The same arguments must always give the same number.

budget = 1: the evolver can score only the seed program,
so every config gets the seed's utility on the scoring instances
