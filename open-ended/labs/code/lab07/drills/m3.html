With a score for configs you can search over configs. The simplest search is hill climbing: change something, keep the change if the score rises, otherwise drop it. The improver does this on a Config, the evolver's settings. It has settings of its own, in a Settings record: proposals candidates per round, n_change fields changed per candidate, and step positions moved along a field's list of choices.

Start with best = config and its score. Each round, draw all settings.proposals candidates from the current best with the given perturb(best, CHOICES, rng, n_change, step), and only then score them in order. The checker replays the exact sequence of configs scored, so the order of drawing and scoring matters. A candidate replaces the best only if its score is strictly higher: a tie changes nothing. The score calls number 1 + rounds * proposals. Return (best_config, best_score).
