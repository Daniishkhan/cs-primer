A gain measured on the tasks an improver (a search over configs) used is biased: it kept whichever settings looked best there, so some of the gain is luck. One level up this is meta-overfitting: the improver fits its training tasks, not the problem. To measure it, run the improver on the training scorer only, then re-score the config it ends with on two scorers it never used: a held-out one with new tasks, and a shifted one with new tasks and a different range of item sizes.

For each seed s, run improve with train_score alone, random.Random(s) and calls // settings.proposals rounds. Each gain is a scorer's value for the final config minus its value for start. Return a dict of means over the seeds: train, held, shifted and gap, which is train - held. A positive gap means overfitting. A naive start config needs a structural fix that should transfer; a hand-tuned one does not, so its gains should not.
