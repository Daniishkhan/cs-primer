An improver (a hill climber over configs) has settings of its own, and settings are numbers, so you can improve the improver with its own method. That needs a score for an improver: the mean gain it makes from a fixed start config, over a few random streams. It is a number like any other, one level up.

improver_utility(settings, score, ...) computes score(start) once, runs improve once per seed with random.Random(s), and averages best_score minus that start score. For a fair fight every improver gets about the same number of score calls, so use rounds = calls // settings.proposals. Without that rule more proposals would always win, and you would learn only that compute helps. self_improve hill-climbs over Settings exactly as improve does over Config: one candidate per round, from perturb(best, SETTING_CHOICES, rng, 1, 1), scored by improver_utility and kept only if strictly better. That is 1 + rounds utility calls.

calls = 4: proposals 4 gives 1 round, proposals 2 gives 2 rounds,
proposals 1 gives 4 rounds
