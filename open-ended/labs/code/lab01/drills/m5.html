Tree search repeats one iteration (select a path, expand one child, simulate a random game, backpropagate the result) many times and keeps the tree it grows. Selection sends more visits to moves that keep looking good, so the visit counts at the root's children become the search's opinion of each move.

mcts creates a root Node. Then, iters times, it walks down with select_child while the current node has no untried moves but does have children, calls expand only if the node has an untried move, scores the node with rollout_fn and hands the result to backpropagate. A node with neither untried moves nor children is a finished game: stay on it. Return the root. best_move returns the move of the child with the most visits, not the highest win rate: one lucky visit gives a perfect win rate, but many visits mean the move survived many attempts to refute it.
