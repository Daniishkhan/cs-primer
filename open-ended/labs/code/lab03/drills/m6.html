The loop's budget counts calls of the mutator (the function that writes a child program), because with a real model that is what costs money. A call picks the island whose turn it is, draws parents from it, asks the mutator for a child, evaluates the child (unless that exact text was seen before, which is still a call) and stores it. Every so often the database reseeds, and the best fitness after each call is recorded.

funsearch(budget, seed, ...) uses one random.Random(seed) for everything. Evaluate canonical(SEED_SRC) first, which is not a call, and put it on every island. Call i (from 0) works on island i % n_islands, and a reseed follows call reseed_every, call 2 * reseed_every and so on. report(src) is the honest part of the loop: a program's mean bins on the training instances the search saw and on held-out instances it never saw (build both with make_instances, score with evaluate), next to best fit's, and the saving on each.

500 calls: saves 1.60 bins on training instances but 1.13 on held-out ones
