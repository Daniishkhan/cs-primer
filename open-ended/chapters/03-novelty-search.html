Why Objectives Deceive

The obvious way to find a hard thing is to measure how close each attempt is and keep the closest. Sometimes that is exactly the wrong thing to do: the attempts that look worst can be the ones that lead to the goal. This chapter shows how an objective turns into a trap, how novelty search escapes it by ignoring the objective altogether, and what that means for the search loops in the rest of the course.

Why this matters

The last two chapters assumed that a higher score means you are closer to what you want. Almost every self-improving AI system leans on the same assumption: score a candidate, keep the best, repeat. When it fails, it fails quietly: the loop converges, the score looks fine, and nobody notices the better solutions it never visited. After this chapter you can recognise a deceptive problem, you know the standard escape (rewarding novelty or diversity instead of, or beside, the score), and you can predict where hill-climbing prompt optimisers, evolutionary program search and reward-trained agents are likely to get stuck. It also prepares the ground for quality-diversity and open-ended algorithms, which turn this idea into a method.

When the score points the wrong way

Consider the instruction "get to the airport as fast as you can" given to a navigation app that can only see straight-line distance. At a river with a single bridge two kilometres upstream, the app will lead you to the nearest bank, which is 300 metres from the airport as the crow flies and utterly useless, and leave you there, because every step away from the bank "makes things worse". The map says you are close; the road says you are not. The straight-line distance is a perfectly reasonable objective (a number that measures progress) that happens to be a bad guide.

A problem is deceptive when following the objective's gradient leads away from the global optimum, so that a search which only accepts improvement converges on a local optimum (a point better than all its neighbours but worse than the best point overall). The phrase comes from the genetic-algorithm literature (Goldberg, 1987); Kenneth Stanley and Joel Lehman made it central to open-endedness research. Deception is not exotic. It appears whenever the route to a goal must pass through states that score badly on the measure you chose:

  • A hospital optimising average waiting time per patient may get stuck with a rota that is locally optimal, while a redesign of the whole pathway (a worse score during transition) would halve it.
  • An engineer tuning a compiler for speed on a benchmark may keep a risky shortcut that works on this benchmark; the changes needed for a deeper redesign make the benchmark slower first.
  • A prompt optimiser that keeps whichever prompt scores best on a test set can keep adding instructions to fit quirks, and never visits the quite different prompt structure that would score better.
  • A research programme funded by "most promising by this year's metric" tends to select against the odd ideas that later turn out to be foundations.

A trap you can run

The smallest deceptive problem is a trap function. The genome is 20 bits. The score falls by one for every 1 bit you add, from 19 for the all-zeros string down to 0 for the string with nineteen 1s. Then, at exactly twenty 1s, the score jumps to 40. The best genome overall is all ones, and nothing in the score hints at it until you are standing on it.

Now compare two searches. The first is the genetic algorithm of the previous chapter, selecting parents by this score. The second selects parents by novelty: how unusual a genome's behaviour is compared with the others. Here the "behaviour" is simply the number of 1 bits. This needs defining before the code makes sense.

Novelty search

Novelty search (Lehman and Stanley, "Exploiting open-endedness to solve problems through the search for novelty", 2008, and "Abandoning objectives: evolution through the search for novelty alone", Evolutionary Computation, 2011) discards the objective as the selection criterion. Instead each candidate is judged by how different its behaviour is from everything seen before. Three pieces make that work.

Behaviour characterisation
A short description of what a candidate does, chosen by the designer: the final position of a robot, the set of unit tests a program passes, the number of 1 bits here. It lives in a behaviour space where distance means "behaves differently". This is not the fitness; it is a description, and choosing it is where domain knowledge enters.
Novelty score
The average distance from a candidate's behaviour to its k nearest neighbours among the current population and an archive of past behaviours. A behaviour in a crowded region scores low; one far from everything scores high. This is the sparseness of the region.
Archive
A growing memory of behaviours that were novel when first found. Without it, a population could circle back to places it visited ten generations ago, which would look novel only because everyone else had moved on. The archive makes "new" mean new to the whole run.

Here are both searches on the trap, plus random search for reference, and a control: the same two searches on a friendly landscape where fitness is just the number of 1s. The novelty-search version stores behaviours in an archive when their novelty exceeds 1.5.

import random

N = 20                                           # genome length
def ones(g): return sum(g)
def fitness(g):                                  # a deceptive "trap": reward grows as 1s disappear...
    u = ones(g)
    return 2 * N if u == N else (N - 1) - u      # ...except the all-ones genome, which is the real prize

def mutate(g, rng):
    return [1 - x if rng.random() < 1 / N else x for x in g]

def novelty(b, others, k=5):
    """Mean distance from behaviour b to its k nearest neighbours (behaviour = number of 1 bits)."""
    d = sorted(abs(b - o) for o in others)[:k]
    return sum(d) / len(d)

def search(seed, use_novelty, pop_size=40, gens=250, fit=fitness):
    rng = random.Random(seed)
    pop = [[rng.randint(0, 1) for _ in range(N)] for _ in range(pop_size)]
    archive, best_seen, evals = [], 0, 0
    for gen in range(gens):
        beh = [ones(g) for g in pop]
        evals += pop_size
        best_seen = max(best_seen, max(ones(g) == N for g in pop))
        if best_seen: return True, evals
        if use_novelty:
            score = [novelty(b, beh[:i] + beh[i + 1:] + archive) for i, b in enumerate(beh)]
            archive += [b for b, s in zip(beh, score) if s > 1.5]    # remember behaviours that were new
        else:
            score = [fit(g) for g in pop]
        kids = []
        for _ in range(pop_size):                # tournament of 3, then mutate (no crossover)
            parent = pop[max(rng.sample(range(pop_size), 3), key=lambda i: score[i])]
            kids.append(mutate(parent, rng))
        pop = kids
    return False, evals

def random_search(seed, evals):
    rng = random.Random(seed)
    return any(ones([rng.randint(0, 1) for _ in range(N)]) == N for _ in range(evals))

runs = 30
smooth = lambda g: ones(g)                       # a friendly landscape: more 1s is simply better
def report(label, fit, use_novelty):
    res = [search(s, use_novelty, fit=fit) for s in range(runs)]
    won = sorted(e for r, e in res if r)
    med = f"{won[len(won) // 2]:,}" if won else "n/a"
    print(f"{label:34s}: found all-ones in {len(won):2d}/{runs} runs, median evaluations {med}")

print(f"genome length {N}; the target is the single all-ones string out of 2^{N} = {2**N:,}")
print("-- deceptive trap (fitness falls as 1s are added, until the very last one) --")
report("objective-driven GA", fitness, False)
report("novelty-driven GA", fitness, True)
print(f"random search, 10,000 evaluations  : found all-ones in {sum(random_search(s, 10000) for s in range(runs)):2d}/{runs} runs")
print("-- smooth landscape (fitness = number of 1s) --")
report("objective-driven GA", smooth, False)
report("novelty-driven GA", smooth, True)

objective-driven GA               : found all-ones in  0/30 runs, median evaluations n/a
novelty-driven GA                 : found all-ones in 17/30 runs, median evaluations 5,800

-- smooth landscape (fitness = number of 1s) --
objective-driven GA               : found all-ones in 30/30 runs, median evaluations 640

The result matches the story. On the trap, the objective-driven GA never finds the optimum: in 30 runs it slid down to all zeros each time, and random search with 10,000 evaluations fares no better because the optimum is one genome in a million. The novelty-driven GA found it in 17 of the 30 runs inside its budget of 10,000 evaluations (250 generations of 40), with a median of 5,800 evaluations. It was not told where to go; it was told to be unlike everything seen, and the behaviour space is a line from 0 to 20, so the only way to keep being novel is to keep pushing outward in both directions until it reaches 20.

The control matters just as much. On the smooth landscape the objective-driven GA solves the problem in 30 of 30 runs, with a median of 640 evaluations. Novelty search is nine times slower (5,800) and fails in 13 runs, because it spends effort exploring everywhere instead of heading to the goal. Novelty search is not a better optimiser. It is a better answer to deceptive problems and a worse one to friendly ones.

Common misconception

"Novelty search is just random search with extra steps, or random search done well." It is directed: selection pushes the population toward unexplored parts of the behaviour space, which is why it reached the all-ones genome in 17 of 30 runs where random search with the same budget reached it in none. But it is not a replacement for objective-driven search either. Whether it helps depends on whether the objective is deceptive and on whether your behaviour description puts the solution somewhere reachable by exploring.

The deceptive maze

The textbook demonstration is a maze. A wheeled robot (in the original work) must reach a goal; the fitness is the straight-line distance from where it stops to the goal. If the maze has a wall between start and goal, fitness rewards robots that drive into the wall. Below is a small version of that setup. A genome is 45 moves (up, down, left, right); a move into a wall does nothing; the behaviour is the final cell. The wall across the middle has one gap at column 3, so the route needs the walker to go away from the goal (up to 8.9 units distant at the gap) before it can approach it.

import math, random

MAZE = ["##############",
        "#..........G.#",
        "#............#",
        "#............#",
        "###.##########",      # the only gap is at column 3
        "#............#",
        "#............#",
        "#............#",
        "#...........S#",
        "##############"]
START, GOAL = (8, 12), (1, 11)
MOVES = [(-1, 0), (1, 0), (0, -1), (0, 1)]
STEPS = 45                                       # a genome is 45 moves: 0=up 1=down 2=left 3=right

def walk(genome):
    r, c = START
    for m in genome:
        dr, dc = MOVES[m]
        if MAZE[r + dr][c + dc] != "#": r, c = r + dr, c + dc
    return (r, c)                                # the behaviour: where the walker ends up

def distance(pos): return math.dist(pos, GOAL)

def mutate(g, rng): return [rng.randrange(4) if rng.random() < 0.05 else m for m in g]

def novelty(pos, others, k=10):
    d = sorted(math.dist(pos, o) for o in others)[:k]
    return sum(d) / len(d)

def search(seed, use_novelty, pop_size=60, gens=200):
    rng = random.Random(seed)
    pop = [[rng.randrange(4) for _ in range(STEPS)] for _ in range(pop_size)]
    archive, closest = [], 99.0
    for gen in range(gens):
        ends = [walk(g) for g in pop]
        closest = min(closest, min(distance(e) for e in ends))
        if closest == 0: return True, closest, (gen + 1) * pop_size
        if use_novelty:
            score = [novelty(e, ends[:i] + ends[i + 1:] + archive) for i, e in enumerate(ends)]
            archive += [e for e, s in zip(ends, score) if s > 1.5]
        else:
            score = [-distance(e) for e in ends]
        pop = [mutate(pop[max(rng.sample(range(pop_size), 3), key=lambda i: score[i])], rng)
               for _ in range(pop_size)]
    return False, closest, gens * pop_size

if __name__ == "__main__":
    print("\n".join(MAZE))
    print(f"start S at {START}, goal G at {GOAL}; straight-line distance {distance(START):.1f}; "
          f"the wall stops you at distance 4.0")
    for use_novelty, label in ((False, "distance-to-goal GA"), (True, "novelty-search GA  ")):
        res = [search(s, use_novelty) for s in range(20)]
        wins = [r for r in res if r[0]]
        stuck = sorted(r[1] for r in res if not r[0])
        extra = (f"median evaluations to solve {sorted(r[2] for r in wins)[len(wins) // 2]:,}" if wins
                 else f"all stuck, closest approach {stuck[0]:.1f}")
        print(f"{label}: solved {len(wins):2d}/20 runs; {extra}")
##############
#..........G.#
#............#
#............#
###.##########
#............#
#............#
#............#
#...........S#
##############
start S at (8, 12), goal G at (1, 11); straight-line distance 7.1; the wall stops you at distance 4.0
distance-to-goal GA: solved  4/20 runs; median evaluations to solve 4,740
novelty-search GA  : solved 15/20 runs; median evaluations to solve 4,200

With a budget of 12,000 evaluations per run (60 walkers for 200 generations), the distance-driven search solves the maze in 4 of 20 runs and novelty search in 15 of 20. The 4 successes for the objective are runs where, early on, some random walkers happened to wander through the gap and became ancestors; the search did not plan that. The Lehman and Stanley papers report the same pattern on larger mazes: the objective-based method almost always fails on the harder mazes, and novelty search succeeds in nearly every attempt. The exact evaluation counts and parameters are in the 2011 paper; I have not reproduced them here, and the toy above is much smaller than their experiments.

Stepping stones

The deeper lesson is about stepping stones: intermediate discoveries that matter because of what they lead to, not because they score well. In the maze, the cell at the gap is a stepping stone: it has a bad score and it is essential. In the history of technology, vacuum tubes were developed for radio and telephony and later became stepping stones to electronic computers; a programme optimising "calculation speed" from the era of mechanical calculators would have had little reason to fund them.

The clearest experimental illustration is Picbreeder (Secretan et al., "Picbreeder: a case study in collaborative evolutionary exploration of design space", Evolutionary Computation, 2011), a website where people evolve images by repeatedly choosing the ones they find interesting. Users bred recognisable pictures such as faces, cars and skulls with no target in mind. Woolley and Stanley (2011) then took some of those images and asked whether a standard objective-driven evolutionary search could reach them directly; they report that it had great difficulty, even though the images were demonstrably reachable, because the lineages that led to them passed through images that looked nothing like the final result. The chain of ancestors were stepping stones that no one could have identified by similarity to the end. Case study 2 reads this work in detail, and Stanley and Lehman's book Why Greatness Cannot Be Planned: The Myth of the Objective (2015) extends the argument to science and society. That wider claim is an argument, not a theorem; this chapter relies only on what the experiments in algorithms show.

Analogy: the hiker in fog

A hiker wants the highest peak in a mountain range but can see only a few metres in the fog. The sensible local rule is "walk uphill", and it works until the hiker reaches a small summit. From there every direction is downhill, so the rule says stop. The higher peak is across a valley the hiker would have to descend into first. A different rule, "go somewhere I have not been", will eventually cross the valley, at the price of walking a great deal of useless ground.

Where it breaks down: a real hiker can look around and carry a map, and knows what a summit is. A search algorithm only receives numbers, and it has no idea whether it is at a summit, in a valley or on a plateau. It also must define for itself what "somewhere new" means, and a poor definition (say, different GPS coordinates by one metre) makes every step look novel.

Where novelty search goes wrong

  • The behaviour description decides everything. If the characterisation does not separate the stepping stones you need, novelty search explores in directions that do not matter. In the maze, final position works; for a robot's gait, it might not. This design choice is a manual step that objective-driven search does not need.
  • Unbounded novelty. With a rich space, almost anything is novel: random noise can be more novel than a useful variation. Pure novelty has no pressure to be good, so the population can wander off to strange but worthless regions.
  • Cost. The k-nearest-neighbour computation grows with the archive, and exploring everywhere takes more evaluations than climbing directly. Our control run showed a ninefold penalty on a friendly problem.
  • No guarantee. Our novelty search solved the trap in 17 of 30 runs, not 30 of 30.

The research response was to combine pressures. Lehman and Stanley's minimal criterion novelty search requires candidates to meet a basic standard before novelty counts. Novelty search with local competition (2011) lets each candidate compete on fitness only against its behavioural neighbours, so a population holds many different kinds of thing, each good of its kind. That idea became quality-diversity search, and its best-known algorithm, MAP-Elites, is the subject of the next chapter. Another line gives an agent an intrinsic reward for novelty beside its task reward. Reinforcement-learning exploration bonuses use the same logic.

Systems connection

Deception shows up in product work as the local-maximum problem of metric-driven iteration: a team A/B tests its way up one hill (a layout, a ranking formula) until further tests stop improving the number, while a different design never gets built because its first version would lose. The experimentation practice in A1 chapter 21 is excellent at climbing and silent about whether the hill is the right one. Setting aside a small budget for deliberately different bets is the organisational form of novelty search.

State of play, October 2026

Novelty and diversity ideas are active in LLM-driven search. Systems that evolve programs with language models (chapter 9) maintain archives and islands so that a single high-scoring lineage does not take over, and ShinkaEvolve (Sakana AI, arXiv 2509.19349, September 2025) adds a novelty-rejection step: a new program that is too similar to existing ones is not evaluated at all, which saves expensive evaluations (chapter 10). Which methods lead the field will keep changing; the principle that selection by score alone collapses diversity is stable.

Key takeaways

  • A problem is deceptive when climbing the objective leads away from the best solution. Score-driven search then converges on a local optimum, often with no visible sign of trouble.
  • Novelty search selects by how different a candidate's behaviour is from its nearest neighbours in the population and an archive, and ignores the objective when choosing.
  • On our trap, objective search solved it in 0 of 30 runs and novelty search in 17 of 30. On a smooth landscape objective search solved it in 30 of 30 and was nine times faster.
  • In the toy maze the distance-driven search covered 31 of 85 cells in one run; novelty search covered 81.
  • Stepping stones can look worse than where you are now. The Picbreeder experiments suggest many valuable things are reached only through such steps.
  • Novelty search depends on a hand-chosen behaviour description and has no pressure toward quality. Quality-diversity methods fix this by combining the two.

Check your understanding

What makes a problem "deceptive" in the sense used in this chapter?

  1. The scoring function is noisy
  2. Following increases in the score leads away from the best solution
  3. The search space is very large
  4. There are several equally good solutions
Deception is about the direction of the gradient, not noise or size: the objective's slope leads to a local optimum rather than the global one. A huge space (option 3) can still be friendly, and multiple optima (option 4) are not deceptive if the score leads to one of them.

In the novelty search described here, what is the novelty score of a candidate?

  1. Its fitness minus the population average
  2. The number of generations since its parents were created
  3. How many mutations separate it from its parent
  4. The average distance in behaviour space to its k nearest neighbours in the population and archive
Novelty is about behaviour relative to what has been seen, using the nearest neighbours in the current population plus the archive. Fitness does not enter the score, and distance from its own parent (option 3) would reward big jumps, not unexplored behaviour.

On the smooth landscape (fitness equals number of 1s), the objective-driven GA solved the problem in 30 of 30 runs at a median of 640 evaluations, and novelty search in 17 of 30 at a median of 5,800. What does this tell you?

  1. Novelty search pays a large cost when the objective is not deceptive
  2. Novelty search is broken
  3. Objective search is always better
  4. The archive was too small
On a friendly landscape, heading straight for the goal is much cheaper than exploring everywhere. It does not show that objectives are always better: on the trap the same objective method found the optimum in 0 of 30 runs.

You apply novelty search to a robot-arm design problem and describe behaviour as "final position of the gripper, rounded to the nearest metre" in a one-metre workspace. What is the likely problem?

  1. The archive will grow without bound
  2. Novelty will be dominated by random noise
  3. Almost every design has the same behaviour, so novelty cannot tell designs apart
  4. The objective will override novelty
The behaviour characterisation is too coarse: nearly everything rounds to the same value, so distances are zero and there is no signal. This is why choosing the behaviour space is the main design decision. Noise domination (option 2) is the opposite failure, from a description that is too fine.

Why does novelty search need an archive, rather than comparing only against the current population?

  1. To store the best solutions found so far
  2. So that behaviours visited earlier still count as not new, and the population cannot circle back
  3. To reduce the number of evaluations
  4. To make mutation more effective
Without memory, a region abandoned ten generations ago looks empty and therefore novel, so the population can oscillate. The archive stores novelty, not quality (option 1), and does not reduce evaluations (option 3).

Which design combines the benefits of novelty search with pressure toward good solutions?

  1. Running novelty search with a larger archive
  2. Running two independent objective-driven searches
  3. Increasing the tournament size
  4. Letting each candidate compete on fitness only against behaviourally similar candidates
Local competition keeps a diverse set of behaviours alive while selecting for quality within each niche; it is the route to quality-diversity algorithms such as MAP-Elites. A larger archive alone adds memory but no quality pressure, and a larger tournament increases selection pressure and reduces diversity.
