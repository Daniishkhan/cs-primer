Matrices as Functions

A matrix is a table of numbers, and also a function that turns one vector into another. This chapter reads a matrix both ways, shows that multiplying two matrices is the same as running two functions in sequence, explains why shapes in NumPy and PyTorch behave like type signatures, and ends with inverses: when a transformation can be undone, how to undo it without hurting accuracy, and what goes wrong when it cannot.

Why this matters

The previous chapter gave you one dot product. A neural network layer is thousands of them done at once, and that is a matrix times a vector (or a matrix times a matrix). If you know a matrix as a function, three habits follow. You can predict the shape of every tensor in a model before running it, which is how most shape bugs are caught. You can see why two layers with no nonlinearity between them are really one layer. And you can see cost differences that look like magic, such as how LoRA fine-tuning (A3, chapter 11) describes a rank-8 update to a 4096 by 4096 weight matrix with 256 times fewer parameters. The chapter after this one, chapter 7, takes matrices apart; this one makes sure you can put them together.

A matrix is a table and a function

A matrix is a rectangular table of numbers. Its shape is written (rows, columns), as in NumPy, so a matrix with 2 rows and 3 columns has shape (2, 3). We name matrices with capital letters (W, X) and refer to the entry in row i, column j as Wij. This is the same indexing as the nested Python list W[i][j].

The key operation is the matrix-vector product y = W x. If W has shape (m, n) and x is a vector of n components, then y has m components, and each one is a dot product from the previous chapter: yi is the dot product of row i of W with x. So W is a function that takes n numbers in and returns m numbers out. A (2, 3) matrix is a function from 3-dimensional vectors to 2-dimensional ones.

There is a second way to read the same arithmetic. Group the work by columns instead of rows: W x equals x1 times column 1 of W, plus x2 times column 2, and so on. The output is a linear combination of the columns, with x supplying the weights. Both views give the same numbers, and each is handy for different thoughts: the row view tells you how each output is computed, the column view tells you what the matrix can produce at all.

# A matrix W with shape (2, 3): a function from 3 numbers to 2 numbers.
W = [[1.0, 2.0, 0.0],
     [0.0, 1.0, 3.0]]
x = [2.0, 1.0, 1.0]

def dot(a, b): return sum(p * q for p, q in zip(a, b))

# Row view: each output is the dot product of one row with x.
by_rows = [dot(row, x) for row in W]

# Column view: the output is a combination of W's columns, weighted by x.
cols = [[W[i][j] for i in range(2)] for j in range(3)]
by_cols = [sum(x[j] * cols[j][i] for j in range(3)) for i in range(2)]

print("rows view   :", by_rows)
print("columns view:", by_cols)

import numpy as np
print("numpy W @ x :", np.array(W) @ np.array(x), " W.shape =", np.array(W).shape)
rows view   : [4.0, 4.0]
columns view: [4.0, 4.0]
numpy W @ x : [4. 4.]  W.shape = (2, 3)

Check the first output by hand: row 1 is (1, 2, 0), so 1×2 + 2×1 + 0×1 = 4. In the column view it is 2 × (1, 0) + 1 × (2, 1) + 1 × (0, 3) = (2 + 2 + 0, 0 + 1 + 3) = (4, 4). Same answer, different route.

What "linear" means, and why matrices are all of it

A function f is linear if it respects the two vector operations: f(x + y) = f(x) + f(y) and f(c x) = c f(x). Equivalently, f of a linear combination is the same combination of the f's. Every matrix is linear, because dot products are. The reverse is also true, and the proof is short enough to be worth seeing. Let e1, e2, … be the basis vectors: e1 = (1, 0, …), e2 = (0, 1, …), and so on. Any vector is x = x1e1 + x2e2 + …. If f is linear then f(x) = x1 f(e1) + x2 f(e2) + …. That is a matrix-vector product with the matrix whose columns are f(e1), f(e2), …. So a linear function is completely determined by what it does to the basis vectors, and the matrix is just a list of those answers.

That sentence is the most useful thing to remember about matrices as pictures. In two dimensions, the first column of a matrix is where the arrow (1, 0) lands and the second column is where (0, 1) lands. Everything else follows because the grid lines stay straight and evenly spaced. Linear maps can rotate, stretch, shear, reflect and flatten space. They cannot bend it, and they always fix the origin: f(0) = 0.

The determinant of a 2×2 matrix [[a, b], [c, d]] is ad − bc. Geometrically it is the factor by which the matrix scales areas: the unit square has area 1, and its image has area |det|. A negative determinant means the plane has been flipped over like a page turned, as a reflection does. A zero determinant means areas collapse to nothing: the matrix squashes the plane onto a line or a point, and as we will see in the last section, that cannot be undone.

Common misconception

"A neural-network layer is a linear function." The matrix part is, but a layer is usually affine, W x + b, which adds a constant shift and so does not fix the origin, and then passes the result through a nonlinear activation. The pieces that are exactly linear are the matrix multiplications; the nonlinearities between them are what let a network represent anything beyond a linear map, as the "collapse" demonstration below shows.

Multiplying matrices is composing functions

Now suppose you apply two matrices in a row: first B, then A. The input x goes to B x, and then to A (B x). Both steps are linear, so the combined function is linear too, which means it must be a single matrix. Which matrix? Call it AB, defined by the requirement (A B) x = A (B x) for every x. Work out column j of AB by feeding in the basis vector ej: B ej is column j of B, and applying A to it gives a dot product of each row of A with that column. Plug in numbers. A is 2×3 and B is 3×2. The script builds one entry, then all four, and ends by checking the claim that makes this the right definition: applying B and then A gives the same answer as applying AB once.

The idea

  1. A is (2, 3), B is (3, 2): inner sizes match, AB is (2, 2)
  2. one entry: multiply A[i][k] × B[k][j] for each k, then add
  3. every entry: repeat for each row i and column j
  4. check: A(Bx) = (AB)x for an input x
"""Matrix product by hand: (AB)[i][j] = sum over k of A[i][k] * B[k][j].
A is 2x3, B is 3x2, so AB is 2x2. Lists of lists, no libraries."""

# ── 1. Two small matrices, and their shapes ──────────────────────────────
A = [[1.0, 2.0, 1.0],                    # shape (2, 3): 2 rows, 3 columns
     [3.0, -1.0, 2.0]]
B = [[2.0, 1.0],                         # shape (3, 2): 3 rows, 2 columns
     [0.0, 4.0],
     [1.0, -1.0]]
M, N, P = len(A), len(B), len(B[0])      # the inner size N must match
print(f"A is ({M}, {N}), B is ({N}, {P}), so AB is ({M}, {P})")

# ── 2. One entry: row i of A against column j of B ───────────────────────
i, j = 0, 1                              # first row, second column
terms = [A[i][k] * B[k][j] for k in range(N)]
print(f"(AB)[{i + 1}][{j + 1}] terms = {terms}")
print(f"(AB)[{i + 1}][{j + 1}] sum   = {sum(terms)}")

# ── 3. Every entry, the same way ─────────────────────────────────────────
AB = [[sum(A[r][k] * B[k][c] for k in range(N)) for c in range(P)]
      for r in range(M)]
print("AB =", AB)

# ── 4. Check: B first, then A, equals AB in one go ───────────────────────
x = [1.0, 2.0]                           # any input of length P


def apply(mat, v):
    return [sum(m * a for m, a in zip(row, v)) for row in mat]


print("A(Bx) =", apply(A, apply(B, x)))
print("(AB)x =", apply(AB, x))
A is (2, 3), B is (3, 2), so AB is (2, 2)
(AB)[1][2] terms = [1.0, 8.0, -1.0]
(AB)[1][2] sum   = 8.0
AB = [[3.0, 8.0], [8.0, -3.0]]

(AB)x = [19.0, 2.0]

Matrix multiplication is defined to be function composition, and the rule above is what that definition looks like in numbers. The product is not arbitrary and it is not element-wise. Everything surprising about it follows from "run B first, then A": the order is read right to left, as with ordinary function notation f(g(x)).

Step through

Shear, then rotate: one matrix for both

  1. Start. The unit square with its basis arrows: blue is (1, 0), green is (0, 1). The matrices are B = [[1, 0.8], [0, 1]], a shear that slides the top of the square to the right, and A = [[0, −1], [1, 0]], a quarter-turn anticlockwise.
  2. Apply B. The columns of B are (1, 0) and (0.8, 1), so the blue arrow stays put and the green one tilts to (0.8, 1). The square becomes a parallelogram.
  3. Apply A to the result. The quarter-turn sends (1, 0) to (0, 1) and (0.8, 1) to (−1, 0.8). Those two arrows are the columns of the new picture.
  4. One matrix does both. AB has columns (0, 1) and (−1, 0.8), exactly the final arrows. Multiplying the matrices once saves running the two steps on every vector afterwards.
import numpy as np

def matmul(A, B):
    """Plain triple loop: C[i][j] = row i of A . column j of B."""
    n, m, p = len(A), len(B), len(B[0])
    assert len(A[0]) == m, f"inner sizes differ: {len(A[0])} vs {m}"
    return [[sum(A[i][k] * B[k][j] for k in range(m)) for j in range(p)]
            for i in range(n)]

A = [[0.0, -1.0], [1.0, 0.0]]       # rotate by 90 degrees anticlockwise
B = [[1.0, 0.8], [0.0, 1.0]]        # shear: slide the top sideways
x = [1.0, 1.0]

AB = matmul(A, B)
BA = matmul(B, A)
print("AB =", AB, " (shear first, then rotate)")
print("BA =", BA, " (rotate first, then shear)")

Ax = lambda M, v: [sum(m * t for m, t in zip(row, v)) for row in M]
print("A(Bx) =", Ax(A, Ax(B, x)))
print("(AB)x =", Ax(AB, x))
print("(BA)x =", Ax(BA, x), " <- order matters")
print("matches numpy:", np.allclose(AB, np.array(A) @ np.array(B)))
AB = [[0.0, -1.0], [1.0, 0.8]]  (shear first, then rotate)
BA = [[0.8, -1.0], [1.0, 0.0]]  (rotate first, then shear)
A(Bx) = [-1.0, 1.8]
(AB)x = [-1.0, 1.8]
(BA)x = [-0.19999999999999996, 1.0]  <- order matters
matches numpy: True

Two things are visible in the output. First, A(Bx) and (AB)x give the same answer, (−1, 1.8), as they must. Second, AB and BA are different matrices, and they send the same x to different places: (−1, 1.8) against (−0.2, 1). Matrix multiplication is not commutative. It is, however, associative: (AB)C = A(BC), which matches the fact that function composition is. That freedom to regroup is not a technicality, as the cost section shows.

Analogy: turn, then walk

Two instructions for a stroll: "turn 90 degrees left" and "walk 10 paces forward". Turn then walk, and you end up 10 paces to your left. Walk then turn, and you end up 10 paces ahead, facing left. Same two instructions, different places. Writing the composition as a product keeps track of which came first, and the rightmost factor is the one that happens first.

Where it breaks down: a walker moves one point. A matrix moves the whole plane at once, including stretches and flips that no walker can perform, and a matrix has no notion of a path between start and end, only the final placement.

Go deeper three equivalent ways to compute AB

The entry formula is the inner-product view: entry (i, j) is a row-times-column dot product. Two other readings give the same matrix. In the column view, column j of AB is A times column j of B, so AB is "A applied to each column of B". In the outer-product view, AB is a sum of n matrices, the k-th being (column k of A) times (row k of B), where multiplying a column vector by a row vector gives a full (m, p) matrix of rank 1. The outer-product view is the one that returns in chapter 7, where any matrix is written as a sum of a few such pieces, and in LoRA, where an update is a product of two thin matrices.

Identity and transpose

Two special matrices round out the algebra. The identity matrix I has ones on the diagonal and zeros elsewhere and does nothing: I x = x and A I = I A = A. The transpose AT swaps rows and columns, so a (m, n) matrix becomes (n, m), and (AT)ij = Aji. It obeys (A B)T = BT AT: the order reverses, just like taking off socks and shoes. The dot product x · y can be written xTy by treating x as a column, which is the notation papers use.

Shapes are contracts

The entry formula only works if the rows of A and columns of B have the same length. That is the one rule of matrix multiplication, and it is easy to state as a type signature: a (m, n) matrix times a (n, p) matrix gives a (m, p) matrix. The inner sizes must agree and they disappear; the outer sizes survive. Read shapes like this and you can tell, without running anything, whether a model's code can possibly work.

This is how every dense layer of a neural network is written. A batch of examples is stacked as the rows of X, with shape (batch, d_in); one matrix product pushes all of them through the layer at once. In the attention mechanism of a Transformer, the scores are Q KT, shapes (T, d) times (d, T) giving a (T, T) table with one score per pair of positions (A2, chapter 9). Here are both in code, together with the error you will see when the contract is broken.

import numpy as np
rng = np.random.default_rng(0)

batch, d_in, d_out = 32, 768, 3072
X = rng.standard_normal((batch, d_in))      # one example per row
W = rng.standard_normal((d_in, d_out)) * 0.02
b = np.zeros(d_out)

Y = X @ W + b                                # (32,768) @ (768,3072) -> (32,3072)
print("X", X.shape, " W", W.shape, " Y", Y.shape)
print("parameters:", W.size + b.size)
print("multiply-adds:", batch * d_in * d_out, "= batch * d_in * d_out")

# Attention-style scores: (T, d) @ (d, T) -> (T, T)
T, d = 5, 64
Q = rng.standard_normal((T, d)); K = rng.standard_normal((T, d))
print("Q K^T:", (Q @ K.T).shape)

try:
    X @ W.T                                  # the classic mistake
except ValueError as e:
    print("ValueError:", e)

The counts are worth keeping in your head. This layer has 768 × 3,072 weights plus 3,072 biases = 2,362,368 parameters, and applying it to 32 examples costs 75,497,472 multiply-adds (each multiply-add is conventionally counted as 2 floating-point operations, or FLOPs). Counting parameters and FLOPs this way is the heart of A2, chapter 16.

Two conventions trip people up. Mathematics texts usually write the vector as a column and the product as W x, with W of shape (d_out, d_in). Code that processes a batch puts examples in rows and writes X W, with W of shape (d_in, d_out). PyTorch's nn.Linear stores its weight as (out_features, in_features) and computes x WT + b, which is the first convention applied to the second layout. Neither is wrong. When you read a paper or a codebase, first work out which one is in use, then track shapes line by line. The failed X @ W.T above is exactly the error you get from picking the wrong one.

Common misconception

"A * B multiplies the matrices." In NumPy and PyTorch the * operator is element-wise multiplication with broadcasting (chapter 2); it will happily "work" on two (3, 3) arrays and silently return the wrong thing. Matrix multiplication is @ (or np.matmul, torch.matmul). When a shape-compatible but wrong operator produces no error, nothing flags the bug; assert the shapes you expect.

Stacking linear layers collapses them

Because composition of matrices is a matrix, two linear layers in a row are one layer in disguise: W2(W1 x) = (W2W1) x. The following run makes that concrete and then puts a ReLU (ReLU is the function max(0, v) applied to each component) between the layers.

import numpy as np
rng = np.random.default_rng(3)
W1 = rng.standard_normal((4, 3)); W2 = rng.standard_normal((2, 4))
x = rng.standard_normal(3)

two_layers = W2 @ (W1 @ x)
one_layer = (W2 @ W1) @ x
print("W2 W1 shape:", (W2 @ W1).shape)
print("two linear layers == one matrix:", np.allclose(two_layers, one_layer))

relu = lambda v: np.maximum(v, 0)
with_relu = W2 @ relu(W1 @ x)
print("with a ReLU in between          :", np.allclose(with_relu, one_layer))
print("outputs:", np.round(two_layers, 3), np.round(with_relu, 3))
W2 W1 shape: (2, 3)
two linear layers == one matrix: True
with a ReLU in between          : False
outputs: [ 2.423 -2.461] [-0.093 -0.047]

Without the nonlinearity, any number of layers can be replaced by one (2, 3) matrix; the network has no more power than a single layer, however deep. With the ReLU the equality breaks, and so does the collapse. This is the reason for the activation functions of A2, chapter 1: the matrices do the mixing; the nonlinearities make depth worth having.

The order of multiplication sets the cost

Associativity says (AB)x and A(Bx) are the same vector, but they are not the same amount of work. Forming AB first costs a full matrix-matrix product, then applies it. Applying the matrices one at a time to the vector costs two matrix-vector products. When the middle dimension is small this difference is enormous, and it is exactly the situation in LoRA, which represents a weight update as a product of a tall, thin matrix B of shape (d, r) and a wide, short matrix A of shape (r, d), with rank r much smaller than d (A3, chapter 11).

import numpy as np
rng = np.random.default_rng(0)
d, r = 4096, 8
W = rng.standard_normal((d, d)) / np.sqrt(d)
B = rng.standard_normal((d, r)) / np.sqrt(r)
A = rng.standard_normal((r, d)) / np.sqrt(d)
x = rng.standard_normal(d)

# Two ways to apply the update (B A) to x
merged = (B @ A) @ x          # form the (4096, 4096) product first
factored = B @ (A @ x)        # never form it
print("same answer:", np.allclose(merged, factored))
print("multiply-adds, forming B@A first :", d * r * d + d * d)
print("multiply-adds, A@x then B@(..)   :", r * d + d * r)
print("parameters in full update        :", d * d)
print("parameters in B and A            :", d * r + r * d)
print("ratio                            :", round(d * d / (2 * d * r), 1))

Two lessons. First, parenthesisation: computing A x first (an r-vector), then B times that, takes 65,536 multiply-adds, against about 151 million for forming the (4096, 4096) product. The answers agree to floating-point tolerance. Second, representation: the full update has 16,777,216 entries, but two thin factors describe a rank-8 update with 65,536, a 256-fold saving. Whether a real fine-tuning update is low rank is a separate empirical question, taken up in the next chapter.

Systems connection

Matrix multiplication is the workload GPUs are built for. An (n, n) times (n, n) product does 2n³ FLOPs on only 3n² numbers, so the longer the matrices, the more arithmetic per byte moved from memory, and the GPU's multipliers stay busy. A matrix-vector product does 2n² FLOPs on n² numbers: about two FLOPs per number fetched. That is memory-bound, and it is why generating one token at a time is bandwidth-limited while processing a long prompt or a big batch is compute-limited (A3, chapter 18). The idea of batching requests so that matrix-vector products become matrix-matrix products is the same one behind the batching of serving engines and the memory accounting in A3, chapter 2.

Inverses: undoing a transformation

If A moves the plane, can you move it back? The inverse A−1 is the matrix that undoes A: A−1A = A A−1 = I. It is the inverse as a function. For a 2×2 matrix [[a, b], [c, d]] with determinant D = ad − bc the formula is (1/D)[[d, −b], [−c, a]]. Take A = [[2, 1], [1, 3]]. Then D = 5 and the inverse is [[0.6, −0.2], [−0.2, 0.4]], which matches the first lines of the run below.

An inverse exists only when no information was lost. If the determinant is zero, the matrix flattens the plane (the last panel of the figure above), and many different inputs share one output, so there is no way to know which one produced it. Such a matrix is called singular. In any dimension, a square matrix is invertible exactly when its columns point in genuinely different directions, that is, none is a combination of the others. The matrix [[1, 2], [2, 4]] is singular because its second row is twice its first.

Solving, not inverting

The reason people reach for an inverse is to solve A x = b: the vector x that A sends to b. Mathematically x = A−1 b. In code, do not compute the inverse. np.linalg.solve(A, b) uses a factorisation (Gaussian elimination, organised as an LU decomposition) that is faster and more accurate than forming A−1 and multiplying. The same goes for the least-squares problems in A1, chapter 5: use np.linalg.lstsq rather than the textbook (XTX)−1XTy.

import numpy as np

A = np.array([[2.0, 1.0], [1.0, 3.0]])
b = np.array([3.0, 5.0])
print("det(A)    =", round(np.linalg.det(A), 6))
print("A^-1      =", np.round(np.linalg.inv(A), 4).tolist())
x = np.linalg.solve(A, b)
print("solve     =", x, " A @ x =", A @ x)

S = np.array([[1.0, 2.0], [2.0, 4.0]])      # second row = 2 * first row
print("det(S)    =", np.linalg.det(S))
try:
    np.linalg.inv(S)
except np.linalg.LinAlgError as e:
    print("inv(S)    : LinAlgError:", e)

# A nearly singular system: small change in b, big change in the answer
N = np.array([[1.0, 1.0], [1.0, 1.02]])
print("cond(N)   =", round(np.linalg.cond(N), 1))
print("solve b=(2, 2.02):", np.linalg.solve(N, [2.0, 2.02]))
print("solve b=(2, 2.00):", np.linalg.solve(N, [2.0, 2.00]))

# Hilbert matrices: a classic ill-conditioned family
for n in (4, 8, 12):

    x_true = np.ones(n)

When the inverse exists but is dangerous

The second half of the output is the part that matters in practice. The matrix N = [[1, 1], [1, 1.02]] is invertible, but only just: its columns are nearly parallel. Changing the right-hand side from (2, 2.02) to (2, 2.00), a nudge of 0.02, moves the answer from (1, 1) to (2, 0). The condition number measures this amplification: it is the ratio of the largest to the smallest stretch the matrix applies (formally, of its largest to smallest singular value, which the next chapter defines), and here it is 202. As a rule of thumb, you lose about log10(condition number) decimal digits of accuracy.

The Hilbert matrices at the bottom of the output show the effect at scale. With 64-bit floating point (about 16 significant digits, chapter 11), a 4×4 Hilbert matrix with condition number 1.55e4 loses about four digits and the solve is accurate to 5e-14. At 8×8 (condition 1.53e10) the error is 1.6e-7. At 12×12 (condition 1.7e16, about the reciprocal of machine precision) the solution is wrong in the first digit: the maximum error is 0.22. Nothing raised an error; the code returned numbers. Condition numbers are why feature-correlated data makes regression coefficients unstable and why mixed precision training (Case 4) pays attention to where precision is spent.

State of play, October 2026

Frameworks now run most matrix multiplications in reduced precision (bf16 or fp8 inputs, accumulating in fp32) on hardware with dedicated matrix units. The mathematics in this chapter is unchanged, but reduced precision makes the condition-number story relevant to everyday training, not only to scientific computing. Specific supported formats and speeds depend on the GPU generation and library version; check your vendor's documentation for the numbers that apply to you, and see chapter 11 for the formats themselves.

Key takeaways

  • A (m, n) matrix is a linear function from n-dimensional to m-dimensional vectors. Each output is a row dot input; the output is also a combination of the columns. The columns are the images of the basis vectors.
  • Matrix multiplication is composition: (AB)x = A(Bx), with the rightmost matrix acting first. It is associative, not commutative.
  • Shapes are contracts: (m, n) @ (n, p) gives (m, p). Track them line by line, know whether code puts examples in rows or columns, and use @, not *.
  • Without nonlinearities, stacked matrices collapse to one. Choosing the parenthesisation, such as B(Ax), can cut cost by orders of magnitude when the inner dimension is small.
  • An inverse exists only if the determinant is non-zero, that is, nothing was flattened. Solve with solve or lstsq; never form the inverse.
  • The condition number tells how many digits a solve can lose. Ill-conditioned problems return plausible but wrong numbers with no error.

Check your understanding

A has shape (10, 3) and B has shape (3, 7). What is the shape of A @ B, and about how many multiply-adds does the product take?

  1. (3, 3); 9
  2. (10, 7); 210
  3. (10, 7); 70
  4. (7, 10); 210
The inner size 3 disappears, the outer sizes 10 and 7 survive, so the result is (10, 7). Each of its 70 entries is a dot product of length 3, so 70 × 3 = 210 multiply-adds. The answer 70 counts entries rather than operations.

You want to apply transformation B first and then transformation A to many vectors. Which single matrix do you precompute?

  1. B A, because the first operation is written first
  2. A + B
  3. A * B (element-wise)
  4. A B, because the rightmost matrix acts first
Composition reads right to left: (A B) x = A (B x). Option 1 is the tempting reading-order mistake and gives a different matrix in general, as shear and rotation showed. Addition and element-wise multiplication are not composition at all.

S = [[1, 2], [2, 4]]. Which statement is true?

  1. S has no inverse; S x = b has solutions only for b on the line through (1, 2), and then it has infinitely many
  2. S has an inverse because all its entries are non-zero
  3. S x = b has exactly one solution for every b
  4. S is invertible, but badly conditioned
det S = 1×4 − 2×2 = 0. The columns (1, 2) and (2, 4) are parallel, so S maps the whole plane onto one line. Outputs off that line are unreachable; outputs on it come from a whole line of inputs. Non-zero entries say nothing about invertibility, and a singular matrix is not just "badly conditioned": its condition number is infinite.

A network has five dense layers with no activation functions between them. What is the most accurate description of its expressive power?

  1. Five times that of one layer
  2. Exponentially more than one layer, because of depth
  3. The same as a single linear layer, because the product of the five matrices is one matrix
  4. Less than one layer, because errors accumulate
W5 W4 W3 W2 W1 is a single matrix, so the whole network computes one linear function. Depth only helps when nonlinearities separate the layers (the ReLU run showed the equality failing). Numerical error is a separate matter and does not reduce expressive power.

A and B are (1000, 1000) matrices and x is a 1000-vector. About how much more work is (A @ B) @ x than A @ (B @ x)?

  1. About the same
  2. About 2 times
  3. About 10 times
  4. About 500 times
A @ B costs 1000³ = 109 multiply-adds, plus 106 for the final matrix-vector product. A @ (B @ x) costs two matrix-vector products, 2 × 106. The ratio is roughly 500. The results are mathematically equal; only the order of evaluation differs, so choose it deliberately.

A solve with a matrix whose condition number is about 108 is run in float64 (about 16 significant digits). What should you expect?

  1. An error message, since 108 is too large
  2. Roughly 8 correct digits in the answer, and no warning from the code
  3. Full 16-digit accuracy, because float64 is precise
  4. Exactly zero correct digits
The rule of thumb is that you lose about log10(cond) digits, leaving about 8. Solvers raise an error only for exactly singular matrices, so an ill-conditioned case returns numbers without complaint. Full accuracy ignores amplification of rounding error; zero correct digits would need a condition number near 1016.
