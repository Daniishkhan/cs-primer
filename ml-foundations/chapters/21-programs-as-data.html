Programs as Data

A program is text, but text is a poor thing to edit. This chapter shows how to read Python source as a tree of small parts, change one part, turn the tree back into source, and run it with a limit on how long it may take.

Why this matters

Later in the path, a loop will propose small changes to a function, score every change, and keep the best. That loop needs four skills. It must change a program without breaking its grammar. It must refuse programs that do dangerous things. It must run the rest. And it must stop any program that never finishes. Python's standard library gives you all four. After this chapter you can write each one yourself, in under a hundred lines.

1. Source text and the tree behind it

You write a Python function as a string of characters. Python does not read it that way. Before anything runs, the interpreter turns the text into a syntax tree. This is a set of connected parts. Each part is a small piece of the program, such as a name, a number or an addition, and is called a node. The tree records which parts sit inside which.

Python's standard module ast (short for abstract syntax tree) lets you see this tree and use it. The step that turns text into a tree is called parsing. The function that does it is ast.parse.

Analogy: a sentence diagram

Take the sentence "The dog chased the cat". A teacher can draw it as a diagram: a subject, a verb, an object, and the words that hang off each. To swap "dog" for "fox", you find the subject slot and change one word. You do not need to hunt through letters. To swap the whole object for "the red ball", you replace one branch. The diagram makes the edit obvious because it shows what each word is for, not only where it sits in the line.

A syntax tree is the same idea for code. It shows what each piece is for: this is the operator, those are its two operands.

Where it breaks down: a sentence diagram can be ambiguous, because English allows two readings of "I saw the man with the telescope". A Python tree never is. There is exactly one tree for a given text. Also, a grammatical sentence can still be nonsense, and a valid tree can still be a bad program. The tree guarantees grammar, not good sense.

Here is the tree for the best-fit rule from the bin-packing thread. The function scores a bin by minus the space that would be left over.

The idea

  1. parse the source text into a tree
  2. print the tree, one node per line, indented by depth
  3. list every node's type with ast.walk
  4. parse an expression on its own to meet a Constant node
"""Read a heuristic as a tree: parse it, dump it, list its node types."""
import ast

# ── 1. Source text in, tree out ─────────────────────────────────────
SRC = "def priority(item, rem):\n    return -(rem - item)\n"
tree = ast.parse(SRC)

# ── 2. Print the tree, one node per line, indented by depth ─────────
print(ast.dump(tree, indent=2))

# ── 3. Count the node types with ast.walk ───────────────────────────
# walk() yields every node, parents before children (breadth first).
print()
names = [type(node).__name__ for node in ast.walk(tree)]
print(len(names), "nodes:", ", ".join(names))

Read the dump from the outside in. A Module is the whole file. It holds one FunctionDef, the function called priority. The function has an argument list and a body. The body is one Return. What it returns is a UnaryOp (an operator with one operand) whose operator is USub, the minus sign. Its operand is a BinOp (an operator with two operands): rem minus item. Each of those is a Name, a reference to a variable. A number such as 10 becomes a Constant, which the last line of the output shows.

The Load() on each name says the program reads the variable. A name being assigned would carry Store() instead. Note that ast.dump(indent=2) needs Python 3.9. Python 3.13 and later leave out fields that are empty, so older versions show a few extra lines such as type_ignores=[].

Why trees are easier to change than text

Suppose a program must make a small random change, such as turning a minus into a plus. In text, you could pick a character and flip it. Most flips give nonsense: return -(rem - item no longer parses, and neither does retur -(rem - item). The program stops working long before it can be scored. In a tree, you pick a Sub node and replace it with an Add node. The result is always grammatical. This is the main reason search systems edit programs as trees, or have a language model write whole new text and then check it by parsing.

2. Walking a tree and checking it

To check a tree, you must visit its nodes. There are two ways. ast.walk(tree) gives you every node, parents before children, in a plain for loop. You saw it in the last script. It is the quick tool when you only need to ask "is there any node of this kind anywhere?"

The second way is a visitor: a class that has one method for each node type it cares about. You subclass ast.NodeVisitor. When you call visit, Python looks at each node's type and calls the method named visit_ plus that type, such as visit_BinOp. Inside it, call self.generic_visit(node) to carry on into the children. If you forget, the children are skipped. A visitor reads the tree and keeps notes. It does not change anything.

The idea

  1. write one visit_ method per node type to watch
  2. visit the whole module, then read the notes
"""A NodeVisitor reads a tree and keeps notes. It never changes it."""
import ast

SRC = """def priority(item, rem):
    gap = rem - item
    if gap < 10:
        return 100 - gap
    return -gap
"""


# ── 1. A visitor with one method per node type it cares about ─────────
class Notes(ast.NodeVisitor):
    def __init__(self):
        self.operators = []
        self.constants = []

    def visit_BinOp(self, node):
        self.operators.append(type(node.op).__name__)
        self.generic_visit(node)        # without this, children are skipped

    def visit_Constant(self, node):
        self.constants.append(node.value)


# ── 2. Visit the whole module and read the notes ──────────────────────
notes = Notes()
notes.visit(ast.parse(SRC))
print("operators:", notes.operators)
print("constants:", notes.constants)
operators: ['Sub', 'Sub']
constants: [10, 100]

The two subtractions are found because generic_visit reached inside the If and the Return. Only the constants 10 and 100 are listed. The name gap is not a constant, so it is ignored.

An evolved program is untrusted

Now the reason this matters. When a program is written by a random mutation, or by a language model, nobody has read it. It is untrusted code. It might import a module that reads your files. It might loop for ever. It might be a perfectly honest program that has a bug. You cannot tell by running it, because running it is the risky act. So you check the tree first, and you run only what passes.

There are two ways to write the check. A blacklist names the bad things: no imports, no eval. The trouble is that you must think of every bad thing in advance, and one gap defeats the whole check. A whitelist names the good things. Anything not on the list is refused. A whitelist is safer because a node type you forgot about is refused by default.

The validator below uses a whitelist of node types. Then it adds three rules that a list of types cannot express. The file must hold exactly one function, called priority, with arguments named item and rem. No name may start with an underscore, which stops access to hidden names. And any call must be to abs, min or max. Loops are left off the list for now. Section 5 brings them back.

The idea

  1. refuse long sources, then refuse text that does not parse
  2. demand exactly one def priority(item, rem)
  3. walk every node: whitelist its type, check names and calls
  4. run the validator on honest and hostile candidates
"""A validator: accept exactly one def priority, refuse everything else."""
import ast

SAFE_CALLS = {"abs", "min", "max"}      # the only functions allowed
MAX_CHARS = 2000                        # reject huge sources before parsing

# The whitelist: every node type a candidate may contain. If a type is
# not listed (Import, While, Attribute, Lambda ...) it is refused.
ALLOWED = (
    ast.Module, ast.FunctionDef, ast.arguments, ast.arg, ast.Return,
    ast.Assign, ast.If, ast.Pass, ast.Name, ast.Load, ast.Store,
    ast.Constant, ast.BinOp, ast.UnaryOp, ast.Compare, ast.IfExp,
    ast.Call, ast.Add, ast.Sub, ast.Mult, ast.Div, ast.FloorDiv,
    ast.Mod, ast.USub, ast.Lt, ast.LtE, ast.Gt, ast.GtE, ast.Eq,
)


class Rejected(Exception):
    """The source may not run at all (decided before any execution)."""


def validate(src):
    """Return the parsed tree, or raise Rejected with the reason."""
    # ── 1. Cheap checks first: length, then syntax ──────────────────
    if len(src) > MAX_CHARS:
        raise Rejected("source too long")
    try:
        tree = ast.parse(src)
    except (SyntaxError, ValueError) as err:
        raise Rejected(f"does not parse: {err}")

    # ── 2. The shape: one module-level function, two named args ─────
    body = tree.body
    ok = len(body) == 1 and isinstance(body[0], ast.FunctionDef)
    if not ok or body[0].name != "priority":
        raise Rejected("need exactly one def priority")
    if [a.arg for a in body[0].args.args] != ["item", "rem"]:
        raise Rejected("arguments must be (item, rem)")

    # ── 3. Walk every node and apply the rules ──────────────────────
    for node in ast.walk(tree):
        kind = type(node).__name__
        if not isinstance(node, ALLOWED):
            raise Rejected(f"{kind} is not allowed")
        if isinstance(node, ast.Name) and node.id.startswith("_"):
            raise Rejected(f"name {node.id!r} is not allowed")
        if isinstance(node, ast.Call):
            func = node.func
            if not (isinstance(func, ast.Name) and func.id in SAFE_CALLS):
                raise Rejected("only abs, min and max may be called")
    return tree


# ── 4. Try it on honest and hostile candidates ──────────────────────
def wrap(body):
    return "def priority(item, rem):\n    " + body + "\n"


CASES = {
    "best fit":   wrap("return -(rem - item)"),
    "uses min":   wrap("return -min(rem, 50)"),
    "import":     wrap("import os\n    return 1"),
    "dunder":     wrap("return ().__class__"),
    "while":      wrap("while True:\n        pass"),
    "open":       wrap("return open('/etc/passwd')"),
    "two defs":   "def f():\n    pass\n" + wrap("return 0"),
    "wrong args": "def priority(a, b):\n    return 0\n",
}
for name, src in CASES.items():
    try:
        validate(src)
        print(f"{name:11s} accepted")
    except Rejected as err:
        print(f"{name:11s} rejected: {err}")
best fit    accepted
uses min    accepted
import      rejected: Import is not allowed
dunder      rejected: Attribute is not allowed
while       rejected: While is not allowed
open        rejected: only abs, min and max may be called
two defs    rejected: need exactly one def priority
wrong args  rejected: arguments must be (item, rem)

Each hostile case is stopped for a different reason. The import and the loop fail the whitelist. The dunder access fails because Attribute is not on the list. (A dunder is a name with double underscores on both sides, such as __class__.) So there is no way to write something.something at all. The call to open fails the call rule. Note that this validator returns its answer by raising a Rejected exception with the reason. That is the style the labs use. A custom exception lets the caller tell "refused" apart from a bug (see Functions, Closures & Objects).

The lab's own validator is a longer version of this one. It also checks that every variable read was assigned first, and that constants are small numbers. See Lab 3, A Mini FunSearch.

3. Changing a tree

To change a tree, subclass ast.NodeTransformer. It works like a visitor, with one difference: what each visit_ method returns replaces the node. Return the same node to leave it alone. Return a new node to swap it. Return None to delete it. A transformer is therefore a visitor that can rewrite.

Three habits keep transformers safe.

  1. Copy first. A transformer changes the tree in place. Call copy.deepcopy(tree) if you still need the original, as you do when you make many children of one parent.
  2. Visit children. Call self.generic_visit(node) so the change reaches nested nodes.
  3. Repair locations. Every node normally records the line it came from. New nodes have none, and compile will refuse them. Call ast.fix_missing_locations(tree) once at the end.

Then ast.unparse(tree) turns the tree back into source text. It needs Python 3.9. The text it produces is tidy but not identical to the original: comments are gone, spacing is normal, and brackets appear only where needed. That is fine here, because the tree is the real program.

The idea

  1. one NodeTransformer per kind of edit, each changing one chosen node
  2. copy the tree, apply the edit, repair locations, unparse to source
  3. show that the original tree did not change
"""Three small mutations of a heuristic, made on the tree, shown as source."""
import ast
import copy

BASE = """def priority(item, rem):
    gap = rem - item
    if gap < 10:
        return 100 - gap
    return -gap
"""


# ── 1. One transformer per kind of edit ─────────────────────────────
# Each visits every node of one kind, but changes only the chosen one.
class TweakConstant(ast.NodeTransformer):
    """Add `delta` to the n-th numeric constant."""
    def __init__(self, n, delta):
        self.n = n
        self.delta = delta
        self.seen = 0

    def visit_Constant(self, node):
        if self.seen == self.n:
            node.value += self.delta
        self.seen += 1
        return node


class SwapOperator(ast.NodeTransformer):
    """Replace the n-th + or - with the other one."""
    def __init__(self, n):
        self.n = n
        self.seen = 0

    def visit_BinOp(self, node):
        self.generic_visit(node)            # visit the children first
        if isinstance(node.op, (ast.Add, ast.Sub)):
            if self.seen == self.n:
                swap = ast.Add if isinstance(node.op, ast.Sub) else ast.Sub
                node.op = swap()
            self.seen += 1
        return node


class SwapComparison(ast.NodeTransformer):
    """Turn every < into >."""
    def visit_Compare(self, node):
        node.ops = [ast.Gt() if isinstance(op, ast.Lt) else op
                    for op in node.ops]
        return node


# ── 2. Apply an edit to a COPY, repair, and print as source ─────────
def mutate(tree, transformer):
    new = transformer.visit(copy.deepcopy(tree))
    ast.fix_missing_locations(new)          # new nodes have no line numbers
    return ast.unparse(new)


tree = ast.parse(BASE)
EDITS = {
    "constant 10 -> 12": TweakConstant(0, +2),
    "'-' -> '+' (first)": SwapOperator(0),
    "'<' -> '>'": SwapComparison(),
}
print("original:")
print(ast.unparse(tree))
for label, transformer in EDITS.items():
    print(f"\nmutant: {label}")
    print(mutate(tree, transformer))

# ── 3. The original is untouched because we copied the tree ─────────
print("\noriginal still reads gap < 10:", "gap < 10" in ast.unparse(tree))

Each mutant is a mutation of the original: a small random-looking edit. The result is a mutant. All three print as valid code, which a character flip rarely achieves. The transformers pick the n-th match by a counter. In a search loop you would choose n with a seeded random number generator, so the same seed gives the same edit. The labs do exactly that.

Step through

Mutating best fit: swap Sub for Add

  1. The original tree. Six nodes, the same ones as the figure above. The source it came from is at the bottom.
  2. Choose a target. A walk over the tree lists the operators. The mutation picks one of them. Here there is only one, the Sub.
  3. Replace one node. The transformer returns a fresh Add node in its place. The other five nodes are untouched. The tree is still grammatical.
  4. Unparse. ast.unparse prints the new tree. This one is a harmless mutation: because item is the same for every bin, minus rem + item ranks bins in the same order as best fit does.

4. Running a tree

So far nothing has run. The next step turns a tree into something the interpreter can execute. compile(tree, "<candidate>", "exec") gives back a code object: the interpreter's internal form of the program, ready to run. The second argument is only a label. It appears in error messages and, as section 5 shows, it can be used to recognise candidate code. The third argument, "exec", says the tree is a whole module made of statements.

A code object does nothing until you call exec(code, namespace). A namespace is just a dictionary that maps names to values. Running the module's def priority statement stores a function in it under the key "priority". You then fetch it with namespace["priority"] and call it like any function.

The dictionary you pass decides what the code can see. Python looks up a name like open in the namespace, then in a special entry called "__builtins__". The builtins are the names every Python program gets without importing, such as len, open and __import__ (the function behind the import statement). If you pass a dictionary with your own "__builtins__", the candidate sees only what you listed.

The idea

  1. compile the tree to a code object, then exec it into a fresh dict
  2. give the dict a tiny __builtins__ and try to open a file
  3. compare: full builtins let an import run, empty builtins refuse it
  4. reach object classes with no builtins at all
"""Compile a checked tree and run it in a fresh namespace."""
import ast

SRC = "def priority(item, rem):\n    return -(rem - item)\n"

# ── 1. tree -> code object -> namespace ─────────────────────────────
tree = ast.parse(SRC)
code = compile(tree, "<candidate>", "exec")    # nothing runs yet

SAFE_BUILTINS = {"abs": abs, "min": min, "max": max}
namespace = {"__builtins__": SAFE_BUILTINS}   # a fresh dict per candidate
exec(code, namespace)                          # runs the def statement
priority = namespace["priority"]
print("priority(40, 70) =", priority(40, 70))

# ── 2. Restricted builtins stop the obvious attacks ─────────────────
ATTACK = "x = open('/etc/passwd')\n"
try:
    exec(compile(ATTACK, "<candidate>", "exec"),
         {"__builtins__": SAFE_BUILTINS})
except NameError as err:
    print("restricted:", err)

# ── 3. With full builtins the same text would have run ──────────────
IMPORT = "import os\nprint('full builtins: cwd is', bool(os.getcwd()))\n"
exec(compile(IMPORT, "<candidate>", "exec"), {})   # {} gets builtins added
try:
    exec(compile(IMPORT, "<candidate>", "exec"), {"__builtins__": {}})
except ImportError as err:
    print("empty builtins:", err)

# ── 4. ...but this is NOT a security boundary ───────────────────────
# No import, no builtin names: just attribute access on a tuple.
ESCAPE = "found = ().__class__.__base__.__subclasses__()\n"
space = {"__builtins__": {}}
exec(compile(ESCAPE, "<candidate>", "exec"), space)
print("classes reachable with empty builtins:", len(space["found"]) > 100)
priority(40, 70) = -30
restricted: name 'open' is not defined
full builtins: cwd is True
empty builtins: __import__ not found
classes reachable with empty builtins: True

The first result is the one you want: a plain function, called with a score of minus thirty. The second shows the allow-list at work, because open is simply not defined. The third shows what happens without it. Passing {} as the namespace makes Python add the full set of builtins, so the import and os.getcwd() ran. A candidate with those powers could delete files instead. Never run untrusted text with exec(src) or exec(src, {}).

Always use a fresh dictionary for each candidate. If you reuse one, a candidate can leave names behind for the next to find.

Common misconception

"Restricted builtins make exec a sandbox." They do not. The last line of the output shows why. With empty builtins, the text ().__class__.__base__.__subclasses__() still ran. It starts from an empty tuple, climbs to object, the parent of every class, and lists every class loaded in the interpreter. From that list, well-known tricks reach functions that can import modules and read files. No builtin name was needed. This is why the validator above refuses all attribute access and all names that start with an underscore. Together the two layers raise the bar, but a determined attacker may still find a path. The only real boundary is a separate process with limited rights. See Running Many Candidates Safely.

Systems connection

Operating systems keep programs apart with processes, user accounts and permission checks. Containers add more walls around a process. These are enforced by the kernel, which the candidate cannot talk its way past. See Sandboxes & Permissions for the layers an agent runs inside, and Cloud & Container Security for how a container is walled off. Your tree checks are the cheap first layer. The process boundary is the second layer, and you need both.

5. Budgets: stopping a program that never ends

A checked program can still hurt you by being slow. A loop such as while True: pass never finishes. An innocent-looking loop that squares a number each turn can build an integer with billions of digits. If the search loop waits for a candidate that never returns, the whole search stops. So every run needs a budget: a limit on the work a candidate may do.

Why count steps and not seconds? A clock measures a particular machine on a particular day. The same candidate might finish in time on your laptop and fail on a busy server. A search that gives different answers on different days is hard to debug. A step count is the same everywhere. (Real wall-clock limits are still needed, and the next chapter adds them with a separate process.)

Method one: fuel injected into the tree

The first method uses a transformer. It inserts a call to a function named _tick as the first statement of the function body and of every loop body. A Fuel object (the lab uses the same name) owns a counter. Each tick adds one. When the count passes the budget, tick raises OutOfFuel. Code with no loop costs one tick per call. A loop that never stops spends fuel on every turn until it runs dry. The namespace gets the real tick function under the name _tick.

The validator from section 2 forbids names that start with an underscore, so a candidate cannot call, replace or hide _tick. That rule and this injection work as a pair.

The idea

  1. Fuel counts ticks and raises OutOfFuel past the budget
  2. a transformer puts _tick() at the top of each function and loop body
  3. compile and exec with _tick in the namespace, then run two programs
"""Two ways to stop a runaway candidate: a fuel counter and a line tracer."""
import ast

FUEL = 1_000                    # ticks one evaluation may use

COUNTS = """def priority(item, rem):
    n = 0
    while n < 5:
        n += 1
    return n
"""
FOREVER = """def priority(item, rem):
    while True:
        pass
    return 1
"""


# ── 1. Fuel: a counter the code must call ───────────────────────────
class OutOfFuel(Exception):
    """The candidate used more ticks than its budget."""


class Fuel:
    def __init__(self, budget):
        self.budget = budget
        self.used = 0

    def tick(self):
        self.used += 1
        if self.used > self.budget:
            raise OutOfFuel(f"more than {self.budget} ticks")


class AddTicks(ast.NodeTransformer):
    """Put _tick() first in every function body and every while body."""
    @staticmethod
    def tick_stmt():
        call = ast.Call(ast.Name("_tick", ast.Load()), [], [])
        return ast.Expr(call)

    def visit_FunctionDef(self, node):
        self.generic_visit(node)
        node.body.insert(0, self.tick_stmt())
        return node

    def visit_While(self, node):
        self.generic_visit(node)
        node.body.insert(0, self.tick_stmt())
        return node


def build(src, fuel):
    tree = AddTicks().visit(ast.parse(src))
    ast.fix_missing_locations(tree)
    print(ast.unparse(tree))
    space = {"__builtins__": {}, "_tick": fuel.tick}
    exec(compile(tree, "<candidate>", "exec"), space)
    return space["priority"]


for name, src in [("counts to 5", COUNTS), ("forever", FOREVER)]:
    fuel = Fuel(FUEL)
    try:
        result = build(src, fuel)(40, 70)
        print(f"{name}: returned {result}, used {fuel.used} ticks")
    except OutOfFuel as err:
        print(f"{name}: OutOfFuel ({err}), used {fuel.used}")
def priority(item, rem):
    _tick()
    n = 0
    while n < 5:
        _tick()
        n += 1
    return n
counts to 5: returned 5, used 6 ticks
def priority(item, rem):

    while True:

        pass
    return 1

The counting loop used six ticks: one for the function and one for each of its five turns. The runaway loop was stopped one tick past the thousand allowed. Nothing waited on a clock.

One more detail from the lab. The lab's instrumenter also rewrites every whole-number constant into a decimal one (5 becomes 5.0). Python integers have no upper limit, so a loop that repeatedly squares one can grow a number far faster than the fuel runs out. Decimal numbers overflow to infinity instead, which is harmless. The full pipeline in section 7 includes this rewrite.

Method two: counting lines with sys.settrace

The second method does not edit the tree. sys.settrace(fn) asks the interpreter to call fn on every event while code runs. A tracer is such a function. It gets a "call" event when a new function starts. If it returns a second function, that one is called with a "line" event before each line runs inside that function. Count the line events, and you have a measure of work. Lab 6 uses this method.

Two details matter. The tracer should return a line-counting function only for frames whose file name is the label you compiled the candidate under. That is why the label "<candidate>" exists. Frames of your own grader code then cost nothing. And you should put the old tracer back in a finally block, so tracing is never left switched on by an error.

The idea

  1. a tracer that counts "line" events in frames labelled <candidate>
  2. run an honest loop, then a runaway that must hit the line budget
  3. time one hot loop with and without tracing
"""Count executed lines with sys.settrace, and see how it can be dodged."""
import sys
import time

CANDIDATE = "<candidate>"       # file name the grader compiles candidates as
BUDGET = 500                    # lines one call may execute


class OutOfLines(Exception):
    """The candidate executed more lines than its budget."""


# ── 1. A tracer that counts "line" events inside candidate code ─────
def run_counted(fn, *args, budget=BUDGET):
    """Call fn(*args). Return (result, candidate lines executed)."""
    lines = [0]

    def local(frame, event, arg):
        if event == "line":
            lines[0] += 1
            if lines[0] > budget:
                raise OutOfLines(f"more than {budget} lines")
        return local

    def global_trace(frame, event, arg):
        if frame.f_code.co_filename == CANDIDATE:
            return local            # trace this frame's lines
        return None                 # grader frames cost nothing

    old = sys.gettrace()
    sys.settrace(global_trace)
    try:
        return fn(*args), lines[0]
    finally:
        sys.settrace(old)           # always put the old tracer back


def load(src):
    space = {"__builtins__": {"range": range}}
    exec(compile(src, CANDIDATE, "exec"), space)
    return space["work"]

How a candidate can dodge the meter

Both methods are only as strong as the walls around them. If a candidate can reach the counter, it can tamper with it. Lab 6 is built around this family of problems: the scorer leaks something, and a search that is rewarded for speed finds the leak. For the tracer, the simplest leak is access to sys. A candidate that calls sys.settrace(None) switches the global tracer off. Every function it calls after that is no longer counted.

The idea

  1. two candidates with the same heavy loop; one calls sys.settrace(None)
  2. count lines for both and compare
"""A candidate that can reach sys.settrace can switch the meter off."""
import sys

CANDIDATE = "<candidate>"


def run_counted(fn, *args):
    """Return (result, lines executed in frames compiled as <candidate>)."""
    lines = [0]

    def local(frame, event, arg):
        if event == "line":
            lines[0] += 1
        return local

    def global_trace(frame, event, arg):
        if frame.f_code.co_filename == CANDIDATE:
            return local
        return None

    sys.settrace(global_trace)
    try:
        return fn(*args), lines[0]
    finally:
        sys.settrace(None)


# ── 1. Two candidates that do the same work ─────────────────────────
HONEST = """
def heavy(n):
    total = 0
    for i in range(n):
        total += i
    return total

def work(n):
    return heavy(n)
"""

# The cheat switches the global tracer off, then calls the heavy part.
# New frames are no longer traced, so their lines are never counted.
CHEAT = """
def heavy(n):
    total = 0
    for i in range(n):
        total += i
    return total

def work(n):
    sys.settrace(None)
    return heavy(n)
"""


def load(src, extra):
    space = {"__builtins__": {"range": range}}
    space.update(extra)
    exec(compile(src, CANDIDATE, "exec"), space)
    return space["work"]


# ── 2. Same answer, very different line counts ──────────────────────
honest = load(HONEST, {})
cheat = load(CHEAT, {"sys": sys})        # the leak: sys is reachable
print("honest:", run_counted(honest, 1000))
print("cheat: ", run_counted(cheat, 1000))
honest: (499500, 2004)
cheat:  (499500, 1)

Both candidates returned the same answer, 499500. The honest one was charged 2004 lines. The cheat was charged one. Only the line that switched tracing off was seen. (The one counted line is the call that switched tracing off.) The fix is the one you have met: do not hand the candidate sys, and refuse the attribute tricks that could fetch it. The labs add a second defence. They keep the meter in a place the candidate cannot name, and they measure again from the grader's side.

6. Canonical form: counting a program once

Evolution produces duplicates. Two mutations can arrive at return -(rem - item) and return -(space - x), which differ only in variable names. If you store both, your archive of "different programs" is padded, and you waste time scoring the same thing twice. You need a way to ask "is this the same program?" without running it.

The answer is a canonical form: a standard version of a program in which meaningless differences have been removed. Rename the arguments and locals to v0, v1 and so on, in order of first appearance. Drop the docstring. Comments and spacing are already gone, because the tree never held them. Then turn the tree back into a string with ast.dump and take a hash of it: a fixed-length fingerprint, here made by hashlib.sha256. Equal strings give equal hashes, and different strings almost never do.

The idea

  1. a transformer drops docstrings and renames variables in order of use
  2. dump the tree and hash it; keep the first label seen for each hash
  3. feed in three spellings of best fit and one different rule
"""Canonical form: different text, same program, one hash."""
import ast
import hashlib


# ── 1. Normalise a tree so cosmetic differences disappear ───────────
class Canon(ast.NodeTransformer):
    """Strip docstrings and rename arguments and locals to v0, v1, ..."""
    def __init__(self):
        self.names = {}

    def new_name(self, old):
        if old not in self.names:
            self.names[old] = f"v{len(self.names)}"
        return self.names[old]

    def visit_FunctionDef(self, node):
        first = node.body[0]
        is_doc = (isinstance(first, ast.Expr)
                  and isinstance(first.value, ast.Constant)
                  and isinstance(first.value.value, str))
        if is_doc and len(node.body) > 1:
            node.body = node.body[1:]       # drop the docstring
        for a in node.args.args:            # rename the parameters
            a.arg = self.new_name(a.arg)
        self.generic_visit(node)
        return node

    def visit_Name(self, node):
        if node.id in ("abs", "min", "max"):
            return node                     # builtins keep their names
        node.id = self.new_name(node.id)
        return node


def canonical(src):
    tree = Canon().visit(ast.parse(src))
    return ast.dump(tree)                   # no line numbers by default


def fingerprint(src):
    digest = hashlib.sha256(canonical(src).encode()).hexdigest()
    return digest[:12]


# ── 2. Three spellings of best fit, and one different program ───────
A = "def priority(item, rem):\n    return -(rem - item)\n"
B = '''def priority(x, space):
    """Tightest bin wins."""
    # a comment, and odd spacing
    return  -( space-x )
'''
C = "def priority(item, rem):\n    gap = rem - item\n    return -gap\n"
D = "def priority(item, rem):\n    return rem - item\n"

archive = {}
for label, src in [("A", A), ("B", B), ("C", C), ("D", D)]:
    key = fingerprint(src)
    archive.setdefault(key, label)
    print(f"{label}: {key}  first seen as {archive[key]}")
print("distinct programs:", len(archive))
A: c4ccde09c6d7  first seen as A
B: c4ccde09c6d7  first seen as A
C: 5c1d5b3d3f47  first seen as C

A and B look different on the page but get the same fingerprint, so the archive keeps one of them. C does the same job in two lines, with a helper variable, and so it counts as a new program. It is a different tree. The canonical form catches rewrites in spelling, not rewrites in meaning. Telling whether two programs always give the same answers is impossible in general. The practical stand-in is a behavioural signature: run each program on a fixed set of inputs and compare the outputs. Lab 3 stores both, the canonical text and the bins used on each instance. Chapter 22 shows how to cache results by this hash.

7. Putting it together

The function make_candidate(src, fuel) joins every step: parse, check, instrument, compile and exec. It either returns the callable priority or returns a Rejected object that explains why not. It does not raise. A search loop can then handle the two outcomes with a plain isinstance test.

The script below collects sections 2 to 5 into one file. It then scores seven programs on three seeded bin-packing instances of 200 items each. Item sizes run from 20 to 60 and bins hold 100. Each score is the number of bins used, so lower is better. The lower bound is the total size divided by 100, rounded up.

Thread: bin packing

The heuristic priority(item, rem) is a function, so it is also a tree. Everything the search needs is now in hand. A mutation edits a node. The validator decides whether the result may run. The fuel counter stops a runaway. The hash recognises a repeat. In the output below, first fit uses 90, 86 and 92 bins, and best fit is better on two of the three instances. The two mutants show the two common results of mutation: one has no effect, and one makes the packing worse. A search needs thousands of these steps to find something that wins.

The idea

  1. whitelist check on the parsed tree, with a reason for any refusal
  2. a transformer adds ticks and turns whole numbers into decimals
  3. make_candidate: parse, check, instrument, compile, exec, return the function
  4. online packing: best-scoring bin that fits, else open a new bin
  5. three seeded instances and the bound; evaluate never raises
  6. mutate two programs with transformers; score all seven
"""make_candidate: untrusted source in, a safe callable or Rejected out."""
import ast
import random

CAP = 100                       # bin capacity
FUEL = 200_000                  # ticks one evaluation may use
SAFE = {"abs": abs, "min": min, "max": max}

ALLOWED = (
    ast.Module, ast.FunctionDef, ast.arguments, ast.arg, ast.Return,
    ast.Assign, ast.AugAssign, ast.If, ast.While, ast.Pass, ast.Name,
    ast.Load, ast.Store, ast.Constant, ast.BinOp, ast.UnaryOp,
    ast.Compare, ast.IfExp, ast.Call, ast.Add, ast.Sub, ast.Mult,
    ast.Div, ast.USub, ast.Lt, ast.LtE, ast.Gt, ast.GtE, ast.Eq,
)


class Rejected(Exception):
    """Not allowed to run (returned, not raised, by make_candidate)."""


class OutOfFuel(Exception):
    """The candidate used more ticks than its budget."""


# ── 1. Check the tree (section 2 of the chapter) ────────────────────
def check(tree):
    body = tree.body
    if len(body) != 1 or not isinstance(body[0], ast.FunctionDef):
        return "need exactly one function"
    if body[0].name != "priority":
        return "function must be called priority"
    if [a.arg for a in body[0].args.args] != ["item", "rem"]:
        return "arguments must be (item, rem)"
    for node in ast.walk(tree):
        if not isinstance(node, ALLOWED):
            return f"{type(node).__name__} is not allowed"
        if isinstance(node, ast.Name) and node.id.startswith("_"):
            return f"name {node.id!r} is not allowed"
        if isinstance(node, ast.Call):
            ok = isinstance(node.func, ast.Name) and node.func.id in SAFE
            if not ok:
                return "only abs, min and max may be called"
    return None


# ── 2. Add ticks and turn ints into floats (section 5) ──────────────
class Instrument(ast.NodeTransformer):
    def tick(self):
        call = ast.Call(ast.Name("_tick", ast.Load()), [], [])
        return ast.Expr(call)

    def visit_FunctionDef(self, node):
        self.generic_visit(node)
        node.body.insert(0, self.tick())
        return node

    def visit_While(self, node):
        self.generic_visit(node)
        node.body.insert(0, self.tick())
        return node

    def visit_Constant(self, node):
        if type(node.value) is int:         # no huge integers
            return ast.Constant(float(node.value))
        return node


# ── 3. The whole pipeline: text -> callable or Rejected ─────────────
def make_candidate(src, fuel):
    try:
        tree = ast.parse(src)
    except (SyntaxError, ValueError) as err:
        return Rejected(f"does not parse: {err}")
    problem = check(tree)
    if problem:
        return Rejected(problem)
    tree = Instrument().visit(tree)
    ast.fix_missing_locations(tree)
    code = compile(tree, "<candidate>", "exec")
    space = {"__builtins__": SAFE, "_tick": fuel.tick}
    exec(code, space)
    return space["priority"]


class Fuel:
    def __init__(self, budget):
        self.used = 0
        self.budget = budget

    def tick(self):
        self.used += 1
        if self.used > self.budget:
            raise OutOfFuel("out of fuel")


# ── 4. Online bin packing and three seeded instances ────────────────
def pack(items, priority):
    bins = []
    for item in items:
        best, best_score = None, None
        for i, rem in enumerate(bins):
            if rem >= item:
                score = priority(float(item), float(rem))
                if best_score is None or score > best_score:
                    best, best_score = i, score
        if best is None:
            bins.append(CAP - item)
        else:
            bins[best] -= item
    return len(bins)


def instance(seed, n=200):
    rng = random.Random(seed)
    return [rng.randint(20, 60) for _ in range(n)]


INSTANCES = [instance(s) for s in (1, 2, 3)]
LOWER = [-(-sum(items) // CAP) for items in INSTANCES]


def evaluate(src):
    fuel = Fuel(FUEL)
    fn = make_candidate(src, fuel)
    if isinstance(fn, Rejected):
        return f"rejected ({fn})"
    try:
        return [pack(items, fn) for items in INSTANCES]
    except OutOfFuel:
        return "out of fuel"
    except Exception as err:
        return f"error ({type(err).__name__})"


# ── 5. Two mutants of a best-fit variant, made with the tree tools ───
class Tweak(ast.NodeTransformer):
    """Add 2 to every numeric constant that is below 10."""
    def visit_Constant(self, node):
        if type(node.value) is int and node.value < 10:
            return ast.Constant(node.value + 2)
        return node


class FlipCmp(ast.NodeTransformer):
    """Turn every < into >."""
    def visit_Compare(self, node):
        node.ops = [ast.Gt() if isinstance(o, ast.Lt) else o
                    for o in node.ops]
        return node


def mutate(src, transformer):
    tree = transformer.visit(ast.parse(src))
    return ast.unparse(ast.fix_missing_locations(tree))


HEAD = "def priority(item, rem):\n"
BONUS = (HEAD + "    gap = rem - item\n    if gap < 4:\n"
         "        return 50 - gap\n    return -gap\n")
PROGRAMS = {
    "first fit":      HEAD + "    return 0\n",
    "best fit":       HEAD + "    return -(rem - item)\n",
    "bonus variant":  BONUS,
    "mutant: 4 -> 6": mutate(BONUS, Tweak()),
    "mutant: < -> >": mutate(BONUS, FlipCmp()),
    "runaway":        HEAD + "    while True:\n        pass\n",
    "sneaky":         HEAD + "    return (1).__class__\n",
}
print("lower bound:", LOWER)
for name, src in PROGRAMS.items():
    print(f"{name:15s}", evaluate(src))
lower bound: [82, 80, 84]
first fit       [90, 86, 92]
best fit        [89, 86, 90]
bonus variant   [89, 86, 90]
mutant: 4 -> 6  [89, 86, 90]
mutant: < -> >  [92, 87, 92]
runaway         out of fuel
sneaky          rejected (Attribute is not allowed)

Read the table. First fit and best fit both sit above the lower bound, as every online method must. The mutant that changed a constant used exactly the same bins as the program it came from. That is a neutral mutation: a change that alters the code but not the score. The mutant that flipped a comparison was worse on all three instances. The runaway ended with a clean out of fuel. The sneaky candidate was rejected before it ran, with a reason. Nothing here needed more than the functions, classes and exceptions of the previous chapter. They are now put to work as a small machine that handles untrusted programs. Chapter 22 adds the process wall, and the evolution engine lab builds the loop around it.

Key takeaways

  • A program is a tree. ast.parse builds it, ast.unparse turns it back into text, and every edit in between is grammatical by construction.
  • ast.walk and NodeVisitor read a tree. NodeTransformer changes it. Copy first, visit children, and call ast.fix_missing_locations at the end.
  • Check untrusted code with a whitelist of node types, plus rules for shape, names and calls. Check the tree before you run anything.
  • compile then exec into a fresh dictionary with a small __builtins__ runs a function. This is bookkeeping, not a security boundary. Real isolation needs a separate process.
  • Bound work by steps, not seconds. Injected _tick() calls are cheap. sys.settrace is exact but slow, and only as strong as the walls that hide the counter.
  • Rename variables and drop docstrings, then hash the dump. That counts spelling variants once. It does not catch programs that differ in shape but behave the same.

  • Green Tree Snakes, "the missing Python AST docs". A readable tour of each node with examples. Start here when a node's fields puzzle you.
  • Python documentation, built-in functions compile and exec. What the modes mean, how the globals dictionary and __builtins__ interact, and the warning about untrusted input.

Check your understanding

A mutation operator flips a random character of a program's source text. Another picks a random node in its syntax tree and swaps it for a different node of the same kind. Which statement is most accurate?

  1. Both give valid programs equally often, because Python is forgiving.
  2. The tree edit always gives grammatical code, but the text flip often does not.
  3. The text flip is safer, because it cannot add new nodes.
  4. The tree edit always improves the program, because it respects the grammar.
A tree edit swaps one valid node for another, so the result always parses. A character flip often breaks brackets or keywords. Grammatical is not the same as better, so the last option is wrong: a tree edit can make the heuristic worse, as the flipped comparison did.

You write a blacklist validator that rejects Import, While and any call to open or eval. Why is a whitelist of node types stronger?

  1. It runs faster, because it checks fewer nodes.
  2. It lets you accept more programs.
  3. It makes exec a real sandbox.
  4. A node type you forgot to think about is refused by default.
A blacklist is safe only as far as your imagination goes. An attribute chain like ().__class__ uses none of the banned things. A whitelist refuses every type not named. It does not speed anything up, and it does not turn exec into a sandbox.

A candidate runs with exec(code, {"__builtins__": {}}). Which statement is true?

  1. It cannot call open by name, but object introspection such as ().__class__.__base__.__subclasses__() may still reach dangerous classes.
  2. It is fully isolated, because it has no builtins at all.
  3. It cannot loop for ever, because loops are also builtins.
  4. It can no longer read the attributes of objects it creates.
Removing builtin names removes only those names. Attribute access on objects the code can already build still works, and it leads to every class in the interpreter. Loops are syntax, not builtins, so a runaway loop still runs.

After a transformer inserts a new node into a tree, compile raises an error about missing line numbers. What is the fix?

  1. Call ast.dump on the tree before compiling.
  2. Call copy.deepcopy on the tree after compiling.
  3. Call ast.fix_missing_locations on the tree before compiling.
  4. Parse the original source a second time.
New nodes are born with no position. fix_missing_locations copies positions from their parents so the compiler can proceed. dump only prints, and deepcopy after compiling is too late. Reparsing the original would throw your edit away.

A search needs to stop runaway candidates and to give the same result on every machine. Which budget fits best?

  1. A wall-clock limit of two seconds inside the same process.
  2. A step count, made by _tick() calls injected at function entry and loop turns.
  3. A limit on the length of the source text.
  4. No limit, but retry any candidate that seems slow.
A step count does not depend on how fast the machine is, so reruns agree. A clock limit gives different answers on busy and idle machines. A short source can still contain an endless loop, and retrying a candidate that never returns blocks the search.

Programs A and C below always return the same numbers. Which statement about their canonical fingerprints is right?
A: return -(rem - item)
C: gap = rem - item; return -gap

  1. They match, because the canonical form compares behaviour.
  2. They match, because renaming makes every program identical.
  3. They differ, because the trees differ; a behavioural signature is needed to merge them.
  4. They differ, because docstrings were removed from only one of them.
The canonical form fixes names and removes docstrings, but it does not rewrite the structure. C has an extra assignment, so its tree is different. Only running both on the same inputs and comparing outputs, a behavioural signature, would show them equal.
