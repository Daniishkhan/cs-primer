Without a map, a path this wide feels like an endless pile of topics. There is linear algebra here, agents there, and a new framework every month. With a map, each chapter has a reason and a place. This course, A0, is the toolkit. It teaches only the mathematics and the working habits that later courses use, and it teaches them at the point they are needed. What an AI systems engineer builds

Since about 2023, a distinct specialty has grown up around building products on top of foundation models. These are large pretrained models that you adapt or call rather than train from nothing. The Latent Space essay "The Rise of the AI Engineer" (30 June 2023) argued that this work calls for engineering skill more than research credentials. Job titles vary, and the boundaries between them are blurry. Examples are AI engineer, applied AI engineer, applied research engineer and forward-deployed engineer. This path takes a broad view of the common core. An AI systems engineer takes a real problem and delivers a working, measured, safe system in which a learned model does part of the work.

The problems come from every domain. A bank wants to triage loan documents and show its reviewers where each answer came from. A hospital wants clinical notes summarised with every claim traceable to the record. A law firm wants contracts compared against a playbook. A government agency wants benefit claims routed correctly and explained to citizens. A retailer wants a support assistant that can look up an order and issue a refund without being talked into issuing ten. A software team wants a coding agent that can fix a bug in a repository and prove it did. The model is one component. The engineering around it is most of the job:

Frame and measure

Turn a vague wish into a task with a metric, a baseline, and a test set that reflects real use. Decide when a model is the wrong tool.

Assemble the system

Prompts, tools, retrieval, workflows and agents, wired together with the same care as any service: timeouts, retries, budgets, state.

Adapt the model

Choose among prompting, retrieval, fine-tuning and distillation; train or serve open models when the economics or the data rules demand it.

Evaluate and guard

Error analysis, judges, statistics, benchmarks of your own, prompt-injection defences, privacy, and incident response.

Operate

Latency, cost per request, observability, rollouts and the improvement loop that follows production traffic.

Deliver

Work with the people who own the problem: discover requirements under ambiguity, prototype the riskiest assumption, and explain the results honestly.

Most of that list is engineering and judgement. This is why the path treats a model as one component of a larger system. A model is an unreliable, probabilistic, expensive dependency. The question "how do I build something dependable on top of that?" is a systems question first.

What it assumes

You should be able to program in Python. You should also be comfortable with the software around a model: processes and memory, HTTP APIs, retries and timeouts, databases, logs and basic security. Where a chapter leans on one of those, it reminds you in a sentence.

This course: six parts

A0 has twenty chapters in six parts. The order follows what the later courses need first, not the order of a mathematics syllabus.

  1. Orientation (this page).
  2. Python for ML and program search (chapters 1 to 4, then 20 to 22): why loops are slow and arrays are fast, NumPy and broadcasting, tables and joins, and experiments you can rerun.   3. Linear algebra (chapters 5 to 7): vectors and similarity, matrices as functions, and the singular value decomposition (SVD).

  6. Working practice (chapters 16 to 19): reading papers, what compute costs, writing, and learning with AI assistants.

How to use these pages

Depth tags

Each chapter carries a badge. Deep dive means the mechanism in full, with derivations and several experiments. Core means the working knowledge, with fewer detours. Quick intro means orientation, read in one sitting. The tags tell you where to spend effort. On a first pass, skim the quick intros and read the deep dives that lead into the course you are about to start.

Labs, case studies and studios

After each part there are hands-on labs. You complete a Python file, using only the standard library so there is nothing to install. You then run python3 check.py, which tests each milestone and tells you what it expected and what it got. The checks are deterministic and run offline in seconds. Where a real model would be interesting, a scripted stand-in is used so the result is the same every time. Short case studies examine a real system or incident around one pattern. Design studios are timed mock design sessions. Sketch your own answer first, then compare. Do the labs. Reading about autodiff is not the same as having built it.

Notation

Vectors are lowercase letters (x, w), matrices are uppercase (W, X), and shapes are written (rows, columns), matching NumPy. The gradient is written ∇. Code is Python. It is pure Python first, so you can see every step, and then NumPy. Each derivation is followed by code that checks it numerically.

Not drowning

  • Use two passes. On the first pass, read the Why box, headings and diagrams, run the code, and move on. On the second pass, when a later course needs the idea, read in full and do the lab.
  • Run every listing. Change a number and predict the effect before running. Pages that you have only read fade within a week.
  • Mark chapters complete honestly. The tick box and progress bar are saved only in your browser. They are for you.
  • Budget your time. The course authors' own estimate for the mathematics and tooling in A0 is on the order of 40 to 60 hours. This is a planning guess, not a measurement, and it varies a lot with background.

A taste of the core idea

Nearly everything in A1 to A3 is one idea repeated at scale. A model is a function with adjustable numbers, called parameters. A loss function scores how wrong its predictions are on the data. The gradient of the loss says which direction to nudge each parameter to make the loss smaller. You take a small step that way, and its size is the learning rate. Then you repeat. This is gradient descent. It trains a two-parameter line in the next listing just as it trains a model with hundreds of billions of parameters.

Analogy: walking downhill in fog

Imagine standing on a hillside in thick fog, trying to reach the valley floor. You cannot see the valley. You can feel which way the ground slopes under your feet. So you take a step downhill, feel the slope again, and step again. The loss is your height, the parameters are your position, and the gradient is the slope under your feet. The learning rate is the length of your stride.

Where it breaks down: a hillside has two directions, but a model has millions or billions of parameters, so the “hill” has that many directions. Real hills also have many valleys, and a stride that is too long can carry you across the valley and up the far side.

# Fit y = w*x + b to five points by gradient descent, in pure Python.
xs = [0.0, 1.0, 2.0, 3.0, 4.0]
ys = [1.1, 2.9, 5.2, 7.1, 8.8]      # roughly y = 2x + 1, with noise

w, b = 0.0, 0.0                      # the parameters, starting from nothing
lr = 0.05                            # learning rate: how big each step is

def loss(w, b):                      # mean squared error
    return sum((w * x + b - y) ** 2 for x, y in zip(xs, ys)) / len(xs)

for step in range(201):
    # gradient of the loss with respect to w and b (derived in chapter 8)
    gw = sum(2 * (w * x + b - y) * x for x, y in zip(xs, ys)) / len(xs)
    gb = sum(2 * (w * x + b - y) for x, y in zip(xs, ys)) / len(xs)
    w, b = w - lr * gw, b - lr * gb  # step downhill
    if step in (0, 1, 10, 50, 200):
        print(f"step {step:3d}: w={w:.3f} b={b:.3f} loss={loss(w, b):.4f}")
step   0: w=1.396 b=0.502 loss=3.6337
step   1: w=1.854 b=0.675 loss=0.4472
step  10: w=2.052 b=0.837 loss=0.0416
step  50: w=1.987 b=1.022 loss=0.0205
step 200: w=1.960 b=1.099 loss=0.0184

The loss falls from 3.63 after the first update to 0.0184 by step 200. The parameters settle near w = 1.96 and b = 1.10. These are the exact least-squares answer for these five points, a calculation you can do with the formulas of ordinary regression. Early steps are large because the gradient is large. Later steps shrink as the line approaches the best fit. You do not need to follow the gradient formulas yet. Chapter 8 derives them, and chapter 9 shows how a computer does it for any function. For now, notice the shape of the program: a loop, a loss, a gradient, a small step. Learning is that loop.

State of play, October 2026

Job titles and tooling in this field shift every few months. Some commercial claims about "the AI engineer" are marketing. This path therefore teaches the parts that outlast them. These are the maths of the loop above, the engineering of dependable systems, and the habit of measuring. Where a page names a framework, protocol or model family, treat it as a dated example and check the primary documentation before relying on it.

Try it yourself

Run the taste script. Then change the learning rate lr from 0.05 to 0.2, and then to 0.3. What happens to the loss? Before running, predict whether a larger step always means faster learning. Then set lr = 0.001 and see how many steps it needs to get close. You have just met the most important knob in chapter 10.

Key takeaways

  • An AI systems engineer delivers measured, safe, operable systems in which a learned model does part of the work. Most of the job is engineering and judgement around the model.
  • The path has eleven courses and leads to four artifacts. A0 is the mathematical and practical toolkit, taught where later courses need it, with every chapter naming where its idea returns.
  • Study in two passes, run every listing, do the labs, and use the depth tags to decide where to spend effort.
  • The core loop of machine learning is: predict, score with a loss, compute the gradient, take a small step, repeat.

Check your understanding

A friend says: "To be an AI systems engineer I just need to learn the newest model API." Which reply best matches this path?

  1. Correct: the model is the whole job, and everything else is detail.
  2. Partly: the model is one unreliable component, and most of the work is framing, evaluation, safety, cost and operation around it, which is why the path treats the model as one part of a larger system.
  3. Incorrect: you must be able to train a new foundation model from scratch.
  4. Correct, provided you also memorise the current leaderboard.
The role is system delivery, not API calling or frontier research alone. Leaderboards and API details are volatile; framing, evaluation and operation are durable. Training foundation models is part of the path (A3) but is not required for every role.

In the gradient-descent listing, what does each step do?

  1. Chooses new random parameters and keeps them if the loss improves.
  2. Solves for the exact best parameters in one calculation.
  3. Increases the learning rate until the loss stops falling.
  4. Computes how the loss changes with each parameter and moves each a small amount in the direction that lowers it.
Gradient descent follows the slope of the loss downhill by a step set by the learning rate. It is not a random search, it does not solve in closed form (though for a line that is possible), and the learning rate is a fixed setting here.

You are short on time before starting the agents course. What is the most sensible use of A0?

  1. Do a first pass over the chapters it names (such as vectors and similarity), run their code, and return to the rest when a later course needs it.
  2. Read all twenty chapters in full, including every "Go deeper" box, before starting anything else.
  3. Skip A0, since mathematics is not used in retrieval.
  4. Only do the labs, without reading any chapter.
The course is built to be read at the point of need, with two passes. Reading everything first is the drowning pattern; skipping it leaves gaps (the dense retrieval chapter of the agents course uses cosine similarity, for instance); labs without the chapters lack the explanation they test.

In this course's notation, what does a shape of (64, 128) mean for a matrix W?

  1. 64 columns and 128 rows.
  2. A vector of 8,192 numbers.
  3. 64 rows and 128 columns, as in NumPy.
  4. 64 matrices of 128 numbers each, stacked.
Shapes are written (rows, columns), as NumPy's .shape does. A (64, 128) matrix does hold 8,192 numbers in total, but it is a matrix with two axes, not a flat vector, and not a stack.
