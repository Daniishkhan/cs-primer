Vectors, Dot Products & Similarity

Almost everything a model does to data starts with a list of numbers and a way to compare two such lists. This chapter builds the vector from two points of view, an arrow and a list. It then derives the dot product, cosine similarity and projection. Real runs show why they behave so differently in 3 dimensions and in 3,000. The question it answers: what does it mean for two things, such as a sentence, a user or a token, to be "close"?

Why this matters

Linear algebra is the language in which models are written down. A word becomes a vector of numbers. A layer becomes a function on vectors. The question "which document answers this?" becomes "which vector points most nearly the same way as the query?". This chapter is Part 2's foundation: the next two chapters (matrices and decompositions) are built from the single operation you meet here, the dot product. Three things are all dot products: attention scores in a Transformer (A2, chapter 9), embedding search (A5, chapter 7) and the prediction of a linear model (A1, chapter 5). After this chapter you will be able to compute and interpret a dot product. You will choose between dot product, cosine and Euclidean distance on purpose. You will also be able to explain why attention divides by √d.

A vector is a list, and an arrow

A vector is an ordered list of numbers. That is the whole definition, and your code uses it. [3.0, 4.0] is a vector with two components, also called entries or coordinates. The number of components is the vector's dimension, written n or d. A vector in n dimensions lives in the space Rn ("R" for the real numbers).

The same list can be read as an arrow from the origin to a point. The list (3, 4) is the arrow that goes 3 steps along the first axis and 4 along the second. The two readings answer different questions. The list tells a program what to store and how to index it (x[1]). The arrow tells a person what the operations mean. Adding two vectors places one arrow at the tip of the other. Multiplying by a number stretches the arrow. "How similar are these two?" becomes "do they point the same way?".

Vectors are how data enters machine learning. A house might be [bedrooms, area, age]. A customer might be a row of fifty usage counts. A document might be counts of each word in a vocabulary, as in the figure. An embedding is a vector that a trained model produces for a word, a sentence or an image, so that similar things get similar vectors. It typically has a few hundred to a few thousand components. Embeddings get their own chapters later (A2, chapter 6). Here we need only the arithmetic.

The two operations that define a vector space

Only two operations are needed to call something a vector space, and both work component by component:

  • Addition: (x + y)i = xi + yi. Both vectors must have the same dimension.
  • Scaling: (c x)i = c · xi, where c is an ordinary number (a scalar).

A linear combination uses both: c1 x + c2 y. Almost everything in a neural network is a linear combination of something. Here they are in pure Python, followed by the dot product and norm we are about to derive, and a NumPy check. The pure version comes first because it is short enough to read in full and makes clear that no magic is involved.

import math

def add(x, y):   return [a + b for a, b in zip(x, y)]
def scale(c, x): return [c * a for a in x]
def dot(x, y):   return sum(a * b for a, b in zip(x, y))
def norm(x):     return math.sqrt(dot(x, x))
def cosine(x, y): return dot(x, y) / (norm(x) * norm(y))

x = [3.0, 4.0]
y = [4.0, 3.0]
print("x + y      =", add(x, y))
print("2 * x      =", scale(2, x))
print("|x|        =", norm(x))
print("x . y      =", dot(x, y))
print("cos(x, y)  =", round(cosine(x, y), 4))
print("angle      =", round(math.degrees(math.acos(cosine(x, y))), 2), "degrees")

import numpy as np
xa, ya = np.array(x), np.array(y)
print("numpy agrees:", xa @ ya, np.linalg.norm(xa), xa.shape)

2 * x      = [6.0, 8.0]
|x|        = 5.0

The shape (2,) is NumPy's way of saying "one axis of length 2". Shapes are written (rows, cols) for matrices; a vector has one number, and the trailing comma is Python's way of writing a one-element tuple. Chapter 2 covered this in detail (NumPy, Arrays & Broadcasting).

Length: how big is a vector?

The norm of a vector is its length. For the arrow (3, 4), Pythagoras gives the length of the hypotenuse of a 3-4 right triangle: √(3² + 4²) = √25 = 5. In n dimensions the same idea applies:

|x| = √(x1² + x2² + … + xn²) = √(∑ xi²)

This is the Euclidean norm or L2 norm, and it is the one meant whenever a norm is written without a subscript. Two others appear in machine learning often enough to name:

NormFormulaFor (3, 4)Where you meet it
L2 (Euclidean)√(∑ xi²)5Weight decay, gradient clipping, normalised embeddings
L1 (Manhattan)∑ |xi|7Lasso regularisation, which pushes weights to exactly zero
L∞ (max)max |xi|4Largest-element checks, quantisation scales (chapter 11)

A vector of length 1 is a unit vector. Dividing any non-zero vector by its norm gives a unit vector with the same direction: (3, 4) / 5 = (0.6, 0.8). This normalisation separates a vector into "how big" (the norm) and "which way" (the unit vector). Much of the rest of this chapter is about the second part.

The dot product

The dot product (or inner product) of two vectors of the same dimension multiplies matching components and adds the results:

x · y = x1y1 + x2y2 + … + xnyn = ∑ xiyi

It returns a single number, not a vector. For x = (3, 4) and y = (4, 3): 3×4 + 4×3 = 24, matching the code above. Note that x · x = ∑ xi² = |x|², so the norm is the dot product of a vector with itself, square-rooted. In NumPy it is x @ y or np.dot(x, y). You may also see it written xTy, which will make sense in the next chapter.

The same number, seen geometrically

The formula above says nothing about angles, yet the dot product measures them:

x · y = |x| |y| cos θ

where θ is the angle between the two arrows. Check it with our example. |x| = |y| = 5, and the angle printed above was 16.26 degrees, whose cosine is 0.96. So 5 × 5 × 0.96 = 24. The two descriptions agree.

Go deeper why the two formulas are equal

Draw x, y and the third side x − y of the triangle they form. The law of cosines (Pythagoras corrected for a non-right angle) says |x − y|² = |x|² + |y|² − 2|x||y| cos θ.

Now expand the left side using the component definition. Two facts help: |v|² = v · v, and the dot product distributes over subtraction. So |x − y|² = (x − y) · (x − y) = x · x − 2 x · y + y · y = |x|² − 2 x · y + |y|².

Both expressions equal |x − y|². Cancel |x|² + |y|² and divide by −2: x · y = |x||y| cos θ. The step that matters is that the component formula makes the dot product "bilinear". It distributes over sums and pulls out scalars, which lets the algebra go through.

Reading the sign

Because |x| and |y| are never negative, the sign of x · y is the sign of cos θ. That sign tells you how the directions relate:

Positive

The angle is below 90 degrees. The vectors point broadly the same way. The closer to 0 degrees, the larger the value for a given pair of lengths.

Zero

The vectors are orthogonal (perpendicular). Neither carries any information about the other. (3, 4) and (−4, 3) have dot product −12 + 12 = 0.

Negative

The angle is above 90 degrees. They point in broadly opposite directions. At exactly 180 degrees the dot product is −|x||y|.

Orthogonality is the most useful special case, because "dot product zero" is easy to test in any dimension, where "perpendicular" cannot be drawn. It is also the basis for the idea of independent directions that chapters 6 and 7 rely on.

Cosine similarity: keep the direction, drop the length

Rearranging the geometric formula gives the angle's cosine from the components alone:

Plug in numbers. Here are two arrows with three entries each. Every line of output is one step above. The last two lines check that length is ignored and that flipping a vector flips the sign.

The idea

  1. x ← (1, 2, 2), y ← (2, 1, 2)
  2. top ← sum of x[i] × y[i]
  3. len_x ← √(x · x); len_y ← √(y · y)
  4. cos ← top ÷ (len_x × len_y); angle ← arccos(cos)
  5. compare: 10 × x, then −x
"""Cosine similarity by hand: cos(theta) = (x . y) / (|x| |y|).
Two 3-number vectors, small enough to check each line on a calculator."""
import math

# ── 1. Two vectors ───────────────────────────────────────────────────────
X = [1.0, 2.0, 2.0]                      # x, three numbers
Y = [2.0, 1.0, 2.0]                      # y, three numbers


# ── 2. The numerator: multiply matching entries, add them up ─────────────
def dot(a, b):
    return sum(p * q for p, q in zip(a, b))


top = dot(X, Y)                          # 1*2 + 2*1 + 2*2
print(f"x . y        = 1*2 + 2*1 + 2*2 = {top}")

# ── 3. The denominator: the two lengths ──────────────────────────────────
len_x = math.sqrt(dot(X, X))             # sqrt(1 + 4 + 4)
len_y = math.sqrt(dot(Y, Y))             # sqrt(4 + 1 + 4)
print(f"|x|, |y|     = {len_x}, {len_y}   product = {len_x * len_y}")

# ── 4. Divide: the cosine, then the angle it stands for ──────────────────
cos = top / (len_x * len_y)
print(f"cos(theta)   = {top} / {len_x * len_y} = {cos:.4f}")
print(f"theta        = {math.degrees(math.acos(cos)):.1f} degrees")

# ── 5. Length does not matter, direction does ────────────────────────────
big = [10 * a for a in X]                # same direction, ten times longer
cos_big = dot(big, Y) / (math.sqrt(dot(big, big)) * len_y)
opposite = [-a for a in X]
cos_opp = dot(opposite, Y) / (math.sqrt(dot(opposite, opposite)) * len_y)
print(f"10 * x vs y  = {cos_big:.4f}   (unchanged)")
print(f"-x vs y      = {cos_opp:.4f}   (opposite direction)")
x . y        = 1*2 + 2*1 + 2*2 = 8.0
|x|, |y|     = 3.0, 3.0   product = 9.0
cos(theta)   = 8.0 / 9.0 = 0.8889
theta        = 27.3 degrees
10 * x vs y  = 0.8889   (unchanged)
-x vs y      = -0.8889   (opposite direction)

This is cosine similarity. It is the dot product of the two normalised vectors, so it ignores how long each is and keeps only the direction. It always lies between −1 and +1, with the landmarks in the figure: +1 for the same direction, 0 for perpendicular, −1 for opposite.

Why not just use distance?

The obvious alternative is the Euclidean distance |x − y|, the length of the gap between the two points. It treats a long vector and a short one in the same direction as far apart. Word counts show why that is a poor fit: a document that repeats the same content five times is not about something different. The following run scores a query ("refund card") against four tiny documents with all three measures.

import numpy as np

vocab = ["refund", "card", "login", "password", "invoice", "reset"]
docs = {
    "A: refund to card":         [3, 2, 0, 0, 1, 0],
    "B: same, 5x longer":        [15, 10, 0, 0, 5, 0],
    "C: reset login password":   [0, 0, 2, 3, 0, 2],
    "D: short refund note":      [1, 0, 0, 0, 0, 0],
}
query = np.array([2, 1, 0, 0, 0, 0], dtype=float)   # "refund card"

print(f"{'document':26s} {'dot':>6s} {'euclid':>7s} {'cosine':>7s}")
for name, v in docs.items():
    v = np.array(v, dtype=float)
    dot = query @ v
    euc = np.linalg.norm(query - v)
    cos = dot / (np.linalg.norm(query) * np.linalg.norm(v))
    print(f"{name:26s} {dot:6.1f} {euc:7.2f} {cos:7.3f}")

# unit vectors: squared distance = 2 - 2 cos
a = np.array(docs["A: refund to card"], float); a /= np.linalg.norm(a)
q = query / np.linalg.norm(query)
print("|q - a|^2   =", round(float(np.sum((q - a) ** 2)), 6))
print("2 - 2 cos   =", round(float(2 - 2 * (q @ a)), 6))
document                      dot  euclid  cosine
A: refund to card             8.0    1.73   0.956
B: same, 5x longer           40.0   16.58   0.956
C: reset login password       0.0    4.69   0.000
D: short refund note          2.0    1.41   0.894
|q - a|^2   = 0.087634
2 - 2 cos   = 0.087634

Read the table row by row. Documents A and B have the same content, B five times over. Cosine gives both 0.956, as it should. The raw dot product ranks B five times higher than A, which rewards length, not relevance. The Euclidean distance puts B (16.58) far away, and even ranks the short, vaguer note D (1.41) as closer than A (1.73). Only cosine ranks the two refund documents together and the unrelated login document C at zero.

The last two lines of output hold a useful identity. For two unit vectors, |q − a|² = 2 − 2 cos θ. To see it, expand (q − a) · (q − a) = 1 − 2 q · a + 1. So after normalising, ranking by smallest distance, largest cosine and largest dot product all give the same ranking. That is why vector databases can offer all three and often store normalised vectors so that the cheapest computation, a plain dot product, gives cosine.

Common misconception

"A cosine similarity of 0.9 means the texts are 90% similar." It does not. Cosine is an angle, not a percentage, and what a given value means depends entirely on the model that produced the vectors. Some embedding models produce vectors that all sit in a narrow cone, so unrelated sentences score 0.6 or more. Others spread them out and give unrelated pairs near 0. Compare scores only within one model, and rank rather than threshold when you can. When you must pick a cut-off, choose it from labelled examples. The evaluation chapters in A5 and A6 show how.

When length does matter

Dropping magnitude is a choice, not a free lunch. A recommender may want the dot product precisely because a vector's length encodes popularity or confidence. Some embedding models are trained with a dot-product objective and give meaningful lengths. A zero vector also has no direction, so its cosine is 0/0 and code must decide what to return. The usual cause is the count vector of an empty document. The rule is to use the measure the model was trained with. Normalise only if the model's documentation says to. Never mix the two within one index.

Projections: how much of x lies along w?

The dot product answers a second question beyond similarity: how much of x points in the direction of w? The projection of x onto w is the part of x that lies along w, the shadow x casts on the line through w. Its formula comes straight from the geometric dot product. The length of the shadow is |x| cos θ, and the direction is that of w, so:

projw(x) = ((x · w) / (w · w)) w

The number c = (x · w)/(w · w) says how many copies of w to take. What is left over, r = x − projw(x), is the residual, and it is orthogonal to w by construction. Step through it with x = (3, 4) and w = (4, 1).

Step through

Projecting x onto w

  1. Two vectors. x = (3, 4) in blue and w = (4, 1) in green. We want the part of x that points along w.
  2. Everything along w is a multiple of w. The dashed line through w is the set of candidates c w. The two dot products on the right are all the arithmetic we need: x · w = 16 and w · w = 17.
  3. Drop a perpendicular. Find the point on that line closest to the tip of x. The shortest path is the perpendicular one, and the coefficient is c = 16/17 = 0.941.
  4. The projection p. p = 0.941 w = (3.765, 0.941), the shadow of x on the line. It is the best approximation to x that uses only the direction w.
  5. The residual r. r = x − p = (−0.765, 3.059) is what w cannot explain. The right-angle mark is checked by r · w = 0, and because p and r are perpendicular, Pythagoras gives |p|² + |r|² = |x|².
import numpy as np

x = np.array([3.0, 4.0])      # the vector to project
w = np.array([4.0, 1.0])      # the direction to project onto

coef = (x @ w) / (w @ w)      # how many copies of w
proj = coef * w               # component of x along w
resid = x - proj              # what is left over

print("coefficient   =", round(float(coef), 4))
print("projection    =", np.round(proj, 4))
print("residual      =", np.round(resid, 4))
print("resid . w     =", round(float(resid @ w), 10), "(orthogonal)")
print("|x|^2         =", x @ x)
print("|proj|^2+|res|^2 =", round(float(proj @ proj + resid @ resid), 10))
coefficient   = 0.9412
projection    = [3.7647 0.9412]
residual      = [-0.7647  3.0588]
resid . w     = 0.0 (orthogonal)
|x|^2         = 25.0
|proj|^2+|res|^2 = 25.0

The printed resid . w = 0.0 confirms orthogonality, and the last two lines confirm Pythagoras: 15.06 + 9.94 = 25.

Analogy: the shadow of a stick

Hold a stick at an angle with the sun directly overhead. Its shadow on the ground is its projection onto the ground. A stick lying flat has a shadow as long as itself. A stick standing upright has none, because it is orthogonal to the ground. A tilted stick has a shadow of length (stick length) × cos(tilt from the ground). The dot product with a direction is "how long is the shadow along that direction?".

Where it breaks down: a shadow is always on the lit side and always positive. A projection coefficient can be negative, when the stick points away from the direction. Also, in a 3,000-dimensional space the "ground" can be a line, a plane or a thousand-dimensional subspace. Intuition about one shadow on one floor stretches thin.

Projection is not a curiosity. It is the engine of several tools you will meet:

  • Gram–Schmidt: to build an orthogonal set of directions, subtract from each new vector its projections onto the ones already chosen. You will write this in Lab 1.
  • Least squares: fitting a line to data is projecting the target vector onto the span of the feature columns. That is why the residual of a linear regression is orthogonal to every feature. It is worth checking this on your own fits.
  • PCA (principal component analysis): projecting each data point onto the directions of greatest variance, found in chapter 7.
  • Steering and probing in language models: researchers project a hidden state onto a direction to read off how strongly a concept is present. That strength is the coefficient c.

High dimensions behave differently

Everything above was drawn in 2D, but real vectors have 384, 768 or 4,096 components. Intuition from the plane fails in two ways that matter in practice, and both can be seen with a few lines of code. Draw pairs of random vectors with independent standard-normal components (mean 0, spread 1) and look at their dot products and cosines.

import numpy as np
rng = np.random.default_rng(0)

print(f"{'d':>5s} {'std(q.k)':>9s} {'std(q.k)/sqrt(d)':>17s} {'std(cos)':>9s} {'1/sqrt(d)':>10s}")
for d in [2, 16, 128, 1024]:
    q = rng.standard_normal((20000, d))
    k = rng.standard_normal((20000, d))
    dots = np.sum(q * k, axis=1)
    cos = dots / (np.linalg.norm(q, axis=1) * np.linalg.norm(k, axis=1))
    print(f"{d:5d} {dots.std():9.2f} {(dots/np.sqrt(d)).std():17.3f} {cos.std():9.3f} {1/np.sqrt(d):10.3f}")
    d  std(q.k)  std(q.k)/sqrt(d)  std(cos)  1/sqrt(d)
    2      1.42             1.003     0.705      0.707
   16      4.01             1.002     0.250      0.250
  128     11.26             0.996     0.088      0.088
 1024     32.04             1.001     0.031      0.031

First effect: the dot product grows like √d

The third column of the output is 1.00 in every row: the spread (standard deviation) of q · k is √d. The reason is a short calculation. Each term qiki has mean 0 and variance 1, because it is the product of two independent unit-variance variables. The variance of a sum of d independent terms is the sum of their variances. So var(q · k) = d and the standard deviation is √d. The scores in an attention layer are exactly such dot products, and they feed a softmax. Suppose they have spread √d = 8 (for d = 64) or 32 (for d = 1,024). Then the softmax saturates. One position gets nearly all the weight, and the gradients through the others almost vanish. Dividing the scores by √d restores a spread of about 1, which is the "scaled" in scaled dot-product attention (Vaswani et al., 2017). The same derivation is revisited with softmax in A2, chapter 9.

Second effect: nearly everything is orthogonal

The cosine column tracks 1/√d. Two random directions in 1,024 dimensions are almost always nearly perpendicular. There is a great deal of room. You can fit far more than 1,024 directions that are all nearly orthogonal to each other. That is one reason embedding spaces can hold many distinct concepts in few dimensions. It also tells you how to read a similarity score. Against a background of random-pair cosines near 0.00 ± 0.03, a score of 0.3 is a strong signal. For the narrow-cone embedding models mentioned earlier, the same 0.3 may be below average.

Systems connection

A dot product is the simplest data-parallel computation there is: n independent multiplications and one sum. That is why CPUs have SIMD (single instruction, multiple data) instructions and GPUs have thousands of lanes for it. It is also memory-bound. Each multiply needs two numbers fetched from memory and does very little arithmetic with them. So speed is set by bandwidth, not by compute. The cost of brute-force search shows both. One query against 1,000,000 stored vectors of 768 float32 components is 768,000,000 multiply-adds. It reads 3.07 GB (1,000,000 × 768 × 4 bytes) of memory. That is why approximate nearest-neighbour indexes exist, and why storing vectors in 8 or 16 bits matters.

Many dot products at once

Real systems never score one pair; they score a query against thousands or millions of stored vectors. Stack the stored vectors as the rows of a table E with shape (items, d). Then E @ q is one dot product per row, computed in a single vectorised call, and the result has shape (items,). This is the first appearance of the idea that the next chapter develops fully: a matrix times a vector is a batch of dot products. Normalise the rows once when you build the index, and every query afterwards needs only a plain matrix-vector product to give cosine scores.

import numpy as np
rng = np.random.default_rng(1)

# 1,000 stored "embeddings" of dimension 8, one per row, and one query
E = rng.standard_normal((1000, 8))
q = E[42] + 0.3 * rng.standard_normal(8)      # a noisy copy of item 42

E_unit = E / np.linalg.norm(E, axis=1, keepdims=True)   # normalise each row once
q_unit = q / np.linalg.norm(q)

scores = E_unit @ q_unit            # (1000, 8) @ (8,) -> (1000,): 1,000 dot products
top = np.argsort(-scores)[:3]
print("scores shape:", scores.shape)
print("top 3 ids   :", top)
print("top 3 scores:", np.round(scores[top], 3))
raw = E @ q
print("raw dot picks:", np.argsort(-raw)[:3], "(not normalised: long vectors win)")
scores shape: (1000,)
top 3 ids   : [ 42 878 629]
top 3 scores: [0.938 0.819 0.819]
raw dot picks: [496 616  42] (not normalised: long vectors win)

The noisy copy of item 42 finds item 42 first, with a score well clear of the rest. The line that follows shows the cost of skipping normalisation: ranking by raw dot product can promote items only because their vectors happen to be long. Whether that is a bug depends on whether the model's training meant length to carry information, as discussed above.

State of play, October 2026

Models differ in whether they return unit-length vectors and in which similarity they were trained for. The same model's hosted and open-source versions can differ too. Many text-embedding models and libraries return normalised vectors by default, so dot product and cosine coincide. Read this from the model card or API documentation. Do not assume it. Several vector stores also let you choose the metric per index (cosine, dot product or Euclidean). Check both before you build an index; changing the metric later means re-indexing.

Key takeaways

  • A vector is a list of numbers you can also draw as an arrow. Addition and scaling work component by component; every other operation here is built from them and the dot product.
  • The dot product ∑ xiyi equals |x||y| cos θ. Its sign says whether the vectors agree, are unrelated (zero, orthogonal) or oppose.
  • Cosine similarity divides out both lengths, so it compares direction only. For unit vectors, squared distance is 2 − 2 cos, so all three measures give one ranking once vectors are normalised.
  • The projection of x onto w is ((x · w)/(w · w)) w; the leftover is orthogonal to w. This underlies Gram–Schmidt, least squares and PCA.
  • In d dimensions the dot product of random vectors has spread √d, hence attention's 1/√d. Random directions are nearly orthogonal, with cosine spread about 1/√d.
  • A cosine score has no model-independent meaning: compare within one model, and set thresholds from labelled data.

Vectors a = (1, 2, 2) and b = (2, 1, −2). What is a · b, and what does it tell you?

  1. 6; they point in broadly the same direction
  2. −3; they point in broadly opposite directions
  3. 0; they are orthogonal
  4. 9; they are parallel
1×2 + 2×1 + 2×(−2) = 2 + 2 − 4 = 0, so the vectors are orthogonal. The other options come from sign slips on the last product. Parallel vectors would give a dot product equal to ±|a||b| = ±9 only if b were a multiple of a, which it is not.

A document is duplicated so that every word count doubles. Its cosine similarity with a fixed query, and its dot product with the query, change as follows.

  1. Cosine unchanged, dot product doubles
  2. Both unchanged
  3. Both double
  4. Cosine halves, dot product doubles
Doubling x multiplies x · q by 2 and |x| by 2, so the ratio in the cosine is unchanged. Option 2 would be true only for a measure that normalises the length and the dot product does not. This is exactly why raw dot product favours long documents.

Two vectors have been normalised to unit length and the Euclidean distance between them is 1.0. What is their cosine similarity?

  1. 1.0
  2. 0.0
  3. 0.707
  4. 0.5
For unit vectors, distance² = 2 − 2 cos, so 1 = 2 − 2 cos and cos = 0.5 (an angle of 60 degrees). The value 0.707 would come from forgetting to square the distance; 0.0 is the answer when the distance is √2.

You project x = (2, 2) onto w = (1, 0). What are the projection and the residual?

  1. Projection (2, 2), residual (0, 0)
  2. Projection (2, 0), residual (0, 2)
  3. Projection (1, 0), residual (1, 2)
  4. Projection (0, 2), residual (2, 0)
c = (x · w)/(w · w) = 2/1 = 2, so the projection is 2w = (2, 0) and the residual is (0, 2), which is orthogonal to w. Option 4 projects onto the wrong axis; option 3 forgets to multiply the coefficient into w.

Attention scores are dot products of query and key vectors with d = 64 and roughly independent, unit-variance components. Without scaling, about how large is the typical score, and why is that a problem?

  1. About 1, which is fine, so scaling is cosmetic
  2. About 64; softmax then ignores all but the smallest score
  3. About 8; softmax saturates onto one position and gradients to the others become tiny
  4. About 0.125, so every position gets nearly equal weight
The spread of a sum of d unit-variance terms is √d = 8. Scores of that size make the softmax nearly one-hot, so small changes elsewhere hardly move the output and learning stalls. Dividing by √d brings the spread back to about 1. The value 64 confuses variance (which is d) with standard deviation (√d).

A colleague sets the rule "flag a duplicate if cosine similarity is above 0.85". They use a new embedding model but the threshold from the old one. What is the main risk?

  1. Cosine values are not comparable across models, so the threshold may flag far too many or too few pairs
  2. Cosine similarity can exceed 1 in high dimensions
  3. Cosine is undefined for embeddings of more than 512 dimensions
  4. Normalised vectors always have cosine above 0.85
Different models spread their vectors differently: some place everything in a narrow cone (high scores for unrelated texts), others do not. Re-derive the threshold from labelled pairs for the new model. Cosine is always in [−1, 1] in any dimension, and normalisation does not force any minimum similarity.
