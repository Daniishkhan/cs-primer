Lab 4: Sampling, Likelihood & Entropy

A language model does three things with probabilities: it samples from them to produce a token, it is trained by making the observed text more likely, and it is compared with another model by a divergence. Chapter 12, 13 and 14 explained each. In this lab you build all three from the ground up, over plain Python lists: samplers made from uniform random numbers, maximum-likelihood fits, a log-softmax that survives logits of 1,000, temperature and nucleus sampling, entropy, and the KL divergence in the forms that PPO, DPO and GRPO use. Every function is checked against a hand-computed answer, and every sampler against the statistics it promises.

Why this lab matters

Almost every number an AI system produces passes through the functions you write here. The next token is a draw from softmax(logits / T) after a truncation step. The training loss is a negative log-likelihood, computed from logits through a log-softmax that must never form a probability. The reported perplexity is an exponentiated entropy. The penalty that keeps a post-trained model near its starting point is a KL divergence, estimated in practice from sampled tokens, not summed over a vocabulary. When one of these is subtly wrong, nothing crashes: the loss is merely a little off, the samples are slightly too varied, the KL estimate is occasionally negative. Engineers who have written them once know where to look.

The habit this lab installs is testing a probabilistic function two ways. First with scripted randomness: feed the sampler the uniform numbers 0.5 and 0.25 and the answer is a fixed number you can compute on paper. Then statistically: draw tens of thousands of samples under a seed and require the frequencies to land within five standard errors of the truth, so that a correct sampler essentially never fails and a subtly wrong one essentially always does. The same two-step pattern checks the evaluation statistics of A6 and the sampling code inside serving engines.

Pure Python, deterministic, under a second

Standard library only (math and random), Python 3.9 or newer. Every random draw in check.py comes from random.Random(seed) or from a scripted source that returns numbers you can read in the file; a failure prints its seed, and python3 check.py solution 1 3 replays milestone 1 on seed 3 only. The oracles never call your functions. The sampling tests use a tolerance of five standard errors, and the seeds are fixed, so they never flake. The full check takes about a fifth of a second.

Milestone 1: samplers from uniform numbers

A computer has one primitive source of randomness: a pseudo-random number generator that, from a seed, produces a long deterministic sequence that behaves like independent draws from the uniform distribution on [0, 1) (chapter 4 on seeds). Every other distribution is a transformation of those numbers. Four transformations cover most needs.

Inverse-cdf sampling. The cdf F(x) = P(X ≤ x) maps a value to a probability. Draw u uniformly in [0, 1) and return x = F−1(u). Then P(x ≤ a) = P(F−1(U) ≤ a) = P(U ≤ F(a)) = F(a), which is exactly the right distribution. For the exponential with rate λ (waiting times; mean 1/λ), F(x) = 1 − e−λx, which inverts to x = −ln(1 − u)/λ. With λ = 2 and u = 0.5 the answer is ln 2 / 2 = 0.3466, a number the check computes by hand before it samples anything.

Categorical draws. For a distribution over a few outcomes the cdf is a staircase of running totals, and inversion becomes: walk along the totals until you pass u. This is how a token is drawn from a softmax output.

Box–Muller. The Gaussian cdf has no closed-form inverse, so a different change of variables is used. Two independent standard Gaussians, viewed in the plane, have a rotationally symmetric joint density; the squared distance from the origin, R2, then has an exponential distribution with mean 2 and the angle is uniform. Sampling those two with u1 and u2 gives z1 = √(−2 ln u1) cos(2πu2) and z2 = √(−2 ln u1) sin(2πu2). Python's random.random() can return exactly 0.0 but never 1.0, so the lab uses 1 − random() inside the logarithm, which is never 0.

Rejection sampling. When even a pdf is awkward to invert, propose a point x uniformly on [0, 1] and a height u, and keep x if u < f(x)/M, where M is any bound on the density. The kept points have density f. Each proposal succeeds with probability 1/M (the density integrates to 1 and the box has area M), so the method costs M proposals per sample, which is cheap for a gentle density and ruinous for a spiky one. The script runs all four, plus a deliberately narrow density:

Common misconception

"Whether the walk stops at u < total or u <= total cannot matter, because u is almost never exactly equal to a total." It matters at the edges. random() can return exactly 0.0, and with <= an outcome with probability 0 at the front of the list would be selected by it: a token the model said was impossible. With the strict <, a zero-probability entry never wins, because its running total does not rise above the one before it. The check has a case for exactly this, with u = 0 and u = 0.5.

def sample_exponential(rng, rate):
    """One draw from Exponential(rate) by inverting the cdf F(x) = 1 - exp(-rate x).

    Use exactly one rng.random() call, u, and return -ln(1 - u) / rate.
    """
    return -math.log(1.0 - rng.random()) / rate

def sample_categorical(rng, probs):
    """One index drawn with the given probabilities: walk along the cumulative sums.

    Use exactly one rng.random() call, u. Return the first index i whose running total
    p_0 + ... + p_i is STRICTLY greater than u (so an entry with probability 0 is never returned).
    If rounding leaves u above every running total, return the last index with positive probability.
    """
    u, acc, last = rng.random(), 0.0, len(probs) - 1
    for i, p in enumerate(probs):
        if p > 0:
            last = i
        acc += p
        if u < acc:
            return i
    return last

def box_muller(rng):
    """Two independent standard Gaussians (z1, z2) from two uniforms.

    u1 = 1 - rng.random() (the first call; this keeps u1 in (0, 1] so the log is finite),
    u2 = rng.random() (the second call); r = sqrt(-2 ln u1); return (r cos(2 pi u2), r sin(2 pi u2)).
    """
    u1 = 1.0 - rng.random()
    u2 = rng.random()
    r = math.sqrt(-2.0 * math.log(u1))
    return r * math.cos(2.0 * math.pi * u2), r * math.sin(2.0 * math.pi * u2)

def rejection_sample(rng, density, bound, n):
    """n draws from a density on [0, 1] that never exceeds `bound`, by rejection.

    Repeat: x = rng.random() (first call), u = rng.random() (second call); keep x if
    u < density(x) / bound. Stop at n kept samples. Return (samples, tries), where tries counts
    the proposals made (kept or not).
    """
    samples, tries = [], 0
    while len(samples) < n:
        x = rng.random()
        u = rng.random()
        tries += 1
        if u < density(x) / bound:
            samples.append(x)
    return samples, tries

Milestone 2: likelihoods and maximum-likelihood fits

Chapter 13's central move is to describe a model as assigning a probability to the data, and to choose parameters that make the observed data as probable as possible. The likelihood L(θ) is the probability of the observed data as a function of the parameter θ; the maximum-likelihood estimate (MLE) is the θ that maximises it. For n independent observations, L is a product of n probabilities, each below 1, so it shrinks towards zero faster than a computer can represent. The remedy is to work with the logarithm: ln L is a sum, it has its maximum at the same θ, and it is what every framework computes. The function you write first makes the problem concrete.

Three lessons sit in that output. The likelihood curve sharpens with data: with 10 flips, θ = 0.6 is 81% as likely as the best value, so the data hardly tell them apart; with 1,000 flips it is one in 2.4 billion. The likelihood of 1,500 flips underflows to exactly 0.0 although its logarithm, −916.30, is an ordinary number, so a program that multiplied probabilities would see every θ tie. And the last table is about honesty of estimators: the MLE of a variance divides by n, and is systematically too small, because the residuals are measured from a mean fitted to the same data. For n = 3 the average is two-thirds of the truth; dividing by n − 1 (Bessel's correction) removes the bias. Your gaussian_mle takes a ddof argument so both are available.

The likelihoods and estimators you need are short. For h heads in n flips, ln L(θ) = h ln θ + (n − h) ln(1 − θ), and setting its derivative h/θ − (n − h)/(1 − θ) to zero gives θ = h/n. For Gaussian data, ln L(μ, σ) = −(n/2) ln(2πσ2) − ∑(xi − μ)2/(2σ2), maximised by the sample mean and, for σ2, the mean squared deviation. For Poisson counts ki (events per interval, such as requests per second), ln L(λ) = ∑(ki ln λ − λ − ln ki!), maximised by the mean count. For a categorical variable, the MLE is the observed frequency of each outcome (with a Lagrange multiplier to keep the probabilities summing to 1). In every case, the maximum-likelihood estimate of a probability is a frequency and of a mean is an average, which is reassuring; the work of the milestone is getting the logarithms and the edge cases right.

The edge cases are the part that bites. A probability of exactly 0 for an outcome that did not occur contributes 0 · ln 0, which is defined as 0 here; for an outcome that did occur it makes the data impossible and the log-likelihood −∞. The check also verifies that your MLE really is a maximum, by comparing its log-likelihood with its neighbours on random data, and uses a neat identity: at the Gaussian MLE the squared-error term equals exactly n/2, so the maximum log-likelihood is −(n/2)(ln(2πσ̂2) + 1).

def bernoulli_loglik(heads, n, theta):
    """ln L(theta) for `heads` successes in n independent trials: h ln(theta) + (n - h) ln(1 - theta).

    A term whose count is 0 contributes 0 even if its probability is 0 (0 ln 0 = 0); a positive
    count with probability 0 makes the data impossible, so return -math.inf.
    Example: bernoulli_loglik(7, 10, 0.7) == 7 ln 0.7 + 3 ln 0.3 = -6.1086.
    """
    total = 0.0
    for count, prob in ((heads, theta), (n - heads, 1.0 - theta)):
        if count > 0:
            if prob <= 0.0:
                return -math.inf
            total += count * math.log(prob)
    return total

def gaussian_loglik(xs, mu, sigma):
    """ln L(mu, sigma) of independent draws xs from N(mu, sigma^2):
    sum over i of  -0.5 ln(2 pi sigma^2) - (x_i - mu)^2 / (2 sigma^2).

    Example: gaussian_loglik([0.0], 0.0, 1.0) == -0.5 ln(2 pi) = -0.9189.
    """
    n = len(xs)
    sq = sum((x - mu) ** 2 for x in xs)
    return -0.5 * n * math.log(2.0 * math.pi * sigma * sigma) - sq / (2.0 * sigma * sigma)

def poisson_loglik(counts, lam):
    """ln L(lambda) of independent Poisson counts: sum over i of  k_i ln(lambda) - lambda - ln(k_i!).

    Use math.lgamma(k + 1) for ln(k!). Example: poisson_loglik([0, 1, 2], 1.0) == -3 - ln 2 = -3.6931.
    """
    return sum(k * math.log(lam) - lam - math.lgamma(k + 1) for k in counts)

def gaussian_mle(xs, ddof=0):
    """(mean, variance) of xs. The maximum-likelihood variance divides by n (ddof=0); the unbiased
    estimate divides by n - ddof with ddof=1. Raise ValueError if xs has too few points."""
    n = len(xs)
    if n - ddof < 1:
        raise ValueError("need more data than ddof")
    mu = sum(xs) / n
    return mu, sum((x - mu) ** 2 for x in xs) / (n - ddof)

def poisson_mle(counts):
    """The maximum-likelihood rate of Poisson counts: their mean. Raise ValueError if empty."""
    if not counts:
        raise ValueError("no data")
    return sum(counts) / len(counts)

def categorical_mle(counts):
    """The maximum-likelihood probabilities of a categorical variable: counts / total.
    Raise ValueError if the total is 0."""
    total = sum(counts)
    if total <= 0:
        raise ValueError("all counts are zero")
    return [c / total for c in counts]

Milestone 3: a line fitted by gradient descent on the NLL

Chapter 13's headline result is that squared error is maximum likelihood under Gaussian noise. This milestone proves it numerically, with a model that also learns how noisy the data are. The model is y = wx + b + ε with ε ∼ N(0, σ2). It has three parameters, and to keep σ positive without constraints the code optimises its logarithm, s = ln σ, so that σ2 = e2s. With the residual ri = yi − (wxi + b), the negative log-likelihood is

NLL(w, b, s) = ∑i [ ½ ln(2πσ2) + ri2 / (2σ2) ].

Differentiate by the chain rule (chapter 8). Since ∂ri/∂w = −xi and ∂ri/∂b = −1,

∂NLL/∂w = −∑ ri xi / σ2,    ∂NLL/∂b = −∑ ri / σ2,    ∂NLL/∂s = ∑ (1 − ri2 / σ2).

The first two are the least-squares gradient divided by σ2: the noise level only rescales them, which is why you can fix σ = 1 when fitting weights. The third is new, and its zero is the answer to "how noisy is the data?": 1 = (1/n) ∑ ri2/σ2, so σ2 is the mean squared residual. check.py verifies your three formulas against central differences of your own NLL at random points, as in Lab 2, plus the hand example in the docstring: for the two points (0, 1) and (1, 3), the gradient at (0, 0, 0) is [−3, −4, −8].

Then fit it two ways. least_squares is the closed form from the normal equations: the slope is cov(x, y)/var(x) and the intercept makes the line pass through the point of means. fit_line runs gradient descent on the mean NLL from (0, 0, 0), with learning rate 0.1 and 1,500 steps; the gradient of the mean is the summed gradient divided by n, which keeps the step size independent of the data size and is why the sums in line_nll must be divided by n inside fit_line.

def line_nll(params, xs, ys):
    """Negative log-likelihood of y = w x + b + noise, noise ~ N(0, sigma^2), with sigma = exp(s).

    params = (w, b, s): the slope, the intercept and the LOG of the noise standard deviation.
    With r_i = y_i - (w x_i + b) and sigma^2 = exp(2 s):
        nll = sum_i  0.5 ln(2 pi sigma^2) + r_i^2 / (2 sigma^2)
    Returns (nll, grad) with grad = [d nll / d w, d nll / d b, d nll / d s]. These are SUMS over the
    data, not means. Example: xs = [0, 1], ys = [1, 3], params (2, 1, 0) has nll = ln(2 pi) = 1.8379,
    and params (0, 0, 0) has gradient [-3, -4, -8].
    """
    w, b, s = params
    var = math.exp(2.0 * s)
    nll, gw, gb, gs = 0.0, 0.0, 0.0, 0.0
    for x, y in zip(xs, ys):
        r = y - (w * x + b)
        nll += 0.5 * math.log(2.0 * math.pi * var) + r * r / (2.0 * var)
        gw -= r * x / var
        gb -= r / var
        gs += 1.0 - r * r / var
    return nll, [gw, gb, gs]

def least_squares(xs, ys):
    """The closed-form least-squares line (w, b): w = cov(x, y) / var(x), b = mean(y) - w mean(x)."""
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    w = sum((x - mx) * (y - my) for x, y in zip(xs, ys)) / sum((x - mx) ** 2 for x in xs)
    return w, my - w * mx

def fit_line(xs, ys, lr=0.1, steps=1500):
    """Gradient descent on the MEAN negative log-likelihood from (w, b, s) = (0, 0, 0).

    Each step moves params by -lr * grad / n, using line_nll. Returns the final (w, b, s) as a list.
    """
    n = len(xs)
    params = [0.0, 0.0, 0.0]
    for _ in range(steps):
        _, g = line_nll(params, xs, ys)
        params = [p - lr * gi / n for p, gi in zip(params, g)]
    return params

Milestone 4: a stable log-softmax and its gradient

The softmax turns scores z1, …, zK (the logits) into probabilities pi = ezi / ∑j ezj. Transcribed literally, it breaks on large inputs: math.exp(1000) overflows (Python raises OverflowError; NumPy returns inf and then nan), and logits in the hundreds are normal in practice. The fix rests on one fact. Softmax does not change when you add the same constant c to every logit, because ez+c = ecez and the factor ec cancels from numerator and denominator. Choose c = −max(z) and the largest exponent becomes e0 = 1: nothing can overflow, and the denominator is at least 1.

The same shift gives the log-sum-exp that anchors everything else: logsumexp(z) = ln ∑j ezj = m + ln ∑j ezj − m with m = max(z). From it, ln pi = zi − logsumexp(z): the log-softmax, computed without ever forming a probability. That matters for the second hazard, underflow. A probability like e−800 is below the smallest positive float and becomes exactly 0, and then the loss −ln p is −ln 0 = ∞. The log-softmax of the same logits is a perfectly ordinary −800. Cross-entropy is then a lookup, loss = −log_softmax(z)[target], and this is why every framework fuses softmax and cross-entropy into one function that takes logits.

def logsumexp(zs):
    """ln(sum_j exp(z_j)) without overflow: m + ln(sum_j exp(z_j - m)) with m = max(zs).

    Raise ValueError for an empty list. If every entry is -math.inf the answer is -math.inf
    (do not compute -inf minus -inf). Example: logsumexp([1000, 1000]) == 1000 + ln 2.
    """
    if not zs:
        raise ValueError("logsumexp of an empty list")
    m = max(zs)
    if m == -math.inf:
        return -math.inf
    return m + math.log(sum(math.exp(z - m) for z in zs))

def log_softmax(zs):
    """ln softmax(z)_i = z_i - logsumexp(z), computed in log space (never form the probabilities)."""
    lse = logsumexp(zs)
    return [z - lse for z in zs]

def softmax(zs):
    """The probabilities exp(log_softmax(z)); they sum to 1 and survive logits of 1000."""
    return [math.exp(v) for v in log_softmax(zs)]

def cross_entropy(logits, target):
    """The loss -ln softmax(logits)[target], computed from the logits without forming a probability."""
    return -log_softmax(logits)[target]

def cross_entropy_grad(logits, target):
    """The gradient of cross_entropy with respect to the logits: softmax(logits) minus the one-hot target."""
    p = softmax(logits)
    p[target] -= 1.0
    return p

Milestone 5: temperature, entropy and truncation

A language model's last layer produces one logit per vocabulary entry. To generate text you choose a token from the softmax of those logits, and three controls shape the choice (A2, chapter 15 treats them as decoding strategies; here you build the arithmetic). Temperature T divides the logits before the softmax: pi = softmax(z/T)i. For T below 1 the largest logits pull further ahead and the distribution sharpens; for T above 1 it flattens; as T tends to 0 it approaches the arg-max, and as T grows the logits stop mattering and it tends to uniform. Top-k keeps only the k most probable tokens, zeroes the rest and renormalises. Top-p (nucleus sampling; Holtzman et al., 2019, The Curious Case of Neural Text Degeneration) keeps the smallest set of most probable tokens whose probabilities add up to at least p, a set whose size adapts to how confident the model is: two tokens when the model is sure, hundreds when it is not.

To describe how much choice is left, chapter 14 uses the entropy H(p) = −∑ pi log pi, the average surprise in bits when the logarithm has base 2, and the perplexity 2H, the effective number of equally likely options. A uniform distribution over 8 tokens has entropy 3 bits and perplexity 8; a distribution that puts all its mass on one token has entropy 0 and perplexity 1. Terms with pi = 0 contribute nothing (0 log 0 = 0), which the code has to say explicitly. The figure sweeps the temperature on the chapter's six example logits.

Common misconception

"Temperature 0 means no randomness, so the API should accept T = 0." Dividing by zero is undefined, and the limit of the softmax as T tends to 0 is the arg-max, so APIs that accept 0 treat it as a special case: greedy decoding. Your softmax_t raises ValueError for T ≤ 0 and is stable for T = 0.001 (where the scaled logits are in the thousands, the situation milestone 4 prepared you for). Note also that greedy decoding is not guaranteed to give the same text on every run: parallel hardware sums floating-point numbers in orders that can vary, and two logits that are nearly tied can swap places (chapter 11).

def softmax_t(logits, temperature=1.0):
    """softmax(logits / T). Raise ValueError unless temperature > 0. Must be stable for T = 0.001."""
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    return softmax([z / temperature for z in logits])

def entropy(p, base=2.0):
    """H(p) = - sum_i p_i log(p_i) in the given base (2 = bits). Terms with p_i = 0 contribute 0."""
    h = 0.0
    for x in p:
        if x > 0:
            h -= x * math.log(x)
    return h / math.log(base)

def perplexity(p, base=2.0):
    """The effective number of choices: base ** entropy(p, base). Equal to e ** (entropy in nats)."""
    return base ** entropy(p, base)

def top_k(p, k):
    """Keep the k most probable entries (ties go to the lower index), zero the rest, renormalise.
    Raise ValueError unless k >= 1. If k >= len(p) nothing changes."""
    if k < 1:
        raise ValueError("k must be at least 1")
    order = sorted(range(len(p)), key=lambda i: (-p[i], i))[:k]
    keep = set(order)
    return normalise([x if i in keep else 0.0 for i, x in enumerate(p)])

def top_p(p, nucleus):
    """Nucleus sampling: keep the smallest set of most probable entries (ties to the lower index)
    whose total probability is at least `nucleus`, zero the rest, renormalise.
    Raise ValueError unless 0 < nucleus <= 1."""
    if not 0 < nucleus <= 1:
        raise ValueError("nucleus must be in (0, 1]")
    order = sorted(range(len(p)), key=lambda i: (-p[i], i))
    keep, total = set(), 0.0
    for i in order:
        keep.add(i)
        total += p[i]
        if total >= nucleus:
            break
    return normalise([x if i in keep else 0.0 for i, x in enumerate(p)])

def sample_token(rng, logits, temperature=1.0, k=None, p=None):
    """One next-token draw: softmax with temperature, then top-k (if k), then top-p (if p), then a
    categorical draw with sample_categorical. Returns the index."""
    probs = softmax_t(logits, temperature)
    if k is not None:
        probs = top_k(probs, k)
    if p is not None:
        probs = top_p(probs, p)
    return sample_categorical(rng, probs)

Milestone 6: cross-entropy, KL, its estimators and the leash

The last milestone assembles the quantities of chapter 14. The cross-entropy H(p, q) = −∑ pi log qi is the average surprise of a model q on data that really come from p; it is the training loss of chapter 13 estimated from a sample. The KL divergence KL(p ‖ q) = ∑ pi log(pi/qi) is the part of it that the model could in principle remove: H(p, q) = H(p) + KL(p ‖ q). It is never negative (Gibbs' inequality), it is zero only when q = p, it is not symmetric, and it is infinite if q gives probability 0 to something p allows. Estimating KL from samples

For a language model the exact KL(π ‖ πref) at one position is a sum over a vocabulary of 100,000 tokens, and over a whole reply it is an expectation over an astronomical number of sequences. Training code instead samples a token x from the current policy π (which was generating it anyway), looks up both models' log-probabilities for that token, and averages. John Schulman's note Approximating KL Divergence (2020) compares three single-sample estimators. Write r = πref(x)/π(x). Then

  • k1 = −ln r = ln(π/πref). Unbiased: its expectation under π is exactly the KL. But it is negative for many individual samples, even though the KL is positive, so it has high variance.
  • k2 = (ln r)2/2. Never negative and lower variance, but slightly biased.
  • k3 = (r − 1) − ln r. Unbiased and never negative. It is k1 plus the term r − 1, which has expectation zero under π because ∑x π(x)(πref(x)/π(x) − 1) = ∑ πref − ∑ π = 1 − 1 = 0, and which is negatively correlated with k1, so adding it cancels noise. Geometrically, it is the gap between the curve ln r and its tangent line at r = 1, which is why it cannot be negative.

That expectation argument can be checked exactly, with no sampling noise, by enumerating the five tokens of a small vocabulary and weighting each estimator by π(x); check.py does so and demands that k1 and k3 reproduce the exact KL to 12 digits while k2 does not. The KL leash in closed form

Reinforcement learning from human feedback tunes a policy π to maximise a reward r(y) while a penalty keeps it near the reference model: maximise Ey∼π[r(y)] − β KL(π ‖ πref). The coefficient β sets how long the leash is. For a small set of candidate replies this has an exact solution, derived in chapter 14 with a Lagrange multiplier for the constraint ∑π = 1:

π*(y) = πref(y) · exp(r(y)/β) / Z,    Z = ∑y πref(y) exp(r(y)/β).

The optimal policy is the reference reweighted by the exponentiated reward, so leash_policy is a softmax of the logits ln πref(y) + r(y)/β, which means your milestone-4 function does the work and the stable form is free. A small enough β makes r/β huge (5,000 at β = 0.001 for a reward of 5), and the naive form overflows exactly as it did in milestone 4. The check also confirms the property that A3's DPO derivation rests on: taking logs, β ln(π*(y)/πref(y)) = r(y) − β ln Z, so the reward equals β times the log-ratio plus a constant that is the same for every reply. A model's log-ratio to its reference is a reward, up to that constant, which is what lets DPO train on preference pairs without a separate reward model.

def xent(p, q, base=2.0):
    """The cross-entropy H(p, q) = - sum_i p_i log(q_i): the average surprise of model q on data from p.
    Terms with p_i = 0 are skipped. If p_i > 0 and q_i = 0 the answer is math.inf."""
    total = 0.0
    for a, b in zip(p, q):
        if a > 0:
            if b <= 0:
                return math.inf
            total -= a * math.log(b)
    return total / math.log(base)

def kl(p, q, base=2.0):
    """KL(p || q) = sum_i p_i log(p_i / q_i), the extra cost of coding data from p with a model q.
    Terms with p_i = 0 are skipped. If p_i > 0 and q_i = 0 the answer is math.inf."""
    total = 0.0
    for a, b in zip(p, q):
        if a > 0:
            if b <= 0:
                return math.inf
            total += a * math.log(a / b)
    return total / math.log(base)

def kl_estimators(logp, logp_ref):
    """The three single-sample estimators of KL(pi || ref) (Schulman, 2020) for a token x drawn from pi.

    logp = ln pi(x), logp_ref = ln ref(x). With the ratio r = ref(x) / pi(x):
        k1 = -ln r,   k2 = (ln r)^2 / 2,   k3 = (r - 1) - ln r.
    Returns (k1, k2, k3). Example: logp = ln 0.5, logp_ref = ln 0.25 gives r = 0.5 and
    (0.6931, 0.2402, 0.1931).
    """
    log_r = logp_ref - logp
    r = math.exp(log_r)
    return -log_r, 0.5 * log_r * log_r, (r - 1.0) - log_r

def estimate_kl(rng, pi, ref, n):
    """Estimate KL(pi || ref) in nats from n tokens sampled from pi (use sample_categorical).

    Returns {"k1": (mean, sd), "k2": (mean, sd), "k3": (mean, sd)}: the mean and the sample standard
    deviation (dividing by n - 1) of each estimator over the n draws.
    """
    log_pi = [math.log(x) if x > 0 else -math.inf for x in pi]
    log_ref = [math.log(x) if x > 0 else -math.inf for x in ref]
    cols = ([], [], [])
    for _ in range(n):
        x = sample_categorical(rng, pi)
        for col, v in zip(cols, kl_estimators(log_pi[x], log_ref[x])):
            col.append(v)
    out = {}
    for name, col in zip(("k1", "k2", "k3"), cols):
        mean = sum(col) / n
        out[name] = (mean, math.sqrt(sum((v - mean) ** 2 for v in col) / (n - 1)))
    return out

def leash_policy(ref, reward, beta):
    """The policy that maximises  E_pi[reward] - beta * KL(pi || ref):  pi*(y) = ref(y) exp(reward(y) / beta) / Z.

    Must not overflow for beta = 0.001 (subtract the largest exponent before exponentiating).
    Returns a list of probabilities summing to 1. Entries with ref = 0 stay at 0.
    """
    expo = [(math.log(r) + w / beta) if r > 0 else -math.inf for r, w in zip(ref, reward)]
    return softmax(expo)

Systems connection

The functions you wrote are the last stage of every inference request: a serving engine runs the model, applies temperature and truncation to a logit vector of vocabulary size, and draws a token with a per-request seed. Three engineering habits follow from this lab. Store log-probabilities, not probabilities: they do not underflow, they add across a sequence, and they are what evaluation and KL-penalty code consumes. Make randomness replayable: record the seed and the sampler settings with each request, the same discipline that chapter 4 applies to experiments, so that a bad generation can be reproduced from a trace (A6, chapter 17). And treat sampling parameters as part of the interface: a change of default temperature changes the distribution of outputs for every user at once, which is the kind of change that deserves a canary rollout (reliability, chapter 12).

What you learned

  • Every sampler is a transformation of uniform numbers: invert the cdf, walk the cumulative sums, change variables (Box–Muller) or accept and reject. Test it with scripted randomness for exactness and with seeded draws at five standard errors for correctness.
  • Work with log-likelihoods: they are sums, they do not underflow, and their maximiser is the maximum-likelihood estimate. The MLE of a probability is a frequency; the MLE of a Gaussian variance divides by n and is biased low by (n − 1)/n.
  • Squared error is Gaussian maximum likelihood: gradient descent on the NLL and the normal equations give the same line, and the fitted noise level is the root-mean-square residual.
  • Softmax is shift-invariant, so subtract the maximum; compute losses from log_softmax and never from a probability; the gradient of the loss with respect to the logits is the probabilities minus the one-hot target.
  • Temperature is a dial on entropy; top-k and top-p cut the tail; the nucleus is the smallest set whose mass reaches p.
  • H(p, q) = H(p) + KL(p ‖ q). KL is asymmetric and infinite when support is missing. Estimate it from samples with k3, which is unbiased and never negative; the KL-regularised optimum is the reference reweighted by exp(reward/β).

Your exponential sampler receives the uniform draw u = 0.5 with rate λ = 2. What should it return?

  2. About 0.347, which is −ln(1 − 0.5) / 2

Inverting F(x) = 1 − e−2x gives x = −ln(1 − u)/2, and with u = 0.5 that is ln 2 / 2 = 0.3466. Since u = 0.5 is the median of the uniform, the answer is the median of the exponential, below its mean of 0.5 because the distribution is skewed. The fourth option multiplies by the rate instead of dividing, a common slip that makes a high-rate (short-wait) distribution produce long waits.

You use rejection sampling with a uniform proposal on [0, 1] for a density that is 20 on the interval [0.475, 0.525] and 0 elsewhere, with bound M = 20. About how many proposals are needed per accepted sample?

  1. About 2, because the density is mostly concentrated
  2. About 5, because the interval is 5% of the box
  3. About 40, because both the proposal and the acceptance test have to succeed
  4. About 20, because each proposal is accepted with probability 1/M = 5%
The density integrates to 1 (20 × 0.05), so the area under it is 1 and the box has area M = 20; the acceptance probability is 1/M. Equivalently only the 5% of proposals that land in the interval can be accepted, and there they are always accepted. A narrow density is the weakness of this method, and it is worse in many dimensions.

You estimate the variance of a Gaussian with true variance 8 from many independent samples of n = 4 points, dividing the sum of squared deviations by n. What is the average of your estimates?

  4. 10.67, because dividing by n instead of n − 1 inflates the estimate
The deviations are measured from the sample mean, which was fitted to the same four points and is therefore closer to them than the true mean is. A classifier has logits (2, 1, 0) and the true class is 0. What does the gradient of the cross-entropy loss with respect to the logit of class 2 (the last one, probability 0.090) equal?

  1. −0.090, so that gradient descent raises that logit
  2. +0.910, one minus its probability
  3. +0.090, so that gradient descent lowers that logit
  4. 0, because class 2 is not the true class and does not enter the loss
The gradient is p − one-hot. For a wrong class the one-hot entry is 0, so the gradient is just the class's probability, +0.090, and a descent step lowers its logit in proportion to how much probability it wrongly holds. Every logit appears in the loss, through the normaliser, so the fourth option is wrong: the loss falls when probability mass leaves the wrong classes. For the true class it is 0.665 − 1 = −0.335, and the three gradients sum to zero.

A training run estimates KL(π ‖ πref) on each batch by averaging −ln r over sampled tokens (k1), and a few batches report a negative KL. What should you conclude?

  1. The policy has drifted below the reference, which is possible and good
  2. There is a bug, because KL divergence can never be negative
  3. The batches are too large, and a smaller batch would fix it
  4. Nothing is wrong: k1 is unbiased but has high variance, so small-batch averages can dip below 0. Switching to k3 removes the problem
The true KL is non-negative, but k1 is the log-ratio of a single sampled token, which is negative for many tokens, and its average over a small batch can be negative by chance when the true KL is small. In the lab's example one sample has a standard deviation of 0.26 against a KL of 0.037. The estimator is unbiased, so nothing is systematically wrong; k3 = (r − 1) − ln r is also unbiased, is never negative and has a spread about four times smaller. Smaller batches make the noise worse, not better. And the first option's idea of a policy "below" the reference has no meaning: KL measures distance in one direction and is never negative.
