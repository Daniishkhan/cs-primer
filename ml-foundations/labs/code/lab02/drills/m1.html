To differentiate a computation, you need to know how each number was made. So use numbers that remember: every operation returns a new number that records its parents (the operand objects themselves, not copies) and a short label. That record is the computation graph, built as a side effect of ordinary arithmetic. Walking it backwards gives the gradients.

  • The class is Value. a + b calls a.__add__(b). For 3 + a the integer gives up and Python falls back to the reflected form a.__radd__(3), so both are needed. A plain-number operand is wrapped in Value(...) first, as a node with no parents.
  • The result's _parents is (self, other) and its _op is "+" or "*".
  • Everything else is built from these two: negation multiplies by −1, subtraction adds the negation, and the reflected forms swap operands.
c = Value(2) * Value(3) + 2
c.data == 8.0, c._op == "+", c._parents[1].data == 2.0
