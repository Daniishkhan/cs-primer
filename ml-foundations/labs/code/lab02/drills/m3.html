Each new operation is a forward value plus a local derivative (how the result changes with one input). Its backward rule multiplies that by the gradient arriving from above (the chain rule) and adds it to the input. The docstrings give every local derivative. The new idea is the gradient check: nudge an input up and down by a tiny step h and divide the change in output by 2h. That slope needs no calculus rules, so it can audit the engine.

  • numerical_grad nudges one input at a time, calling f on fresh Values built from the floats. autograd_grad calls f once on fresh Values, then backward().
  • A smaller h is not always better: rounding error grows like 1/h while the step error shrinks like h squared, so EPS = 1e-6 sits near the bottom of a V.
  • max_error divides each difference by at least 1, so tiny gradients compare absolutely and large ones relatively.
max_error([1000, 0.001], [1001, 0.002]) = 0.001
below about 1e-6 the gradients agree; above 1e-3 there is a bug
