Lab 1: A Small Linear Algebra Library

Chapters 5, 6 and 7 showed you dot products, matrices as functions, Gram–Schmidt, eigenvectors and PCA, and NumPy did the arithmetic. In this lab you do the arithmetic yourself: a library of about twenty functions over plain Python lists, from dot to a working PCA, tested against hand-computed values, against mathematical identities and against the numerical traps that real libraries are built to avoid.

Why this lab matters

Almost everything later in the path is linear algebra wearing a costume. An embedding search is a cosine over millions of vectors, a neural-network layer is a matrix product, LoRA is a low-rank update, and PCA, PageRank and the singular value decomposition are all "find the dominant direction of a matrix". If those are black boxes, every shape error and every nan is a mystery. Once you have written matmul and seen it reject a (2, 3) times (2, 2) with a message that names both shapes, shape errors in PyTorch read like plain English.

The second reason is numerics. The three bugs this lab is designed to catch are all invisible on friendly inputs: a norm that overflows on large numbers, a Gram–Schmidt that quietly loses orthogonality, and a power iteration that never converges when two eigenvalues tie. You meet each one on purpose, in a test that fails with an explanation.

Pure Python, deterministic, fast

Standard library only: no NumPy, no installs, Python 3.9 or newer. Nothing uses the clock or the network. The random inputs in check.py come from seeded generators, and a failure prints its seed so you can replay it: python3 check.py solution 4 7 runs milestone 4 on seed 7 only. The checks compare your answers with independent plain-loop versions written inside check.py, never with your own code, and the whole run takes a fraction of a second.

What you'll build

Vectors are Python lists of floats. Matrices are lists of rows, so A[i][j] is the entry in row i, column j, and shapes are written (rows, cols) exactly as NumPy writes them. The notation matches the chapters: vectors are lowercase (x, w), matrices uppercase (A, B), and AT is the transpose.

  1. Vectors: add, sub, scale, dot, an overflow-safe norm, normalise, cosine and project, with errors for mismatched lengths and zero vectors.
  2. Matrices: identity, transpose, matvec and matmul, with shape checks whose error messages show both shapes.
  3. Gram–Schmidt and QR: an orthonormal basis for any list of vectors (dependent ones dropped), then the QR factorisation, checked on a case where the textbook version fails.
  4. Power iteration and PageRank: the dominant eigenpair by repeated multiplication, its failure modes, and PageRank for a small web graph.
  5. Deflation and PCA: the top k eigenpairs of a symmetric matrix, the covariance matrix of a data set, and a PCA that reconstructs the data from k directions.

Milestone 1: vectors

You met these operations in chapter 5. Addition, subtraction and scaling work entry by entry. The dot product x · y is the sum of xi yi, the norm |x| = √(x · x) is the length of the arrow, and the cosine of the angle between x and y is x · y / (|x| |y|), which ignores length and keeps direction.

Two design decisions make this more than transcription. First, shapes are contracts: dot([1, 2], [1]) should raise ValueError("length mismatch: 2 vs 1"), not silently use the shorter list as zip would. A function that fails loudly at the wrong shape is worth more than one that returns a plausible wrong number. Second, degenerate inputs get a decision: the zero vector has no direction, so normalise and cosine must refuse it, and project onto the zero vector divides by zero, so it refuses too.

The projection of x onto the line through w is the vector

projw(x) = ((x · w) / (w · w)) w

and what is left, x − projw(x), is perpendicular to w. For x = (3, 4) and w = (2, 0): x · w = 6, w · w = 4, so the projection is 1.5 w = (3, 0) and the leftover is (0, 4). Note that the answer does not depend on the length of w, only on its direction; check.py tests exactly that.

Common misconception

"The norm is math.sqrt(sum(a * a for a in x)), there is nothing to get wrong." That one-liner is correct for small numbers and wrong for large ones. Python floats overflow near 1.8 × 10308, so squaring 3 × 10200 gives inf even though the length of (3×10200, 4×10200) is a perfectly representable 5 × 10200. Tiny numbers fail the other way: squares underflow to 0. The fix is the trick behind a stable softmax in chapter 11: divide by the largest absolute entry first, take the length of the scaled vector, multiply back.

def _same_length(x, y):
    """GIVEN: raise ValueError if two vectors differ in length. Use it in add, sub, dot."""
    if len(x) != len(y):
        raise ValueError(f"length mismatch: {len(x)} vs {len(y)}")

def add(x, y):
    """x + y, entry by entry. Different lengths raise ValueError."""
    _same_length(x, y)
    return [a + b for a, b in zip(x, y)]

def sub(x, y):
    """x - y, entry by entry. Different lengths raise ValueError."""
    _same_length(x, y)
    return [a - b for a, b in zip(x, y)]

def scale(c, x):
    """c * x: every entry multiplied by the number c."""
    return [c * a for a in x]

def dot(x, y):
    """The dot product: the sum of x[i] * y[i]. Different lengths raise ValueError."""
    _same_length(x, y)
    return sum(a * b for a, b in zip(x, y))

def norm(x):
    """The Euclidean length sqrt(x . x).

    Must not overflow for entries like 3e200 (squaring them gives inf): divide by the
    largest absolute entry first, take the length, and multiply back.
    """
    m = max((abs(a) for a in x), default=0.0)
    if m == 0.0:
        return 0.0
    return m * math.sqrt(sum((a / m) ** 2 for a in x))

def normalise(x):
    """x scaled to length 1. The zero vector has no direction: raise ValueError."""
    n = norm(x)
    if n == 0.0:
        raise ValueError("cannot normalise the zero vector")
    return scale(1.0 / n, x)

def cosine(x, y):
    """cos(angle between x and y) = x . y / (|x| |y|). A zero vector raises ValueError."""
    _same_length(x, y)
    nx, ny = norm(x), norm(y)
    if nx == 0.0 or ny == 0.0:
        raise ValueError("cosine is undefined for the zero vector")
    c = dot(x, y) / (nx * ny)
    return max(-1.0, min(1.0, c))          # rounding can push 1.0 up to 1.0000000000000002

def project(x, w):
    """The projection of x onto the line through w: ((x . w) / (w . w)) w. Zero w raises ValueError."""
    _same_length(x, w)
    ww = dot(w, w)
    if ww == 0.0:
        raise ValueError("cannot project onto the zero vector")
    return scale(dot(x, w) / ww, w)

Milestone 2: matrices

A matrix is a table and a function (chapter 6). As a table, a (m, n) matrix is a list of m rows each of length n. As a function, it takes a length-n vector to a length-m vector: output entry i is the dot product of row i with the input. That is matvec, and it is one line once you have dot.

Matrix multiplication is the same idea applied to every column of B at once. For A of shape (m, n) and B of shape (n, p), the product AB has shape (m, p), and its entry (i, j) is the dot product of row i of A with column j of B. Your lists store rows, so to get columns you transpose B first: the rows of BT are the columns of B. The inner dimensions must agree, and when they do not the error should say exactly what went wrong:

ValueError: cannot multiply (2, 3) by (2, 2): inner dimensions 3 and 2 differ

Three facts are worth seeing in your own code. Multiplication is associative but not commutative: (AB)C = A(BC), but AB and BA differ (and may not even both exist). It is linear: A(cx + y) = c Ax + Ay, which is the defining property of the functions matrices represent. And the transpose reverses the order: (AB)T = BTAT. All three are in the check as properties on random matrices.

Associativity matters for cost, not for the answer. For 20×20 matrices A and B and a vector v, computing (AB)v costs 20³ = 8,000 multiplications for the product plus 400 for the matrix–vector step, 8,400 in all; computing A(Bv) costs 400 + 400 = 800. Same result, ten times less work. The same ordering argument is why LoRA (A3, chapter 11) keeps its update as two thin factors instead of one big matrix.

Solution spoiler 
def identity(n):
    """The (n, n) identity matrix: 1 on the diagonal, 0 elsewhere."""
    return [[1.0 if i == j else 0.0 for j in range(n)] for i in range(n)]

def transpose(A):
    """A^T: the (cols, rows) matrix whose entry (j, i) is A[i][j]."""
    rows, cols = shape(A)
    return [[A[i][j] for i in range(rows)] for j in range(cols)]

def matvec(A, x):
    """A x for a (m, n) matrix and a length-n vector: a length-m vector, each entry a row . x."""
    rows, cols = shape(A)
    if cols != len(x):
        raise ValueError(f"cannot multiply {(rows, cols)} by a vector of length {len(x)}: "
                         f"inner dimensions {cols} and {len(x)} differ")
    return [dot(row, x) for row in A]

def matmul(A, B):
    """A B for (m, n) and (n, p): the (m, p) matrix with entry (i, j) = row i of A . column j of B.

    Mismatched inner dimensions raise ValueError whose message shows both shapes.
    """
    m, n = shape(A)
    n2, p = shape(B)
    if n != n2:
        raise ValueError(f"cannot multiply {(m, n)} by {(n2, p)}: inner dimensions {n} and {n2} differ")
    Bt = transpose(B)                      # rows of B^T are columns of B
    return [[dot(row, col) for col in Bt] for row in A]

Milestone 3: Gram–Schmidt and QR

Given a list of vectors, can you replace it with an orthonormal list (every vector length 1, every pair perpendicular) that spans the same space? Gram–Schmidt does it with the projection you already wrote. Take the vectors in order. For each one, subtract its projection onto every basis vector found so far; what remains is, by construction, perpendicular to all of them. If anything is left, scale it to length 1 and add it to the basis.

Two details decide whether your version is any good.

Dependent vectors. If a vector already lies in the span of the earlier ones, subtracting its projections leaves (almost) nothing. "Almost" is the problem: floating-point error leaves a speck of 10−17, and normalising a speck gives a confident, meaningless unit vector. So compare the remainder's length with the original's, and if it is below a tolerance (RANK_TOL = 1e-10, as a fraction of the original), skip the vector. Five vectors that span only three dimensions should produce three basis vectors.

Classical versus modified. The textbook formula subtracts the projections of the original vector v onto each q. The modified version subtracts them one at a time from the running remainder: r ← r − (r · q)q. In exact arithmetic they are identical. In floating point they are not, whenever vectors are nearly parallel, because the classical version never notices the rounding error left behind by the first subtraction. Try the classic test, three vectors (1, e, 0, 0), (1, 0, e, 0), (1, 0, 0, e) with e = 10−8:

def classical(vectors):
    basis = []
    for v in vectors:
        r = list(v)
        for q in basis:
            r = sub(r, scale(dot(v, q), q))      # projects the ORIGINAL v each time
        basis.append(normalise(r))
    return basis
# ... then compare it with your gram_schmidt on those three vectors
classical worst |q_i . q_j| = 5.0e-01
modified  worst |q_i . q_j| = 7.1e-09

The "orthonormal" basis from the classical version has two vectors with a dot product of 0.5, which is 60 degrees apart, nowhere near perpendicular. The modified version is off by 10−8, which is the best a double can do here. A change of one variable name is the whole difference, and nothing but a test on nearly dependent input would ever reveal it. check.py has that test.

QR. Run Gram–Schmidt on the columns of A and record what you subtracted. Each column is a combination of the basis vectors, aj = ∑i (qi · aj) qi, and that sentence is a matrix equation A = QR: Q has the qi as columns, and Rij = qi · aj for i ≤ j (zero below the diagonal, since aj only involves the first j basis vectors). R is upper triangular, which is what makes solving linear systems with it cheap; QR is a standard route to least-squares solutions in numerical libraries. The projection onto the span of Q's columns is QQT, the same idea as the residual in the regression of chapter 5.

def gram_schmidt(vectors, tol=RANK_TOL):
    """An orthonormal list spanning the same space as `vectors` (modified Gram-Schmidt).

    For each vector v in turn: subtract its projection onto every basis vector found so
    far, ONE AT A TIME, updating v after each subtraction. If what is left is shorter than
    tol times the original length, v was (numerically) dependent on the earlier ones: skip
    it. Otherwise normalise it and append it to the basis.
    """
    basis = []
    for v in vectors:
        original = norm(v)
        if original == 0.0:
            continue
        r = list(v)
        for q in basis:
            r = sub(r, scale(dot(r, q), q))      # uses the UPDATED r: this is the 'modified' part
        if norm(r) <= tol * original:
            continue
        basis.append(normalise(r))
    return basis

def qr(A):
    """The QR factorisation of a (m, n) matrix with m >= n and independent columns.

    Returns (Q, R): Q is (m, n) with orthonormal columns, R is (n, n) upper triangular,
    and Q R = A. Dependent columns raise ValueError.
    """
    m, n = shape(A)
    cols = transpose(A)
    Q_cols = gram_schmidt(cols)
    if len(Q_cols) < n:
        raise ValueError(f"columns are dependent: rank {len(Q_cols)} < {n}")
    # R[i][j] = q_i . a_j for i <= j, and 0 below the diagonal
    R = [[dot(Q_cols[i], cols[j]) if i <= j else 0.0 for j in range(n)] for i in range(n)]
    return transpose(Q_cols), R

Milestone 4: power iteration and PageRank

Chapter 7 showed that repeated multiplication by a matrix pulls any starting vector towards the eigenvector with the largest eigenvalue (in absolute value). Write the start as a combination of eigenvectors; after k steps each piece has been multiplied by its eigenvalue k times, so the biggest eigenvalue's piece dominates. Power iteration turns that into an algorithm: repeat w = Av, then v = w / |w| (renormalising so the numbers do not overflow). Then v approaches the dominant eigenvector, and the Rayleigh quotient v · Av / (v · v) approaches the dominant eigenvalue.

The interesting part is deciding when to stop, and what to do when it cannot.

  • The stopping rule. Stop when the residual |Av − λv| is tiny, measured relative to the size of λ. It works for any sign of λ. A rule that waits for v itself to stop changing fails when the dominant eigenvalue is negative, because v flips sign on every step. check.py tests diag(−3, 1).
  • The convergence rate. The second-largest component shrinks by the ratio |λ2/λ1| each step. For [[4, 1], [2, 3]] that is 2/5 = 0.4: about 25 steps to reach 10−10. When the top two eigenvalues are close it takes far longer:
for A in ([[2.0, 0.0], [0.0, 1.0]], [[2.0, 0.0], [0.0, 1.5]], [[2.0, 0.0], [0.0, 1.98]]):
    lam, v, it = power_iteration(A, v0=[1.0, 1.0])
    print(f"diag(2, {A[1][1]:<4}) ratio {A[1][1] / 2:.2f}: eigenvalue {lam:.6f} after {it:4d} iterations")
try:
    power_iteration([[0.0, 1.0], [1.0, 0.0]], [1.0, 0.3], max_iter=500)
except RuntimeError as e:
    print("swap matrix:", e)
diag(2, 1.0 ) ratio 0.50: eigenvalue 2.000000 after   34 iterations
diag(2, 1.5 ) ratio 0.75: eigenvalue 2.000000 after   77 iterations
diag(2, 1.98) ratio 0.99: eigenvalue 2.000000 after 1834 iterations
swap matrix: power iteration did not converge in 500 iterations

The last line is the other failure. The swap matrix [[0, 1], [1, 0]] has eigenvalues +1 and −1, equal in size, so neither wins; the vector just flips between two states for ever. A robust function stops after max_iter steps and raises RuntimeError rather than looping or returning a wrong answer with confidence. The third edge case is a start vector with no component along the dominant eigenvector, such as (0, 1) for diag(1, 0): then Av is the zero vector and you must return eigenvalue 0 rather than divide by zero. That is why default_start (given) is a fixed but irregular vector.

PageRank is power iteration on the web. Model a reader who, with probability d = 0.85 (the damping factor), follows a random link on the current page, and otherwise jumps to a page chosen uniformly. Page j's long-run share of visits is its rank. Build the column-stochastic matrix M with M[j][i] = 1/(links out of i) for each link i→j, so each column sums to 1; form G = d·M + (1 − d)/n in every entry; the rank vector is the dominant eigenvector of G, whose eigenvalue is exactly 1. A page with no outgoing links is a dead end that would leak probability, so treat it as linking to every page. Rescale the unit-length eigenvector so it sums to 1 and it is a probability distribution. The method comes from Brin and Page (1998), "The Anatomy of a Large-Scale Hypertextual Web Search Engine".

def rayleigh(A, v):
    """The Rayleigh quotient v . (A v) / (v . v): the best single-number guess for an eigenvalue."""
    return dot(v, matvec(A, v)) / dot(v, v)

def power_iteration(A, v0=None, tol=1e-10, max_iter=10_000):
    """The dominant eigenpair of a square matrix by repeated multiplication.

    Start from v0 (default_start(n) if None), normalised. Repeat: w = A v; v = w / |w|.
    Stop when the residual |A v - lam v| is below tol * max(1, |lam|), with lam the Rayleigh
    quotient of v. Returns (lam, v, iterations), v of length 1 with its largest entry positive.

    - If A v is the zero vector, v lies in the null space: return (0.0, v, iterations).
    - If it has not converged after max_iter steps (two eigenvalues of equal size, say),
      raise RuntimeError.
    - A non-square A raises ValueError.
    """
    n, cols = shape(A)
    if n != cols:
        raise ValueError(f"power iteration needs a square matrix, got {(n, cols)}")
    v = normalise(list(v0) if v0 is not None else default_start(n))
    for it in range(1, max_iter + 1):
        w = matvec(A, v)
        nw = norm(w)
        if nw == 0.0:
            return 0.0, _fix_sign(v), it
        lam = dot(v, w)                                   # v has length 1, so this is the Rayleigh quotient
        residual = norm(sub(w, scale(lam, v)))
        if residual <= tol * max(1.0, abs(lam)):
            return lam, _fix_sign(v), it
        v = scale(1.0 / nw, w)
    raise RuntimeError(f"power iteration did not converge in {max_iter} iterations")

def pagerank(links, damping=0.85):
    """PageRank scores (summing to 1) for a web graph.

    links[i] is the list of pages that page i links to. A page with no links is a dead end
    and is treated as linking to every page. Build the column-stochastic matrix M with
    M[j][i] = 1/len(links[i]) for each link i -> j, form the Google matrix
    G = damping * M + (1 - damping)/n (every entry), and return its dominant eigenvector
    rescaled to sum to 1, using power_iteration.
    """
    n = len(links)
    M = [[0.0] * n for _ in range(n)]
    for i, outs in enumerate(links):
        targets = list(outs) if outs else list(range(n))   # dead end: spread evenly
        for j in targets:
            M[j][i] += 1.0 / len(targets)
    G = [[damping * M[j][i] + (1.0 - damping) / n for i in range(n)] for j in range(n)]
    lam, v, _ = power_iteration(G)
    total = sum(v)
    return [x / total for x in v]

Milestone 5: deflation and PCA

Power iteration finds one eigenpair. To find the next, remove the first from the matrix. For a symmetric A with eigenvalue λ and unit eigenvector v, the matrix A − λvvT has the same eigenvectors as A, except that v's eigenvalue has become 0. Power iteration on the deflated matrix then finds the next largest. Repeat k times to get the top k eigenpairs. The vvT term is the outer product (outer is given): an (n, n) matrix with entry vivj. Deflation is a teaching tool rather than production code, because each pass inherits the previous rounding error and repeated eigenvalues defeat it; real libraries use the QR algorithm or the SVD.

Now use it. PCA (chapter 7) finds the directions along which a data set varies most. Given a data matrix X of shape (n, d), one row per sample:

  1. Centre each column on its mean, giving Xc.
  2. Covariance: C = XcTXc / (n − 1), a symmetric (d, d) matrix. Dividing by n − 1 rather than n is the usual sample estimate; the check uses it.
  3. Eigenpairs of C, biggest first. The eigenvectors are the principal components: orthonormal directions in feature space. Each eigenvalue is the variance of the data along its direction.
  4. Reconstruct from k components: for each row, subtract the mean, take the coefficient cj = (x − mean) · qj on each component, and rebuild mean + ∑ cjqj.

A fact the check verifies on every seed: the mean squared reconstruction error after keeping k components equals the sum of the eigenvalues you dropped. Keep 2 of 3 components with variances 16, 2.4 and 0.18, and you lose 0.18 of the total 18.6. It is the PCA version of the best low-rank approximation of chapter 7, and the same statement, for the singular value decomposition, is what makes LoRA's low-rank updates sensible (A3, chapter 11).

A small example you can verify by hand: the points (1, 2), (2, 4), (3, 6) lie on the line y = 2x. Their mean is (2, 4), the covariance is [[1, 2], [2, 4]], the top eigenvalue is 1 + 4 = 5 with direction (1, 2)/√5 = (0.4472, 0.8944), and the second eigenvalue is 0: all the variance is in one direction. Common misconception

"Every PCA component is meaningful." When the data is exactly low-rank, as in the line above, the components after the real ones belong to a deflated matrix that is numerically zero, and power iteration returns an arbitrary direction there (the check only tests the variance of such a component, never its direction). Directions with tiny variance are noise to be dropped, not features to be explained; telling structure from noise is the subject of the last section of chapter 7.

Solution spoiler 
def covariance(X):
    """The sample covariance of data X, shape (n, d), one row per sample: a (d, d) matrix.

    Centre each column on its mean, then C = (X_c^T X_c) / (n - 1). Fewer than two rows raise ValueError.
    """
    n, d = shape(X)
    if n < 2:
        raise ValueError("covariance needs at least two samples")
    means = [sum(X[i][j] for i in range(n)) / n for j in range(d)]
    Xc = [[X[i][j] - means[j] for j in range(d)] for i in range(n)]
    S = matmul(transpose(Xc), Xc)
    return [[s / (n - 1) for s in row] for row in S]

def top_k_eigen(A, k):
    """The k largest eigenpairs [(lam, v), ...] of a symmetric matrix, biggest first, by deflation.

    Find the dominant pair with power_iteration, then subtract lam v v^T from the matrix so
    that eigenvalue is removed, and repeat on what is left.
    """
    n, _ = shape(A)
    if not 1 <= k <= n:
        raise ValueError(f"k must be between 1 and {n}")
    pairs = []
    B = [row[:] for row in A]
    for _ in range(k):
        lam, v, _ = power_iteration(B)
        pairs.append((lam, v))
        B = [[b - lam * o for b, o in zip(rb, ro)] for rb, ro in zip(B, outer(v, v))]
    return pairs

def pca(X, k):
    """Principal components of data X (n, d): returns (mean, components, variances).

    mean is the length-d column mean; components is a list of k orthonormal length-d vectors;
    variances is the list of the k largest eigenvalues of the covariance, biggest first.
    """
    n, d = shape(X)
    mean = [sum(X[i][j] for i in range(n)) / n for j in range(d)]
    pairs = top_k_eigen(covariance(X), k)
    return mean, [v for _, v in pairs], [lam for lam, _ in pairs]

def reconstruct(X, mean, components):
    """Project every row of X onto the components and map back: the best rank-k picture of X.

    For each row x: centre it, take the coefficient c_j = (x - mean) . components[j] for each
    component, and rebuild  mean + sum_j c_j components[j]. Returns a matrix shaped like X.
    """
    out = []
    for x in X:
        xc = sub(x, mean)
        r = list(mean)
        for q in components:
            r = add(r, scale(dot(xc, q), q))
        out.append(r)
    return out

Systems connection

Your matmul is a triple loop in an interpreter. On the machine used to write this lab, the reference matmul multiplied two 100×100 matrices in about 0.022 seconds (roughly 45 million multiply-adds a second), where NumPy took about 7 microseconds, and a GPU does trillions of multiply-adds a second by running the same arithmetic in parallel across thousands of cores with the data laid out so each core reads neighbouring memory. The chapters on parallelism and GPUs and performance engineering explain why that gap exists, and chapter 17 turns it into a cost estimate. The numerical traps (overflow in norm, lost orthogonality, ill-conditioning) do not go away on a GPU. They get worse as the number format gets smaller (chapter 11).

What you learned

  • A matrix is a list of rows; a product is dot products of rows with columns; shapes are contracts that deserve a loud error naming both shapes.
  • Identities such as (AB)T = BTAT, associativity and linearity are the best tests of linear algebra code, because they hold for every input.
  • The naive formula is often not the safe one: scale before squaring in norm, subtract from the running remainder in Gram–Schmidt.
  • Power iteration converges at the rate |λ2/λ1| per step, fails when two eigenvalues tie, and needs a residual-based stopping rule.
  • PCA is centring, a covariance matrix, its top eigenpairs and a projection; the error after k components is the sum of the eigenvalues you dropped.

Check your understanding

Your norm returns inf for the vector (3e200, 4e200), though its true length is 5e200. What is the right fix?

  1. Convert the entries to int first so Python's arbitrary-precision integers avoid overflow
  2. Return the sum of absolute values instead, because it is cheaper and close enough
  3. Divide every entry by the largest absolute entry, take the length of the scaled vector, and multiply the result back
  4. Use x ** 0.5 instead of math.sqrt, which has a larger range
The overflow happens in the squaring, before any square root, so changing the root changes nothing. Scaling by the largest entry keeps every squared term at most 1, and multiplying back restores the size. The sum of absolute values is a different quantity (the L1 norm), not an approximation of the Euclidean length; converting to int would lose the fractional part and is no help for 3e-200.

A has shape (4, 3) and B has shape (3, 5). Which statement about (AB)T is correct?

  1. It equals ATBT, with shape (3, 5)
  2. It equals BTAT, with shape (5, 4)
  3. It equals BTAT, with shape (4, 5)
  4. It does not exist, because A and B are not square
AB has shape (4, 5), so its transpose is (5, 4). The transpose reverses the order of a product: BT is (5, 3) and AT is (3, 4), and their product is (5, 4). ATBT would be (3, 4) times (5, 3), which does not even exist: the shapes catch the wrong order for free. Matrices need not be square to be multiplied, only to have matching inner dimensions.

Classical and modified Gram–Schmidt agree in exact arithmetic. On three nearly parallel vectors the classical version returns two "orthogonal" vectors with dot product 0.5. What is the difference in the code?

  1. Modified subtracts each projection from the running remainder (using the updated vector in every dot product); classical uses the original vector every time
  2. Modified normalises every vector before projecting; classical normalises only at the end
  3. Modified processes the vectors in reverse order, which reduces rounding error
  4. Modified uses double the precision, so it needs twice the memory
Both do the same amount of arithmetic in the same precision. The modified method computes each coefficient from the remainder after earlier subtractions, so it sees (and corrects) the rounding error left behind by them; the classical method computes every coefficient from the original vector and lets errors pile up undetected. Normalising early or reversing the order is not what differs.

Four symmetric matrices have these two largest-magnitude eigenvalues. For which does power iteration converge in the fewest steps?

  1. 5 and 4.5
  2. 5 and −4.9
  3. 3 and 2
  4. 5 and 1
The error shrinks by |λ2/λ1| per step: 0.9, 0.98, 0.667 and 0.2. The size of the top eigenvalue does not matter, only its gap in ratio to the next. The second option is tempting because its second eigenvalue is negative, but the sign is irrelevant: −4.9 is almost as big as 5 and slows convergence badly. With a ratio of exactly 1 in magnitude, the method would not converge at all.

PCA on a data set gives covariance eigenvalues 9, 4 and 1. You keep the top two components and reconstruct. What is the mean squared reconstruction error (with the same n − 1 divisor as the covariance)?

  1. 5
  2. 4
  3. 1
  4. 13
The error is the sum of the eigenvalues of the discarded directions: just 1. The variance explained by the kept components is 9 + 4 = 13, which is the opposite quantity (and 13 of 14 is 93% of the total). 5 is the sum of the two smallest eigenvalues, which would be the error if you kept only the weakest components.
