Security Engineering

Every system so far assumed its users were merely careless. This course assumes some of them are adversaries. You'll learn to model threats before writing code, use cryptography without inventing it, get authentication, sessions, OAuth and authorization right, recognise the bug classes behind most breaches (injection, XSS, SSRF, the supply chain), isolate tenants, protect personal data, and bring a security lens to every design review.

How to use this course

🔗 Builds on what you know

TLS from networking, isolation from containers, transactions from data systems, API design from architecture: this course shows how each one fails under attack.

🛡️ Defence first

Attacks are explained so you can recognise and prevent them. Every exercise runs against code on your own machine. Never test systems you don't own or have permission to test.

🧪 Break it, then fix it

Labs have you store passwords properly, build and break a token format, attack a simulated OAuth flow, write an authorization engine, exploit and fix injection bugs, and delete a tenant by destroying its key.
