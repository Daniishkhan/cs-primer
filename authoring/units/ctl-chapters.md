# Unit: ctl-chapters

Course: **A11 AI Control & Sandbox Security** (id `ctl`, folder `control/`), a new course serving Artifact 3 (evaluator-hardening kit). Status in the catalog: building.

## Course brief
A11 supplies the walls of **Artifact 3**: the evaluator lives outside the agent's write boundary, checker code is never visible to the proposer, tool results are typed and attested so an agent cannot author a "tests passed" log, egress is deny-by-default, and an offline transcript monitor reads what the loop did. Chapters: the threat model of a research loop (proposer against evaluator, the write boundary, what an agent with a key and a box can reach), deny-by-default egress and sandboxes (allowlists, an egress proxy, filesystem and resource limits; specialise A4 chapter 20 for a loop that runs for days rather than repeating it), attested tool results (typed envelopes, content hashes, signatures, the evaluator as a separate principal, hash-chained tamper-evident logs), monitoring transcripts offline (trusted and untrusted monitoring and audit budgets from Redwood Research's AI-control work; the edits to flag: tests, logs, timeouts, the checker), incident playbooks (kill switches, budget caps, rollback, disclosure). It builds on A4 chapters 19 (agent security) and 20 (sandboxes), A7 chapters 15-17 (evaluator hacking, held-out evaluation, safety of self-modifying systems), and A3 chapter 13 (reward hacking). Sources to fetch: OpenAI's post on the Hugging Face incident (roadmap: openai.com/index/hugging-face-incident-and-the-road-ahead/: verify it exists and what it says; if it cannot be fetched the case study must say so and rest on what can be verified), Greenblatt et al., AI Control (arXiv 2312.06942) and Redwood's later control papers, the Darwin Gödel Machine paper's objective-hacking appendix (arXiv 2505.22954), SpecBench (roadmap: arXiv 2605.21384: verify), the Reward Hacking Benchmark (roadmap: arXiv 2605.02964: verify), METR's June 2025 reward-hacking report.
