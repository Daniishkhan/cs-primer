# Legs: one program, one step per page

A **leg** is a build-along. One program grows for twenty steps from a real
dataset to a learning loop; each step is a page that asks for one function,
checked on the real data in the page. Leg 1 is `taxi/` ("From Five Rides to a
Learning Loop"): catalog track `"leg"`, chapters are its steps. This file is
the contract for writing a step page. The model pages are steps 1 to 4:
`taxi/chapters/01-a-guess.html` … `04-a-loss.html`. Copy their skeleton exactly.

## The files of a leg

| Path | What it is | Who edits it |
|---|---|---|
| `taxi/code/project.py` | The complete program, in step order. Banners `# ── Step N: title ───` open each step; `# drill` ends the `def` line of every function the learner writes. | The coordinator only. If a check or a function must change, say so in your report; do not edit it. |
| `taxi/code/check.py` | `python3 check.py N` checks step N against `project.py`; prints ✔ with real numbers, ✘ with what was expected, or "not implemented yet". | Coordinator only. |
| `taxi/code/rides.csv` | 6,367 real rides (seaborn's sample of the NYC TLC record, March 2019). | Nobody. |
| `taxi/code/drills/sNN.py` | Generated by `python3 authoring/build_leg.py taxi --verify`: the program up to step N with step N's drill functions stubbed. The page's workspace loads this file as `project.py`. | Generated; never by hand. |
| `taxi/code/drills/leg.json` | Per step: title, drill functions with signature and docstring, what the file already has. | Generated. |
| `taxi/code/torch/common.py` | Loads the same rides as tensors (`load_rides`, `design_matrix`, `targets`, `RIDES5`). | Coordinator. |
| `taxi/code/torch/stepNN.py` | "The library way": the step in PyTorch, run on the lab VM. | The step's author. |
| `taxi/chapters/NN-name.html` | The step page. File name and title come from `assets/js/catalog.js` (course `taxi`). | The step's author. |
| `assets/js/leg.js` | Mounts the workspace, opens the editor at the stub, marks the step done when `check.py N` passes. | Coordinator. |

## The page, section by section

Every step page has these `h2` sections, in this order, and nothing else.

1. **Where we are** (step 1 calls it "The rides"). The program as it stands and
   the real numbers it produces, in two or three sentences, then one runnable
   in-page cell (`pre.terminal data-title="name.py"` followed by its real
   `output` block). The cell is self-contained: standard library, data inlined
   (the five rides of `RIDES5` or a few hand-picked numbers), no file reads, no
   imports of `project.py`, under three seconds in browser Python. Invite one
   edit ("change 2.0 to 3.0 and run again").
2. **The wall.** The one thing the program cannot yet do, shown with a number
   from the real rides. One paragraph. Bold the sentence that names what is
   needed. Do not reveal the idea here.
3. **The idea.** The smallest concept that gets past the wall, in plain words:
   one `div.eq-display` with `data-tex` and an HTML fallback (at most two
   equations), and one `figure.diagram` SVG using the site's classes (`box`,
   `mono`, `f-*`, `fs-*`, `s-*`, `tc-*`, `t-sm`, `t-faint`, `line`,
   `line-dash`) with a `figcaption`. Define each new term once with
   `<span class="term">`. Say what the next steps will do with it, in one line.
4. **Your move.** One sentence per function, then the signature box: a
   `pre.terminal data-title="your move"` holding the `def` line(s) and
   docstring(s) copied verbatim from `project.py` (no bodies). Then one
   sentence about the workspace, then the workspace:
   ```html
   <div class="step-workspace" data-dir="../code/" data-step="N" data-files="check.py rides.csv"></div>
   ```
   (`data-files="check.py"` alone for steps 1 and 2; every later step needs
   `rides.csv`). Then one paragraph saying what the check verifies, then the
   real output of `cd taxi/code && python3 check.py N` as a
   `pre.terminal data-title="output"` block, verbatim. Then
   `details.deeper` **Hints** (two or three bullets, no code beyond a fragment)
   and `details.deeper` **Solution** (the reference body from `project.py`,
   in a plain `pre><code`, HTML-escaped).
5. **The library way.** One `details.deeper` whose summary is
   "The same step in PyTorch <span class="hint">run on the lab VM</span>":
   a sentence, the script as `pre.terminal data-title="torch/stepNN.py (PyTorch, run on the lab VM)"`
   (that title does not match the runner's `name.py` pattern, so the block is
   not runnable in the page), its real output block, and one closing
   paragraph that names what the library did for you. For steps 18 to 20,
   where PyTorch has no equivalent, the summary is "The real thing" and the
   box shows how the research loop of Artifact 1 does it, linking
   `research-eng/chapters/01-research-loop.html` and
   `research-eng/labs/lab-01-keep-or-revert.html`; quote only facts those
   pages already state.
6. **What you have now.** A `ul` of the functions the file holds after this
   step (the ones given marked "Given.", the learner's marked "<em>Yours.</em>"),
   then one paragraph: the real result in one sentence, the link to the course
   chapter that is the long version of the idea, and "Next step: …" in one line.

No quiz, no "Why this matters" box, no key-takeaways box, no state-of-play
box. The eyebrow, the table of contents, the complete button and the pager are
built by `main.js`. Target 600 to 1,000 words of prose.

## Real numbers only

- The check's output block is the verbatim output of `python3 check.py N` run
  in `taxi/code` on the complete program.
- The in-page cell's output block is the verbatim output of running that cell
  with `python3` (save it in your scratch directory first).
- The PyTorch block's output comes from the lab VM:
  `workbench/vm sync` then
  `workbench/vm ssh 'cd ~/zts/taxi/code && ~/lab/bin/python torch/stepNN.py'`.
  (Both need the sandbox off; `workbench/vm status` says whether the VM is
  running and `workbench/vm start` starts it.) Nothing runs on the Mac except
  standard-library Python.
- Any number stated in prose (a share, a loss, a weight) comes from one of
  those runs. Say "about" when you round.

## The PyTorch script

- Under 40 lines. `from common import …` for the data (it lives next to the
  script; run from `taxi/code` with `torch/` on the path as `common.py`'s
  docstring shows). `torch.manual_seed(0)` before anything random.
- Use `dtype=torch.float64` where the page compares the library's number with
  the learner's, so they agree to the printed digits. Print with two to four
  decimals; never dump raw floats.
- Mirror the step, not the whole leg: step 7 shows `loss.backward()` giving
  the same gradient as the learner's formula, step 8 `torch.optim.SGD`, step 14
  `torch.utils.data.random_split`, step 15 `nn.Sequential`, step 16
  `DataLoader`, step 17 the same five-seed loop with `torch.manual_seed`.

## Style

`authoring/guide.md` section 3 applies: British spelling, "artifact", no
em-dashes anywhere, no hype, every term defined once, numbers in prose only
when they change what the reader does. The voice is a colleague at the next
desk: short sentences, the problem before the concept, the concept before the
library. The reader has done the earlier steps and nothing else.

## Verify before you report

```
python3 authoring/check_page.py taxi/chapters/NN-name.html   # 0 errors, 0 warnings
grep -c "—" taxi/chapters/NN-name.html                       # 0
```

`check_page.py` knows a leg page: it insists on the workspace, the right
`data-step`, the files it names, the generated stub, and the three section
titles "Your move", "The library way" and "What you have now".
