Workbench 1: AIDE on One Task, CPU-Sized

Lab 1 compared a greedy climber with an AIDE-style tree on a toy, with a seeded editor standing in for the model. Here the editor is a real language model and the tree is the real aideml package. It writes and runs scikit-learn and LightGBM scripts on a house-price task on the lab VM. You measure how many nodes it finishes an hour, what a node costs, and whether five drafts beat one when both spend the same twenty nodes, scored on rows the agent never saw.

Why measure it

Chapter 2 describes the nodes and the selection rule, and chapter 5 says that budgets for research agents are stated in steps, minutes and dollars. A README gives you none of those. The number you need before planning Artifact 2, which will run an agent like this hundreds of times, is what one node costs and how long it takes. The second reason is that a search agent reports its own score. A node is one script the agent wrote and ran. The validation metric is the number the agent computes inside that script, on data it chose. The private score is what the same script's predictions get on 360 rows whose labels the agent never saw. The agent keeps the node with the best validation metric, so the gap between the two numbers is the lab's winner's curse, on a real agent.

What you need

  • Machine: the lab VM (lab machine): 16 vCPU and 64 GB, Ubuntu, no GPU. The scripts the agent writes are CPU-sized: gradient-boosted trees and linear models on 1,100 rows. A laptop with enough cores would also do, but the page was run on the VM.
  • Disk: about 3 GB for a fresh virtual environment (aideml pulls in PyTorch).
  • An OpenAI API key in OPENAI_API_KEY. Never print it, commit it or paste it into a notebook.
  • Time: about two hours with reading. A run of 20 nodes took 5 to 12 minutes on a quiet machine. The runs are independent, so start them together.
  • No GPU time. The spend is model credit; see the dated box below.

Predict before you run

A node is two model calls: one that writes the script (a plan and the code) and one that reads its output and reports the metric. The price of a call is its input tokens times the input rate plus its output tokens times the output rate:

cost per node = (nin × pin + nout × pout) / 1,000,000

Here n counts tokens and p is a price in dollars per million tokens. On 15 October 2026 OpenAI's pricing page listed gpt-5.4-mini at $0.75 per million input tokens and $4.50 per million output tokens (cached input $0.075), and gpt-5.4-nano at $0.20 and $1.25. The agent's prompts differ by node type. A draft sends the task and a data preview. An improve step also sends the previous code and a summary of every earlier node, so its prompt grows as the run goes on.

Your prediction

A three-node smoke test before the real runs gave a draft of 1,684 input and 794 output tokens. Take that as the starting point and decide: (1) the cost of a draft with gpt-5.4-mini; (2) the cost of an improve step late in a run, if the prompt has grown to about 5,000 input and 1,600 output tokens; (3) nodes per hour on a quiet 16-core machine; (4) whether five drafts beat one on the private score after 20 nodes.

Check my arithmetic and my reasoning

A draft: (1,684 × 0.75 + 794 × 4.5) / 106 = (1,263 + 3,573) / 106 = $0.0048. The smoke test's own meter said $0.00484. A late improve step: (5,000 × 0.75 + 1,600 × 4.5) / 106 = $0.0109. So I expected $0.005 to $0.011 a node, and about $0.15 to $0.25 for twenty. The output tokens dominate: they are six times the price and, for a reasoning model, include its hidden thinking.

Speed: the smoke test's first node took 7 seconds including the script. I expected 10 to 25 seconds a node, so 150 to 350 nodes an hour, if nothing else was running. For the comparison I expected no visible difference between the arms at three seeds. In the lab the tree helped only when good edits were rare, and a house-price table with hundreds of columns has plenty of easy edits. The results below test that.

Run it

Set up once

$ mkdir -p ~/work/he-build && cd ~/work/he-build
$ uv venv --python 3.12 aide-env && source aide-env/bin/activate
$ uv pip install -U aideml          # 0.2.2 when this page was written
$ export OPENAI_API_KEY=...          # your own key; never commit it
$ export OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 LOKY_MAX_CPU_COUNT=4

The last line caps the threads each generated script may use. Without it, a script that asks for "all cores" takes all 16 and every other run on the machine slows down. The files are in harness-eng/workbench/code/w01/: make_task.py, aide_one_task.py (the script below) and the notebook aide_one_task.ipynb.

The task is the Ames house-price table that ships with aideml (1,460 labelled rows, 79 columns). make_task.py splits it the way chapter 3 asks. The agent's folder gets 1,100 labelled rows and 360 rows with the price removed; the 360 true prices go to a folder the agent's code cannot see. The metric is the root-mean-squared error of the log price, lower is better.

$ python make_task.py --aide-dir aide-env/lib/python3.12/site-packages/aide/example_tasks/house_prices
public train rows 1100, private test rows 360
agent sees: data_description.txt, sample_submission.csv, test.csv, train.csv
evaluator only: test_labels.csv

The idea

  1. start aideml's own Agent on the task with the chosen model, 20 steps, and 5 drafts (tree) or 1 draft (greedy)
  2. count every model call's tokens by wrapping the OpenAI backend function, and price them with the formula above
  3. after each node, score the submission.csv it wrote against the private labels, whatever the agent thought of it
  4. between nodes, kill leftover worker processes and restart the script runner if it died
  5. report nodes per hour, seconds and dollars per node, and the private score of the node the agent's own metric selected
"""AIDE on one small task: nodes per hour, cost per node, tree versus greedy.

    python aide_one_task.py --arm tree   --seed 0 --steps 20
    python aide_one_task.py --arm greedy --seed 0 --steps 20
    python aide_one_task.py --report runs/tree-s0 runs/greedy-s0 ...

Needs: pip install aideml, OPENAI_API_KEY in the environment, and the
task/ and private/ folders from make_task.py in the current directory.

Both arms run aideml's own Agent with the same prompts, model and steps.
The only difference is agent.search.num_drafts: 5 for the tree arm (aideml's
default), 1 for the greedy arm, so it drafts once and then keeps improving
the best node it has. Each node's submission.csv is scored on the private
rows after the agent has finished with it; the agent never sees that score.
"""
import argparse
import csv
import glob
import json
import math
import os
import random
import shutil
import signal
import subprocess
import time

ap = argparse.ArgumentParser()
ap.add_argument("--arm", choices=["tree", "greedy"], default="tree")
ap.add_argument("--seed", type=int, default=0)       # python's random only
ap.add_argument("--steps", type=int, default=20)     # nodes per run (budget)
ap.add_argument("--model", default="gpt-5.4-mini")
ap.add_argument("--feedback-model", default="gpt-5.4-mini")
ap.add_argument("--out", default="runs")
ap.add_argument("--report", nargs="*", default=None)
ap.add_argument("--exec-timeout", type=int, default=300)  # s per script
args, _ = ap.parse_known_args()

# USD per million tokens, from OpenAI's pricing page (see the workbench page)
PRICE = {"gpt-5.4-mini": (0.75, 4.50), "gpt-5.4-nano": (0.20, 1.25)}


# ── 1. The private scorer: RMSE between log prices ───────────────────────
def private_rmse(path, labels="private/test_labels.csv"):
    """Return the RMSE of log prices for a submission, or None if unusable."""
    try:
        with open(labels, newline="") as f:
            want = {r["Id"]: float(r["SalePrice"]) for r in csv.DictReader(f)}
        with open(path, newline="") as f:
            got = {r["Id"]: float(r["SalePrice"]) for r in csv.DictReader(f)}
        if set(got) != set(want) or any(v <= 0 for v in got.values()):
            return None
        se = [(math.log(got[i]) - math.log(want[i])) ** 2 for i in want]
        return math.sqrt(sum(se) / len(se))
    except (OSError, KeyError, ValueError):
        return None


# ── 2. One run: AIDE's own agent, with counters bolted on ────────────────
def sweep_strays(keep):
    """Kill every process in our session except those in `keep`.

    The agent's generated scripts often start joblib worker pools. When a
    script times out, aideml kills the script but its workers can survive
    and keep every core busy, so we clear them out between nodes."""
    sid = os.getsid(0)
    ps = subprocess.run(["ps", "-eo", "pid=,sid="], capture_output=True,
                        text=True).stdout
    for line in ps.splitlines():
        pid, s = (int(x) for x in line.split())
        if s == sid and pid not in keep:
            try:
                os.kill(pid, signal.SIGKILL)
            except OSError:
                pass


def watchdog(signum, frame):
    raise RuntimeError("step watchdog: the step took far too long")


def run_once():
    import aide.backend as backend
    from aide import Experiment, Interpreter
    from aide.utils.config import save_run
    from omegaconf import OmegaConf

    try:
        os.setsid()                    # our own session, to sweep later
    except OSError:
        pass
    signal.signal(signal.SIGALRM, watchdog)
    random.seed(args.seed)
    name = f"{args.arm}-s{args.seed}"
    run_dir = os.path.abspath(os.path.join(args.out, name))
    shutil.rmtree(run_dir, ignore_errors=True)
    os.makedirs(run_dir)
    os.chdir(run_dir)                  # aideml writes logs/ and workspaces/
    task = os.path.abspath("../../task")
    labels = os.path.abspath("../../private/test_labels.csv")

    calls = []                         # (seconds, tokens in, tokens out)
    inner = backend.provider_to_query_func["openai"]

    def counted(**kw):
        out = inner(**kw)
        calls.append((out[1], out[2], out[3]))
        return out
    backend.provider_to_query_func["openai"] = counted

    exp = Experiment(
        data_dir=task,
        goal="Predict the sales price for each house",
        eval="RMSE between log-prices")
    cfg = exp.cfg
    cfg.agent.code.model = args.model
    cfg.agent.feedback.model = args.feedback_model
    cfg.agent.search.num_drafts = 5 if args.arm == "tree" else 1
    cfg.exec.timeout = args.exec_timeout
    sub = os.path.join(cfg.workspace_dir, "working", "submission.csv")
    pin, pout = PRICE[args.model]
    log = open("steps.jsonl", "w")
    t_start = time.time()
    died = 0                           # times the script's child died
    while len(exp.journal.nodes) < args.steps and died < 5:
        step = len(exp.journal.nodes)
        child = getattr(exp.interpreter, "process", None)
        sweep_strays({os.getpid(), child.pid if child else 0})
        if os.path.exists(sub):
            os.remove(sub)             # no stale file from the last node
        n0, t0 = len(calls), time.time()
        signal.alarm(2 * args.exec_timeout + 120)   # per-node ceiling
        try:
            exp.agent.step(exec_callback=exp.interpreter.run)
            signal.alarm(0)
        except RuntimeError as err:    # child died, or the watchdog fired
            signal.alarm(0)
            died += 1
            mine = calls[n0:]
            tin = sum(c[1] for c in mine)
            tout = sum(c[2] for c in mine)
            log.write(json.dumps({
                "step": step, "died": str(err), "tok_in": tin,
                "tok_out": tout,
                "usd": round((tin * pin + tout * pout) / 1e6, 5)}) + "\n")
            log.flush()
            exp.interpreter = Interpreter(
                cfg.workspace_dir,
                **OmegaConf.to_container(cfg.exec))   # a fresh child
            continue
        node = exp.journal.nodes[-1]
        mine = calls[n0:]
        tin = sum(c[1] for c in mine)
        tout = sum(c[2] for c in mine)
        row = {
            "step": step, "stage": node.stage_name,
            "parent": node.parent.step if node.parent else None,
            "buggy": bool(node.is_buggy),
            "val": None if node.is_buggy else node.metric.value,
            "maximize": None if node.is_buggy else node.metric.maximize,
            "crashed": node.exc_type is not None,
            "private": private_rmse(sub, labels),   # even if flagged buggy
            "seconds": round(time.time() - t0, 1),
            "calls": len(mine), "tok_in": tin, "tok_out": tout,
            "usd": round((tin * pin + tout * pout) / 1e6, 5)}
        log.write(json.dumps(row) + "\n")
        log.flush()
        save_run(cfg, exp.journal)
        print(f"{name} step {step:2d} {row['stage']:7s} "
              f"val {row['val']} private {row['private']} "
              f"{row['seconds']} s ${row['usd']}", flush=True)
    exp.interpreter.cleanup_session()
    log.write(json.dumps({"total_seconds": round(time.time() - t_start, 1),
                          "model": args.model, "arm": args.arm,
                          "seed": args.seed}) + "\n")
    log.close()


# ── 3. Report: speed and cost, then quality, then the paired gap ─────────
def load(d):
    rows = [json.loads(x) for x in open(os.path.join(d, "steps.jsonl"))]
    steps = [r for r in rows if "stage" in r]
    lost = [r for r in rows if "died" in r]
    total = [r for r in rows if "total_seconds" in r]
    secs = total[0]["total_seconds"] if total else \
        sum(r["seconds"] for r in steps)
    good = [r for r in steps if r["val"] is not None
            and r["private"] is not None]
    sign = -1 if good and good[0]["maximize"] else 1
    best = min(good, key=lambda r: sign * r["val"]) if good else None
    return steps, lost, secs, good, best


def report(dirs):
    runs = {d: load(d) for d in dirs}
    print(f"{'run':10s} {'nodes':>5s} {'min':>6s} {'nodes/h':>8s} "
          f"{'median s':>8s} {'max s':>6s} {'$/node':>7s} {'$ total':>8s} "
          f"{'died':>5s}")
    for d, (steps, lost, secs, good, best) in runs.items():
        usd = sum(r["usd"] for r in steps + lost)
        per = sorted(r["seconds"] for r in steps)
        print(f"{os.path.basename(d):10s} {len(steps):5d} {secs / 60:6.1f} "
              f"{len(steps) / secs * 3600:8.1f} {per[len(per) // 2]:8.1f} "
              f"{per[-1]:6.0f} {usd / len(steps):7.4f} "
              f"{usd:8.3f} {len(lost):5d}")
    print()
    print(f"{'run':10s} {'ok':>3s} {'false bug':>9s} {'best val':>9s} "
          f"{'its private':>11s} {'best private':>12s} {'1st draft':>9s}")
    for d, (steps, lost, secs, good, best) in runs.items():
        flagged = [r for r in steps if r["buggy"] and not r["crashed"]
                   and r["private"] is not None]
        draft = next((r for r in good if r["stage"] == "draft"), None)
        print(f"{os.path.basename(d):10s} {len(good):3d} {len(flagged):9d} "
              f"{best['val']:9.4f} {best['private']:11.4f} "
              f"{min(r['private'] for r in good):12.4f} "
              f"{draft['private'] if draft else float('nan'):9.4f}")
    by = {os.path.basename(d): v[4]["private"] for d, v in runs.items()}
    diffs = [(k.split("-s")[1], by[k] - by["tree-s" + k.split("-s")[1]])
             for k in by if k.startswith("greedy-s")
             and "tree-s" + k.split("-s")[1] in by]
    if diffs:
        print("\nprivate RMSE of the selected node, greedy minus tree "
              "(positive: tree better)")
        for seed, d in sorted(diffs):
            print(f"  seed {seed}: {d:+.4f}")
        m = sum(d for _, d in diffs) / len(diffs)
        print(f"  mean over {len(diffs)} seeds: {m:+.4f}")


if args.report is not None:
    report(args.report or sorted(glob.glob(os.path.join(args.out, "*"))))
else:
    run_once()

Both arms run aideml's own agent, with the same prompts, models and 20 nodes. The only setting that differs is agent.search.num_drafts. With one draft the selection rule of Lab 1's milestone 3 reduces to "improve the best node, and debug a failed one half the time": the nearest thing the package has to a greedy hill-climber. It is not the autoresearch loop of FML-Bench (case study 1), and I do not claim that it is. Start the runs, three seeds for each arm:

$ for s in 0 1 2; do
    python aide_one_task.py --arm tree   --seed $s --steps 20 &
    python aide_one_task.py --arm greedy --seed $s --steps 20 &
    wait
  done
$ python aide_one_task.py --report runs/greedy-s0 runs/greedy-s1 runs/greedy-s2 \
      runs/tree-s0 runs/tree-s1 runs/tree-s2

The seed sets Python's random module, which drives the selection rule and the shuffled package list in the prompt. It does not fix the model: the API takes no seed here, so two runs with the same seed give different scripts. Treat "seed" as "a repeat with its own search randomness".

What you should see

  • Cost per node. $0.0074 to $0.0115, in line with the $0.005 to $0.011 predicted. Twenty nodes cost $0.15 to $0.23, and the six kept runs cost $1.07 in all. Counting the smoke test and the runs I discarded (below), the page cost about $1.3.
  • Nodes per hour. 29 to 241. That spread is the machine, not the agent. The lab VM is shared, and during the first batch its load average was 5 to 17 on 16 cores; during the rerun of tree seed 0 it was 33 to 42, because other jobs were using it. The more robust column is median s, the median seconds per node: 10 to 18 for five of the runs, 45 for one. The max s column is the cost of contention: one node took 440 seconds, almost all of it a script competing for cores. On a quiet machine, plan on 150 to 250 nodes an hour; on a busy one, do not plan on it.
  • The private score of the selected node. Greedy: 0.1303, 0.1482, 0.1316. Tree: 0.1690, 0.1626, 0.1989. In all three seeds the greedy arm's selected node was better on the private rows, by 0.039 on average. Look at its private against best private: every selected node was worse than the best node the run produced. And the first draft that ran (1st draft) scored within 0.006 of the run's best private score in four of the five runs where one ran. For this task, the improving steps did not improve generalisation.
  • The reviewer. false bug counts nodes the reviewing model marked buggy although the script ran and wrote a submission. Only tree seed 1 had one (its step 0, whose private score of 0.1307 was the run's best). That is a node thrown away for a reviewer's mistake. The first smoke test showed two such nodes in three, with the same model as reviewer; the real runs were kinder.
  • Repeats. The trace shows tree seed 1 improving node 5 eleven times and getting the identical validation score of 0.1476 each time. The script below counts how often a node reproduces a score its own run already had:
"""How many nodes repeat a score the same run already produced?

    python repeats.py runs/tree-s0 runs/greedy-s0 ...

A node whose validation score is identical, to five digits, to an earlier
node's in the same run most probably re-ran the same model.
"""
import json
import sys

print(f"{'run':10s} {'scored':>6s} {'repeats':>7s} {'share':>6s}")
for d in sys.argv[1:]:
    rows = [json.loads(x) for x in open(d + "/steps.jsonl")]
    seen, scored, rep = set(), 0, 0
    for r in rows:
        if r.get("val") is None:
            continue
        scored += 1
        rep += r["val"] in seen
        seen.add(r["val"])
    print(f"{d.split('/')[-1]:10s} {scored:6d} {rep:7d} {rep / scored:6.0%}")

In tree seed 1, 11 of 16 scored nodes repeated an earlier score: most of its budget bought nothing. Elsewhere the share is 5 to 31 per cent. This is a property of the proposer, not the tree: a model asked to "improve the best solution" often proposes the same change from the same code.

Common misconception

“Greedy won all three seeds, so greedy beats tree.” Three paired differences cannot say that. They are −0.039, −0.014 and −0.067 (greedy minus tree, so negative favours greedy). Their mean is −0.040 and their standard deviation 0.027. A 95 per cent interval from a t distribution with two degrees of freedom is wide, and it contains zero:

"""Is three seeds enough? A t interval and a rough sample size.

The three differences are the greedy-minus-tree private RMSEs printed by
the report above (negative: greedy better).
"""
import math
import statistics

DIFFS = [-0.0387, -0.0144, -0.0674]
T_975 = {2: 4.303, 3: 3.182, 4: 2.776, 5: 2.571, 9: 2.262}   # t, df = n - 1

n = len(DIFFS)
mean, sd = statistics.mean(DIFFS), statistics.stdev(DIFFS)
half = T_975[n - 1] * sd / math.sqrt(n)
print(f"n = {n}, mean {mean:+.4f}, sd {sd:.4f}")
print(f"95% interval for the mean: [{mean - half:+.4f}, {mean + half:+.4f}]")
need = ((1.96 + 0.84) * sd / abs(mean)) ** 2     # 80% power, z approximation
print(f"seeds for 80% power if the true gap is {abs(mean):.3f}: "
      f"about {math.ceil(need)} (z approximation; add one or two for t)")
n = 3, mean -0.0402, sd 0.0265
95% interval for the mean: [-0.1061, +0.0257]
seeds for 80% power if the true gap is 0.040: about 4 (z approximation; add one or two for t)

If the true gap were about 0.04, four to six seeds per arm would be needed to see it with reasonable power, which is a cheap experiment at these prices. Also note what the comparison does not control: the model's randomness is unseeded, so some of the spread between seeds is the model, not the search. The FML-Bench study ran three rounds per agent on 18 tasks, and the Artifact 2 plan is three tasks and three seeds; treat three seeds as the minimum, not as proof.

What went wrong along the way

A workbench that hides its failed attempts is a poor guide to the next one. Four things happened, and each changed the page.

  • A tree run died. The first tree run for seed 0 stopped at node 9 when aideml's script runner reported REPL child process died unexpectedly; I do not know why (the machine is shared, so another job killing it is possible). Its nine nodes are in the repository's logs but not in the table. I added a restart of the runner and reran seed 0 from scratch. The other five runs used the earlier version of the script, which differs only by that restart, a watchdog on each node and the clearing of leftover worker processes; none of them triggered it.
  • Orphaned workers. When a generated script times out, aideml kills the script but its joblib worker processes can survive and keep running. A later batch stalled for ten minutes behind them, so the script now clears them between nodes. I cut that batch (two more seeds per arm and a gpt-5.4-nano pair) short when the shared machine's load went above 35, and discarded the partial runs. The page is therefore three seeds, not five, and has no nano result.
  • Thread caps. The first smoke test, with no thread cap, stalled for more than ten minutes on one node while the machine's load average was above 80. After I added the cap, a repeat of the smoke test finished its three nodes in 44 seconds, though the load had also dropped by then, so I cannot say how much the cap helped.
  • The reviewer's verdicts. In that first smoke test two of three nodes that ran fine, with a cross-validation RMSE of 0.136, were marked buggy by the reviewing model. I changed the script to record the private score of every node that wrote a submission, so these are visible in the false bug column rather than silently lost.

Break it

  • Swap the model. Run one pair with --model gpt-5.4-nano --feedback-model gpt-5.4-nano. Predict first: from the price list, the cost per node should fall by roughly a factor of 3 to 4 if the token counts are similar (the input rate is 3.75 times lower, the output rate 3.6 times lower). Will the nodes also be worse? Count crashed nodes and repeats. Not run here: I did not run nano, for the reason in the previous section, so this is a prediction to check, not a result.
  • Select on the private score. In the report, choose each run's best node by private instead of val. Predict the size of the improvement: the best private column is the answer, and it is 0.0003 to 0.0687 below the selected node's. Then say why you could not do this in a real loop: you would be selecting on the test set (chapter 3).
  • Double the budget. Run with --steps 40 for one seed per arm. Predict whether the first-draft score still beats the later nodes, and how many more nodes will repeat.
  • Plant a peekable file. Copy private/test_labels.csv into the task folder as test_labels.csv before a run. Predict whether the agent notices, how you would detect it (Lab 1's milestone 6: a gap between validation and private score), and what the hacking rate would be over three seeds. Then delete the file.

Key takeaways

  • A node of this agent cost about $0.009 on average with gpt-5.4-mini (range $0.0074 to $0.0115 per run), 10 to 18 seconds of median time on this task, and the number of nodes an hour depends more on your neighbours than on the agent.
  • Greedy beat tree on the private score in all three seeds, by 0.040 RMSE on average, and the interval for that gap includes zero. Three seeds show a direction at best; four to six would be needed for a gap of that size.
  • The node chosen by the agent's own metric was worse on unseen rows than the best node the run had made, in every run. The first draft was often as good as anything later.
  • Budget in dollars and in nodes, and watch for repeats and false bugs: they spend the budget without searching.
  • A shared machine, an unseeded model and a restart that was added halfway are all part of the result. Report them.
