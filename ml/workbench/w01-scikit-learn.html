Workbench 1: The Same Models in scikit-learn

In labs 1 and 2 you built least squares, ridge, the lasso, logistic regression and gradient boosting from nothing. scikit-learn is the library most practitioners reach for instead. Here you feed the labs' own data to both, compare coefficients, cross-validated scores and a boosted model number by number, and explain every gap. A coefficient is the weight a model puts on one feature. Cross-validation scores a model on rows it did not train on. Gradient boosting builds many small trees, each fixing the errors of the ones before.

Why measure it

You will almost never fit a model with your own solver at work. You will call a library, and then ask whether its answer can be trusted and what its knobs mean. The same knob can mean different things in two places. A ridge strength of 3 in one tutorial and 3 in another can be two different models. When the lab's numbers and the library's agree to ten decimals, you have learned what the library does. When they differ, the cause is nearly always a convention, and finding it is the skill. Write down what you expect, then measure.

What you need

  • Your laptop, no GPU. Python 3.10 or later, the workbench environment (below) and scikit-learn 1.8 or later. The numbers here were produced with 1.9.1. Nothing is downloaded. (Version 1.8 deprecated two options this script would otherwise need, so it avoids them.)
  • The course folder. The script imports the reference solutions ml/labs/code/lab01/solution.py and lab02/solution.py. To use your own lab code instead, copy it to a folder with the same layout and pass --labs.
  • Time. The script takes about 20 seconds, most of it the labs' pure-Python boosting. Allow about 90 minutes with the experiments.

Predict before you run

Start from the objectives. Each library minimises a sum of two terms: how badly the model fits, and a charge for large weights. The strength knob scales the charge. Chapter 6 gives the ridge loss (its anatomy block) and the lasso loss. Both labs use these exact forms, on features standardised to mean 0 and standard deviation 1:

ridge: ∑ (yi − w·xi)2 + α ∑ wj2; lasso: (1/2n) ∑ (yi − w·xi)2 + α ∑ |wj|

scikit-learn documents Ridge and Lasso with the same two expressions. So the first prediction is that the same alpha gives the same answer, as long as both see standardised features. scikit-learn's estimators do not standardise for you.

Logistic regression is where the conventions part. The lab minimises the mean log-loss (ℓi is the log-loss of row i) plus a penalty with strength l2. scikit-learn's LogisticRegression instead takes a knob C, the inverse of the strength, and puts it on the sum of the losses:

lab: (1/n) ∑ ℓi + (l2 / 2) ∑ wj2
scikit-learn: C ∑ ℓi + (1 / 2) ∑ wj2

Divide the second expression by C n, which does not change where its minimum is, and it takes the lab's form:

(1 / Cn) [ C ∑ ℓi + (1/2) ∑ wj2 ] = (1/n) ∑ ℓi + (1 / 2Cn) ∑ wj2, so l2 = 1 / (C n)

Your prediction

On paper first. (1) The churn data has n = 700 rows. If the lab uses l2 = 0.1, what C must you give scikit-learn? What happens if you guess C = 1 / l2 = 10? (2) The labs' cross-validation puts row i in fold i mod 5 and scales the features inside each fold. scikit-learn's KFold cuts five contiguous blocks. Do you expect identical scores? (3) The lab and scikit-learn grow depth-3 trees on the same residuals, starting from the mean of y. Will the boosted predictions agree to the last digit? Think about what happens when two splits are equally good.

Check your arithmetic

(1) C = 1 / (700 × 0.1) = 0.0143. Guessing C = 10 gives a penalty 700 times weaker than the lab's, so the weights should come out visibly different. (2) With the lab's folds and the scaler fitted inside each fold, scores should match to rounding error. Contiguous blocks hold different rows, so the scores should differ somewhat, and by an amount you will be able to compare with the gaps between alphas. A scaler fitted on all the rows first leaks a little information from the validation rows, and the scores should shift slightly. (3) The two should agree closely, and exactly at the start. But when two splits tie, the lab takes the lowest feature number and scikit-learn takes whichever it meets first. Both choices give the same predictions on the training rows and can differ on new rows.

Run it

Set up once

One virtual environment serves every workbench page. From the site's folder:

$ python3 -m venv ~/.venvs/zts
$ ~/.venvs/zts/bin/pip install -r workbench/requirements.txt
$ source ~/.venvs/zts/bin/activate

The script is code/w01/lab_vs_sklearn.py, and the same code split into cells is lab_vs_sklearn.ipynb for Jupyter. The labs themselves are lab 1 and lab 2.

The idea

  1. import the labs' solutions and their data generators (rent, sparse, churn, Friedman)
  2. least squares and ridge: lab against LinearRegression and Ridge; the largest difference in any weight
  3. lasso at three strengths: how many features each keeps, and the largest weight difference
  4. logistic regression: C = 1 / (n × l2), then the wrong guess
  5. cross-validated RMSE for six alphas, three ways of splitting and scaling
  6. boosting: test RMSE, time, and the first tree where the two part ways
"""The same models in scikit-learn: run the ml labs' own data and code
beside scikit-learn's, and compare number by number.

    python lab_vs_sklearn.py
    python lab_vs_sklearn.py --labs /path/to/ml/labs/code

Needs: numpy, scikit-learn (workbench/requirements.txt) and the course
folder, because it imports ml/labs/code/lab01/solution.py and lab02."""
import argparse
import importlib.util
import math
import time
import warnings
from pathlib import Path

import numpy as np
from sklearn.ensemble import (GradientBoostingRegressor,
                              HistGradientBoostingRegressor)
from sklearn.linear_model import (Lasso, LinearRegression,
                                  LogisticRegression, Ridge)
from sklearn.model_selection import GridSearchCV, KFold, PredefinedSplit
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
import sklearn

# ── 1. Load the labs' reference solutions ────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--labs", default=None)        # folder holding lab01, lab02
args, _ = ap.parse_known_args()        # notebooks pass their own flags


def find_labs():
    if args.labs:
        return Path(args.labs)
    try:
        here = Path(__file__).resolve()
    except NameError:                  # inside a notebook
        here = Path.cwd().resolve()
    for base in [here, *here.parents]:
        if (base / "ml/labs/code").is_dir():
            return base / "ml/labs/code"
        if (base / "labs/code").is_dir():
            return base / "labs/code"
    raise SystemExit("cannot find ml/labs/code; pass --labs")


def load(name):
    path = find_labs() / name / "solution.py"
    spec = importlib.util.spec_from_file_location(name, path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


lab1, lab2 = load("lab01"), load("lab02")
print(f"scikit-learn {sklearn.__version__}, numpy {np.__version__}")


def worst(a, b):
    """Largest absolute difference between two lists of numbers."""
    return float(np.max(np.abs(np.asarray(a) - np.asarray(b))))


# ── 2. Ordinary least squares (chapter 5) ────────────────────────────────
# Predict: both solve the same normal equations, so the numbers agree to
# rounding error (about 1e-9 or better), not just to two decimals.
Xl, yl = lab1.make_rent(seed=1, n=200)
X, y = np.array(Xl), np.array(yl)
theta = lab1.fit_ols(Xl, yl)                    # [b, w_area, w_dist, w_age]
sk = LinearRegression().fit(X, y)
print("\nOLS on the rent data (true: 300, 11, -25, -2)")
print(f"  lab      b={theta[0]:9.4f}  w={np.round(theta[1:], 4)}")
print(f"  sklearn  b={sk.intercept_:9.4f}  w={np.round(sk.coef_, 4)}")
print(f"  largest difference: "
      f"{worst(theta, [sk.intercept_, *sk.coef_]):.2e}")

# ── 3. Ridge and lasso: what alpha means (chapter 6) ─────────────────────
# Lab ridge:  sum of squares + alpha * sum w^2           (standardised X)
# sklearn Ridge: the same expression. Predict: same alpha, same answer.
# Lab lasso:  1/(2n) * sum of squares + alpha * sum |w|  (standardised X)
# sklearn Lasso: the same 1/(2n) convention. Predict: same alpha, same.
# The trap is the features. sklearn does not standardise for you; on raw
# columns the penalty falls unevenly, and the answer is a different model.
Xs, ys, support = lab1.make_sparse(seed=2, n=60, d=20, sigma=3.0)
Xs, ys = np.array(Xs), np.array(ys)
Z = StandardScaler().fit_transform(Xs)         # divides by the population sd
alpha = 3.0
m = lab1.ridge_fit(Xs.tolist(), ys.tolist(), alpha)
r = Ridge(alpha=alpha).fit(Z, ys)
print("\nridge, alpha=3, 20 features, 60 rows")
print(f"  lab vs sklearn on standardised X: "
      f"{worst(m.w, r.coef_):.2e} apart")

# The same alpha on the rent data, whose columns have very different
# scales (area 25 to 120 m2, distance 0.5 to 15 km, age 0 to 80 years).
# Predict: sklearn Ridge on the raw columns shrinks the small-scale
# column (distance) far less than the lab does, so the two models differ.
BIG = 20000.0
lab_r = lab1.ridge_fit(Xl, yl, BIG).to_original()
pipe = make_pipeline(StandardScaler(), Ridge(alpha=BIG)).fit(X, y)
sc, rg = pipe[0], pipe[-1]
pipe_w = rg.coef_ / sc.scale_              # back to the original units
pipe_b = rg.intercept_ - float(np.sum(pipe_w * sc.mean_))
raw_r = Ridge(alpha=BIG).fit(X, y)
print(f"\nridge, alpha={BIG:g}, rent data, weights in original units")
print(f"  lab                  w={np.round(lab_r[1:], 3)}")
print(f"  sklearn + scaler     w={np.round(pipe_w, 3)}"
      f"  ({worst(lab_r[1:], pipe_w):.1e} from the lab)")
print(f"  sklearn, raw columns w={np.round(raw_r.coef_, 3)}")

a_max = lab1.alpha_max(Xs.tolist(), ys.tolist())
print(f"\nlasso: lab alpha_max = {a_max:.4f}")
print("  alpha   kept(lab) kept(sklearn)  largest difference in w")
for frac in (0.5, 0.2, 0.05):
    a = frac * a_max
    lm = lab1.lasso_fit(Xs.tolist(), ys.tolist(), a)
    sl = Lasso(alpha=a, tol=1e-12, max_iter=100000).fit(Z, ys)
    kl = sum(abs(w) > 1e-12 for w in lm.w)
    ks = int(np.sum(np.abs(sl.coef_) > 1e-12))
    print(f"  {a:6.3f}  {kl:8d}  {ks:12d}   {worst(lm.w, sl.coef_):.2e}")

# ── 4. Logistic regression: C is not l2 (chapter 5 and 6) ────────────────
# Lab:     mean log-loss + (l2 / 2) * sum w^2
# sklearn: C * sum log-loss + (1 / 2) * sum w^2
# Divide sklearn's by C * n: mean log-loss + (1 / (2 C n)) * sum w^2.
# Predict: the two agree when l2 = 1 / (C n), that is C = 1 / (n * l2).
Xc, yc = lab1.make_churn(seed=3, n=700)
Xc, yc = np.array(Xc), np.array(yc)
n = len(yc)
Zc = StandardScaler().fit_transform(Xc)
print("\nlogistic regression on the churn data (n=700)")
print("  l2    lab steps   C used by sklearn     largest |w| difference")
for l2 in (0.0, 0.01, 0.1):
    lm = lab1.fit_logistic(Xc.tolist(), yc.tolist(), l2=l2, steps=400)
    if l2 == 0.0:
        sk = LogisticRegression(C=np.inf, tol=1e-12, max_iter=10000)
        c_txt = "infinity (no penalty)"
    else:
        c = 1.0 / (n * l2)
        sk = LogisticRegression(C=c, tol=1e-12, max_iter=10000)
        c_txt = f"1/(n*l2) = {c:.4f}"
    sk.fit(Zc, yc)
    w_lab = lm.theta[1:]
    print(f"  {l2:<5} {400:9d}   {c_txt:21} "
          f"{worst(w_lab, sk.coef_[0]):.2e}")
wrong = LogisticRegression(C=1 / 0.1, tol=1e-12).fit(Zc, yc)
lm = lab1.fit_logistic(Xc.tolist(), yc.tolist(), l2=0.1)
print(f"  with the wrong guess C = 1/l2 = 10: "
      f"{worst(lm.theta[1:], wrong.coef_[0]):.2e} apart")
more = lab1.fit_logistic(Xc.tolist(), yc.tolist(), l2=0.0, steps=5000)
sk0 = LogisticRegression(C=np.inf, tol=1e-12, max_iter=10000)
sk0.fit(Zc, yc)
print(f"  l2=0 with 5,000 lab steps instead of 400: "
      f"{worst(more.theta[1:], sk0.coef_[0]):.2e} apart")

# ── 5. Cross-validation (chapter 6) ──────────────────────────────────────
# Lab: row i is in fold i % 5, the scaler is refitted inside every fold,
# and the score is the MEAN OF THE FOLD RMSEs. sklearn's KFold cuts
# contiguous blocks. Predict: a pipeline (scaler inside the fold) with the
# lab's own folds matches the lab to rounding; KFold blocks differ a
# little; and a scaler fitted on all rows before cross-validating (the
# leak of chapter 14) gives yet another set of numbers.
alphas = [0.01, 0.1, 1, 10, 100, 1000]
folds = np.arange(len(ys)) % 5
lab_best = lab1.select_alpha(Xs.tolist(), ys.tolist(), alphas, k=5)
pipe = make_pipeline(StandardScaler(), Ridge())
score = "neg_root_mean_squared_error"
grid = {"ridge__alpha": alphas}
same = GridSearchCV(pipe, grid, cv=PredefinedSplit(folds),
                    scoring=score).fit(Xs, ys)
blocks = GridSearchCV(pipe, grid, cv=KFold(5), scoring=score).fit(Xs, ys)
leaky = GridSearchCV(Ridge(), {"alpha": alphas},
                     cv=PredefinedSplit(folds), scoring=score).fit(Z, ys)
print("\n5-fold CV RMSE for ridge (lab folds: row i in fold i % 5)")
print("  alpha   lab        sklearn, same folds  KFold blocks"
      "  scaler outside")
for i, a in enumerate(alphas):
    cv = lab1.kfold_rmse(lambda Xt, yt, a=a: lab1.ridge_fit(Xt, yt, a),
                         Xs.tolist(), ys.tolist(), k=5)
    cells = [-g.cv_results_["mean_test_score"][i]
             for g in (same, blocks, leaky)]
    print(f"  {a:<7g} {cv:.6f}   {cells[0]:.6f}           "
          f"{cells[1]:.6f}      {cells[2]:.6f}")
print(f"  best alpha: lab {lab_best[0]}, same folds "
      f"{same.best_params_['ridge__alpha']}, KFold "
      f"{blocks.best_params_['ridge__alpha']}, scaler outside "
      f"{leaky.best_params_['alpha']}")

# ── 6. Gradient boosting (chapter 9) ─────────────────────────────────────
# Same recipe: start at mean(y), fit a depth-3 tree to the residuals,
# add lr times its predictions. Predict: the two agree closely, at the
# start exactly, but not to the last digit: when two splits have equal
# gain the lab takes the lowest feature index and sklearn takes whichever
# it meets first. HistGradientBoosting bins every feature into at most
# 255 buckets first, so it is a different algorithm and will differ more.
Xtr, ytr = lab2.make_friedman(seed=4, n=600)
Xte, yte = lab2.make_friedman(seed=5, n=2000)
Rounds, LR = 100, 0.1
t0 = time.perf_counter()
gb = lab2.fit_gbm(Xtr, ytr, n_rounds=Rounds, lr=LR, max_depth=3)
t_lab = time.perf_counter() - t0
p_lab = np.array(lab2.gbm_predict(gb, Xte))
t0 = time.perf_counter()
sk = GradientBoostingRegressor(
    n_estimators=Rounds, learning_rate=LR, max_depth=3,
    random_state=0).fit(Xtr, ytr)
t_sk = time.perf_counter() - t0
p_sk = sk.predict(Xte)
hist = HistGradientBoostingRegressor(
    max_iter=Rounds, learning_rate=LR, max_depth=3, max_leaf_nodes=None,
    min_samples_leaf=1, early_stopping=False, random_state=0)
hist.fit(Xtr, ytr)
p_hist = hist.predict(Xte)


def rm(p):
    return math.sqrt(float(np.mean((np.asarray(p) - yte) ** 2)))


print(f"\ngradient boosting on Friedman #1 (600 train, 2000 test, "
      f"noise floor 1.0)")
print(f"  {'model':26}{'test RMSE':>10}{'fit time':>10}")
print(f"  {'lab fit_gbm':26}{rm(p_lab):>10.4f}{t_lab:>9.2f}s")
print(f"  {'sklearn GradientBoosting':26}{rm(p_sk):>10.4f}{t_sk:>9.2f}s")
print(f"  {'sklearn HistGradientBoost':26}{rm(p_hist):>10.4f}")
print(f"  largest prediction difference, lab vs sklearn GB: "
      f"{worst(p_lab, p_sk):.2e}")
print(f"  largest prediction difference, lab vs Hist:       "
      f"{worst(p_lab, p_hist):.2e}")
f0 = gb.f0
print(f"  starting value: lab f0 = {f0:.6f}, "
      f"sklearn init mean = {float(np.mean(ytr)):.6f}")
stage = list(sk.staged_predict(Xte))
curve = lab2.staged_rmse(gb, Xte, yte)
print("  test RMSE after n rounds (lab / sklearn):")
for k in (1, 10, 50, 100):
    print(f"    {k:4d}  {curve[k - 1]:.4f} / {rm(stage[k - 1]):.4f}")
first = None
for i, t in enumerate(gb.trees):               # compare tree by tree
    tr = max(abs(lab2.predict_one(t, r) - v) for r, v in
             zip(Xtr, sk.estimators_[i, 0].predict(np.array(Xtr))))
    te = np.array([lab2.predict_one(t, r) for r in Xte])
    d = np.abs(te - sk.estimators_[i, 0].predict(np.array(Xte)))
    if d.max() > 1e-6 and first is None:
        first = (i + 1, tr, int((d > 1e-6).sum()), float(d.max()))
if first:
    print(f"  first tree that differs: number {first[0]}. On the "
          f"training rows the two trees agree to {first[1]:.1e}; on the "
          f"test rows they disagree on {first[2]} of {len(Xte)} "
          f"(by up to {first[3]:.2f})")

What you should see

  • Least squares: a difference of 2e-13. Both solve the same equations, so they agree to rounding error. The fitted intercept of 318 against the true 300 is not a disagreement between the two. It is the noise in 200 rows, which is the point of the standard errors in chapter 5.
  • Ridge, standardised: 1.8e-15. Same alpha, same answer, as predicted. Next, the rent data, whose columns have very different scales. With alpha = 20,000 the lab and a scikit-learn pipeline (StandardScaler then Ridge) agree to 4e-16 in the original units. Ridge on the raw columns gives an area weight of 9.786 instead of 0.111. The penalty acts on the size of the weights, and a weight's size depends on the units of its column. Raw area runs from 25 to 120, so its sum of squares is huge and alpha = 20,000 is a light tax on it. After standardising, every column has the same sum of squares (200, the number of rows), so the same alpha is a heavy tax. It is the same name for a different model.
  • Lasso: differences near 1e-10, and the same features kept. Both keep 3, 6 and 12 of the 20 features at the three strengths. The labs' alpha_max of 4.94 is the smallest strength that sets every weight to zero. Both are coordinate-descent solvers that stop when the weights move by less than a tolerance (the lab's is 1e-9), so 1e-10 is what remains. The lasso here keeps fewer than the 5 true features at the strongest setting and picks up noise features at the weakest, which is chapter 6's trade.
  • Logistic regression: 1e-9 apart with C = 1 / (n × l2), and 0.37 apart with the wrong guess. The conversion works, including with no penalty at all (C set to infinity). The data is not separable, so the lab's 400 gradient-descent steps are already enough. Giving it 5,000 leaves the gap at 4.95e-9, so what remains is the stopping tolerance of the two solvers, not the step count.
  • Cross-validation: the lab's folds and a pipeline match to six places. The fold scores are the mean of five fold RMSEs in both. KFold blocks give different numbers, up to 0.19 higher at small alpha, and they change the shape of the curve: alpha = 10 looks 0.2 better than alpha = 1 under blocks, but only 0.01 better under the lab's folds. Nothing is wrong. Sixty rows in five folds is a small sample, and two ways of cutting it disagree about how much one alpha beats another. The scaler fitted on every row before cross-validating (last column) moves scores in the third decimal and picks alpha = 1 instead of 10. The leak is small for plain scaling. Chapter 14 shows leaks that are not small.
  • Boosting: the same recipe, not the same trees. The starting value is identical to six places and the test RMSE after 1 and 10 rounds agrees to four. At 100 rounds it is 1.7435 for the lab and 1.7414 for scikit-learn, against a noise floor of 1.0. The script finds the first tree that differs: number 44. On the 600 training rows the two trees agree to 3e-15. On 6 of the 2,000 test rows they disagree, by up to 1.76. That is the tie. Two candidate splits of a small node gain the same amount. Either one gives the same predictions on the rows that built the tree, but a new row can fall on different sides. The lab breaks ties by feature number, scikit-learn by the order it happened to visit the features. Neither is wrong.
  • HistGradientBoostingRegressor is a different algorithm. It sorts each feature into at most 255 bins before looking for splits and grows its trees in its own order. Its predictions differ from the lab's by up to 1.81, and its test RMSE is 1.7065. That is one test set and one seed, so do not read a 0.04 gap as a ranking. The fit time is worth a glance: 0.5 s for the lab, 0.1 s for GradientBoostingRegressor. Your timings will differ.

Break it

  • Match the raw-column ridge by hand. A weight on standardised column j equals the raw weight times that column's standard deviation. So the penalty is the same only if the raw alpha for column j is 20,000 × sdj2. Predict: can one raw alpha reproduce the lab for all three columns? (The standard deviations of area, distance and age differ by a factor of about 40 in variance, so no.) Check by trying Ridge(alpha=20000 * X[:, 0].var()) and comparing each weight to the lab's.

  • Another random state. Change random_state in GradientBoostingRegressor to 1, 2 and 3. Predict which digit of the test RMSE moves and whether any of them reproduces the lab's 1.7435 exactly. Then look for the first differing tree in each case.

Key takeaways

  • Closed forms agree to rounding error: 2e-13 for least squares, 2e-15 for ridge on standardised features. The lasso agrees to its solver's tolerance, about 1e-10.
  • The same name can hide a different convention. Ridge and lasso alpha match the labs. Logistic C is 1 / (n × l2), and the wrong guess gave weights 0.37 apart.
  • scikit-learn does not standardise for you. Ridge on raw columns is a different model, because the penalty depends on units.
  • A cross-validation score depends on how you cut the folds and where you fit the scaler. Put the scaler in a pipeline so it is fitted inside each fold.
  • Boosting follows the same recipe in the lab and the library, and the predictions part ways only at ties. A library is not more correct than your code, only faster.
