Lab 2: Trees & Gradient Boosting from Scratch

On the tabular data of most businesses, the models that win are ensembles of decision trees. Chapter 8 showed how one tree chooses its questions, and chapter 9 showed how averaging many trees (a forest) and stacking many small ones (boosting) tame a single tree's instability. In this lab you build all three in plain Python on top of a single function, the split search: a CART tree, a random forest with out-of-bag error, and a gradient-boosted regressor with early stopping. Each is checked against a brute-force search, a hand value from the chapters, or a property it must satisfy.

Why this lab matters

XGBoost, LightGBM and CatBoost are heavily engineered, but their core is what you will write here: sort a feature, sweep the cut point with running sums, take the biggest impurity decrease, recurse. Everything else (histograms, leaf-wise growth, second-order gradients) is about doing that faster or regularising it better. Knowing the core changes how you use the libraries. You see why a deep unpruned tree memorises noise, why bootstrap samples give you a free validation score, why a boosting learning rate and a number of rounds are one decision and not two, and why impurity-based feature importance can flatter a noise column. And because both ensembles reuse one grow function, a single subtle bug in the split search (an off-by-one in a running sum, a cut placed between equal values) corrupts everything above it, which is exactly why milestone 1 is tested against a brute-force oracle.

Standard library only, deterministic, about ten seconds

Nothing here needs NumPy or scikit-learn. Every dataset and every random choice comes from a seeded random.Random, so every run prints the same numbers, and a failure names its seed: python3 check.py solution 3 2 replays milestone 3 on dataset seed 2 alone. The whole check takes about ten seconds; the split search is fast enough that growing a tree on 1,000 rows takes a few hundredths of a second, as long as you use running sums. Python 3.9 or newer. Conventions follow the chapters: X is a list of rows (n_samples, n_features); a tree is nested dictionaries; a leaf predicts the mean of its rows, which for 0/1 labels is the probability of class 1.

What you'll build

Five milestones, each reusing the last:

  1. Impurity and the best split: Gini impurity, variance, and a split search that sorts each feature once and sweeps every cut with running sums.
  2. Growing a tree: recursive greedy splitting with depth and leaf-size limits, prediction, and the experiment that shows a tree memorising noise.
  3. Bagging and the random forest: bootstrap samples, random feature subsets at each split, averaging, and the out-of-bag error estimate.
  4. Gradient boosting: a constant, then trees fitted to residuals, added with a learning rate; staged errors and early stopping.
  5. Importances and a shoot-out: impurity-decrease importances for all three models, and the test errors of a tree, a forest and boosting side by side.

Milestone 1: impurity and the best split

A tree's only decision is: which feature, and which threshold, split this group of rows best? "Best" needs a number for how mixed a group is. For classification with labels 0 and 1 and a fraction p of ones, the Gini impurity is 1 − p2 − (1 − p)2 = 2p(1 − p): the probability that two rows drawn at random from the node have different labels, 0 for a pure node and 0.5 for an even mix. For a numerical target, the impurity is the variance of the target in the node, and a leaf predicts the mean. A split is scored by the gain: the parent's impurity minus the size-weighted average impurity of the two children.

Take chapter 8's ten customers, sorted by tenure, with churn flags 1 1 1 0 1 0 0 0 1 0. The parent is five and five, so its Gini is 0.5. There are nine candidate cuts, one between each pair of neighbouring distinct tenures, placed at the midpoint. The cut at 6 puts three churners on the left (Gini 0) and seven customers with two churners on the right (Gini 0.408), a weighted impurity of 0.286 and a gain of 0.214. The cut at 23 splits the group into eight and two with the same overall mixture on both sides, and gains exactly nothing.

Scoring each cut from scratch is easy to write and ruinously slow: with n rows, n cuts and n rows to recount each time, that is n2 work per feature, and a tree needs it at every node. The trick of chapter 8 is to sort the feature once, then walk along it moving one row at a time from the right group to the left, keeping the running count of ones (and, for variance, the running sums of y and y2). The statistics of both children at every cut then cost a few additions. The check enforces it: it times your search on 3,000 rows and 10 features and fails if it takes more than 1.5 seconds (the reference does it in under 20 milliseconds).

Three details decide whether the search is right. Thresholds sit between distinct values. If four rows have tenure 1, 1, 1, 2, the only legal cut is between 1 and 2, at 1.5; a cut "inside" the three equal values cannot be expressed as a threshold on that feature. Rows with x <= threshold go left. Leaves have a minimum size (min_leaf): both children must keep at least that many rows, which is the main overfitting control of chapter 8. And zero gain is no split: return None unless the best gain is positive. This is also why a greedy tree cannot learn XOR: every first cut on 0/1 inputs has exactly zero gain, so the tree stays a single leaf. The check includes that example, so you see the limitation rather than read about it.

One identity is worth knowing, and the check uses it: for 0/1 labels, the variance is p(1 − p), which is exactly half the Gini impurity. So the "gini" and "mse" criteria choose identical splits on classification data; the "mse" gains are simply half as large (0.107 against 0.214 on the toy).

Hints try without first

  • Skip a cut if either child is smaller than min_leaf, or if col[order[i]] == col[order[i + 1]]. The threshold is the average of those two values.

  • Only accept a cut whose gain beats the best so far by more than about 1e-12 so that rounding noise cannot reorder tied cuts; start the best gain at 1e-12 so that zero-gain cuts are never returned.
  • A random-problem failure prints the best gain, the feature and the threshold the oracle found, which is usually enough to see which rule you broke.

def gini(y):
    """Gini impurity of a list of class labels: 1 - sum_k p_k^2 (0 for an empty or pure list)."""
    if not y:
        return 0.0
    n = len(y)
    counts = {}
    for label in y:
        counts[label] = counts.get(label, 0) + 1
    return 1.0 - sum((c / n) ** 2 for c in counts.values())

def variance(y):
    """Population variance of y (0 for an empty list): the regression impurity."""
    if not y:
        return 0.0
    m = sum(y) / len(y)
    return sum((v - m) ** 2 for v in y) / len(y)

def best_split(X, y, criterion="gini", min_leaf=1, features=None):
    """The split (gain, feature, threshold) with the largest impurity decrease, or None.

    criterion  "gini" (y is 0/1; impurity 2p(1-p)) or "mse" (impurity = variance of y)
    min_leaf   both children must have at least this many rows
    features   the column indices to search (default: all)

    Candidate thresholds are the midpoints between consecutive DISTINCT sorted values of a feature; rows with
    x <= threshold go left. gain = impurity(parent) - (n_left * impurity(left) + n_right * impurity(right)) / n.
    Sort each feature once and keep running sums, so a feature costs one pass.
    Ties go to the lowest feature index, then the lowest threshold. Return None unless the best gain is positive.
    """
    n = len(y)
    if n < 2 * min_leaf or n < 2:
        return None
    feats = range(len(X[0])) if features is None else features
    use_gini = criterion == "gini"
    total, total_sq = sum(y), sum(v * v for v in y)
    if use_gini:
        p = total / n
        parent = 2 * p * (1 - p)
    else:
        parent = total_sq / n - (total / n) ** 2
    best = (1e-12, None, None)
    for f in feats:
        col = [row[f] for row in X]
        order = sorted(range(n), key=col.__getitem__)
        ls = lq = 0.0                                   # running sum and sum of squares of the left side
        for i in range(n - 1):
            v = y[order[i]]
            ls += v
            lq += v * v
            nl = i + 1
            nr = n - nl
            if nl < min_leaf or nr < min_leaf:
                continue
            a, b = col[order[i]], col[order[i + 1]]
            if a == b:                                  # cannot cut between equal values
                continue
            if use_gini:
                pl, pr = ls / nl, (total - ls) / nr
                child = (nl * 2 * pl * (1 - pl) + nr * 2 * pr * (1 - pr)) / n
            else:
                rs, rq = total - ls, total_sq - lq
                child = ((lq - ls * ls / nl) + (rq - rs * rs / nr)) / n
            gain = parent - child
            if gain > best[0] + 1e-12:
                best = (gain, f, (a + b) / 2)
    return None if best[1] is None else best

Milestone 2: growing and using a tree

With a split search, a tree is a few lines of recursion, which is the algorithm of Breiman, Friedman, Olshen and Stone (1984): find the best split of the rows at this node; if there is none, or a limit applies, make a leaf holding the mean of y; otherwise partition the rows by the winning question and grow each child on its own rows, ignoring the rest of the data. The limits are the knobs of chapter 8: max_depth (the number of splits on the longest path) and min_leaf. A node whose y values are all equal stops too, since there is nothing left to explain.

Each node is a dictionary. Every node stores "n" (rows that reached it) and "value" (the mean of its y), and a split node also stores "feat", "thr", "gain" and its two children. The gain is stored for a reason that only pays off in milestone 5: it is how importances are computed. Prediction walks a row down the tree, going left when x[feat] <= thr, and returns the leaf's value. Here is a depth-3 tree grown on chapter 8's churn data by your grow, printed by the given show:

Look at the last line: allowed to grow to depth 20 with leaves of a single row, the same algorithm reaches 99.9% training accuracy with 160 leaves and falls to 80.2% on test rows. The label noise in this data is 12%, so the best possible accuracy is about 88%, and the shallow tree is within a rounding error of it.

Training accuracy can only rise as the tree deepens (each extra split refines the partition), which the check asserts. Test accuracy peaks at depth 3 and then falls: the extra splits are fitting which customers happened to be unlucky. A tree has no built-in sense of when to stop, so the stopping rule is yours; min_leaf is usually the better knob, because it demands evidence (many rows) for every rule. The check also demands that grow(..., "gini", ...) and grow(..., "mse", ...) build the same tree on 0/1 labels, which is the identity from milestone 1 seen at the level of the whole tree.

One argument of grow belongs to the next milestone: max_features with rng. When given, each node searches only a random subset of that many features, drawn with rng.sample. You can leave it unimplemented until milestone 3, and the starter's docstring says so.

def grow(X, y, criterion="gini", max_depth=3, min_leaf=1, max_features=None, rng=None, depth=0):
    """Grow a CART tree by greedy recursive splitting. Returns the root node (see the module docstring).

    Every node stores "n" and "value" (the mean of y). Stop and return a leaf when depth == max_depth, when y is
    constant, or when best_split finds nothing. A split node also stores "feat", "thr", "gain", "left", "right".
    If max_features is not None, each node searches only a random subset of that many features, drawn with
    rng.sample(range(n_features), max_features) (this is what milestone 3's forest uses).
    """
    node = {"n": len(y), "value": sum(y) / len(y)}
    if depth >= max_depth or min(y) == max(y):
        return node
    feats = None
    if max_features is not None and max_features < len(X[0]):
        feats = sorted(rng.sample(range(len(X[0])), max_features))
    s = best_split(X, y, criterion, min_leaf, feats)
    if s is None:
        return node
    gain, f, thr = s
    left = [i for i, row in enumerate(X) if row[f] <= thr]
    right = [i for i, row in enumerate(X) if row[f] > thr]
    node.update(feat=f, thr=thr, gain=gain,
                left=grow([X[i] for i in left], [y[i] for i in left], criterion, max_depth, min_leaf, max_features, rng, depth + 1),
                right=grow([X[i] for i in right], [y[i] for i in right], criterion, max_depth, min_leaf, max_features, rng, depth + 1))
    return node

def predict_one(node, x):
    """Walk one row down the tree and return the value of the leaf it lands in."""
    while "feat" in node:
        node = node["left"] if x[node["feat"]] <= node["thr"] else node["right"]
    return node["value"]

def predict_tree(node, X):
    """predict_one for every row."""
    return [predict_one(node, row) for row in X]

def depth_of(node):
    """Number of splits on the longest path from the root (a single leaf has depth 0)."""
    if "feat" not in node:
        return 0
    return 1 + max(depth_of(node["left"]), depth_of(node["right"]))

def n_leaves(node):
    """Number of leaves."""
    if "feat" not in node:
        return 1
    return n_leaves(node["left"]) + n_leaves(node["right"])

Milestone 3: bagging and the random forest

A deep tree has low bias and high variance: change a few rows and its shape changes. Bagging (Breiman, 1996, "Bagging Predictors") turns that instability into an asset. Draw a bootstrap sample: n rows chosen with replacement from the n you have, so some rows appear twice and about 37% (the limit of (1 − 1/n)n is 1/e) do not appear at all. Grow one deep tree on each of many such samples and average their predictions. Each tree is wrong in its own way, and the errors partly cancel.

The random forest (Breiman, 2001, "Random Forests") adds one more source of randomness, because bagged trees still look alike: a strong feature wins the first split of nearly every tree. At every split, only a random subset of max_features columns is considered, so different trees must find different routes to the signal, and their errors are less correlated. The check tests that the knob does something: with max_features=1 the root features of 40 trees must be varied (at least five different ones), and with all features available they must concentrate on the few strongest.

The bootstrap's leftover 37% is a gift. For any training row, about 37% of the trees never saw it, so you can predict it with only those trees and compare with its label. That out-of-bag (OOB) prediction is an honest estimate of generalisation error without holding any data back. The check verifies the definition exactly: for rows 0, 7 and 100, your OOB prediction must equal the average over precisely the trees whose bootstrap list does not contain the row, and with a single tree about 63% of rows must come back as None (the rows it drew have no tree to predict them).

The numbers on Friedman's benchmark (ten features uniform on [0, 1], of which only the first five matter, noise sd 1, so the best possible RMSE is 1.0): one unlimited tree scores 3.4 on 1,000 fresh test rows, a bagged ensemble of 40 trees 2.2, a forest with four features per split 2.3, and the OOB estimate lands within 20% of the test error on all three datasets. Note that a forest does not beat plain bagging here: with only five relevant features in ten, restricting each split to four of them costs some signal, and the benefit of decorrelation depends on the data. Chapter 9's mtry advice is a starting point to tune, not a law.

def bootstrap_sample(n, rng):
    """n row indices drawn uniformly WITH replacement from range(n)."""
    return [rng.randrange(n) for _ in range(n)]

def fit_forest(X, y, n_trees=50, max_features=None, max_depth=8, min_leaf=3, criterion="mse", seed=0):
    """A random forest: n_trees trees, each grown on its own bootstrap sample.

    rng = random.Random(seed) is used for everything (bootstrap samples first, then each tree's feature subsets).
    Returns a Forest holding the trees and, for every tree, the list of indices of its bootstrap sample.
    max_features=None means every feature at every split (plain bagging).
    """
    rng = random.Random(seed)
    forest = Forest()
    for _ in range(n_trees):
        idx = bootstrap_sample(len(y), rng)
        tree = grow([X[i] for i in idx], [y[i] for i in idx], criterion, max_depth, min_leaf, max_features, rng)
        forest.trees.append(tree)
        forest.bags.append(idx)
    return forest

def forest_predict(forest, X):
    """The average of the trees' predictions, row by row (for 0/1 labels this is a probability)."""
    per_tree = [predict_tree(t, X) for t in forest.trees]
    return [sum(col) / len(col) for col in zip(*per_tree)]

def oob_predict(forest, X):
    """Out-of-bag prediction for every row of X, which must be the training rows the forest was fitted on.

    Row i is predicted by the average over only those trees whose bootstrap sample did not contain i.
    Rows that every tree saw get None.
    """
    in_bag = [set(b) for b in forest.bags]
    out = []
    for i, row in enumerate(X):
        votes = [predict_one(t, row) for t, bag in zip(forest.trees, in_bag) if i not in bag]
        out.append(sum(votes) / len(votes) if votes else None)
    return out

def oob_rmse(forest, X, y):
    """RMSE of the out-of-bag predictions, over the rows that have one."""
    pred = oob_predict(forest, X)
    pairs = [(t, p) for t, p in zip(y, pred) if p is not None]
    return rmse([t for t, _ in pairs], [p for _, p in pairs])

Milestone 4: gradient boosting for regression

Bagging builds deep trees in parallel and averages away their variance. Boosting builds shallow trees in sequence and removes bias: each tree corrects what the ensemble so far gets wrong. With squared error it is almost embarrassingly simple, and it is chapter 9's algorithm: start from the constant F0 = mean(y); in each round compute the residuals y − F(x) (they are the negative gradient of the squared error with respect to the prediction, which is why this is gradient descent in function space), fit a small regression tree to them, and add a fraction lr (the learning rate or shrinkage) of its predictions to the running total.

Chapter 9's eight points make a hand check you can do on paper. The targets for x = 1 to 8 are 1.0, 1.6, 1.3, 3.0, 3.6, 3.1, 5.4, 4.9, whose mean is 2.9875 (RMSE 1.524 for the constant). The best stump on the residuals splits at x <= 3.5: the left residuals average −1.6875 and the right 1.0125. With lr = 0.5, the predictions become 2.9875 + 0.5 × (−1.6875) = 2.14375 on the left and 2.9875 + 0.5 × 1.0125 = 3.49375 on the right, and the RMSE falls to 1.021. Two more rounds give 0.597 and 0.428. The check asserts all of those, and a second property with no numbers in it: with lr = 1 and a tree deep enough to isolate every row, one round fits the training rows exactly.

Why take only a fraction of each tree? Because each tree is fitted to noisy residuals and is partly wrong; a full step commits to its mistakes, while many small steps average over many different mistakes. Training error can only fall (each tree is the best least-squares fit to the residuals, and any step from 0 to 1 of the way towards it helps), and the check asserts that for three learning rates. Validation error tells a different story, and it is what you stop on. The learning rate and the number of rounds are therefore one decision, not two: a smaller step needs more rounds and usually ends lower.

The scenario puts numbers on it, on Friedman data with depth-3 trees. At lr = 1.0 the validation error bottoms out at round 3 (2.98) and then climbs to 3.22 by round 500 while training error collapses. At lr = 0.1 it keeps improving until round 360 and reaches 1.74, 42% lower. The check demands the same shape on three datasets: the large step's best round under 25, the small step's more than eight times later and at least 15% lower, and a training error at round 500 less than half of the best validation error.

def fit_gbm(X, y, n_rounds=100, lr=0.1, max_depth=3, min_leaf=1):
    """Gradient boosting with squared error.

    Start from the constant f0 = mean(y). In each round compute the residuals y - F(x) (the negative gradient of
    the squared error), grow a regression tree ("mse" criterion, max_depth, min_leaf) on them, and add lr times
    that tree to the running predictions. Returns a GBM holding f0, lr and the n_rounds trees in order.
    """
    n = len(y)
    f0 = sum(y) / n
    F = [f0] * n
    model = GBM(f0, lr)
    for _ in range(n_rounds):
        resid = [yi - fi for yi, fi in zip(y, F)]
        tree = grow(X, resid, "mse", max_depth, min_leaf)
        model.trees.append(tree)
        F = [fi + lr * predict_one(tree, row) for fi, row in zip(F, X)]
    return model

def gbm_predict(model, X, n_rounds=None):
    """F(x) = f0 + lr * (sum of the first n_rounds trees' predictions); all rounds if n_rounds is None."""
    trees = model.trees if n_rounds is None else model.trees[:n_rounds]
    return [model.f0 + model.lr * sum(predict_one(t, row) for t in trees) for row in X]

def staged_rmse(model, X, y):
    """The RMSE on (X, y) after 1, 2, ..., M rounds, as a list of length M, in one pass over the trees."""
    F = [model.f0] * len(y)
    curve = []
    for tree in model.trees:
        F = [fi + model.lr * predict_one(tree, row) for fi, row in zip(F, X)]
        curve.append(rmse(y, F))
    return curve

def best_round(curve):
    """The 1-based round with the smallest value in the curve (the first one if there is a tie)."""
    return min(range(len(curve)), key=curve.__getitem__) + 1

Milestone 5: importances, and the three models side by side

A fitted forest of hundreds of trees cannot be read, but it can be asked which features it relied on. The standard answer is impurity importance: every split in every tree reduced the impurity of its node, so credit that reduction to the feature it used, weighted by the number of rows it affected (a gain on a node with 500 rows matters more than on one with 5). Per tree: for each split node, add n × gain to its feature, then divide by the total so that a tree's importances sum to 1 (a tree with no splits has nothing to share and reports all zeros, not a division error). For a forest, average the trees' normalised importances; for boosting, add up every tree's raw importance first, then normalise, since later trees are fitted to small residuals and should weigh less than the first ones.

On Friedman's data every model puts at least 85% of the credit on the five real features (boosting about 95%), as it should, with x3 (the linear term with coefficient 10) leading. Importances answer "how much splitting did this feature do", not "how does it change the prediction" (that is partial dependence, chapter 16), and the noise bars are never exactly zero: with enough rows and depth, a tree finds some chance cut worth a little gain on every column. The second stretch exercise below shows the worse case, where a noise feature with many distinct values outranks a genuinely useful binary one.

Then the shoot-out, the lab's last scenario: a mean-predictor, one depth-5 tree, a 60-tree forest, and boosting stopped by validation error, scored on 1,000 fresh test rows from the same generator. On the first dataset the check prints test RMSEs of 4.99, 3.18, 2.30 and 1.65 against a noise floor of 1.0, and demands that boosting beats the forest, which beats one tree, which beats the mean, on all three datasets. That ordering is no law of nature: it is what chapter 9 predicts for a smooth additive-plus-interaction target with a few hundred rows and a boosted model whose rounds were chosen on held-out data. On other data, a forest with almost no tuning can match a boosted model with a lot of it, which is why chapter 9 recommends the forest as the first, low-effort baseline.

def tree_importance_raw(node, d):
    """Total weighted impurity decrease per feature: for every split node add n_node * gain to its feature.
    Returns a list of d floats (not normalised)."""
    imp = [0.0] * d

    def walk(nd):
        if "feat" in nd:
            imp[nd["feat"]] += nd["n"] * nd["gain"]
            walk(nd["left"])
            walk(nd["right"])

    walk(node)
    return imp

def normalise(v):
    """Scale a list of non-negative numbers to sum to 1 (all zeros stay all zeros)."""
    s = sum(v)
    return [x / s for x in v] if s > 0 else [0.0] * len(v)

def tree_importance(node, d):
    """Feature importances of one tree: tree_importance_raw, normalised to sum to 1."""
    return normalise(tree_importance_raw(node, d))

def forest_importance(forest, d):
    """The average of the trees' normalised importances."""
    per = [tree_importance(t, d) for t in forest.trees]
    return [sum(col) / len(per) for col in zip(*per)]

def gbm_importance(model, d):
    """Boosting importances: add up every tree's raw importance, then normalise."""
    total = [0.0] * d
    for t in model.trees:
        total = [a + b for a, b in zip(total, tree_importance_raw(t, d))]
    return normalise(total)

Systems connection

A tree ensemble is, at serving time, a few hundred small data structures traversed with comparisons: no matrix multiplications, no GPU. That is why a boosted model can score a request in microseconds on a CPU and sit inside a tight latency budget, and why the dominant cost is often fetching the features, not evaluating the model. Training is the opposite shape: the split search over many features is embarrassingly parallel, which is what the libraries exploit across cores and, for large data, across machines. Your fit_forest trees share no state, so they could run in separate processes without changing the answer, the property that makes bagging easy to scale and boosting (strictly sequential across rounds) harder.

What you learned

  • A tree is one function applied recursively: sort a feature, sweep every cut with running sums, take the biggest impurity decrease. Gini and variance choose the same splits on 0/1 labels. Zero gain means no split, so a greedy tree cannot see XOR.
  • An unlimited tree memorises its training rows; test accuracy peaks at a shallow depth, and max_depth and min_leaf are the controls. Trees cannot extrapolate beyond the training range.
  • Bagging averages deep trees fitted to bootstrap samples; a forest adds random feature subsets per split. Each tree misses about 37% of rows, and predicting each row with only those trees gives a free out-of-bag error estimate.
  • Gradient boosting fits small trees to residuals and adds a fraction lr of each. Training error only falls; validation error has a minimum, and a smaller learning rate with more rounds usually reaches a lower one, so stop on validation error.
  • Impurity importance credits each split's weighted gain to its feature. It agrees across models on clean data and flatters continuous noise columns on small leaves, so confirm important features with permutation importance.

Ten customers sorted by tenure have churn flags 1 1 1 0 1 0 0 0 1 0. The cut at tenure <= 23 puts eight customers on the left (four churners) and two on the right (one churner). What is its Gini gain?

  1. About 0.21, the same as the best cut at tenure <= 6
  2. Zero: both children have a churn rate of 50%, the same mixture as the parent
  3. About 0.05, because the right child is nearly pure
  4. Negative, because the split creates a small leaf
The left child has 4 of 8 churners and the right has 1 of 2, so both children have a churn rate of 0.5, exactly the parent's, and the weighted Gini is 0.5. Gain is parent minus weighted children, so zero. A split can never have negative gain (impurity is concave), and a "nearly pure" look can be misleading when the leaf is tiny.

A single decision tree is grown with no depth limit and min_leaf=1 on noisy training data. Compared with a depth-3 tree, what do you expect?

  1. Lower training accuracy and higher test accuracy, because the deeper tree is more careful
  2. The same test accuracy, because both pick the same first splits
  3. Lower test accuracy and lower training accuracy, because the deep tree is unstable
  4. Higher training accuracy (near 100%) and usually lower test accuracy, because the extra splits fit noise
Each additional split can only refine the partition, so training accuracy never falls, and with single-row leaves it reaches about 100%. The splits beyond the real structure carve up noise, so test accuracy typically falls (0.886 at depth 3 to 0.802 at depth 20 in the lab). The shared first splits (option 2) are true but irrelevant to what the extra splits then do.

In a random forest of 200 trees, row 17 of the training set was drawn into the bootstrap samples of 126 of them. How is its out-of-bag prediction computed?

  1. Average the predictions of the 74 trees whose bootstrap sample did not include row 17
  2. Average the predictions of all 200 trees, since each tree saw most of the data
  3. Average the 126 trees that did include it, because they know it best
  4. Refit a tree on the remaining rows and predict row 17 with it
An honest estimate of how the forest does on a row it was not trained on must use only trees that never saw the row: here the 74 that left it out. Using all 200 or the 126 that included it would be partly evaluating on training data. The out-of-bag estimate needs no refitting at all, which is its appeal.

A gradient-boosted model with lr=1.0 and depth-3 trees reaches its lowest validation error at round 3 and then worsens, while its training error keeps falling. Which change is most likely to give a better model?

  1. Train for more rounds, since the training error is still improving
  2. Pick the number of rounds by training error instead
  3. Lower the learning rate (say to 0.1), allow more rounds, and stop at the best validation round
  4. Raise the learning rate so that each tree corrects more of the error
A full step commits to each tree's mistakes on noisy residuals. A smaller step averages over many different mistakes and typically bottoms out later and lower (1.74 at round 360 against 2.98 at round 3 in the lab). More rounds or a higher rate make the overfitting worse, and training error always falls, so it cannot choose the stopping round.

Your fit_gbm updates its running predictions with the full tree output, but gbm_predict multiplies each tree by lr. With lr = 0.5, which symptom appears?

  1. Every prediction is exactly twice as large as it should be
  2. One round matches the hand values, but from round two the residuals, and so the trees, are the wrong ones and the RMSE no longer follows the expected sequence
  3. The model cannot overfit, because the learning rate is ignored
  4. The model raises an exception because the shapes disagree
With one round the training update never matters (the next residuals are not needed), so a one-round check passes. From round two the residuals are computed from predictions that are too large, so the later trees correct the wrong thing.
