Target leakage is a column that is a consequence or a proxy of the label, such as a flag written during the cancellation call. Two cheap checks find it: score each column alone, since honest features are rarely near perfect, and read the feature register, which says when each column is written relative to the prediction time.

column_auc_scan reuses your roc_auc on one column at a time. It reports the distance from 0.5, not the AUC, because a column that ranks perfectly backwards leaks as much as one that ranks perfectly. In suspects a distance exactly on the threshold counts; 0.30 is a judgement that flags AUC 0.96 and spares a strong honest column at 0.70. audit_register needs no data, so it catches a late column too weak for the scan, while only the scan catches a wrongly recorded lag.

AUC 0.96 or 0.04: distance 0.46, flagged.   AUC 0.70: distance 0.20, fine.
lag_days 9 with AUC 0.55: the scan misses it, the register catches it
