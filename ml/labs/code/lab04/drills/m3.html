Choosing features is a learning step, so it belongs inside each fold, using that fold's training rows only. Done once on all rows first, it lets the validation rows help choose: among 300 noise columns some correlate with the labels by luck, and choosing the best ten with all the labels in view keeps exactly those.

select_top_k ranks columns by the size of their correlation with the labels, a number from -1 to 1 for how closely a column rises and falls with them; the sign does not matter. cv_with_selection is the experiment itself: the same selection done once on all rows (the leak) or inside each fold. shuffle_test needs no knowledge of which step is guilty: feed the team's whole validation function randomly permuted labels. They carry no signal, so a procedure that scores well on them is fitting its own validation labels.

coin-flip labels, 100 rows, 300 noise columns, keep 10, 5-fold AUC:
select on all rows 0.81     select inside each fold 0.46 (honest: 0.5)
