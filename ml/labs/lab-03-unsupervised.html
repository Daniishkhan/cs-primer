Lab 3: k-means, PCA & Anomalies

Chapters 10 to 12 gave you three ways to find structure without a target: k-means groups rows around centres, PCA finds the few directions that carry the variance, and an isolation forest scores how quickly a row can be cut off from the rest. In this lab you build all three from first principles on plain Python lists, then point them at one fleet of sensors in which each tool sees a different kind of strange reading and is blind to the others. A checker compares every function with hand-worked values from the chapters, independent oracles and properties the answer must have, and says which mistake you probably made.

Why this lab matters

Unsupervised methods have no score to check against, so the only defence against fooling yourself is knowing what they do. That is easy to say and hard to feel from a library call. Writing Lloyd's loop yourself shows why inertia can never rise, why the starting centres decide which local optimum you land in, and why n_init exists. Writing power iteration shows that PCA is a repeated matrix multiplication whose speed depends on a ratio of eigenvalues, which explains why the low-variance components at the tail of a PCA are the shaky ones. Growing an isolation tree shows that an anomaly score is nothing more mysterious than a path length. The last milestone is the one that matters in practice: three detectors, three blind spots, and the arithmetic of how many false alarms a rare event produces.

These are also the parts inside bigger systems. k-means partitions the vectors in an IVF index (approximate nearest-neighbour search), PCA is the oldest embedding compressor, and a residual or path-length score is the first alert many monitoring pipelines try.

Milestone 1: Lloyd's algorithm

k-means divides n rows into k groups by choosing k centres (also called centroids) so that the total squared distance from each row to its nearest centre is as small as possible. That total is the inertia, also called the within-cluster sum of squares. Finding the best centres is hard in general, but Lloyd's algorithm (chapter 10) finds a good set quickly by alternating two easy steps:

  1. Assign. Give every row to its nearest centre.
  2. Update. Move every centre to the mean of the rows assigned to it.

Repeat until the assignment stops changing. Each half can only lower the inertia or leave it alone. Reassigning a row to a nearer centre shrinks that row's term. And the mean of a set of points is the position that minimises the sum of squared distances to them, so moving a centre to the mean shrinks the sum over its rows (the calculus is in derivatives: differentiate ∑(xi − c)2 with respect to c and set it to zero). Inertia cannot go below zero and there are finitely many assignments, so the loop must stop. It stops at a local minimum, which is not always the best one; that is milestone 2's problem.

Here is a complete run on four one-dimensional rows at 0, 1, 4 and 5, with the two starting centres at 0 and 1:

StepCentresLabels of rows 0, 1, 4, 5Inertia
assign to the start0, 10, 1, 1, 10 + 0 + 9 + 16 = 25
update, then assign0, (1 + 4 + 5)/3 = 3.330, 0, 1, 10 + 1 + 0.44 + 2.78 = 4.22
update, then assign0.5, 4.50, 0, 1, 14 × 0.25 = 1.0

Row 1 is the interesting one. At the start it sits exactly on centre 1, so it joins the cluster of 4 and 5. Once that centre moves to 3.33, row 1 is closer to centre 0 (distance 1 against 2.33), and the next update pulls both centres to where they belong. This is the same walk that check.py asks for, and the history it expects is [25.0, 4.222, 1.0].

Three details make the function deterministic and safe. Compare squared distances: the nearest centre by squared distance is the nearest by distance, and you skip a square root per comparison. Ties go to the lower index, so a row halfway between two centres is not a coin flip. And an empty cluster keeps its old centre: a centre that attracts no rows has no mean to move to, and dividing by zero is the classic crash.

def sq_dist(a, b):
    """Squared Euclidean distance between two rows: sum_j (a_j - b_j)^2."""
    return sum((x - y) ** 2 for x, y in zip(a, b))


def assign(X, centres):
    """labels[i] = index of the centre nearest to X[i] (squared distance). Ties go to the lower index."""
    labels = []
    for x in X:
        best, best_d = 0, sq_dist(x, centres[0])
        for j in range(1, len(centres)):
            d = sq_dist(x, centres[j])
            if d < best_d:                  # strict: an exact tie keeps the lower index
                best, best_d = j, d
        labels.append(best)
    return labels


def update_centres(X, labels, centres):
    """New centres: the mean of the rows assigned to each centre. A centre that got no rows keeps its old position.

    Returns a new list of k rows; `centres` is not modified.
    """
    k, p = len(centres), len(centres[0])
    sums = [[0.0] * p for _ in range(k)]
    counts = [0] * k
    for x, j in zip(X, labels):
        counts[j] += 1
        for c in range(p):
            sums[j][c] += x[c]
    return [[s / counts[j] for s in sums[j]] if counts[j] else list(centres[j]) for j in range(k)]


def inertia(X, labels, centres):
    """Sum over rows of the squared distance to the row's own centre."""
    return sum(sq_dist(x, centres[j]) for x, j in zip(X, labels))


def lloyd(X, centres, max_iter=100):
    """Lloyd's algorithm from the given starting centres: assign, update, repeat until the labels stop changing.

    Returns a KMeansResult. history[0] is the inertia of the first assignment; every round then appends the
    inertia after updating the centres and re-assigning. The history never increases. n_iter counts the
    update rounds (the round that confirms nothing moved is included). `centres` is not modified.
    """
    centres = [list(c) for c in centres]
    labels = assign(X, centres)
    history = [inertia(X, labels, centres)]
    n_iter = 0
    for n_iter in range(1, max_iter + 1):
        centres = update_centres(X, labels, centres)
        new_labels = assign(X, centres)
        history.append(inertia(X, new_labels, centres))
        changed = new_labels != labels
        labels = new_labels
        if not changed:
            break
    return KMeansResult(centres, labels, history[-1], n_iter, history)

Milestone 2: k-means++, restarts and the silhouette

Lloyd's algorithm is a descent, and a descent ends in whichever valley it started in. With six well-separated groups and six random starting centres, it is likely that two centres begin in one group and none in another. The loop then settles with one group split in two and two groups sharing a centre, which is a local minimum with a much larger inertia than the right answer. Chapter 10 measured this: with plain random rows as starts, 131 of 300 single runs ended more than 10% above the best.

k-means++ (Arthur and Vassilvitskii, 2007, "k-means++: The Advantages of Careful Seeding") chooses the starting centres to be far apart. Take the first centre uniformly at random from the rows. Then, for each later centre, compute D(x), the distance from every row to its nearest centre chosen so far, and pick the next centre with probability proportional to D(x)2. A row that is already a centre has D = 0 and can never be chosen again; a row far from every centre has a large D2 and is very likely to be chosen. Drawing from such a distribution is a walk along a strip:

Take four rows at 0, 1, 10 and 11 and suppose row 0 is the first centre. The squared distances to it are 0, 1, 100 and 121, a total of 222. Draw a random number between 0 and 1, multiply by 222, and take the first row whose running total exceeds the result. A draw of 0.5 gives 111, which lies beyond the running totals 0, 1 and 101 and inside row 3, so the second centre is the row at 11. This is exactly how the checker tests you: it hands your function a scripted random generator that returns 0 from randrange and 0.5, then 0.75, from random, and compares the centres you return with the ones worked out by hand. For the third centre D is the distance to the nearest of two centres (0 and 11), so the squared distances are 0, 1, 1, 0, and the draw 0.75 × 2 = 1.5 picks row 2. Keeping a running minimum of D2, rather than recomputing it against the latest centre only, is the part most often written wrong.

Even k-means++ does not remove bad runs, only makes them rarer, so the standard practice is restarts: run the whole algorithm several times (n_init in scikit-learn) and keep the run with the lowest inertia. Here is what that buys on chapter 10's six-group data, measured against the inertia of the true grouping:

(The median of 0.98 means the best runs beat the nominal centres, because the true grouping's centres are not exactly the group means.) The checker repeats this experiment and requires n_init=10 to land within 2% of the true grouping's inertia on three datasets, and requires that more restarts never do worse with the same seed. That second property is why the contract says one random.Random(seed) feeds all the restarts in order: the first restart of a ten-restart run is then identical to a one-restart run.

The last two functions help with the awkward question of how many clusters there are. Inertia always falls as k grows (at k = n it is zero), so it cannot choose k on its own. The silhouette score can. For each row, let a be its mean distance to the other rows in its own cluster and b the smallest mean distance to the rows of any other cluster. Then s = (b − a)/max(a, b), which is near 1 for a row deep inside a tight, separate cluster, near 0 for a row on a boundary and negative for a row that looks closer to another cluster. The mean over all rows is the silhouette of the clustering. For rows at 0, 1, 10 and 11 split into the pairs {0, 1} and {10, 11}, row 0 has a = 1 and b = 10.5, so s = 0.905; row 1 has b = 9.5, so s = 0.895; the other two mirror these, and the mean is 0.900. A row alone in its cluster is defined to have s = 0.

def kmeans_pp_init(X, k, rng):
    """k-means++ seeding (Arthur and Vassilvitskii, 2007). Returns k starting centres (copies of rows of X).

    The first centre is X[rng.randrange(n)]. Each later centre is drawn with probability proportional to D(x)^2,
    the squared distance from x to its nearest centre chosen so far. Draw it exactly like this, so a scripted
    rng reproduces your choice: r = rng.random() * total, then take the first row whose running total of
    D^2 exceeds r. If the total is 0 (every row already is a centre), take rng.randrange(n) instead.
    """
    n = len(X)
    centres = [list(X[rng.randrange(n)])]
    d2 = [sq_dist(x, centres[0]) for x in X]
    while len(centres) < k:
        total = sum(d2)
        if total == 0:
            pick = rng.randrange(n)
        else:
            r = rng.random() * total
            acc, pick = 0.0, n - 1
            for i, w in enumerate(d2):
                acc += w
                if acc > r:
                    pick = i
                    break
        centres.append(list(X[pick]))
        d2 = [min(w, sq_dist(x, centres[-1])) for w, x in zip(d2, X)]
    return centres


def kmeans(X, k, seed, n_init=10, max_iter=100):
    """The best of n_init runs of Lloyd's algorithm, each from its own k-means++ start.

    One random.Random(seed) feeds all the restarts, in order. 'Best' is the lowest final inertia; on an
    exact tie keep the earlier run. Returns a KMeansResult.
    """
    rng = random.Random(seed)
    best = None
    for _ in range(n_init):
        res = lloyd(X, kmeans_pp_init(X, k, rng), max_iter)
        if best is None or res.inertia < best.inertia:
            best = res
    return best


def silhouette(X, labels):
    """Mean silhouette coefficient (Euclidean distance, not squared).

    For row i: a = mean distance to the other rows of its own cluster, b = the smallest, over the other
    clusters, of the mean distance to that cluster's rows, and s = (b - a) / max(a, b). A row alone in its
    cluster has s = 0. With fewer than two clusters return 0.0.
    """
    clusters = sorted(set(labels))
    if len(clusters) < 2:
        return 0.0
    members = {c: [i for i, l in enumerate(labels) if l == c] for c in clusters}
    total = 0.0
    for i, x in enumerate(X):
        own = members[labels[i]]
        if len(own) == 1:
            continue
        a = sum(math.sqrt(sq_dist(x, X[j])) for j in own if j != i) / (len(own) - 1)
        b = min(sum(math.sqrt(sq_dist(x, X[j])) for j in members[c]) / len(members[c])
                for c in clusters if c != labels[i])
        total += (b - a) / max(a, b)
    return total / len(X)


def sweep_k(X, ks, seed=0, n_init=5):
    """For each k in ks run kmeans(X, k, seed, n_init) and return a list of (k, inertia, silhouette)."""
    out = []
    for k in ks:
        res = kmeans(X, k, seed, n_init)
        out.append((k, res.inertia, silhouette(X, res.labels)))
    return out

Milestone 3: PCA by power iteration

Principal component analysis (chapter 11) looks for the direction through the centred data in which it spreads the most, then the most spread among directions at right angles to it, and so on. Those directions are the principal components. The algebra reduces the search to an eigenvector problem. Centre the data matrix X (subtract each column's mean) and form the covariance matrix C = XTX/(n − 1), a p × p symmetric matrix whose diagonal holds the column variances and whose off-diagonal entries record how pairs of columns move together. The variance of the data projected on a unit direction v is vTCv, and the direction that maximises it is the eigenvector of C with the largest eigenvalue λ, which is also the variance along it (see eigenvectors, SVD and low rank).

Libraries use the SVD. You will use something plainer that needs only multiplication, power iteration. Start from any non-zero vector v. Multiply by C and rescale to length 1. Repeat. Why does that find the top eigenvector? Write the start vector as a mix of the eigenvectors, v = c1e1 + c2e2 + …. One multiplication by C scales each piece by its own eigenvalue, so after t multiplications the mix is c1λ1te1 + c2λ2te2 + …. Dividing by λ1t, every piece except the first shrinks like (λi/λ1)t. The biggest eigenvalue wins, at a speed set by the ratio of the second to the first. Here is C = [[2, 1], [1, 2]] (eigenvalues 3 and 1) starting from (1, 0):

"""Power iteration by hand on C = [[2, 1], [1, 2]] (eigenvalues 3 and 1, eigenvectors (1, 1) and (1, -1))."""
import math
C = [[2.0, 1.0], [1.0, 2.0]]
v = [1.0, 0.0]
print("step   v                      angle to (1, 1) in degrees   Rayleigh quotient")
for step in range(0, 7):
    w = [C[0][0] * v[0] + C[0][1] * v[1], C[1][0] * v[0] + C[1][1] * v[1]]
    lam = (v[0] * w[0] + v[1] * w[1]) / (v[0] ** 2 + v[1] ** 2)
    ang = math.degrees(math.atan2(v[1], v[0])) - 45
    print(f"{step:4d}   ({v[0]:.4f}, {v[1]:.4f})         {abs(ang):10.4f}                   {lam:.5f}")
    n = math.hypot(*w)
    v = [w[0] / n, w[1] / n]

The angle to the true eigenvector (1, 1)/√2 shrinks by a factor of 3 each step, the ratio λ1/λ2, and the Rayleigh quotient vTCv (the estimate of λ) converges even faster because it is quadratic in the angle. After six steps the eigenvalue estimate is good to five decimals and the vector to about three.

The figure shows why this matters for the later components. The three curves are real runs of the same loop on matrices whose second eigenvalue is one third, 0.9 and 0.99 of the first. Well-separated eigenvalues converge in a dozen steps; a ratio of 0.99 has barely moved after forty. In the factor data of chapter 11 the three real components are well separated from each other and from the noise, but the five noise eigenvalues are nearly tied, so asking this routine for a fourth component is asking for an answer that depends on the starting vector. That is a property of the problem, not of the method: nearly tied eigenvalues mean the directions themselves are ill-defined.

To get the second component, remove the first. Deflation subtracts the part of C that the found pair explains: C − λvvT has the same eigenvectors as C, except that v now has eigenvalue 0, so power iteration on it finds the next largest. Do it k times and you have k components. Two conventions keep the answer unique: an eigenvector can be flipped to its negative and still be an eigenvector, so the contract fixes the sign (the entry with the largest magnitude is positive), and the starting vector comes from the generator you are given, so the same seed gives the same run.

With components in hand, project turns each centred row into k scores (its dot product with each component) and reconstruct maps scores back into the original columns by adding the mean back. One identity ties everything together, and the checker uses it as a test: the squared reconstruction error summed over all rows and columns, divided by n − 1, equals the total variance minus the variance of the components you kept. Here is chapter 11's setting, 400 rows of 8 columns built from three hidden factors with standard deviations 3, 2 and 1 plus noise of standard deviation 0.5:

"""PCA by power iteration on chapter 11's factor data: 400 rows, 8 columns, 3 hidden factors."""

  • If the variances look right but the identity fails, check that reconstruct adds the mean back and that project subtracts it.

def column_means(X):
    """Mean of each column."""
    n = len(X)
    return [sum(row[c] for row in X) / n for c in range(len(X[0]))]


def covariance(X):
    """Sample covariance matrix (p x p, list of rows) with the n - 1 denominator. Centres X itself."""
    n, p = len(X), len(X[0])
    mu = column_means(X)
    Xc = [[row[c] - mu[c] for c in range(p)] for row in X]
    return [[sum(r[a] * r[b] for r in Xc) / (n - 1) for b in range(p)] for a in range(p)]


def power_iteration(C, rng, max_iter=10000, tol=1e-12):
    """Dominant eigenpair of a symmetric positive semi-definite matrix C by power iteration.

    Start from a random vector [rng.gauss(0, 1) for each column], then repeat: v <- C v / |C v|, until the
    vector moves by less than tol (Euclidean distance) in one step, or max_iter steps. Return (lam, v) where v
    has unit length and lam = v^T C v. Fix the sign so the entry of v with the largest magnitude is positive.
    If C v is the zero vector (C is zero) return (0.0, v) with v the unit start vector.
    """
    p = len(C)
    v = [rng.gauss(0, 1) for _ in range(p)]
    nv = norm(v)
    v = [x / nv for x in v]
    for _ in range(max_iter):
        w = mat_vec(C, v)
        nw = norm(w)
        if nw == 0:
            return 0.0, v
        w = [x / nw for x in w]
        moved = norm([a - b for a, b in zip(w, v)])
        v = w
        if moved < tol:
            break
    lam = dot(v, mat_vec(C, v))
    big = max(range(p), key=lambda i: abs(v[i]))
    if v[big] < 0:
        v = [-x for x in v]
    return lam, v


def deflate(C, lam, v):
    """Remove the eigenpair (lam, v) from C: return C - lam * v v^T as a new matrix."""
    p = len(C)
    return [[C[a][b] - lam * v[a] * v[b] for b in range(p)] for a in range(p)]


def pca(X, k, seed=0):
    """The first k principal components of X by repeated power iteration with deflation.

    One random.Random(seed) feeds all k power iterations, in order. Returns a PCAModel: the column means, the
    k components (unit length, sign as in power_iteration), their variances (eigenvalues of the covariance
    matrix) and the total variance (the trace of the covariance matrix, computed before any deflation).
    """
    rng = random.Random(seed)
    C = covariance(X)
    total = sum(C[i][i] for i in range(len(C)))
    comps, variances = [], []
    for _ in range(k):
        lam, v = power_iteration(C, rng)
        comps.append(v)
        variances.append(lam)
        C = deflate(C, lam, v)
    return PCAModel(column_means(X), comps, variances, total)


def project(X, model):
    """Scores: row i -> [ (x_i - mean) . component_j  for each component j ]."""
    return [[dot([a - m for a, m in zip(x, model.mean)], comp) for comp in model.components] for x in X]


def reconstruct(Z, model):
    """Map scores back to the original columns: mean + sum_j z_j * component_j."""
    p = len(model.mean)
    return [[model.mean[c] + sum(z[j] * model.components[j][c] for j in range(len(z))) for c in range(p)] for z in Z]

Milestone 4: an isolation-forest score

Every method so far models what normal looks like and measures a distance from it. The isolation forest (Liu, Ting and Zhou, 2008, "Isolation Forest", ICDM) turns the idea round: anomalies are few and different, so they should be easy to separate from the crowd. Grow a random binary tree on a subsample of rows. At each node pick a column at random, pick a cut value uniformly between that column's minimum and maximum in the node, and send rows with a smaller value left and the rest right. Stop when a row is alone, when the node's depth reaches a limit, or when the chosen column is constant. A row in an empty region of space is alone after a few cuts; a row in the middle of a crowd takes many. The number of cuts to reach a row's leaf is its path length h(x), and averaging it over many trees gives a stable measure.

Here is the smallest worked example, with the five values 0, 1, 2, 3 and 100 and cuts at the midpoints (the checker uses a scripted generator that always picks column 0 and the midpoint, so you can follow it by hand):

Two refinements turn path lengths into a score. First, the depth limit is only ceil(log2 ψ) for a subsample of ψ rows, because we care about rows that are isolated early; a leaf that still holds several rows stands for the cuts that were never made. A leaf of size s is charged c(s) extra, where c(n) = 2(ln(n − 1) + 0.5772) − 2(n − 1)/n is the average path length of an unsuccessful search in a binary search tree of n items (chapter 12's form), with c(n) = 0 for n ≤ 1. Second, the raw average depends on ψ, so it is normalised: s(x) = 2−E[h(x)]/c(ψ). If a row takes about as many cuts as the typical c(ψ), the exponent is −1 and the score is 0.5; a row isolated in far fewer cuts scores towards 1; a row buried deeper than average scores below 0.5. Using the paper's exact harmonic-number form, c(2) would be 1 where the approximation gives 0.154; the two differ only for tiny nodes, which the depth limit makes rare.

def c_factor(n):
    """c(n): the average path length of an unsuccessful search in a binary search tree of n rows.

    c(n) = 2 (ln(n - 1) + 0.5772156649) - 2 (n - 1) / n for n > 1, and 0 for n <= 1. Chapter 12 uses this form.
    """
    if n <= 1:
        return 0.0
    return 2 * (math.log(n - 1) + 0.5772156649) - 2 * (n - 1) / n


def build_tree(S, depth, limit, rng):
    """One isolation tree grown on the rows S (a list of rows). Nodes are dicts.

    A leaf is {"size": len(S)}; make a leaf when depth >= limit, when len(S) <= 1, or when the chosen
    column is constant over S. Otherwise draw, in this order, j = rng.randrange(p), then (after finding the
    minimum and maximum of column j in S) t = rng.uniform(lo, hi), and return
    {"feat": j, "thr": t, "left": <rows with x[j] < t>, "right": <rows with x[j] >= t>}, each child grown with
    depth + 1.
    """
    n = len(S)
    if depth >= limit or n <= 1:
        return {"size": n}
    j = rng.randrange(len(S[0]))
    lo = min(r[j] for r in S)
    hi = max(r[j] for r in S)
    if lo == hi:
        return {"size": n}
    t = rng.uniform(lo, hi)
    left = [r for r in S if r[j] < t]
    right = [r for r in S if r[j] >= t]
    return {"feat": j, "thr": t,
            "left": build_tree(left, depth + 1, limit, rng),
            "right": build_tree(right, depth + 1, limit, rng)}


def path_length(x, node, depth=0):
    """h(x): the depth at which x reaches a leaf, plus c(leaf size) for the cuts the depth limit stopped."""
    while "feat" in node:
        node = node["left"] if x[node["feat"]] < node["thr"] else node["right"]
        depth += 1
    return depth + c_factor(node["size"])


def fit_iforest(X, n_trees=100, psi=128, seed=0):
    """An isolation forest: n_trees trees, each grown on psi rows drawn without replacement.

    psi is capped at len(X). The depth limit is ceil(log2(psi)). One random.Random(seed) does everything: for
    each tree, S = rng.sample(X, psi), then build_tree(S, 0, limit, rng).
    """
    rng = random.Random(seed)
    psi = min(psi, len(X))
    limit = math.ceil(math.log2(psi)) if psi > 1 else 0
    trees = [build_tree(rng.sample(X, psi), 0, limit, rng) for _ in range(n_trees)]
    return IForest(trees, psi)


def anomaly_score(forest, x):
    """s(x) = 2 ** (-E[h(x)] / c(psi)), where E[h(x)] is the mean path length over the forest's trees.

    Near 1: isolated much faster than average. About 0.5: average. Below 0.5: harder to isolate than most.
    """
    mean_h = sum(path_length(x, t) for t in forest.trees) / len(forest.trees)
    return 2 ** (-mean_h / c_factor(forest.psi))

Milestone 5: three detectors, one list

Now use everything on one problem. A fleet of sensors reports four numbers each. In normal operation the readings lie on a flat two-dimensional plane inside the four-dimensional space, in three operating modes: wide in the plane (standard deviation 1.2) and almost flat off it (0.15). The data, from make_sensors, has 600 normal readings and 36 anomalies of three kinds, 12 each, that a real fleet would produce:

  • Far away: a unit running at a crazy setting, 13 to 16 units from the middle, still on the plane.
  • In between: a unit stuck mid-transition, in the empty gap between the three modes, still on the plane.
  • Off the plane: a broken sensor channel. The reading is inside a mode's footprint on the plane, but lifted 0.9 off it. Each coordinate on its own looks ordinary.

Each detector turns every row into a score where larger means stranger. k-means as a detector scores a row by its Euclidean distance to the nearest centre. PCA scores it by its squared reconstruction error with two components, the part of the reading the plane cannot explain. The isolation forest uses the score you just built. A detector's strength is the kind of strangeness it measures: far-away and in-between readings are far from every centre but exactly on the plane, so PCA reconstructs them perfectly; off-plane readings are close to a centre in the plane but far from it in the direction PCA discards.

The three scores live on different scales (distances, squared errors, values between 0 and 1), so they cannot be compared directly. Rank-normalisation fixes that: replace each score by its rank divided by the number of rows, so the strangest row of each detector gets 1.0. Taking the largest rank-normalised value per row gives a combined score that is high whenever any detector is alarmed. To judge detectors, use the AUC from chapter 12 (given as auc): the chance that a random anomaly outscores a random normal row, computed here separately for each kind. Then precision_at_k asks the question a review team lives with: of the k rows we send to a person, how many were real?

def centre_distance_scores(X, result):
    """k-means as a detector: each row's Euclidean distance (not squared) to its nearest centre."""
    return [math.sqrt(sq_dist(x, result.centres[j])) for x, j in zip(X, assign(X, result.centres))]


def pca_residual_scores(X, model):
    """PCA as a detector: each row's squared reconstruction error, sum over columns of (x - x_hat)^2."""
    Xhat = reconstruct(project(X, model), model)
    return [sq_dist(x, xh) for x, xh in zip(X, Xhat)]


def rank_normalise(scores):
    """Replace each score by its average rank divided by n, so the largest score becomes 1.0.

    rank_normalise([10, 30, 20]) is [1/3, 1, 2/3]; tied scores share an average rank.
    """
    n = len(scores)
    return [r / n for r in average_ranks(scores)]


def combine_max(score_lists):
    """Rank-normalise each list of scores, then take the largest value per row across the lists."""
    normed = [rank_normalise(s) for s in score_lists]
    return [max(col) for col in zip(*normed)]


def precision_at_k(scores, positive, k):
    """Fraction of the k highest-scoring rows that are positive. Ties are broken by the lower row index."""
    order = sorted(range(len(scores)), key=lambda i: (-scores[i], i))[:k]
    return sum(1 for i in order if positive[i]) / k


def expected_alerts(n, base_rate, tpr, fpr):
    """The base-rate arithmetic of chapter 12. n rows, a fraction base_rate of them anomalous; the detector
    flags a fraction tpr of the anomalies and a fraction fpr of the normal rows.

    Returns (true_alerts, false_alerts, precision) where precision = true / (true + false).
    """
    true_alerts = n * base_rate * tpr
    false_alerts = n * (1 - base_rate) * fpr
    return true_alerts, false_alerts, true_alerts / (true_alerts + false_alerts)


def run_detectors(X, seed=0):
    """Fit the three unsupervised detectors on X and return {name: scores} for "kmeans", "pca", "iforest"
    and "combined". Use kmeans(X, 3, seed, n_init=5), pca(X, 2, seed), fit_iforest(X, 100, 128, seed); score
    with centre_distance_scores, pca_residual_scores and anomaly_score; "combined" is combine_max of the three.
    """
    km = kmeans(X, 3, seed, n_init=5)
    model = pca(X, 2, seed)
    forest = fit_iforest(X, 100, 128, seed)
    s_km = centre_distance_scores(X, km)
    s_pca = pca_residual_scores(X, model)
    s_if = [anomaly_score(forest, x) for x in X]
    return {"kmeans": s_km, "pca": s_pca, "iforest": s_if, "combined": combine_max([s_km, s_pca, s_if])}

Look under the hood

  • Why k-means++ is more than a heuristic. Arthur and Vassilvitskii prove that the seeding alone gives an inertia within a factor of O(log k) of the best possible, in expectation, before Lloyd's algorithm runs at all. Plain random starts have no such guarantee. The restarts then buy robustness against the unlucky draw that the expectation hides.
  • Power iteration versus the SVD. One step costs p2 multiplications for a p-column matrix, and the number of steps depends on the eigenvalue ratio, so it is a good fit when you want the top few components of a large sparse matrix and a poor fit when eigenvalues are nearly tied. Libraries use the SVD of the centred matrix or the covariance eigenproblem, which cost more but do not care about ratios. The checker's Jacobi solver is a third route, rotating pairs of axes until the matrix is diagonal.
  • The detectors were trained on the data they score. run_detectors fits on all 636 rows, anomalies included, which is the outlier-detection set-up of chapter 12. The 5.7% contamination barely moves the plane, as the first experiment below shows. With heavy contamination you would fit on a believed-clean sample (novelty detection) instead.
  • Where this sits in scikit-learn. The equivalents are below. Two conventions differ from this lab: score_samples on an IsolationForest returns the negative of the score defined here (lower means more abnormal), and the library's PCA is built on the SVD.
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.ensemble import IsolationForest

km = KMeans(n_clusters=6, init="k-means++", n_init=10, random_state=0).fit(X)   # inertia: km.inertia_
pca = PCA(n_components=3).fit(X)                                                # variances: pca.explained_variance_
iso = IsolationForest(n_estimators=100, max_samples=128, random_state=0).fit(X)
score = -iso.score_samples(X)                                                   # larger now means stranger, like this lab

Systems connection

The last numbers of milestone 5 are an alerting problem, not a modelling one: a rare event and a small false-alarm rate give a pager that mostly rings for nothing. The cure is the one in alerting and on-call: alert on a symptom that matters, tune to what a person can act on, and measure precision as well as recall. Meanwhile k-means and PCA are components inside storage and search: an IVF index partitions vectors with k-means so a query only scans a few cells (ANN indexes, and vector stores), and PCA is the standard first step to shrink embeddings before indexing them.

What you learned

  • Lloyd's algorithm is an alternating descent: both halves can only lower the inertia, so it stops, but at a local minimum that depends on the start. Compare squared distances, break ties by index and keep empty clusters where they were.
  • k-means++ draws each new centre with probability proportional to the squared distance to the nearest existing centre. Restarts keep the lowest inertia. Inertia alone cannot choose k; the silhouette can.
  • PCA is the eigenproblem of the covariance matrix. Power iteration finds the top eigenvector at a speed set by λ2/λ1, deflation exposes the next, and the reconstruction error equals the variance you discarded. Units decide what PCA finds.
  • An isolation forest scores a row by how few random cuts isolate it: 2−E[h]/c(ψ), near 1 for easy-to-isolate rows and about 0.5 for the typical row. A single tree is noisy; a hundred are stable.
  • Each detector is blind to some kind of strange: centre distance misses off-plane readings, PCA residual misses anything on the plane, the forest is weakest on off-plane. Rank-normalise before combining. And with a rare event, a small false-alarm rate still buries the true alerts.

Check your understanding

Rows sit at 0, 1, 10 and 11, and the centres chosen so far are the rows at 0 and 11. With k-means++, what is the probability that the next centre is the row at 10?

  1. 0%, because the row at 10 is next to the centre at 11
  2. 25%, because there are four rows and each is equally likely
  3. 50%, because the squared distances to the nearest centre are 0, 1, 1, 0
  4. 100%, because it is the farthest from the centre at 0
D is the distance to the nearest centre: 0 for the rows at 0 and 11, which are centres, and 1 for the rows at 1 and 10. The squared distances 0, 1, 1, 0 give each of the two remaining rows probability 1/2. Measuring from the centre at 0 alone, as the last option does, is the slip the lab's checker catches; uniform probability would ignore D altogether.

A covariance matrix has eigenvalues 5.0 and 4.5. Roughly how many power-iteration steps does it take to shrink the error in the direction by a factor of a million?

  1. About 130, because the error shrinks by 0.9 each step
  2. About 13, because six orders of magnitude take about twice six steps
  3. About 1,300, because the error shrinks by 0.99 each step
  4. About 6, because each step gains an order of magnitude
The error shrinks by λ2/λ1 = 0.9 per step, so you need 0.9t = 10−6, which gives t = 6 ln(10)/−ln(0.9), about 131. The other options assume a faster ratio (one tenth gains an order of magnitude a step). Nearly tied eigenvalues are exactly where power iteration is slow, and where the direction itself is poorly determined.

In an isolation forest, a row's mean path length across the trees equals c(ψ). What is its anomaly score?

  1. 0, because it takes the maximum number of cuts
  2. 0.25, because it is a quarter of the way to isolated
  3. 1, because it is as isolated as it can be
  4. 0.5, because 2 to the power of −1 is one half
The score is 2−E[h]/c(ψ). With E[h] = c(ψ) the exponent is −1 and the score is 0.5: the row is as easy to isolate as an unremarkable row. Shorter paths give scores towards 1, longer paths below 0.5; the score is never 0 or 1 exactly.

A fleet's readings normally lie on a plane. A fault pushes some readings far away from the middle but still exactly on the plane. Which detector from this lab misses them?

  1. k-means distance to the nearest centre
  2. PCA reconstruction error with the plane's two components
  3. The isolation forest
  4. The rank-normalised maximum of all three
A reading on the plane is reconstructed perfectly from the plane's components, however far along it lies, so its PCA residual is zero (AUC about 0.52 in the lab). k-means and the forest both see it as far from the crowd, and the combined score inherits that. PCA residual detects what the model cannot express, not what is extreme within it.

0.2% of 100,000 readings are anomalous. A detector flags 80% of anomalies and 2% of normal readings. About what share of its alerts are real anomalies?

  1. About 80%
  2. About 40%
  3. About 7%
  4. About 0.2%
True alerts: 100,000 × 0.002 × 0.8 = 160. False alerts: 99,800 × 0.02 = 1,996. Precision is 160/2,156, about 7.4%. The 80% is the detector's recall, which is a different question; 0.2% is the base rate that precision would equal for a detector with no skill.
