Random Forests & Gradient Boosting

One decision tree is readable but unstable. Many trees, combined well, are the most reliable workhorse for rows-and-columns data. This chapter explains the two ways to combine them, averaging independent trees (bagging and random forests) and adding corrective trees one after another (gradient boosting), and what XGBoost, LightGBM and CatBoost add on top.

Why this matters

Chapter 8 ended with a single tree that explains itself easily and changes shape when you change a few rows. That instability is not a flaw to be patched: it is a raw material. Averaging many unstable models cancels their disagreements, and stacking many weak ones lets each fix the last one's mistakes. These two ideas give you the model that wins most tabular benchmarks and most business problems built on tables: customer churn, credit risk, demand, fraud scores, ranking. After this chapter you will be able to say why a forest and a boosted model behave differently, set the handful of parameters that matter, read an early-stopping curve, and explain what the three big libraries do differently. The later chapters on validation, calibration, interpretation and competitions all assume you can use these models.

Why averaging helps: the variance formula

Suppose you train one deep tree on 400 rows. Retrain it on a different 400 rows from the same source and you get a different tree, with different splits and different predictions for the same customer. In the language of chapter 6, a deep tree has low bias (it can bend to fit almost anything) and high variance (its predictions move a lot with the training sample). If its errors on one input are noisy but not systematically wrong, averaging several such trees should keep the signal and cancel part of the noise. How much it cancels depends on one quantity. Let each of B models make a prediction with variance σ2, and let any two of them have correlation ρ (their errors partly move together). The variance of their average is:

Var(average) = ρ σ2 + (1 − ρ) σ2 / B

The second term shrinks as you add models. The first does not: it is the part of the error the models share. With independent models (ρ = 0) the variance falls like 1/B; with identical models (ρ = 1) averaging does nothing. So there are exactly two levers: make each model good, and make the models different from one another. Everything in the first half of this chapter is a way to pull the second lever without ruining the first.

Analogy: a jury and a crowd guessing a weight

Ask 500 people to guess the weight of an ox and the average is often startlingly close, because individual over- and under-estimates cancel. Ask 500 people who all read the same wrong newspaper article and the average inherits the article's mistake. Independent errors cancel; shared errors do not. A random forest works hard to make its trees "read different articles".

Where it breaks down: a crowd's guesses are independent by construction, but the trees in a forest are all trained on overlapping rows from one sample, so some correlation is unavoidable. Also, averaging cannot repair a bias that every member shares: if the whole crowd cannot see the ox, the average is still blind.

Bagging and random forests

Bootstrap samples

To get different trees you need different training sets, and you only have one. The trick (Breiman, 1996, "Bagging Predictors") is the bootstrap from A0 chapter 15: draw n rows with replacement from the original n. Some rows appear twice or three times; others do not appear at all. The chance that a particular row is missing from a bootstrap sample is (1 − 1/n)n, which approaches 1/e ≈ 0.368 as n grows. So each tree sees about 63 percent of the distinct rows. Bagging (bootstrap aggregating) trains one tree per bootstrap sample and averages the predictions (for classification, it averages the class probabilities or takes a vote).

The left-out 37 percent is a free gift. For any row, about 37 percent of the trees never saw it, so you can predict it using only those trees and compare with its true label. The resulting error estimate is called the out-of-bag (OOB) error. It behaves like a validation score without holding anything out, which is why random forest implementations report it by default.

Decorrelating the trees: random forests

Bagged trees are still similar. If one feature is strongly predictive, every tree will pick it for its first split, so the trees share a top structure and ρ stays high. Breiman's fix (2001, "Random Forests") is to inject more randomness: at every split, consider only a random subset of mtry features (also called max_features) and choose the best split among those. Trees are forced to use different features in different places, and their errors decorrelate. Each tree becomes a little worse on its own (it sometimes cannot use the best feature), and the average becomes better because ρ falls. A common rule of thumb is about √p features for classification and p/3 for regression, where p is the number of features, but it is a starting point, not a law. (In scikit-learn, as of recent versions, the regressor's default is to consider all features, which makes it plain bagging unless you lower max_features.)

Systems connection

Each tree in a forest is trained independently, so training is embarrassingly parallel: one tree per core, or per machine, with no communication until the end (compare the scaling limits in Parallelism, SIMD & GPUs). Boosting, as you will see, is sequential across trees and has to parallelise inside each tree instead. At prediction time a forest of 500 deep trees walks 500 pointer-chasing paths per row, which is the kind of cost Designing with ML & LLMs asks you to budget for.

A forest from scratch

The script below builds everything with NumPy so you can see each moving part. The world is synthetic and fixed by a seed: 8 features uniform on −1 to 1, and a target that mixes a smooth curve of feature 0, an interaction between features 1 and 2, a threshold on feature 3, and Gaussian noise with standard deviation 0.5. Features 4 to 7 are pure noise. 400 rows train; 2,000 fresh rows test. Because the noise has standard deviation 0.5, no model can reach a test RMSE below 0.50. We compare one deep tree, plain bagging (mtry = all 8 features) and a forest with mtry = 3, each with 100 trees, and measure the correlation between the trees' test predictions.

import numpy as np

def make_data(n, rng):
    X = rng.uniform(-1, 1, size=(n, 8))
    y = (np.sin(3 * X[:, 0]) + X[:, 1] * X[:, 2] * 2 + (X[:, 3] > 0.3)
         + rng.normal(0, 0.5, n))          # features 4-7 are pure noise
    return X, y

def build(X, y, depth, min_leaf, mtry, rng):
    if depth == 0 or len(y) < 2 * min_leaf:
        return y.mean()
    best = (np.inf, None, None)
    for j in rng.choice(X.shape[1], mtry, replace=False):
        o = np.argsort(X[:, j]); xs, ys = X[o, j], y[o]
        cs, cs2 = np.cumsum(ys), np.cumsum(ys ** 2)
        k = np.arange(min_leaf, len(y) - min_leaf + 1)
        sse = (cs2[k - 1] - cs[k - 1] ** 2 / k) + \
              ((cs2[-1] - cs2[k - 1]) - (cs[-1] - cs[k - 1]) ** 2 / (len(y) - k))
        sse[xs[k - 1] == xs[k]] = np.inf          # cannot split between equal values
        i = sse.argmin()
        if sse[i] < best[0]:
            best = (sse[i], j, (xs[k[i] - 1] + xs[k[i]]) / 2)
    _, j, t = best
    if j is None:
        return y.mean()
    m = X[:, j] <= t
    return (j, t, build(X[m], y[m], depth - 1, min_leaf, mtry, rng),
            build(X[~m], y[~m], depth - 1, min_leaf, mtry, rng))

def predict(tree, X):
    if not isinstance(tree, tuple):
        return np.full(len(X), tree)
    j, t, left, right = tree
    out = np.empty(len(X)); m = X[:, j] <= t
    out[m] = predict(left, X[m]); out[~m] = predict(right, X[~m])
    return out

rng = np.random.default_rng(0)
Xtr, ytr = make_data(400, rng); Xte, yte = make_data(2000, rng)
rmse = lambda p: np.sqrt(np.mean((yte - p) ** 2))

def ensemble(B, mtry):
    preds, oob_sum, oob_n = [], np.zeros(len(ytr)), np.zeros(len(ytr))
    for b in range(B):
        idx = rng.integers(0, len(ytr), len(ytr))           # bootstrap sample
        tree = build(Xtr[idx], ytr[idx], 12, 3, mtry, rng)
        preds.append(predict(tree, Xte))
        out = np.setdiff1d(np.arange(len(ytr)), idx)         # rows this tree never saw
        oob_sum[out] += predict(tree, Xtr[out]); oob_n[out] += 1
    ok = oob_n > 0
    oob = np.sqrt(np.mean((ytr[ok] - oob_sum[ok] / oob_n[ok]) ** 2))
    return np.array(preds), oob

print(f"noise floor RMSE 0.50, baseline (the mean) {rmse(ytr.mean()):.3f}")
for name, B, mtry in [("one deep tree", 1, 8), ("bagging, 100 trees", 100, 8),
                      ("forest, 100 trees, mtry=3", 100, 3)]:
    P, oob = ensemble(B, mtry)
    rho = (np.corrcoef(P[:30])[np.triu_indices(30, 1)].mean()
           if B > 1 else float("nan"))
    print(f"{name:27s} test RMSE {rmse(P.mean(0)):.3f}  OOB RMSE {oob:.3f}  "
          f"tree-tree corr {rho:.2f}")

one deep tree               test RMSE 1.160  OOB RMSE 1.164  tree-tree corr nan
bagging, 100 trees          test RMSE 0.784  OOB RMSE 0.838  tree-tree corr 0.58

Read the numbers in order. Predicting the training mean gives 1.198. One deep tree scores 1.160, barely better than the mean: it has memorised 400 noisy rows. Averaging 100 bootstrap trees drops the error to 0.784, a huge gain from variance reduction alone. Lowering mtry from 8 to 3 reduces the average tree-to-tree correlation from 0.58 to 0.47 and the error edges down to 0.777. That last gain is small here because the world has only a few strong features and four useless ones; with many correlated, useful features the decorrelation matters more. The OOB RMSE (0.838 and 0.827) is slightly pessimistic compared with the test score because each row's OOB prediction averages only about 37 trees, not 100, but it tracks the test error and ranks the models correctly without touching the test set.

The variance formula explains the floor. With ρ = 0.47 the shared term ρσ2 is 47 percent of one tree's variance, and no number of extra trees can remove it. This is why a forest stops improving after a few hundred trees: it converges to a limit rather than overfitting further.

Common misconception

"A random forest overfits if you add too many trees." Adding trees does not overfit a forest: the average converges to its limit as B grows, and a larger B only costs time and memory. What can overfit is each tree's depth and leaf size, and a forest of fully grown trees can still fit noise in a regression with very noisy targets. The honest statement is that more trees are safe, and the parameters that control complexity are depth, minimum leaf size and mtry. Also note what a forest cannot do: it cannot predict outside the range of targets it saw, because every prediction is an average of training targets. A forest trained on prices up to 500 will never predict 600.

Boosting: a different idea

Bagging attacks variance by averaging models that are individually flexible. Boosting attacks bias by combining models that are individually weak. A weak learner is a model only a little better than guessing, such as a tree with two or three splits. Boosting adds weak learners one at a time, and each new one is trained to fix what the ensemble so far still gets wrong. The final prediction is a sum, not an average.

Fitting residuals

Start with the simplest case: regression with squared error. Begin with a constant prediction, the mean of y. Compute the residual for every row, y − F(x): how far the current prediction is from the target. Fit a small tree to predict those residuals from the features. Add a fraction of that tree to the model, recompute the residuals, and repeat. Each tree is a correction. Step through a toy example: eight points, stumps (trees with one split), and a learning rate of 0.5.

Step through

Three rounds of boosting on eight points

  1. Start with a constant. The targets are 1.0, 1.6, 1.3, 3.0, 3.6, 3.1, 5.4, 4.9 for x = 1 to 8. The best constant for squared error is their mean, F0 = 2.99 (RMSE 1.52). It is a poor model, but it is a start.
  2. Compute residuals. Each bar is y − F0. Points on the left sit below the line (negative bars), points on the right above (positive bars). The residuals are the part of the signal still unexplained.
  3. Fit a stump to the residuals. The best single split is between x = 3 and x = 4. The stump predicts −1.69 on the left (the mean residual there) and +1.01 on the right. It is a crude summary of the pattern in the bars.
  4. Add half of it. With learning rate η = 0.5 the model becomes F1 = F0 + 0.5 × stump: 2.14 on the left, 3.49 on the right. RMSE drops from 1.52 to 1.02. We took only half a step on purpose; the reason is below.
  5. New residuals. Recomputed against F1, the bars are smaller, and a new pattern shows: the last two points are well above the model.
  6. Round 2. The best stump now splits between x = 6 and x = 7 (−0.55 on the left, +1.66 on the right). Adding half of it gives F2, with a third level for x = 7 and 8. RMSE is 0.60.
  7. After round 3. A third stump (split between x = 4 and x = 5, ±0.48) refines the middle. RMSE is 0.43 and the model follows the staircase in the data. Real models repeat this for hundreds or thousands of rounds, with trees of several splits, each a small correction.

Why it is called gradient boosting

Fitting residuals looks like a trick that only works for squared error. Friedman (2001, "Greedy Function Approximation: A Gradient Boosting Machine") showed it is a special case of something general, which is gradient descent where the thing being adjusted is the whole prediction function rather than a vector of weights. Recall from A0 chapter 10 that gradient descent moves parameters against the gradient of the loss. Here, think of the model's prediction for each training row, F(xi), as n numbers you are free to adjust. The loss is a function of those numbers, and its gradient with respect to F(xi) tells you, row by row, which way to nudge each prediction. The catch is that you cannot nudge them freely: the nudges must come from a function of the features, or the model could not predict a new row. So at each round you fit a small tree to the negative gradients, which is the best function-of-features approximation to the steepest-descent step, and take a small step along it.

  1. Start with a constant F0 that minimises the loss (the mean for squared error, the log-odds of the base rate for log-loss).
  2. For round m = 1 to M, compute for each row the pseudo-residual ri = − ∂ℓ(yi, F)/∂F evaluated at F = Fm−1(xi).
  3. Fit a small regression tree hm to predict ri from xi by least squares.
  4. Update Fm = Fm−1 + η hm, where η (eta, 0 < η ≤ 1) is the learning rate or shrinkage.

For squared error ℓ = ½(y − F)2, the derivative with respect to F is −(y − F), so the pseudo-residual is the plain residual: that is the stepper above. For log-loss with F the log-odds and p = 1/(1 + e−F), the derivative is p − y, so the pseudo-residual is y − p: how far the predicted probability is from the 0 or 1 label. Absolute error gives the sign of the residual, which makes boosting robust to outliers. Any differentiable loss gives a boosting algorithm, including rankings and quantile losses. This generality is the reason the method spread so far beyond regression.

Go deeper optional: boosting as gradient descent, and its history

In ordinary gradient descent on parameters θ, one step is θ ← θ − η ∇θL. Treat the vector of training predictions F = (F(x1), …, F(xn)) as the parameters: the gradient g = ∇FL has one entry per row, and the steepest-descent step is F ← F − η g. That step is only defined on training rows. Fitting a tree h to −g by least squares extends it to a function on all of feature space, at the cost of smoothing the step. The learning rate plays the role of η, and the number of rounds is the number of steps.

The historical route was different. Freund and Schapire's AdaBoost (1997) reweighted training rows so that each new weak classifier concentrated on the previously misclassified ones, and was explained as minimising an exponential loss by Friedman, Hastie and Tibshirani (2000). Friedman's gradient boosting (2001) generalised the idea to any differentiable loss. Modern libraries use the gradient view, usually with a second-order refinement (below).

Shrinkage, rounds and early stopping

Why take only half a step, or a tenth? Because each tree is fitted to noisy residuals and is partly wrong; a full-size step commits fully to its mistakes. Many small steps average over many different mistakes. Friedman's own experiments found that a small learning rate with more trees almost always generalises better than a large one with few. The price is compute: halving η roughly doubles the rounds needed. The other half of the picture is that boosting does overfit as rounds accumulate, unlike a forest: each round fits the training residuals a little better, and eventually it fits noise. So the number of rounds M is a complexity parameter, and the standard way to choose it is early stopping: monitor the error on a validation set after each round and stop when it has not improved for, say, 50 rounds. The script below uses the same synthetic world as the forest (noise floor 0.50) and trains boosted depth-3 trees for 300 rounds under four settings, recording training and validation RMSE every round. The validation set is 2,000 fresh rows, large enough to give a stable curve.

         + rng.normal(0, 0.5, n))

    if depth == 0 or len(y) < 2 * min_leaf:
        return y.mean()
    best = (np.inf, None, None)
    for j in range(X.shape[1]):
        o = np.argsort(X[:, j]); xs, ys = X[o, j], y[o]
        cs, cs2 = np.cumsum(ys), np.cumsum(ys ** 2)
        k = np.arange(min_leaf, len(y) - min_leaf + 1)
        sse = (cs2[k-1] - cs[k-1]**2 / k) + ((cs2[-1]-cs2[k-1]) - (cs[-1]-cs[k-1])**2 / (len(y)-k))
        sse[xs[k - 1] == xs[k]] = np.inf
        i = sse.argmin()
        if sse[i] < best[0]:
            best = (sse[i], j, (xs[k[i] - 1] + xs[k[i]]) / 2)
    _, j, t = best
    if j is None:
        return y.mean()
    m = X[:, j] <= t
    return (j, t, build(X[m], y[m], depth - 1), build(X[~m], y[~m], depth - 1))

def predict(tree, X):
    if not isinstance(tree, tuple):
        return np.full(len(X), tree)
    j, t, l, r = tree
    out = np.empty(len(X)); m = X[:, j] <= t
    out[m] = predict(l, X[m]); out[~m] = predict(r, X[~m])
    return out

def boost(X, y, Xv, yv, rounds, lr, depth):
    F, Fv = np.full(len(y), y.mean()), np.full(len(yv), y.mean())
    curve = []
    for _ in range(rounds):
        tree = build(X, y - F, depth)        # fit the residuals = negative gradient of 1/2(y-F)^2
        F += lr * predict(tree, X); Fv += lr * predict(tree, Xv)
        curve.append((np.sqrt(np.mean((y - F) ** 2)), np.sqrt(np.mean((yv - Fv) ** 2))))
    return np.array(curve)

Xtr, ytr = make_data(400, rng); Xva, yva = make_data(2000, rng)
out = {}

for lr, depth in [(1.0, 3), (0.1, 3), (0.1, 1), (0.02, 3)]:

    print(f"{lr:<5} {depth:<6} {b + 1:<11} {c[b, 1]:<16.3f} {c[b, 0]:<17.3f} {c[-1, 1]:.3f}")

Newton steps and XGBoost

Plain gradient boosting uses only the first derivative of the loss, so it knows which way to move each prediction but not how far. Adding the second derivative, the curvature, gives a Newton step, the same upgrade that takes gradient descent to Newton's method. This is the central idea of XGBoost (Chen and Guestrin, 2016, "XGBoost: A Scalable Tree Boosting System"). For each row i it records two numbers at the current prediction: the gradient gi and the hessian hi (second derivative of the loss). For log-loss, g = p − y and h = p(1 − p). For squared error, g = −(y − F) and h = 1.

The objective for the new tree is approximated by a second-order Taylor expansion plus a penalty on the tree's size: a cost γ per leaf and an L2 penalty ½λ on the squared leaf values w (as in ridge regression). Collect the rows that land in one leaf and let G = Σ gi and H = Σ hi over them. Minimising the leaf's share of the objective gives:

optimal leaf value w* = − G / (H + λ)     gain of a split = ½ [ GL2/(HL + λ) + GR2/(HR + λ) − (GL + GR)2/(HL + HR + λ) ] − γ

These two formulas carry most of the library's behaviour. The leaf value is the Newton step shrunk by λ: a small leaf (small H) is pulled towards zero, which stops a leaf with three rows from making a confident claim. The gain compares the objective before and after the split; a split is made only if the gain exceeds zero, so γ acts as a minimum improvement ("pruning"). The min_child_weight parameter is a minimum on H, not on a row count. For log-loss h is at most 0.25, so min_child_weight = 1 means "at least four rows at p = 0.5, and more when the model is already confident", because confident rows contribute less hessian.

Go deeper optional: where the leaf formula comes from

For a tree with leaf values wj and a leaf j containing rows Ij, expand the loss around the current prediction to second order: ℓ(yi, F + f) ≈ ℓ(yi, F) + gi f + ½hi f2. For rows in leaf j the new tree adds f = wj, so the objective, dropping constants and adding the regulariser, is Σj [ Gj wj + ½(Hj + λ) wj2 ] + γT. Each bracket is a quadratic in wj, minimised at wj* = −Gj/(Hj + λ), where it equals −½ Gj2/(Hj + λ). The tree's score is therefore −½ Σj Gj2/(Hj + λ) + γT; splitting a leaf replaces one term by two and adds one to T, and the difference is the gain formula above. Squared error has h = 1 for every row, so H is the row count and the leaf value is (sum of residuals) / (count + λ), the mean residual shrunk towards zero.

Here is the arithmetic on a case small enough to check by hand. Eight points on one feature, labels 0 0 0 1 0 1 1 1, and a first-round prediction of probability 0.5 everywhere. Every row has g = ±0.5 and h = 0.25. Splitting after the third point puts three rows with g = +0.5 on the left (GL = 1.5, HL = 0.75) and five on the right (GR = −1.5, HR = 1.25). With λ = 0 the gain is ½(1.52/0.75 + 1.52/1.25) = ½(3 + 1.8) = 2.4, and the leaf values are −1.5/0.75 = −2.0 (left) and 1.5/1.25 = +1.2 (right), in log-odds units. The script confirms this and shows what λ and γ do. Its second half then answers a question about speed: instead of scanning all 100,000 candidate thresholds, bucket the feature into bins and scan only the bin edges.

import numpy as np

def gain(GL, HL, G, H, lam, gamma):
    GR, HR = G - GL, H - HL
    return 0.5 * (GL**2/(HL+lam) + GR**2/(HR+lam) - G**2/(H+lam)) - gamma

# Part 1: eight labelled points, one feature, current prediction p = 0.5 for all
x = np.array([1, 2, 3, 4, 5, 6, 7, 8.]);  y = np.array([0, 0, 0, 1, 0, 1, 1, 1.])
p = np.full(8, 0.5)
g, h = p - y, p * (1 - p)                    # log-loss gradient and hessian per row
G, H = g.sum(), h.sum()
print("g =", g, " h =", h[0], " G =", G, " H =", H)
for lam, gamma in [(0, 0), (1, 0), (1, 1.0)]:
    gains = [gain(g[:k].sum(), h[:k].sum(), G, H, lam, gamma) for k in range(1, 8)]
    k = int(np.argmax(gains)) + 1
    wl = -g[:k].sum() / (h[:k].sum() + lam); wr = -(G - g[:k].sum()) / (H - h[:k].sum() + lam)
    print(f"lambda={lam} gamma={gamma}: best split after x={x[k-1]:.0f}, gain {gains[k-1]:.3f}, "
          f"leaf weights {wl:+.3f} / {wr:+.3f}")

# Part 2: exact split search versus histogram search (regression, g = -(residual), h = 1)
rng = np.random.default_rng(1)
n = 100_000
f = rng.normal(size=n); r = np.where(f > 0.37, 1.0, 0.0) + rng.normal(0, 1, n)
g, h = -(r - r.mean()), np.ones(n)
o = np.argsort(f); gs = np.cumsum(g[o]); hs = np.cumsum(h[o])
ex = gain(gs[:-1], hs[:-1], g.sum(), h.sum(), 1, 0)
i = ex.argmax(); print(f"exact: {n-1} candidates, best threshold {f[o][i]:.3f}, gain {ex[i]:.1f}")
for bins in (16, 64, 255):
    edges = np.quantile(f, np.linspace(0, 1, bins + 1)[1:-1])
    b = np.searchsorted(edges, f)             # one pass over the data to build the histogram
    Gb, Hb = np.bincount(b, g, bins), np.bincount(b, h, bins)
    hg = gain(np.cumsum(Gb)[:-1], np.cumsum(Hb)[:-1], g.sum(), h.sum(), 1, 0)
    j = hg.argmax(); print(f"{bins:>3} bins: {bins-1:>3} candidates, best threshold {edges[j]:.3f}, gain {hg[j]:.1f}")
g = [ 0.5  0.5  0.5 -0.5  0.5 -0.5 -0.5 -0.5]  h = 0.25  G = 0.0  H = 2.0

The first block matches the hand calculation (2.400, −2.000, +1.200). Setting λ = 1 halves the gain and shrinks the leaves towards zero (−0.857 and +0.667); setting γ = 1 subtracts a flat cost, leaving a gain of 0.143, which is a split barely worth making. With γ = 1.5 it would be rejected and the tree would stop growing. The second block is the idea behind the histogram method: with 255 bins (the common default) the best threshold found is 0.370, identical to the exact scan, and the gain is 11,477.3 against the exact 11,484.2, within 0.1 percent, after looking at 254 candidates instead of 99,999. Even 16 bins found a threshold close to the true edge (0.311 against 0.370) and 91 percent of the gain. Binning also lets the algorithm compute a node's histogram once and get a sibling's by subtraction, which is the main reason modern libraries are fast. For the engineering side of XGBoost (sparsity-aware splits, cache-aware access, out-of-core training) see Case 5.

XGBoost adds several smaller ideas that matter in practice. Missing values are handled inside the tree: at each split the algorithm tries sending the missing rows left, then right, and keeps the direction with higher gain, so each split learns its own default direction. Row and column subsampling (subsample, colsample_bytree) borrow from random forests: each tree sees a random fraction of rows and features, which decorrelates the trees and speeds training. Shrinkage (learning_rate, also called eta) is the η from above.

Common misconception

"Boosting needs hundreds of deep trees to work." The opposite is usually true: shallow trees (depth 3 to 8) with a small learning rate generalise best, because each tree is only meant to be a weak correction. A boosted model of a thousand depth-4 trees is far less likely to overfit than a model of ten depth-20 trees, since the first adds small, shrunken steps and the second commits to large, specific ones. If your boosted model overfits quickly, the first levers to try are a lower learning rate, shallower trees, a larger min_child_weight or min_data_in_leaf, and row or column subsampling, not more trees.

LightGBM and CatBoost

XGBoost popularised the family; two later libraries made different engineering choices that are worth knowing because they change what each is best at.

LightGBM: faster by looking at less

LightGBM (Ke et al., 2017, "LightGBM: A Highly Efficient Gradient Boosting Decision Tree") is built around speed on large data. Three ideas stand out. First, histogram-based splits, as in the listing above: bin each feature once (255 bins by default), then every split search touches bins, not rows. Second, leaf-wise growth. Classical trees grow level by level, splitting every node at a given depth. LightGBM instead repeatedly splits whichever leaf currently offers the largest gain, regardless of depth. For the same number of leaves this reaches lower training loss, but it can grow lopsided, deep branches that fit small groups of rows, so the main complexity control is num_leaves together with min_data_in_leaf, not max_depth. Third, two sampling tricks: gradient-based one-side sampling (GOSS) keeps all rows with large gradients (the ones the model gets most wrong) and a random sample of the small-gradient rows, reweighted to stay unbiased; and exclusive feature bundling (EFB) merges sparse features that are rarely non-zero at the same time into one, which cuts the effective feature count for wide one-hot data.

CatBoost: honest categorical features

CatBoost (Prokhorenkova et al., 2018, "CatBoost: unbiased boosting with categorical features") targets a different pain: categorical columns with many values (user id, postcode, product code). One-hot encoding those columns explodes the width; the common alternative, target encoding (replace each category by the mean target of its rows), leaks. The problem is that a row's own label is inside its category's mean, so on the training set the encoded feature is correlated with the label even when the category is meaningless. A boosted model then trusts a feature that will not work on new rows. CatBoost's answer is an ordered target statistic: shuffle the rows, and encode each row using only the rows that come before it in that order, with a prior so rare categories start from the overall mean. A row never sees its own label.

The script builds the worst case for the naive method: 2,000 rows, a category with 500 values (about four rows each), and a label that is a coin flip independent of everything. Any apparent signal is leakage.

import numpy as np

rng = np.random.default_rng(3)
n, n_cat = 2000, 500
cat = rng.integers(0, n_cat, n)              # a high-cardinality category: ~4 rows each
y = rng.integers(0, 2, n).astype(float)      # labels are pure coin flips: NO real signal
prior = y.mean()

# naive target statistic: each row's own label is inside its category mean
sums, cnts = np.bincount(cat, y, n_cat), np.bincount(cat, minlength=n_cat)
naive = sums[cat] / cnts[cat]

# ordered target statistic: a row sees only rows that come BEFORE it in a random permutation
perm = rng.permutation(n)
s, c = np.zeros(n_cat), np.zeros(n_cat)
ordered = np.empty(n)
a = 1.0                                      # weight of the prior
for i in perm:
    ordered[i] = (s[cat[i]] + a * prior) / (c[cat[i]] + a)
    s[cat[i]] += y[i]; c[cat[i]] += 1

# fresh data from the same coin-flip world, encoded with the full-training statistics
cat2 = rng.integers(0, n_cat, n); y2 = rng.integers(0, 2, n).astype(float)
fresh = (sums[cat2] + prior) / (cnts[cat2] + 1)
corr = lambda u, v: np.corrcoef(u, v)[0, 1]
print(f"correlation of encoded feature with the label (true signal is zero)")
print(f"  naive encoding,   training rows: {corr(naive, y):+.3f}")
print(f"  ordered encoding, training rows: {corr(ordered, y):+.3f}")
print(f"  full-train encoding, fresh rows: {corr(fresh, y2):+.3f}")
correlation of encoded feature with the label (true signal is zero)
  naive encoding,   training rows: +0.490
  ordered encoding, training rows: -0.019
  full-train encoding, fresh rows: -0.021

The naive encoding correlates +0.49 with a label it has no real relationship with, because with about four rows per category the row's own label supplies a quarter or more of the mean. The ordered version is close to zero (−0.019), as is the honest check on fresh rows (−0.021). This is the same disease as the preprocessing leaks of chapter 14, and chapter 17 returns to safe target encoding in general. CatBoost applies the same ordering idea to the boosting itself ("ordered boosting"): the gradients used to fit a tree for a row come from a model that was not trained on that row, which removes a subtle bias in how ordinary boosting estimates residuals on its own training data. CatBoost also uses symmetric (oblivious) trees, in which every node at a given depth uses the same split. Such a tree is a lookup table indexed by the bits of its splits, which is fast to evaluate and acts as a strong regulariser.

Tuning boosted trees without a random search addiction

Boosted models have many parameters, but they are not equally important and they interact in predictable ways. A sensible order, which works for all three libraries:

  1. Fix a learning rate (0.05 to 0.1 for exploration, 0.01 to 0.03 for the final fit) and set the number of rounds very high.
  2. Use early stopping on a validation fold so that the number of rounds is found, not guessed. With cross-validation, use the average best round (or a slightly higher number when refitting on all rows).
  3. Tune tree complexity: depth (3 to 8) or num_leaves (8 to 64), together with min_child_weight or min_data_in_leaf. This is where most of the generalisation gain is.
  4. Add randomness: subsample and colsample_bytree between 0.6 and 1.0.
  5. Add regularisation: L2 (lambda) and, for XGBoost, gamma, in small steps.
  6. Lower the learning rate and let early stopping pick a larger number of rounds. This usually gives a small, reliable improvement.
import xgboost as xgb
from sklearn.model_selection import train_test_split

# X: (n_samples, n_features) array or DataFrame, y: 0/1 labels
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)

model = xgb.XGBClassifier(
    n_estimators=5000,            # an upper bound; early stopping chooses the real number
    learning_rate=0.05,
    max_depth=4,
    min_child_weight=5,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_lambda=1.0,
    eval_metric="logloss",
    early_stopping_rounds=100,    # stop when validation log-loss has not improved for 100 rounds
)
model.fit(X_tr, y_tr, eval_set=[(X_va, y_va)], verbose=False)
print(model.best_iteration, model.best_score)

Why boosted trees rule tabular data

The claim "gradient-boosted trees are the best default for tables" is an empirical one, and it has been tested. Grinsztajn, Oyallon and Varoquaux (2022, "Why do tree-based models still outperform deep learning on typical tabular data?", NeurIPS Datasets and Benchmarks) compared tree ensembles and neural networks on 45 medium-sized tabular datasets (around ten thousand rows) with large tuning budgets, and found tree-based models still ahead. Their analysis points to three properties of tabular data that favour trees:

Irregular targets

Tabular targets often jump: a credit limit changes at an income threshold, a fee applies above a quantity. Trees represent steps naturally. Neural networks are biased towards smooth functions and need much more data to carve sharp edges.

Uninformative features

Real tables carry many columns that do not matter. Trees choose splits by gain and mostly ignore the useless ones; a network's first layer mixes every input and has to learn to ignore them.

No rotation symmetry

Columns in a table mean different things (age, postcode, balance), so rotating the feature space destroys information. Trees work one feature at a time and respect the axes; networks treat rotated inputs as equivalent.

Practical reasons stack on top. Boosted trees need almost no preprocessing: no scaling (splits depend on order, not magnitude), natural handling of mixed numeric and categorical columns, missing values built in, and monotone transformations of a feature change nothing. They train in seconds to minutes on a laptop, tune with few parameters, and are well understood by the tools of interpretation and calibration. A new baseline is therefore a few lines, and any alternative must beat it by enough to justify its cost.

State of play, October 2026

The picture above is the settled finding of 2022 to 2025 benchmark work, but it is moving at the edges. Pretrained tabular foundation models such as TabPFN (Hollmann et al., published in Nature, 2025) report strong results on small tables (the Nature paper reports up to about ten thousand rows), without per-dataset tuning, and neural methods with careful embeddings narrow the gap on some larger datasets. Boosted trees remain the first thing to try and the thing to beat; chapter 19 covers when the alternatives win. Verify any specific benchmark claim against its paper and its dataset sizes: results on "typical" tables do not transfer to your table automatically.

Using these models well

Importance, extrapolation and other traps

  • Built-in importance is biased. Impurity-based importance, the default in forests, favours features with many distinct values or categories, because they offer more split points to choose from. Prefer permutation importance on held-out data, or SHAP, and read chapter 16 before showing anyone a bar chart.
  • Trees cannot extrapolate. A forest or boosted model predicts a constant within each region, so beyond the training range of a feature it predicts the value of the nearest region. For trending quantities such as sales or prices, model the change or a ratio, or add a linear term; chapter 18 shows this failure on forecasts.
  • Probabilities need checking. Forests produce votes-as-probabilities that are typically under-confident near 0 and 1 because averaging pulls them in; boosted models can be over-confident when overfit. Neither is calibrated by default. Chapter 15 shows how to check and fix this.
  • Leaky validation inflates everything. Boosting is very good at finding any pattern in the features, including accidental ones (row order, IDs, timestamps). A suspiciously high score is more often a leak than a breakthrough (chapter 14).
  • Constraints are available. All three libraries support monotonic constraints (for example "predicted risk never decreases as number of missed payments increases"), which add domain knowledge and often improve generalisation and acceptability to reviewers.
  • Imbalance. Class weights or scale_pos_weight change the loss, not the data; thresholds and metrics for rare positives are the subject of chapter 15.

Forest or boosting, then?

Both are excellent, and the choice is rarely dramatic. A forest has few sensitive parameters, trains in parallel, gives an honest OOB score for free, and is hard to ruin: use it as a strong, low-effort baseline and as a sanity check on a boosted model. A boosted model usually has the higher ceiling, as the 0.676 against 0.777 in our synthetic world suggests, but it has more parameters, needs early stopping, and is easier to overfit. A reasonable workflow is the one chapter 4 set out: the linear model and a forest first, then a boosted model, each judged by the same cross-validation, with the extra complexity kept only if the gain is larger than the noise in the estimate. When the best performance is the goal, as in competitions, the answer is often both, blended.

Key takeaways

  • Averaging B models with variance σ2 and pairwise correlation ρ gives variance ρσ2 + (1 − ρ)σ2/B: more models remove only the independent part, so decorrelating them matters as much as adding them.
  • Bagging trains deep trees on bootstrap samples; a random forest also restricts each split to mtry random features. Extra trees do not overfit a forest, and the out-of-bag rows give a free error estimate.
  • Boosting adds shallow trees in sequence, each fitted to the negative gradient of the loss (the residual, for squared error), scaled by a learning rate. It reduces bias but, unlike a forest, can overfit as rounds accumulate.
  • Choose the number of rounds by early stopping on validation data; a small learning rate with more rounds almost always beats a large one with few.
  • XGBoost uses gradient and hessian: leaf value −G/(H + λ), split gain from the same sums, γ as a minimum gain. Histograms make split search fast with almost no loss of quality.
  • LightGBM grows leaf-wise and samples cleverly; CatBoost uses ordered target statistics so that categorical encodings do not leak the row's own label.
  • Boosted trees lead on tabular data because targets are irregular, many features are uninformative and axes carry meaning. Treat that as the default to beat, not a law.

Check your understanding

A forest of 200 trees has an average pairwise correlation of 0.6 between trees and each tree has prediction variance 4. Roughly what is the variance of the forest's average, and what would adding another 800 trees do?

  1. About 0.02, and the extra trees would lower it to about 0.004
  2. About 4, because averaging does not change variance for correlated trees
  3. About 2.4, and the extra trees would barely change it
  4. About 1.2, and the extra trees would halve it
Plug into ρσ2 + (1 − ρ)σ2/B: 0.6 × 4 = 2.4 plus 0.4 × 4/200 = 0.008, so about 2.41. Going to 1,000 trees changes the second term to 0.0016, which is negligible. The shared 2.4 is the floor. Option 2 ignores the independent part, and options 1 and 4 forget that the correlated term does not shrink with B.

You fit a random forest on 50,000 rows and want a quick, honest estimate of its generalisation error without a separate validation set. Which statement about the out-of-bag (OOB) estimate is correct?

  1. It predicts each row using only trees whose bootstrap sample did not include that row, so it works like a validation score
  2. It is the error on rows that were duplicated in the bootstrap sample
  3. It is the training error, which is why forests overfit
  4. It is only valid for a forest with a single tree
About 37 percent of trees never saw a given row, and averaging only those gives an unbiased-in-spirit held-out prediction (slightly pessimistic because fewer trees vote). It is not the training error: the trees that scored the row did not use it. Rows that were duplicated are the in-bag rows, the opposite of OOB.

A gradient-boosted model has a training RMSE that keeps falling, while the validation RMSE bottomed out at round 40 and has been rising since. The learning rate is 0.3 and the trees have depth 8. Which change is most likely to improve validation performance?

  1. Add more rounds so the model can finish converging
  2. Increase the depth to 12 so each tree is more accurate
  3. Use the training RMSE to pick the number of rounds
  4. Lower the learning rate, reduce the depth, and let early stopping choose a larger number of rounds
Rising validation error with falling training error is overfitting. Smaller steps, weaker trees and early stopping all reduce it. More rounds or deeper trees make it worse, and training error always prefers more rounds, so it cannot choose the stopping point.

In XGBoost with log-loss, a leaf contains 6 rows whose predicted probabilities are all 0.9. With min_child_weight = 1, what happens to a split that creates this leaf?

  1. It is allowed, since 6 rows is more than 1
  2. It is rejected, because the leaf's hessian sum is 6 × 0.09 = 0.54, which is below 1
  3. It is allowed, because confident rows count extra towards the weight
  4. It is rejected, because probabilities above 0.5 are not allowed
The per-row hessian for log-loss is p(1 − p) = 0.9 × 0.1 = 0.09, so six rows sum to 0.54. min_child_weight constrains the hessian sum, not the row count, so confident rows count for less and the split is rejected. Option 1 treats the parameter as a row count, which it is not.

A table has a high-cardinality category (about four rows per value). You replace each category by the mean target of its rows, train on the encoded column, and see excellent training scores and poor validation scores. What is the most likely cause, and a CatBoost-style remedy?

  1. The category has too few values; use one-hot encoding with all 500 columns
  2. The model is under-fitted; add more rounds
  3. Each row's own label is inside its category's mean, which leaks; encode each row from earlier rows only, with a prior
  4. Mean encoding always fails; drop the column
With four rows per value, a quarter or more of the encoded value is the row's own label, so the feature looks predictive on training data and is not on new rows (in our run, a correlation of +0.49 with a pure coin-flip label). An ordered statistic (or out-of-fold encoding) removes the self-reference. One-hot could work but is wide and sparse, and the column may carry real signal, so dropping it is overkill.

Which statement best explains why boosted trees usually beat neural networks on typical medium-sized tabular datasets, according to the benchmark discussed in the chapter?

  1. Targets are often irregular, many columns are uninformative, and column axes carry meaning, all of which suit trees better than smooth, rotation-invariant networks
  2. Neural networks cannot be trained on tables at all
  3. Trees use more parameters, so they always fit better
