Regularisation & the Bias-Variance Trade-off

A model that fits its training data perfectly has usually learned the noise along with the signal. This chapter explains why, splits prediction error into three parts you can reason about, shows how learning curves tell you which part is hurting, and develops the two penalties, L2 and L1, that rein a model in.

Why this matters

Chapter 1 introduced overfitting as a symptom: training error low, validation error high. Chapter 5 ended with a model whose weights run off to infinity when the data is separable. Both are the same disease, and this chapter is the treatment. You will learn the vocabulary every practitioner uses to diagnose it (bias, variance, learning curves), the standard remedies (ridge, lasso, elastic net, and their cousins early stopping, depth limits and weight decay), and, just as important, when a remedy will not help. Almost every model in the rest of the course has a knob that trades flexibility against stability, and this is the chapter that explains what the knob is doing.

Fitting the noise

Data is signal plus noise. The signal is the repeatable relationship between inputs and the target; the noise is everything else (measurement error, the things nobody recorded, plain luck) and will be different the next time you collect data. A model should learn the first and ignore the second. The trouble is that the training set cannot tell them apart. A flexible enough model will bend to pass through every training point, and the bends that capture noise are exactly the ones that fail on new data.

We will use a deliberately simple world so that we know the truth and can measure everything. The true relationship is a smooth curve, f(x) = sin(2πx) for x between 0 and 1, and each observation adds noise with standard deviation 0.3. The model family is a polynomial of chosen degree: degree 1 is a straight line, degree 3 allows two bends, degree 12 allows eleven. Degree is a measure of model complexity (flexibility, or capacity): how many different shapes the family can express. This is a linear model in the sense of chapter 5, with columns 1, x, x2, …, xdegree.

Analogy: two students and an exam

One student prepares by memorising last year's paper, answer by answer. Given last year's paper again, they score 100 percent. Given this year's, they stumble, because they learned the particular questions and not the subject. Another student learns only one formula and applies it to everything. They score the same mediocre mark on both papers. The first student is high-variance: what they learned depends heavily on which paper they studied. The second is high-bias: their approach is too crude to capture what the subject asks, however many papers they see.

Where it breaks down: a student knows when a question looks unfamiliar and can say so. A fitted model returns a confident number for any input, including inputs far from anything it was trained on, and carries no warning.

Three kinds of error

Suppose you could repeat the whole exercise many times: draw a fresh training set of 15 points from the same world, fit the model, and look at its prediction at some fixed x. Each repetition gives a slightly different curve, because the noise in the training set is different. Now compare the predictions with the truth. The expected squared error at a point splits cleanly into three pieces:

E[(y − f̂(x))2] = (f(x) − E[f̂(x)])2 + E[(f̂(x) − E[f̂(x)])2] + σ2

Bias (squared, the first term)
How far the average prediction, over all possible training sets, is from the truth. A straight line fitted to a sine wave has high bias: however much data you give it, on average it misses the curve, because the family cannot bend.
Variance (the second term)
How much the prediction moves from one training set to the next. A degree-12 polynomial fitted to 15 points has high variance: it chases whichever noise it happened to see, so each training set produces a very different curve.
Irreducible error (σ2, the third term)
The noise in the target itself. No model can predict it. Here it is 0.32 = 0.09, so the best possible RMSE is 0.30.
Go deeper optional: the three-term derivation

Write the target as y = f + ε with E[ε] = 0, Var(ε) = σ2, and ε independent of the training set that produced f̂. Let m = E[f̂] be the average prediction over training sets. Add and subtract f and m inside the square: y − f̂ = ε + (f − m) + (m − f̂). Expand the square into six terms. Every cross term contains either ε (zero mean and independent of the rest) or (m − f̂) multiplied by a constant (zero mean, since E[f̂] = m), so each cross term has expectation zero. What survives is E[ε2] + (f − m)2 + E[(m − f̂)2]: noise, squared bias and variance. The identity is exact for squared error. For other losses (log-loss, 0-1 error) there are analogous decompositions but they are messier, and the intuition carries over while the clean formula does not.

The formula describes an experiment you cannot run on real data, where you have one training set. But in a simulation you can run it, which is how you get a feel for the shape. The script refits each polynomial degree on 500 fresh training sets (the same 15 evenly spaced x values each time, new noise each time) and measures all three terms on a grid of 101 test points. The last two columns are a check: the sum of the three terms and, separately, the error measured directly against fresh noisy targets.

import numpy as np

rng = np.random.default_rng(6)
f = lambda x: np.sin(2 * np.pi * x)              # the true curve
sigma, n_train, n_sets = 0.3, 15, 500
x_test = np.linspace(0, 1, 101)

def design(x, degree):
    return np.vander(2 * x - 1, degree + 1, increasing=True)   # columns 1, u, u^2, ... with u in [-1, 1]

print("degree  bias^2  variance  noise  bias^2+var+noise  measured test MSE")
for degree in (1, 2, 3, 4, 6, 9, 12):
    preds = np.empty((n_sets, len(x_test)))
    test_err = []
    for s in range(n_sets):
        x = np.linspace(0, 1, n_train)                       # same x positions every time; only the noise changes
        y = f(x) + rng.normal(0, sigma, n_train)          # a fresh training set each time
        w = np.linalg.lstsq(design(x, degree), y, rcond=None)[0]
        preds[s] = design(x_test, degree) @ w
        y_new = f(x_test) + rng.normal(0, sigma, len(x_test))
        test_err.append(np.mean((preds[s] - y_new) ** 2))
    bias2 = np.mean((preds.mean(axis=0) - f(x_test)) ** 2)
    var = np.mean(preds.var(axis=0))
    print(f"{degree:>6}  {bias2:6.3f}  {var:8.3f}  {sigma**2:5.2f}  {bias2 + var + sigma**2:16.3f}  {np.mean(test_err):17.3f}")

The last two columns agree to within sampling error, so the decomposition really is an identity. Read down the table. Degrees 1 and 2 have bias squared of 0.21: a line or a parabola cannot follow a full period of a sine wave. From degree 3 the bias vanishes (a cubic can follow a sine over this range) and a bigger family buys nothing. Meanwhile the variance climbs steadily, 0.011, 0.016, 0.022, 0.026, 0.036, 0.064, and then jumps to 0.50 at degree 12, when the model has 13 free parameters to fit 15 points and is close to interpolating them. The best expected error, 0.118, is at degree 3; degree 12 is five times worse.

One rule of thumb makes the variance column unsurprising. For a linear model fitted by least squares, the variance of the fitted values at the training points averages σ2 × (number of parameters) / (number of rows). That is 0.024 for the four parameters of a cubic with 15 rows, and approaches the whole noise variance as the parameter count approaches the row count. Between and beyond the training points, as at degree 12, it is worse. A model with as many parameters as rows can pass through every point exactly, which is perfect on the training set and tells you nothing about the next one.

Common misconception

"Overfitting means the training score is high." Overfitting is a gap between training and new-data performance, not a high training score. A model can have a modest training score and a larger gap, and a model with a near-perfect training score and a tiny gap is fine (a small, well-behaved dataset, a simple rule). Look at both numbers together. Equally, a model with poor scores on both sets is not overfitting: it is underfitting, which is a bias problem, and no penalty will cure it.

Learning curves: diagnosing which problem you have

On a real project you cannot refit 500 times, but you can do something cheaper that reveals the same thing. A learning curve plots the training error and the validation error of a model as the training set grows. Train on 12 rows and evaluate, then 16, then 24, and so on, always scoring on the same held-out validation data (cross-validation, chapter 13, makes this robust). Here are the curves for a line (degree 1) and for a degree-9 polynomial, averaged over 100 fits per point:

import numpy as np

rng = np.random.default_rng(7)
f = lambda x: np.sin(2 * np.pi * x)
sigma = 0.3
def design(x, degree): return np.vander(2 * x - 1, degree + 1, increasing=True)
x_val = np.linspace(0, 1, 200)

def curve(degree, sizes, repeats=100):
    rows = []
    for n in sizes:
        tr, va = [], []
        for _ in range(repeats):
            x = np.linspace(0, 1, n)
            y = f(x) + rng.normal(0, sigma, n)
            w = np.linalg.lstsq(design(x, degree), y, rcond=None)[0]
            tr.append(np.sqrt(np.mean((design(x, degree) @ w - y) ** 2)))
            y_v = f(x_val) + rng.normal(0, sigma, len(x_val))
            va.append(np.sqrt(np.mean((design(x_val, degree) @ w - y_v) ** 2)))
        rows.append((n, np.mean(tr), np.mean(va)))
    return rows

sizes = [12, 16, 24, 40, 80, 160, 320]
print(f"noise floor (RMSE of the best possible model): {sigma:.2f}")
for degree in (1, 9):
    print(f"\ndegree {degree}:   n   train RMSE   validation RMSE   gap")
    for n, tr, va in curve(degree, sizes):
        print(f"        {n:>4}   {tr:9.3f}   {va:15.3f}   {va - tr:5.3f}")

The two patterns look nothing alike, and each prescribes a different action.

  • High bias (the line). Training and validation error sit almost on top of each other at about 0.54, far above the 0.30 noise floor, and they stop improving by n = 24. The model is too limited for the task: there is little to gain from more rows and nothing to gain from regularisation (it would make the model even more rigid). Add features, add interactions, use a more flexible model family.
  • High variance (degree 9). Training error starts tiny (0.118 at 12 rows) and validation error starts high (0.451). The gap closes as rows increase, to 0.007 at 320 rows where both are close to 0.30. Here more data helps, and so do the other ways of restraining the model: a penalty, fewer features, a simpler family. A large, persistent gap with the curves still converging at your largest n is the signature that more data would pay.

A third reading, which is common and underrated: both curves are flat and near the noise floor. You are done; stop tuning. Chapter 4's baselines are the reference for "how low can it go", and chapter 2's question (what accuracy does the decision need?) tells you when to stop.

Regularisation: paying for complexity

Regularisation is any change that makes a model less able to fit noise, at the cost of fitting the signal slightly worse. The most common form adds a penalty on the size of the weights to the loss. The reasoning is that wild curves need big weights. A degree-12 polynomial that swings between −3 and +3 between neighbouring points is built from large, nearly cancelling coefficients, so a model forced to keep its weights small cannot swing.

Ridge (L2)

Ridge regression minimises the usual squared error plus the sum of the squared weights, scaled by a knob α (also written λ):

loss(w) = ∑i (yi − w · xi)2 + α ∑j wj2

The sum of squares is the squared L2 norm, which is where the name L2 penalty comes from. With α = 0 you get ordinary least squares. As α grows, the weights are pulled towards zero, and in the limit the model predicts the mean of the target for everyone. The solution is still a formula: the normal equations of chapter 5 gain a constant on the diagonal,

w = (XTX + αI)−1 XTy

and that diagonal is a bonus. Collinear features make XTX nearly singular; adding α to its diagonal makes it invertible and well-conditioned, so ridge also cures the unstable coefficients we saw in the collinearity demonstration of chapter 5. It does this by sharing weight between correlated features instead of letting them fight.

Go deeper optional: ridge as shrinkage along singular directions

Write the SVD of the centred feature matrix as X = USVT (A0 chapter 7) with singular values sk. Least squares fits the target along each principal direction with a coefficient proportional to 1/sk; ridge multiplies the fit along direction k by sk2 / (sk2 + α). Directions with large singular values (where the data varies a lot and the fit is well determined) are barely touched; directions with small singular values (where the data hardly varies, and the least-squares fit is mostly noise amplified by 1/sk) are shrunk almost to zero. Ridge is therefore a soft version of "drop the principal components with little variance", and the effective number of parameters, ∑k sk2/(sk2 + α), falls smoothly from the full count at α = 0 to zero.

Two practical rules come with any penalty on weights. First, standardise the features (mean 0, standard deviation 1) before fitting: the penalty adds up squares of weights, and a weight in "rent per square metre" is numerically a different size from the same weight in "rent per square foot", so without standardising the penalty favours some features arbitrarily. Second, do not penalise the intercept: it only sets the average level of the prediction, and shrinking it towards zero would bias every prediction for no reason. Centring the target and standardising the columns, as the code below does, takes care of both.

The experiment: 24 random training points from the same sine world, 1,000 fresh test points, and a degree-9 polynomial. The nine polynomial columns are strongly correlated, which is where unpenalised least squares is at its worst. The table sweeps α; the last block chooses it by 5-fold cross-validation on the training data alone.

import numpy as np

rng = np.random.default_rng(8)
f = lambda x: np.sin(2 * np.pi * x)
sigma, degree = 0.3, 9
x_tr = rng.uniform(0, 1, 24); y_tr = f(x_tr) + rng.normal(0, sigma, 24)
x_te = rng.uniform(0, 1, 1000); y_te = f(x_te) + rng.normal(0, sigma, 1000)

def powers(x):                                   # columns u, u^2, ..., u^9 with u = 2x - 1
    return np.column_stack([(2 * x - 1) ** k for k in range(1, degree + 1)])

def ridge_fit(X, y, alpha):
    mu, sd = X.mean(0), X.std(0)
    Z = (X - mu) / sd                            # standardise: the penalty treats all columns alike
    yc = y - y.mean()                            # centring y means the intercept is never penalised
    w = np.linalg.solve(Z.T @ Z + alpha * np.eye(Z.shape[1]), Z.T @ yc)
    return lambda Xn: y.mean() + ((Xn - mu) / sd) @ w, w

rmse = lambda a, b: float(np.sqrt(np.mean((a - b) ** 2)))
X_tr, X_te = powers(x_tr), powers(x_te)
print("alpha      train RMSE  test RMSE  sum |w|     largest |w|")
for alpha in (0, 1e-4, 1e-2, 1, 3, 10, 100, 1000):
    predict, w = ridge_fit(X_tr, y_tr, alpha)
    print(f"{alpha:<9g}  {rmse(predict(X_tr), y_tr):9.3f}  {rmse(predict(X_te), y_te):9.3f}  {np.abs(w).sum():9.2f}  {np.abs(w).max():10.2f}")

# choose alpha by 5-fold cross-validation on the training data only
folds = np.arange(24) % 5
best = None
for alpha in (1e-4, 1e-2, 0.1, 0.3, 1, 3, 10, 30, 100):
    errs = []
    for k in range(5):
        predict, _ = ridge_fit(X_tr[folds != k], y_tr[folds != k], alpha)
        errs.append(rmse(predict(X_tr[folds == k]), y_tr[folds == k]))
    cv = float(np.mean(errs))
    if best is None or cv < best[1]: best = (alpha, cv)
predict, _ = ridge_fit(X_tr, y_tr, best[0])
print(f"\n5-fold CV picks alpha = {best[0]} (CV RMSE {best[1]:.3f}); test RMSE = {rmse(predict(X_te), y_te):.3f}")
print(f"noise floor: {sigma}")

With no penalty the test RMSE is 4.5 (fifteen times the noise level), coming from weights as large as 40 that cancel each other on the training points and blow up between them. Training error is as low as it will ever be, 0.294, below the noise floor of 0.30: the signature of fitting noise. A tiny penalty, α = 0.0001, already cuts the test error to 1.9 and the largest weight to 12.9; α = 0.01 takes it to 0.39. Beyond that the picture is the familiar trade-off: training error rises steadily (0.30, 0.36, 0.43, 0.55, 0.80, 0.91) because the model is being held back, while test error bottoms out and rises again as the model becomes too rigid (0.69 at α = 100). The test column is bumpy rather than a smooth U (0.39, 0.49, 0.40) because one dataset of 24 points is a noisy experiment, a reminder that a single split gives a noisy picture of the best α. Cross-validation chose 0.1 and delivered a test RMSE of 0.425, close to the best value in the table, using nothing but the training data.

α is a hyperparameter: a setting you choose rather than learn from the training loss. If you minimised the training loss over α as well, you would always pick zero. The choice must be made on data the fit did not see: a validation set or cross-validation. The tuning loop itself overfits a little if you try thousands of settings on a small validation set, one reason the final test set must stay untouched (chapter 1, and in depth chapter 13).

Lasso (L1) and sparsity

Replace the squared weights by their absolute values and you get the lasso (least absolute shrinkage and selection operator, Tibshirani, 1996, "Regression Shrinkage and Selection via the Lasso"):

loss(w) = (1/2n) ∑i (yi − w · xi)2 + α ∑j |wj|

The sum of absolute values is the L1 norm. The change looks cosmetic and has a dramatic consequence: the lasso sets many weights to exactly zero, so it selects features as well as shrinking them. Ridge shrinks every weight a little and never reaches zero.

The geometry explains it. A penalty is the same as a budget on the weights: for some r, minimise the squared error subject to ∑wj2 ≤ r2 (a disc) or ∑|wj| ≤ r (a diamond). The squared error has elliptical level curves around the unpenalised optimum. The constrained answer is where the smallest ellipse that reaches the allowed region just touches it.

A disc has no corners, so the touching point is wherever the geometry puts it, usually with both weights non-zero. A diamond has corners on the axes, where one weight is exactly zero, and an ellipse approaching a pointed corner reaches it first for a whole range of orientations. In more dimensions the diamond becomes a polytope with corners, edges and faces of every dimension, and a high-dimensional contact point is very likely to land on one of the low-dimensional ones, where many weights are zero.

The algorithm that fits the lasso, coordinate descent, is short. Standardise the columns so each has mean square one. Then cycle through the features: remove feature j's current contribution from the residuals, compute the best single weight for it given everything else (ρj = the average of feature j times the residual), and apply the soft-threshold operator, S(ρ, α) = sign(ρ) · max(|ρ| − α, 0): shrink towards zero by α, and if the result would cross zero, stop at zero. Repeat until the weights stop changing. The code is a dozen lines, and the demonstration below uses 100 rows, 20 features of which only 5 matter (true weights 3, −2, 1.5, 1, −1; the other 15 columns are pure noise) and a noise standard deviation of 3, so the signal is noticeable but not obvious:

import numpy as np

rng = np.random.default_rng(9)
n, d = 100, 20
w_true = np.zeros(d); w_true[:5] = [3, -2, 1.5, 1, -1]       # 5 real signals, 15 irrelevant columns
def make(n):
    X = rng.normal(size=(n, d)); return X, X @ w_true + rng.normal(0, 3, n)
X, y = make(n); X_te, y_te = make(2000)
mu, sd = X.mean(0), X.std(0); Z, Zte = (X - mu) / sd, (X_te - mu) / sd
yc, ybar = y - y.mean(), y.mean()

def soft(r, t): return np.sign(r) * np.maximum(np.abs(r) - t, 0)

def lasso(Z, y, alpha, sweeps=200):
    """Coordinate descent for (1/2n)||y - Zw||^2 + alpha * sum|w|, columns standardised."""
    n, d = Z.shape; w = np.zeros(d); r = y.copy()
    for _ in range(sweeps):
        for j in range(d):
            r += Z[:, j] * w[j]                          # remove feature j's contribution
            w[j] = soft(Z[:, j] @ r / n, alpha)          # best single weight, shrunk towards 0
            r -= Z[:, j] * w[j]
    return w

def ridge(Z, y, alpha): return np.linalg.solve(Z.T @ Z + alpha * len(y) * np.eye(Z.shape[1]), Z.T @ y)
rmse = lambda w: float(np.sqrt(np.mean((ybar + Zte @ w - y_te) ** 2)))

print("noise sd is 3.0; true signals are features 0-4")
print("alpha   lasso: kept  which features                 test RMSE | ridge test RMSE  nonzero")
for a in (0.0, 0.05, 0.2, 0.5, 1.0, 2.0):
    wl = lasso(Z, yc, a); wr = ridge(Z, yc, a)
    keep = [int(j) for j in np.flatnonzero(np.abs(wl) > 1e-9)]
    shown = str(keep) if len(keep) <= 9 else str(keep[:8])[:-1] + ", ...]"
    print(f"{a:<5}  {len(keep):>11}  {shown:<30} {rmse(wl):6.3f}  | {rmse(wr):14.3f}  {int(np.sum(np.abs(wr) > 1e-9)):>7}")

Common misconception

"The lasso finds the true features." It finds a sparse set that predicts well, and when features are correlated the choice among them is close to arbitrary. We can show it. Take two features with correlation 0.92, both truly important with equal effect, and run the lasso on 200 bootstrap resamples of the same 100 rows, using a penalty strong enough to drop one (α = 2.0):

import numpy as np

rng = np.random.default_rng(10)
n = 100
x1 = rng.normal(size=n)
x2 = 0.95 * x1 + np.sqrt(1 - 0.95 ** 2) * rng.normal(size=n)      # correlation about 0.95 with x1
y = 1.5 * x1 + 1.5 * x2 + rng.normal(0, 2, n)                      # both genuinely matter, equally
print("corr(x1, x2) =", round(float(np.corrcoef(x1, x2)[0, 1]), 3))

def soft(r, t): return np.sign(r) * np.maximum(np.abs(r) - t, 0)
def lasso(Z, y, alpha, sweeps=300):
    n, d = Z.shape; w = np.zeros(d); r = y.copy()
    for _ in range(sweeps):
        for j in range(d):
            r += Z[:, j] * w[j]; w[j] = soft(Z[:, j] @ r / n, alpha); r -= Z[:, j] * w[j]
    return w
def ridge(Z, y, alpha): return np.linalg.solve(Z.T @ Z + alpha * len(y) * np.eye(2), Z.T @ y)

counts = {"x1 only": 0, "x2 only": 0, "both": 0, "neither": 0}
w_l, w_r = [], []
for b in range(200):
    idx = rng.integers(0, n, n)
    Z = np.column_stack([x1[idx], x2[idx]]); Z = (Z - Z.mean(0)) / Z.std(0); yc = y[idx] - y[idx].mean()

The lasso dropped the first feature in 80 of 200 resamples, the second in 19, and kept both in only 101: which one it "selected" depended on which rows were drawn. The ridge weights, meanwhile, are almost identical (0.66 and 0.67) and steady (standard deviation 0.06 and 0.05): it shares credit between correlated features. Do not read lasso's survivors as a list of causes; stability selection (repeat on resamples and keep what survives often) and domain knowledge are the safeguards.

Elastic net, and how the libraries name things

The elastic net adds both penalties, with a mixing ratio between them: it keeps the lasso's sparsity but, because of the L2 part, tends to keep groups of correlated features together instead of picking one at random. It is the sensible default when you want some sparsity and have correlated inputs. In scikit-learn terms Ridge(alpha) minimises the sum of squared errors plus alpha times the squared weight norm, Lasso(alpha) minimises half the mean squared error plus alpha times the L1 norm, and the factor of n between those conventions matters when you compare alphas (our ridge above scales by n for that reason). Logistic regression reverses the knob: C is the inverse penalty strength, so a small C means a strong penalty. Always check which convention a library uses before comparing numbers.

Go deeper optional: penalties as priors

In A0 chapter 13, squared error was a Gaussian likelihood in disguise. Add a prior over the weights and the maximum a posteriori estimate maximises likelihood × prior, which means minimising negative log-likelihood plus negative log-prior. A Gaussian prior on each weight, centred on zero with variance τ2, has negative log-density proportional to w2/(2τ2): exactly the ridge penalty, with α = σ2/τ2. A Laplace (double exponential) prior has negative log-density proportional to |w|: the lasso. So the penalty strength states how strongly you believed, before seeing data, that weights are small; and the Laplace prior's sharp peak at zero is why it produces exact zeros. This is the same trade-off, reached from probability instead of geometry.

Other ways to restrain a model

A weight penalty is one instance of a broader idea: anything that restricts what the model can fit, or gives it more evidence, reduces variance. The same trade-off, with different knobs, appears in every model family in this course.

Early stopping deserves a sentence of its own because it needs no formula. Start gradient descent from zero weights (chapter 5) and watch validation error. At first the loss falls on both sets; later training loss keeps falling while validation loss turns up. Stopping at the turn is a regulariser: the weights have not had time to grow large. For a linear model it is, to a good approximation, equivalent to ridge. It is cheap and universal, which is why it is the first regulariser everybody reaches for in boosting and neural networks.

Beyond the textbook picture

The U-shaped curve in this chapter is the classical account and it holds for the models here. It is not the whole story for very large models. Belkin, Hsu, Ma and Mandal (2019), "Reconciling modern machine-learning practice and the classical bias-variance trade-off", reported that for some model families test error falls, rises to a peak where the model just fits the training data exactly (the interpolation threshold), and then falls again as capacity grows further: a "double descent" curve, and the paper reports it for several model families, including neural networks and random forests. This does not undo the lessons above. At the peak the variance is as bad as the table showed at degree 12; the second descent depends on how the extra capacity is used (implicit or explicit regularisation, the training algorithm) and on the data; and for the tabular problems of this course, a tuned, regularised model of moderate size remains the dependable choice. Treat it as a reminder that "more parameters always overfit" is a rule of thumb, not a theorem.

Systems connection

Complexity has a running cost as well as a statistical one. In a deployed model every non-zero weight is a feature the serving system must compute, fetch and keep consistent with training, which is the skew problem described in Designing with ML & LLMs. A lasso that keeps 40 of 4,000 candidate features is 100 times cheaper to feed than the full model, and 100 fewer upstream pipelines can break or drift. Regularisation also stabilises retraining: a ridge-penalised model's weights change smoothly when the training window moves, whereas an unpenalised one with collinear features may flip its coefficients between weekly refits, making monitoring noisy and explanations inconsistent.

Key takeaways

  • Expected squared error on new data equals bias squared plus variance plus irreducible noise. Bias is error from a model family too rigid to express the truth; variance is error from the model changing with the training sample; noise cannot be removed.
  • Flexibility lowers bias and raises variance, so test error is U-shaped in model complexity in the classical setting. The best model is usually in the middle, and the penalty for too much flexibility is sharpest when parameters approach rows.
  • Learning curves diagnose which problem you have: curves that converge high mean bias (add features or flexibility); a persistent gap means variance (add data, simplify or regularise); both flat near the noise floor means stop.
  • Ridge (L2) adds the squared weight norm to the loss, shrinks all weights, stabilises correlated features and has a closed form. Lasso (L1) adds the absolute weight norm, drives many weights exactly to zero, and selects features, but its choices among correlated features are unstable. Elastic net mixes them.
  • Standardise features before penalising them, do not penalise the intercept, and choose the penalty strength by validation or cross-validation, never by training loss.
  • Penalties are one tool among many: more data, fewer features, depth limits, averaging, early stopping and weight decay all trade a little bias for a lot less variance.

Check your understanding

A learning curve shows training RMSE 0.52 and validation RMSE 0.54 at every training-set size from 50 to 5,000 rows. The irreducible noise is about 0.30. Which action is most likely to help?

  1. Collect ten times more training rows
  2. Increase the strength of the L2 penalty
  3. Add informative features or move to a more flexible model family
  4. Stop tuning, because the model is already at its best
Both curves are flat, close together and well above the noise floor: classic high bias. More rows will not change flat curves, and a stronger penalty makes an already rigid model more rigid. The model is not at its best, because 0.52 is far above the 0.30 floor, so stopping would leave a lot of error unexplained.

In the decomposition of expected squared error into bias squared, variance and noise, which term can no choice of model or amount of data reduce?

  1. The noise term, because it comes from the target itself
  2. The variance term, because it depends on the training sample
  3. The bias term, because the model family is fixed
  4. None of them: all three can be driven to zero with enough data
The noise term is the variance of the target around the true function, which no predictor can remove. Variance falls with more data or a restrained model, and bias falls with a richer family, so those two can be reduced. With an infinite dataset variance goes to zero but the noise stays.

You are about to fit a ridge model on features in very different units: area in square metres (up to 120), distance in kilometres (up to 15), and age in years. What should you do first, and why?

  1. Nothing: ridge is invariant to feature units
  2. Remove the intercept, because the penalty applies to it too
  3. Take the logarithm of every feature so that they are comparable
  4. Standardise the features, because the penalty on a weight depends on the units of its feature
The penalty sums squared weights, and a weight's numerical size depends on the units of its feature, so unstandardised features are penalised unevenly (the feature measured in small units has large weights and is shrunk hard). Ridge is not unit-invariant. The intercept is normally left out of the penalty, not removed. Logarithms change the shape of relationships and are not a general fix for scale.

Two features are nearly identical copies of each other and both genuinely matter. Compared with ridge, what will the lasso typically do?

  1. Give both features exactly equal weights, as ridge does
  2. Keep one and drop the other, with the choice varying from sample to sample
  3. Drop both, because it cannot tell which one matters
  4. Keep both with larger weights than least squares would give
With near-duplicate columns the L1 penalty is the same whichever one carries the weight, so small differences in the sample decide, and the surviving feature can change on resampling (in our run, 80 of 200 resamples kept only the second and 19 only the first). Ridge's squared penalty prefers to split the weight, giving similar weights to both. Dropping both would happen only with a very strong penalty, and neither penalty enlarges weights beyond least squares.

A colleague picks the ridge penalty by trying 500 values and keeping the one with the lowest test-set error, then reports that test error as the model's expected performance. What is wrong?

  1. Nothing, as long as the test set is large
  2. The penalty should be the one with the lowest training error instead
  3. The test set has been used to make a decision, so its error is now optimistic; the penalty should be chosen on validation data or by cross-validation
  4. Ridge penalties can only be chosen by a closed-form formula
Once the test set guides a choice it is no longer an unbiased measurement: with 500 tries the winner partly reflects luck on that particular sample. Training error always prefers no penalty, so it cannot choose alpha. Cross-validation or a separate validation split exists exactly for tuning, leaving the test set for one final honest estimate. Size helps a little but does not remove the selection effect.

In the bias-variance explorer, you fix the degree at 12 with 15 training points and raise the number of training points to 60 with no penalty. What happens to the three error terms?

  1. Variance falls sharply, bias stays near zero, noise is unchanged
  2. Bias rises and variance falls by the same amount
  3. All three fall, because more data reduces noise
  4. Nothing changes, because the degree is the same
With 60 rows the 13 parameters are well determined, so the fits agree with each other (low variance); the model family is unchanged so bias remains near zero. The noise term is a property of the target and does not move. More data is a regulariser through variance only: it does not make the family more or less flexible, which is why it cannot fix a high-bias model.
