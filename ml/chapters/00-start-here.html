Learning from examples

There are two ways to get a computer to do something like "decide whether this email is spam". You can write the rules yourself: if the subject contains "WINNER" and the sender is unknown, flag it. This works until the spammers change their wording, and it needs an expert to keep it current. Or you can give the computer many examples, emails already marked as spam or not, and let an algorithm find a rule that fits them. That second way is machine learning: a program improves at a task by fitting a function to data instead of being given the function.

The vocabulary is small. Each example has features, the facts you feed in (word counts, sender age, number of links), and in the usual setting a label, the answer you wish you could predict (spam or not). Collected together, the features form a matrix X with one row per example and one column per feature, so its shape is (n_samples, n_features); the labels form a vector y with one entry per row. The learned function is the model, and the step that finds it is training, or fitting. This course uses scikit-learn's conventions throughout: model.fit(X, y) to train and model.predict(X_new) to use it.

When the labels are present this is supervised learning, and it comes in two flavours: classification (predict a category) and regression (predict a number). When there are no labels and you look for structure, such as groups of similar customers, it is unsupervised learning. This course works with the labelled kind. Almost everything else you will meet, from boosted trees to the large models of later courses, is a variation on these ideas.

A first taste: memorising versus learning

Here is the idea the whole course is organised around, in a dozen lines. Students study for a number of hours, and each passes or fails; the true relationship is noisy, so the same hours do not always give the same result. We draw 40 students to train on and a fresh 1,000 to test on. Two "models" compete. The memoriser predicts, for any new student, the label of the single most similar training student (1-nearest-neighbour: pure lookup). The threshold model learns one cut-off in hours that gets the most training examples right.

"""Two ways to answer 'will this student pass?': memorise the examples, or learn a rule."""
import random

rng = random.Random(0)

def make(n):
    rows = []
    for _ in range(n):
        hours = round(rng.uniform(0, 10), 1)        # hours studied
        p_pass = 1 / (1 + 2.718 ** (-(hours - 5)))  # real, noisy relationship
        rows.append((hours, int(rng.random() < p_pass)))
    return rows

train, test = make(40), make(1000)

def memoriser(x, data):
    """1-nearest-neighbour: copy the label of the closest training example."""
    return min(data, key=lambda r: abs(r[0] - x))[1]

def learn_threshold(data):
    """Pick the cut-off on hours that gets the most training examples right."""
    cuts = sorted({h for h, _ in data})
    return max(cuts, key=lambda c: sum((h >= c) == y for h, y in data))

cut = learn_threshold(train)
def acc(pred, data):
    return sum(pred(h) == y for h, y in data) / len(data)

print(f"learned cut-off: {cut} hours")
print(f"{'model':<12}{'train acc':>10}{'test acc':>10}")
print(f"{'memoriser':<12}{acc(lambda h: memoriser(h, train), train):>10.3f}{acc(lambda h: memoriser(h, train), test):>10.3f}")
print(f"{'threshold':<12}{acc(lambda h: int(h >= cut), train):>10.3f}{acc(lambda h: int(h >= cut), test):>10.3f}")
learned cut-off: 4.2 hours
model        train acc  test acc
memoriser        0.950     0.835
threshold        0.900     0.852

The memoriser looks better on the training data (0.950 against 0.900), because it can copy even the unlucky cases. On 1,000 students it has never seen it is worse: 0.835 against 0.852. The simpler model had learned the pattern; the other had absorbed some of the noise. (The memoriser scores 0.95, not 1.0, because two students with the same rounded hours and different results cannot both be copied.) Judging a model by the data it was trained on rewards memory; judging it on fresh data rewards learning. Chapter 1 turns this observation into a discipline.

The data-science loop

A newcomer imagines the work as picking the right algorithm. In practice, fitting the model is a small box in a larger loop, and the loop is where projects succeed or fail.

Each step has a typical failure. A project that skips framing optimises a number nobody needs. One that skips EDA trains on duplicated or shifted data. One that skips the baseline cannot tell a good model from a bug. One that validates carelessly ships a leak. One that never monitors finds out about drift from angry customers. None of these failures is an algorithm problem, which is why this course teaches framing and validation, and leaves the algorithms to later courses and to the library you use.

What this course covers

A1 is deliberately short. It has five chapters, this one and four more, because those four hold the ideas that every later course relies on and that are easiest to get wrong. It has one lab and two case studies, and no studios. The course teaches how to judge a learned model. Algorithms such as trees and boosting are not taught here: in later courses a model is something you train, call or evaluate, and the habits below are how you tell whether it works.

Part 1: Framing problems
Generalisation (training, validation and test sets, overfitting and underfitting) and framing problems and choosing metrics. You decide what to predict and how to judge it before you build anything.
Part 2: Validation
Cross-validation with splits that mirror how the model will be used, and leakage, the silent way a good-looking number turns out to be false. The lab, The Leakage Hunt, asks you to build a validation harness that catches four planted leaks.

How to study this course

  • Depth tags. Each chapter is labelled deep, core or intro. Deep chapters derive things in full and contain widgets and several code experiments; core chapters give the working knowledge; intro chapters orient you. The reading time in the page header is an estimate for a first pass.
  • Run the code. Listings in the chapters were run, and the output beside them is real. Scripts use only the Python standard library and NumPy, so you can run every one on a laptop in seconds. Where a scikit-learn listing would be the natural way to write something, the chapter shows it labelled "not run here" and runs an equivalent that we wrote.
  • Data is synthetic and seeded. Examples generate small datasets from a random seed and describe them concretely. Synthetic data lets us plant a problem (a leak, a drift, a missing pattern) and check that a method finds it. Real data is messier, and the case studies cover real systems.
  • The lab runs offline. The lab is a Python starter file plus a check.py that tells you which milestones pass, and needs nothing but Python 3.9 or later. Writing the algorithm yourself, in plain Python, is the quickest way to learn what scikit-learn is doing for you.
  • Quizzes check application. Each chapter ends with questions that ask what you would do, not what a term means. Answer before opening the explanation.
  • Case studies. The two cases analyse real episodes: a flu-forecasting system whose early accuracy did not hold, and the leaks that won competitions.

Common misconception

"Machine learning is mostly about choosing the right algorithm." On tabular business data a small set of methods (regularised linear models and gradient-boosted trees) covers most needs. The differences that change outcomes are usually in the framing, the data, the validation and the monitoring. An excellent algorithm with a leaky validation scheme is worse than a mediocre one with an honest one.

  1. Raise the training set from 40 students to 400. Does the memoriser's test accuracy move towards the threshold model's? Why might it?

Key takeaways

  • Machine learning fits a function to examples. Features go into X of shape (n_samples, n_features); labels go into y; fit learns and predict uses.
  • Scoring a model on the data it was trained on rewards memory. A lookup model had better training accuracy (0.950 against 0.900) and worse test accuracy (0.835 against 0.852).
  • The data-science loop is: frame, explore, baseline, model, validate, deploy, monitor. The model is one box of seven.
  • This course has five chapters (this one, generalisation, metrics, cross-validation and leakage), one lab and two case studies. It builds on A0 and underpins A2 to A12, especially the evaluation habits of A6 and the held-out discipline of the artifacts.
  • Study by running the code, writing the labs from scratch and answering the quizzes before reading the explanations.

Check your understanding

In scikit-learn conventions, a table of 500 customers with 12 features each and a yes/no label is stored as:

  1. X of shape (12, 500) and y of shape (12,)
  2. X of shape (500, 12) and y of shape (500,)
  3. X of shape (500, 13) with the label inside
  4. X of shape (500,) and y of shape (12,)
Rows are samples and columns are features, so X is (n_samples, n_features) = (500, 12), and y has one entry per sample. Option 1 transposes the table; option 3 mixes the label into the features, which would leak the answer.

A model scores 100% on its training data and 70% on new data; a simpler model scores 85% and 82%. Which statement is best supported?

  1. The first is better, because it has the higher training score.
  2. The two are equally good, since both exceed 70%.
  3. The first is better, because a lower new-data score means the new data is wrong.
  4. The simpler model generalises better; the first has memorised noise in the training data.
What matters is performance on unseen data: 82% beats 70%, and the 30-point gap for the first model is the signature of overfitting. Training scores reward memory, which is the lesson of the first experiment in this chapter.

Which step of the data-science loop is most likely to be skipped by a team eager to show results, and what does skipping it cost?

  1. The baseline: the team cannot tell whether a good-looking score is good, or whether the pipeline is correct.
  2. The training step: no model exists.
  3. Choosing the programming language: nothing runs.
  4. Exporting the model: nobody can see it.
Baselines and honest validation are the usual casualties because they produce no exciting artifact, yet they are what makes any number meaningful. The other options describe steps nobody skips or that do not determine whether results are trustworthy.

Which task is unsupervised learning?

  1. Predicting next month's sales from past sales and prices.
  2. Classifying images as cat or dog using labelled photos.
  3. Grouping customers by purchasing behaviour without any predefined groups.
  4. Predicting whether a loan will default using past outcomes.
Unsupervised learning has no label to predict and looks for structure, as in clustering. The other three have a target (sales, cat or dog, default), so they are supervised: regression, classification and classification.
