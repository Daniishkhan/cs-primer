Tabular Deep Learning & Foundation Models

Neural networks conquered images, speech and text, yet on ordinary tables boosted trees have stayed hard to beat. This chapter explains why the gap exists, what neural networks designed for tables do about it, and how a different idea, a model pre-trained on millions of synthetic tables that classifies a new one without training, has changed the picture for small datasets.

Why this matters

You will be told, often, that deep learning makes the old methods obsolete. For tabular data the honest answer is "sometimes, and here is when". Knowing the reasons behind that answer lets you decide quickly whether a neural network or a foundation model is worth a day of your time on a given problem, and lets you read benchmark claims critically. It also connects this course to the next: A2 builds the networks used here from the ground up, so this chapter treats them as given and asks only whether tables suit them.

Why trees keep winning on tables

A tabular dataset is a table of heterogeneous columns: ages, postcodes, prices, flags, each with its own meaning and scale, and no inherent order among columns. Images and text are different: pixels and words are homogeneous, their neighbours matter, and a convolution or an attention layer builds that structure into the model. For tables, gradient-boosted trees have been the default winner for a decade, and Grinsztajn, Oyallon and Varoquaux (2022), "Why do tree-based models still outperform deep learning on tabular data?", measured it carefully on a standard collection of 45 datasets: tree-based models remain state of the art on medium-sized data (around 10,000 samples), even before counting their speed advantage, after a large hyperparameter search for every model (about 20,000 compute hours).

Their explanation is about inductive bias, the assumptions a model makes before it sees data. Three differences stand out.

  1. Irregular targets. Real tabular targets often change abruptly: a risk that jumps at an age threshold, a price that steps at a round number. Trees fit step functions directly. Neural networks, trained by gradient descent, prefer smooth functions and learn sharp features slowly.
  2. Uninformative columns. Tables often contain many columns that carry no signal. A tree simply never splits on them. A fully connected network wires every input into every unit, so noise columns add variance unless the network is regularised or the data is large.
  3. Orientation matters. The columns of a table have meaning. A network's first layer is a matrix multiplication, so it treats a rotation of the inputs as an equivalent problem, whereas for a table the original axes (age, income) are the informative directions. Trees, which split one column at a time, use that.

The experiment tests each claim on a synthetic table of 2,000 training rows whose target depends in a step-like way on four columns (signs, a sine's sign, and a conjunction), with the log-odds known so that we can compute the best achievable AUC. It compares a boosted-tree model with a small multilayer perceptron written in NumPy (two hidden layers of 64 units, the Adam optimiser of chapter 10 of A0, early stopping on 20% of the training rows). The columns are then varied in two ways: 10 and 40 uninformative columns added, and, with none added, the four informative columns mixed by a random rotation.

"""Trees versus a small neural network on a table with an irregular target and uninformative columns."""
import numpy as np
from lib import Boost, roc_auc, sigmoid

def make(n, d_noise, rng):
    X = rng.uniform(-1, 1, (n, 4))
    z = (2.0 * np.sign(X[:, 0] - 0.3) + 1.5 * np.sign(np.sin(7 * X[:, 1])) + 1.2 * ((X[:, 2] > 0) & (X[:, 3] < 0.2)) - 0.8)
    y = (rng.random(n) < sigmoid(z)).astype(float)       # irregular, step-like dependence on 4 columns
    make.z = z                                           # remember the true log-odds (only to print the ceiling)
    return np.c_[X, rng.normal(size=(n, d_noise))], y    # plus d_noise columns that carry no information

def mlp_fit_predict(Xtr, ytr, Xte, rng, hidden=64, epochs=120, lr=2e-3, wd=1e-4):
    mu, sd = Xtr.mean(0), Xtr.std(0) + 1e-9; A, B = (Xtr - mu) / sd, (Xte - mu) / sd
    k = len(A) * 4 // 5; Atr, ytr2, Aval, yval = A[:k], ytr[:k], A[k:], ytr[k:]      # last 20% for early stopping
    P = {"W1": rng.normal(0, np.sqrt(2 / A.shape[1]), (A.shape[1], hidden)), "b1": np.zeros(hidden),
         "W2": rng.normal(0, np.sqrt(2 / hidden), (hidden, hidden)), "b2": np.zeros(hidden),
         "W3": rng.normal(0, np.sqrt(1 / hidden), (hidden, 1)), "b3": np.zeros(1)}
    M = {k_: np.zeros_like(v) for k_, v in P.items()}; V = {k_: np.zeros_like(v) for k_, v in P.items()}
    def fwd(X):
        h1 = np.maximum(X @ P["W1"] + P["b1"], 0); h2 = np.maximum(h1 @ P["W2"] + P["b2"], 0)
        return h1, h2, (h2 @ P["W3"] + P["b3"]).ravel()
    best, best_P, step = -1, None, 0
    for ep in range(epochs):
        order = rng.permutation(len(Atr))
        for i in range(0, len(order), 64):
            idx = order[i:i + 64]; x, t = Atr[idx], ytr2[idx]
            h1, h2, z = fwd(x); g = ((sigmoid(z) - t) / len(idx))[:, None]            # d(loss)/d(logit) for cross-entropy
            G = {"W3": h2.T @ g, "b3": g.sum(0)}; d2 = (g @ P["W3"].T) * (h2 > 0)
            G["W2"], G["b2"] = h1.T @ d2, d2.sum(0); d1 = (d2 @ P["W2"].T) * (h1 > 0)
            G["W1"], G["b1"] = x.T @ d1, d1.sum(0); step += 1
            for k_ in P:                                                               # Adam update
                M[k_] = 0.9 * M[k_] + 0.1 * G[k_]; V[k_] = 0.999 * V[k_] + 0.001 * G[k_] ** 2
                P[k_] -= lr * (M[k_] / (1 - 0.9 ** step)) / (np.sqrt(V[k_] / (1 - 0.999 ** step)) + 1e-8) + lr * wd * P[k_]
        a = roc_auc(fwd(Aval)[2], yval.astype(int))
        if a > best: best, best_P = a, {k_: v.copy() for k_, v in P.items()}
    P.update(best_P)
    return fwd(B)[2]

def rotation(d, rng):
    q, _ = np.linalg.qr(rng.normal(size=(d, d))); return q

print(f"{'uninformative cols':<20}{'boosted trees':>14}{'MLP':>8}{'trees, rotated':>16}{'MLP, rotated':>14}{'ceiling':>9}")
for d_noise in (0, 10, 40):
    rng = np.random.default_rng(19 + d_noise)
    Xtr, ytr = make(2000, d_noise, rng); Xte, yte = make(6000, d_noise, rng); ceiling = roc_auc(make.z, yte.astype(int))
    gb = lambda A, B: Boost(rounds=150, lr=0.1, depth=4, min_leaf=20).fit(A, ytr).predict(B)
    a_gb = roc_auc(gb(Xtr, Xte), yte.astype(int)); a_nn = roc_auc(mlp_fit_predict(Xtr, ytr, Xte, rng), yte.astype(int))
    if d_noise == 0:
        Q = rotation(Xtr.shape[1], rng); R_tr, R_te = Xtr @ Q, Xte @ Q                  # same information, columns mixed
        r_gb = roc_auc(gb(R_tr, R_te), yte.astype(int)); r_nn = roc_auc(mlp_fit_predict(R_tr, ytr, R_te, rng), yte.astype(int))
        print(f"{d_noise:<20}{a_gb:>14.3f}{a_nn:>8.3f}{r_gb:>16.3f}{r_nn:>14.3f}{ceiling:>9.3f}")
    else:
        print(f"{d_noise:<20}{a_gb:>14.3f}{a_nn:>8.3f}{'':>16}{'':>14}{ceiling:>9.3f}")
uninformative cols   boosted trees     MLP  trees, rotated  MLP, rotated  ceiling
0                            0.885   0.807           0.778         0.824    0.902
10                           0.874   0.772                                  0.898
40                           0.867   0.749                                  0.892

Start with the first row. On the clean table the boosted trees reach an AUC of 0.885 against a ceiling of 0.902, and the network 0.807: the irregular target favours the trees. Adding noise columns costs the trees little (0.874 and then 0.867) and the network a lot (0.772 and 0.749), the second effect. The rotated columns show the third: the trees fall from 0.885 to 0.778 because the informative axes are gone, while the network's score barely moves in the other direction (0.807 to 0.824, within what to expect from training noise), because it never relied on the axes. Each claim from the paper appears in a toy world, which does not prove it for yours. It does show what to look for.

Common misconception

"Neural networks are worse on tables because they are not good enough yet." The gap is not about capability or training budget; it is about fit between the model's assumptions and the data. A network given an easy, smooth target, a very large table, or several data types at once (text, images and numbers together) can match or beat trees. Equally, a tree ensemble on 50 rows will not. Ask what the data looks like, not which family is newer.

Neural networks built for tables

The research response to those three biases has been architectures and preprocessing designed for tables. Gorishniy, Rubachev, Khrulkov and Babenko (2021), "Revisiting Deep Learning Models for Tabular Data", compared many proposals under one protocol and made two points that still hold. A plain ResNet-like network (an MLP with skip connections, normalisation and dropout, A2 chapter 3) is a strong baseline that earlier papers omitted. And their FT-Transformer, which turns each column into a learned embedding vector and runs a transformer over those column tokens, performed best on most tasks; they also found that no model was universally superior, and that boosted trees remained ahead on some datasets.

The common ingredients in modern tabular networks are worth knowing because each answers one of the biases above.

Numerical embeddings
Instead of feeding a number in directly, map it through periodic functions (sines and cosines at learned frequencies) or piecewise-linear bins before the network. This lets the model represent sharp changes in one column, which answers the "irregular target" problem.
Quantile transform
Replace each column's values by their rank, rescaled to a uniform or normal shape. It tames skew and outliers, like the log transforms of chapter 17.
Categorical embeddings
A learned vector per category, replacing one-hot encoding. Useful for high-cardinality columns, with the caveat that rare categories need enough data to learn a vector.
Ensembling inside the model
Architectures such as TabM (Gorishniy et al., 2024, "TabM: Advancing Tabular Deep Learning with Parameter-Efficient Ensembling") train several cheap sub-models that share most weights and average them, imitating the variance reduction that makes forests and boosted ensembles strong.

These help, and on large tables with many rows, or where a network's other strengths matter (training end-to-end with text or image inputs, learning from streaming data, producing embeddings for other tasks), they are competitive. But they take more tuning than a boosted-tree library, train more slowly on a CPU, and still often match rather than beat trees on a typical business table. A common pragmatic result is that an ensemble of a tuned boosted model and a tuned network beats either alone, because their errors differ: the mechanism behind chapter 20.

Tabular foundation models

The most striking development is a different way of using a neural network on a table. A foundation model is a large model trained once on broad data and then used for many tasks without training a new model for each. For text, that data was the internet. There is no equivalent pile of real tables with labels, so the TabPFN family (Hollmann, Müller, Eggensperger and Hutter, 2022, "TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second") trains on synthetic tables instead.

The mechanism is in-context learning: the transformer receives the whole labelled training set and the unlabelled new rows as one input, and outputs predictions for the new rows without any change to its weights. Pre-training is done on datasets drawn from a prior over data-generating processes (random causal structures and random functions with noise, including features that matter and ones that do not), so that the network learns something like approximate Bayesian prediction across everything such a prior can produce. The first version, as the authors report, classified small datasets (up to 1,000 training points, 100 numerical features and 10 classes) in under a second, outperforming boosted trees on that benchmark, with no hyperparameter tuning. The Nature paper (Hollmann et al., 2025, "Accurate predictions on small data with a tabular foundation model") presented TabPFN v2, which extended the approach to regression, categorical and missing values and datasets of up to about 10,000 samples and 500 features.

The trade-offs follow from the design. The model is only as good as its prior: tables that look unlike anything the prior generates are a risk. Prediction cost grows with the size of the training set because the whole set is re-read on every call (attention over rows is expensive), which is why size limits exist, and why a deployment may distil the model into a smaller network or a tree ensemble. A prediction is not trivially explained, though the usual model-agnostic tools of chapter 16 work on any predictor. And as everywhere, leakage and honest validation are your job: the foundation model will happily exploit a leaked column.

State of play, October 2026

The scale limits have moved quickly. The first TabPFN handled 1,000 training rows; v2 (Nature, January 2025) about 10,000 rows and 500 features; and Prior Labs' TabPFN-2.5 report (6 November 2025) states support for up to 50,000 rows and 2,000 features, claims first place on TabArena and parity with a four-hour tuned AutoGluon ensemble, and describes distillation into a small MLP or tree ensemble. These are the developer's own claims. The independent TabArena benchmark (Erickson et al., NeurIPS 2025, 51 datasets, 16 models including three tabular foundation models) reports that foundation models excel on smaller datasets, that gradient-boosted trees remain strong contenders, that deep networks have narrowed the gap with ensembling and longer time budgets, and that tuning plus ensembling matters more than the choice of a single model; it covers small-to-medium, independent-and-identically-distributed data only. It is a living leaderboard, so positions will have changed by the time you read this. Check the licence of any model before commercial use, since licence terms differ between versions.

Key takeaways

  • On medium-sized tables, tree ensembles still match or beat neural networks, for reasons of inductive bias: irregular targets, uninformative columns and meaningful column axes.
  • In the toy experiment the boosted trees scored AUC 0.885 against 0.807 for a network; 40 noise columns cost the trees 0.018 and the network 0.058; rotating the columns cost the trees 0.107 and the network nothing.
  • Tabular networks (ResNet-style, FT-Transformer, TabM) add embeddings for numbers and categories and internal ensembling, and are strongest on large or multi-modal data.
  • Tabular foundation models such as TabPFN are pre-trained on synthetic tables and predict by in-context learning with no training on your data. They are strong challengers on small and medium tables, within size limits that have been growing.
  • Treat every claim as dated and vendor-reported until an independent benchmark such as TabArena confirms it, and always compare against a tuned boosted-tree baseline on honest validation.

Check your understanding

A table has 8,000 rows, 120 columns of which about 10 matter, and a target that steps sharply at certain thresholds. Which model family do you expect to do best out of the box?

  1. A fully connected neural network, since deeper models are more expressive.
  2. A linear model, since it has the fewest parameters.
  3. A boosted-tree ensemble, since trees ignore uninformative columns and fit steps directly.
  4. All families should score the same given enough tuning.
Many noise columns and abrupt target changes are the two situations in which trees have a built-in advantage. A network has to learn to ignore the noise and to represent the steps, both of which cost data. A linear model cannot represent the steps at all. There is no reason to expect parity.

Why does a tabular foundation model like TabPFN need no training on your dataset?

  1. It was pre-trained to predict test labels from labelled examples given in its input, so your training rows are supplied as context and one forward pass produces the predictions.
  2. It memorised the public datasets that most users have.
  3. It uses a decision tree internally and fits it instantly.
  4. It ignores your labels and predicts the average.
The model learned, across millions of synthetic datasets, how to predict from labelled examples in its context, much as a language model uses examples in a prompt. Your data enters as input, not as training data for the weights. It does use your labels, and the claim is not based on memorising real datasets.

A vendor reports that its tabular model beats boosted trees on 100% of a set of datasets. What is the most sensible response?

  1. Adopt it immediately; 100% is conclusive.
  2. Ignore it; neural networks cannot beat trees on tables.
  3. Ask only about the number of parameters.
  4. Check how the trees were tuned, which datasets and sizes were used, whether an independent benchmark agrees, and then test it on your own data with honest validation.
A vendor's comparison may use default-parameter trees, favourable dataset sizes or a metric chosen to flatter. Independent benchmarks and your own backtest are the checks. Dismissing the claim outright is as unfounded as accepting it, and parameter counts say nothing about accuracy.

In the chapter's experiment, randomly rotating the four informative columns hurt the boosted trees but not the network. What does this show?

  1. Networks are always more robust than trees.
  2. Trees exploit the original column axes, which carry the information in a table, while a network's first layer is indifferent to rotations.
  3. Rotation added noise columns.
  4. Trees cannot handle numerical features.
Rotation preserves the information but mixes columns, so one-column-at-a-time splits lose their natural axes. The network's weight matrix can absorb a rotation. This is why tables, whose axes have meaning, favour trees. It does not generalise to "networks are more robust": the same networks lost 0.058 AUC to noise columns.
