Cross-Validation Done Right

A validation score is a forecast of how the model will do in use, and a forecast is only as good as the rehearsal behind it. This chapter shows how k-fold cross-validation works and how noisy a single split is, then builds the variants (stratified, grouped, time-based, nested) that make the rehearsal match the deployment. The question throughout: what exactly will the model be asked to do, and does my split ask it the same thing?

Why this matters

Chapter 1 argued that a model must be judged on data it has not seen, and chapter 4 gave you the numbers to beat. Both assumed you have a trustworthy way to measure. This chapter is about building that measuring instrument. Get it wrong and every later decision (which features, which model, which threshold, whether to ship) rests on a number that flatters you. Most "it worked offline and failed in production" stories are not bad models. They are validation schemes that quietly let the model see something it will not have in use: a patient it already met, a month it could not know, a setting that was chosen because it scored well on the same rows. After this chapter you will be able to choose a splitting scheme from a description of the deployment, run it without leaking, and say how much a cross-validated number should be trusted.

What a validation score is for

You train a model and need to know one thing: how will it perform on data it has never seen? The training score cannot tell you, because the model has already adjusted to those rows. So you hold some rows back, fit on the rest, and score the held-back rows. The score on those rows is an estimate of future performance, and like any estimate it has two ways of being wrong. It can be biased, systematically too high or too low, and it can be noisy, landing a different distance from the truth every time you repeat the exercise.

A single hold-out split (say 80% to train, 20% to validate) is cheap and honest, but with a few hundred rows it is surprisingly noisy. Which 40 rows happened to land in validation matters a great deal, and you only get one draw. Cross-validation is the standard answer to the noise: use every row for validation exactly once, and average.

k-fold cross-validation

The procedure for k-fold cross-validation is short.

  1. Shuffle and cut. Randomly divide the rows into k parts of roughly equal size, called folds.
  2. Rotate. For each fold in turn, train a fresh model on the other k − 1 folds and score it on the held-out fold.
  3. Average. Report the mean of the k scores, and (as later sections insist) a measure of how much they vary.

Every row is used for validation once and for training k − 1 times, so nothing is wasted. The model that you finally ship is normally refit on all the rows; the cross-validation was a rehearsal to estimate how that kind of model, trained on that much data, will behave.

How noisy is a single split, really?

Measure it rather than assert it. The script below builds a world where we know the truth: 10 features, a logistic relationship to the target that uses only four of them, and datasets of 200 rows. It repeats the whole exercise on 300 different datasets. For each dataset it computes the truth (the accuracy of the model fitted on all 200 rows, scored on 50,000 fresh rows) and five estimates of it: a single 80/20 hold-out and 2-, 5-, 10- and 20-fold cross-validation. Then it asks how far each estimate lands from the truth.

The model and helper functions live in a small module, lib.py, which this chapter and the next three reuse. It is at the end of this section, under "Go deeper". Everything uses NumPy only; the scikit-learn equivalents are shown afterwards, labelled as not run here.

"""How good is each way of estimating accuracy? Repeat the whole exercise on 300 different datasets of 200 rows."""
import numpy as np
from lib import *

rng = np.random.default_rng(13)
w_true = np.array([1.0, -0.8, 0.6, 0.5])
def make(n):
    X = rng.normal(size=(n, 10))
    y = (rng.random(n) < sigmoid(X[:, :4] @ w_true + 0.3)).astype(int)
    return X, y

def fit_acc(Xtr, ytr, Xte, yte):
    return np.mean((predict_proba(fit_logreg(Xtr, ytr, l2=1.0, iters=12), Xte) >= 0.5) == yte)

def cv(X, y, k):
    folds = np.array_split(rng.permutation(len(y)), k)
    return np.mean([fit_acc(X[np.concatenate([folds[j] for j in range(k) if j != i])],
                            y[np.concatenate([folds[j] for j in range(k) if j != i])], X[folds[i]], y[folds[i]])
                    for i in range(k)])

Xbig, ybig = make(50_000)
rows = {m: [] for m in ("holdout 80/20", "2-fold", "5-fold", "10-fold", "20-fold")}
true = []
for _ in range(300):
    X, y = make(200)
    true.append(fit_acc(X, y, Xbig, ybig))           # truth: this dataset's model on 50,000 fresh rows
    p = rng.permutation(200)
    rows["holdout 80/20"].append(fit_acc(X[p[:160]], y[p[:160]], X[p[160:]], y[p[160:]]))
    for k in (2, 5, 10, 20):
        rows[f"{k}-fold"].append(cv(X, y, k))
true = np.array(true)
print(f"accuracy of the model fitted on all 200 rows, on fresh data: mean {true.mean():.3f}, sd across datasets {true.std():.3f}")
print(f"{'estimator':<15}{'mean estimate':>14}{'bias vs truth':>15}{'sd of estimate':>16}{'RMS error vs truth':>20}")

    v = np.array(v)
    print(f"{name:<15}{v.mean():>14.3f}{v.mean() - true.mean():>+15.3f}{v.std():>16.3f}{np.sqrt(np.mean((v - true) ** 2)):>20.3f}")

Read the last column, the root-mean-square distance between the estimate and the truth. The single hold-out is off by 0.073 on average: more than seven accuracy points, from a model whose real accuracy varies by only a point across datasets (the first line, sd 0.010). Five-fold cross-validation cuts the error by more than half (0.034), 10-fold barely improves on that (0.033), and 20-fold does not help at all. Two things to take away. First, the noise in a hold-out is large and avoidable. Second, the returns diminish quickly: the estimate also has a floor set by the dataset, since 200 rows can only say so much.

Choosing k

Two forces pull in opposite directions.

  • Bias. Each fold's model is trained on (k − 1)/k of the data. With k = 2 that is half, and a model trained on half the data is usually a little worse than the final model, so the estimate is slightly pessimistic (the table shows 2-fold at −0.017 against the truth). Raising k shrinks this bias: at 20 folds it is −0.001.
  • Cost and variance. More folds means more models to fit, k times the training time. The fold models also overlap almost completely when k is large, so their errors are highly correlated and averaging them removes less noise than it seems to.

The common defaults, k = 5 or 10, sit near the best trade-off for most tabular problems. Kohavi (1995), in "A Study of Cross-Validation and Bootstrap for Accuracy Estimation and Model Selection", compared choices of k empirically and recommended ten-fold stratified cross-validation. Use 5 when training is slow and 10 when you have the time and the data is small. Leave-one-out cross-validation, where k equals the number of rows, is almost unbiased but the most expensive and not less noisy; it is worth it mainly for tiny datasets or models with a closed-form shortcut (ridge regression has one). If the budget allows, repeated k-fold (repeat the whole procedure with different shuffles and pool all scores) smooths the luck of one particular partition and gives you a spread to report.

What cross-validation actually estimates

A subtle point, made precise by Bates, Hastie and Tibshirani in "Cross-validation: what does it estimate and how well does it do it?" (arXiv, 2021). Cross-validation does not estimate the error of the one particular model you will ship. It estimates the average error of models trained by this procedure on fresh datasets of the same kind and slightly smaller size. That is the right question when you are choosing between procedures (this algorithm, those hyperparameters), which is the usual use. It is a looser answer to "how good is this exact fitted model?" You will see the consequence two sections from now, when we ask how far to trust the number.

from sklearn.model_selection import KFold, RepeatedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model = make_pipeline(StandardScaler(), LogisticRegression(C=1.0))     # preprocessing lives INSIDE the pipeline
cv = RepeatedKFold(n_splits=5, n_repeats=10, random_state=0)           # 50 scores from 10 different shuffles
scores = cross_val_score(model, X, y, cv=cv, scoring="accuracy")       # X has shape (n_samples, n_features)
print(scores.mean(), scores.std())

The comment on the second line matters more than it looks, and chapter 14 is about why: any step that learns something from the data (scaling, imputing, selecting features, encoding categories) must be refit inside each fold, which is exactly what putting it in a pipeline does.

The experiments in chapters 13 to 15 import these helpers: a logistic regression fitted by Newton's method (as in chapter 5), prediction, and two ranking metrics (chapter 2). Save it as lib.py next to the scripts.

import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-np.clip(z, -35, 35)))

def fit_logreg(X, y, l2=1.0, iters=25, w=None):
    """L2-penalised logistic regression by Newton steps. Returns (b, coef)."""
    n, d = X.shape
    A = np.c_[np.ones(n), X]
    beta = np.zeros(d + 1)
    sw = np.ones(n) if w is None else w
    pen = np.r_[0.0, np.full(d, l2)]
    for _ in range(iters):
        p = sigmoid(A @ beta)
        g = A.T @ (sw * (p - y)) + pen * beta
        H = (A * (sw * p * (1 - p))[:, None]).T @ A + np.diag(pen) + 1e-9 * np.eye(d + 1)
        beta -= np.linalg.solve(H, g)
    return beta

def predict_proba(beta, X):
    return sigmoid(np.c_[np.ones(len(X)), X] @ beta)

def roc_auc(s, y):
    order = np.argsort(s, kind="mergesort")
    ranks = np.empty(len(s)); ranks[order] = np.arange(1, len(s) + 1)
    # average ranks for ties
    _, inv, cnt = np.unique(s, return_inverse=True, return_counts=True)
    sums = np.bincount(inv, weights=ranks)
    ranks = (sums / cnt)[inv]
    n1 = y.sum(); n0 = len(y) - n1
    return (ranks[y == 1].sum() - n1 * (n1 + 1) / 2) / (n1 * n0)

def average_precision(s, y):
    ys = y[np.argsort(-s, kind="mergesort")]
    tp = np.cumsum(ys)
    return (tp / np.arange(1, len(y) + 1))[ys == 1].mean()

Stratified folds: when the positives are rare

Random folds assume each fold looks like the whole dataset. With a common class that is nearly true. With a rare one it fails in a way you can count. Suppose 12 of 200 rows are positive (6%) and you use 5 folds: the expected number of positives in a validation fold is 2.4, but a random shuffle can easily give one fold none and another five. A fold with no positives cannot compute recall, precision or AUC at all, and a fold with one has a recall of 0 or 1.

Stratified k-fold fixes this by dealing each class out separately: shuffle the positives and deal them round-robin into the folds, then do the same with the negatives. Every fold gets (almost) the same class proportions. The script counts what happens over 2,000 shuffles.

"""Stratified k-fold: positives per fold when the positive class is rare."""
import numpy as np

rng = np.random.default_rng(2)
n, n_pos, k = 200, 12, 5                      # 6% positives, 5 folds: 2.4 positives per validation fold on average
y = np.r_[np.ones(n_pos, int), np.zeros(n - n_pos, int)]

def plain_folds(y):
    return np.array_split(rng.permutation(len(y)), k)

def stratified_folds(y):
    """Deal each class round-robin into the folds after shuffling within the class."""
    folds = [[] for _ in range(k)]
    for cls in (0, 1):
        idx = rng.permutation(np.where(y == cls)[0])
        for i, j in enumerate(idx):
            folds[i % k].append(j)
    return [np.array(f) for f in folds]

for name, fn in (("plain shuffled", plain_folds), ("stratified", stratified_folds)):
    empty = spread = 0; worst = []
    for _ in range(2000):
        counts = [y[f].sum() for f in fn(y)]
        empty += min(counts) == 0
        worst.append((min(counts), max(counts)))
    lo = min(w[0] for w in worst); hi = max(w[1] for w in worst)
    print(f"{name:<15} positives per validation fold ranged from {lo} to {hi}; "
          f"{empty / 2000:.1%} of shuffles had a fold with no positives (metrics undefined)")
plain shuffled  positives per validation fold ranged from 0 to 8; 30.1% of shuffles had a fold with no positives (metrics undefined)
stratified      positives per validation fold ranged from 2 to 3; 0.0% of shuffles had a fold with no positives (metrics undefined)

Almost a third of plain shuffles produced a fold with no positive at all; stratification made that impossible and kept every fold at two or three positives. Stratification is a variance-reduction trick, and it is free, so use it as the default for classification. It also generalises to regression by binning the target into quantiles and stratifying on the bins. What it does not do is protect you from any dependence between rows, which is the next problem.

Grouped folds: when rows are not independent

Every scheme so far rests on the assumption from chapter 1 that rows are i.i.d., independent draws from one distribution. Real tables break it constantly. A hospital has several visits per patient, a bank has many transactions per customer, a phone has hundreds of photos, a website has many sessions per user. Rows from the same group (patient, customer, device, document, store) are alike in ways that have nothing to do with the target relationship you want to learn: the same body, the same habits, the same camera, the same author.

Now ask the deployment question. Will the model be used on new patients? Almost always yes: you build it from the patients you have seen and apply it to the ones who arrive next. A random split puts some of a patient's visits in training and others in validation, so the model can recognise the patient instead of learning the disease. Validation then measures "how well can I recognise people I already know", which is not what you will do in production.

Here is a controlled version. There are 60 patients with 10 visits each. Each patient has a stable signature in the features (their own offset in 8 measurements) and a risk the features do not reveal directly; the visible features carry only a weak real signal. We compare random 5-fold, group k-fold (whole patients move together, so no patient appears on both sides), and the truth: the model fitted on all 60 patients, scored on 3,000 rows from 300 brand-new patients. Two models, a flexible one that can memorise (3-nearest-neighbours) and a rigid one (logistic regression). Forty fresh datasets, averaged.

"""Repeated measures: 60 patients x 10 visits. Random k-fold versus group k-fold versus new patients."""
import numpy as np
from lib import *

rng = np.random.default_rng(31)
D = 8
def make_patients(n_pat, visits=10):
    u = rng.normal(0, 1.0, (n_pat, D))            # each patient's stable signature (age, sex, device, ...)
    r = rng.normal(0, 2.5, n_pat)                 # patient-level risk the features cannot explain directly
    g = np.repeat(np.arange(n_pat), visits)
    X = u[g] + rng.normal(0, 0.5, (n_pat * visits, D))
    y = (rng.random(len(g)) < sigmoid(r[g] + 0.6 * X[:, 0])).astype(int)
    return X, y, g

def knn_fit_predict(Xtr, ytr, Xte, k=3):
    d = ((Xte[:, None, :] - Xtr[None, :, :]) ** 2).sum(-1)
    nn = np.argpartition(d, k, axis=1)[:, :k]
    return (ytr[nn].mean(1) >= 0.5).astype(int)

def lr_fit_predict(Xtr, ytr, Xte):
    return (predict_proba(fit_logreg(Xtr, ytr, l2=1.0, iters=12), Xte) >= 0.5).astype(int)

def folds_random(g, k):
    return np.array_split(rng.permutation(len(g)), k)

def folds_group(g, k):
    ids = rng.permutation(np.unique(g))
    return [np.where(np.isin(g, part))[0] for part in np.array_split(ids, k)]

def cv_acc(model, X, y, g, folds_fn, k=5):
    folds = folds_fn(g, k); s = []
    for i in range(k):
        tr = np.concatenate([folds[j] for j in range(k) if j != i])
        s.append(np.mean(model(X[tr], y[tr], X[folds[i]]) == y[folds[i]]))
    return np.mean(s)

res = {}
for mname, model in (("3-nearest-neighbours", knn_fit_predict), ("logistic regression", lr_fit_predict)):
    a, b, t = [], [], []
    for _ in range(40):
        X, y, g = make_patients(60)
        Xn, yn, _ = make_patients(300)                    # 3,000 rows from 300 patients the model never saw
        a.append(cv_acc(model, X, y, g, folds_random)); b.append(cv_acc(model, X, y, g, folds_group))
        t.append(np.mean(model(X, y, Xn) == yn))
    res[mname] = (np.mean(a), np.mean(b), np.mean(t))
print(f"{'model':<22}{'random 5-fold':>15}{'group 5-fold':>14}{'new patients':>14}")
for m, (a, b, t) in res.items():
    print(f"{m:<22}{a:>15.3f}{b:>14.3f}{t:>14.3f}")
model                   random 5-fold  group 5-fold  new patients
3-nearest-neighbours            0.714         0.516         0.511
logistic regression             0.589         0.526         0.537

The random-fold estimate for nearest neighbours is 0.714 while the model is, on new patients, close to a coin flip (0.511). Group folds report 0.516, within a hair of the truth. Notice also the ranking this would produce: under random folds, nearest neighbours (0.714) looks far better than logistic regression (0.589); under honest folds, logistic regression (0.526 and 0.537) is better. A leaky split does not just inflate the numbers, it can pick the wrong model. The more flexible a model is, the more it profits from the leak, so flexible models are systematically over-selected.

Common misconception

"I shuffled the rows, so the split is fair." Shuffling makes the folds look alike, which is a different property from making them independent. If a patient, customer or document appears on both sides of the split, shuffling does nothing to stop the model recognising them. The fair-split question is not "are the folds similar?" but "is anything in validation known to the training data that will not be known when the model meets a new case?"

Finding the groups

Groups are rarely labelled for you. Find them by asking what repeats: customer or patient IDs, device IDs, sellers, stores, authors of the documents, the same property listed twice, frames from the same video, near-duplicate images, sentences from the same article. The check from chapter 3 is to count rows per candidate key; a column with far fewer distinct values than rows is a group candidate. Then choose the group by the deployment: if the model will meet new customers, the group is the customer; if it will meet new transactions of known customers, grouping by customer is too strict and random folds (within time) may be right. Be explicit about which one you mean.

scikit-learn provides GroupKFold (whole groups per fold, but no shuffling and no stratification), StratifiedGroupKFold (groups stay together and class balance is approximated) and GroupShuffleSplit. When some groups are huge, folds become unbalanced and the estimate noisy; there is no free fix, only the advice to plot rows per group first.

from sklearn.model_selection import StratifiedGroupKFold, cross_val_score

cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_val_score(model, X, y, groups=patient_id, cv=cv, scoring="average_precision")

Time-based folds: validate on the future

The third way rows are not independent is time. A model trained today will be used tomorrow, and tomorrow is different: customer behaviour shifts, fraudsters adapt, prices move, a product launches. A random split mixes the future into the training set, so the model can interpolate between its past and its future. In production it only ever extrapolates from its past.

The fix is to respect the arrow of time. In a forward-chaining (or expanding-window) split, each fold trains on everything before a cut-off and validates on the block right after it; the next fold moves the cut-off later. A sliding window variant drops the oldest data too, useful when old behaviour is stale. Add a gap (also called an embargo) when the label takes time to arrive or the features look back over a window: if you predict 30-day churn, the last 30 days before the cut-off have labels that are not yet known at the cut-off, and using them is a time leak of its own. In finance, López de Prado (Advances in Financial Machine Learning, 2018) calls the removal of training rows whose labels overlap the validation period purging.

How much does it matter? A simulation with 36 months of 200 rows each. The relationship between two features and the label slowly rotates (what predicts the label in month 3 is not quite what predicts it in month 30), and a slowly moving context feature, think of a price index, tells the model roughly when a row comes from. A flexible model (15-nearest-neighbours) can use that to borrow from nearby months. We compare random 6-fold, forward chaining with 3-month validation blocks (with and without a one-month gap), and the real future: train on months 0 to 32, score months 33 to 35.

"""Time: the relationship between x and y drifts. Random k-fold versus forward chaining versus the real future."""
import numpy as np

rng = np.random.default_rng(4)
M, PER = 36, 200                                    # 36 months, 200 rows a month

def sigmoid(z): return 1 / (1 + np.exp(-z))

def month_data(m):
    t = m / M
    x = rng.normal(size=(PER, 2))
    drift = t + rng.normal(0, 0.03, PER)            # a slowly moving context feature (say, a price index)
    ang = 2.2 * np.pi * t                           # the direction in (x0, x1) that predicts y rotates over the three years
    y = (rng.random(PER) < sigmoid(3.0 * (np.cos(ang) * x[:, 0] + np.sin(ang) * x[:, 1]))).astype(int)
    return np.c_[x, 4 * drift], y, np.full(PER, m)

parts = [month_data(m) for m in range(M)]
X = np.vstack([p[0] for p in parts]); y = np.concatenate([p[1] for p in parts]); month = np.concatenate([p[2] for p in parts])

def knn_predict(Xtr, ytr, Xte, k=15):
    d = ((Xte[:, None, :] - Xtr[None, :, :]) ** 2).sum(-1)
    nn = np.argpartition(d, k, axis=1)[:, :k]
    return (ytr[nn].mean(1) >= 0.5).astype(int)

def acc(tr, te):
    return np.mean(knn_predict(X[tr], y[tr], X[te]) == y[te])

def random_kfold(k=6):
    folds = np.array_split(rng.permutation(len(y)), k)
    return np.mean([acc(np.concatenate([folds[j] for j in range(k) if j != i]), folds[i]) for i in range(k)])

def forward_chaining(first_train=12, test_len=3, gap=0):
    scores = []
    for start in range(first_train + gap, M - test_len + 1, test_len):
        tr = np.where(month < start - gap)[0]; te = np.where((month >= start) & (month < start + test_len))[0]
        scores.append(acc(tr, te))
    return np.mean(scores), len(scores)

truth_tr = np.where(month < 33)[0]; truth_te = np.where(month >= 33)[0]
print(f"random 6-fold                          : {random_kfold():.3f}")
for g in (0, 1):
    s, n = forward_chaining(gap=g)
    print(f"forward chaining, {n} folds, gap {g} month  : {s:.3f}")
print(f"truth: train on months 0-32, score months 33-35: {acc(truth_tr, truth_te):.3f}")
print(f"(for reference, the same model scored within months 33-35 only, 5-fold inside that block: ", end="")
idx = truth_te; f = np.array_split(rng.permutation(idx), 5)
print(f"{np.mean([acc(np.concatenate([f[j] for j in range(5) if j != i]), f[i]) for i in range(5)]):.3f})")
random 6-fold                          : 0.806
forward chaining, 8 folds, gap 0 month  : 0.750
forward chaining, 7 folds, gap 1 month  : 0.719
truth: train on months 0-32, score months 33-35: 0.765
(for reference, the same model scored within months 33-35 only, 5-fold inside that block: 0.812)

Random folds report 0.806, because every validation row has training neighbours on both sides of it in time. Forward chaining gives 0.750 and, with a one-month gap, 0.719; the real next three months scored 0.765 (a single block of 600 rows, so give it a couple of points of noise either way). The honest schemes are close to the truth and around four to nine points below the random estimate. The last line shows the model scored inside the same block of months it trained on: 0.812, which is almost exactly what random folds claim. Random folds measure "how well do I know this period", forward chaining measures "how well do I predict the next one".

For the whole story on time (seasonality, backtesting a forecast, features built from lags) see chapter 18. For classification with a time component the rule is the same: if the model will be used on tomorrow's data, validate on a tomorrow. scikit-learn's TimeSeriesSplit(n_splits, test_size, gap, max_train_size) implements this (a sliding window via max_train_size); note that it assumes the rows are already sorted by time, and it will not check that for you.

Systems connection

A time-respecting split is only possible if you can reconstruct what the world looked like at each past moment: the customer record as of that date, not as it is today. That is the same discipline as an event log with replayable history (streams, logs and change data capture) and is the reason feature stores offer "point-in-time" joins (designing with ML and LLMs). If your warehouse only keeps the latest state of each row, you cannot build an honest backtest, however careful the splitter.

Match the split to the deployment

The three variants are not alternatives to memorise but three answers to one question: what will be different between the data the model trains on and the data it will see? Write the answer down first, then pick the splitter.

In production the model sees…Rows that must stay apartSplitter
New rows from the same stable process, no repeated entitiesNothing in particularStratified k-fold (shuffled)
New patients, customers, devices, documentsAll rows of one entityGroup k-fold (stratified if rare)
The future of the same entities (e.g. next month's transactions)Rows after the cut-off; labels not yet knownForward chaining with a gap
New entities and the future (a new region next year)Both: entity and timeSplit on both; train on earlier periods and other entities
A different population (another hospital, another country)The whole sourceLeave-one-source-out (group k-fold on source)

The last row deserves a sentence. When the goal is generalisation across sources, such as models that must work in hospitals that did not contribute training data, hold out whole sources. Roberts and colleagues (2017, "Cross-validation strategies for data with temporal, spatial, hierarchical, or phylogenetic structure", Ecography) show for ecological and similar data that random folds can be seriously over-optimistic when the data have such structure, and recommend blocking the folds along the structure. The same lesson, in a different field, from a paper written by people who had been bitten.

Choosing a model with the same rows: nested cross-validation

So far cross-validation has been used to measure one model. Normally you also use it to choose: among regularisation strengths, tree depths, feature sets, algorithms. That reuse has a cost. The best of many noisy scores is not an unbiased estimate of anything; it is the maximum of noise plus signal, and the noise part is positive by construction. Chapter 1 called this using up the validation set. Here it is measured.

The experiment is deliberately extreme so the effect is unmistakable. The labels are coin flips, so every possible model has a true accuracy of exactly 0.50. We create 200 candidate models (each uses a different random set of 5 of 50 features), score them all with 5-fold cross-validation on 100 rows, and keep the best. Then we do it properly with nested cross-validation: an outer loop holds out a fold, and the whole selection (an inner cross-validation over the candidates) runs only on the remaining rows; the held-out fold scores the model that selection picked.

"""Selection bias: choose the best of 200 candidate models on pure-noise labels, with and without nested CV."""
import numpy as np
from lib import *

rng = np.random.default_rng(5)
N, P, N_CAND = 100, 50, 200
subsets = [rng.choice(P, 5, replace=False) for _ in range(N_CAND)]    # candidate i uses these 5 features

def acc(cols, Xtr, ytr, Xte, yte):
    b = fit_logreg(Xtr[:, cols], ytr, l2=1.0, iters=8)
    return np.mean((predict_proba(b, Xte[:, cols]) >= 0.5) == yte)

def cv_scores(X, y, k):
    folds = np.array_split(rng.permutation(len(y)), k)
    out = np.zeros(N_CAND)
    for i in range(k):
        tr = np.concatenate([folds[j] for j in range(k) if j != i])
        for c, cols in enumerate(subsets):
            out[c] += acc(cols, X[tr], y[tr], X[folds[i]], y[folds[i]]) / k
    return out

naive, nested, picked_true = [], [], []
Xbig = rng.normal(size=(20_000, P)); ybig = (rng.random(20_000) < 0.5).astype(int)
for rep in range(8):
    X = rng.normal(size=(N, P)); y = (rng.random(N) < 0.5).astype(int)     # labels are coin flips
    s = cv_scores(X, y, 5)
    best = int(np.argmax(s)); naive.append(s[best])
    picked_true.append(acc(subsets[best], X, y, Xbig, ybig))
    outer = np.array_split(rng.permutation(N), 5); sc = []
    for i in range(5):
        tr = np.concatenate([outer[j] for j in range(5) if j != i])
        inner = cv_scores(X[tr], y[tr], 5)                                  # selection sees only the outer-training rows
        sc.append(acc(subsets[int(np.argmax(inner))], X[tr], y[tr], X[outer[i]], y[outer[i]]))
    nested.append(np.mean(sc))
print("true accuracy of every candidate on noise labels: 0.500")
print(f"best-of-{N_CAND} 5-fold CV score, averaged over 8 datasets : {np.mean(naive):.3f}")
print(f"nested CV estimate of the whole select-then-fit procedure: {np.mean(nested):.3f}")
print(f"chosen model on 20,000 fresh rows                        : {np.mean(picked_true):.3f}")
true accuracy of every candidate on noise labels: 0.500
best-of-200 5-fold CV score, averaged over 8 datasets : 0.671
nested CV estimate of the whole select-then-fit procedure: 0.536
chosen model on 20,000 fresh rows                        : 0.501

The best candidate's cross-validated score averages 0.671, a result that would look like a real model, on data with no signal whatsoever. The nested estimate is 0.536, close to the truth, and when the chosen model is scored on 20,000 fresh rows it gets 0.501. The inflated number was the price of looking at 200 candidates. With real signal the same mechanism applies, just smaller: the more candidates, the noisier the data and the smaller the differences between candidates, the larger the optimism. Cawley and Talbot (2010, "On Over-fitting in Model Selection and Subsequent Selection Bias in Performance Evaluation") and Varma and Simon (2006, "Bias in error estimation when using cross-validation for model selection") documented this for classifiers on small datasets, and it is the reason a final, untouched test set exists.

Step through

Nested cross-validation, one outer fold at a time

  1. Hold out an outer fold. Cut the data into five outer folds and set the first aside. It plays the part of "future data": nothing about choosing a setting may look at it.
  2. Inner loop on what is left. The other four outer folds form the outer-training rows. Cut those again into four inner folds and rotate them, exactly as ordinary cross-validation would.
  3. Score every candidate. Each candidate setting (A, B, C: a regularisation strength, a depth, a feature set) gets an inner cross-validated score. B scores highest, and that score is flattered by having been picked as the best of three.
  4. Refit the winner. Train setting B once on all of the outer-training rows. This is the model that selection would have shipped, had the outer fold been the end of the data.
  5. Score it on the untouched outer fold. This number is not flattered: the outer fold took no part in choosing B. Here it is 0.72, lower than B's inner 0.74, as selection bias predicts.
  6. Repeat and average. Do the same with each outer fold held out. Every outer score evaluates a complete select-then-fit run, and their mean is the estimate of how that whole procedure performs.
  7. Ship once. For the deployed model, run the selection a final time on all the data. Nested cross-validation is a measurement of the procedure; its models are discarded.

Nested cross-validation costs (outer folds) × (inner folds) × (candidates) fits, which is why people skip it. Two cheaper habits capture most of the benefit. Keep a final test set that is touched once, after every choice is made (chapter 1). And keep the search small and principled: a handful of settings chosen on prior knowledge introduces little selection bias; a random search over thousands of configurations introduces a lot. If you tune extensively, use nested cross-validation at least once to find out how much optimism your pipeline carries.

How far to trust the number

A cross-validated score arrives as five or ten numbers, and the temptation is to treat them like ten independent measurements: take the mean and put a confidence interval of mean ± 1.96 × sd/√k around it. That interval is too narrow. The fold models are trained on mostly the same rows, so their errors are correlated, and the formula for the standard error of a mean assumes independence. Bengio and Grandvalet (2004), in "No Unbiased Estimator of the Variance of K-Fold Cross-Validation", proved that no estimator built from the fold scores alone is unbiased for the variance, and Bates, Hastie and Tibshirani found in simulation that the naive intervals often fail to cover. Test it:

"""Does 'mean +/- 1.96 sd/sqrt(k)' from the fold scores contain the truth 95% of the time?"""
import numpy as np
from lib import *

rng = np.random.default_rng(66)
w_true = np.array([1.0, -0.8, 0.6, 0.5])
def make(n):
    X = rng.normal(size=(n, 10))
    return X, (rng.random(n) < sigmoid(X[:, :4] @ w_true + 0.3)).astype(int)
def fit_acc(Xtr, ytr, Xte, yte):
    return np.mean((predict_proba(fit_logreg(Xtr, ytr, l2=1.0, iters=12), Xte) >= 0.5) == yte)

Xbig, ybig = make(50_000)
# 'truth' = accuracy of the procedure on a fresh dataset of the same size, averaged over many fresh datasets
ref = np.mean([fit_acc(*make(160), Xbig, ybig) for _ in range(300)])
print(f"average accuracy of the procedure when trained on 160 rows (the quantity CV targets): {ref:.3f}")
for k in (5, 10):
    hits_ref = hits_own = 0; widths = []
    for _ in range(300):
        X, y = make(200)
        folds = np.array_split(rng.permutation(200), k)
        s = []
        for i in range(k):
            tr = np.concatenate([folds[j] for j in range(k) if j != i])
            s.append(fit_acc(X[tr], y[tr], X[folds[i]], y[folds[i]]))
        m, se = np.mean(s), np.std(s, ddof=1) / np.sqrt(k)
        own = fit_acc(X, y, Xbig, ybig)                       # accuracy of THIS dataset's fitted model on fresh data
        hits_ref += abs(m - ref) <= 1.96 * se; hits_own += abs(m - own) <= 1.96 * se; widths.append(2 * 1.96 * se)
    print(f"{k:>2}-fold, naive 95% interval: mean width {np.mean(widths):.3f}; contains the procedure's average accuracy in {hits_ref / 300:.0%} of datasets, "
          f"this dataset's own model's accuracy in {hits_own / 300:.0%}")
average accuracy of the procedure when trained on 160 rows (the quantity CV targets): 0.715
 5-fold, naive 95% interval: mean width 0.114; contains the procedure's average accuracy in 86% of datasets, this dataset's own model's accuracy in 83%
10-fold, naive 95% interval: mean width 0.120; contains the procedure's average accuracy in 89% of datasets, this dataset's own model's accuracy in 88%

An interval meant to contain the target 95% of the time contains it 86% (5-fold) and 89% (10-fold) of the time, and it is already wide, about 0.11 across in total (roughly 5 to 6 points either side). Two reasons beyond fold correlation: the quantity being estimated is an average over training sets, not this dataset's fitted model (compare the last two figures on each line), and the interval cannot see variation in which rows you were handed. Practical consequences:

  • Treat the spread as a floor on uncertainty. A 5-fold standard deviation tells you how much the fold luck matters; the real uncertainty is larger. Say "about 0.71, give or take a few points", not "0.712 ± 0.004".
  • Compare models on the same folds. Use identical splits for every candidate and look at the per-fold differences; fold-to-fold difficulty cancels, which makes a paired comparison far more sensitive than comparing two separate means. For the final call on a close race, use a paired bootstrap on out-of-fold predictions (see statistics for experiments) or a repeated, nested design.
  • Do not chase differences smaller than the noise. If two models differ by 0.3 points and the fold standard deviation is 3, you do not know which is better; choose the simpler, cheaper or more robust.
  • Pool predictions carefully. For metrics like AUC, either score each fold and average, or collect all out-of-fold predictions and score once. Both are used; they differ a little, especially when fold models are not on the same score scale (a point chapter 15 returns to). Pick one and report which.

A checklist for a trustworthy split

  1. Write the deployment sentence. "The model scores each new loan application at submission, using data known at that moment, for applicants it has never seen." Every property of that sentence maps to a constraint on the split.
  2. Find what repeats and what moves. Entities that appear more than once (group them); a time order (respect it); sources or sites (hold out whole sources if you must travel).
  3. Stratify on the label when classes are rare, inside whichever grouping you chose.
  4. Fit every learned preprocessing step inside the fold. Scalers, imputers, encoders, feature selectors, resamplers, PCA. Use a pipeline object so this cannot be forgotten (chapter 14).
  5. Resample only the training part. Oversampling or SMOTE applied before splitting copies validation rows into training (chapter 15).
  6. Fix the seed and store the fold assignment, not just the seed, so a later run or a colleague can reproduce the exact split (reproducible experiments). Compare candidate models on identical folds.
  7. Keep a final test set, split by the same rules, and look at it once.
  8. Sanity-check the result. Compare with the baselines of chapter 4. If the cross-validated score is suspiciously high, look for a leak before you celebrate.

Key takeaways

  • A single hold-out is noisy: on 200 rows its typical error against the truth was 0.073. Five-fold cross-validation more than halves that (0.034); beyond ten folds you gain little.
  • Cross-validation estimates the average performance of a procedure on a slightly smaller training set, not the exact model you ship.
  • Stratify folds on the label when positives are rare; otherwise a third of shuffles can leave a fold with none.
  • When rows repeat an entity, keep the entity together. Random folds scored a memorising model at 0.714 when its accuracy on new patients was 0.511, and they can rank models in the wrong order.
  • When the model is used on the future, validate on the future: forward chaining with a gap. Random folds claimed 0.806 where forward chaining said 0.719 to 0.750.
  • Choosing among many candidates inflates the winner's score (0.671 on pure noise); nested cross-validation measures the whole select-then-fit procedure honestly (0.536).
  • Fold scores are correlated, so mean ± 1.96 se intervals under-cover (86% to 89% in the test). Report spreads as lower bounds on uncertainty and compare models on the same folds.

Check your understanding

You have 300 labelled rows and a single 80/20 hold-out says 0.78 accuracy. A colleague reshuffles and gets 0.71. What is the most sensible conclusion?

  1. One of you made a coding error, since the same model must give the same score.
  2. The model is overfitting, so it needs more regularisation.
  3. With only 60 validation rows the estimate is noisy; repeated or k-fold cross-validation gives a steadier number.
  4. Use the higher score, because it shows what the model can do.
The training rows differ between the two splits, and a validation set of 60 rows has a standard error of several points on its own. Disagreements of this size are normal and are the reason to average over folds. Choosing the higher number is optimistic selection, the same bias the nested-CV section measures.

A hospital dataset has 40 visits per patient and the model will be used on newly admitted patients. Which split mirrors this?

  1. Group k-fold with patient as the group.
  2. Plain shuffled k-fold, since there are many rows.
  3. Leave-one-visit-out cross-validation.
  4. Stratified k-fold on the label only.
The model will meet patients it has never seen, so validation must contain only patients absent from training. Shuffled folds, leave-one-visit-out and label-only stratification all leave other visits of the same patient in training, which rewards recognising the patient. Having many rows does not make them independent.

In a churn model, the label for a customer is "cancelled within 30 days after the prediction date". You build time-ordered folds. What should you add at the boundary between training and validation?

  1. Nothing: forward chaining already guarantees no leakage.
  2. More training rows from the validation period, to keep the model fresh.
  3. Random shuffling inside the validation block.
  4. A gap of at least 30 days, so that training labels are not computed from outcomes that happen after the cut-off.
A training row dated just before the cut-off has a label that depends on the following 30 days, which overlaps the validation period. Excluding a 30-day gap (or purging overlapping rows) keeps training knowledge to what was truly known at the cut-off. Forward chaining alone orders the rows but does not remove this overlap.

You try 500 hyperparameter settings with 5-fold cross-validation and report the best mean score, 0.83. What is the most accurate description of that number?

  1. An unbiased estimate, because each fold was held out properly.
  2. Optimistic: it is the maximum over many noisy scores, so it includes the luck that made this setting win.
  3. Pessimistic, because each fold trains on only 80% of the data.
  4. Meaningless, because cross-validation cannot be used for tuning.
The 80% training size adds a small pessimistic bias, but the selection of the maximum adds a larger optimistic one when many close candidates compete. Cross-validation is fine for tuning; the problem is quoting the tuned winner's score as its performance. Nested cross-validation or an untouched test set gives the honest figure.

In the grouped-patients experiment, random folds gave 3-nearest-neighbours 0.714 and logistic regression 0.589, while on new patients they scored 0.511 and 0.537. What does this show beyond "random folds are optimistic"?

  1. Nearest neighbours is always a better model than logistic regression.
  2. Logistic regression is immune to leakage.
  3. A leaky split favours flexible models that can memorise, so it can reverse the ranking of models.
  4. Group folds are pessimistic because they remove information.
The flexible model profited far more from patient identity leaking across the split (about 20 points against 5), enough to turn a real deficit into an apparent lead. Logistic regression was fooled less but not immune. Group folds were within a point of the truth, so they were not pessimistic.

Five-fold cross-validation gives fold accuracies with mean 0.74 and standard deviation 0.02. A teammate reports 0.74 ± 0.009 (that is 1.96 × 0.02/√5) as a 95% interval. What is wrong?

  1. The interval should use the standard deviation, not the standard error.
  2. The fold scores are positively correlated because the training sets overlap, so the interval is too narrow and under-covers.
  3. Five folds are too few to compute a standard deviation.
  4. Nothing: this is the standard formula and it is exact.
The formula assumes independent scores. The fold models share about 75% of their training rows, so their errors move together and the true uncertainty is larger. In the chapter's test, intervals built this way contained the target only 86% of the time. Using the standard deviation instead would be too wide in a different, arbitrary way.
