Nearest Neighbours, Naive Bayes & Kernels

Three classifiers that are not built on a weighted sum of features: one that remembers the training data and looks up similar examples, one that multiplies up evidence word by word with Bayes' rule, and one that bends a linear model by measuring similarity in a richer space. Each is a good idea, a useful baseline and a lesson in what goes wrong when its assumption is broken.

Why this matters

The linear models of the last two chapters draw straight boundaries from a handful of weights. Many problems need something else: curved boundaries, very little data, text with tens of thousands of features, or a prediction that is explained by pointing at a similar past case. The three families here cover those situations, and each one reappears in modern systems under another name. Nearest-neighbour search is the heart of vector databases and retrieval-augmented generation (A5 chapter 11). Naive Bayes is the standard first baseline for text. Kernels are the idea behind similarity functions everywhere, and they give the cleanest picture of why adding features can turn an impossible problem into an easy one. After this chapter you will be able to implement each from scratch, say what it assumes, and predict which of its assumptions your data is breaking.

All three methods share a theme from chapter 6: each has one knob (the number of neighbours, the smoothing constant, the kernel width) that trades bias against variance, and each depends on how the features are measured.

Nearest neighbours: the training set is the model

The k-nearest neighbours (kNN) classifier has one idea: similar inputs have similar outputs. To predict for a new point, find the k training points closest to it, and let them vote (for a class) or average their targets (for a number). There is no training step beyond storing the data, which makes kNN a lazy learner: all the work happens at prediction time.

"Closest" needs a distance. The default is the Euclidean distance, the straight-line length of the difference between two feature vectors, which is the same quantity as in A0 chapter 5; Manhattan distance (sum of absolute differences) and the cosine distance for directions are common alternatives. The choice of k is the complexity knob. With k = 1 the model reproduces the training data exactly, so each point is its own nearest neighbour and the training accuracy is 100 percent, but the prediction follows every stray point. With k as large as the training set it predicts the majority class everywhere, which is the baseline of chapter 4. Somewhere between lies the best bias-variance balance.

Here is a complete implementation in NumPy on a synthetic problem, the standard "two moons" shape: two interlocking half-circles, with noise added, 300 training rows and 300 test rows. A straight line cannot separate them; a neighbourhood vote can. Each distance matrix is (n_query, n_train), and the vote is the mean of the neighbours' 0/1 labels.

import numpy as np

rng = np.random.default_rng(7)
def moons(n, noise=0.25):
    t = rng.uniform(0, np.pi, n // 2)
    a = np.column_stack([np.cos(t), np.sin(t)])                  # upper moon, class 0
    b = np.column_stack([1 - np.cos(t), 0.5 - np.sin(t)])        # lower moon, class 1
    X = np.vstack([a, b]) + rng.normal(0, noise, (n, 2))
    return X, np.r_[np.zeros(n // 2), np.ones(n // 2)]
X_tr, y_tr = moons(300); X_te, y_te = moons(300)

def knn_predict(X_train, y_train, X_query, k):
    d2 = ((X_query[:, None, :] - X_train[None, :, :]) ** 2).sum(axis=2)   # (n_query, n_train) squared distances
    nearest = np.argsort(d2, axis=1)[:, :k]                                # indices of the k closest rows
    return (y_train[nearest].mean(axis=1) > 0.5).astype(float)            # majority vote (k odd: no ties)

acc = lambda p, y: float(np.mean(p == y))
print("k     train acc  test acc")
for k in (1, 3, 5, 15, 45, 101, 299):
    print(f"{k:<5} {acc(knn_predict(X_tr, y_tr, X_tr, k), y_tr):9.3f}  {acc(knn_predict(X_tr, y_tr, X_te, k), y_te):8.3f}")

print("\nsame model, k=15, after changing the data (not the algorithm):")
print("  as is                              :", round(acc(knn_predict(X_tr, y_tr, X_te, 15), y_te), 3))
S = np.array([1.0, 100.0])                    # second feature recorded in different units (x100)
print("  feature 2 in units 100x larger     :", round(acc(knn_predict(X_tr * S, y_tr, X_te * S, 15), y_te), 3))
mu, sd = (X_tr * S).mean(0), (X_tr * S).std(0)
print("  ...then standardised               :", round(acc(knn_predict((X_tr * S - mu) / sd, y_tr, (X_te * S - mu) / sd, 15), y_te), 3))
junk_tr, junk_te = rng.normal(size=(300, 10)), rng.normal(size=(300, 10))
print("  plus 10 irrelevant noise features  :", round(acc(knn_predict(np.hstack([X_tr, junk_tr]), y_tr, np.hstack([X_te, junk_te]), 15), y_te), 3))

Read the first table. At k = 1 the training accuracy is a perfect 1.000 and the test accuracy 0.900: the gap of chapter 6. The test accuracy peaks around k = 15 (0.930) and the training accuracy slides down as the model smooths, until k = 299 (nearly the whole training set) gives 0.647, close to a majority-class guess. This is the familiar U in disguise, with the complexity axis reversed: small k is the flexible model.

kNN is only as good as its distance

The second block of the output is the lesson most people learn the hard way. The algorithm is identical in all four lines; only the data changes.

  • Units. Record the second feature in units one hundred times larger and the test accuracy falls from 0.930 to 0.790. The distance is now dominated by that one feature, and the first is effectively ignored. Standardising (subtract the mean, divide by the standard deviation, using training data only) restores 0.927. Any distance-based method needs scaled features.
  • Irrelevant features. Add ten columns of pure noise and accuracy drops to 0.750. Each noise feature adds random distance between points that are actually close in the two informative features, so the true neighbours are pushed apart and false ones drawn in. Trees and penalised linear models can ignore useless features; kNN cannot unless you remove them.

The curse of dimensionality

The second effect has a general form. In one dimension, 500 points spread over a line give every query a very close neighbour. In 1,000 dimensions the same 500 points are lost in an enormous space, and every point is far from every other. The script measures it directly: for 500 random points in the unit cube, the ratio of the nearest to the farthest distance from a query.

import numpy as np

rng = np.random.default_rng(3)
n = 500
print("dim d   nearest / farthest distance   edge of a cube holding 1% of the data")
for d in (1, 2, 5, 10, 50, 200, 1000):
    ratios = []
    for _ in range(20):
        X = rng.uniform(size=(n, d)); q = rng.uniform(size=d)
        dist = np.sqrt(((X - q) ** 2).sum(axis=1))
        ratios.append(dist.min() / dist.max())
    print(f"{d:<7} {np.mean(ratios):26.3f}   {0.01 ** (1 / d):28.3f}")

With one feature the nearest point is about a thousand times closer than the farthest (ratio 0.001). With ten features the ratio is 0.30; with 1,000 it is 0.90, so "nearest" and "farthest" are almost the same distance and the vote is nearly arbitrary. The last column is the same phenomenon seen another way: to capture just 1 percent of uniformly spread data around a point in 10 dimensions, a neighbourhood must span 63 percent of the range of every feature. It is no longer local. This curse of dimensionality is the reason kNN works on a handful of informative features and fails on hundreds of raw ones, and why distances are computed in a learned, lower-dimensional embedding instead (chapter 11 covers reducing dimensions). Real data often has structure that keeps it from filling the space (it lies near a lower-dimensional surface), so the picture is less bleak than uniform random points suggest, but the warning stands.

Common misconception

"kNN has no training, so it is the cheap option." Training is free; prediction is expensive. A naive query compares the new point with every stored row, which is n × d operations: for a million rows and 100 features, 100 million multiply-adds per prediction, plus the memory to hold the whole training set in the serving process. Indexes (k-d trees, ball trees) help in low dimensions and stop helping as the curse bites; for high dimensions, approximate nearest-neighbour search trades a little recall for large speed-ups. That machinery is the subject of A5 chapter 11.

Naive Bayes: evidence multiplied up

The second family starts from Bayes' rule. For a class c and features x:

P(c | x) ∝ P(c) × P(x | c)

The left side is what we want: the probability of each class given what we observed. The right side is the prior, how common the class is, times the likelihood, how likely this evidence would be if the class were true. Estimating P(x | c) for a whole feature vector is the hard part, because it needs a joint distribution over all the features and the number of combinations explodes. Naive Bayes cuts through with one simplifying assumption: given the class, the features are independent. Then the joint likelihood is a product of per-feature terms, each estimated by simple counting:

Plug in numbers. One two-word message, two classes, and made-up word probabilities; each line is one step above.

The idea

  1. PRIOR P(c) and LIKELIHOOD P(word | c) for 2 classes, 1 message
  2. per class: score ← P(c) × P(word1 | c) × P(word2 | c)
  3. posterior ← score ÷ (sum of scores over classes)
  4. same in logs: log P(c) + sum of log P(word | c)
"""Naive Bayes by hand for one message and two classes.
P(c | x) is proportional to P(c) times the product of P(x_j | c)."""
import math

# ── 1. Prior and per-word likelihoods (made up, from imagined counts) ────
PRIOR = {"spam": 0.3, "ham": 0.7}         # P(c): how common each class is
LIKELIHOOD = {                            # P(word | c)
    "spam": {"free": 0.20, "prize": 0.10, "meeting": 0.01},
    "ham":  {"free": 0.02, "prize": 0.01, "meeting": 0.15},
}
MESSAGE = ["free", "prize"]               # the evidence x, as two words

# ── 2. Per class: prior, then one factor per word, then the product ──────
score = {}
for c in PRIOR:
    s = PRIOR[c]                          # step 1: start from P(c)
    parts = [f"{s:.2f}"]
    for word in MESSAGE:
        s *= LIKELIHOOD[c][word]          # steps 2-3: times P(x_j | c)
        parts.append(f"{LIKELIHOOD[c][word]:.2f}")
    score[c] = s
    print(f"{c:4s}: {' x '.join(parts)} = {s:.6f}")

# ── 3. Divide by the total so the scores become probabilities ────────────
total = sum(score.values())               # step 4: the missing constant
print()
for c in PRIOR:
    print(f"P({c} | message) = {score[c] / total:.3f}")

# ── 4. The same thing in logs, as real implementations do ────────────────
print()
for c in PRIOR:
    logs = math.log(PRIOR[c]) + sum(math.log(LIKELIHOOD[c][w])
                                    for w in MESSAGE)
    print(f"log score {c:4s} = {logs:7.3f}   exp = {math.exp(logs):.6f}")
spam: 0.30 x 0.20 x 0.10 = 0.006000
ham : 0.70 x 0.02 x 0.01 = 0.000140

P(spam | message) = 0.977
P(ham | message) = 0.023

log score spam =  -5.116   exp = 0.006000
log score ham  =  -8.874   exp = 0.000140

"Naive" because the assumption is rarely true: in an email, "free" and "prize" appear together far more often than independence predicts. The method works surprisingly often anyway, because to rank the classes it needs the right ordering of the scores, not exact probabilities. For text, the usual version treats a document as a bag of words and the likelihood of a document under a class as the product of the probabilities of its words under that class (the multinomial model). Because a product of many small numbers underflows (A0 chapter 11), implementations add logarithms instead: the score of a class is its log prior plus the sum of the log word probabilities.

The whole algorithm fits on a page. This example classifies support tickets into billing, technical and account problems from a nine-ticket training set small enough to check by hand. Training is counting: how often each class occurs, and how often each word occurs within each class. One detail needs care. A word that never appeared with a class in training would have probability zero and, by multiplication, veto that class forever. Laplace smoothing adds a pseudo-count α (here 1) to every word count in every class, so nothing is ever impossible.

import math
from collections import Counter

train = [("billing", "refund charged twice"), ("billing", "invoice wrong amount charged"), ("billing", "refund invoice"),
         ("tech", "app crashes on start"), ("tech", "error when uploading photo"), ("tech", "app error crashes"),
         ("account", "reset password login"), ("account", "cannot login password"), ("account", "change email login")]
classes = sorted({c for c, _ in train})
vocab = sorted({w for _, t in train for w in t.split()})
prior = {c: sum(1 for k, _ in train if k == c) / len(train) for c in classes}
counts = {c: Counter(w for k, t in train for w in t.split() if k == c) for c in classes}
total = {c: sum(counts[c].values()) for c in classes}

def log_score(c, words, alpha):
    s = math.log(prior[c])
    for w in words:
        s += math.log((counts[c][w] + alpha) / (total[c] + alpha * len(vocab)))   # Laplace smoothing
    return s

def posterior(text, alpha=1.0):
    words = [w for w in text.split() if w in vocab]           # words never seen in training carry no information
    scores = {c: log_score(c, words, alpha) for c in classes}
    m = max(scores.values())
    z = sum(math.exp(v - m) for v in scores.values())          # normalise in log space (stable)
    return {c: math.exp(scores[c] - m) / z for c in classes}

print("vocabulary size:", len(vocab), "| priors:", {c: round(p, 2) for c, p in prior.items()})
for text in ("charged twice login", "app crashes login"):
    p = posterior(text)
    print(f"{text!r:24} ->", {c: round(v, 3) for c, v in p.items()})
print()
text = "refund invoice login"
print("alpha=1 :", {c: round(v, 3) for c, v in posterior(text, 1.0).items()})
try:
    print("alpha=0 :", {c: round(v, 3) for c, v in posterior(text, 0.0).items()})
except ValueError as e:
    print("alpha=0 : math domain error, a word with zero count in a class made log(0):", e)
vocabulary size: 20 | priors: {'account': 0.33, 'billing': 0.33, 'tech': 0.33}
'charged twice login'    -> {'account': 0.37, 'billing': 0.555, 'tech': 0.076}
'app crashes login'      -> {'account': 0.323, 'billing': 0.081, 'tech': 0.596}

alpha=1 : {'account': 0.289, 'billing': 0.651, 'tech': 0.059}
alpha=0 : math domain error, a word with zero count in a class made log(0): expected a positive input, got 0.0

The ticket "charged twice login" is a mixed message: "charged" and "twice" point to billing, "login" to accounts. The model says billing 0.555, account 0.370, technical 0.076, which is a sensible reading. The last two lines show smoothing earning its keep. With α = 1 the ticket "refund invoice login" is billing with probability 0.651; with α = 0 the calculation crashes, because "login" has count zero in the billing class and a logarithm of zero is undefined (without logs, the product would be exactly zero and the class eliminated).

Analogy: jurors who all heard the same witness

Imagine a jury where each member judges the case on one piece of evidence, and the verdict is the product of their confidence levels. If the pieces are genuinely separate (a fingerprint, a receipt, an alibi), multiplying is right. If twelve jurors all heard the same witness repeat the same story, multiplying counts that story twelve times, and the jury becomes absurdly sure of a verdict that rests on one voice. Naive Bayes is that jury.

Where it breaks down: real jurors discuss and notice they heard the same witness; naive Bayes cannot. And the jury analogy suggests the verdict (guilty or not) is wrong. In practice the ranking of the verdicts is often still right and only the confidence is inflated, as the next experiment shows.

To see this, generate a larger synthetic corpus: 40 words, three classes that each favour their own eight words mildly, 15 tokens per document, 1,500 training and 1,500 test documents. Then break the independence assumption deliberately by feeding every word to the model twice, and four times (as perfectly redundant features, the extreme version of "free" and "prize" going together).

import numpy as np

rng = np.random.default_rng(21)
V, K, L = 40, 3, 15                    # vocabulary size, classes, tokens per document
word_p = np.full((K, V), 0.65 / (V - 8))
for c in range(K): word_p[c, c * 8:(c + 1) * 8] = 0.35 / 8      # each class favours its own 8 words, mildly
word_p /= word_p.sum(1, keepdims=True)

def make(n):
    y = rng.integers(0, K, n)
    X = np.array([rng.multinomial(L, word_p[c]) for c in y])      # bag of words: counts, shape (n, V)
    return X, y
X_tr, y_tr = make(1500); X_te, y_te = make(1500)

def fit_nb(X, y, alpha=1.0):
    prior = np.log(np.bincount(y) / len(y))
    cnt = np.array([X[y == c].sum(0) for c in range(K)]) + alpha
    return prior, np.log(cnt / cnt.sum(1, keepdims=True))

def predict_proba(model, X):
    prior, loglik = model
    s = prior + X @ loglik.T                                       # log prior + sum over words of count * log P(word | class)
    s -= s.max(1, keepdims=True)
    p = np.exp(s); return p / p.sum(1, keepdims=True)

def report(name, Xa, Xb):
    P = predict_proba(fit_nb(Xa, y_tr), Xb)
    acc = float(np.mean(P.argmax(1) == y_te)); conf = float(P.max(1).mean())
    ll = float(-np.mean(np.log(P[np.arange(len(y_te)), y_te] + 1e-12)))
    print(f"{name:<34} accuracy {acc:.3f}   mean confidence {conf:.3f}   log-loss {ll:.3f}")

report("independent words", X_tr, X_te)
report("every word duplicated (x2)", np.hstack([X_tr, X_tr]), np.hstack([X_te, X_te]))
report("every word duplicated (x4)", np.hstack([X_tr] * 4), np.hstack([X_te] * 4))
independent words                  accuracy 0.765   mean confidence 0.766   log-loss 0.571
every word duplicated (x2)         accuracy 0.765   mean confidence 0.879   log-loss 0.699
every word duplicated (x4)         accuracy 0.767   mean confidence 0.940   log-loss 1.175

Accuracy does not move: 0.765, 0.765, 0.767. The classes are ranked the same way. But the model's mean confidence climbs from 0.766 (matching the accuracy: honest) to 0.879 and 0.940, while the log-loss, which punishes confident mistakes, goes from 0.571 to 0.699 to 1.175. The probabilities got worse even though the decisions did not. Treat naive Bayes as a ranker, not as a source of probabilities: if you need honest probabilities from it, calibrate them afterwards (chapter 15).

Where naive Bayes earns its place: it trains in one pass over the data (counting), updates incrementally as new examples arrive, needs very little data, scales to vocabularies of hundreds of thousands of words, and gives a strong text-classification baseline in minutes. For continuous features the same recipe uses a Gaussian per class and feature (Gaussian naive Bayes). It is a baseline to beat, in the spirit of chapter 4, not an endpoint.

Kernels: curves from a linear model

The third idea starts from a limitation we met in chapter 5. A linear classifier draws a straight boundary, and some problems cannot be split by one. Suppose a feature x is on one side of a threshold for green points and on both sides for red ones, as in the left of the next figure. No cut on a line works. But add a single new feature, x2, and plot each point at (x, x2): the points lie on a parabola, and a horizontal line now separates them perfectly. The data did not change; the representation did.

This is the general move: map each input x into a richer feature space with a function φ(x) (squares, products, whatever helps), then fit a linear model there. A straight boundary in the new space is a curved boundary in the old. The cost is that the new space can be huge: all products of pairs of 100 features is 5,000 columns; all products up to degree 5 is millions. The kernel trick avoids paying it. Many algorithms (the support vector machine, ridge regression, the perceptron) can be rewritten so that the data enters only through inner products between pairs of points, φ(x) · φ(z). A kernel function K(x, z) computes that inner product directly from the original inputs, without ever building φ.

For the degree-2 polynomial kernel, K(x, z) = (x · z + 1)2, the matching feature map has six coordinates for a two-dimensional input: 1, √2x1, √2x2, x12, √2x1x2, x22. The script verifies the identity numerically, then runs three classifiers on a problem a line cannot solve: 300 training points on two concentric rings, radius 1 and 2, with a little noise.

import numpy as np

rng = np.random.default_rng(4)
# 1. The kernel trick in numbers: (x.z + 1)^2 equals an inner product in a 6-dimensional feature space
def phi(x):                                   # explicit degree-2 feature map for a 2-d point
    x1, x2 = x
    return np.array([1, np.sqrt(2) * x1, np.sqrt(2) * x2, x1 ** 2, np.sqrt(2) * x1 * x2, x2 ** 2])
x, z = np.array([0.7, -1.2]), np.array([2.0, 0.5])
print("kernel  (x.z + 1)^2     =", round(float((x @ z + 1) ** 2), 6))
print("explicit phi(x).phi(z)  =", round(float(phi(x) @ phi(z)), 6), "  (6 numbers per point instead of 2)")

# 2. Two concentric rings: no straight line separates them
def rings(n):
    r = np.r_[rng.normal(1.0, 0.1, n // 2), rng.normal(2.0, 0.1, n // 2)]
    t = rng.uniform(0, 2 * np.pi, n)
    return np.column_stack([r * np.cos(t), r * np.sin(t)]), np.r_[-np.ones(n // 2), np.ones(n // 2)]
X_tr, y_tr = rings(300); X_te, y_te = rings(300)

def logistic_acc(F_tr, F_te):
    A = np.column_stack([np.ones(len(F_tr)), F_tr]); w = np.zeros(A.shape[1]); t = (y_tr + 1) / 2
    for _ in range(3000):
        w -= 0.5 * A.T @ (1 / (1 + np.exp(-A @ w)) - t) / len(t)
    B = np.column_stack([np.ones(len(F_te)), F_te])
    return float(np.mean((B @ w > 0) == (y_te > 0)))

print("\nlinear classifier on (x1, x2)               : test accuracy", round(logistic_acc(X_tr, X_te), 3))
r2 = lambda X: (X ** 2).sum(1, keepdims=True)
print("same classifier plus one new feature r^2    : test accuracy", round(logistic_acc(np.hstack([X_tr, r2(X_tr)]), np.hstack([X_te, r2(X_te)])), 3))

# 3. Kernel ridge regression with an RBF kernel: never builds the new features, only pairwise similarities
def rbf(A, B, gamma): return np.exp(-gamma * ((A[:, None, :] - B[None, :, :]) ** 2).sum(2))
gamma, lam = 1.0, 0.1
K = rbf(X_tr, X_tr, gamma)
alpha = np.linalg.solve(K + lam * np.eye(len(K)), y_tr)          # one weight per TRAINING POINT
pred = np.sign(rbf(X_te, X_tr, gamma) @ alpha)
print("RBF kernel ridge (gamma=1, lambda=0.1)      : test accuracy", round(float(np.mean(pred == y_te)), 3))
print("kernel matrix shape:", K.shape, "->", K.nbytes // 1024, "KiB; for 100,000 rows it would be", 100000 ** 2 * 8 // 10 ** 9, "GB")
kernel  (x.z + 1)^2     = 3.24
explicit phi(x).phi(z)  = 3.24   (6 numbers per point instead of 2)

linear classifier on (x1, x2)               : test accuracy 0.503
same classifier plus one new feature r^2    : test accuracy 1.0
RBF kernel ridge (gamma=1, lambda=0.1)      : test accuracy 1.0

The first two lines are the identity in action: the kernel (a multiplication and a square) and the explicit six-coordinate inner product give the same number, 3.24. The linear classifier on the raw coordinates gets 0.503, exactly chance: a line cannot separate rings. Add one engineered feature, r2 = x12 + x22 (the squared distance from the centre), and the same classifier scores 1.000, the ring problem solved by a line in a space where it is one. The third model never builds features at all. Kernel ridge regression with the RBF (radial basis function or Gaussian) kernel, K(x, z) = exp(−γ |x − z|2), which is a similarity score between 0 (far apart) and 1 (identical), also scores 1.000. The RBF kernel corresponds to a feature space of infinite dimension, which you could never build explicitly, yet the kernel costs one distance and one exponential per pair.

The bill arrives in the last line. A kernel method stores one weight per training point and needs the matrix of all pairwise similarities: 300 × 300 values here (703 KiB), but 100,000 rows would be a 100,000 × 100,000 matrix, 80 GB of 8-byte floats, and solving with it takes time that grows with the cube of the rows. The fit time of the library's kernel SVC scales at least quadratically with the number of samples, and its own documentation (checked on 14 October 2026, version 1.9.1) says it may be impractical beyond tens of thousands of samples. That scaling is the main reason kernel methods faded for large data, and approximations (random feature maps, the Nyström method) exist to restore it.

The support vector machine, in one paragraph

The best-known kernel method is the support vector machine (SVM; Cortes and Vapnik, 1995, "Support-vector networks"). It chooses, among all separating boundaries, the one with the widest margin: the largest gap to the nearest points of each class. Only the points on or inside the margin, the support vectors, determine the boundary; the rest could be deleted without changing it. A constant C sets how much margin violation to tolerate (small C is a wider, more forgiving margin, the regularisation of chapter 6 in another form), and the loss is the hinge loss, zero for points safely past the margin. Swap in an RBF kernel and the boundary can be as wiggly as the data demands, with the kernel width γ as the second complexity knob: a large γ makes every point a narrow island and overfits, a small one makes the boundary nearly linear. SVMs were the strongest general-purpose classifier of the late 1990s and 2000s, and they remain a good choice for small and medium datasets with a well-chosen kernel. For large tabular data, gradient-boosted trees (chapter 9) have replaced them.

Systems connection

Each method leaves a different footprint in a production system. kNN keeps the entire training set in memory and searches it on every request: it is a vector search service with all of that service's concerns, from index memory to refresh time to filtering by permissions, and the moment you have more than a few hundred thousand rows you will be choosing an approximate index. Naive Bayes is a table of counts, which can be merged across shards and updated one event at a time, an attractive property for a streaming pipeline. A kernel model carries its support vectors with it, so its serving cost scales with how many of them there are. Choosing among them is therefore also a choice about memory, latency and how the model is updated.

# kNN: scaling is part of the model, so it lives inside the pipeline

nb = make_pipeline(CountVectorizer(), MultinomialNB(alpha=1.0))

Key takeaways

  • kNN predicts from the k most similar training points. It has no training cost and a high prediction cost, k is its bias-variance knob (small is flexible), and it depends entirely on the distance: scale the features and remove irrelevant ones.
  • The curse of dimensionality makes "near" meaningless as features multiply: with 1,000 uniform features the nearest and farthest points are almost equally far. Distance methods need few, informative dimensions or a learned embedding.
  • Naive Bayes multiplies per-feature likelihoods by a class prior, working in log space and with Laplace smoothing. It is a strong cheap baseline for text, trains by counting and updates incrementally.
  • Its independence assumption leaves rankings sound and probabilities inflated: duplicating every feature left accuracy unchanged and pushed the log-loss from 0.57 to 1.18. Calibrate before trusting its probabilities.
  • A kernel computes the inner product in a richer feature space without building it, so a linear method can draw curved boundaries. The price is a pairwise-similarity matrix that grows with the square of the rows, which limits kernel methods to small and medium data.
  • An SVM picks the widest-margin boundary, depends only on its support vectors, and has C and the kernel width as its complexity knobs.

Check your understanding

A kNN classifier with k = 1 scores 100 percent on its training data and 90 percent on test data, while k = 15 scores 95 percent and 93 percent. What explains the training score at k = 1?

  1. The model is a perfect fit to the true underlying rule
  2. Each training point is its own nearest neighbour, so the model reproduces the training labels, noise included
  3. The test set was accidentally included in training
  4. kNN with k = 1 minimises the test error by construction
When a training point is queried, its nearest neighbour is itself at distance zero, so with k = 1 it always predicts its own label. That reproduces the training noise and signals high variance, which the test score confirms. A perfect fit to the true rule would not have a 10-point gap; nothing suggests leakage; and no value of k is guaranteed to minimise test error.

A kNN model uses two features: a distance in kilometres (0 to 20) and an income in pounds (20,000 to 90,000). Accuracy is poor. What is the most likely issue and fix?

  1. The model needs a larger k, because income has too many values
  2. Remove the distance feature, since income varies more
  3. Use the median instead of the mean when voting
  4. Income dominates the Euclidean distance because of its scale; standardise both features
A difference of 10,000 pounds swamps a difference of 10 kilometres in the distance, so the neighbours are effectively chosen by income alone. Standardising puts both on a comparable scale (using training statistics only). Changing k or the voting rule does not fix a badly scaled distance, and dropping the feature with the smaller range throws away information instead of rebalancing it.

You add 40 columns of random noise to a kNN problem that had 3 informative features. What do you expect to happen to accuracy, and why?

  1. It falls: the noise adds random distance, so true neighbours are pushed apart and unrelated points drawn in
  2. It rises: more features mean more information about each point
  3. It is unchanged: kNN ignores features that do not help
  4. It rises, because the curse of dimensionality makes points more separable
Euclidean distance treats every feature equally, so 40 noise dimensions contribute much more random distance than the 3 informative ones contribute signal. kNN has no mechanism for learning that a feature is useless. High dimensionality makes points more equidistant, not more separable.

Every word in your text classifier's input is accidentally duplicated before it reaches a multinomial naive Bayes model, in training and in prediction. What is the most likely effect?

  1. Accuracy halves, because the evidence is counted incorrectly
  2. No effect on any output, because the duplicates cancel in the product
  3. Accuracy changes little, but the predicted probabilities become more extreme and less trustworthy
  4. The model fails, because duplicated features make the class priors zero
Duplicating a word doubles its log-likelihood contribution, so the gaps between class scores double: the ranking is largely preserved (accuracy about the same) but the probabilities become sharper, i.e. overconfident, with worse log-loss in our experiment. The duplicates do not cancel; they compound. The priors are unaffected.

Why does naive Bayes need Laplace smoothing?

  1. To make the independence assumption true
  2. So that a word never seen with a class in training does not give that class probability exactly zero and veto it for ever
  3. To make the class priors equal
  4. To reduce the number of words in the vocabulary
Without a pseudo-count, a single unseen word-class pair multiplies the class's likelihood by zero (or takes the logarithm of zero), eliminating the class however strong the other evidence. Smoothing keeps every probability positive. It does nothing about independence, leaves the priors alone and does not shrink the vocabulary.

You have 5 million labelled rows of 40 numeric features and want to try a kernel SVM with an RBF kernel. What is the main obstacle?

  1. The RBF kernel cannot handle numeric features
  2. SVMs only work for two or fewer features
  3. Kernel training needs work and memory that grow at least quadratically with the number of rows, which is impractical at this size
  4. The kernel trick requires the features to be integers
A kernel method works with the matrix of pairwise similarities between training points: 5 million squared is 25 trillion entries, and training time grows at least quadratically. That is why kernel SVMs are used on small and medium data, and why large problems use linear models, approximate kernels or boosted trees. The RBF kernel is designed for numeric features and the number of features is not the limiting factor.
