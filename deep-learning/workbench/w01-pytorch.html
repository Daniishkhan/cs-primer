Workbench 1: PyTorch by Hand

Chapter 5 built a small NumPy autodiff engine and then showed the PyTorch code that does the same job. Here you run the real thing. You make tensors and watch views share memory, ask PyTorch for the gradient of a small expression and compare it with the scalar engine you wrote in A0 lab 2, check every gradient of a small network the same way, then train an nn.Module with the standard loop. The two engines should agree to six decimal places, and they do.

Why measure it

Autograd is easy to use and easy to half believe. If you have only called loss.backward(), the gradient is a number that appears. When you have computed the same number a second way, with an engine you wrote yourself, the framework stops being a black box: you know exactly what it is doing, and you can trust it in the places where it is quietly wrong, such as accumulating gradients you forgot to clear. The habit is the one this whole track uses: write the prediction down, then measure.

What you need

  • The lab VM, CPU only. The rented 16-vCPU machine described on Your Lab Machine, with PyTorch already installed in its ~/lab environment. No downloads at run time and no GPU. The script takes a few seconds; allow an hour to work through the page.

Predict before you run

The chapter's engine and PyTorch both apply the chain rule node by node (chapter 2). For the loss below, with one weight w and one bias b, the chain rule gives a closed form you can evaluate on paper:

L = (tanh(wx + b) − t)2 + 0.1 w2, and ∂L/∂w = 2 (tanh u − t)(1 − tanh2 u) x + 0.2 w with u = wx + b

Take w = 0.8, x = 1.5, b = −0.3 and the target t = 0.5. Two more predictions: the network the script trains has two hidden layers of 32 units, and PyTorch's nn.Linear(n_in, n_out) holds an nin × nout weight matrix plus nout biases.

Your prediction

On paper, to four decimal places: the value of u, tanh u and the loss; then ∂L/∂w. And how many parameters does a 2 → 32 → 32 → 1 network have? If you forget zero_grad() and call backward() three times on the same loss, what happens to p.grad?

Check your arithmetic

u = 0.8 × 1.5 − 0.3 = 0.9. tanh 0.9 = 0.7163, so the error is 0.2163 and the squared error is 0.0468. Add 0.1 × 0.64 = 0.064 to get L ≈ 0.1108. The slope 1 − tanh2 0.9 = 0.4869, so ∂L/∂w = 2 × 0.2163 × 0.4869 × 1.5 + 0.16 = 0.3160 + 0.16 = 0.4760.

Parameters: (2 × 32 + 32) + (32 × 32 + 32) + (32 + 1) = 96 + 1,056 + 33 = 1,185. Gradients accumulate: each call adds to .grad, so three identical calls give 1, 2 and 3 times the first value.

The idea

  1. make tensors; show shape, dtype, device, and that a transpose is a view
  2. one expression, two engines: PyTorch autograd and a scalar Value from lab 2, plus a finite difference
  3. a 2-3-1 network: copy PyTorch's weights into the scalar engine and compare all 13 gradients
  4. train a 2-32-32-1 nn.Module on two moons with zero_grad, backward, step
  5. drop zero_grad on purpose and watch the gradient grow
"""PyTorch by hand: tensors, autograd and a training loop, with PyTorch's
gradients checked against the scalar engine you built in lab 2.

    python pytorch_by_hand.py

Needs: torch (workbench/requirements.txt). No downloads."""
import argparse
import math
import random

import torch
from torch import nn

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--steps", type=int, default=300)     # training steps
ap.add_argument("--seed", type=int, default=0)
args, _ = ap.parse_known_args()        # notebooks pass their own flags

if torch.cuda.is_available():
    DEVICE = "cuda"
else:
    DEVICE = "cpu"
torch.manual_seed(args.seed)
print(f"training device: {DEVICE}; torch {torch.__version__}")

# ── 2. Tensors: shape, dtype, device, and views that share memory ────────
x = torch.arange(12, dtype=torch.float32).reshape(3, 4)
print("\n[tensors]")
print(f"shape {tuple(x.shape)}, dtype {x.dtype}, device {x.device}, "
      f"{x.numel() * x.element_size()} bytes")
t = x.T                                  # a view: no data copied
print(f"transpose shares memory: {t.data_ptr() == x.data_ptr()}; "
      f"strides {x.stride()} -> {t.stride()}")
r = x.reshape(2, 6)
r[0, 0] = 99.0                           # write through the view
print(f"write through a view changed the original: x[0, 0] = {x[0, 0]:.0f}")
col, row = torch.zeros(3, 1), torch.zeros(4)
print(f"broadcast (3,4) + (3,1) + (4,) -> {tuple((x + col + row).shape)}")

# ── 3. The scalar engine from lab 2, cut down to what we need ────────────


class Value:
    """One number that remembers how it was made (ml-foundations lab 2)."""

    def __init__(self, data, parents=()):
        self.data, self.grad = float(data), 0.0
        self.parents, self._backward = parents, lambda: None

    def __add__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data + o.data, (self, o))

        def back():
            self.grad += out.grad
            o.grad += out.grad
        out._backward = back
        return out

    def __mul__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data * o.data, (self, o))

        def back():
            self.grad += o.data * out.grad
            o.grad += self.data * out.grad
        out._backward = back
        return out

    __radd__, __rmul__ = __add__, __mul__
    def __neg__(self): return self * -1.0
    def __sub__(self, o): return self + (-o)
    def __rsub__(self, o): return (-self) + o

    def __pow__(self, n):
        out = Value(self.data ** n, (self,))

        def back():
            self.grad += n * self.data ** (n - 1) * out.grad
        out._backward = back
        return out

    def tanh(self):
        th = math.tanh(self.data)
        out = Value(th, (self,))

        def back():
            self.grad += (1 - th * th) * out.grad
        out._backward = back
        return out

    def backward(self):
        order, seen = [], set()

        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for p in v.parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):
            v._backward()


# ── 4. Autograd: the same expression in both engines ─────────────────────
# loss = (tanh(w x + b) - target)^2 + 0.1 w^2
W0, X0, B0, T0 = 0.8, 1.5, -0.3, 0.5
w = torch.tensor(W0, dtype=torch.float64, requires_grad=True)
b = torch.tensor(B0, dtype=torch.float64, requires_grad=True)
loss = (torch.tanh(w * X0 + b) - T0) ** 2 + 0.1 * w ** 2
loss.backward()

vw, vb = Value(W0), Value(B0)
vloss = ((vw * X0 + vb).tanh() - T0) ** 2 + 0.1 * vw ** 2
vloss.backward()

eps = 1e-6                                # central difference on w


def f(wv):
    return (math.tanh(wv * X0 + B0) - T0) ** 2 + 0.1 * wv ** 2


numeric = (f(W0 + eps) - f(W0 - eps)) / (2 * eps)
print("\n[autograd] loss = (tanh(w x + b) - t)^2 + 0.1 w^2, "
      f"w={W0}, x={X0}, b={B0}, t={T0}")
print(f"loss    torch {loss.item():.6f}   engine {vloss.data:.6f}")
print(f"dL/dw   torch {w.grad.item():.6f}   engine {vw.grad:.6f}   "
      f"finite diff {numeric:.6f}")
print(f"dL/db   torch {b.grad.item():.6f}   engine {vb.grad:.6f}")

# ── 5. A whole 2-3-1 network: every gradient, both engines ───────────────
net = nn.Sequential(nn.Linear(2, 3), nn.Tanh(), nn.Linear(3, 1)).double()
X = torch.tensor([[0.5, -1.0], [1.0, 0.3], [-0.7, 0.8], [0.2, 0.2]],
                 dtype=torch.float64)
Y = torch.tensor([[1.0], [0.0], [0.0], [1.0]], dtype=torch.float64)
torch.mean((net(X) - Y) ** 2).backward()
tg = torch.cat([p.grad.flatten() for p in net.parameters()])

W1, B1, W2, B2 = [p.detach().tolist() for p in net.parameters()]
vW1 = [[Value(v) for v in rw] for rw in W1]
vB1 = [Value(v) for v in B1]
vW2 = [Value(v) for v in W2[0]]
vB2 = Value(B2[0])
total = Value(0.0)
for xs, ys in zip(X.tolist(), Y.tolist()):
    hid = [(vW1[j][0] * xs[0] + vW1[j][1] * xs[1] + vB1[j]).tanh()
           for j in range(3)]
    out = vW2[0] * hid[0] + vW2[1] * hid[1] + vW2[2] * hid[2] + vB2
    total = total + (out - ys[0]) ** 2
(total * (1 / len(X))).backward()
eg = []                                  # same order as PyTorch's flatten
for j in range(3):
    eg += [vW1[j][0].grad, vW1[j][1].grad]
eg += [v.grad for v in vB1] + [v.grad for v in vW2] + [vB2.grad]
worst = max(abs(a - c) for a, c in zip(tg.tolist(), eg))
print(f"\n[network] {len(eg)} gradients, 2-3-1 tanh net, 4 points")
print(f"largest |torch - engine| over all {len(eg)}: {worst:.2e}")
print("first three:", " ".join(f"{a:.6f}/{c:.6f}"
                               for a, c in zip(tg.tolist()[:3], eg[:3])))

# ── 6. nn.Module and the five-line training loop ─────────────────────────


def make_moons(n, noise=0.15, seed=0):
    """Two interleaved half-circles (the shape of deep-learning lab 1)."""
    g = random.Random(seed)
    pts, ys = [], []
    for i in range(n):
        k, a = i % 2, g.uniform(0.0, math.pi)
        px = math.cos(a) if k == 0 else 1.0 - math.cos(a)
        py = math.sin(a) if k == 0 else 0.5 - math.sin(a)
        pts.append([px + g.gauss(0, noise), py + g.gauss(0, noise)])
        ys.append(float(k))
    return torch.tensor(pts), torch.tensor(ys).unsqueeze(1)


class MLP(nn.Module):
    def __init__(self, width=32):
        super().__init__()
        self.body = nn.Sequential(
            nn.Linear(2, width), nn.ReLU(),
            nn.Linear(width, width), nn.ReLU(),
            nn.Linear(width, 1))

    def forward(self, x):
        return self.body(x)


Xtr, Ytr = make_moons(400, seed=1)
Xte, Yte = make_moons(400, seed=2)
Xtr, Ytr, Xte, Yte = [a.to(DEVICE) for a in (Xtr, Ytr, Xte, Yte)]
model = MLP().to(DEVICE)
n_params = sum(p.numel() for p in model.parameters())
print(f"\n[training] parameters: {n_params} "
      f"(predicted 2*32+32 + 32*32+32 + 32+1 = {2*32+32 + 32*32+32 + 33})")
opt = torch.optim.Adam(model.parameters(), lr=0.01)
lossfn = nn.BCEWithLogitsLoss()
for step in range(args.steps + 1):
    if step % 100 == 0:
        with torch.no_grad():
            acc = ((model(Xte) > 0).float() == Yte).float().mean().item()
        print(f"step {step:4d}  train loss "
              f"{lossfn(model(Xtr), Ytr).item():.4f}  test accuracy {acc:.3f}")
    opt.zero_grad()                       # 1. clear old gradients
    loss = lossfn(model(Xtr), Ytr)        # 2. forward
    loss.backward()                       # 3. backward
    opt.step()                            # 4. update

# ── 7. The classic bug: forget zero_grad ─────────────────────────────────
p = nn.Parameter(torch.tensor([3.0]))
for call in (1, 2, 3):
    ((p * 2.0 - 10.0) ** 2).sum().backward()
    print(f"backward call {call} with no zero_grad: p.grad = "
          f"{p.grad.item():.0f}")

What you should see

  • The tensors block. A new tensor lives on the CPU in 32-bit floats (torch.float32) unless you say otherwise: 12 numbers of 4 bytes make 48 bytes. The transpose shares memory with the original and only swaps the strides, so writing through the reshaped view changed x[0, 0] to 99. Moving data to the GPU is an explicit .to(device).
  • The autograd block. The loss is 0.110785 and ∂L/∂w is 0.475958, matching the 0.1108 and 0.4760 of your paper arithmetic. PyTorch, the lab-2 style engine and the central finite difference agree to all six decimals. They must, because they compute the same chain rule; the finite difference is the independent witness.
  • The network block. All 13 gradients (6 + 3 first-layer weights and biases, 3 + 1 second-layer ones) differ by less than 10−16 (5.6 × 10−17 in the run above), which is rounding in 64-bit floats. If you ran the engine in 32-bit the gap would be nearer 10−7.
  • The training block. 1,185 parameters, exactly your prediction. The loss starts near ln 2 = 0.693 (the model knows nothing, and the binary cross-entropy of a coin flip is ln 2; the printed 0.6892 is the first forward pass with small random weights) and falls to about 0.015, with 98.3% test accuracy on fresh points. The few remaining errors are most likely points where noise pushed the two moons into each other.
  • The last three lines. The gradient of (2p − 10)2 at p = 3 is −16, and without zero_grad() it becomes −32 and −48. This is the most common PyTorch bug, and it is a feature in disguise: accumulation lets you sum gradients over several small batches before one update.

Break it

  • Remove opt.zero_grad() from the training loop. Predict first: the gradient the optimiser sees is a running sum, so with Adam (which normalises by the gradient's scale) the loss may still fall but behave differently; with plain SGD it behaves like a rising learning rate. Run both and describe what changes.
  • Run the engine in 32 bits. Change .double() and dtype=torch.float64 to 32-bit. Predict the new size of the largest difference (hint: a 32-bit float carries about seven decimal digits), then measure it.
  • Add an operation to the lab engine. Give Value an exp method and change the expression to use exp(b). Work out the local derivative yourself, compare with PyTorch, and check that a wrong rule (try exp(self.data) times 2) is caught by the six-decimal comparison.
  • Evaluate with the graph on. Wrap the test-accuracy line in torch.no_grad() versus leaving it out, and compare the process's peak memory (resource.getrusage(resource.RUSAGE_SELF).ru_maxrss) after each. Predict which is larger and why.

Key takeaways

  • PyTorch's autograd is the chain rule recorded as the code runs; a 40-line scalar engine gives the same gradients, here to six decimals and better.
  • A finite difference is the independent check for any gradient you did not derive by hand.
  • An nn.Linear(n_in, n_out) holds ninnout + nout numbers, so you can predict a model's parameter count before you build it.
  • Gradients accumulate until cleared: zero_grad() belongs in every loop.
