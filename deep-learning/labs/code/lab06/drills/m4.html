To produce a token, attention needs the keys and values of every previous token, so a server stores them in a KV cache: one per sequence, while the weights are stored once in all. Making a token also means reading every weight from memory to do only 2 FLOPs per weight, so decoding is limited by memory bandwidth until a batch shares the reads.

A step takes the larger of two times: memory time (bytes read divided by bandwidth) and compute time (FLOPs divided by peak speed). The ridge is the batch where they are equal; below it, extra sequences barely change the step time. weight_bytes counts every expert of a mixture of experts, idle or not, and max_batch is how many caches fit beside the weights.

16 GB of weights at 3.35 TB/s: 4.8 ms per step, 209 tokens/s for one sequence
batch 8 reads the weights once: 8 tokens per 4.8 ms = 1,669 tokens/s
