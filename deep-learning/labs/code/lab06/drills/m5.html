Given a compute budget, should you train a bigger model on fewer tokens or a smaller one on more? A fitted law models the loss as an unbeatable floor, plus a penalty for having too few parameters N, plus a penalty for seeing too few tokens D; each penalty shrinks as a power law.

Fix the budget with C = 6*N*D, so D is C / (6*N): the loss then depends on N alone and has one lowest point. optimum is the closed form in its docstring, and the checker tests it indirectly: 6ND must equal C, and sizes 0.5, 0.8, 1.25 and 2 times the optimum must all do worse. The bottom of the curve is flat, so excess_loss at half or twice the best size is small.

N = 2, D = 2: loss 1.414; N = 1, D = 4 and N = 4, D = 1: loss 1.5
