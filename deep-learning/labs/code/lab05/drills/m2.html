Training a byte-pair tokeniser repeats one step: count the adjacent pairs of tokens, take the most frequent, give it the next free id (256, then 257, and so on), and merge it everywhere. The ordered list of merges is the whole result, because encoding later replays it in that order; if no pair is left, training stops early.

Work on pieces, not on the raw text: pretokenise cuts the text, a Counter counts each distinct piece once, and each piece becomes its list of byte ids, so no merge can cross a word. Recount after every merge, since merging changes what is adjacent. Once "e" and "s" fuse, the pair "s" "t" no longer exists in "newest", and the best new pair is "es" followed by "t". Keep the merges in a dict in learning order.

256: e+s = es   257: es+t = est   258: " "+l = " l"   259: o+w = ow
260: " l"+ow = " low"    (later merges build on earlier ones)
