A merge table is useless until it is applied to new text: encoding cuts the text into pieces, starts each as bytes, and keeps applying the earliest-learned merge present until none applies. Decoding runs backwards, because every token id stands for a fixed string of bytes.

"Earliest-learned" means the lowest merge id, not the most frequent pair now; that keeps encoding consistent with training. vocab_bytes walks the merges in learning order: an id below 256 is one byte, and a merged id is the bytes of its two parts joined. decode joins the bytes and reads them as UTF-8 with errors="replace", because tokens do not respect character boundaries: an emoji cut across two tokens must give the character U+FFFD, not an exception.

merges learned: es, est, " l", ow, " low" (ids 256 to 260)
" lowest" never appeared, yet encodes to [260, 257] = " low" + "est"
