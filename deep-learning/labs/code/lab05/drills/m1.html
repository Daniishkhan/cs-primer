A tokeniser must be able to spell any string, so it starts from bytes: every character becomes one to four numbers between 0 and 255. Byte-pair encoding then repeatedly fuses the most frequent adjacent pair of tokens into one new token.

utf8_ids is the standard UTF-8 encoding. Counting over a whole corpus every round is slow, so count_pairs counts each distinct word once and weights its pairs by how often the word occurs; pairs never span two words. In merge_pair, scan left to right and consume each pair as you merge it. best_pair needs a tie rule so that two runs on the same data learn the same vocabulary: the smaller ids win.

" newest" x 6, " widest" x 3: (101, 115) "es" occurs 9 times, so does "st"
tie: 101 beats 115, so "es" wins: " newest" -> [32, 110, 101, 119, 256, 116]
