Lab 4: Train a Tiny GPT

In chapter 12 you read a 108,352-weight GPT trained with NumPy on Shakespeare. Here you build a smaller one in which nothing is borrowed: not the array library, not the framework, not even the derivatives. You write a scalar autograd engine (a class that remembers how each number was made and walks the graph backwards), the layers on top of it, a GPT that processes one token at a time with a cache of keys and values, the Adam optimiser and the training loop, and finally a sampler. Then you train 1,264 weights on 146 first names for about 20 seconds and watch it invent names it has never seen.

Why this lab matters

Every large language model is this program with larger numbers. The GPT of this lab has the same parts as the one behind any chatbot: token and position embeddings, residual blocks of attention and MLP, a normalisation, an output head over the vocabulary, a cross-entropy loss over the next token, a gradient computed by backpropagation, an Adam update and a sampler. At 1,264 weights you can print every one of them, and when the loss is wrong you can find out why. Doing it once, with nothing hidden, changes how you read framework code afterwards: loss.backward() stops being a spell and becomes the function you wrote in milestone 1.

The second reason is that the loss number now means something. Chapter 14 taught that an untrained model scores about ln V, that the loss is measured in nats, and that eloss (the perplexity) is the effective number of choices the model hesitates between. You will see all three on your own model: a start near ln 27 = 3.30, an end near 2.1 to 2.3, and a held-out perplexity of about 10 where chance would be 27. The work follows A0 chapter 9 (autodiff), chapter 10 (Adam and schedules) and chapter 11 (stable softmax) as well as the course's own chapters 9, 10, 12 and 14.

Prior art, and what is different here

The idea of a scalar autograd engine comes from Karpathy's micrograd (2020), and the idea of a whole GPT in plain Python comes from his microgpt, published on 12 February 2026 as a single 200-line file with no dependencies. I read the author's write-up for this lab (the post describes 4,192 parameters, a width of 16 with 4 heads, one layer, a context of 16, 1,000 training steps on about 32,000 names and a final loss near 2.37) but did not copy any code. The design below is my own: a smaller model (1,264 weights, width 8, 2 heads, a context of 8) so that the whole check runs in under a minute, a 146-name list written for this lab, an iterative backward pass that survives deep graphs, a held-out split, and tests against an independent reference. Numbers are not comparable with Karpathy's because the data and sizes differ.

Pure Python, seeded, about 20 seconds

Python 3.9 or newer and nothing else. Milestones 1 to 3 run in a couple of seconds. Milestones 4 and 5 share one training run of 600 steps, which takes roughly 16 seconds on a recent laptop; slower machines take longer but should stay well inside a minute. Everything is seeded (the weights, the order of the names, the sampling), so the numbers in this page are what you should see to the last printed digit, up to floating-point differences between machines. Random tests print their seed when they fail; replay one with python3 check.py solution 1 7 (milestone 1, seed 7).

What you'll build

Five milestones, each building on the last:

  1. A scalar autograd engine: a Value class with addition, multiplication, powers, exp, log and ReLU, and a backward() that applies the chain rule over the whole graph.
  2. Layers on Values: linear, a stable softmax, rmsnorm and the cross-entropy loss, each checked against finite differences.
  3. The GPT, one token at a time: embeddings, residual attention and MLP blocks with a cache of keys and values, a head, and the loss of a whole name, verified against a full-sequence reference and against numerical gradients.
  4. Adam and the training loop: the optimiser of A0 chapter 10 with bias correction, a linearly decaying learning rate and 600 steps on 146 names.
  5. Held-out loss and sampling: the loss on names the model never saw, and a temperature sampler that invents new ones.

Milestone 1: a scalar autograd engine

Backpropagation (chapter 2) computes the derivative of a loss with respect to every weight by applying the chain rule backwards. In chapter 2 you did it with matrices; A0 chapter 9 showed that the same thing works for any computation if each operation records its inputs and knows its own local derivative. That is what you build: a Value is a number that remembers the Values it was computed from (its children) and a small function that, given the gradient of the output, hands the correct share to each child. A whole model, however large, is then a graph of Values, and backward() is one function.

Each operation has a local rule. For c = a + b both inputs receive the output's gradient unchanged. For c = a b each input receives the output gradient times the other input. For c = ak the input receives k ak−1 times the output gradient. For exp the local derivative is exp itself, for log it is 1/a, and for ReLU it is 1 where the input was positive and 0 elsewhere (including exactly 0, the convention of Lab 1). Everything else (subtraction, division, negation) is built from those six in the given code.

Two details decide whether your engine works on a real model. Accumulate, never assign: a node's .grad starts at 0 and every use adds to it (+=). The example above has a used twice, and x * x uses the same Value as both factors; assign instead of add and one contribution is silently lost. Order matters: a node may push its gradient to its children only after every node that uses it has pushed to it, so backward() first builds a topological order (each node after all its children, found by depth-first search) and then walks it in reverse, calling each node's stored function once.

Common misconception

"Backward is just recursion: call backward on the children." A recursive version that visits a child every time it is reached computes the right answer on a tree and an exponential amount of work on a diamond: in the graph above, a would be processed twice, and in a model each activation feeds many later computations. It also overflows Python's recursion limit (about 1,000 frames) on the graph of even one small model, which is thousands of nodes deep. The check includes a chain of 20,000 operations, so use an explicit stack and visit each node once.

import math
from starter import Value

a, b = Value(2.0), Value(-3.0)
c = a * b + a ** 2
c.backward()
print("c =", c.data, "  dc/da =", a.grad, "  dc/db =", b.grad)

x = Value(3.0)
y = x * x + x              # x is used three times: the gradients must add up
y.backward()
print("y =", y.data, "  dy/dx =", x.grad, " (2x + 1 = 7)")

Hints try without first
  • Pattern for every operation: compute out = Value(new_data, (self, other)), define def back(): ... that does self.grad += local_slope * out.grad (and the same for other), set out._back = back, return out.
  • The closure reads out.grad when it runs, not when it is defined, which is what you want: it has been filled in by then.
  • For __pow__ the local slope is k * self.data ** (k - 1). Division, via ** -1, depends on it.
  • backward: build order with a stack of (node, expanded) pairs. Pop a node; if it is unexpanded and not yet seen, mark it seen, push it back as expanded, then push its children. When you pop an expanded node, append it to order. Then set self.grad = 1.0 and run _back on reversed(order).
  • If the reused-node test fails with a gradient that is too small, you used = somewhere instead of +=.

class Value:
    # __init__ and the operators built from these six (-, /, reflected ones) are given.

    def __add__(self, other):
        """self + other, where other is a Value or a plain number."""
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))

        def back():
            self.grad += out.grad                  # d(a + b)/da = 1
            other.grad += out.grad
        out._back = back
        return out

    def __mul__(self, other):
        """self * other."""
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))

        def back():
            self.grad += other.data * out.grad     # d(a b)/da = b
            other.grad += self.data * out.grad
        out._back = back
        return out

    def __pow__(self, k):
        """self ** k for a plain number k (an int or a float, not a Value)."""
        out = Value(self.data ** k, (self,))

        def back():
            self.grad += k * self.data ** (k - 1) * out.grad
        out._back = back
        return out

    def exp(self):
        """e ** self, as a new Value."""
        out = Value(math.exp(self.data), (self,))

        def back():
            self.grad += out.data * out.grad       # d exp(a)/da = exp(a)
        out._back = back
        return out

    def log(self):
        """Natural logarithm, as a new Value (self.data must be positive)."""
        out = Value(math.log(self.data), (self,))

        def back():
            self.grad += out.grad / self.data      # d log(a)/da = 1/a
        out._back = back
        return out

    def relu(self):
        """max(0, self); the slope is 1 where self.data > 0 and 0 elsewhere (including exactly 0)."""
        out = Value(self.data if self.data > 0 else 0.0, (self,))

        def back():
            self.grad += (1.0 if self.data > 0 else 0.0) * out.grad
        out._back = back
        return out

    def backward(self):
        """Set self.grad = 1 and propagate to every Value this one depends on.
        Visit each node once, in reverse topological order, so a node's grad is complete before it is pushed on."""
        order, seen = [], set()
        stack = [(self, False)]                    # iterative depth-first search: deep graphs must not overflow the stack
        while stack:
            v, expanded = stack.pop()
            if expanded:
                order.append(v)                    # appended only after all its inputs
            elif id(v) not in seen:
                seen.add(id(v))
                stack.append((v, True))
                for p in v._prev:
                    stack.append((p, False))
        self.grad = 1.0
        for v in reversed(order):
            if v._back:
                v._back()

Milestone 2: layers on Values

With Value in hand, the layers of chapter 10 are ordinary Python over lists of Values; backward comes free. You need four of them. linear(x, W) maps a vector of n_in Values to n_out Values with a row of W per output: the dot products sum(w * xi for w, xi in zip(row, x)). softmax(logits) returns probabilities as Values. Subtract the largest logit first, as a plain float taken from .data: the constant cancels in the ratio, so it changes no probability and no gradient, and it keeps exp from overflowing (the same one-line fix as Lab 1 and A0 chapter 11). rmsnorm(x) rescales a vector to unit root-mean-square, xi (mean(x2) + ε)−1/2. RMSNorm is the layer norm of Lab 3 without the mean subtraction and without learned gain and bias; many recent models use it (chapter 3), and it needs only the power and the multiplication you have already differentiated. cross_entropy(logits, target) is minus the log of the probability of the correct next token, in nats.

You do not have to derive a single new gradient. The check compares every layer's gradient with finite differences, and the cross-entropy has a result worth recognising on sight: the gradient of the loss with respect to the logits is p − onehot(target), the predicted probabilities minus the truth (chapter 2). Your engine will rediscover it through softmax, log and negation without being told.

from starter import Value, softmax, cross_entropy, rmsnorm, linear

The loss on logits (2, 1, 0.1) with true class 0 is 0.417 nats, as in chapter 2's example, and the gradient (−0.341, 0.2424, 0.0986) is p − (1, 0, 0). The logits (1000, 1001) work because of the maximum subtraction. RMSNorm of (3, 4) divides by √12.5 = 3.536, giving (0.8485, 1.1314), whose mean square is 1.

Common misconception

"Subtracting the maximum inside softmax changes the answer, so the gradient needs a correction." It changes neither. The shift is the same number c for every logit, and softmax(z − c) = softmax(z) exactly, so there is nothing to correct. In your code the subtraction uses a plain float (max(v.data for v in logits)), so the graph contains no node for it. If you take the max as a Value instead, the gradient still comes out right (the contributions cancel) but you pay for extra nodes on every call, which matters when each node costs microseconds.

Solution spoiler 
def linear(x, W):
    """x: list of n_in Values, W: n_out rows of n_in Values. Returns n_out Values, out[i] = sum_j W[i][j] x[j]."""
    return [sum((w * xi for w, xi in zip(row, x)), Value(0.0)) for row in W]

def softmax(logits):
    """Probabilities as Values. Subtract the largest logit (a plain float, a constant) before exp."""
    m = max(v.data for v in logits)
    exps = [(v - m).exp() for v in logits]
    total = sum(exps, Value(0.0))
    return [e / total for e in exps]

def rmsnorm(x, eps=1e-5):
    """Scale the vector to unit root-mean-square: x_i * (mean(x^2) + eps) ** -0.5 (chapter 03, RMSNorm)."""
    ms = sum((xi * xi for xi in x), Value(0.0)) * (1.0 / len(x))
    scale = (ms + eps) ** -0.5
    return [xi * scale for xi in x]

def cross_entropy(logits, target):
    """-log softmax(logits)[target] as one Value, in nats."""
    return -softmax(logits)[target].log()

The 1,264 weights are two embedding tables (27 × 8 for tokens and 8 × 8 for positions), one block (four 8 × 8 attention matrices, an 8 → 32 and a 32 → 8 MLP) and a 27 × 8 head. Note how the chapter's count appears: the block holds 4C2 + 8C2 = 768 of the weights, 61%, with the MLP twice the size of attention (compare Lab 3's 12C2 + 9C, less the biases and norm parameters this model omits). The last line of the output needs explaining: only 992 of the 1,264 weights received a gradient from the name "ana". The 24 embedding rows of the 24 letters that never appeared are untouched, as are the position rows for positions 4 to 7, and a few ReLU units were silent; weights that played no part in the loss have a gradient of exactly zero. That is autograd being correct, not a bug.

Your job is the forward pass. It differs from Lab 3 in one way: instead of a (T, C) matrix with a mask, gpt_step processes one token at a time and keeps a KV cache, the list of keys and values of all earlier positions in each layer. Position t computes its query, key and value, appends its key and value to the cache, and attends over the cache, which holds exactly the positions 0 to t. The causal mask is therefore not a matrix any more; it is the fact that the future has not been added yet. This is also how real models generate text (A3 chapter 18 measures what the cache costs), and the check verifies that it gives the same logits as the full-sequence, masked computation of Lab 3.

The steps for one token with id token at position pos, per layer l, are:

  1. x = wte[token] + wpe[pos], a vector of C Values.
  2. xn = rmsnorm(x), then q, k, v = linear(xn, wq), linear(xn, wk), linear(xn, wv). Append k and v to keys[l] and values[l].
  3. For each head i (columns i*d_k to (i+1)*d_k - 1): the score against every cached key is the dot product of the query slice and the key slice divided by √dk; softmax over the scores; the head's output is the weighted sum of the cached value slices. Concatenate the heads.
  4. x = x + linear(heads, wo): the residual connection around attention.
  5. x = x + linear(relu(linear(rmsnorm(x), w1)), w2): the residual connection around the MLP.

After the last layer, linear(rmsnorm(x), head) gives the V = 27 logits for the next token. Then sequence_loss(cfg, params, ids) loops over the positions of a tokenised name, calls gpt_step for ids[t], scores the logits against ids[t + 1] with cross_entropy and returns the mean over the predictions. It cuts ids to T + 1 entries first, because the context holds at most T = 8 inputs.

Common misconception

"With a KV cache the model only sees one token at a time, so it cannot be trained on a whole sequence in parallel." During training here the loop over positions only exists because the engine is scalar. The mathematics is identical to the masked, whole-matrix computation: the check compares your logits with such a computation to 10−9. A real framework runs the T positions at once with a mask (chapter 12); a real server runs them one at a time with a cache (A3 chapter 18). Same function, two schedules.

Hints try without first
  • Create the cache before attending: append k and v first, so the token can read itself. If you append afterwards, the first token has an empty cache and softmax fails on an empty list.
  • Slices of lists are cheap: q[s] with s = slice(i * d_k, (i + 1) * d_k) gives head i's part of a vector.
  • The score for head i against cached key kt is sum(a * b for a, b in zip(q[s], kt[s])) times 1.0 / math.sqrt(d_k). A plain float on the right of a Value is fine.
  • The head output for each coordinate j in the slice is sum(w[t] * values[l][t][j] for t in range(len(w))).
  • If the finite-difference check fails for one matrix only, you used the wrong matrix in that line (for example wq for the key). The failing weight's value tells you which matrix the sampled index came from if you print it.

def gpt_step(cfg, params, token, pos, keys, values):
    """Process ONE token at position pos and return its V logits (a list of Values).

    keys[l] and values[l] are the caches of layer l: lists with one C-vector (list of Values) per earlier
    position. Append this token's key and value to them BEFORE attending, so the token can read itself.
    Because only past entries are ever in the cache, the model is causal by construction."""
    C, h, L = cfg["C"], cfg["h"], cfg["L"]
    d_k = C // h
    x = [t + p for t, p in zip(params["wte"][token], params["wpe"][pos])]          # token + position embedding
    for l in range(L):
        xn = rmsnorm(x)
        q, k, v = linear(xn, params[f"l{l}.wq"]), linear(xn, params[f"l{l}.wk"]), linear(xn, params[f"l{l}.wv"])
        keys[l].append(k)
        values[l].append(v)
        heads = []
        for i in range(h):
            s = slice(i * d_k, (i + 1) * d_k)
            scores = [sum((a * b for a, b in zip(q[s], kt[s])), Value(0.0)) * (1.0 / math.sqrt(d_k)) for kt in keys[l]]
            w = softmax(scores)
            heads += [sum((w[t] * values[l][t][j] for t in range(len(w))), Value(0.0)) for j in range(s.start, s.stop)]
        x = [a + b for a, b in zip(x, linear(heads, params[f"l{l}.wo"]))]           # residual around attention
        hid = [z.relu() for z in linear(rmsnorm(x), params[f"l{l}.w1"])]
        x = [a + b for a, b in zip(x, linear(hid, params[f"l{l}.w2"]))]             # residual around the MLP
    return linear(rmsnorm(x), params["head"])

def sequence_loss(cfg, params, ids):
    """Mean cross-entropy of predicting ids[t+1] from ids[:t+1], over t = 0 .. len(ids) - 2 (one Value)."""
    ids = ids[:cfg["T"] + 1]                         # the context holds at most T input tokens
    keys = [[] for _ in range(cfg["L"])]
    values = [[] for _ in range(cfg["L"])]
    total = Value(0.0)
    for t in range(len(ids) - 1):
        total = total + cross_entropy(gpt_step(cfg, params, ids[t], t, keys, values), ids[t + 1])
    return total * (1.0 / (len(ids) - 1))

Milestone 4: Adam and the training loop

Gradient descent moves each weight a little against its gradient. Plain gradient descent uses one learning rate for every weight, which is a poor fit when gradients differ by orders of magnitude between the embedding of a rare letter and the weights of an MLP. Adam (Kingma and Ba, 2015; A0 chapter 10) keeps two running averages for each weight, the mean of its recent gradients, m, and the mean of their squares, v, and steps by the ratio:

m ← β1 m + (1 − β1) g,   v ← β2 v + (1 − β2) g2,   w ← w − lr · (m / (1 − β1t)) / (√(v / (1 − β2t)) + ε)

The divisions by 1 − βt are the bias correction: m and v start at 0 and would be too small in the first steps. With the correction, the very first step of any weight is lr × sign(g), whatever the size of g, which the check tests. This lab uses β1 = 0.9, β2 = 0.99 and ε = 10−8.

The loop (chapter 12, "The training loop", in scalar form) repeats five things for 600 steps: take the next name (a seeded shuffle of the training names, reshuffled when exhausted), compute sequence_loss, call backward(), set the learning rate for this step, and call the optimiser, whose step() also zeroes every gradient so the next step starts clean. Forgetting to zero the gradients is the classic bug: because the engine accumulates with +=, the gradients of step 2 would include those of step 1. The learning rate decays linearly to zero: lr * (1 - step / steps), which is large while the weights are far from useful and small at the end, when large steps would only jitter around the minimum. With one name per step the loss is noisy; you will see it bounce by a few tenths from step to step even when the trend is clean, so judge a run by averages over many steps.

Analogy: a learner who studies faster at the start

Imagine learning to spell names by being corrected one name at a time. At first every correction is a large improvement and a bold adjustment is right. Later, each correction is about a small habit, and bold changes undo earlier progress. A decaying learning rate is that change in attitude, and Adam's per-weight scaling is a student who pays more attention to the habits they are corrected on rarely (the weights with small gradients) and less to the ones that are corrected all the time.

Where it breaks down: a student remembers a correction; Adam only keeps two running averages per weight, and the 146 names are seen about four times each in 600 steps, with every pass in a different order, so memorising individual names is possible in principle for a larger model than this one (the held-out loss in milestone 5 is the test).

class Adam:
    # __init__ is given.

    def step(self, lr=None):
        """One update using each p.grad, with bias correction; then set every p.grad back to 0."""
        lr = self.lr if lr is None else lr
        self.t += 1
        c1, c2 = 1 - self.beta1 ** self.t, 1 - self.beta2 ** self.t
        for i, p in enumerate(self.params):
            g = p.grad
            self.m[i] = self.beta1 * self.m[i] + (1 - self.beta1) * g
            self.v[i] = self.beta2 * self.v[i] + (1 - self.beta2) * g * g
            p.data -= lr * (self.m[i] / c1) / (math.sqrt(self.v[i] / c2) + self.eps)
            p.grad = 0.0
def train(cfg, names, steps=600, seed=0, lr=0.02):
    """Train a fresh model for `steps` steps, one name per step, cycling through a seeded shuffle of names.
    The learning rate decays linearly from lr to 0 over the run. Returns (params, losses): the per-step losses."""
    params = init_params(cfg, seed)
    opt = Adam(flat_params(params), lr)
    rng = random.Random(seed)
    order, losses = [], []
    for step in range(steps):
        if not order:
            order = list(names)
            rng.shuffle(order)
        loss = sequence_loss(cfg, params, encode(order.pop()))
        loss.backward()
        opt.step(lr * (1.0 - step / steps))
        losses.append(loss.data)
    return params, losses

Milestone 5: held-out loss and sampling

A falling training loss shows that the model is fitting the names it sees, which a big enough model would do by memorising them. The honest measure is the loss on names it has never trained on (chapter 12, "Why hold some text back"). average_loss(cfg, params, names) returns the mean cross-entropy per predicted character over a list of names, in nats. Weight every prediction equally: a seven-letter name contributes eight predictions (seven letters and the end marker) and counts for more than a two-letter name, so sum the loss over all predictions and divide by their number, rather than averaging per-name means. Remember to cut each name to the context length exactly as sequence_loss does.

Chapter 14 gave the way to read the number. Chance is ln 27 = 3.30 nats. The perplexity eloss is the number of letters the model is effectively hesitating between: at 3.30 it is 27, a uniform guess. A model with a held-out loss of 2.30 has a perplexity of about 10: it has learned enough about how names are spelled to narrow 27 candidates to roughly ten at every position.

Sampling turns the trained next-token distribution into names (chapter 15). sample_name(cfg, params, rng, temperature=1.0) starts from the BOS token at position 0, runs gpt_step to get logits, divides the logits by the temperature, turns them into probabilities with a stable softmax over plain floats (the sampler needs no gradients), draws a token with the given sample_index using rng, and repeats. It stops when the model draws BOS (the end of the name) or after T letters, and returns the letters as a string. Temperature reshapes the distribution: below 1 it sharpens it (the likeliest letter becomes much more likely), above 1 it flattens it, and in the limit of 0 it becomes greedy decoding, always the single likeliest token.

Common misconception

"A model that generates new-looking names has understood names." The model has learned which letters tend to follow which, at the scale of a few characters, and the held-out loss measures exactly that. It has no idea what a name is, which is why some samples are plausible ("lana", "dana") and others are not. The pass criterion of the check is statistical (most sampled letter pairs occur in the training names; most samples are not copies of them), not a judgement about whether a name is real.

def average_loss(cfg, params, names):
    """Mean per-character cross-entropy, in nats, over all names (every position of every name counts once)."""
    total, count = 0.0, 0
    for name in names:
        ids = encode(name)[:cfg["T"] + 1]
        total += sequence_loss(cfg, params, ids).data * (len(ids) - 1)
        count += len(ids) - 1
    return total / count

def sample_name(cfg, params, rng, temperature=1.0):
    """Generate one name: start from BOS, repeatedly sample the next token, stop at BOS or after T letters."""
    keys = [[] for _ in range(cfg["L"])]
    values = [[] for _ in range(cfg["L"])]
    token, out = BOS, []
    for pos in range(cfg["T"]):
        logits = gpt_step(cfg, params, token, pos, keys, values)
        scaled = [z.data / temperature for z in logits]
        m = max(scaled)
        e = [math.exp(z - m) for z in scaled]
        token = sample_index([x / sum(e) for x in e], rng)
        if token == BOS:
            break
        out.append(token)
    return decode(out)

Systems connection

The wall-clock cost of this lab is a systems lesson in itself. A step takes about 25 milliseconds because each of the roughly 15,000 Values created per step is a Python object with a closure, so most of the time goes to allocating and walking the graph, not to arithmetic. Frameworks avoid exactly this by recording one node per tensor operation (a whole matrix product) instead of one per number, and by running that operation as a single fused kernel on a GPU. The memory story is the same one in miniature: the graph keeps every intermediate Value alive until backward() has used it, which is the activation memory that dominates large training runs (chapter 16).

What you learned

  • Reverse-mode autodiff needs three things per operation: the output, the inputs it came from and its local derivative; backward() visits each node once in reverse topological order and accumulates (+=) because values are reused.
  • The gradient of softmax followed by cross-entropy on the logits is p − onehot; your engine finds it by itself, and finite differences are the test that you can trust a gradient.
  • A GPT processed one token at a time with a KV cache gives the same logits as the masked full-sequence computation; causality is then the fact that the future is not in the cache.
  • An untrained model scores about ln V; a trained one is measured on held-out text, and eloss is its effective number of choices (about 10 here against 27 for chance).
  • Adam's first step is lr × sign(g); the learning rate decays to zero; gradients must be zeroed each step, and a single-name step makes the loss curve noisy.
  • Temperature trades safety for variety: near 0 is greedy decoding, above 1 flattens the distribution until the output is noise.
  • Everything larger models add is scale and engineering, not a different algorithm.

Check your understanding

In y = x * x + x at x = 3 the engine reports dy/dx = 6 instead of 7. What is the likeliest bug?

  1. The local derivative of addition is wrong; it should be 2
  2. The graph was visited in the wrong order
  3. A gradient is assigned (=) where it must be accumulated (+=), so one of the uses of x is lost
  4. The exponent rule was applied to a product
dy/dx = 2x + 1 = 7 comes from three uses of x: two as factors of x * x and one in the sum. With = the later use overwrites the earlier one and the total is short by one contribution (6 = 3 + 3 here, missing the 1). The addition rule passes the gradient on unchanged. A wrong order would typically give a different, order-dependent error.

The logits are (2, 1, 0.1) and the correct class is index 1 (the second). What is the gradient of the cross-entropy loss with respect to the three logits, to two decimals?

  1. (−0.34, 0.24, 0.10)
  2. (0.66, 0.24, 0.10)
  3. (0.34, −0.24, −0.10)
  4. (0.66, −0.76, 0.10)
The gradient is p − onehot(target). The probabilities are (0.66, 0.24, 0.10), and subtracting 1 at the target index gives (0.66, −0.76, 0.10); the entries sum to 0. The first option is the answer for class 0, the second forgets to subtract the one-hot vector and the third has the signs reversed.

In gpt_step you append the current token's key and value to the cache after computing attention instead of before. What goes wrong?

  1. Nothing: the token does not need to read itself
  2. Position 0 attends over an empty cache, and every later token cannot read itself, which changes the model and fails the reference comparison
  3. The model reads the future
  4. The gradients become zero
Attention in the full-sequence model lets token t attend to positions 0 to t inclusive, so a token reads its own key and value. Appending afterwards leaves out the diagonal, and at position 0 the softmax would see an empty list. The cache never holds future tokens in either order, so there is no leak, and the gradients remain non-zero.

The first Adam step is taken with lr = 0.02 on two weights whose gradients are 0.001 and 100. How far does each move?

  1. Both by about 0.02, in the direction opposite to their gradients
  2. The first by 0.00002, the second by 2
  3. The first by 0.02, the second by 2
  4. Neither: the first step only fills m and v
With bias correction, mhat = g and the square root of vhat is |g| on step 1, so the step is lr × g / (|g| + ε) ≈ lr in magnitude, whatever the size of g. That per-weight normalisation is what Adam adds to plain gradient descent, which would have moved the second weight 100,000 times as far as the first.

The trained model's held-out loss is 2.30 nats per character. Roughly how many letters is it hesitating between at each position (e2.30)?

  1. About 27, the vocabulary size
  2. About 10
  3. About 2.3
  4. About 3.3
Perplexity is eloss, and e2.30 = 10.0. Chance is e3.30 = 27, so the model has narrowed 27 equally likely letters to about 10. The loss itself (2.3 or 3.3) is not a count of choices; it is the log of one.

You sample 20 names at temperature 0.01 with 20 different random seeds. What do you expect?

  1. Twenty very different names, because the seeds differ
  2. Twenty random strings of letters
  3. The same name twenty times, the model's single most likely sequence
  4. Empty strings, because the end marker always wins
Dividing the logits by 0.01 multiplies their differences by 100, so the likeliest token has a probability of essentially 1 at every step and the random draw always selects it. The result is greedy decoding, independent of the seed. It is not random; the end marker wins only if the model already finds it likeliest at position 0, which a trained model does not.
