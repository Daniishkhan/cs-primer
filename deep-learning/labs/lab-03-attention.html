Lab 3: Attention & a Transformer Block

Chapters 9 and 10 explained attention and the Transformer block with NumPy arrays and pictures. In this lab you write them with nothing but Python lists, so that every shape is something you can print. You build a numerically safe softmax, layer normalisation and GELU; scaled dot-product attention with a causal mask; multi-head attention; the MLP and the full pre-norm block; and finally a complete tiny GPT forward pass that you check shape by shape. Every milestone is tested against an independent, deliberately plain reference, and against the numbers printed in the chapters.

Why this lab matters

A Transformer is a small number of ideas stacked many times, and nearly every bug in one is a statement about a shape or a mask: a softmax over the wrong axis, a mask applied after the softmax, a layer norm that averages across tokens instead of across features, heads split in the wrong order. These bugs rarely crash. They produce a model that trains, with a slightly worse loss, or one that quietly reads the future during training and fails at generation time. The only reliable defence is the habit this lab drills: write the shape next to every line, and test properties that must hold (rows sum to one, the output has the input's shape, editing the last token changes nothing before it).

The second reason is that this is the model of Lab 4, chapter 12 and, with more layers and a few refinements, of every large language model in the next course. Karpathy's Let's build GPT lecture and nanoGPT follow the same path; this lab keeps their spirit and their notation (B, T, C, h) but replaces arrays with lists so that nothing is hidden behind a library call. The batch dimension B is handled by looping over sequences, which keeps every function about one (T, C) matrix.

Pure Python, seeded, under a second

Python 3.9 or newer and nothing else: no NumPy, no downloads. The sizes are small (a width of 4 to 16, a handful of tokens), so python3 check.py solution finishes in well under a second and prints identical numbers every time. Random property tests print their seed when they fail, and you can replay one with python3 check.py solution 3 5, which means milestone 3, seed 5. The reference checks are written with scalar loops on purpose, in a different style from the solution, so that a mistake cannot hide behind a shared helper.

What you'll build

Five milestones, each building on the last:

  1. Softmax, layer norm and GELU: a stable softmax that treats -inf as "forbidden" and refuses a row where everything is forbidden, a per-token layer norm, and the GELU activation.
  2. Scaled dot-product attention: the causal mask and softmax(Q KT / sqrt(d_k)) V for one head, reproducing the worked example of chapter 9.
  3. Multi-head attention: split the width into h heads, attend in each, merge, project with WO, and check causality and equivalence with a per-head reference.
  4. The MLP and the block: the position-wise feed-forward network and the pre-norm block with its two residual connections.
  5. A whole tiny GPT: embeddings, a stack of blocks, a final norm and an output head; closed-form parameter counts that reproduce GPT-2 small; a shape trace; and the check that an untrained model scores about ln V.

Milestone 1: softmax, layer norm and GELU

Three small functions carry most of the numerical care in a Transformer, and each has a classic way to go wrong. Start with the softmax that turns a row of scores into weights: wj = esj / ∑m esm. As in Lab 1, subtract the row's largest score before exponentiating (A0 chapter 11), so the largest exponent is e0 = 1 and nothing overflows. The new requirement here is masking. The causal mask of chapter 9 sets the scores of forbidden keys to -inf, and your softmax must give them a weight of exactly 0. That falls out of the maths: math.exp(-math.inf) is 0.0 in Python, and the maximum of a row that has at least one finite score is finite. The remaining weights still sum to one, which is why masking the scores works and zeroing the weights afterwards does not.

The edge case is a row in which every score is -inf. The maximum is -inf, the subtraction gives -inf - (-inf) = nan, and a row of NaN silently poisons everything downstream, which then shows up as a loss of nan a thousand steps later. A query with no key it is allowed to read is a bug in whoever built the mask, so the lab asks you to fail loudly: raise ValueError.

Layer normalisation (chapter 3; Ba, Kiros and Hinton, 2016) rescales each token's vector of C numbers to mean 0 and variance 1, then applies a learned per-feature gain and bias: y = (x − μ) / √(σ2 + ε) × g + b, with μ and σ2 computed over the C numbers of that one token. Two details matter. The variance is the population variance (divide by C, not C − 1), as in every framework. And the small ε (1e-5) sits inside the square root to protect against a token whose features are all equal.

Common misconception

"Layer norm normalises over the sequence." It normalises over the features of one token. In a (T, C) matrix it works along each row, and it never mixes tokens. If you normalise down the columns instead, token 3's output depends on token 7, which breaks causality in a way that no mask can repair, because the leak happens before attention. Milestone 4 includes a test that would catch it. (Batch norm, which the chapter 3 comparison contrasts with, does average across examples; that is exactly why Transformers avoid it.)

Last, the GELU activation (Hendrycks and Gimpel, 2016) that the MLP will use. It is a smooth ReLU: z Φ(z) where Φ is the standard normal cumulative distribution. GPT-2 used the cheaper tanh form, which is what you implement: 0.5 z (1 + tanh(√(2/π) (z + 0.044715 z3))). It is close to zero for large negative z, close to z for large positive z, and dips slightly below zero around z = −1.

Solution spoiler 
def softmax_rows(S):
    """Softmax of each row. Subtract the row maximum first; -inf entries must get weight exactly 0.
    A row in which every entry is -inf has no valid answer: raise ValueError."""
    out = []
    for row in S:
        m = max(row)
        if m == -math.inf:
            raise ValueError("a row of all -inf has no softmax (every key was masked)")
        e = [math.exp(s - m) for s in row]        # exp(-inf - m) is 0.0, so masked entries vanish
        z = sum(e)
        out.append([x / z for x in e])
    return out

def layernorm_rows(X, gain, bias, eps=1e-5):
    """Normalise each row over its C numbers: (x - mean) / sqrt(var + eps) * gain + bias.
    The variance is the population variance (divide by C), as in chapter 03."""
    out = []
    for row in X:
        mu = sum(row) / len(row)
        var = sum((x - mu) ** 2 for x in row) / len(row)
        inv = 1.0 / math.sqrt(var + eps)
        out.append([(x - mu) * inv * g + b for x, g, b in zip(row, gain, bias)])
    return out

def gelu(z):
    """GELU, tanh approximation used by GPT-2, for one number."""
    return 0.5 * z * (1.0 + math.tanh(math.sqrt(2.0 / math.pi) * (z + 0.044715 * z ** 3)))

Milestone 2: scaled dot-product attention

Attention for one head is a soft dictionary lookup (chapter 9). Each of the T tokens has a query q, a key k and a value v, all vectors of width dk (the value may differ in width, dv). Token i scores every key by a dot product, turns the scores into weights with a softmax, and returns the weighted average of the values:

Attention(Q, K, V) = softmax( Q KT / √dk ) V

Follow the shapes: Q and K are (T, dk), so Q KT is (T, dk) × (dk, T) = (T, T), one score for every (query, key) pair; the softmax acts along each row; and multiplying the (T, T) weights by V of shape (T, dv) gives an output of shape (T, dv). You will write attention(Q, K, V, mask=None) to return both the output and the weights, because the weights are what you inspect when something looks wrong.

The 1/√dk is not decoration. If the entries of q and k have variance 1, their dot product is a sum of dk terms and has variance dk, so a width-64 head produces scores with standard deviation 8, and a softmax over scores that spread out is nearly one-hot, with almost no gradient (the derivation is in chapter 9). Dividing by √dk brings the spread back to 1 at any width. The check measures this with your own function.

Analogy: a group chat read in order

Picture a group chat where each message is a token. When you write message 5 you may look at messages 1 to 5 and nothing later, because later messages do not exist yet. The causal mask enforces that rule. Your query is the question you are asking of the history, each earlier message advertises a key ("I mention a date", "I am a greeting"), and the value is what you take from it. Because you read all of them at once with different intensities, you end up with a blend, not one message.

Where it breaks down: in a real chat you read once; here all T messages ask their questions in parallel, in one matrix product, and the same weights (the learned projections) are used for every message. The "chat" is also reread in full at every layer.

Common misconception

"I can mask by zeroing the weights after the softmax." The softmax has already shared out probability to the forbidden keys, so after zeroing them the row no longer sums to 1 and the output is shrunk by an amount that depends on how much weight the future would have taken. The model also sees the future through the normaliser during training. The mask goes on the scores, before the softmax; this lab's check fails loudly on the other order. For the same reason, use true -math.inf and not a large negative number such as -1e9: the weight is then exactly 0, and the "all keys masked" case is detectable rather than a silent uniform row.

The chapter 9 worked example makes a good test, because you can verify every number by hand. def causal_mask(T):
    """(T, T) matrix of booleans; True where query i must NOT read key j, i.e. where j > i."""
    return [[j > i for j in range(T)] for i in range(T)]

def attention(Q, K, V, mask=None):
    """softmax(Q K^T / sqrt(d_k)) V for one head. Q, K: (T, d_k), V: (T, d_v).
    mask: optional (T, T) booleans, True = forbidden. Apply it to the scores, BEFORE the softmax.
    Returns (output (T, d_v), weights (T, T))."""
    d_k = len(Q[0])
    scores = [[s / math.sqrt(d_k) for s in row] for row in matmul(Q, transpose(K))]
    if mask is not None:
        scores = [[-math.inf if hidden else s for s, hidden in zip(srow, mrow)]
                  for srow, mrow in zip(scores, mask)]
    weights = softmax_rows(scores)
    return matmul(weights, V), weights

Milestone 3: multi-head attention

One head can only make one kind of lookup per layer: one set of weights saying which tokens matter. Multi-head attention runs h lookups in parallel, each in its own lower-dimensional subspace, and concatenates the results. The trick that keeps the cost the same is to split the width: with C = 64 and h = 4 each head works on dk = C / h = 16 numbers per token. The sequence of shapes for one sequence is:

StepOperationShape
inputx(T, C)
projectQ = x WQ, K = x WK, V = x WV (each W is (C, C))(T, C) each
splithead i takes columns i·dk to (i+1)·dk − 1 of Q, K and V(h, T, dk)
attendscaled dot-product attention in each head (milestone 2)weights (h, T, T), outputs (h, T, dk)
mergeconcatenate the h outputs along the feature axis(T, C)
mixmultiply by WO (C, C), so the heads can combine what they found(T, C)

With a batch, every shape gains a leading B, and because the sequences do not interact, a loop over the batch is all that is needed. The check calls your function once per sequence, and the demo below shows the shapes with apply_batch.

Common misconception

"More heads means more parameters and more compute." With the split above, h heads of width C / h cost exactly the same as one head of width C: WQ, WK, WV and WO are always four (C, C) matrices, whatever h is. What changes is the shape of the computation: h separate (T, T) attention maps instead of one, which is where the memory cost of long contexts comes from (chapter 19). Also note that the split is a reshape of the projected vectors, not h separate projections of x: head 1 is simply the second slice of the columns of Q, K and V.

def split_heads(x, h):
    """(T, C) -> h matrices of shape (T, d_k): head i takes columns i*d_k .. (i+1)*d_k - 1."""
    C = len(x[0])
    if C % h:
        raise ValueError(f"width {C} is not divisible by {h} heads")
    d_k = C // h
    return [[row[i * d_k:(i + 1) * d_k] for row in x] for i in range(h)]

def merge_heads(heads):
    """h matrices of shape (T, d_k) -> (T, h * d_k): the undo of split_heads (concatenate columns)."""
    return [sum((head[t] for head in heads), []) for t in range(len(heads[0]))]

def multi_head_attention(x, Wq, Wk, Wv, Wo, h, causal=True):
    """Multi-head self-attention for one sequence x (T, C). Wq, Wk, Wv, Wo are (C, C).
    Returns (output (T, C), weights): weights is a list of h matrices (T, T)."""
    T = len(x)
    Qh, Kh, Vh = (split_heads(matmul(x, W), h) for W in (Wq, Wk, Wv))
    mask = causal_mask(T) if causal else None
    outs, weights = [], []
    for q, k, v in zip(Qh, Kh, Vh):
        o, w = attention(q, k, v, mask)
        outs.append(o)
        weights.append(w)
    return matmul(merge_heads(outs), Wo), weights

Milestone 4: the MLP and the Transformer block

Attention moves information between tokens; it is almost entirely linear in what it moves. The second half of the block does the nonlinear thinking, one token at a time. The MLP (position-wise feed-forward network) is the two-layer network of Lab 1 applied to every token's vector independently: expand from C to 4C numbers, bend each with GELU, and project back to C:

MLP(x) = GELU( x W1 + b1 ) W2 + b2,   W1: (C, 4C), W2: (4C, C)

Because the matrix product treats the T rows as a batch, the same weights act on every position and no information crosses between them. The check tests this directly: running the MLP on one row alone gives the same answer as running it on the whole matrix.

The pre-norm block wraps both sublayers in a normalisation in front and a residual connection around:

x ← x + MultiHead( LN1(x) ),   then   x ← x + MLP( LN2(x) )

The residual connection is addition, not replacement: each sublayer computes a correction and writes it into the stream (the residual stream of chapter 10). This has a testable consequence that makes a good debugging tool. If you set WO to zero, attention adds nothing; if you set W2 and b2 to zero, the MLP adds nothing; with both zero the block must return its input unchanged. A block that fails that test has the wiring wrong, however good its pieces are. The pre-norm placement has a second test: the normalisation is applied only to the copy that goes into a sublayer, never to the stream, so a stream of large numbers stays large.

Common misconception

"Layer norm goes after the residual addition, as in the original paper." The 2017 Transformer normalised after each addition (post-norm); almost every model since normalises before each sublayer (pre-norm), because gradients then reach the early layers through the unnormalised skip path and deep stacks train without a long warm-up (Xiong et al., 2020, "On Layer Normalization in the Transformer Architecture"; chapter 10). The two differ by moving one line, and a model written one way with weights trained the other way will produce nonsense, so the order is part of a model's definition.

The demo stacks six blocks of random weights with the default 1/√fan-in scale and prints the size of the stream after each. The stream grows slowly, because each block adds its contribution to what is already there (chapter 3 shows the GPT-2 rule of scaling the output matrices by 1/√(2L) to slow that growth; this lab uses the plain scale). It then does the causality test of chapter 10 through all six blocks: add a random vector to the last token and compare every position's output.

def mlp(x, W1, b1, W2, b2):
    """Position-wise MLP: gelu(x W1 + b1) W2 + b2, with shapes (T, C) -> (T, 4C) -> (T, C)."""
    hidden = [[gelu(z) for z in row] for row in add_bias(matmul(x, W1), b1)]
    return add_bias(matmul(hidden, W2), b2)

def block(x, p, h, causal=True):
    """One pre-norm block: x = x + MHA(LN1(x)); x = x + MLP(LN2(x)). (T, C) -> (T, C)."""
    a, _ = multi_head_attention(layernorm_rows(x, p["ln1_g"], p["ln1_b"]),
                                p["Wq"], p["Wk"], p["Wv"], p["Wo"], h, causal)
    x = add(x, a)                                   # write attention's result into the stream
    m = mlp(layernorm_rows(x, p["ln2_g"], p["ln2_b"]), p["W1"], p["b1"], p["W2"], p["b2"])
    return add(x, m)                                # write the MLP's result into the stream

Milestone 5: a whole tiny GPT, shape by shape

Around the block sit three more pieces (chapter 10, "From blocks to a model"): an embedding table of shape (V, C) that turns each token id into a vector; a position table of shape (Tmax, C) that tells the model where each token is (chapter 11 explains the options; this lab uses learned positions as GPT-2 does); and, after the last block, a final layer norm and an output head of shape (C, V) that turns each token's vector into V logits. The forward pass for one sequence of ids is:

  1. Look up tok_emb = the rows of the embedding table for the ids, shape (T, C).
  2. Add the first T rows of the position table: x0, shape (T, C).
  3. Apply each block in turn: block0, block1, …, all (T, C).
  4. Apply the final layer norm: ln_f, (T, C).
  5. Multiply by the head: logits, (T, V). Row t is the model's score for every possible next token after position t.

Your model_forward takes an optional list called trace and appends (name, shape) after each of these steps. The check compares the trace to the one above. It sounds like bookkeeping, and it is the cheapest bug detector in deep learning: a wrong shape shows up on the first run, long before a wrong value does.

Counting parameters. A model's size is the count of numbers in its weights, and for this architecture it has a closed form. One block holds attention (four (C, C) matrices, 4C2), the MLP (W1 has 4C2 weights, b1 has 4C, W2 has 4C2, b2 has C: 8C2 + 5C) and two layer norms (a gain and a bias each: 4C). That is 12C2 + 9C per block, and two thirds of the weights are in the MLP (chapter 10). The whole model adds V·C for the embedding table, Tmax·C for positions, 2C for the final norm and C·V for the head. You write both the closed form and a counter that walks the nested lists, and the check requires them to agree. The script below applies them to the shape of GPT-2 small and then to a tiny model.

def block_param_count(C):
    """Closed form for one block: attention 4C^2, MLP 8C^2 + 5C, two LayerNorms 4C."""
    return 4 * C * C + (2 * C * 4 * C + 4 * C + C) + 4 * C

def model_param_count(V, C, T_max, n_layers):
    """Closed form for the whole model of init_model."""
    return V * C + T_max * C + n_layers * block_param_count(C) + 2 * C + C * V

def count_params(obj):
    """Count the numbers inside nested lists and dicts (what 'parameters' means)."""
    if isinstance(obj, dict):
        return sum(count_params(v) for v in obj.values())
    if isinstance(obj, list):
        return sum(count_params(v) for v in obj)
    return 1

def model_forward(ids, params, h, trace=None):
    """Logits for one sequence of token ids: shape (T, V).

    Steps, in order, each recorded as trace.append((name, shape(value))) when trace is a list:
      'tok_emb' (T, C), 'x0' (T, C) = token + position embeddings, 'block0', 'block1', ... (T, C),
      'ln_f' (T, C), 'logits' (T, V)."""
    T = len(ids)
    if T > len(params["wpe"]):
        raise ValueError(f"sequence of {T} tokens is longer than the {len(params['wpe'])} positions")
    note = (lambda name, val: trace.append((name, shape(val)))) if trace is not None else (lambda *a: None)
    tok = [params["wte"][i] for i in ids]
    note("tok_emb", tok)
    x = [[a + b for a, b in zip(tok[t], params["wpe"][t])] for t in range(T)]
    note("x0", x)
    for i, p in enumerate(params["blocks"]):
        x = block(x, p, h)
        note(f"block{i}", x)
    x = layernorm_rows(x, params["lnf_g"], params["lnf_b"])
    note("ln_f", x)
    logits = matmul(x, params["head"])
    note("logits", logits)
    return logits

def mean_cross_entropy(logits, targets):
    """Mean over positions of -log softmax(logits[t])[targets[t]], in nats."""
    P = softmax_rows(logits)
    return -sum(math.log(P[t][y]) for t, y in enumerate(targets)) / len(targets)

Systems connection

Every line of your attention is a matrix product, the operation a GPU exists to do (Zero to Systems chapter 21). The (T, T) score matrix for each head is the object whose memory grows with the square of the context, and the reason an exact attention kernel that never writes it out (FlashAttention, chapter 19) changed what context lengths are practical. The causal mask also halves the useful work: the upper triangle is computed and thrown away unless a kernel skips it. Your Python version computes everything, which is exactly why the real thing is a hand-tuned kernel.

What you learned

  • Softmax with a causal mask works on the scores, as −∞, before the exponential; the forbidden weights are then exactly 0 and the rest still sum to 1. A row with nothing allowed is a bug and should raise.
  • Scaling the scores by 1/√dk keeps their standard deviation at 1 for any head width; without it a wide head becomes one-hot and learns slowly.
  • Multi-head attention is a reshape: h heads of width C / h cost the same as one head of width C, and the number of (T, T) maps grows with h.
  • A pre-norm block is x + attention(LN(x)) and then x + MLP(LN(x)); zeroing both output matrices must return the input unchanged, and the output shape equals the input shape.
  • Layer norm works per token over the C features; the MLP is position-wise; only attention moves information between tokens, and only the mask decides in which direction.
  • A block has 12C2 + 9C weights here; the formula reproduces GPT-2 small's 124,439,808 once weight tying and the attention biases are accounted for.
  • Shape traces, a causality test and the untrained-loss test (about ln V) catch most Transformer bugs before any training happens.

Check your understanding

A head has dk = 64 and its queries and keys have independent entries of mean 0 and variance 1. Without the 1/√dk factor, what is the standard deviation of a score, and what does it do to the softmax?

  1. 1; nothing, the softmax is already well behaved
  2. 8; it makes the weights almost one-hot and the gradient through the softmax almost zero
  3. 64; it makes the weights nearly uniform
  4. 8; it makes the weights nearly uniform, because large scores cancel
A dot product of 64 unit-variance terms has variance 64 and standard deviation 8. Scores that spread out give a softmax dominated by the largest one: nearly one-hot, with an almost zero Jacobian, so little gradient reaches the rest. Near-uniform weights would need small scores, which is what the division produces, not what its absence produces.

An implementation applies the causal mask by multiplying the softmax output by a 0/1 lower-triangular matrix. For T = 4 and equal scores, what are the row sums of the weights?

  1. All 1, because zeros do not change a sum
  2. All 0, because the future is removed
  3. 1/4, 2/4, 3/4 and 1: the rows no longer sum to 1
  4. 1, 2, 3 and 4
With equal scores the softmax gives 1/4 to every key, and zeroing the future leaves row i with (i + 1)/4. The output is then shrunk by a position-dependent factor. Masking the scores with −∞ before the softmax makes the rows 1, 1/2 + 1/2, and so on, each summing to exactly 1.

A model has C = 64. How do the attention weight matrices WQ, WK, WV, WO change when you go from h = 1 to h = 8 heads (dk from 64 to 8)?

  1. They do not: four (64, 64) matrices either way, so 4C2 = 16,384 weights
  2. Eight times as many weights, since each head has its own matrices
  3. Eight times fewer, since each head is narrower
  4. Only WO changes, to (64, 8)
The heads are slices of the columns of the same projected matrices, so the parameter count is independent of h. What grows with h is the number of (T, T) weight maps. The second option would be true if each head projected from the full width to its own full width, which is not how the split is done.

Using this lab's counting (no attention biases, MLP width 4C, two layer norms with a gain and a bias), how many weights does one block have at C = 64?

  1. 16,640, attention and layer norms only
  2. 25,024, with an MLP of hidden width 2C
  3. 49,152, ignoring all biases and norms
  4. 49,728, which is 12C2 + 9C
Attention is 4 × 642 = 16,384; the MLP is 2 × 64 × 256 + 256 + 64 = 33,088; the layer norms are 4 × 64 = 256. The total is 49,728. The first option leaves out the MLP, the second uses the wrong hidden width, and the third drops the 9C = 576 bias and norm terms.

You edit only the last of eight input tokens, and the logits at position 3 change. Which is the most likely cause?

  1. The mask is applied before the softmax instead of after
  2. The MLP is position-wise, so it mixes the tokens
  3. The layer norm normalises down the columns (across tokens) instead of across the features of each token
  4. The residual connection adds the stream back to itself
Normalising across tokens makes every token's output depend on all the others, a leak that happens before attention and that no mask can undo. Masking before the softmax is the correct order, a position-wise MLP by definition does not mix tokens, and a residual connection is a per-token addition.

Your untrained model, with V = 27, reports a loss of 11.8 on its first batch. What does this most likely indicate?

  1. Nothing: an untrained model can start anywhere
  2. The logits start far too large, for example from badly scaled initial weights, instead of near zero so that the loss is about ln 27 = 3.3
  3. The model has already learned the data
  4. The causal mask has removed too many keys
With small initial weights the softmax is close to uniform and the loss starts near ln V. A loss of 11.8 means confident wrong predictions: the initial weights or the final-layer scale are too big. A model that had learned the data would have a loss below ln V, and a bad mask changes values but does not by itself produce confident wrong guesses.
