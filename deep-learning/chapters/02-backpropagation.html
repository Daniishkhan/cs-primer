Backpropagation Through a Network

Training needs the gradient of the loss with respect to every weight in the network, often billions of them. Backpropagation gets all of them for roughly the price of two extra forward passes. This chapter derives the matrix form layer by layer and runs it on a small example by hand. Then it writes the method in NumPy and checks it against numerical differentiation.

Why this matters

Deep-learning frameworks compute gradients for you (chapter 05), and you will rarely write a backward pass by hand again. But gradients are where training goes wrong, and you cannot debug what you cannot derive. Gradients can explode or vanish (chapter 03). A loss may refuse to move. A NaN (not a number) may appear after ten thousand steps. A model may need more memory than its parameter count suggests. All of these are statements about the backward pass. After this chapter you can write the gradient of any layer from its shapes. You can explain why training costs about three times a forward pass and why activations must be stored. You can also verify a hand-written gradient so that you trust it.

The problem: a million knobs and one number

A network from chapter 01 is a chain of functions. Call the inputs a0 = X. For each layer l, compute zl = al−1Wl + bl and al = f(zl). The last layer's output goes into a loss function, which produces one number L, the average badness over the batch. Training wants ∂L/∂Wl and ∂L/∂bl for every layer. The gradient says which way to nudge each weight to lower L (A0 chapter 10 turns gradients into updates).

You met the key rule in A0 chapter 08: the chain rule. If L depends on z through a, then ∂L/∂z = (∂L/∂a)(∂a/∂z). In chapter 09 you saw reverse-mode automatic differentiation. Record the computation as a graph, then sweep backwards from the output. Each node is passed the gradient of the loss with respect to its output, and it computes the gradients for its inputs. Backpropagation is that algorithm applied to a layered network, with one change that matters in practice. Instead of one scalar at a time, each node is a whole matrix operation. The bookkeeping becomes matrix algebra, and the only real work is getting the shapes right.

Why not differentiate each weight separately?

The obvious alternative is to nudge one weight by a tiny amount, re-run the whole network and see how the loss changes (a finite difference). That costs one forward pass per weight. A network with 100 million weights would need 100 million passes for one gradient. Backpropagation computes all of them together, because the gradient for an early layer reuses the work already done for the later layers. The cost is a single backward sweep, about twice the cost of the forward pass (we count exactly below). We still use the slow finite-difference method, but only as a test on tiny networks.

Notation and shapes

Fix a network with layers l = 1 to L. For layer l, al−1 has shape (B, Cl−1) and Wl has shape (Cl−1, Cl). The bias bl has shape (Cl), and zl and al have shape (B, Cl). We introduce one new object, the upstream gradient or error signal,

δl = ∂L/∂zl,   of shape (B, Cl).

The rule that organises everything: a gradient always has the same shape as the thing it is the gradient of. The gradient of L with respect to Wl has shape (Cl−1, Cl). The gradient with respect to al−1 has shape (B, Cl−1). The same holds for every other tensor. When you are unsure of a formula, the shapes usually force the answer.

Deriving the layer gradients

Suppose a layer has just received δ = ∂L/∂z from the layer above it (the next section shows where the first δ comes from). It must produce three things: the gradient for its weights, for its biases, and the gradient to hand to the layer below. Write the layer elementwise, for example b and j indexing batch row and output neuron:

zbj = ∑i abi Wij + bj

Weights. Wij influences zbj for every example b, with strength abi. That is, the derivative of zbj with respect to Wij is abi. By the chain rule, sum over the batch rows that Wij touches:

Plug in numbers. Two examples, three inputs, two neurons. The script computes one entry by hand, then the whole matrix as aTδ, then checks the entry by nudging the weight.

The idea

  1. a is (2, 3), delta is (2, 2): made-up numbers
  2. one entry: dW[1][1] ← sum over examples of a[b][1] × delta[b][1]
  3. all entries: dW ← transpose(a) times delta, shape (3, 2)
  4. check: nudge W[1][1] and watch L = sum(delta × z) change
"""dW = a^T delta, checked three ways on a batch of two examples."""

# ── 1. The data: B = 2, C_in = 3, C_out = 2 ──────────────────────────────
a = [[1.0, 2.0, 0.5],
     [0.0, -1.0, 2.0]]            # layer input, shape (B, C_in)
delta = [[0.5, -1.0],
         [1.0, 0.25]]             # upstream gradient dL/dz, shape (B, C_out)
B, C_IN, C_OUT = 2, 3, 2

# ── 2. One entry, W[1][1]: one product per example, then the sum over b ──
i, j = 1, 1
parts = [a[b][i] * delta[b][j] for b in range(B)]
print(f"dW[{i}][{j}]: per example {parts}, sum over the batch = {sum(parts)}")

# ── 3. Every entry at once: the sum over b is a matrix product a^T delta ─
a_T = [[a[b][i] for b in range(B)] for i in range(C_IN)]   # (C_IN, B)
dW = [[sum(a_T[i][b] * delta[b][j] for b in range(B))
       for j in range(C_OUT)] for i in range(C_IN)]        # (C_IN, C_OUT)
print(f"a^T is {(C_IN, B)}, delta is {(B, C_OUT)}, dW is {(C_IN, C_OUT)}")
for row in dW:
    print("  ", row)

# ── 4. Check: let L = sum(delta * z), so that dL/dz is exactly delta ─────
W = [[0.4, -0.5], [0.3, 0.2], [-0.2, 0.6]]
EPS = 1e-6                        # size of the nudge to one weight


def loss(W):
    z = [[sum(a[b][k] * W[k][c] for k in range(C_IN)) for c in range(C_OUT)]
         for b in range(B)]
    return sum(delta[b][c] * z[b][c] for b in range(B) for c in range(C_OUT))

Biases. bj is added to zbj for every example with strength 1. So ∂L/∂bj = ∑b δbj, that is, db = sum of δ over the batch rows, shape (Cout). This is the broadcast of the forward pass, undone. A quantity that was copied across the batch in the forward pass is summed across it in the backward pass.

Inputs to the layer. abi influences zbj for every output neuron j, with strength Wij:

∂L/∂abi = ∑j δbj Wij   ⇒   da = δ WT   with shapes (B, Cout)(Cout, Cin) = (B, Cin).

Through the activation. The activation acts on each element on its own: abi = f(zbi), so ∂L/∂zbi = ∂L/∂abi · f′(zbi). In matrix terms δ = da ⊙ f′(z), an elementwise product (⊙). This is where the slope of the activation from chapter 01 enters. For ReLU the factor is 1 where z > 0 and 0 elsewhere, so the gradient passes through unchanged or is blocked.

Go deeper optional: why the sums look the way they do

A reliable way to avoid slips is to ask, for each variable, "which outputs does it touch, and with what coefficient?" and then sum the contributions. Wij is used once for each example b, always in the output neuron j, with coefficient abi. So the sum runs over b. abi is used only inside example b, but in every output neuron j, with coefficient Wij. So the sum runs over j. The two results are exactly the matrix products aTδ and δWT, because the matrix product (PQ)xy = ∑k PxkQky sums over the shared index. If you ever mistrust a formula, write it out for a 2×2 case and compare with the transposes.

Another check is dimensional. Both a and δ have B rows, and B must disappear from dW, because the weights do not depend on the batch size. The only way to combine them is to contract over B, which is aTδ.

Collecting the four lines gives the whole backward recipe for layer l, using the cached forward values al−1 and zl:

  1. Receive δl = ∂L/∂zl, shape (B, Cl).
  2. dWl = al−1T δl and dbl = ∑batch δl.
  3. dal−1 = δl WlT.
  4. δl−1 = dal−1 ⊙ f′(zl−1), then repeat for layer l−1.

What the matrices are really doing: vector-Jacobian products

A layer maps a vector of Cin numbers to Cout numbers. Its derivative is therefore a whole matrix of partial derivatives, the Jacobian J with entries ∂zj/∂ai. For a linear layer J is just W. Backpropagation does not need J itself. It needs the product of the incoming gradient row with J, written δJ (here δWT). This is a vector-Jacobian product. For an elementwise activation J is a diagonal matrix with f′(z) on the diagonal. That is why the product collapses to the elementwise multiplication ⊙ and never needs a C×C matrix. This matters for cost. The Jacobian of an operation on a million numbers has a trillion entries. The vector-Jacobian product needs only a million. Reverse-mode autodiff is a sequence of vector-Jacobian products, one per operation. This is how PyTorch's backward() works. Every operation in the library defines its own vector-Jacobian product (chapter 05).

When a value is used twice, gradients add

The recipe above assumed a chain. Real networks branch: one tensor feeds two operations. The multivariable chain rule says that the gradient arriving at a branching point is the sum of the gradients returned along each branch. A minimal example is y = x + g(x), where g is any layer. Then ∂L/∂x = ∂L/∂y · 1 (the direct path) + ∂L/∂y · g′(x) (the path through g). The direct path passes the gradient through untouched. This is the arithmetic behind the skip connections of chapter 03 and the residual stream of the Transformer (chapter 10). A skip gives every gradient an unobstructed route back to early layers, however badly the layers on the other path behave. Frameworks handle this automatically by accumulating into each tensor's gradient. That is also why you must zero gradients between steps: new contributions are added to old ones.

How to gradient-check properly

  1. Use a tiny network and a tiny batch (a handful of examples), in float64.
  2. Use a centred difference, (L(w + ε) − L(w − ε)) / 2ε, with ε around 10−6. One-sided differences are far less accurate.
  3. Compare with the relative error |gnum − gbp| / (|gnum| + |gbp|), not the absolute error, because gradients can be tiny.
  4. Turn off anything random (dropout, data shuffling). Avoid points where the function has a corner, such as a pre-activation within ε of zero in a ReLU, where the finite difference straddles the kink.
  5. Check every parameter tensor, not only the last layer: the bug is often in an earlier one.

Where the first δ comes from: softmax and cross-entropy

The recipe needs a starting point: δ for the last layer, which comes from the loss. For classification the last layer produces logits z, with shape (B, K). Softmax gives probabilities pk = ezk/S with S = ∑j ezj. The loss for one example whose true class is y is the cross-entropy L = −ln py (A0 chapter 13). Expand it: L = −zy + ln S. Differentiate with respect to logit zk:

∂L/∂zk = −1[k = y] + ezk/S = pk − 1[k = y].

The gradient on the logits is simply the predicted probabilities minus the one-hot truth. If the model puts probability 0.659 on the true class, the gradient on that logit is 0.659 − 1 = −0.341: raise this logit. For every wrong class it is the positive probability: lower those. Averaging over B examples divides by B. This tidy form is why frameworks provide softmax and cross-entropy as one fused function; it is also numerically safer than differentiating through a separately computed softmax. For a regression with squared error L = ½(ŷ − t)², the starting gradient is ŷ − t, the same shape.

A worked example, step by step

Return to the tiny network of chapter 01: x = (1, 2), W1 = [[0.5, −1.0], [0.25, 0.25]], ReLU, W2 = (0.6, −0.4)T, target 1. The forward pass gave z1 = (1.0, −0.5), a1 = (1.0, 0), ŷ = 0.6 and L = 0.08. Now run it backwards. The animation shows each step. The script below it prints the same numbers.

Step through

Backward pass and one update

  1. Start from the cached forward pass. The forward pass stored z1 = (1.0, −0.5) and a1 = (1.0, 0). Without them the backward pass could not compute f′(z) or aTδ.
  2. Gradient at the output. For squared error, ∂L/∂ŷ = ŷ − t = 0.6 − 1 = −0.4. The negative sign says: increasing the output would reduce the loss.
  3. Output weights. dW2 = a1T·(−0.4) = (−0.4, 0). Only unit 1 was active, so only its output weight has a gradient. Subtracting the gradient will raise W2[0].
  4. Back into the hidden layer. da1 = (−0.4)·W2T = (−0.24, 0.16). Unit 1 should output more (negative gradient), unit 2 less, since its output weight is negative.
  5. Through the ReLU. Unit 2's pre-activation was −0.5, so f′(z) = 0 and its gradient is blocked: dz1 = (−0.24, 0). A unit that was clipped for this example learns nothing from it.
  6. First-layer weights. dW1 = xTdz1 = [[−0.24, 0], [−0.48, 0]]: the input x2 = 2 is twice as large as x1, so its weight's gradient is twice as large. The second column is zero because unit 2 was blocked.
  7. Update. W ← W − 0.25·dW gives W2 = (0.7, −0.4) and W1 = [[0.56, −1.0], [0.37, 0.25]]. The new output is 0.91 and the loss has fallen from 0.08 to 0.004.
import numpy as np
x = np.array([[1.0, 2.0]])                       # (1, 2)
W1 = np.array([[0.5, -1.0], [0.25, 0.25]])       # (2, 2)
W2 = np.array([[0.6], [-0.4]])                   # (2, 1)
t = 1.0
z1 = x @ W1; a1 = np.maximum(0, z1); yh = a1 @ W2
L = 0.5 * (yh - t) ** 2
dy = yh - t; dW2 = a1.T @ dy; da1 = dy @ W2.T; dz1 = da1 * (z1 > 0); dW1 = x.T @ dz1
print("z1", z1, "a1", a1, "yhat", yh, "L", L)
print("dy", dy, "dW2", dW2.ravel(), "da1", da1, "dz1", dz1)
print("dW1", dW1.tolist())
lr = 0.25
W1n, W2n = W1 - lr * dW1, W2 - lr * dW2
yn = np.maximum(0, x @ W1n) @ W2n
print("new W1", W1n.tolist(), "new W2", W2n.ravel(), "yhat", yn, "L", 0.5 * (yn - t) ** 2)

A full network in NumPy, checked

The next script does everything for a two-layer network with a tanh hidden layer and softmax cross-entropy, on a batch of 4 examples with 3 inputs, 5 hidden units and 2 classes. It computes the loss and runs the four-line recipe. Then it verifies each gradient against a centred finite difference: nudge each weight by ±10−6 and see how the loss changes. This gradient check is the standard way to trust hand-written backward code.

import numpy as np
rng = np.random.default_rng(0)
B, Cin, H, K = 4, 3, 5, 2
X = rng.normal(size=(B, Cin)); y = np.array([0, 1, 1, 0])
W1 = rng.normal(size=(Cin, H)) * 0.5; b1 = np.zeros(H)
W2 = rng.normal(size=(H, K)) * 0.5;   b2 = np.zeros(K)

def forward(W1, b1, W2, b2):
    z1 = X @ W1 + b1                 # (B, H)
    a1 = np.tanh(z1)                 # (B, H)
    z2 = a1 @ W2 + b2                # (B, K) logits
    z2s = z2 - z2.max(1, keepdims=True)
    p = np.exp(z2s) / np.exp(z2s).sum(1, keepdims=True)
    loss = -np.log(p[np.arange(B), y]).mean()
    return loss, (z1, a1, p)

loss, (z1, a1, p) = forward(W1, b1, W2, b2)
dz2 = p.copy(); dz2[np.arange(B), y] -= 1; dz2 /= B   # (B, K)
dW2 = a1.T @ dz2                                       # (H, K)
db2 = dz2.sum(0)                                       # (K,)
da1 = dz2 @ W2.T                                       # (B, H)
dz1 = da1 * (1 - a1**2)                                # (B, H)
dW1 = X.T @ dz1                                        # (Cin, H)
db1 = dz1.sum(0)
print("loss", round(float(loss), 4))
for name, g in [("dW2", dW2), ("da1", da1), ("dW1", dW1)]:
    print(name, g.shape)

def numgrad(param_idx, arr, eps=1e-6):
    g = np.zeros_like(arr)
    for i in np.ndindex(*arr.shape):
        old = arr[i]
        arr[i] = old + eps; lp, _ = forward(W1, b1, W2, b2)
        arr[i] = old - eps; lm, _ = forward(W1, b1, W2, b2)
        arr[i] = old
        g[i] = (lp - lm) / (2 * eps)
    return g
for name, arr, g in [("W1", W1, dW1), ("b1", b1, db1), ("W2", W2, dW2), ("b2", b2, db2)]:
    ng = numgrad(0, arr)
    rel = np.abs(ng - g).max() / (np.abs(ng).max() + np.abs(g).max())
    print(f"{name}: max relative error {rel:.2e}")

Read the shapes: dW2 is (5, 2) like W2 and dW1 is (3, 5) like W1. The relative errors are around 10−9 to 10−10, which is as good as finite differences get in double precision. As a rule of thumb, with float64 an error below about 10−6 means the gradient is right. An error of 10−4 to 10−2 usually means a real bug. An error near 1 means a gross one, such as a missing transpose or a wrong sign. Check in float64, not float32, otherwise rounding noise masks the signal.

Common misconception

"Backpropagation is the learning algorithm." Backpropagation only computes gradients; it makes no change to any weight. Learning is the optimiser, such as stochastic gradient descent (SGD) or AdamW, using those gradients. The two are separable. You can compute gradients by backpropagation and then feed them to any optimiser. Or you can compute them another way (finite differences, forward-mode autodiff) and still train. Backpropagation is also not a claim about the brain. It is an efficient bookkeeping method for the chain rule.

Putting it in a loop

Training repeats three steps: forward, backward, update. Here is a three-layer ReLU network (2 → 32 → 32 → 2) learning to separate two interleaved spirals, a problem a single neuron or any linear model cannot solve. It uses He-scaled starting weights (chapter 03 explains the scale). It trains with plain gradient descent at learning rate 0.1 on all 200 points per step. The backward recipe is written out once per layer.

import numpy as np
rng = np.random.default_rng(0)
# two interleaved spirals, 100 points each
n = 100
t = np.linspace(0.2, 3.5, n)
def arm(phase):
    r = t
    return np.c_[r*np.cos(t*1.6+phase), r*np.sin(t*1.6+phase)] + rng.normal(size=(n, 2))*0.1
X = np.vstack([arm(0), arm(np.pi)]); y = np.r_[np.zeros(n, int), np.ones(n, int)]
X = X / 3.0
H = 32
W1 = rng.normal(size=(2, H)) * np.sqrt(2/2); b1 = np.zeros(H)
W2 = rng.normal(size=(H, H)) * np.sqrt(2/H); b2 = np.zeros(H)
W3 = rng.normal(size=(H, 2)) * np.sqrt(1/H); b3 = np.zeros(2)
lr, B = 0.1, len(X)
for step in range(2001):
    z1 = X @ W1 + b1; a1 = np.maximum(0, z1)
    z2 = a1 @ W2 + b2; a2 = np.maximum(0, z2)
    z3 = a2 @ W3 + b3
    e = np.exp(z3 - z3.max(1, keepdims=True)); p = e / e.sum(1, keepdims=True)
    loss = -np.log(p[np.arange(B), y]).mean()
    acc = (p.argmax(1) == y).mean()
    if step % 400 == 0: print(f"step {step:>4}  loss {loss:.4f}  acc {acc:.3f}")
    d3 = p.copy(); d3[np.arange(B), y] -= 1; d3 /= B
    dW3 = a2.T @ d3; db3 = d3.sum(0)
    d2 = (d3 @ W3.T) * (z2 > 0); dW2 = a1.T @ d2; db2 = d2.sum(0)
    d1 = (d2 @ W2.T) * (z1 > 0); dW1 = X.T @ d1; db1 = d1.sum(0)
    for P, G in [(W1, dW1), (b1, db1), (W2, dW2), (b2, db2), (W3, dW3), (b3, db3)]:
        P -= lr * G

What backpropagation costs

Count the floating-point operations for one linear layer with batch B, Cin inputs and Cout outputs. The forward product aW does B×Cin×Cout multiply-adds, or 2×B×Cin×Cout floating-point operations (FLOPs). The backward pass does two products of the same size: aTδ for dW and δWT for da. So backward is about twice the forward cost, and a training step is about 3× a forward pass. For the 784→128 layer with a batch of 32, the forward multiply is 2×32×784×128 = 6,422,528 FLOPs. The whole step for that layer is about 19 million. Chapter 16 turns this observation into the "6ND" rule for whole models: 2 FLOPs per parameter per token forward, and 4 backward.

The other cost is memory. The recipe needs al−1 and zl for every layer. They are produced early in the forward pass but used late in the backward pass, so they must be kept in between. That store of activations grows with batch size, sequence length and depth. For large models it, not the weights, is often what exhausts a GPU. Reducing it is a major engineering topic. Activation checkpointing keeps only some activations and recomputes the rest during the backward pass. It trades about one extra forward pass for much less memory.

A small calculation shows how quickly this grows. Take 32 linear layers of width 4096 in 32-bit floats (4 bytes per number). The weights are fixed in size. The cached tensors (z and a for each layer) scale with the number of rows pushed through. For a sequence model that is the batch size times the sequence length.

# Memory a training step must hold for a stack of 32 linear+ReLU layers of width 4096 (float32)
L, C, bytes_per = 32, 4096, 4
weights = L * C * C * bytes_per
for rows in (64, 64 * 2048):                  # rows = B for an MLP, B x T for a sequence model
    acts = L * 2 * rows * C * bytes_per        # cache z and a for every layer
    print(f"rows {rows:>7}: weights {weights / 2**30:5.1f} GiB, cached activations {acts / 2**30:6.1f} GiB")
rows      64: weights   2.0 GiB, cached activations    0.1 GiB
rows  131072: weights   2.0 GiB, cached activations  128.0 GiB

With 64 rows the cached activations are 64 MiB (printed as 0.1 GiB), small next to the 2 GiB of weights. With 64 sequences of 2,048 tokens there are 131,072 rows. The cache is 2,048 times larger, 128 GiB, and the weights are the small part. Real Transformers cache more tensors per block than this toy, so the same effect appears sooner. This is why sequence length is such an expensive knob in training. It is also why chapter 16 and A3 chapter 02 treat activation memory as its own line in the budget.

Analogy: passing back the bill

Imagine a factory line in which a customer returns the final product with a complaint: "too expensive by 40 pence". The last station asks how much it contributed to that. It tells the station before it how much of the blame is passed on, scaled by how much that station's output mattered. Each station repeats the question to the one before it. Each ends up with a number that says "reduce my cost by this much". One sweep from the customer back to the first station gives every station its number.

Where it breaks down: in a factory, blame is a fixed share of one cost. In a network, every layer's gradient depends on the current values everywhere else. The numbers are only valid at this exact setting of the weights. After one small step they must be recomputed.

What goes wrong

  • Shape bugs that broadcast silently. If you accidentally compute a gradient of shape (B, 1) where (1, B) was intended, NumPy may still broadcast it to something plausible. Assert shapes: assert dW.shape == W.shape.
  • Forgetting the 1/B. If the loss is a mean over the batch, the starting gradient is divided by B. Omit it and every gradient is B times too large. Your gradient check will be off by exactly a factor of B, and training behaves as if the learning rate were B times larger.
  • Forgetting to sum the bias gradient over the batch, leaving a (B, C) array where a (C) vector is needed.
  • Stale caches. Reusing an activation from a previous step, or modifying a cached array in place, gives gradients for a function you did not run.
  • Accumulating gradients unintentionally. Frameworks add new gradients into the existing ones; you must clear them each step (chapter 05).
  • Numerical overflow. Differentiating a separately computed softmax and log can produce NaN from 0 times infinity. Use the fused p − y form.

Systems connection

A backward pass is two matrix multiplications per forward one. That is why the compute is 2× and why the same GPU kernels serve both directions. Cached activations make training memory-hungry. A3 chapter 02 accounts for weights, gradients, optimiser state and activations together. Chapter 16 does the arithmetic for a Transformer. Profiling a training step with the methods of chapter 22 shows how time splits between forward, backward and the optimiser.

Key takeaways

  • Backpropagation is reverse-mode autodiff on a layered network: one backward sweep gives every gradient for about twice the cost of the forward pass.
  • For z = aW + b: dW = aTδ, db = sum of δ over the batch, and da = δWT. Through an activation, multiply elementwise by f′(z). A gradient always has the shape of the thing it differentiates.
  • For softmax with cross-entropy the gradient on the logits is the probabilities minus the one-hot truth, divided by the batch size.
  • The forward pass must cache the activations that the backward pass needs; this is why training uses far more memory than inference.
  • Always verify a hand-written backward pass with a finite-difference gradient check in float64.

Check your understanding

A layer has input a of shape (B, C_in), weights W of shape (C_in, C_out), and receives δ of shape (B, C_out). Which expression gives the weight gradient, and what shape does it have?

  1. δTa, shape (C_out, C_in)
  2. aTδ, shape (C_in, C_out)
  3. δWT, shape (B, C_in)
  4. aδ, shape (B, B)
The weight gradient must have the shape of W, and the batch dimension must be summed away, which is aTδ. The third option is the gradient with respect to the input a, a different quantity. The first has the transposed shape and would not subtract from W.

For one example, softmax outputs (0.659, 0.242, 0.099) and the true class is class 0. What is the gradient of the cross-entropy loss with respect to the three logits?

  1. (0.659, 0.242, 0.099)
  2. (0.341, −0.242, −0.099)
  3. (−0.417, 0, 0)
  4. (−0.341, 0.242, 0.099)
The gradient is p minus the one-hot vector: (0.659 − 1, 0.242, 0.099). The second option has the signs reversed, which would increase the loss. 0.417 is the loss value itself, not a gradient.

Why does a training step use much more memory than a forward pass used only for prediction?

  1. The backward pass needs the forward activations, so they are kept until the backward sweep reaches them
  2. Gradients of the loss are larger numbers than activations
  3. The backward pass copies the training data once per layer
  4. The optimiser doubles every weight each step
dW = aTδ and f′(z) need the stored a and z. In inference each activation can be freed as soon as the next layer has used it. The optimiser does add memory (its state, see A3), but it does not copy weights every step, and data are not duplicated per layer.

A ReLU hidden unit has a negative pre-activation for a training example. What gradient flows to that unit's incoming weights from this example?

  1. A small positive value that grows during training
  2. The same as for an active unit but with the opposite sign
  3. Zero, because f′(z) = 0 blocks the error signal
  4. It cannot be known without running a finite-difference check
δ = da ⊙ f′(z), and f′(z) is 0 for z < 0. A unit that is "off" for an example gets no update from it. If it is off for every example it never recovers (chapter 01).

You forget to divide the loss gradient by the batch size B (the loss is a batch mean). What is the most likely symptom?

  1. A shape error when the gradients are subtracted from the weights
  2. Every gradient is B times too large, so a finite-difference check is off by a factor of B and training behaves as if the learning rate were B times bigger
  3. Only the bias gradients are wrong
  4. Nothing; the mean cancels out later
The scale factor propagates linearly through every layer, so all gradients scale together. Shapes are unaffected, so no error is raised, which is why this bug is silent. It is not cancelled anywhere, because there is no later division.

Roughly how does the compute of one training step (forward, backward) compare with a forward pass alone for a stack of linear layers?

  1. About the same
  2. About 2 times as much
  3. About 10 times as much, because each weight needs a finite-difference estimate
  4. About 3 times as much: one forward product plus two backward products per layer
Each layer does aW forward, and aTδ and δWT backward, all of the same size, so the step costs three units against one. 2× is the cost of the backward pass alone, the tempting wrong answer. Finite differences are far costlier and are not used for training.
