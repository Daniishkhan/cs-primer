Neurons, Layers & Activations

A neural network is built from one tiny part repeated many times: a weighted sum followed by a bend. This chapter builds that part and stacks it into layers. It shows why the bend is the only thing that stops the whole stack collapsing into a single line. It also explains what depth buys that width alone does not.

Why this matters

Every model in this path, from a spam filter to a large language model, is made of these parts. The Transformer's feed-forward sublayer (chapter 10) is exactly the two-layer network you will build here. About two thirds of a typical Transformer's parameters live in such layers. Suppose you can write the shape of every tensor in a layer, count its parameters and say what its activation does to the gradient. Then you can read an architecture diagram as a specification instead of a picture. After this chapter you will be able to do four things. You will implement a layer in NumPy. You will explain why a non-linearity is necessary. You will choose between the standard bends (the classic sigmoid and tanh, and the newer ones that replaced them) with reasons. You will also see why a deep narrow network can do what a shallow wide one cannot do economically.

One neuron: a weighted vote

Start with a decision. Should a bank flag a card payment? Three signals arrive as numbers. The first is the amount relative to the customer's usual spend (2.0, twice as much). The second is how unusual the shop is (−1.0, a familiar one). The third is how recently the card was used abroad (0.5). Some signals should count more than others, and some push towards "flag" while others push away. The simplest rule that captures this multiplies each signal by an importance and adds up the results.

That rule is a neuron (also called a unit). It takes n input numbers x1 to xn. It multiplies each by a weight wi, which says how much that input matters and in which direction. It adds a constant called the bias b, which sets the baseline. The result is a single number, the pre-activation:

z = w1x1 + w2x2 + … + wnxn + b = w · x + b

The last form is a dot product, the operation from A0 chapter 05. The neuron then passes z through an activation function f to give its output a = f(z). The activation is what makes a neuron different from a plain linear model; the next sections show why it must be there.

With weights (0.4, 0.3, −0.2) and bias 0.1, the three signals above give this:

z = 0.4×2.0 + 0.3×(−1.0) + (−0.2)×0.5 + 0.1 = 0.8 − 0.3 − 0.1 + 0.1 = 0.5.

Check it by running it:

import numpy as np

x = np.array([2.0, -1.0, 0.5])      # three input features
w = np.array([0.4, 0.3, -0.2])      # one weight per input
b = 0.1                              # bias
z = w @ x + b                        # weighted sum plus bias
print("z =", round(float(z), 3))
print("relu(z) =", max(0.0, round(float(z), 3)))
print("sigmoid(z) =", round(float(1 / (1 + np.exp(-z))), 4))

# a layer: B=2 examples, 3 inputs, 4 neurons
rng = np.random.default_rng(0)
X = rng.normal(size=(2, 3))          # (B, C_in)
W = rng.normal(size=(3, 4)) * 0.5    # (C_in, C_out)
b = np.zeros(4)                      # (C_out,)
H = np.maximum(0, X @ W + b)         # (B, C_out), broadcasting adds b to each row
print("X", X.shape, "W", W.shape, "H", H.shape)
print(np.round(H, 3))

The first three lines are the single neuron. Here z = 0.5. A ReLU activation leaves it at 0.5. A sigmoid squeezes it to 0.6225, which you could read as a probability of "flag". The remaining lines are a whole layer, which we come to shortly.

The geometry: a neuron draws a line

With two inputs, the set of points where z = 0 is a straight line. The weight vector (w1, w2) points at right angles to that line, towards the side where z is positive. The bias slides the line towards or away from the origin. In three inputs it is a plane, and in n dimensions a hyperplane. A single neuron with a step or sigmoid activation is therefore a linear classifier, the logistic regression of A1 chapter 05. Try it below: drag the weights and see the line move and the output change across the plane.

What to notice. With no activation, the output is a smooth slope across the whole plane. With ReLU, one half of the plane is flat at zero and the other half is the slope. The neuron is "off" on one side of the line. With sigmoid or tanh, the output changes quickly near the line and flattens far from it. Making the weights larger makes the transition sharper without moving the line; changing the bias moves the line without changing its direction.

A layer: many neurons side by side

One neuron gives one number. To get a richer description, use several neurons that look at the same inputs with different weights. That set is a layer. If the layer has Cin inputs and Cout neurons, its weights fit in a matrix W of shape (Cin, Cout), where column j holds neuron j's weights. Its biases fit in a vector b of shape (Cout). For a batch of B examples stacked as the rows of X, shape (B, Cin), the whole layer is one matrix multiplication:

Plug in numbers. Two examples with three features each go through a layer of two neurons with a ReLU. Each printed line is one step above, with its shape.

The idea

  1. X is (2, 3), W is (3, 2), b is (2,): made-up numbers
  2. XW ← for every example and neuron, a dot product of a row with a column
  3. XW + b ← add b to every row
  4. H ← ReLU of every entry: negatives become 0
"""One dense layer, H = f(XW + b), on a batch of two examples.
Every step prints its result and its shape."""

# ── 1. The data: B = 2 examples, C_in = 3 features, C_out = 2 neurons ────
X = [[1.0, 2.0, 0.5],
     [0.0, -1.0, 2.0]]            # inputs, one example per row
W = [[0.4, -0.5],
     [0.3, 0.2],
     [-0.2, 0.6]]                 # weights, one neuron per column
b = [0.1, -0.3]                   # one bias per neuron


def shape(m):
    """(rows, columns) of a list-of-lists matrix."""
    return (len(m), len(m[0]))


def show(name, m):
    print(f"{name:<8}{shape(m)}  {[[round(v, 2) for v in r] for r in m]}")


# ── 2. XW: each neuron takes a dot product with each example ─────────────
XW = [[sum(x * W[i][j] for i, x in enumerate(row))
       for j in range(len(W[0]))] for row in X]
show("XW", XW)

# ── 3. XW + b: the bias vector is added to every row (broadcast) ─────────
Z = [[v + b[j] for j, v in enumerate(row)] for row in XW]
show("XW + b", Z)

# ── 4. f(...): ReLU acts on each element on its own ──────────────────────
H = [[max(0.0, v) for v in row] for row in Z]
show("H", H)
XW      (2, 2)  [[0.9, 0.2], [-0.7, 1.0]]
XW + b  (2, 2)  [[1.0, -0.1], [-0.6, 0.7]]
H       (2, 2)  [[1.0, 0.0], [0.0, 0.7]]

The addition of b uses the broadcasting rule from A0 chapter 02: the vector is added to every row. This single formula, a matrix multiply, a broadcast add and an elementwise function, is the most executed line of code in the world's data centres. It is also why GPUs matter: a matrix multiply is exactly the regular, parallel work they are built for.

The second half of the script above ran one layer with B = 2 examples, Cin = 3 and Cout = 4. The shape line confirms the contract: (2, 3) times (3, 4) gives (2, 4). Most of the first example's four outputs are zero because ReLU clipped their negative pre-activations; keep that in mind for the "dead unit" discussion below.

Weights as templates

Here is a way to read a weight column that makes later chapters easier. The dot product w · x is large and positive when x points in the same direction as w. It is near zero when they are unrelated, and negative when they oppose. Cosine similarity in A0 chapter 05 is the same quantity with the lengths divided out. So each neuron is a template for an input pattern, and its pre-activation measures how well the input matches the template. In the first layer of an image network a template is a small picture that you can display. Many look like edges or colour patches. In a language model, the embedding and attention layers are doing exactly this kind of matching between vectors. A layer of 128 neurons is 128 templates compared against the input at once, and the activation keeps the strong matches.

Counting parameters

A layer has Cin×Cout weights and Cout biases, so Cin×Cout + Cout parameters. A network for 28×28-pixel images flattened to 784 numbers, with a hidden layer of 128 units and 10 output classes, has

(784×128 + 128) + (128×10 + 10) = 100,480 + 1,290 = 101,770 parameters.

Notice where the parameters are: almost all of them in the first layer, because its input is wide. When we reach Transformers the same arithmetic gives the headline figures on model cards, and chapter 16 does it exactly. The diagram shows this small network with its shapes.

Why the bend is essential

Suppose we stack two layers but leave out the activation. The first computes XW1 + b1. The second multiplies that by W2 and adds b2. Multiplying out gives (XW1 + b1)W2 + b2 = X(W1W2) + (b1W2 + b2). That is a single linear layer with weights W1W2 and bias b1W2 + b2. No matter how many such layers you stack, the result is one linear map. The extra parameters buy no extra expressive power. The script confirms this numerically, and then shows a hand-built network that does something no linear map can.

import numpy as np
rng = np.random.default_rng(1)
X = rng.normal(size=(5, 3))
W1, b1 = rng.normal(size=(3, 4)), rng.normal(size=4)
W2, b2 = rng.normal(size=(4, 2)), rng.normal(size=2)
two = (X @ W1 + b1) @ W2 + b2            # two linear layers, no activation
W, b = W1 @ W2, b1 @ W2 + b2             # one equivalent layer
print("two linear layers == one:", np.allclose(two, X @ W + b))
print("max difference:", float(np.abs(two - (X @ W + b)).max()))

# XOR: hidden ReLU layer, weights chosen by hand
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], float)
W1 = np.array([[1, 1], [1, 1]], float); b1 = np.array([0, -1.0])
W2 = np.array([[1], [-2]], float)
h = np.maximum(0, X @ W1 + b1)
print("hidden:\n", h)
print("output:", (h @ W2).ravel())

The first two lines show that two linear layers equal one, to within floating-point rounding (1.8×10−15, see A0 chapter 11). The rest computes XOR ("exclusive or": output 1 when exactly one of the two inputs is 1). No single neuron can compute XOR, because no straight line separates {(0,1), (1,0)} from {(0,0), (1,1)}. Minsky and Papert made this point in Perceptrons (1969). It was one reason interest in neural networks faded for years. A hidden layer of two ReLU units fixes it. The first unit computes x1 + x2. The second computes max(0, x1 + x2 − 1), which is non-zero only for input (1,1). The output layer then takes the first minus twice the second: 0, 1, 1 and 2 − 2 = 0. The hidden layer has re-described the four points so that a straight line does separate them. That is the pattern to remember: layers change the representation until the final, linear layer can finish the job.

Activation functions

An activation function is applied to each number of the pre-activation on its own (elementwise), so it never changes the shape. Four matter in this course. Each has a formula and a derivative. Backpropagation (chapter 02) multiplies gradients by f′(z) at every layer. So the slope of the activation controls how well learning signals travel.

Each cell shows the value and then the slope, measured numerically. Look at z = 4. The sigmoid and tanh slopes are 0.018 and 0.001, so a gradient passing through that unit is multiplied by almost nothing. This is called saturation. ReLU and GELU have slope 1 there. At z = 0 the ReLU slope reads 0.500 only because the numerical estimate straddles the corner. In a framework the convention is a slope of 0.

The trade-offs

  • Sigmoid and tanh saturate. Stacked in a deep network, their small slopes multiply and the gradient for early layers shrinks towards zero. Chapter 03 measures this: through thirty sigmoid layers the gradient fell by a factor of about 4×1018. Sigmoid survives as the output of a binary classifier and inside gates.
  • ReLU is cheap and does not saturate on the positive side, which is much of why networks like AlexNet trained faster (Krizhevsky et al., 2012). Its flaw is the flat negative side. A unit whose pre-activation is negative for every training example has slope zero everywhere. It receives no gradient, so it never changes again. This is a dead unit. A learning rate that is too large, or a bad initialisation, can kill many at once.
  • The Gaussian error linear unit (GELU) is a smooth ReLU. Hendrycks and Gimpel ("Gaussian Error Linear Units", 2016) weight the input by the probability that a standard normal variable is below it. Near zero it is gently curved, with a small dip below zero, instead of having a corner. It became the default in the original GPT (generative pre-trained transformer) and in BERT (bidirectional encoder representations from Transformers) style models.
  • Gated variants. Shazeer ("GLU Variants Improve Transformer", 2020) tested gated linear unit (GLU) activations of the form (f(XW) ⊙ XV), where a second linear projection gates the first elementwise. With f = SiLU (z times sigmoid of z) this is called SwiGLU. The cost is a third weight matrix per feed-forward layer, which designers offset by shrinking the hidden width.

State of play, October 2026

Published recipes for large open-weight language models since PaLM (2022) and LLaMA (2023) have mostly used SwiGLU-style gated feed-forward layers rather than a plain GELU. Both are still in use, and the differences in quality are small. Which one a new model uses changes with fashion and is rarely the decisive design choice; check the model's technical report rather than assuming. The mathematics in this chapter does not change whichever is chosen.

What goes in the last layer

The last layer usually has no elementwise activation. A classifier with K classes ends with a linear layer producing K numbers called logits. Softmax turns them into probabilities: pk = ezk / ∑j ezj. Softmax must be computed in a numerically stable way: subtract the maximum first (see A0 chapter 11). The loss that goes with it is the cross-entropy of A0 chapter 13. A regressor ends with a plain linear layer. A language model ends with a linear layer of V logits, one per vocabulary token.

import numpy as np

logits = np.array([2.0, 1.0, 0.1])          # (K,) raw scores for three classes
shifted = logits - logits.max()              # subtract the max for numerical stability
p = np.exp(shifted) / np.exp(shifted).sum()  # softmax: positive, sums to 1
print("probabilities:", np.round(p, 3), "sum =", p.sum().round(3))

true_class = 0
print("cross-entropy loss:", round(float(-np.log(p[true_class])), 3))

# stable even when the raw numbers are huge
big = np.array([1000.0, 1001.0, 1002.0])
e = np.exp(big - big.max())
print("huge logits:", np.round(e / e.sum(), 3))
print("naive version:", np.exp(big) / np.exp(big).sum())
probabilities: [0.659 0.242 0.099] sum = 1.0
cross-entropy loss: 0.417
huge logits: [0.09  0.245 0.665]
naive version: [nan nan nan]

Three logits (2.0, 1.0, 0.1) become probabilities (0.659, 0.242, 0.099). The loss for true class 0 is −ln 0.659 = 0.417. The more probability the model puts on the right answer, the closer the loss gets to zero. The last two lines show why the shift matters. With logits near 1000 the naive formula overflows and returns nan. (NumPy also prints two overflow warnings to the error stream, not shown.) The shifted version gives the right answer, because softmax is unchanged by adding the same constant to every logit.

Practical notes on inputs and sizes

  • Scale the inputs. If one input ranges over millions and another over fractions, the pre-activations are dominated by the large one and saturating activations flatten out. Standardise numeric inputs (zero mean, unit variance), as in the preprocessing of A1 chapter 05. Embedding layers (chapter 06) handle categorical inputs.
  • Width multiplies cost. The size of a layer grows with Cin×Cout, so doubling a width roughly quadruples the layer's parameters and the arithmetic per example.
  • Count before you build. A quick parameter count, as above, catches a mis-typed layer size that would otherwise surface as an out-of-memory error an hour into training.

Following a forward pass by hand

The next widget walks one example through a tiny network with real numbers: two inputs, a hidden layer of two ReLU units, one output. The same numbers return in chapter 02 for the backward pass, so it is worth following the arithmetic now.

Step through

A forward pass with numbers

  1. Inputs. One example enters with x = (1, 2), shape (1, 2). The network has weights W1 of shape (2, 2), no biases, ReLU, then weights W2 of shape (2, 1).
  2. Weights of layer 1. Unit 1 weights its inputs by (0.5, 0.25); unit 2 by (-1.0, 0.25). These four numbers are the matrix W1, stored column by column.
  3. Pre-activations. z = xW1 = (1.0, -0.5). Unit 1 gets a positive vote, unit 2 a negative one.
  4. ReLU. Unit 1 passes 1.0 through; unit 2 is clipped to 0. Its output carries no information forward, and (chapter 02) no gradient flows back through it for this example.
  5. Weights of layer 2. The output weights are W2 = (0.6, -0.4), shape (2, 1).
  6. Output and loss. ŷ = 1.0×0.6 + 0×(-0.4) = 0.6. With target 1 and squared-error loss L = ½(0.6 − 1)² = 0.08. Training will adjust W1 and W2 to reduce it.

Why depth helps

So far we have used one hidden layer. Is that not enough? In one sense it is. The universal approximation theorem says a network with one hidden layer and enough units can approximate any reasonable continuous function on a bounded region as closely as you like. Cybenko (1989) proved this for sigmoid units, and Hornik, Stinchcombe and White (1989) proved it more generally. The theorem only says such a network exists. It does not say how many units are needed or how to find the weights. It does not say how well the result will generalise to new data.

Width alone can be expensive

A ReLU network computes a piecewise-linear function: straight segments joined at corners. Here is a measurement. Take 2 hidden ReLU units, wired to make a "tent" shape on [0, 1] that rises from 0 to 1 and falls back to 0. Feed the tent's output into another tent, and again. Count the straight pieces of the final function, and compare with the number of units used.

import numpy as np
def tent(x):                    # 2 ReLU units: 2*relu(x) - 4*relu(x-0.5) on [0,1]
    return 2*np.maximum(0, x) - 4*np.maximum(0, x-0.5)
xs = np.linspace(0, 1, 100001)
y = xs.copy()
for depth in range(1, 7):
    y = tent(y)
    s = np.sign(np.diff(y)); s = s[s != 0]
    turns = int((s[1:] != s[:-1]).sum())
    print(f"depth {depth}: units {2*depth:>2}, linear pieces {turns+1:>3}")
depth 1: units  2, linear pieces   2
depth 2: units  4, linear pieces   4
depth 3: units  6, linear pieces   8
depth 4: units  8, linear pieces  16
depth 5: units 10, linear pieces  32
depth 6: units 12, linear pieces  64

Every extra layer costs two more units but doubles the number of pieces: 12 units in 6 layers give 64 pieces. A single hidden layer of 12 ReLU units on one input can have at most 13 pieces, because each unit adds at most one corner. To get 64 pieces from one layer you would need about 63 units. To match 20 layers (40 units) you would need over a million. Composition multiplies where width only adds.

This is a special example with carefully chosen weights, so it shows a possibility, not what training finds. The next script shows the width side of the story more smoothly. It fixes random hidden units, so the first layer is never trained. Then it solves for the best output weights to fit sin(2x) on [−3, 3]:

import numpy as np
rng = np.random.default_rng(0)
xs = np.linspace(-3, 3, 400)[:, None]
target = np.sin(2*xs).ravel()
for width in [2, 4, 8, 16, 64]:
    W = rng.normal(size=(1, width)); b = rng.uniform(-3, 3, size=width)
    H = np.maximum(0, xs @ W + b)                  # (400, width) random ReLU features
    H1 = np.hstack([H, np.ones((400, 1))])
    coef, *_ = np.linalg.lstsq(H1, target, rcond=None)
    err = np.sqrt(np.mean((H1 @ coef - target) ** 2))
    print(f"width {width:>3}: RMSE {err:.4f}")
width   2: RMSE 0.7220
width   4: RMSE 0.4923
width   8: RMSE 0.2627
width  16: RMSE 0.2647
width  64: RMSE 0.0130

More units give a better fit, as the theorem promises, but not smoothly. Widths 8 and 16 happened to land at similar errors because the random corners fell in similar places. It took 64 units to reach an error of 0.013 on something as simple as a sine wave. A trained, deeper network reuses structure instead.

Depth composes simple features

The practical argument for depth is that real data is built hierarchically. A photograph is made of edges, which form textures and parts, which form objects. Text is made of characters, words, phrases and clauses. A layer can build on whatever the layer below has already computed, so each layer's job stays easy. Early image layers do respond to edges and colour blobs, and later ones to larger patterns. This is documented by looking at trained networks (chapter 07). The same layered re-description is what the XOR example did in miniature.

Analogy: an assembly line versus one huge workbench

A shallow wide network is like one enormous workbench where a single craftsperson has a separate tool for every product they might ever make. A deep network is an assembly line: station one cuts the parts, station two joins them, station three finishes. The same small set of stations can produce a huge range of products because later stations reuse what earlier ones prepared.

Where it breaks down: an assembly line is designed by an engineer who decides what each station does. In a network nobody assigns the roles; training discovers whatever intermediate steps help, and they are often hard to name.

Depth has a price

Deeper networks are harder to train. Gradients must travel through every layer, signals can shrink or grow, and small errors compound. Much of the engineering in the next chapters (careful initialisation, normalisation, skip connections) exists to make depth usable. A GPT-style model is deep, tens to over a hundred blocks in published designs, and without these tools it would not train.

Reading an architecture as a specification

With these pieces you can read most descriptions. "Multi-layer perceptron (MLP) with hidden width 4C" means two linear layers, (C, 4C) then (4C, C), with an activation between them. Its parameter count is 4C² + 4C + 4C² + C = 8C² + 5C. For C = 768 that is 4,722,432 per block, dominated by the 8C² term. This is the feed-forward sublayer of the original GPT-2-small shape. Chapter 16 counts the rest. Multiplying width by two multiplies this layer's size by four, which is why width is the expensive knob.

Common misconception

"A deeper network is always more powerful, so add layers until it works." More layers mean more expressive power in principle. They also mean harder optimisation, more activation memory, and more places for the signal to be damaged. A 50-layer network with a poor initialisation will often train worse than a 3-layer one. Depth pays off only together with the techniques of chapter 03, and only when the data have the compositional structure that depth can exploit.

Systems connection

A layer is a matrix multiplication followed by an elementwise function. The multiply does about 2×B×Cin×Cout floating-point operations (FLOPs) and is limited by arithmetic speed on a GPU. The activation does one operation per element. It is limited by memory bandwidth, because the data must be read and written once. That is why frameworks fuse it into the multiply. Chapter 16 of this course turns both ideas into FLOP and byte counts.

Key takeaways

  • A neuron computes z = w · x + b and then an activation f(z); its z = 0 set is a hyperplane.
  • A layer is f(XW + b) with shapes (B, Cin) × (Cin, Cout) → (B, Cout) and CinCout + Cout parameters.
  • Without a non-linear activation, any stack of layers is one linear layer. The activation is what lets hidden layers re-describe the data.
  • Sigmoid and tanh saturate; ReLU is cheap but can die; GELU and gated variants such as SwiGLU are the Transformer defaults.
  • One wide layer can approximate anything in theory. Depth composes features and can create exponentially many pieces from linearly many units, but it makes training harder.

  • Karpathy, micrograd (2020) and the "Zero to Hero" first lecture. A tiny neuron-and-autograd engine and the video that builds it.
  • Hendrycks and Gimpel, "Gaussian Error Linear Units (GELUs)" (2016). The paper that defines GELU.
  • Shazeer, "GLU Variants Improve Transformer" (2020). Two pages that introduced SwiGLU and its relatives.
  • Telgarsky, "Benefits of depth in neural networks" (2016). The formal version of the tent-map argument.
  • Goodfellow, Bengio and Courville, "Deep Learning" (2016), chapter 6. Feed-forward networks, activations and the universal approximation discussion.

Check your understanding

A linear layer maps 100 inputs to 50 outputs and has a bias. How many parameters does it have?

  1. 150
  2. 5,000
  3. 5,050
  4. 10,050
The weight matrix has 100×50 = 5,000 entries and the bias adds 50, giving 5,050. Forgetting the bias gives 5,000; adding the input and output sizes (150) confuses a sum with a product.

You stack ten linear layers with no activation functions between them. Compared with a single linear layer, the stack can represent:

  1. Exactly the same set of functions, because the product of the weight matrices is itself one matrix
  2. Ten times as many functions, because it has ten times the parameters
  3. Any continuous function, by the universal approximation theorem
  4. Only functions with outputs between 0 and 1
Composition of linear maps is linear. The theorem applies to networks with a non-linear activation. Extra parameters do not help here, because many different weight settings produce the same function.

Why does a 30-layer network of sigmoid units train poorly compared with ReLU units, other things equal?

  1. Sigmoid outputs are always negative
  2. Sigmoid cannot be differentiated
  3. Sigmoid is far more expensive to compute than any other function
  4. Sigmoid's slope is at most 0.25 and near zero when saturated, so the gradient is multiplied by small numbers at every layer and shrinks towards zero
Sigmoid is smooth and differentiable, so the second option is wrong. Cost is a minor effect. The problem is the repeated multiplication of small slopes during backpropagation (measured in chapter 03).

X has shape (32, 10), W has shape (10, 20) and b has shape (20). What is the shape of f(XW + b) and how is b combined?

  1. (32, 20), with b added to the first row only
  2. (32, 20), with b broadcast and added to every row
  3. (10, 20), with b added to every column
  4. It is an error: b must have shape (32, 20)
XW is (32, 20); broadcasting adds the length-20 vector to each of the 32 rows. Elementwise f keeps the shape.

In the tent experiment, 12 ReLU units arranged in 6 layers gave 64 linear pieces. What is the largest number of pieces that 12 ReLU units can produce in a single hidden layer on a one-dimensional input?

  1. 12
  2. 64
  3. 13
  4. 4,096
Each unit contributes at most one corner (where its pre-activation crosses zero), so 12 units give at most 12 corners and 13 pieces. The first option forgets the extra piece. The comparison shows that composing layers multiplies pieces while adding units only adds them.

A ReLU unit's pre-activation is negative for every example in the training set. What happens to that unit during training?

  1. Its weights grow until it becomes active again
  2. It acts like a sigmoid with a small slope
  3. It is removed from the network automatically
  4. Its slope is zero for every example, so it receives no gradient, its weights stop changing, and it stays dead
With a slope of exactly zero on the negative side, backpropagation sends nothing to that unit's weights. Unlike a saturated sigmoid, which has a tiny but non-zero slope, a dead ReLU has none at all. Frameworks do not remove it.
