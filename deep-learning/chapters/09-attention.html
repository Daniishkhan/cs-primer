Attention from First Principles

Every large language model is, at its core, a stack of one idea: let each position in a sequence look at the other positions and take a weighted average of what it finds there. This chapter builds that operation from a dictionary lookup and derives each factor in the attention formula. It adds the mask that makes the operation usable for generation. Then it multiplies the operation into several heads. Everything is run in NumPy, shape by shape.

Why this matters

Attention is the mechanism that lets a model use context. A chat model may resolve "it" to the right noun three paragraphs back. It may copy an identifier from your prompt into its answer. It may follow a format you showed it once. In each case, attention heads are moving information between positions. Attention is also the part of a Transformer whose cost grows with the square of the sequence length. So it decides context-window limits, memory use and a large share of serving cost (chapters 16 and 19, and the cache of past keys and values in A3 chapter 18). After this chapter you can write scaled dot-product attention with a causal mask and multiple heads from memory. You can say what every tensor shape means and explain why the √dk is there. You can also spot the common bugs: a mask applied after the softmax, a mask that leaks the future, and a row that is masked entirely and returns NaN. Chapter 10 puts this operation into a full Transformer block. Chapter 12 trains a small language model built from it.

The problem attention solves

A language model must predict a token from the tokens before it, and the useful evidence can be anywhere. In "The trophy did not fit in the suitcase because it was too big", what "it" refers to depends on a word eight positions back. In a Python file, the right closing bracket depends on an opening bracket that may be hundreds of tokens earlier. Whatever the architecture, it needs a way to route information from the position that has it to the position that needs it.

Chapter 08 showed the recurrent answer: read the tokens one at a time and squeeze everything seen so far into a single hidden state vector. That state is a bottleneck. Information from early tokens must survive many updates. Gradients must travel back through every step. The computation is sequential, so a GPU cannot process the tokens of a sequence in parallel during training. Bahdanau, Cho and Bengio ("Neural Machine Translation by Jointly Learning to Align and Translate", 2014) made the first big change inside a recurrent translator. They stopped forcing the decoder to rely on one summary vector of the source sentence. Instead it can look back at all the encoder's states and take a weighted average. It computes the weights itself at each output step. They called this soft alignment, and it is the origin of the word attention in deep learning.

Vaswani et al. ("Attention Is All You Need", 2017) then asked whether the recurrence was needed at all. Their answer was an architecture that uses only attention (plus position-wise networks, chapter 10) to route information. This removes the sequential dependency, because every position can compute its attention output at the same time. The case study Attention Is All You Need reads that paper closely. Here we build the operation itself.

A soft dictionary

Start with something familiar. A Python dictionary maps keys to values: d["currency"] finds the entry whose key equals the query and returns its value. It is a hard lookup: exactly one entry matches, or none does. Attention generalises this in two ways. The match is graded rather than exact, so every key receives a score saying how well it fits the query. And the answer is a blend: the scores become weights that sum to one, and the result is the weighted average of all the values.

The three roles get names. The query is the vector that asks the question. A key is a vector attached to each item that advertises what the item is about. A value is the vector attached to each item that is handed over if the item is selected. The score of a key for a query is their dot product, the similarity measure of A0 chapter 05. It is large and positive when the vectors point the same way. The weights come from a softmax. This turns any list of real numbers into positive weights summing to one. It must be computed stably, as A0 chapter 11 explains:

weightsj = exp(sj) / ∑m exp(sm),    output = ∑j weightsj · valuej.

The script below stores three items under unit-vector keys and queries it with a vector that matches the second key exactly. A multiplier β applied to the scores (think of it as 1 over a temperature) controls how sharp the lookup is.

import numpy as np
np.set_printoptions(precision=3, suppress=True)

# a tiny table: three keys (unit vectors) and the value stored under each
keys   = np.eye(3)                           # "capital", "currency", "language"
values = np.array([[10., 0.], [0., 10.], [5., 5.]])
q = np.array([0.0, 1.0, 0.0])                # a query that matches the second key exactly

def softmax(a):
    e = np.exp(a - a.max()); return e / e.sum()

print("hard lookup (argmax):", values[np.argmax(keys @ q)])
for beta in (0.5, 2, 8):                     # beta plays the role of 1/temperature
    w = softmax(beta * keys @ q)
    print(f"beta={beta:<3} weights={w}  result={w @ values}")

# a query halfway between two keys
q2 = np.array([0.7, 0.7, 0.0])
w = softmax(8 * keys @ q2)
print("blended query, beta=8:", w, "->", w @ values)
hard lookup (argmax): [ 0. 10.]
beta=0.5 weights=[0.274 0.452 0.274]  result=[4.111 5.889]
beta=2   weights=[0.107 0.787 0.107]  result=[1.598 8.402]
beta=8   weights=[0.    0.999 0.   ]  result=[0.005 9.995]
blended query, beta=8: [0.499 0.499 0.002] -> [5. 5.]

With β = 0.5 the result is a vague mixture of everything. With β = 8 it is almost exactly the stored value of the best match, (0, 10), so the soft lookup has become the hard one. A query halfway between two keys returns the average of their two values, (5, 5). This is the whole behaviour of attention: a lookup whose sharpness and target are both learned. It is differentiable everywhere, so gradient descent can tune what is asked, what is advertised and what is handed over.

Analogy: asking a room of experts

Picture a meeting where each person wears a badge listing their specialities (the key) and has notes prepared (the value). You stand up with a question (the query). People whose badges fit your question wave their notes the hardest. You listen to everyone at once, weighting each by how hard they wave. You walk away with a blend of what they said. Different questions make different people wave.

Where it breaks down: real keys and queries are learned vectors of dozens or hundreds of numbers with no human-readable meaning. The badge and the notes are produced from the same underlying person by two different learned maps. Also, in a Transformer everyone in the room asks a question at the same moment. The room also has many parallel meetings (the heads) at once.

Queries, keys and values from the same tokens

In a Transformer the queries, keys and values are not given. They are computed from the sequence itself. This is called self-attention. The input is the matrix x of shape (T, C) for one sequence. Here T is the number of tokens, and C (also written dmodel) is the width of each token's vector, the notation of this course. Three learned weight matrices project it:

Q = x WQ,   K = x WK,   V = x WV,    with WQ, WK of shape (C, dk) and WV of shape (C, dv).

Row i of Q is the query of token i, row j of K is the key of token j, and row j of V is its value. With a batch dimension everything gains a leading B: x is (B, T, C) and Q, K, V are (B, T, dk). The core is then two matrix products and a softmax:

Plug in numbers. Two tokens and a width of 2 (T = 2, dk = dv = 2), small enough to check by hand. Each printed line is one step above. This is full attention with no causal mask; a decoder would also hide the upper triangle.

The idea

  1. Q, K, V: three (2, 2) matrices, one row per token
  2. scores ← Q times KT, shape (2, 2): query i dotted with key j
  3. scaled ← scores ÷ sqrt(d_k)
  4. weights ← softmax of each row; each row sums to 1
  5. output ← weights times V: a weighted average of the value rows
"""Scaled dot-product attention for T = 2 tokens and d_k = d_v = 2."""
import math

# ── 1. Queries, keys, values: one row per token ──────────────────────────
Q = [[2.0, 0.0],
     [1.0, 1.0]]                  # shape (T, d_k) = (2, 2)
K = [[1.0, 0.0],
     [0.0, 2.0]]                  # shape (T, d_k) = (2, 2)
V = [[1.0, 2.0],
     [3.0, 0.0]]                  # shape (T, d_v) = (2, 2)
T, D_K = 2, 2


def show(name, m):
    print(f"{name:<8}{[[round(v, 3) for v in r] for r in m]}")


# ── 2. Scores: entry (i, j) is query i dotted with key j ─────────────────
scores = [[sum(q * k for q, k in zip(Q[i], K[j])) for j in range(T)]
          for i in range(T)]      # Q K^T, shape (T, T)
show("QK^T", scores)

# ── 3. Scale by sqrt(d_k) ────────────────────────────────────────────────
scaled = [[s / math.sqrt(D_K) for s in row] for row in scores]
show("scaled", scaled)

# ── 4. Softmax along each row: a distribution over the T positions ───────
weights = []
for row in scaled:
    exps = [math.exp(s) for s in row]
    weights.append([e / sum(exps) for e in exps])
show("weights", weights)
print("row sums", [round(sum(r), 3) for r in weights])

# ── 5. Weighted average of the value rows: shape (T, d_v) ────────────────
out = [[sum(weights[i][j] * V[j][c] for j in range(T)) for c in range(2)]
       for i in range(T)]
show("output", out)
QK^T    [[2.0, 0.0], [1.0, 2.0]]
scaled  [[1.414, 0.0], [0.707, 1.414]]
weights [[0.804, 0.196], [0.33, 0.67]]
row sums [1.0, 1.0]
output  [[1.391, 1.609], [2.34, 0.66]]

Q KT has shape (T, dk) × (dk, T) = (T, T). Entry (i, j) is the dot product of query i with key j: how strongly token i wants to read from token j. The softmax is taken along each row, so row i becomes a probability distribution over the T positions that token i may read. Multiplying by V, shape (T, dv), forms for every token a weighted average of all value vectors. The output has shape (T, dv). One matrix product scores all T² pairs at once. This is why attention maps so well onto GPUs.

Why three separate projections?

One could imagine using x directly for all three roles. Separate maps are worth their parameters for two reasons. First, they decouple what a token asks from what it advertises. A verb might ask for "my subject" while advertising "I am a verb in the past tense". With a single map the same vector would have to do both jobs. Second, with Q = K the score matrix would be symmetric. Token i's interest in j would equal j's interest in i. Every token's strongest match would be itself, since a vector has its largest dot product with itself among equal-length vectors. Separate WQ and WK break that symmetry. Finally, V is separate from K because the thing that makes a token findable is not necessarily the thing you want to read from it.

A worked example with numbers

Here is the whole operation on three tokens, small enough to check by hand. Each token is a vector of C = 4 numbers, and the projections map to dk = 2. The matrices were chosen to give readable values. The final lines add a causal mask, which we derive properly below.

import numpy as np
np.set_printoptions(precision=2, suppress=True)

x = np.array([[1., 0., 1., 0.],    # token 0: "the"
              [0., 1., 0., 1.],    # token 1: "cat"
              [1., 1., 0., 0.]])   # token 2: "sat"      x is (T, C) = (3, 4)
Wq = np.array([[1, 0], [0, 1], [0, 0], [0, 0]], float)   # (C, d_k) = (4, 2)
Wk = np.array([[1, 0], [0, 1], [1, 0], [0, 1]], float)
Wv = np.array([[1, 0], [0, 1], [1, 0], [0, 0]], float)

Q, K, V = x @ Wq, x @ Wk, x @ Wv         # each (3, 2)
print("Q", Q.tolist(), "\nK", K.tolist(), "\nV", V.tolist())

S = Q @ K.T / np.sqrt(2)                 # (3, 3): score of query i against key j
print("scores\n", S)

def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

P = softmax(S)
print("weights\n", P, "\nrow sums", P.sum(1))
print("output = P @ V\n", P @ V)

mask = np.triu(np.ones((3, 3), bool), k=1)       # True above the diagonal = future
Pc = softmax(np.where(mask, -np.inf, S))
print("causal weights\n", Pc)
print("causal output\n", Pc @ V)

Check row 0 of the weights by hand. Query 0 is (1, 0). The keys are (2, 0), (0, 2) and (1, 1), so the dot products are 2, 0 and 1. Dividing by √2 = 1.414 gives the scores 1.41, 0 and 0.71. Their exponentials are 4.11, 1.00 and 2.03, which sum to 7.14. So the weights are 0.58, 0.14 and 0.28, as printed. The output is 0.58 (2, 0) + 0.14 (0, 1) + 0.28 (1, 1) = (1.44, 0.42). Row 2 has equal scores, so its weights are all 1/3 and it averages the three values. With the causal mask, row 0 can see only itself and is forced to weight (1, 0, 0). So token 0's output is exactly its own value, (2, 0). Step through the same computation below.

Step through

Causal self-attention on three tokens

  1. Start with embedded tokens. Three tokens, each a vector of C = 4 numbers, form x with shape (T, C) = (3, 4). Attention will let each of them read from the others.
  2. Project to Q, K and V. Three matrix products give three (3, 2) matrices from the same x. Nothing has been mixed between tokens yet: row i depends only on token i.
  3. Score every pair. Q KT / √2 is a 3 × 3 table. Row 0 (yellow) holds token 0's scores against all three keys. This is the first place information from different tokens meets.
  4. Apply the causal mask. Entries above the diagonal are the future. They are replaced by −∞ so that the softmax will give them weight exactly zero.
  5. Softmax along each row. Each row becomes a distribution over the positions it may read. Row 0 is (1, 0, 0), row 1 is (0.20, 0.80, 0), row 2 is uniform.
  6. Mix the values. Output row i is the weighted average of the rows of V with the weights in row i of P. The result has shape (T, dv) = (3, 2), ready for the next stage of the network.

Why divide by √dk

The factor 1/√dk looks like a detail but it is what makes the softmax trainable at realistic widths. Vaswani et al. (2017) gave the reason in a footnote; here it is in full.

Suppose a query q and a key k each have dk components that are independent, with mean 0 and variance 1. This is roughly true at initialisation if the inputs are normalised and the projection weights follow the scaling rules of chapter 03. The score is q·k = ∑i qiki. Each product qiki has mean 0 and variance E[qi2]E[ki2] = 1. A sum of dk independent terms has variance equal to the sum of the variances, so

Var(q·k) = dk,    standard deviation √dk.    Dividing by √dk restores a standard deviation of 1.

It is the same variance rule as the initialisation derivation of chapter 03, applied to a dot product instead of a neuron. Why does a large score spread matter? The softmax turns scores into weights with exp. Suppose the scores have a standard deviation of 30. Then the largest beats the second largest by many units, and exp(10) is about 22,000 times exp(0). The softmax output is then almost exactly one-hot. A one-hot softmax has an almost zero derivative. Its Jacobian is ∂pi/∂sj = pi(δij − pj). When one p is near 1 and the rest near 0, every entry is near 0. The gradient to the query and key projections vanishes. The head is stuck attending to whichever key it happened to prefer at initialisation. Measure it:

import numpy as np
rng = np.random.default_rng(0)

def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

print(f"{'d_k':>5} {'std(q.k)':>9} {'std(q.k/sqrt d)':>16} {'max weight raw':>15} {'max weight scaled':>18}")
for d_k in (4, 16, 64, 256, 1024):
    q = rng.normal(size=(2000, d_k))           # 2000 queries
    k = rng.normal(size=(2000, 10, d_k))       # 10 keys each
    s = np.einsum("nd,nkd->nk", q, k)          # raw scores, (2000, 10)
    raw = softmax(s).max(-1).mean()
    sca = softmax(s / np.sqrt(d_k)).max(-1).mean()
    print(f"{d_k:>5} {s.std():>9.2f} {(s/np.sqrt(d_k)).std():>16.2f} {raw:>15.3f} {sca:>18.3f}")

# how much gradient flows back through the softmax? mean Frobenius norm of its Jacobian
print()

The standard deviation of the raw score is almost exactly √dk (2, 4, 7.9, 16, 32), and the scaled score stays at 1.0 for every width. With ten random keys a uniform softmax would give each key 0.10 of the weight. The raw dot products at dk = 1024 put 0.97 of the weight on one key on average. The scaled ones put about 0.32, whatever dk is. The Jacobian norm tells the same story. With raw scores it drops from 0.34 to 0.045 as dk grows from 4 to 1024. With scaling it stays near 0.35. The original paper reports that for large dk, additive attention (a small network scoring each pair) outperformed unscaled dot-product attention. Scaling closes the gap while keeping the speed of a matrix product.

Go deeper optional: when the unit-variance assumption fails

The derivation assumes that the components of q and k are independent with unit variance. Trained queries and keys are not like that. The model can learn to make some components large and correlated, and then the real score spread differs from √dk. That is allowed. The scaling fixes the starting point, and the model learns whatever sharpness it needs from there. Some recent models normalise the queries and keys themselves. This is often called query-key (QK) normalisation, or QK-norm. It is a LayerNorm or RMSNorm on each head's Q and K before the dot product. They do it because in large, long training runs the scores can still drift large enough to saturate the softmax and cause loss spikes (chapter 17). A related line of work (for example "Scalable-Softmax", 2025) argues that the right scaling should also depend on the sequence length T. The softmax over more keys is flatter for the same scores. Treat these as active research. The √dk rule remains the standard default.

Masking: what a token may not read

The formula so far lets every token read every other token, which suits an encoder that processes a whole sentence at once. A language model that generates text cannot work that way. During training it sees a whole sequence of T tokens and predicts the next token at every position in one pass (chapter 14). If position 3 could read token 4 it could copy the answer, learn nothing, and fail at generation time when token 4 does not exist yet. The causal mask forbids this: query i may attend only to keys j ≤ i. The matrix of allowed pairs is lower-triangular.

The mask has to act on the scores, before the softmax, by setting forbidden entries to −∞. Since exp(−∞) = 0, such entries get weight exactly zero and the remaining weights still sum to one. The tempting alternative is zeroing the weights after the softmax. That is wrong. The softmax has already shared out probability to the forbidden positions. After removing them the rows no longer sum to one. The output is shrunk by an amount that depends on how much of the weight was in the future. The script shows both, plus the second kind of mask and the classic failure.

import numpy as np
np.set_printoptions(precision=2, suppress=True)
rng = np.random.default_rng(1)
T = 5
S = rng.normal(size=(T, T))               # raw scores for one head
def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

future = np.triu(np.ones((T, T), bool), k=1)
good = softmax(np.where(future, -np.inf, S))               # mask BEFORE softmax
bad = softmax(S) * ~future                                  # zero AFTER softmax
print("masked before softmax: row sums", good.sum(1))
print("zeroed after softmax:  row sums", bad.sum(1))
print(good)

# padding mask: sequence of length 3 padded to T=5 (keys 3 and 4 are padding)
pad = np.array([False, False, False, True, True])
Sp = np.where(pad[None, :], -np.inf, S)
print("padding mask, query 0:", softmax(Sp)[0])

# a fully masked row gives NaN: the classic bug
print("all -inf row:", softmax(np.full((1, 3), -np.inf)))

A second kind is the padding mask. To process several sequences of different lengths as one batch tensor, shorter ones are padded with dummy tokens up to the batch's length. Those positions hold no information, so every query must be forbidden from attending to them: the key positions that are padding get −∞. In the output above, query 0 spreads its weight over the three real tokens and gives exactly 0 to the two padded ones. In a padded batch of a decoder the two masks are combined (a position is forbidden if it is in the future or is padding).

Finally, the failure at the bottom of the output. If every entry of a row is −∞, the stable softmax computes −∞ minus the row maximum (−∞). That is not a number, and the whole row becomes NaN. With a causal mask this cannot happen, because the diagonal is always allowed. With a padding mask on a left-padded batch, or a sequence whose real length is zero, it can happen. A single NaN in one row of one head then spreads to the whole network within a layer or two. Real implementations take one of three routes. They guarantee one allowed entry per row. Or they use a large negative finite number such as −109 instead of −∞, so a fully masked row becomes uniform rather than NaN. Or they fix up the rows after the fact. nanoGPT fills with float('-inf') and relies on the diagonal.

Common misconception

"Attention weights show why the model produced its answer." The weights are a real intermediate quantity, easy to plot as a heatmap, and tempting to read as an explanation. But they are one step of a deep computation. The values they mix pass through the output projection, the feed-forward multi-layer perceptron (MLP) and many more layers. Other heads and layers carry information too. Jain and Wallace ("Attention is not Explanation", 2019) showed in text classifiers that attention weights often correlate weakly with other measures of feature importance. They also showed that very different weights could give the same prediction. Wiegreffe and Pinter ("Attention is not not Explanation", 2019) replied that the answer depends on what one means by explanation. The practical position is this. Attention maps are a useful hint about where to look, never a proof of what the model relied on. Testing a claim means intervening, by removing or changing the token and watching the output, not just looking.

Multiple heads

One attention operation computes one weighted average per token with one set of weights. But a token often needs several different kinds of information from its context at once. It may need the subject of the verb, the previous token, the matching opening bracket, or something quoted earlier. A single softmax puts one probability distribution over the positions and cannot do all of these. The remedy is to run several attention operations side by side, each with its own projections, and combine them. This is multi-head attention. Each parallel copy is a head.

The cheap way to do it divides the width. With h heads, give each a slice of size dk = C / h (Vaswani et al. used C = 512, h = 8, dk = 64). Head i has its own WQ(i), WK(i), WV(i) of shape (C, dk) and computes its own (T, dk) output. The h outputs are concatenated along the feature axis, restoring width h · dk = C. A final learned matrix WO of shape (C, C) mixes the heads' results together:

MultiHead(x) = Concat(head1, …, headh) WO,    headi = Attention(xWQ(i), xWK(i), xWV(i)).

In code the h separate small matrices are stored as one big (C, C) matrix for each of Q, K and V. The heads are made by reshaping, so one large matrix product serves all heads. Column block i of WQ is head i's projection. The reshape takes (B, T, C) to (B, T, h, dk) and then swaps axes to (B, h, T, dk). Heads become an extra batch-like axis, and the attention code from before runs unchanged on the last two axes.

The script below builds this with B = 2, T = 6, C = 32 and h = 4 (so dk = 8). It prints the shape after every stage. It also checks the batched version against a plain loop over heads with ordinary 2-D matrices.

import numpy as np
rng = np.random.default_rng(0)
B, T, C, h = 2, 6, 32, 4
d_k = C // h

def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

x = rng.normal(size=(B, T, C))
Wq, Wk, Wv, Wo = (rng.normal(size=(C, C)) / np.sqrt(C) for _ in range(4))

def split(t):                       # (B, T, C) -> (B, h, T, d_k)
    return t.reshape(B, T, h, d_k).transpose(0, 2, 1, 3)

def mha(x, causal=True):
    q, k, v = split(x @ Wq), split(x @ Wk), split(x @ Wv)
    print("q, k, v:", q.shape)
    s = q @ k.transpose(0, 1, 3, 2) / np.sqrt(d_k)
    print("scores :", s.shape)
    if causal:
        s = np.where(np.triu(np.ones((T, T), bool), 1), -np.inf, s)
    p = softmax(s)
    o = p @ v
    print("per-head output:", o.shape)
    o = o.transpose(0, 2, 1, 3).reshape(B, T, C)      # concatenate heads
    print("concatenated:", o.shape)
    return o @ Wo, p

y, p = mha(x)
print("output:", y.shape)

# the same thing, one head at a time with plain 2-D matrices
outs = []
for i in range(h):
    sl = slice(i * d_k, (i + 1) * d_k)
    q, k, v = x[0] @ Wq[:, sl], x[0] @ Wk[:, sl], x[0] @ Wv[:, sl]
    s = q @ k.T / np.sqrt(d_k)
    s[np.triu_indices(T, 1)] = -np.inf
    outs.append(softmax(s) @ v)
y0 = np.concatenate(outs, axis=-1) @ Wo

print("weights sum to 1:", np.allclose(p.sum(-1), 1), "| future weights:", p[0, 0][np.triu_indices(T, 1)].max())

Two things to notice. The scores have shape (B, h, T, T). Every head has its own T × T table, so memory for the scores grows with the number of heads as well as with T². And the parameter count, 4C², does not depend on h at all. Splitting the width into more heads costs no extra parameters or arithmetic. It only changes how the same C columns are grouped. More heads buy diversity of attention patterns. They cost richness, because each head works with fewer dimensions (dk shrinks), which limits how rich each head's matching can be.

What heads learn

Heads differ because they are initialised differently and trained to be useful together, not because anyone assigns them roles. Interpretability work has found recurring patterns anyway. Voita et al. ("Analyzing Multi-Head Self-Attention: Specialized Heads Do the Heavy Lifting, the Rest Can Be Pruned", 2019) studied a translation model. They found a few heads that tracked adjacent positions, syntactic relations or rare words. Many other heads could be removed with little loss. Michel, Levy and Neubig ("Are Sixteen Heads Really Better than One?", 2019) reached a similar conclusion for removing heads at test time. Olsson et al. ("In-context Learning and Induction Heads", 2022) identified induction heads. These are a pair of heads in two layers that, after seeing "A B" earlier in the context, notice a new "A" and predict "B". They linked the appearance of such heads during training to a sharp improvement in the model's ability to learn from examples given in the prompt. This is a research finding about particular models, not a law. Do not assume each head in a model you load has a tidy job.

Self-attention, cross-attention, encoders and decoders

In self-attention Q, K and V all come from the same sequence. In cross-attention the queries come from one sequence and the keys and values from another: the decoder of a translation model queries the encoder's output. A vision-language model's text tokens can query image features (chapter 21). The computation is identical. Only the source of K and V changes, and the score matrix becomes (Tquery, Tkey), no longer square. Models built from self-attention with a causal mask only are called decoder-only. These include the GPT (generative pre-trained transformer) family and nearly every current chat model. Models with no mask are encoders. They are BERT (bidirectional encoder representations from Transformers) style models, used for classification and embedding ( A4 chapter 23).

Gradients through attention

Attention is built from matrix products and a softmax, so autodiff handles it. It is still worth knowing the backward pass once. It helps you check an implementation and see where the softmax's near-zero gradient from the previous section enters. Take one head with P = softmax(S) row-wise and O = PV. Suppose the loss sends back dO of the same shape as O. The three steps are the reverse of the forward pass (chapter 02 and A0 chapter 09):

  1. Through O = P V. dV = PT dO and dP = dO VT. The first is the gradient into the values: each value row receives the output gradients of the tokens that read it, weighted by how much they read it.
  2. Through the row-wise softmax. For each row, dS = P ⊙ (dP − rowsum(dP ⊙ P)). This is the Jacobian pi(δij − pj) applied without forming the matrix. If a row of P is one-hot, dS is zero for that row.
  3. Through S = QKT/√dk. dQ = dS K / √dk and dK = dST Q / √dk. Masked entries have P = 0, hence dS = 0, so no gradient flows through forbidden pairs.

The script implements these three lines and compares them with central finite differences (the check from chapter 02) on a causal 5-token head.

import numpy as np
rng = np.random.default_rng(0)
T, d = 5, 4
def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True)); return e / e.sum(-1, keepdims=True)
mask = np.triu(np.ones((T, T), bool), 1)

def forward(Q, K, V):
    S = np.where(mask, -np.inf, Q @ K.T / np.sqrt(d))
    P = softmax(S)
    return P @ V, P

def backward(dO, Q, K, V, P):
    dV = P.T @ dO
    dP = dO @ V.T
    dS = P * (dP - (dP * P).sum(-1, keepdims=True))   # softmax backward, row by row
    dQ = dS @ K / np.sqrt(d)
    dK = dS.T @ Q / np.sqrt(d)
    return dQ, dK, dV

Q, K, V = (rng.normal(size=(T, d)) for _ in range(3))
W = rng.normal(size=(T, d))                  # loss = sum(W * output)
O, P = forward(Q, K, V)
dQ, dK, dV = backward(W, Q, K, V, P)

def num_grad(f, A, eps=1e-6):
    g = np.zeros_like(A)
    for i in np.ndindex(*A.shape):
        a = A[i]; A[i] = a + eps; hi = f(); A[i] = a - eps; lo = f(); A[i] = a
        g[i] = (hi - lo) / (2 * eps)
    return g
loss = lambda: (W * forward(Q, K, V)[0]).sum()
for name, A, g in (("Q", Q, dQ), ("K", K, dK), ("V", V, dV)):
    print(f"d{name}: max |analytic - numeric| = {np.abs(g - num_grad(loss, A)).max():.1e}")
dQ: max |analytic - numeric| = 8.0e-10
dK: max |analytic - numeric| = 1.6e-09
dV: max |analytic - numeric| = 7.8e-10

All three gradients agree with the numeric ones to about 10−9, so the formulas are right. Fast attention kernels (chapter 19) recompute P in the backward pass instead of storing it, but the algebra is exactly this.

What attention costs

The score matrix has T² entries per head per sequence. Computing Q KT and then P V takes about 2 · 2 · T² · dk floating-point operations (FLOPs) per head. Each of the two matrix products is T × T × dk multiply-adds, and a multiply-add counts as two operations. If the whole T × T matrix is stored, it also takes T² numbers of memory. The next script tabulates both for one head with dk = 128 and 16-bit numbers.

# memory of the T x T score matrix for ONE head, ONE sequence, in 16-bit numbers, and the multiply-adds of QK^T and PV
for T in (1_024, 8_192, 32_768, 131_072):
    entries = T * T
    mib = entries * 2 / 2**20
    d_k = 128
    flops = 2 * 2 * T * T * d_k          # two matmuls, 2 FLOPs per multiply-add
    print(f"T={T:>7,}  entries={entries:>16,}  one head, fp16: {mib:>10,.0f} MiB   QK^T + PV: {flops/1e9:>10,.1f} GFLOPs")

Going from 1,024 to 131,072 tokens multiplies the length by 128 and the cost by 128² = 16,384. A naive implementation holding the full score matrix would need 32 GiB for a single head at 131k tokens. A full model's worth of heads could not fit on any GPU, so long-context models never materialise it. This is the motivation for the techniques of chapter 19. Grouped-query attention shrinks what must be stored per token during generation. Sliding windows restrict which pairs are scored. FlashAttention computes exactly the same result in small tiles without ever writing the T × T matrix to GPU memory (case study 5). For generation, previous tokens' K and V are cached so each new token needs only one new row of scores (A3 chapter 18).

Systems connection

Attention is two large matrix multiplications with a softmax between them, which is the workload GPUs were built for. The matrix products are limited by arithmetic throughput. The softmax and the masking are limited by memory bandwidth, because they do little arithmetic per element but touch the whole T × T matrix. That mismatch is why attention was memory-bound before fused kernels. It is also why measuring it needs the profiling habits of chapter 22 rather than counting FLOPs alone. The quadratic cost is also a capacity-planning fact. Doubling the context a service accepts quadruples the attention work for a request of full length and raises the memory for caching. That is why providers price and limit long contexts as they do.

State of play, October 2026

As far as published model reports show, the operation in this chapter, causal multi-head softmax attention, is still the core of nearly every frontier language model. The variants are in how keys and values are stored and which pairs are scored. Grouped-query attention, where several query heads share one key/value head, is widespread. Some models compress the key-value (KV) cache with a learned low-rank projection, as in DeepSeek's multi-head latent attention (2024). Many models mix full-attention layers with sliding-window or other sparse layers. PyTorch has exposed fused attention kernels through torch.nn.functional.scaled_dot_product_attention since version 2.0 (2023). So most users never write the loop of this chapter outside teaching code. All of these change cost and memory, not the idea. Chapters 19 to 22 cover them. Details of any given model change with each release, so check its current technical report.

Key takeaways

  • Attention is a differentiable dictionary lookup: scores from query-key dot products, a softmax to make weights, and a weighted average of values. Q, K and V are three learned projections of the same tokens in self-attention.
  • Shapes: x is (B, T, C); Q, K are (B, T, dk); scores and weights are (B, T, T); the output is (B, T, dv). With h heads, insert an h axis: (B, h, T, dk) and (B, h, T, T).
  • Dividing by √dk keeps the score variance at 1 whatever the width; without it the softmax saturates, becomes one-hot and passes almost no gradient.
  • The causal mask sets future scores to −∞ before the softmax. Masking after the softmax breaks the row sums; a fully masked row gives NaN.
  • Multi-head attention splits the width into h slices of dk = C/h, runs attention on each and mixes with WO. The four matrices cost 4C² parameters whatever h is.
  • Attention costs O(T²) time and, if materialised, memory per head. That drives context limits, the KV cache and fast kernels. Attention weights are a hint, not an explanation.

A decoder layer has B = 4, T = 128, C = 768 and h = 12 heads. What is the shape of the attention-weight tensor P?

Each of the 12 heads has its own T × T table of weights for each sequence, so the shape is (B, h, T, T) = (4, 12, 128, 128). (4, 12, 128, 64) is the shape of one head's Q, K, V or output, with dk = 768/12 = 64. (4, 128, 128) would be a single head.

You change dk from 64 to 256 and forget the 1/√dk factor. Compared with the dk = 64 model, roughly how does the standard deviation of the scores change at initialisation, and what is the effect?

  1. It is unchanged, because the softmax normalises it
  2. It halves, so attention becomes too uniform
  3. It grows by a factor of 4, so the weights become uniform
  4. It doubles, so the softmax is sharper and the gradient to Q and K shrinks
Var(q·k) = dk, so the standard deviation goes from 8 to 16: a factor of √4 = 2, not 4. Larger scores make the softmax closer to one-hot, which reduces its gradient. The softmax normalises the weights, not the scores that go into it, so the sharpness changes.

Which statement about the causal mask is correct?

  1. Future positions' scores are set to −∞ before the softmax, so their weights are exactly zero and each row still sums to one
  2. Future positions' weights are set to zero after the softmax, which is equivalent
  3. The mask is applied to V, so future values are zeroed
  4. The mask is only needed at inference time
Masking before the softmax lets the remaining weights renormalise. Zeroing after leaves rows summing to less than one, which is not equivalent. Masking V is not enough: the weights would still be shared out to future positions. The mask matters in training most, because there the whole sequence is present and an unmasked model could read the answer.

A model has C = 512. You go from h = 8 heads to h = 16 heads, keeping C. What happens to the number of parameters in the Q, K, V and output projections and to the size of the score tensor?

  1. Parameters double; score tensor is unchanged
  2. Parameters are unchanged (4C²); the score tensor doubles because there are twice as many T × T tables
  3. Parameters are unchanged; the score tensor is unchanged
  4. Parameters double; the score tensor doubles
The projections are (C, C) matrices however the columns are grouped, so 4C² = 1,048,576 in both cases. Each head has its own T × T scores, so h doubling doubles the score tensor, while dk halves from 64 to 32.

While training a decoder you notice that changing token 9 of a sequence changes the model's output at position 5. Which is the most likely cause?

  1. The √dk scaling is missing
  2. There are too many heads
  3. The causal mask is missing, wrong or applied after the softmax, so position 5 can read the future
  4. The values V are too wide
Output at position 5 should depend only on tokens 0 to 5. Any dependence on token 9 is leakage from the future, which a missing or misapplied mask produces (an off-by-one that lets the mask start on the diagonal rather than above it is another classic). Scaling, head count and value width affect quality and trainability, not causality. The test is cheap: change a late token and assert earlier outputs are identical.

A colleague shows a heatmap in which a head's attention from the word "bank" is concentrated on "river" and concludes "the model decided the meaning from 'river'". What is the soundest response?

  1. It is a useful hypothesis, but test it by intervening, for example replacing or removing "river" and checking whether the output changes
  2. It is proven, because attention weights are probabilities of importance
  3. It is meaningless, because attention weights carry no information
  4. It is only valid for decoder-only models
Weights are real quantities but one step among many; other heads, layers and the MLPs also carry information, so high weight does not establish reliance (Jain and Wallace, 2019). They are not meaningless either, which is why the debate is not settled in either direction. The cure is an intervention that measures the effect on the output.
