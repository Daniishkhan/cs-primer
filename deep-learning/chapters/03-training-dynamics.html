Initialisation, Normalisation & Residuals

A network with a hundred layers multiplies a hundred matrices together. If each one makes the signal slightly smaller, nothing reaches the end; slightly larger, and it explodes. This chapter measures that effect, derives the initial weight scale that prevents it, and then explains the two structural fixes that every modern deep network relies on: normalisation layers and skip connections.

Why this matters

These three ideas are the difference between a deep network that trains and one that sits at a flat loss or produces NaN on the first step. Every Transformer block you will meet in Part 3 is built from them: a residual connection around each sublayer, a normalisation layer in front of each, and weights initialised at a carefully chosen scale. If you know why each is there, you can diagnose a run that will not start, choose sensible defaults when you change a model's width or depth, and read the initialisation code in nanoGPT or a model card without treating it as folklore. After this chapter you can compute the right initial scale for a layer, implement LayerNorm with its gradient, and predict whether a given stack of layers will preserve, shrink or amplify a signal.

The signal must survive the stack

Chapter 01 showed that a layer is z = aW + b. Chapter 02 showed that backpropagation sends gradients through the transposed weights WT. Both directions repeatedly multiply by weight matrices, so the scale of the weights decides what happens. Start with the forward direction. We want to know how the typical size of the activations, measured by their variance, changes from one layer to the next.

The forward variance rule

Take one neuron with n inputs, z = ∑i=1n wixi (ignore the bias, which starts at zero). Assume, as an approximation, that the weights are drawn independently with mean zero and variance Var(w), that the inputs have mean zero and variance Var(x), and that weights and inputs are independent. Each product wixi has mean zero and variance E[wi2]E[xi2] = Var(w)Var(x). The variance of a sum of n independent terms is the sum of their variances, so

Var(z) = n · Var(w) · Var(x).

Here n is the fan-in, the number of inputs to the neuron (the number of rows of W). Across layers these factors multiply. If every layer has n Var(w) = c, the activations' variance after L layers is about cL times the input's. With c = 0.5 and L = 20 that is a factor of one in a million; with c = 2 it is a million times larger. Only c = 1 is stable, which gives the rule:

Var(w) = 1 / nin    (LeCun, 1998; the forward half of "Xavier" initialisation).

Glorot and Bengio ("Understanding the difficulty of training deep feedforward neural networks", 2010) noticed that the backward pass has the mirror-image condition. The gradient δ passes through WT, where each neuron sums over nout terms, so backward stability wants Var(w) = 1/nout. They compromised with the average: Var(w) = 2 / (nin + nout), called Xavier or Glorot initialisation, designed for tanh-like activations. It is equal to the forward rule when a layer is square.

What ReLU changes

The derivation assumed the inputs x have zero mean and the same variance as the pre-activations of the layer before. A ReLU breaks the first assumption: it replaces negative values by zero, so its outputs are all non-negative, and it throws away half of the signal's energy. He, Zhang, Ren and Sun ("Delving Deep into Rectifiers", 2015) did the sum: for a symmetric zero-mean pre-activation z, E[ReLU(z)2] = ½Var(z). The factor ½ must be compensated by doubling the weight variance:

Var(w) = 2 / nin    (He or Kaiming initialisation, for ReLU).
Go deeper optional: where the factor of one half comes from

Let z be symmetric around zero with variance σ2. Then E[z2] = σ2. ReLU(z) equals z when z > 0 and 0 otherwise. By symmetry, z > 0 half of the time, and given that, z2 has the same average as for the whole distribution. So E[ReLU(z)2] = ½E[z2] = ½σ2. Note this is the second moment, not the variance: the output has non-zero mean, but the next layer's weights multiply it and, because the weights have zero mean, the next pre-activation's variance depends on the sum of squares, i.e. the second moment. So the pre-activation variance in the next layer is n · Var(w) · ½σ2, which equals σ2 exactly when Var(w) = 2/n.

A PyTorch note: torch.nn.init.kaiming_normal_ has a mode argument choosing fan-in or fan-out, and a nonlinearity argument that sets the gain (√2 for ReLU, 5/3 for tanh).

Measuring it

The script below sends a random batch of 256 vectors of width 512 through 20 layers with weights of various scales and prints the standard deviation of the activations at four depths. The weights are fresh Gaussian draws, the biases zero.

import numpy as np
rng = np.random.default_rng(0)
B, C, depth = 256, 512, 20
X = rng.normal(size=(B, C))
def run(act, scale_fn, name):
    h = X; stds = []
    for l in range(depth):
        W = rng.normal(size=(C, C)) * scale_fn(C)
        h = act(h @ W); stds.append(h.std())
    print(f"{name:<24}" + " ".join(f"{stds[i]:>9.2e}" for i in (0, 4, 9, 19)))
relu = lambda z: np.maximum(0, z)
print(f"{'setting':<24}" + " ".join(f"{'layer '+str(i+1):>9}" for i in (0, 4, 9, 19)))
run(np.tanh, lambda C: 0.01, "tanh, std 0.01")
run(np.tanh, lambda C: 1.0, "tanh, std 1.0")
run(np.tanh, lambda C: np.sqrt(1/C), "tanh, Xavier")
run(relu, lambda C: np.sqrt(1/C), "relu, Xavier")
run(relu, lambda C: np.sqrt(2/C), "relu, He")

Read the table against the rule. With a weight standard deviation of 0.01 and tanh, n Var(w) = 512 × 10−4 = 0.05, so the variance falls by a factor of 20 each layer and the standard deviation reaches 10−13 by layer 20: the network outputs essentially the same thing for every input. Xavier initialisation with ReLU has n Var(w) = 1 but the ReLU halves the second moment, so the standard deviation falls by √2 per layer (0.585 to 0.0007). He initialisation compensates exactly and the value stays near 0.7 for twenty layers. The weights with standard deviation 0.05 are just under the He value of √(2/512) = 0.0625, and the signal decays slowly but surely: even a 20% error in scale compounds.

The tanh row with standard deviation 1.0 needs care. Its activations have a standard deviation of 0.98 at every layer, which looks healthy but is not: the pre-activations are so large (n Var(w) = 512, so std about 23) that every tanh output is pinned at ±1. The layer is saturated: the output is a sign function, its slope (chapter 01) is nearly zero, and gradients cannot flow back through it. The standard deviation alone does not reveal this, so when you inspect a real network look at the histogram or the fraction of saturated units, not only at one summary number.

The backward direction: vanishing and exploding gradients

Gradients are products too. By the recipe of chapter 02, the gradient entering layer l from above is multiplied by WlT and by the activation's slope f′(z). Across L layers the gradient at the first layer is a product of L such factors. If they are typically smaller than one the gradient shrinks exponentially (vanishing gradients), and early layers receive almost no learning signal; if larger, it grows exponentially (exploding gradients) and an update can throw the weights far off. The problem was named in the early 1990s (Hochreiter's 1991 diploma thesis; Bengio, Simard and Frasconi, 1994, for recurrent networks).

Sigmoid is the extreme case. Its slope never exceeds 0.25 (at z = 0). Even if the weights are perfectly scaled, each layer multiplies the gradient by at most 0.25 from the activation. Over ten layers that is 0.2510, about 10−6. The script measures a 30-layer network with sigmoid units against ReLU units with He initialisation, recording the norm of the gradient arriving at each layer (the loss gradient at the output is the same for both).

import numpy as np
rng = np.random.default_rng(0)
B, C, depth = 64, 128, 30
def grad_norms(act, dact, scale):
    Ws = [rng.normal(size=(C, C)) * scale for _ in range(depth)]
    h = rng.normal(size=(B, C)); zs, hs = [], [h]
    for W in Ws:
        z = h @ W; zs.append(z); h = act(z); hs.append(h)
    g = np.ones_like(h) / B            # pretend dL/dh_out = 1/B
    norms = []
    for l in reversed(range(depth)):
        g = (g * dact(zs[l])) @ Ws[l].T
        norms.append(np.linalg.norm(g))
    return norms[::-1]
sig = lambda z: 1/(1+np.exp(-z))
n1 = grad_norms(sig, lambda z: sig(z)*(1-sig(z)), np.sqrt(1/C))
n2 = grad_norms(lambda z: np.maximum(0,z), lambda z: (z>0)*1.0, np.sqrt(2/C))
print("gradient norm w.r.t. layer input; layer 30 is nearest the loss")
print(f"{'layer':>6} {'sigmoid':>12} {'relu+He':>12}")
for l in (30, 25, 20, 10, 5, 1):
    print(f"{l:>6} {n1[l-1]:>12.3e} {n2[l-1]:>12.3e}")

The sigmoid gradient falls from 0.36 at layer 30 to 9×10−20 at layer 1: no optimiser can use that, and in float32 or float16 the numbers would underflow to zero well before then (A0 chapter 11). The ReLU network with He initialisation keeps gradients of order one to five. They even grow gently, which is a small hint of the exploding direction: the exact balance in the derivation is only approximate. For the exploding side, try the widget with a scale of x1.3.

This is why the combination of ReLU-family activations and He-style scaling made much deeper networks trainable after 2010, and why AlexNet (2012) could use ReLU where earlier networks used sigmoid or tanh. It is not enough on its own beyond a few dozen layers, which is where the next two tools come in. For exploding gradients that do still happen, the emergency tool is gradient clipping (chapter 17).

Initialisation in practice

  • Frameworks pick sensible defaults. PyTorch's nn.Linear draws weights uniformly from (−1/√fan_in, +1/√fan_in), a variance of 1/(3·fan_in), a little below the "preserve variance" value but with the same scaling. Weights depend on the layer's own width, never on a fixed constant.
  • Biases start at zero, unless there is a reason (for example the final bias of a rare-event classifier).
  • GPT-2 style models use a fixed small constant. nanoGPT, following GPT-2, draws linear and embedding weights from a normal with standard deviation 0.02. For width 768 the He value would be √(2/768) = 0.051, but a Transformer's blocks are wrapped in normalisation and skip connections (below), which changes the calculation. The projection at the end of each residual branch is further scaled to 0.02/√(2·n_layer), where n_layer counts blocks and the 2 counts the two branches (attention and MLP) in each. The GPT-2 paper describes this as scaling the weights of residual layers by 1/√N for N residual layers.
  • Zero or tiny output layers. If the final layer's weights are small, the network begins by predicting the same near-uniform distribution for every input. That gives a useful sanity check, below.
  • Re-derive when the width changes. The scale depends on fan-in, so a hand-set constant (like 0.02) that works at one width may be wrong at another. Recipes that make hyperparameters transfer across widths exist (Yang et al., 2022, "Tensor Programs V", the μP parameterisation), but they are beyond this course.

Try it yourself: the loss at step zero

A model that knows nothing should assign probability 1/V to each of V tokens, and its cross-entropy is then ln V. For GPT-2's vocabulary of 50,257 tokens that is ln 50,257 = 10.82 nats. Before you train anything, compute the loss of your freshly initialised model on one batch. If it prints about 10.8, initialisation is sane. If it prints 40 or 200, the logits are huge and confidently wrong, which is the signature of weights that are too large; if it prints exactly 0.0 or NaN, something else is broken. This five-second check, popularised by Karpathy's makemore lectures, catches many errors before a long run is started.

Normalisation layers

Careful initialisation sets the scale at step zero. During training, weights change and the scales drift. A normalisation layer removes the dependence: it rescales the activations to a standard mean and variance at every forward pass, wherever the weights have wandered. Two variants dominate. Both compute

x̂ = (x − μ) / √(σ2 + ε),    y = γ ⊙ x̂ + β

where μ and σ2 are a mean and variance, ε (about 10−5) prevents division by zero, and γ and β are learned vectors that restore the layer's ability to choose any scale and offset it wants. They differ in which numbers the mean and variance are computed over.

BatchNorm

Ioffe and Szegedy ("Batch Normalization", 2015) computed μ and σ2 for each feature over the examples in the mini-batch. It made image networks train much faster and tolerate larger learning rates, and it remains the standard in convolutional networks. Its costs: the output for one example depends on the other examples in the batch, which couples them and makes small batches noisy; at test time it must use running averages collected during training, a different code path from training (a classic source of bugs: forgetting model.eval()); and for sequences of varying length the statistics are awkward.

LayerNorm

Ba, Kiros and Hinton ("Layer Normalization", 2016) computed the statistics over the features of a single example (for a Transformer, a single token's C numbers). There is no batch dependence, and training and inference behave identically. This is the normalisation used in Transformers. Zhang and Sennrich ("Root Mean Square Layer Normalization", 2019) proposed RMSNorm, which skips the mean: y = γ ⊙ x / √(mean(x2) + ε). It is slightly cheaper, works about as well, and is used in many recent open-weight language models.

Following LayerNorm by hand

One token with C = 4 features x = (2, 4, 6, 12), learned scale γ = (1.5, 1, 1, 0.5) and shift β = (0, 0, 0.5, 0):

Step through

LayerNorm on one token

  1. One token's features. x = (2, 4, 6, 12). Nothing is shared with other tokens or other examples.
  2. Mean. μ = (2 + 4 + 6 + 12)/4 = 6.
  3. Variance. σ2 = ((−4)2 + (−2)2 + 02 + 62)/4 = 56/4 = 14, so √(σ2 + ε) = 3.742. Note the divisor is C, not C−1.
  4. Centre. Subtract the mean: (−4, −2, 0, 6). The values now sum to zero.
  5. Scale. Divide by 3.742: (−1.07, −0.53, 0.00, 1.60). Mean 0, variance 1, whatever the input scale was. If x had been (20, 40, 60, 120) the result would be identical.
  6. Learned scale and shift. y = γ⊙x̂ + β = (−1.60, −0.53, 0.50, 0.80). Training can set γ and β to undo the normalisation if that helps, so the layer loses no expressiveness.

Implementing it, with its gradient

The forward pass is four lines. The backward pass takes some algebra because μ and σ depend on every element of x, so the gradient must account for the paths through them. The result, derived below, is compact: with dx̂ = dy ⊙ γ,

dx = (1/σ) · ( dx̂ − mean(dx̂) − x̂ · mean(dx̂ ⊙ x̂) ),

where means are taken over the feature axis. Intuitively: the gradient is made to have zero mean and zero correlation with x̂, because moving x along those two directions (shifting all features, or scaling them) does not change the output.

Go deeper optional: deriving the LayerNorm gradient

Let x̂i = (xi − μ)/s with s = √(σ2 + ε), μ = (1/C)∑xj and σ2 = (1/C)∑(xj − μ)2. We need ∂x̂j/∂xi. First, ∂μ/∂xi = 1/C. Second, ∂σ2/∂xi = (2/C)(xi − μ) (the terms through μ cancel because ∑(xj − μ) = 0), so ∂s/∂xi = (xi − μ)/(C s) = x̂i/C. Then by the quotient rule

∂x̂j/∂xi = (1/s)( δij − 1/C − x̂ix̂j/C ),

where δij is 1 when i = j and 0 otherwise. Summing dx̂j times this over j gives dxi = (1/s)( dx̂i − mean(dx̂) − x̂i mean(dx̂ ⊙ x̂) ), the formula above. The gradients for the learned parameters are dγ = ∑ dy ⊙ x̂ and dβ = ∑ dy, summed over all tokens in the batch.

import numpy as np
rng = np.random.default_rng(0)
B, T, C = 2, 3, 6
x = rng.normal(size=(B, T, C)) * 5 + 3          # (B, T, C), badly scaled on purpose
gamma, beta = np.ones(C), np.zeros(C)

def layernorm(x, gamma, beta, eps=1e-5):
    mu = x.mean(-1, keepdims=True)               # (B, T, 1)
    var = x.var(-1, keepdims=True)               # (B, T, 1)
    xhat = (x - mu) / np.sqrt(var + eps)
    return gamma * xhat + beta, (xhat, var)

def layernorm_backward(dy, cache, gamma, eps=1e-5):
    xhat, var = cache
    dxhat = dy * gamma
    C = xhat.shape[-1]
    dx = (dxhat - dxhat.mean(-1, keepdims=True)
          - xhat * (dxhat * xhat).mean(-1, keepdims=True)) / np.sqrt(var + eps)
    return dx

y, cache = layernorm(x, gamma, beta)
print("per-token mean:", np.round(y.mean(-1)[0], 6))
print("per-token std: ", np.round(y.std(-1)[0], 4))

# gradient check against a random linear readout
r = rng.normal(size=y.shape)
f = lambda x: (layernorm(x, gamma, beta)[0] * r).sum()
dx = layernorm_backward(r, cache, gamma)
num = np.zeros_like(x)
for i in np.ndindex(*x.shape):
    o = x[i]; x[i] = o + 1e-6; fp = f(x); x[i] = o - 1e-6; fm = f(x); x[i] = o
    num[i] = (fp - fm) / 2e-6
print("backward max abs error:", float(np.abs(num - dx).max()))
per-token mean: [ 0.  0. -0.]
per-token std:  [1. 1. 1.]
backward max abs error: 8.978193327680017e-10

The input was deliberately badly scaled (mean 3, standard deviation 5), yet every token comes out with mean 0 and standard deviation 1. The final line compares the backward formula with a finite-difference gradient (the method from chapter 02): the largest error is about 10−9, so the derivation is right. Shapes: x is (B, T, C) = (2, 3, 6); the statistics have shape (B, T, 1), and gamma, beta have shape (C).

Common misconception

"Normalisation makes initialisation unimportant" and "BatchNorm works because it removes internal covariate shift." The first is only partly true: normalisation lets training survive a poor scale, but it does not fix, for example, the growth of a residual stream with depth (the widget shows a stack with LayerNorm and residuals still growing), and bad scales still cost training speed. The second was the original explanation (Ioffe and Szegedy, 2015); Santurkar et al. ("How Does Batch Normalization Help Optimization?", 2018) found that the benefit comes mainly from making the loss surface smoother and the gradients more predictable, not from stabilising the input distributions of layers. Treat normalisation as an engineering tool whose effects are empirically strong and theoretically still debated.

Residual connections

The second structural fix is the simplest idea in this chapter. He, Zhang, Ren and Sun ("Deep Residual Learning for Image Recognition", 2015) observed a puzzle: a 56-layer plain network had higher training error than a 20-layer one on CIFAR-10. A deeper network can in principle copy the shallower one and make the extra layers do nothing, so it should never be worse; optimisation was failing to find that solution. Their remedy was to let the layer compute only a correction to its input:

y = x + F(x).

The path x → y is a skip connection (or residual connection, shortcut). If F outputs zero, the block is the identity, a perfectly good starting point. If F is small, the block makes small refinements. Two consequences matter.

  1. Gradients get a highway. By the rule from chapter 02 that gradients add at a branch, ∂L/∂x = ∂L/∂y · (I + ∂F/∂x). The identity term I carries the gradient straight through. Through L blocks the gradient is the product of L factors (I + Jl), which expands into a sum that includes a term with no Jacobians at all: the gradient arriving at the top reaches the bottom unchanged, however badly the branches behave.
  2. The forward signal accumulates. The output is the input plus the sum of every branch's contribution: xL = x0 + ∑lFl(xl−1). Transformer researchers call this running total the residual stream (chapter 10): a shared channel that every block reads from and writes to.

Measuring the highway

The experiment below builds 40-layer ReLU stacks and records the gradient norm arriving at layers 1 and 20 and the standard deviation of the output. Each branch is a ReLU layer with He-scaled weights, multiplied by a branch scale shown in the name; the residual versions compute x + branch(x).

import numpy as np
rng = np.random.default_rng(0)
B, C, depth = 64, 128, 40
def grads(residual, scale):
    Ws = [rng.normal(size=(C, C)) * np.sqrt(2/C) * scale for _ in range(depth)]
    h = rng.normal(size=(B, C)); zs, hs = [], []
    for W in Ws:
        z = h @ W; zs.append(z)
        h = (h + np.maximum(0, z)) if residual else np.maximum(0, z)
    g = np.ones_like(h) / B; out = []
    for l in reversed(range(depth)):
        back = (g * (zs[l] > 0)) @ Ws[l].T
        g = g + back if residual else back
        out.append(np.linalg.norm(g))
    return out[::-1], h.std()
for name, res, sc in [("plain, He", False, 1.0), ("plain, He x 0.5", False, 0.5), ("residual, He", True, 1.0), ("residual, He x 0.5", True, 0.5), ("residual, He x 0.1", True, 0.1), ("residual, He /sqrt(2N)", True, 1/np.sqrt(2*depth))]:
    n, s = grads(res, sc)
    print(f"{name:<24} grad@layer1 {n[0]:.2e}  grad@layer20 {n[19]:.2e}  forward std {s:.2e}")

plain, He x 0.5          grad@layer1 6.02e-12  grad@layer20 2.30e-06  forward std 9.42e-13
residual, He             grad@layer1 4.35e+09  grad@layer20 1.91e+05  forward std 1.14e+09
residual, He x 0.5       grad@layer1 8.06e+04  grad@layer20 5.07e+02  forward std 1.84e+04
residual, He x 0.1       grad@layer1 9.75e+00  grad@layer20 4.27e+00  forward std 1.68e+00
residual, He /sqrt(2N)   grad@layer1 1.34e+01  grad@layer20 5.33e+00  forward std 2.11e+00

Three findings. First, the plain network with proper He scaling is fine at 40 layers, but cut the weight scale in half (plain, He × 0.5) and its gradient at layer 1 collapses to 6×10−12. Second, the residual network with the full He-scaled branches explodes: the identity path keeps the signal alive but every branch adds a contribution as large as the stream itself. Because ReLU outputs are never negative, the contributions add up coherently instead of cancelling, so the stream grows by a factor of about 1.7 per block and after 40 blocks the activations are of order 109. Third, shrinking the branches (a scale of 0.1, or 1/√(2N) with N = 40 layers) keeps both the forward signal and the gradients at order one at layer 1 and at layer 20. The rule of thumb behind GPT-2's 1/√(2·n_layer): if each of N branches adds an independent contribution of variance v to the stream, the stream's variance grows like N·v, so choosing v proportional to 1/N holds the total roughly constant.

Where the normalisation goes

The original Transformer (Vaswani et al., 2017) applied LayerNorm after the addition: LN(x + F(x)), called post-norm. This puts a normalisation on the skip path, so the highway has a toll booth at every block. GPT-2 and nearly all later large models moved it inside the branch: x + F(LN(x)), pre-norm, as in the figure. Xiong et al. ("On Layer Normalization in the Transformer Architecture", 2020) analysed both at initialisation: with post-norm, the gradients at the output layers are large, which is why post-norm Transformers need a learning-rate warmup (chapter 17) to start stably; with pre-norm they are well behaved and training is more forgiving. The price is that the residual stream's size keeps growing with depth, so pre-norm models normalise once more before the output layer (GPT-2 calls it ln_f). Post-norm can reach slightly better results when it trains successfully, which is why the choice is still discussed.

State of play, October 2026

As far as published technical reports show, the standard recipe for decoder-only language models is pre-norm with RMSNorm in place of LayerNorm, and residual-branch scaling or equivalent initialisation. Variants exist: some recent models add extra normalisation of attention queries and keys, or place normalisation both before and after a sublayer. These are details of stability engineering that move with each model generation. The principles here (keep the per-layer signal gain near one, keep a clean identity path) do not.

Analogy: a relay with a spoken message

Pass a message through a hundred people in a chain. If each whispers a little more quietly, the last person hears nothing; if each shouts slightly louder, the last is deafened. Careful initialisation is asking everyone to repeat at the same volume. Normalisation is giving each person a volume knob that resets the message to a standard loudness. A skip connection is a written copy of the original message passed alongside, which each person may annotate but nobody can erase.

Where it breaks down: in a real relay the message is a single sentence. A network passes thousands of numbers at once, and each layer is allowed, and trained, to change them in ways that carry meaning, so "repeat faithfully" is not the goal. The goal is only that the scale and the gradient neither die nor blow up.

Systems connection

Normalisation does very little arithmetic per element, so on a GPU it is limited by memory traffic rather than by compute (Zero to Systems chapter 21). Production frameworks therefore fuse normalisation with neighbouring operations into a single kernel (A3 chapter 04). The variance computation is also a numerical hazard in half precision: summing squares of large values can overflow float16, which is one reason training uses bfloat16 and keeps the statistics in float32 (A0 chapter 11; chapter 17 here). BatchNorm across several GPUs raises a design question that LayerNorm avoids: compute statistics per device, or exchange them over the interconnect on every step.

Key takeaways

  • Var(z) = n·Var(w)·Var(x): choosing Var(w) = 1/nin (Xavier-like), or 2/nin for ReLU (He), keeps the forward signal at a constant scale. A 20% error in scale compounds over layers.
  • Gradients are products of layer factors, so they vanish or explode exponentially. Sigmoid's slope is at most 0.25, which is why deep sigmoid networks did not train.
  • Sanity checks: the initial loss should be about ln V; look at activation histograms for saturation, not only at the standard deviation.
  • LayerNorm normalises each token over its features and has no batch dependence; BatchNorm normalises each feature over the batch. RMSNorm drops the mean subtraction.
  • A residual connection y = x + F(x) gives gradients an identity path and makes the identity the default; branches must be scaled so the residual stream does not grow with depth. Pre-norm, x + F(LN(x)), is the standard Transformer arrangement.

Check your understanding

A ReLU layer has 512 inputs. What weight standard deviation does He initialisation prescribe?

  1. √(1/512) ≈ 0.044
  2. 2/512 ≈ 0.0039
  3. √(2/512) = 0.0625
  4. 0.02, always
He sets the variance to 2/n_in, so the standard deviation is √(2/512) = 0.0625. The first option is the Xavier-style value that ignores ReLU's halving of the signal. The second forgets to take a square root. A fixed 0.02 is used in GPT-2-style models only because their blocks have normalisation and skip connections.

A 10-layer network uses sigmoid activations. Even with ideal weights, roughly what is the best-case bound on how much the activation slopes alone can shrink the gradient reaching layer 1?

  1. 0.2510, about 10−6
  2. 0.25 × 10, about 2.5
  3. 1 ÷ 10, about 0.1
  4. No shrinkage, if the weights are initialised correctly
Sigmoid's slope is at most 0.25 and the factors multiply over layers. Proper weight scaling does not remove this, because the slope factor is separate from the weight factor. Adding rather than multiplying is the common slip.

A Transformer's activations have shape (B, T, C). Over which axis does LayerNorm compute its mean and variance?

  1. The batch axis B, separately for each token position and feature
  2. The sequence axis T, separately for each example and feature
  3. All three axes together
  4. The feature axis C, separately for each token of each example
LayerNorm normalises each token's vector on its own, which is why it has no dependence on batch size and behaves identically in training and inference. The first option describes BatchNorm (with T also pooled in convolutional use). Normalising over T would mix information between positions, which would break causal masking in a language model.

For y = x + F(x), what is the Jacobian of y with respect to x, and why does it help training?

  1. ∂F/∂x; it makes the layer's output smaller
  2. I + ∂F/∂x; the identity term lets gradients pass through unchanged whatever F does
  3. I × ∂F/∂x; it multiplies gradients to make them larger
  4. 0; the skip connection blocks gradient flow into F
The derivative of x is the identity matrix and the branches add. That identity term is the highway. A product I × ∂F/∂x would be the derivative of F alone and would have no highway. The skip does not block gradient to F: both paths receive it.

Your freshly initialised language model has a vocabulary of 50,257 tokens and prints an initial loss of 187 on its first batch. What is the most likely cause?

  1. The learning rate is too small
  2. The vocabulary is too large for the model width
  3. The final layer's weights (or the embeddings it shares) are far too large, so the logits are huge and confidently wrong
  4. The data are too clean
A uniform guess gives ln 50,257 = 10.8. A loss of 187 means probabilities near zero are assigned to the true tokens, which happens when logits are large. The learning rate has not yet acted at step 0, and vocabulary size alone does not push loss above ln V.

Why do pre-norm Transformers, x + F(LN(x)), usually train more stably than post-norm ones, LN(x + F(x)), without warmup?

  1. The skip path carries x and its gradient without passing through a normalisation layer, so the gradient at initialisation is better behaved
  2. Pre-norm uses fewer parameters
  3. Pre-norm removes the need for residual connections
  4. Pre-norm makes the residual stream stop growing with depth
Putting LN inside the branch leaves a clean identity path (Xiong et al., 2020). The parameter counts are the same. Pre-norm keeps the residual connection. The stream does keep growing with depth in pre-norm, which is why a final LayerNorm is added before the output layer.
