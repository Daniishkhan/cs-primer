Regularising Deep Networks

A network with more parameters than training examples can memorise its training set exactly, and still be useful. This chapter covers the four standard ways to steer it towards the useful answer (weight decay, dropout, data augmentation and early stopping), measures each one on a small problem you can rerun, and ends with the odd finding that making a model bigger can make it generalise better after it has got worse.

Why this matters

Chapters 01 to 03 gave you a network that can fit almost anything and a training run that stays numerically healthy. Fitting is now the easy part. The question that decides whether a model is any use is whether it works on data it has not seen, and with millions of parameters the training loss will happily fall to zero while the held-out loss gets worse. Every deep-learning recipe you will read, from a small image classifier to a large language model, contains regularisation choices: a weight-decay value, a dropout rate, a stopping rule, an augmentation list. After this chapter you will know what each one does mechanically, what it costs, how to tell from a loss curve which one you need, and why "the model has more parameters than data, so it must overfit" is only half true.

Overfitting, seen in a network

Overfitting is the gap that opens when a model learns the particular quirks of its training examples (the noise, the accidents of sampling) instead of the pattern behind them. A1 chapter 1 introduced it with linear models and polynomials, and A1 chapter 6 introduced regularisation: any change to a learning procedure that trades a little training accuracy for better accuracy on new data. This chapter is the deep-learning version of that story. The ideas are the same; the tools differ because a network's capacity comes from its size and its training time, not from a single polynomial degree.

We need a test bed small enough to run in seconds and clean enough that the true answer is known. Take the function sin(2πx) on the interval 0 to 1, draw only 20 training points from it, and add Gaussian noise with standard deviation 0.3 to each label. Train a network with two hidden layers of 64 tanh units (about 4,300 parameters, roughly 200 per training example) using the Adam optimiser from A0 chapter 10, on the mean squared error, with all 20 points in every step. Because we generated the data we also know the noise-free function, so we can measure the real error of the learned curve on a grid of 500 points (the "test" error below). We keep a separate noisy validation set of 100 points for making decisions, exactly as you would with real data.

This shape is the signature to learn. Two curves start together, then separate: the training loss goes on falling, the held-out loss reaches a minimum and climbs. The size of the gap, not the training loss itself, is what tells you how much you are overfitting. If both curves are high and close together, the problem is the opposite one (underfitting) and no regulariser will help; you need a bigger model, a better optimiser setting or more training time.

Common misconception

"Overfitting means the training loss is too low." A low training loss is not the problem, and often it is the goal: a language model trained for one pass over a huge corpus has a training loss that is also its held-out loss. What matters is the gap between the two. Checking only the training loss tells you whether optimisation works; checking the gap tells you whether learning has worked.

Weight decay

Large weights make a network's output change sharply with small changes in the input, which is how it threads a curve through noisy points. The oldest remedy is to penalise them. L2 regularisation adds a term to the loss that grows with the squared size of the weights:

Ltotal(w) = Ldata(w) + (λ/2) ∑ wi2

The gradient of the new term with respect to one weight is λw. So a gradient-descent step with learning rate η becomes

w ← w − η(g + λw) = (1 − ηλ) w − ηg

where g is the gradient of the data loss. Read the right-hand side: before taking the usual step, every weight is multiplied by a number slightly below 1. That is why the same idea is called weight decay: left alone, with no data gradient, each weight would shrink geometrically towards zero. The data gradient pushes weights away from zero where they help; decay pulls everything back; the weights that survive are the ones that earn their size. If you read A0 chapter 13, this is the same as maximum a posteriori estimation with a Gaussian prior on the weights centred on zero: the penalty is the negative log of the prior, and λ says how strongly you believe weights should be small.

L2 in the loss is not the same as decay, once Adam is involved

For plain SGD the two descriptions give identical updates, as the first lines of the script below check. With an adaptive optimiser they do not. Adam divides each weight's gradient by a running estimate of its size. If you put λw into the gradient, the decay term gets divided too, so a weight with large loss gradients is barely decayed and a weight with tiny gradients is decayed at a rate set by the learning rate rather than by λ. Loshchilov and Hutter ("Decoupled Weight Decay Regularization", 2017, published at ICLR 2019) fixed this by applying the shrinkage outside the adaptive step. That optimiser is AdamW, and it is the default for Transformers. Here is the difference on two weights: A is pushed steadily upward by the loss, B has no loss gradient at all.

import numpy as np

# 1. With plain SGD, an L2 penalty and decoupled weight decay are the same update.
lr, lam = 0.1, 0.5
w, g = 2.0, 0.3                                  # a weight and the loss gradient at it
l2_in_loss = w - lr * (g + lam * w)              # gradient of loss + (lam/2) w^2
decoupled  = (1 - lr * lam) * w - lr * g         # shrink first, then the usual step
print("SGD: L2 in the loss", round(l2_in_loss, 4), " decoupled decay", round(decoupled, 4))

# 2. With Adam they are different. Weight A feels a steady push upward (loss gradient -1),
#    weight B has no loss gradient at all. Both start at 1.0.
def adam(steps, lr=0.01, lam=0.1, decoupled=False):
    w = np.array([1.0, 1.0]); m = np.zeros(2); v = np.zeros(2)
    loss_grad = np.array([-1.0, 0.0])
    for t in range(1, steps + 1):
        g = loss_grad + (0 if decoupled else lam * w)           # L2 added to the gradient
        m = 0.9 * m + 0.1 * g; v = 0.999 * v + 0.001 * g * g
        step = (m / (1 - 0.9 ** t)) / (np.sqrt(v / (1 - 0.999 ** t)) + 1e-8)
        if decoupled: w = w - lr * lam * w                       # AdamW: decay outside the adaptive step
        w = w - lr * step
    return w

for steps in (100, 1000):
    print(f"after {steps:4d} Adam steps  (A, B):  L2 in loss {np.round(adam(steps), 3)}   AdamW {np.round(adam(steps, decoupled=True), 3)}")

after  100 Adam steps  (A, B):  L2 in loss [1.981 0.224]   AdamW [1.857 0.905]
after 1000 Adam steps  (A, B):  L2 in loss [ 8.107 -0.   ]   AdamW [6.691 0.368]

Line one confirms the SGD equivalence (both 1.87). The Adam rows are the interesting ones. Weight B should simply decay slowly towards zero, since nothing else acts on it. With the penalty inside the loss it is crushed to 0.224 within 100 steps, and I checked that this number is the same for λ = 0.01, 0.1 and 1, because Adam rescales the tiny gradient λw back up to a step of about the learning rate. Under AdamW the weight follows the smooth exponential (1 − ηλ)t that the formula promises, and λ means what it says. That predictability is why the value can be transferred between runs.

Practical points

  • Which parameters. Decay weight matrices; usually exclude biases and the scale and shift parameters of normalisation layers (chapter 03). They are few, and shrinking a normalisation gain just fights the layer doing its job.
  • How much. It interacts with the learning rate, because the per-step shrinkage is ηλ. PyTorch's torch.optim.AdamW defaults to 0.01. Large-language-model recipes commonly use 0.1: the GPT-3 paper (Brown et al., 2020) says "all models use weight decay of 0.1 to provide a small amount of regularization", and Llama 2 (Touvron et al., 2023) also reports 0.1.
  • It does more than prevent overfitting. With normalisation layers, scale-invariant weights make the decay act mainly on the effective learning rate (van Laarhoven, 2017). That is why large models trained for a single pass over their data still use it.

Dropout

Dropout (Hinton et al., 2012; Srivastava et al., 2014) regularises by damaging the network on purpose. On every training step, each hidden unit is independently set to zero with probability p, as if it had been deleted from the network for that step. The next step draws a fresh random set.

Why would breaking a network help it? Two views, both useful. First, co-adaptation: without dropout, a unit can learn to fix the mistakes of its neighbours, giving a brittle combination that works on the training set and nowhere else. A unit that cannot rely on any particular partner has to learn something useful by itself. Second, implicit ensembling: a layer of n units with dropout is training an exponentially large family of thinned sub-networks (2n of them) that share weights, and the full network at test time behaves like an average over that family. Averaging many different models is the oldest trick for lowering variance (A1 chapter 9), and here it is nearly free.

Inverted dropout: the scaling detail that causes bugs

If a layer feeds ten units into the next one and 25% are zeroed in training, the next layer receives about 25% less input than it will at test time, when nothing is dropped. The fix used everywhere today is inverted dropout: multiply the kept units by 1/(1 − p) during training, so the expected value of each activation is unchanged, and do nothing at test time. The numbers:

import numpy as np
rng = np.random.default_rng(0)
h = np.array([2.0, -1.0, 0.5, 3.0, 1.5, -2.0, 0.8, 1.0])      # activations of one hidden layer
p = 0.25                                                       # probability of dropping a unit

mask = (rng.random(h.shape) >= p) / (1 - p)                    # 0 for dropped, 1/(1-p) = 1.333 for kept
print("mask   :", np.round(mask, 3))
print("h      :", h)
print("h*mask :", np.round(h * mask, 3))

# The mask changes every step, but on average the layer's output is unchanged:
masks = (rng.random((100_000, h.size)) >= p) / (1 - p)
print("mean of h*mask over 100,000 masks:", np.round((h * masks).mean(0), 2))

# Without the 1/(1-p) scaling the average shrinks, and eval mode would see bigger activations:
plain = (rng.random((100_000, h.size)) >= p)
print("mean without scaling             :", np.round((h * plain).mean(0), 2))
print("sum of one layer's inputs, train:", round(float((h * mask).sum()), 2), " eval:", round(float(h.sum()), 2))
mask   : [1.333 1.333 0.    0.    1.333 1.333 1.333 1.333]
h      : [ 2.  -1.   0.5  3.   1.5 -2.   0.8  1. ]
h*mask : [ 2.667 -1.333  0.     0.     2.    -2.667  1.067  1.333]
mean of h*mask over 100,000 masks: [ 2.  -1.   0.5  3.   1.5 -2.   0.8  1. ]
mean without scaling             : [ 1.5  -0.75  0.38  2.25  1.13 -1.5   0.6   0.75]

The first block shows one mask: dropped units become 0, kept units are inflated by 1/(1 − 0.25) = 1.333. The second block averages 100,000 masks and recovers the original activations. The third shows what happens without the scaling: every average is 25% too small, and the last line shows the training-time sum (3.07 for this one mask, a noisy draw) against the evaluation sum 5.8. Dropout noise is real noise: individual training steps see a rough version of the network, which is why dropout slows convergence and why you train longer with it.

Common misconception

"Dropout is applied when the model is used, so predictions are random." Dropout is on in training mode and off in evaluation mode. Forgetting to switch (calling model.eval() in PyTorch) gives noisy, slightly worse predictions at test time, and a test score that changes every time you run it. The reverse mistake (evaluating in training mode, then wondering why validation loss is oddly noisy) is just as common. Keeping dropout on at test time on purpose, and averaging many passes to measure uncertainty, is a real technique ("Monte Carlo dropout", Gal and Ghahramani, 2016), but it is a decision, not an accident.

Where dropout is used now

Rates of 0.1 to 0.5 are typical; Srivastava et al. used 0.5 on hidden layers. The original Transformer (Vaswani et al., 2017) applies dropout of 0.1 to each sub-layer output and to the embeddings in its base model. It matters most where data are scarce relative to model size: small datasets, fine-tuning, recommendation models. Dropout is less common for convolutional layers, where neighbouring activations are strongly correlated and dropping one pixel's feature removes little information, and in normalisation-heavy networks it can interact badly with the statistics those layers estimate.

State of play, October 2026

Many published large-language-model pretraining recipes use little or no dropout, and the reason is in the data rather than the architecture. When each token is seen about once, there is almost no opportunity to memorise it, so the gap to close is small. The GPT-3 paper samples data without replacement "until an epoch boundary is reached" specifically "to minimize overfitting". Muennighoff et al. ("Scaling Data-Constrained Language Models", 2023) found that for a fixed compute budget, up to about 4 epochs of repeated data gave negligible change in loss compared with unique data, after which the value of more repetition decays quickly. Treat both as a snapshot: the balance moves as the supply of fresh text tightens and as models are trained on more passes. Fine-tuning small models on small datasets (the usual case for applied engineers) is back in the regime where dropout, weight decay and early stopping all matter.

Data augmentation

Data augmentation creates extra training examples by applying transformations that you are confident do not change the label. It is regularisation by supplying more (synthetic) data rather than by constraining the model, and it is often the most effective of the four because it injects knowledge you have about the world. A cat flipped left to right is still a cat; an audio clip with a little background noise is still the same sentence.

  • Images: random crops, horizontal flips, small rotations, colour and brightness jitter. AlexNet (Krizhevsky et al., 2012) trained on random 224×224 patches cut from 256×256 images, plus their horizontal reflections. Chapter 07 returns to this.
  • Audio: added noise, time shifts, masking bands of the spectrogram.
  • Text: harder, because small edits can change meaning. Common choices are back-translation (translate to another language and back), word dropout and synonym swaps; for language-model pretraining, usually none.
  • Mixing examples: mixup (Zhang et al., 2017, "mixup: Beyond Empirical Risk Minimization") trains on blends: a random fraction λ of one image plus 1 − λ of another, with the labels blended in the same proportions. Cutout (DeVries and Taylor, 2017) blanks a random square patch.
  • Noise on inputs: adding small Gaussian noise to each input in each step is the simplest augmentation, and it is closely related to L2 regularisation (Bishop, 1995, showed the equivalence for small noise).

Three rules keep augmentation honest. Augment the training set only. Validation and test examples must be untouched, or you are measuring something other than what you will meet in use. Check the label really is preserved. Flipping a photo of the letter "b" turns it into "d", and in a medical scan, left and right are meaningful. Match the real variation. Rotations help if the camera angle varies in production; they only waste capacity if it does not.

Early stopping

The curve in the first figure suggests a regulariser that costs nothing to implement: stop training when the held-out loss stops improving. Early stopping evaluates on a validation set every so often, remembers the weights from the best evaluation, and ends the run if there has been no improvement for a number of evaluations called the patience. When the run ends, you restore the best weights, not the last ones.

  1. After every epoch (or every N steps), compute the loss on the validation set.
  2. If it is the best so far, save a checkpoint of the weights and reset a counter.
  3. Otherwise add one to the counter. When the counter reaches the patience, stop.
  4. Load the saved checkpoint. That is your model.

Why does stopping early act as regularisation? Weights start small, and gradient descent moves them away from zero a little each step. Fewer steps means smaller weights and a smoother function, so the number of steps behaves like the inverse of an L2 penalty strength (for a quadratic loss the two are close to equivalent, as Goodfellow, Bengio and Courville show in Deep Learning, section 7.8). Two cautions. First, patience should be generous for noisy validation curves; with small validation sets a stop signal may be noise. Second, the validation set has now influenced the model: you chose a checkpoint because it scored well there. Report the final number on a separate test set, as A1 chapter 13 and the leakage chapter explain, or the estimate is optimistic.

Comparing them on one problem

All four on the same test bed, eight seeds each, averaged. The script builds the data, the network and Adam by hand in NumPy, so every line of the mechanisms is visible: the dropout mask is applied in the forward pass and reused in the backward pass, weight decay is the decoupled form from above, and jitter perturbs the training inputs afresh each step. The "early stop" column picks, within each run, the epoch with the lowest loss on the noisy validation set, then reports the noise-free test error at that epoch.

import numpy as np

def make_data(seed, n=20, n_val=500, noise=0.3):
    rng = np.random.default_rng(seed)
    f = lambda x: np.sin(2 * np.pi * x)
    x = rng.uniform(0, 1, (n, 1)); y = f(x) + noise * rng.standard_normal((n, 1))
    xv = np.linspace(0, 1, n_val)[:, None]            # test grid: noise-free targets = true error
    xs = rng.uniform(0, 1, (100, 1)); ys = f(xs) + noise * rng.standard_normal((100, 1))  # noisy validation set
    return x, y, xv, f(xv), xs, ys

def init(rng, sizes=(1, 64, 64, 1)):
    return [(rng.standard_normal((a, b)) * np.sqrt(1.0 / a), np.zeros(b)) for a, b in zip(sizes, sizes[1:])]

def forward(P, x, p_drop=0.0, rng=None):
    acts, masks = [x], []
    for i, (W, b) in enumerate(P):
        z = acts[-1] @ W + b
        if i < len(P) - 1:
            h = np.tanh(z)
            if p_drop > 0:                                   # inverted dropout
                m = (rng.random(h.shape) >= p_drop) / (1 - p_drop)
                h = h * m; masks.append(m)
            else:
                masks.append(None)
            acts.append(h)
        else:
            acts.append(z)
    return acts, masks

def backward(P, acts, masks, y):
    n = len(y); g = 2 * (acts[-1] - y) / n; grads = []
    for i in reversed(range(len(P))):
        W, _ = P[i]
        grads.append((acts[i].T @ g, g.sum(0)))
        if i > 0:
            g = g @ W.T
            if masks[i - 1] is not None: g = g * masks[i - 1]
            g = g * (1 - acts[i] ** 2)                       # tanh'
    return grads[::-1]

def mse(P, x, y): return float(np.mean((forward(P, x)[0][-1] - y) ** 2))

def train(seed, epochs=4000, lr=3e-3, wd=0.0, p_drop=0.0, jitter=0.0):
    x, y, xv, yv, xs, ys = make_data(seed); rng = np.random.default_rng(1000 + seed)
    P = init(rng); m = [[np.zeros_like(a) for a in l] for l in P]; v = [[np.zeros_like(a) for a in l] for l in P]
    hist = []
    for t in range(1, epochs + 1):
        xt = x + jitter * rng.standard_normal(x.shape) if jitter else x
        acts, masks = forward(P, xt, p_drop, rng)
        G = backward(P, acts, masks, y)
        for i, layer in enumerate(P):
            for j in range(2):
                g = G[i][j]
                m[i][j] = 0.9 * m[i][j] + 0.1 * g; v[i][j] = 0.999 * v[i][j] + 0.001 * g * g
                step = (m[i][j] / (1 - 0.9 ** t)) / (np.sqrt(v[i][j] / (1 - 0.999 ** t)) + 1e-8)
                if j == 0: layer[j][...] -= lr * wd * layer[j]  # decoupled decay, weights only
                layer[j][...] -= lr * step
        if t % 20 == 0: hist.append((t, mse(P, x, y), mse(P, xs, ys), mse(P, xv, yv)))
    return hist

if __name__ == "__main__":
    configs = {"no regularisation": {}, "weight decay 0.3": dict(wd=0.3), "dropout 0.1": dict(p_drop=0.1),
               "input jitter 0.05": dict(jitter=0.05)}
    print(f"{'setting':20s} {'train':>7s} {'test (end)':>11s} {'test (early stop)':>18s} {'stop epoch':>11s}")
    for name, kw in configs.items():
        runs = [train(s, **kw) for s in range(8)]
        tr = np.mean([h[-1][1] for h in runs]); end = np.mean([h[-1][3] for h in runs])
        pick = [min(h, key=lambda r: r[2]) for h in runs]     # epoch with the lowest noisy-validation loss
        es = np.mean([p[3] for p in pick]); ep = np.mean([p[0] for p in pick])
        print(f"{name:20s} {tr:7.4f} {end:11.4f} {es:18.4f} {ep:11.0f}")

Read the table in three steps. Training error rises as regularisation gets stronger (0.014 up to 0.059): regularised networks fit the training set less closely, which is exactly the point. Test error at the end of training tells you how safe each setting is if you simply run for a fixed budget: with no regularisation it is 0.144, and any of the three regularisers cuts that by 37% (weight decay) to 58% (dropout, jitter). Test error at the best epoch shows something less comfortable: early stopping alone reaches 0.030, and the regularisers do not beat it here. They changed where the best epoch is (610 for no regularisation, about 1,300 to 1,800 with them), and made the final model far less fragile, but on a problem this small, with so little signal to learn, stopping at the right moment was already enough. That finding is specific to this toy. On large networks and real data the methods usually stack, and a fixed training budget with regularisation (no stopping rule) is the norm for large pretraining runs where evaluating often is expensive.

Double descent

The textbook picture (A1 chapter 6) is a U-shape: as a model grows, test error falls, bottoms out, then rises as the model begins to fit noise. Modern networks do not follow the right-hand side of that picture. Zhang et al. ("Understanding deep learning requires rethinking generalization", 2016) showed that standard image networks can fit training sets with completely random labels, so capacity is far more than needed, and yet the same networks generalise when the labels are real. Belkin et al. ("Reconciling modern machine learning practice and the bias-variance trade-off", 2018) and Nakkiran et al. ("Deep Double Descent: Where Bigger Models and More Data Hurt", 2019) described the missing piece. As model size passes the point where the model can just barely fit the training data exactly (the interpolation threshold), test error spikes, and then falls a second time as the model keeps growing. This is double descent.

Nakkiran et al. also found the effect along two other axes. Epoch-wise: for a model near the threshold, test error can fall, rise and fall again as training continues, so stopping at the first minimum is not always optimal. Sample-wise: near the threshold, adding training data can temporarily make test error worse.

The smallest model that shows it

You do not need a neural network to see this. Take linear regression with n = 30 training examples and a model that is allowed to use the first p of 1,000 possible input features. When p is below 30 the fit is a standard least-squares line. When p is 30 or more there are more unknowns than equations, infinitely many weight vectors fit the training data exactly, and we pick the one with the smallest norm (this is what the pseudo-inverse returns, and, for linear models, where gradient descent started at zero ends up). The code uses features whose usefulness and variance decline with their index, which is the situation in real data: a few directions matter, many weak ones barely do.

import numpy as np

n, d, noise, trials = 30, 1000, 0.3, 200      # 30 training examples, up to 1,000 features
scale = np.arange(1, d + 1) ** -0.75           # later features vary less (variance falls as j^-1.5)
beta = np.arange(1, d + 1) ** -1.0 / scale     # true weights: signal concentrated in early features
beta /= np.linalg.norm(beta * scale)           # so the noise-free target has variance 1

def fit(A, y, ridge):
    if ridge == 0:
        return np.linalg.pinv(A) @ y                                    # minimum-norm least squares
    return A.T @ np.linalg.solve(A @ A.T + ridge * np.eye(len(A)), y)   # ridge, written in "dual" form

def run(ps, ridge=0.0):
    tr = {p: [] for p in ps}; te = {p: [] for p in ps}
    for s in range(trials):
        rng = np.random.default_rng(s)
        X = rng.standard_normal((n, d)) * scale; y = X @ beta + noise * rng.standard_normal(n)
        Xt = rng.standard_normal((300, d)) * scale; yt = Xt @ beta
        for p in ps:                                   # the model sees only the first p features
            w = fit(X[:, :p], y, ridge)
            tr[p].append(np.mean((X[:, :p] @ w - y) ** 2)); te[p].append(np.mean((Xt[:, :p] @ w - yt) ** 2))
    return {p: (float(np.mean(tr[p])), float(np.median(te[p]))) for p in ps}

Look at the columns. Training error hits exactly zero at p = 30: the model interpolates. Test error at the same point is 6.4, about fifty times worse than the best earlier value of 0.1264 at p = 10. By p = 1,000 it is 0.0993, below the classical best. The ridge column never spikes.

The mechanism fits in a paragraph. At p slightly below n, least squares is already squeezing the training data hard. At exactly p = n there is a single weight vector that fits the data, and finding it means inverting a matrix whose smallest singular values are tiny (A0 chapter 7). Small singular values amplify noise, so the weights become enormous, and the label noise in the 30 examples is spread into a wild fit. Beyond n, there are many exact fits and the minimum-norm rule picks the gentlest one, and with a long tail of weak features the spare directions soak up the noise at little cost to the prediction. In neural networks the picture is less tidy, but the same ingredients appear: interpolation, an implicit preference for small-norm or smooth solutions from the optimiser and initialisation, and a peak that explicit regularisation flattens. See Bartlett et al. ("Benign Overfitting in Linear Regression", 2019) and Hastie et al. ("Surprises in High-Dimensional Ridgeless Least Squares Interpolation", 2019) for theory, and Schaeffer et al. ("Double Descent Demystified", 2023) for a careful explanation in terms of singular values.

Common misconception

"Double descent means you should always make the model bigger and skip regularisation." No. The second descent is a statement about what can happen, not a guarantee. In this chapter's own regularisation test bed, the network is heavily over-parameterised and still overfits by epoch 4,000 unless something intervenes. The spike is also a warning: a model sitting right at the interpolation threshold is the worst place to be, and a small ridge term or noise in the labels shifts where that is. Finally, in the example above the ridge-penalised model matches or beats the unpenalised one everywhere, so the lesson for practice is that explicit regularisation removes the need to guess where the peak is.

Putting it together

A defensible order of work for a new problem:

  1. Plot training and validation loss together. No gap means you are underfitting; fix capacity or optimisation first.
  2. Add data or augmentation if you can. Cheapest and usually strongest.
  3. Turn on AdamW with a moderate decay (0.01 to 0.1), excluding biases and normalisation parameters.
  4. Add dropout (0.1 to 0.3) if the gap remains, especially with small data or large dense layers.
  5. Use early stopping as a safety net, with a checkpoint of the best weights, and keep a test set untouched until the end.
  6. Change one thing at a time, across several seeds, as the table above did. Differences smaller than the seed-to-seed spread are not findings.

Systems connection

Augmentation is computed fresh every epoch, so for image and audio work the input pipeline can become the bottleneck: random crops and colour jitter run on CPU workers while the GPU waits. That is the usual CPU and accelerator balance. Early stopping needs checkpoints written to durable storage on a schedule, which is the same trade-off between write cost and recovery time as in failure handling. And a stopping rule or dropout seed that is not recorded makes a result impossible to reproduce, the habit A0 chapter 4 builds.

Analogy: revising for an exam

A student can prepare by memorising last year's paper word for word, or by understanding the subject. Weight decay is a rule that you must explain each answer briefly, which discourages elaborate memorised tricks. Dropout is revising with random pages of your notes torn out, so no answer can depend on one particular page. Augmentation is practising on rephrased questions. Early stopping is putting the books down when practice-test scores stop rising.

Where it breaks down: a student knows when they have understood something; a network has no inner sense of this, and the "practice test" is the validation set, which is only an estimate. Use it often and it stops being independent of your choices.

Key takeaways

  • Overfitting is the gap between training and held-out loss. Plot both, always.
  • Weight decay shrinks weights by a factor (1 − ηλ) each step. With Adam, put it outside the adaptive step (AdamW), or its strength depends on gradient size, not on λ.
  • Dropout zeroes random hidden units in training and rescales the survivors by 1/(1 − p) so evaluation needs no change. Always switch to evaluation mode for prediction.
  • Augmentation encodes invariances you know about; apply it to training data only and check the labels survive it.
  • Early stopping restores the best checkpoint; because the validation set picked it, keep a separate test set.
  • Double descent: test error can peak when the model can just fit the data exactly, and fall again as it grows. Explicit regularisation flattens the peak. It is no reason to skip validation.

Check your understanding

A network reaches near-zero training loss, and validation loss has been rising for 30 epochs. Which change is most likely to help?

  1. Train for more epochs so the optimiser can recover
  2. Add dropout or weight decay, or stop at the epoch with the lowest validation loss
  3. Reduce the validation set so it is less noisy
  4. Use a larger learning rate to escape the current solution
Rising validation loss with falling training loss is the overfitting signature, so you want regularisation or an earlier stop. More epochs make the gap wider, not smaller. Shrinking the validation set makes its estimate noisier and does not alter the model. A larger learning rate changes optimisation, not the gap between fit and generalisation.

You switch from Adam with L2 added to the loss to AdamW with the same lambda. A weight whose loss gradient is nearly zero is now decayed

  1. Faster, because the penalty is added to a larger gradient
  2. At the same rate as before, since lambda is unchanged
  3. Not at all, since decoupled decay only applies to large gradients
  4. Slowly and predictably, by a factor of (1 minus learning rate times lambda) per step
In the coupled version Adam rescales the tiny gradient lambda times w back up to a step of roughly the learning rate, so the weight is crushed quickly whatever lambda is. In AdamW the shrinkage factor is applied outside the normalisation, so the rate follows the formula. Decay in AdamW applies to every decayed weight regardless of gradient size, which rules out the third option.

A layer's 100 units each have activation 2.0, and inverted dropout with p = 0.2 is used in training. What is the expected value of one unit's activation after the mask, and how much does a kept unit equal?

  1. Expected 2.0; a kept unit equals 2.5
  2. Expected 1.6; a kept unit equals 2.0
  3. Expected 2.0; a kept unit equals 1.6
  4. Expected 2.5; a kept unit equals 2.5
Kept units are multiplied by 1/(1 - 0.2) = 1.25, so a kept unit is 2.5; it is kept with probability 0.8, so the expected value is 0.8 x 2.5 = 2.0, which is the evaluation-time value. Option 2 describes dropout without rescaling; option 3 has the scaling the wrong way round.

You tune augmentation settings by watching validation accuracy, and you apply the same random crops and flips to the validation images "for consistency". What is the problem?

  1. Nothing: validation data should always match training data exactly
  2. The validation images become too easy, so accuracy falls
  3. Validation now measures performance on distorted images, which is not what you will meet in use, and the comparison between settings is muddied
  4. Augmentation never alters labels, so the results are identical
Augmentation belongs to training: it supplies variety so the model learns invariances. Validation and test sets should resemble deployment data. Applying random transforms to them changes what you measure and adds noise to every comparison. It does not make the task systematically easier, and whether labels survive depends on the transform, so the last option is false too.

In the linear-regression experiment, test error spikes when the number of features p equals the number of examples n = 30. What best explains the spike?

  1. The model has too few parameters to learn anything
  2. There is exactly one exact fit, found through a badly conditioned matrix, so label noise is amplified into huge weights
  3. Gradient descent diverges at that model size
  4. The test set is too small at that point
At p = n the system of equations has a single solution, and solving it needs a matrix with tiny singular values, which inflates noise. Below n the model is simply constrained, above n the minimum-norm choice among many fits is gentle. Nothing here uses gradient descent (the pseudo-inverse is exact) and the test set is the same size at every p.

Which statement about double descent is best supported by this chapter?

  1. Bigger models always generalise better than smaller ones
  2. Regularisation becomes harmful once a model is large enough to interpolate
  3. Test error can rise near the interpolation threshold and fall again beyond it, and explicit regularisation can flatten the peak
  4. Early stopping is useless because the second descent always rescues a model
