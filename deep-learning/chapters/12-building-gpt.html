Building a GPT

Chapters 03, 06, 09, 10 and 11 gave you the parts. This chapter puts them together into one working language model. It is a decoder-only Transformer that reads characters, predicts the next one, and learns from Shakespeare. You will read the whole model line by line. You will train it with a hand-written backward pass that is checked against numerical gradients. You will watch its loss fall past each simple baseline. You will also learn the four tests that catch the commonest bugs before they cost you a training run.

Why this matters

Every large language model you will fine-tune, serve or evaluate is this program with bigger numbers. It has more layers, a wider stream, a subword vocabulary instead of characters, and a cluster instead of a laptop. If you have built the small one, you can read a model's code or a technical report without treating any line as mysterious. You know which numbers in a training log are healthy. You also know why a loss that looks wonderful can still mean a broken model. After this chapter you can write the forward pass of a small language model in NumPy with every tensor shape stated. You can explain what each line of a training loop does and why. You can reproduce a run in about a minute on a laptop. You can also diagnose four classic failures: a wrong starting loss, a model that cannot memorise one batch, a leak from the future, and wrong gradients. The chapter follows the structure of Andrej Karpathy's nanoGPT and his lecture that builds the same model, from the Zero to Hero series. Both are worth watching alongside (the lecture is linked under further reading). The explanations and code here are written fresh for this course.

What we are building

A language model is a program that assigns a probability to the next piece of text given the text so far. Ask it what follows "Before we proceed any further, hear me" and a good one puts most of its probability on " speak". A GPT (Generative Pre-trained Transformer, the name OpenAI gave its 2018 model) is a language model built from the decoder-only Transformer of chapter 10. It is autoregressive. To produce text it predicts one piece, appends it to the text so far, and predicts again. Training and generation are two uses of the same function. That function maps the text so far to a distribution over what comes next.

The text is cut into tokens, the units the model reads and writes. Real models use subword tokens, which chapter 13 builds. Here a token is a single character. That keeps the vocabulary tiny (65 symbols) and lets every idea show up with nothing in the way. The data is the "tiny Shakespeare" file that Karpathy prepared for his 2015 character-level experiments with a recurrent neural network (RNN). It holds 1,115,394 characters of speeches from several plays, in plain text. Speaker names are in capitals followed by a colon. The task is to read up to T = 64 characters and predict the one after.

Four decisions define the project, and the rest of the chapter takes them in order.

  1. Data. Turn text into integer ids, hold some of it back for validation, and cut random windows from the rest.
  2. Model. An embedding table, L Transformer blocks, a final normalisation and an output head. This is the architecture of chapter 10, with five size parameters.
  3. Objective. At every position, the cross-entropy between the model's predicted distribution and the character that actually came next (chapter 14 treats this objective in depth).
  4. Optimisation. Backpropagation to get gradients, then AdamW with a warmed-up, decaying learning rate and gradient clipping.

Analogy: reading with the next word covered

Imagine learning a language by reading a book with a card over the next word. At every word you guess what is under the card, lift it, and note how surprised you were. After a million guesses you have learned spelling, common phrases, the layout of a play script and a little of what characters tend to say. A language model is trained exactly this way. The difference is that it keeps the score as a number (the loss) and adjusts its weights to be less surprised next time.

Where it breaks down: a reader guesses one word at a time and remembers the whole book. The model processes a window of 64 characters in parallel, as 64 guesses at once. It remembers nothing outside the window except what it stored in its weights. The next section shows how one window becomes 64 guesses.

One window is many examples

A training example is a window. It is a run of T consecutive characters, written x, paired with y, the same window shifted one character to the right. The last lines of the output show it. With x = " are all" the target y is "are all ". At every position t, the model sees x[0..t] and must produce y[t], the character that follows. Position 0 sees " " and must say "a". Position 3 sees " are" and must say " ". Position 7 sees " are all" and must say " ". One window of T characters is T prediction problems, all solved by a single forward pass. This is why the causal mask of chapter 09 is essential. If position 3 could read x[4], it would be reading its own answer.

Training data comes as a batch. A batch is B independent windows stacked into integer arrays x and y of shape (B, T), so the GPU or CPU can process them with the same matrix multiplications. Windows start at random offsets. So no sample is cut at a fixed boundary, and the model sees the file in a different slicing every step. With B = 32 and T = 64, one step processes 2,048 characters, which means 2,048 predictions. Play with the explorer to see how the window, the shift and the mask fit together.

Why hold some text back



The training script keeps the last 10% of the file (111,540 characters) for validation. This is text the model never trains on. It is used to measure whether the model has learned something general or merely memorised the examples it saw. The training loss tells you how well the model fits the data you let it study. The validation loss is the honest number. Everything the chapter quotes as "val" comes from that held-out tenth. One caution is specific to this file. The last tenth comes from different plays than the first nine tenths. So some gap between training and validation loss is a difference in material rather than overfitting. For a serious study you would shuffle at the level of plays or documents.



The model, line by line



Figure 2 is the whole model with its tensor shapes and parameter counts. It is the skeleton of chapter 10 with every size filled in. B = 32 windows of T = 64 token ids go in. A table of 65 vectors of width C = 64 turns ids into (32, 64, 64) activations. A learned position vector is added, and two blocks refine the stream. A final LayerNorm and the transposed embedding table turn each position's vector into 65 scores. The total is 108,352 weights, of which 9 in 10 sit in the blocks.





The code is below, in three parts. First come the configuration and the initialisation. Every size in the model derives from five numbers, so scaling this model up is a matter of editing one line. The initialisation follows GPT-2. All matrices are drawn from a normal distribution with standard deviation 0.02. Biases start at zero and LayerNorm gains at one. The two matrices that write into the residual stream, Wo and W2, are shrunk by 1/√(2L) so that 2L additions do not inflate the stream (chapter 03 derived this). With such small weights the logits begin close to zero. That is what we want, because a model that starts out knowing nothing should predict about the same probability for every character.



import math
import numpy as np

# ---- configuration: every size in the model comes from these five numbers ----
CFG = dict(V=65, T=64, C=64, h=4, L=2)     # vocab, context length, width, heads, layers

def init_params(cfg, seed=0):
    """GPT-2 style initialisation: N(0, 0.02), residual projections shrunk by 1/sqrt(2L)."""
    rng = np.random.default_rng(seed)
    V, T, C, L = cfg["V"], cfg["T"], cfg["C"], cfg["L"]
    w = lambda *shape, s=0.02: rng.normal(0.0, s, shape)
    p = {"wte": w(V, C), "wpe": w(T, C), "lnf_g": np.ones(C), "lnf_b": np.zeros(C)}
    for i in range(L):
        p.update({
            f"{i}.ln1_g": np.ones(C), f"{i}.ln1_b": np.zeros(C),
            f"{i}.Wqkv": w(C, 3 * C), f"{i}.bqkv": np.zeros(3 * C),
            f"{i}.Wo": w(C, C, s=0.02 / math.sqrt(2 * L)), f"{i}.bo": np.zeros(C),
            f"{i}.ln2_g": np.ones(C), f"{i}.ln2_b": np.zeros(C),
            f"{i}.W1": w(C, 4 * C), f"{i}.b1": np.zeros(4 * C),
            f"{i}.W2": w(4 * C, C, s=0.02 / math.sqrt(2 * L)), f"{i}.b2": np.zeros(C),
        })
    return p



Second come the building blocks. These are the functions from chapters 03, 09 and 10, with one change from chapter 10. The tanh form of GELU (Gaussian error linear unit) uses the constant 0.79788…, which is √(2/π). softmax subtracts the row maximum before exponentiating (the stable form from chapter 11). attention does six things. It projects once with a (C, 3C) matrix and splits the result into queries, keys and values. It reshapes so each head has its own axis. It scores every pair with a scaled dot product. It replaces scores above the diagonal by −∞, so that the softmax gives them exactly zero weight. Finally it merges the heads back before the output projection. The flag causal exists only so that we can switch the mask off later, to see what the bug looks like.



def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

def layernorm(x, g, b, eps=1e-5):                       # over the last axis (C)
    xh = (x - x.mean(-1, keepdims=True)) / np.sqrt(x.var(-1, keepdims=True) + eps)
    return xh * g + b

def gelu(x):                                            # tanh approximation, as in GPT-2
    return 0.5 * x * (1 + np.tanh(0.7978845608028654 * (x + 0.044715 * x**3)))

def attention(x, p, i, h, causal=True):                 # x: (B, T, C)
    B, T, C = x.shape
    q, k, v = np.split(x @ p[f"{i}.Wqkv"] + p[f"{i}.bqkv"], 3, axis=-1)
    heads = lambda t: t.reshape(B, T, h, C // h).transpose(0, 2, 1, 3)   # (B, h, T, d_k)
    q, k, v = heads(q), heads(k), heads(v)
    s = q @ k.transpose(0, 1, 3, 2) / math.sqrt(C // h)                  # (B, h, T, T)
    if causal:
        s = np.where(np.triu(np.ones((T, T), bool), 1), -np.inf, s)      # no peeking right
    o = softmax(s) @ v                                                   # (B, h, T, d_k)
    return o.transpose(0, 2, 1, 3).reshape(B, T, C) @ p[f"{i}.Wo"] + p[f"{i}.bo"]



Third come the model itself and the loss. forward is eight lines. The embedding lookup p["wte"][idx] turns a (B, T) array of ids into (B, T, C) vectors by picking rows. p["wpe"][:T] is a (T, C) table of learned position vectors that broadcasts across the batch. Each block adds an attention correction and a correction from its multi-layer perceptron (MLP) to the stream. After the last block comes one more LayerNorm, then the output head. Multiplying by the transposed embedding table scores each position's vector against all 65 characters. The model returns logits, raw scores that can be any real number. No softmax is applied inside the model. The loss function wants logits, because it combines softmax and logarithm in one stable step. Generation will apply its own softmax. cross_entropy averages −log p(correct character) over all B·T positions. Chapter 14 explains why this is the right number to minimise.



def forward(p, idx, cfg, causal=True):
    """idx: (B, T) integer token ids  ->  logits: (B, T, V)."""
    B, T = idx.shape
    x = p["wte"][idx] + p["wpe"][:T]                    # (B, T, C): token + position
    for i in range(cfg["L"]):
        x = x + attention(layernorm(x, p[f"{i}.ln1_g"], p[f"{i}.ln1_b"]), p, i, cfg["h"], causal)
        m = layernorm(x, p[f"{i}.ln2_g"], p[f"{i}.ln2_b"])
        x = x + gelu(m @ p[f"{i}.W1"] + p[f"{i}.b1"]) @ p[f"{i}.W2"] + p[f"{i}.b2"]
    x = layernorm(x, p["lnf_g"], p["lnf_b"])
    return x @ p["wte"].T                               # tied output head: (B, T, V)

def cross_entropy(logits, targets):
    """Mean over all B*T positions of -log p(target), computed stably."""
    z = logits - logits.max(-1, keepdims=True)
    logp = z - np.log(np.exp(z).sum(-1, keepdims=True))
    return -np.take_along_axis(logp, targets[..., None], -1).mean()

    p = init_params(CFG)
    n = sum(a.size for a in p.values())
    print("parameters:", f"{n:,}")
    rng = np.random.default_rng(1)
    idx = rng.integers(0, CFG["V"], size=(4, CFG["T"]))
    tgt = rng.integers(0, CFG["V"], size=(4, CFG["T"]))
    logits = forward(p, idx, CFG)
    print("logits shape:", logits.shape)
    print("initial loss: %.4f   ln(V) = %.4f" % (cross_entropy(logits, tgt), math.log(CFG["V"])))
    idx2 = idx.copy(); idx2[:, -1] = (idx2[:, -1] + 1) % CFG["V"]      # change only the last token
    d = np.abs(forward(p, idx2, CFG) - logits).max(axis=(0, 2))
    print("logits that changed when the last token changed:", np.flatnonzero(d > 0))

Common misconception

  
"The model reads a sentence and predicts the next word, once." During training the model makes a prediction at every position of every window, and all of them contribute to the loss. A batch of 32 windows of 64 characters supplies 2,048 learning signals, not 32. At generation time only the last position's prediction is used, and the others are thrown away. Seeing this removes most of the confusion about why the causal mask matters. It also shows why training is so much more efficient than step-by-step generation.





Learning: the backward pass



To train, we need the gradient of the loss with respect to all 108,352 weights. In PyTorch you write loss.backward(), and autograd builds the backward pass from the forward code (chapters 02 and 05 of this course, and chapter 09 of A0). Here we write it by hand, for two reasons. No part of the machine is hidden, and NumPy has no autograd. The pattern is always the same. Each operation in the forward pass saves what its derivative will need. The backward pass walks the operations in reverse. It turns "how the loss changes with my output" into "how the loss changes with my input and my weights".



Most pieces are ones you have met. The loss's gradient with respect to the logits is the most elegant: softmax probabilities minus the one-hot target, divided by the number of positions. Chapter 14 proves it, and the script checks it numerically. LayerNorm's gradient has the compact form inv * (dxh - mean(dxh) - xh * mean(dxh * xh)) that chapter 03 derived. Attention's backward is two matrix products for the values. Then comes the softmax Jacobian trick p * (dp - sum(dp * p)). Then come two more matrix products for the queries and keys. The residual connections matter in the backward pass too. Wherever the forward code computes x = x + f(x), the gradient arriving at x is passed straight through the addition and sent through f. The two are then added. Finally, the embedding matrix is used twice, to look up inputs and as the output head. Its gradient is the sum of both contributions. Read the listing with those five facts in mind.



Go deeper: the hand-written backward pass optional, about 110 lines

import math
import numpy as np
from gpt_model import CFG, init_params, forward, softmax, cross_entropy

# Each op returns (output, cache); the backward pass reads the cache. PyTorch's autograd does this for you.

def ln_fwd(x, g, b, eps=1e-5):
    inv = 1.0 / np.sqrt(x.var(-1, keepdims=True) + eps)
    xh = (x - x.mean(-1, keepdims=True)) * inv
    return xh * g + b, (xh, inv, g)

def ln_bwd(dy, c):
    xh, inv, g = c
    dxh = dy * g
    dx = inv * (dxh - dxh.mean(-1, keepdims=True) - xh * (dxh * xh).mean(-1, keepdims=True))
    return dx, (dy * xh).sum((0, 1)), dy.sum((0, 1))

def gelu_fwd(x):
    u = 0.7978845608028654 * (x + 0.044715 * x**3); t = np.tanh(u)
    return 0.5 * x * (1 + t), (x, t)

def gelu_bwd(dy, c):
    x, t = c
    du = 0.7978845608028654 * (1 + 3 * 0.044715 * x**2)
    return dy * (0.5 * (1 + t) + 0.5 * x * (1 - t**2) * du)

def lin_bwd(dy, x, W):                                  # y = x @ W + b, x: (B, T, n)
    return dy @ W.T, x.reshape(-1, x.shape[-1]).T @ dy.reshape(-1, dy.shape[-1]), dy.sum((0, 1))

def attn_fwd(x, W, b, Wo, bo, h, causal=True):
    B, T, C = x.shape
    q, k, v = np.split(x @ W + b, 3, axis=-1)
    hd = lambda t: t.reshape(B, T, h, C // h).transpose(0, 2, 1, 3)
    q, k, v = hd(q), hd(k), hd(v)
    s = q @ k.transpose(0, 1, 3, 2) / math.sqrt(C // h)
    if causal:
        s = np.where(np.triu(np.ones((T, T), bool), 1), -np.inf, s)
    p = softmax(s)
    om = (p @ v).transpose(0, 2, 1, 3).reshape(B, T, C)
    return om @ Wo + bo, (x, q, k, v, p, om)

def attn_bwd(dy, c, W, Wo, h):
    x, q, k, v, p, om = c
    B, T, C = x.shape
    dom, dWo, dbo = lin_bwd(dy, om, Wo)
    do = dom.reshape(B, T, h, C // h).transpose(0, 2, 1, 3)              # (B, h, T, d_k)
    dp = do @ v.transpose(0, 1, 3, 2)
    dv = p.transpose(0, 1, 3, 2) @ do
    ds = p * (dp - (dp * p).sum(-1, keepdims=True)) / math.sqrt(C // h)  # softmax backward
    dq, dk = ds @ k, ds.transpose(0, 1, 3, 2) @ q
    mg = lambda t: t.transpose(0, 2, 1, 3).reshape(B, T, C)
    dqkv = np.concatenate([mg(dq), mg(dk), mg(dv)], axis=-1)
    dx, dW, db = lin_bwd(dqkv, x, W)
    return dx, dW, db, dWo, dbo

def loss_and_grads(p, idx, tgt, cfg, causal=True):
    h, L = cfg["h"], cfg["L"]
    B, T = idx.shape
    x = p["wte"][idx] + p["wpe"][:T]
    caches = []
    for i in range(L):
        a, c1 = ln_fwd(x, p[f"{i}.ln1_g"], p[f"{i}.ln1_b"])
        y, c2 = attn_fwd(a, p[f"{i}.Wqkv"], p[f"{i}.bqkv"], p[f"{i}.Wo"], p[f"{i}.bo"], h, causal)
        x = x + y
        m, c3 = ln_fwd(x, p[f"{i}.ln2_g"], p[f"{i}.ln2_b"])
        u = m @ p[f"{i}.W1"] + p[f"{i}.b1"]
        gu, c4 = gelu_fwd(u)
        x = x + gu @ p[f"{i}.W2"] + p[f"{i}.b2"]
        caches.append((c1, c2, c3, m, c4, gu))
    xf, cf = ln_fwd(x, p["lnf_g"], p["lnf_b"])
    logits = xf @ p["wte"].T
    loss = cross_entropy(logits, tgt)

    # ---- backward ----
    g = {}
    dlog = softmax(logits)
    np.put_along_axis(dlog, tgt[..., None], np.take_along_axis(dlog, tgt[..., None], -1) - 1, -1)
    dlog /= B * T                                       # d loss / d logits = (p - onehot) / N
    g["wte"] = dlog.reshape(-1, dlog.shape[-1]).T @ xf.reshape(-1, xf.shape[-1])   # head use of the tied matrix
    dx, g["lnf_g"], g["lnf_b"] = ln_bwd(dlog @ p["wte"], cf)
    for i in reversed(range(L)):
        c1, c2, c3, m, c4, gu = caches[i]
        dgu, g[f"{i}.W2"], g[f"{i}.b2"] = lin_bwd(dx, gu, p[f"{i}.W2"])
        dm, g[f"{i}.W1"], g[f"{i}.b1"] = lin_bwd(gelu_bwd(dgu, c4), m, p[f"{i}.W1"])
        dxn, g[f"{i}.ln2_g"], g[f"{i}.ln2_b"] = ln_bwd(dm, c3)
        dx = dx + dxn                                   # the skip connection adds its own gradient path
        da, g[f"{i}.Wqkv"], g[f"{i}.bqkv"], g[f"{i}.Wo"], g[f"{i}.bo"] = attn_bwd(dx, c2, p[f"{i}.Wqkv"], p[f"{i}.Wo"], h)
        dxn, g[f"{i}.ln1_g"], g[f"{i}.ln1_b"] = ln_bwd(da, c1)
        dx = dx + dxn
    g["wpe"] = np.zeros_like(p["wpe"]); g["wpe"][:T] = dx.sum(0)
    np.add.at(g["wte"], idx, dx)                        # embedding use of the tied matrix
    return loss, g

    rng = np.random.default_rng(0)
    p = init_params(cfg, seed=3)
    for k in p:                                         # larger weights make the check informative
        p[k] = p[k] + 0.3 * rng.normal(size=p[k].shape) * (p[k].ndim > 1)
    idx, tgt = rng.integers(0, 11, (3, 6)), rng.integers(0, 11, (3, 6))
    loss, g = loss_and_grads(p, idx, tgt, cfg)
    print("training forward matches inference forward:",
          np.isclose(loss, cross_entropy(forward(p, idx, cfg), tgt)))
    worst = {}
    for k in p:
        flat = p[k].reshape(-1); num = np.zeros(flat.size)
        for j in range(flat.size):
            old = flat[j]; e = 1e-6
            flat[j] = old + e; lp = cross_entropy(forward(p, idx, cfg), tgt)
            flat[j] = old - e; lm = cross_entropy(forward(p, idx, cfg), tgt)
            flat[j] = old; num[j] = (lp - lm) / (2 * e)
        a = g[k].reshape(-1)
        worst[k] = np.abs(a - num).max() / (np.abs(a).max() + np.abs(num).max() + 1e-12)
    for k in ["wte", "wpe", "0.ln1_g", "0.Wqkv", "0.Wo", "0.W1", "1.W2", "lnf_b"]:
        print(f"  {k:8s} relative error {worst[k]:.1e}")
    print("worst over all", len(p), "tensors: %.1e" % max(worst.values()))


The helper pairs ln_fwd/ln_bwd, gelu_fwd/gelu_bwd and attn_fwd/attn_bwd each return a cache from the forward direction that the backward direction consumes. lin_bwd is the backward pass of y = x W + b. It returns the gradient for x (dy @ W.T). It returns the gradient for W (the inputs, flattened over batch and time, transposed, times the output gradients). It returns the gradient for b (the sum of dy). In loss_and_grads the first half is the forward pass again, saving caches. The second half runs it backwards. The line np.add.at(g["wte"], idx, dx) is the embedding gradient. Each position adds its incoming gradient to the row of the character that was looked up. It accumulates when a character occurs several times.





A hand-written backward pass is exactly the kind of code that is easy to get subtly wrong. A subtly wrong gradient does not crash anything. The loss falls more slowly than it should, or plateaus. So the file ends with the third test, a gradient check. It shrinks the model (11 characters, 6 positions, width 8) and nudges each of its weights up and down by 10−6. It measures the change in the loss. It then compares the resulting slope with what the backward pass reports.

The training loop



The loop does five things at each step: draw a batch, compute loss and gradients, clip the gradients, set the learning rate, and update the weights. The optimiser is AdamW (Loshchilov and Hutter, 2017; chapter 10 of A0 builds it). It keeps a running average of each weight's gradient (first moment, decay 0.9) and of its square (second moment, decay 0.99). It divides one by the square root of the other, so that every weight takes steps of a similar size. It also applies weight decay directly to the weights rather than through the gradient. Decay is applied only to matrices (ndim ≥ 2), not to biases or LayerNorm gains. The nanoGPT code follows the same convention. Three more details make the first steps safe.



    
  
  • Learning-rate warmup: the rate climbs linearly from nearly zero to its peak (3×10−3) over 100 steps. Adam's second-moment estimate is unreliable in the first few steps. A large step taken on a poor estimate can throw a model somewhere it never recovers from.
    • 
  
  • Cosine decay: after warmup, the rate follows half a cosine wave down to a tenth of the peak. Late updates are then small, and the weights settle instead of jittering around the minimum.
    • 
  
  • Gradient clipping: if the gradient's global norm exceeds 1, all of it is scaled down to length 1. The global norm is the length of all gradients taken together as one long vector. One unusual batch then cannot produce an enormous update. Chapter 17 returns to this as one of the stability tools of large runs.
    • 




import math, sys, time
import numpy as np
from gpt_model import CFG, init_params, forward, cross_entropy, softmax
from gpt_grad import loss_and_grads

text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))                                  # the vocabulary: every distinct character
stoi = {c: i for i, c in enumerate(chars)}
encode = lambda s: np.array([stoi[c] for c in s])
decode = lambda ids: "".join(chars[i] for i in ids)
data = encode(text)
n = int(0.9 * len(data))
train, val = data[:n], data[n:]
print(f"{len(text):,} characters, vocabulary {len(chars)}, train {len(train):,} / val {len(val):,}")

B, T = 32, CFG["T"]
def get_batch(d, rng):
    ix = rng.integers(0, len(d) - T - 1, B)                # B random windows
    x = np.stack([d[i:i + T] for i in ix])                 # (B, T)   inputs
    y = np.stack([d[i + 1:i + T + 1] for i in ix])         # (B, T)   the same windows shifted by one
    return x, y

p = {k: v.astype(np.float32) for k, v in init_params(CFG).items()}
m = {k: np.zeros_like(v) for k, v in p.items()}            # Adam first moments
v2 = {k: np.zeros_like(v) for k, v in p.items()}           # Adam second moments
steps, warmup, lr_max, lr_min, wd = 3000, 100, 3e-3, 3e-4, 0.1
every = int(sys.argv[1]) if len(sys.argv) > 1 else 500

def lr_at(t):                                              # linear warmup, then cosine decay
    if t < warmup: return lr_max * (t + 1) / warmup
    r = (t - warmup) / (steps - warmup)
    return lr_min + 0.5 * (1 + math.cos(math.pi * r)) * (lr_max - lr_min)

def estimate(d, k=20):                                     # mean loss over k random batches
    rng = np.random.default_rng(0)                         # the same batches every time
    return float(np.mean([cross_entropy(forward(p, x, CFG), y) for x, y in (get_batch(d, rng) for _ in range(k))]))

rng, t0 = np.random.default_rng(1337), time.time()
for t in range(steps + 1):
    if t % every == 0:
        print(f"step {t:4d}  lr {lr_at(min(t, steps - 1)):.1e}  train {estimate(train):.3f}  val {estimate(val):.3f}  ({time.time() - t0:.0f}s)")
    if t == steps: break
    x, y = get_batch(train, rng)
    loss, g = loss_and_grads(p, x, y, CFG)
    norm = math.sqrt(sum(float((a * a).sum()) for a in g.values()))
    clip = min(1.0, 1.0 / (norm + 1e-6))                   # gradient clipping at global norm 1
    lr = lr_at(t)
    for k in p:
        gk = g[k] * clip
        m[k] = 0.9 * m[k] + 0.1 * gk
        v2[k] = 0.99 * v2[k] + 0.01 * gk * gk
        mh, vh = m[k] / (1 - 0.9 ** (t + 1)), v2[k] / (1 - 0.99 ** (t + 1))
        if p[k].ndim >= 2: p[k] -= lr * wd * p[k]          # decoupled weight decay on matrices only
        p[k] -= lr * mh / (np.sqrt(vh) + 1e-8)

np.savez("gpt.npz", **p)

def generate(prompt, n_new, seed=0):
    r = np.random.default_rng(seed)
    ids = list(encode(prompt))
    for _ in range(n_new):
        ctx = np.array(ids[-T:])[None]                     # at most the last T characters
        probs = softmax(forward(p, ctx, CFG)[0, -1])       # distribution over the next character
        ids.append(r.choice(len(probs), p=probs / probs.sum()))
    return decode(ids)

The log prints training and validation loss every 500 steps. Each is averaged over the same 20 batches so that the numbers are comparable from line to line. The run takes about a minute on a laptop CPU with NumPy, using a single thread's worth of arithmetic. Step through one iteration below, then look at the whole curve.




  
Step through
One training step, forwards then backwards

  
  
    
    
  1. Draw a batch. get_batch cuts 32 random windows: x and y, both (32, 64) integers, y being x shifted by one.
    2. 
    
  2. Embed. Each id becomes the row of the character table, and the position vector of its slot is added. Shape (32, 64, 64).
    3. 
    
  3. Blocks. Two blocks of attention and MLP write corrections into the residual stream. Shape is unchanged.
    4. 
    
  4. Head. A final LayerNorm and the transposed character table give 65 logits at each of the 2,048 positions.
    5. 
    
  5. Loss. Softmax, then the negative log probability of the true next character, averaged over all 2,048 positions: one number. Early in training it is about 4.17.
    6. 
    
  6. Backward. The gradient with respect to the logits is (softmax − one-hot) divided by 2,048, and it is pushed back through the head, the blocks and the embedding, producing one gradient for each of the 108,352 weights.
    7. 
    
  7. Update. Clip the gradient's global norm to 1, then take one AdamW step with this step's learning rate. The weights are the only thing that persists between steps.
    8. 
    
  8. Repeat. The next batch is different text, so the loss moves around from step to step. The log averages 20 batches to smooth that noise.
    9. 
  





Reading the loss curve



The log is more informative when put next to what simple counting methods achieve on the same validation text. The dashed lines in the figure are computed from character counts in the training file (chapter 14 explains the models behind them). Guessing uniformly costs ln 65 = 4.17 nats. A model that knows only how often each character occurs costs 3.35. One that knows which character tends to follow the previous one costs 2.49. One that looks at the previous four characters costs 1.67.





Three things stand out. The curve passes each baseline in order. First the model learns which characters are common (4.17 to 3.35 within the warmup). Then it learns which pairs go together (to 2.49 by step 150). Only after that does attention begin to use longer context. Models learn the statistics of language in roughly increasing order of context length. The tiny GPT does not beat the 5-gram table. That is not a failure. The count model stores hundreds of thousands of context-to-next-character entries. The GPT has 108,352 weights, and it is 1.4 minutes of training away from where its architecture could take it. The GPT's case is that its parameters scale smoothly and generalise. A table of 8-character contexts would be astronomically large and mostly empty, while a Transformer gets bigger and better. Validation sits above training by 0.17 nats at the end. With 108k weights and 6 passes over a million characters, memorisation is not the whole story. As noted above, the validation text is also different material. The gap would widen if training continued. In the 10.8-million-weight nanoGPT configuration, which can really memorise this file, the model overfits within a few thousand steps. Its recipe therefore adds dropout of 0.2 and saves only the checkpoint with the best validation loss.

Sampling from the trained model



Generation is the training forward pass used in a loop. Encode a prompt and run the model. Take the logits of the last position and turn them into probabilities with a softmax. Choose a character, append it, and repeat. The model never sees more than its last T characters, so the loop crops the context (ids[-T:]) once the text outgrows the window. The function generate at the bottom of train.py chooses by drawing from the full distribution. That is the simplest option, and it matches what the model was trained to produce. Chapter 15 covers the alternatives: greedy choice, temperature, top-k, top-p and beam search. All of them are variations on that one line.



The sample printed at the end of the training output begins with the prompt ROMEO: and continues for 280 characters. It reproduces the format of the file with surprising fidelity. It has speaker names in capitals followed by colons, short lines, line breaks after clauses, and an occasional exclamation mark or question mark. It spells words that are almost right ("gentlest", "soveres", "haste"), but its grammar and meaning are nonsense. This is a recognisable fingerprint of a small character model. It has learned the statistics of spelling and layout, which are local. It has not learned sense, which needs far more capacity and data. Add more layers, more width and more text, and the same program produces coherent paragraphs. Nothing about the method changes.



One inefficiency to note: each new character repeats the full forward pass over the whole 64-character context, although the keys and values of the earlier positions have not changed. Real inference engines save them in a KV cache and compute only the new position. A3 chapter 18 covers it. For a model this small the waste does not matter.



What the heads do



The attention weights are available at no extra cost, since attention computes them on the way to the output. Looking at them is a good habit. The figure shows two heads of the trained model on the first 28 characters of the file. Each row is a query position and each column a position it may read. A stronger colour means more weight, and the faint upper triangle is the causal mask. Layer 1 head 4 is a "recent history" head. It puts about 0.39 of its weight on the previous character on average. The figures come from attn_probe.py in the course materials, a direct copy of the attention code that also returns the weights. A head in layer 2 spreads its attention widely, with an average look-back of about 14 characters.





No one told the heads to do this. The first layer's heads are mostly local because local context is where most of the predictable information lies. That means the previous one or two characters. The second layer combines that into broader summaries. Careful studies of larger models have found sharper, more specialised heads. One example is a head that copies a token that followed an earlier occurrence of the current one (Olsson et al., 2022, "In-context learning and induction heads"). A two-layer model with 64-wide streams is too small to be a good example of that. Read the maps above as illustration, not as evidence of a particular mechanism.



Four tests before you trust a model



The expensive bugs in model code are silent. A wrong mask, an off-by-one in the targets or a faulty gradient does not stop the program. It produces a number that looks plausible and trains something that is not what you meant. The defence is a short set of tests that are cheap to run. Every new model implementation should pass them. We have met three. The fourth is below.

Test 2 is the most useful one in day-to-day work, because it exercises the whole pipeline (data, model, loss, optimiser) on a problem that must be solvable. The script below runs it. It then runs the opposite experiment, the bug that tests 1 and 3 are designed to catch. It trains the same model with the causal mask removed.



import math, numpy as np
from gpt_model import CFG, init_params, forward, cross_entropy
from gpt_grad import loss_and_grads

data = np.array([stoi[c] for c in text]); n = int(0.9 * len(data)); train, val = data[:n], data[n:]
T = CFG["T"]

def batch(d, rng, B=32):
    ix = rng.integers(0, len(d) - T - 1, B)
    return np.stack([d[i:i + T] for i in ix]), np.stack([d[i + 1:i + T + 1] for i in ix])

def fit(steps, causal=True, fixed=None, lr=3e-3, seed=0):
    p = {k: v.astype(np.float32) for k, v in init_params(CFG).items()}
    m = {k: np.zeros_like(v) for k, v in p.items()}; v2 = {k: np.zeros_like(v) for k, v in p.items()}
    rng, curve = np.random.default_rng(seed), []
    for t in range(steps):
        x, y = fixed if fixed else batch(train, rng)          # `fixed`: the same single batch every step
        loss, g = loss_and_grads(p, x, y, CFG, causal)
        for k in p:
            m[k] = 0.9 * m[k] + 0.1 * g[k]; v2[k] = 0.99 * v2[k] + 0.01 * g[k] ** 2
            p[k] -= lr * (m[k] / (1 - 0.9 ** (t + 1))) / (np.sqrt(v2[k] / (1 - 0.99 ** (t + 1))) + 1e-8)
        curve.append(loss)
    return p, curve

The mask was the only thing between a model that learns the language and one that learns to look ahead.




  
Common misconception

  
"A lower loss means a better model." A lower loss on the problem you meant to set means a better model. The leaky model above has the lowest loss of any run in this chapter and cannot produce a single useful character. Any metric can be gamed by a bug that gives the model information it will not have at use time. The defence is to evaluate the way the model will be used. Generate, or score with the same masks and inputs that production will have. Treat results that are much better than a simple baseline (here, the 5-gram table at 1.67) as a reason for suspicion before celebration. The same applies to test-set contamination, the evaluation version of the leak, which A6 chapter 07 covers.

class CausalSelfAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.c_attn = nn.Linear(cfg.n_embd, 3 * cfg.n_embd)       # Wqkv
        self.c_proj = nn.Linear(cfg.n_embd, cfg.n_embd)           # Wo
        self.n_head = cfg.n_head

    def forward(self, x):
        B, T, C = x.size()
        q, k, v = self.c_attn(x).split(C, dim=2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)   # (B, h, T, d_k)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)       # mask, softmax, weighted sum
        return self.c_proj(y.transpose(1, 2).contiguous().view(B, T, C))

class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.ln_1, self.attn = nn.LayerNorm(cfg.n_embd), CausalSelfAttention(cfg)
        self.ln_2 = nn.LayerNorm(cfg.n_embd)
        self.mlp = nn.Sequential(nn.Linear(cfg.n_embd, 4 * cfg.n_embd), nn.GELU(), nn.Linear(4 * cfg.n_embd, cfg.n_embd))

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        return x + self.mlp(self.ln_2(x))

class GPT(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.wte, self.wpe = nn.Embedding(cfg.vocab_size, cfg.n_embd), nn.Embedding(cfg.block_size, cfg.n_embd)
        self.h = nn.ModuleList([Block(cfg) for _ in range(cfg.n_layer)])
        self.ln_f = nn.LayerNorm(cfg.n_embd)
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        self.lm_head.weight = self.wte.weight                              # weight tying

    def forward(self, idx, targets=None):
        pos = torch.arange(idx.size(1), device=idx.device)
        x = self.wte(idx) + self.wpe(pos)
        for block in self.h:
            x = block(x)
        logits = self.lm_head(self.ln_f(x))
        loss = None if targets is None else F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

Our NumPy model, at 1.73 after 3,000 steps with a bigger batch, sits between the two. I have not run the PyTorch listing here because PyTorch is not installed in this environment. Those loss figures are the README's, not mine.




  
State of play, October 2026

  
Karpathy's nanoGPT repository now carries a notice (November 2025) calling itself "very old and deprecated". It points to nanochat, a single-node harness that covers tokenisation, pretraining, fine-tuning, evaluation and a chat interface. Its README states that a "GPT-2 capability" model trains in about 1.5 hours on one 8×H100 node, for about $48 at on-demand prices. The recorded best was 1.65 hours at the time I read it. For context, Karpathy's llm.c reproduction of GPT-2 small reported about 90 minutes on 8×A100 and about $20 in May 2024. The community "speedrun" in the modded-nanogpt repository asks how fast 8 H100s can reach a validation loss of 3.28 on FineWeb with a GPT-2-small-sized model. Its README (read in October 2026) says "under 40 seconds", down from the 45 minutes of the llm.c baseline. The gains come from changes such as new optimisers, 8-bit floating-point (FP8) matrices and architecture tweaks. Those numbers are repository claims, not independently reproduced, and will move. What stays fixed is the program of this chapter: the same forward pass, loss and training loop.






  
Systems connection

  
The training loop is a data pipeline feeding a compute-bound kernel. get_batch is the input pipeline. On real runs the token file is memory-mapped and read by background workers so that the GPU never waits. This is the same producer-consumer structure as a queue between services. Batch size in tokens is a throughput knob with a ceiling set by memory. Activations for the backward pass scale with B·T. Chapter 16 counts them, and A3 chapter 02 shows what runs out first. The learning-rate schedule and optimiser state are state. A run that dies at step 40,000 resumes cleanly only if the checkpoint includes the optimiser's moments, the schedule position and the random-number state. This is the same recovery problem as any stateful service (A3 chapter 05). Seeds make runs reproducible here. On GPUs, though, reproducibility also depends on the order of floating-point additions, which the hardware does not always fix. The test suite of this chapter is the model-code equivalent of the unit and invariant tests you would write for any service before deploying it.






  
Key takeaways

  
    
    
  • A GPT is the decoder-only Transformer of chapter 10 plus an embedding table, a final LayerNorm and an output head, trained to predict the next token. Training and generation use the same function.
    • 
    
  • A window of T tokens, with targets shifted by one, is T training examples. The causal mask is what stops a position from reading its own answer. Batches are (B, T) integer arrays.
    • 
    
  • The toy model here has 108,352 weights (V = 65, T = 64, C = 64, h = 4, L = 2). The formula V·C + T·C + L(12C² + 13C) + 2C reproduces its size, nanoGPT's Shakespeare model (10,770,816) and GPT-2 small (124,439,808).
    • 
    
  • The gradient of the loss with respect to the logits is (softmax − one-hot) / N. A hand-written backward pass is validated by finite differences (error about 10−9 here); autograd does the same job in PyTorch.
    • 
    
  • The training recipe is AdamW with weight decay on matrices only, a linear warmup and cosine decay of the learning rate, and gradient-norm clipping at 1. The loss starts at ln V (4.17) and passes the unigram (3.35) and bigram (2.49) levels first.
    • 
    
  • Four tests catch the silent bugs: starting loss near ln V, overfitting a single batch, a causality check and a gradient check. A model without the causal mask trains to 0.04 and generates at 7.9. Low loss is only good news if the evaluation matches use.
    • 
    
  • Scaling to GPT-2 changes the tokeniser, the sizes, the data and the hardware, not the forward pass.
    •

Check your understanding

  

    
A window of 64 characters is cut with its target shifted by one. Roughly how many separate prediction problems does the model solve for that window in one forward pass?

    
  1. One: the character after the 64th
  2. 64: one per position, each seeing only the characters up to it
  3. 64 × 64: one per pair of positions
  4. 65: one per vocabulary entry

    
The causal mask lets position t see only x[0..t], so each of the 64 positions is a separate next-character problem, and all 64 losses are averaged. One prediction per window would waste the parallelism. The pairs of positions (64 × 64) are the entries of the attention matrix, not separate predictions, and 65 is the number of classes in each prediction.

  

  

    
You start training a character model with V = 65. The printed loss at step 0 is 37.8. What is the most likely explanation?

    
  1. The learning rate is too low
  2. The model has too few layers
  3. The training set is too small
  4. The initial weights or logits are far too large, so the model starts out confidently wrong

    
A model that knows nothing gives every character probability about 1/65 and loss ln 65 = 4.17. Loss 37.8 means the model assigns tiny probability to the true character with great confidence, which happens when initial logits are large (weights drawn with too big a standard deviation, or no 0.02-scale initialisation). The learning rate only matters after step 0, and neither depth nor data size changes the loss of an untrained network.

  

  

    
You remove the causal mask by mistake. The training loss falls to 0.04 within a few hundred steps, and the validation loss, measured the same way, is also tiny. What do you conclude?

    
  1. Information from future positions is leaking into the predictions, so the numbers do not reflect generation ability
  2. The model has become far better than a 5-gram model and is ready to deploy
  3. The validation set must be too easy
  4. Weight decay is working unusually well

    
Each position can read the very character it is asked to predict from the next input position, so the task becomes copying. Both losses look excellent because both are measured with the leak. Evaluated as a generator, with the future hidden, the same weights scored 7.9 in the chapter's run. A suspiciously large improvement over simple baselines should trigger a causality test, not a celebration.

  

  

    
The gradient check prints relative errors of 10−9 for every weight tensor except wte, where it is 0.35. wte is used twice: as the input embedding and, transposed, as the output head. Which bug is most likely?

    
  1. The optimiser's weight decay is applied to the embedding
  2. The softmax is not numerically stable
  3. The backward pass counts only one of the two uses of the matrix, or counts one twice
  4. The learning rate is too high

    
When a weight is used in two places, its gradient is the sum of the gradients from both uses; forgetting one (or overwriting rather than accumulating) gives a wrong gradient only for that tensor. Weight decay and the learning rate are not part of a gradient check, which compares derivatives of the loss. An unstable softmax would hurt every tensor, and would show up as NaNs or large errors everywhere.

  

  

    
The chapter's tiny GPT reaches a validation loss of 1.73 nats per character while a 5-gram count model reaches 1.67. Which statement is the fairest reading?

    
  1. The count model is a better language model and Transformers are not needed
  2. At this size and training time the table is better, but the Transformer's parameters scale and generalise, so the ranking changes as size grows
  3. The GPT must have a bug, because it should always win
  4. The comparison is meaningless because they use different units

    
Both numbers are nats per character on the same validation text, so the comparison is valid, and a small model trained for a minute need not beat a large table of counts on a one-megabyte file. A table of contexts grows exponentially with context length and cannot generalise to unseen contexts, whereas Transformers improve smoothly with size and data (chapter 18). Neither "tables win" nor "bug" follows from one comparison at one scale.

  

  

    
You double the batch from 32 to 64 windows with the same T. Which of the following changes by exactly the factor of two?

    
  1. The number of weights
  2. The training loss after the same number of steps
  3. The number of tokens processed (and predictions made) per step
  4. The size of one position's attention matrix

    
Tokens per step are B × T, so they double. The weights do not depend on B, and one position's attention matrix is T × T per head, independent of B (the whole tensor of scores doubles, but that is a different quantity). The loss after the same number of steps will usually be somewhat lower with the gradient averaged over more tokens, but not by a fixed factor of two.
