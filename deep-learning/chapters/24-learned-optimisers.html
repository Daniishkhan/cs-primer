Learned Optimisers & In-Context Learning

Gradient descent, Adam and the learning-rate schedule were all designed by people. Two lines of research ask what happens when the learning algorithm is itself learned: an optimiser trained like a model, and a transformer that learns a new task from examples inside its prompt. This chapter shows both, and a published argument that they are closer than they look.

Why this matters

This is reading for the literacy pack, not a step of any artifact. It helps most with Artifact 4, the capstone in which an outer agent improves an inner agent. That is the two-level shape of a learned optimiser: the outer loop is scored by how well an inner process does after it runs. After this chapter you can say what is optimised at each level, why the outer score must come from unseen problems, and what "a model learns in context" does and does not mean.

Two loops, one trick

An optimiser is a rule that turns gradients into parameter updates (A0 chapter 10). Stochastic gradient descent (SGD), momentum and Adam are such rules, written by hand. A learned optimiser replaces the rule with a small model: it reads the gradient (and perhaps its history) and outputs the update. Its own parameters are trained by an outer loop, which runs the optimiser on many training problems for a fixed number of steps and adjusts the optimiser to make the final loss lower. This is meta-learning, or learning to learn.

Andrychowicz et al. (2016, "Learning to learn by gradient descent by gradient descent") framed optimiser design as a learning problem. Their learned optimisers were LSTMs (long short-term memory networks, the recurrent cells of chapter 8). The authors report that these outperformed generic hand-designed optimisers on the tasks they were trained on, and generalised to new tasks with similar structure, on simple convex problems, neural network training and neural art style transfer.

VeLO (Metz et al., 2022, "VeLO: Training Versatile Learned Optimizers by Scaling Up") applied the scaling idea. The learned optimiser is a small neural network that takes gradients in and puts parameter updates out. It was meta-trained on a wide range of tasks using roughly four thousand TPU-months of compute (a TPU is Google's tensor processing unit, a machine-learning accelerator), according to the abstract, which also reports that it needs no hyperparameter tuning and adapts to the problem it is given. Those are the authors' claims. The abstract says the optimiser, code and a benchmark suite were released, so they can be checked.

A learned optimiser you can run

The script is the smallest honest version. The "optimiser" is 30 numbers: a learning rate and a momentum coefficient for each of 15 steps. The tasks are random quadratic bowls with curvatures between 0.1 and 10. The outer loop is a simple evolution strategy (A7 chapter 2): mutate the 30 numbers, keep a child if the average final loss on 64 training problems drops. The baseline is fair in the sense the artifact standards ask for: a hand-designed optimiser (momentum SGD) with its learning rate and momentum tuned on the same 64 problems. Both are scored on 500 new problems.

"""A learned optimiser in miniature: per-step learning rates and momenta,
meta-trained by a (1+8) evolution strategy on random quadratic problems,
then tested on problems it never saw.
"""
import numpy as np

K, D = 15, 10                    # optimiser steps per problem, dimensions

# ── 1. A family of problems: f(w) = 0.5 * sum(h * w^2), h in [0.1, 10] ──
def make_tasks(n, seed, hi=10):
    r = np.random.default_rng(seed)
    h = np.exp(r.uniform(np.log(0.1), np.log(hi), size=(n, D)))
    return h, r.normal(size=(n, D))              # curvatures, start points

def final_loss(theta, h, w0):
    """Run K steps of momentum SGD whose lr and beta depend on the step."""
    lr, beta = np.exp(theta[:K]), 1 / (1 + np.exp(-theta[K:]))
    w, v = w0.copy(), np.zeros_like(w0)
    for t in range(K):
        v = beta[t] * v + h * w                  # gradient of the quadratic
        w = w - lr[t] * v
    loss = 0.5 * np.sum(h * w**2, axis=1)
    return np.mean(np.where(np.isfinite(loss), loss, 1e9))

# ── 2. Hand-designed baselines: tune lr on the same training problems ──
h_tr, w_tr = make_tasks(64, seed=1)
h_te, w_te = make_tasks(500, seed=2)

def fixed(lr, beta):
    return np.r_[np.full(K, np.log(lr)), np.full(K, np.log(beta / (1 - beta)))]

grid = [(lr, b) for lr in np.exp(np.linspace(np.log(0.003), np.log(0.5), 30))
        for b in (1e-6, 0.3, 0.6, 0.8, 0.9)]
lr, b = min(grid, key=lambda g: final_loss(fixed(*g), h_tr, w_tr))
base = fixed(lr, b)
print(f"best tuned momentum SGD: lr {lr:.3f}, beta {b:.1f}  test loss "
      f"{final_loss(base, h_te, w_te):.4f}")

# ── 3. Meta-train: evolve the 2K numbers that define the optimiser ─────
rng = np.random.default_rng(0)
theta = np.r_[np.full(K, np.log(0.1)), np.full(K, -3.0)]
best = final_loss(theta, h_tr, w_tr)
for gen in range(600):
    kids = [theta + 0.1 * rng.normal(size=2 * K) for _ in range(8)]
    scores = [final_loss(k, h_tr, w_tr) for k in kids]
    if min(scores) < best:
        best, theta = min(scores), kids[int(np.argmin(scores))]
print(f"learned optimiser: train loss {best:.4f}  test loss "
      f"{final_loss(theta, h_te, w_te):.4f}")
print("learned lr per step:", np.round(np.exp(theta[:K]), 2))

# ── 4. Outside the family: curvatures up to 12 instead of 10 ───────────
h_ood, w_ood = make_tasks(500, seed=3, hi=12)
print(f"curvature up to 12: tuned SGD {final_loss(base, h_ood, w_ood):.3g}, "
      f"learned {final_loss(theta, h_ood, w_ood):.3g}")
best tuned momentum SGD: lr 0.295, beta 0.6  test loss 0.0101
learned optimiser: train loss 0.0042  test loss 0.0051
learned lr per step: [0.15 0.2  0.14 0.16 4.59 0.18 0.13 0.58 0.15 0.16 0.13 0.84 0.44 0.14
 1.27]
curvature up to 12: tuned SGD 1.91e+05, learned 1.27e+06

The learned optimiser reaches a test loss of 0.0051, about half the tuned baseline's 0.0101. The gain is real against a fair baseline, but this is a small system with one seed. Treat the factor of two as an illustration, not an estimate. The learned learning rates are worth reading: most steps use about 0.15, but a few use much larger values (4.59 at step 5, 1.27 at the last). Used for every step, 4.59 would blow up on the steep directions; used once, between safe steps, it removes the error along the shallow ones. No person wrote that schedule down, and the optimiser found it by being scored on the final loss.

The last line shows the cost. Curvatures up to 12 instead of 10 are only 20% outside the training family, and both optimisers diverge (the learned one by more). A learned optimiser is tuned to the distribution of problems it saw. This is the same lesson as held-out evaluation in A7 chapter 16: a score on the training problems says little about the next problem.

Common misconception

"A learned optimiser is a better Adam for everything." It is better on the family of problems it was meta-trained on, and the evidence for wider use depends on how wide the family was. VeLO's approach was to make that family very large, with a very large compute bill. The small script above shows the failure in miniature: the gain is real inside the family and gone just outside it.

In-context learning: a learner inside the forward pass

Brown et al. (2020, "Language Models are Few-Shot Learners") showed that a large language model can pick up a task from a few examples in its prompt, with no change to its weights. This is in-context learning (ICL). Here the weights were trained by an outer loop (next-token prediction over a huge corpus). What that loop produced behaves like a learner when it is given examples. The learning algorithm is not written anywhere; it is what the trained network computes.

Garg et al. (2022, "What Can Transformers Learn In-Context? A Case Study of Simple Function Classes") made this testable. They trained standard transformers from scratch, where every training prompt contained examples of a freshly drawn function, and found that for linear functions the transformers reached performance comparable to the optimal least-squares estimator. They also report that this holds under two distribution shifts, and that transformers trained on sparse linear functions, two-layer neural networks and decision trees matched or exceeded task-specific algorithms.

That raises the question of which algorithm a trained transformer is running. von Oswald et al. (2022, "Transformers learn in-context by gradient descent") give one answer for a simple setting. Their abstract reports that a single linear self-attention layer can transform data in the same way as a step of gradient descent on a regression loss, that trained attention-only transformers closely resemble models trained by gradient descent, and that in some cases the learned weights match their construction. They call such a network a mesa-optimiser, one that learns by gradient descent inside its forward pass. The argument for the first step is short enough to run. Start with weights of zero and squared error on n examples. One gradient step of size η gives weights η ∑ yi xi, so the prediction for a query xq is:

prediction = η × (sum over examples of yi × (xi · xq))

That is exactly attention without the softmax: the dot products xi · xq are the scores, the yi are the values, and η is a scale. Stacking layers corresponds to taking more steps. The script checks the identity and then compares the predictors.

"""In-context regression: one gradient-descent step IS a linear attention read.

Each 'prompt' holds n examples (x_i, y_i) of a fresh random linear function
y = w . x, plus a query x_q. The predictor never updates stored weights.
"""
import numpy as np

rng = np.random.default_rng(0)
d, n, TASKS = 5, 10, 2000

def prompt():
    w = rng.normal(size=d)                       # a new task every time
    X = rng.normal(size=(n, d))
    return X, X @ w, rng.normal(size=d), w

# ── 1. Gradient descent on the in-context examples, from w = 0 ─────────
def gd_predict(X, y, xq, eta, steps):
    w = np.zeros(d)
    for _ in range(steps):
        w = w - eta * X.T @ (X @ w - y)          # grad of 0.5*sum (w.x-y)^2
    return w @ xq

# ── 2. The same first step as linear attention (no softmax) ────────────
def attention_predict(X, y, xq, eta):
    scores = X @ xq                              # key . query for each example
    return eta * np.sum(scores * y)              # weighted sum of the values

X, y, xq, w = prompt()
print("1 GD step vs linear attention:",
      round(gd_predict(X, y, xq, 0.05, 1), 6),
      round(attention_predict(X, y, xq, 0.05), 6))

# ── 3. 'Meta-train' eta on many tasks, then compare predictors ─────────
data = [prompt() for _ in range(TASKS)]
def mse(f):
    return np.mean([(f(X, y, xq) - xq @ w) ** 2 for X, y, xq, w in data])

etas = [0.005, 0.01, 0.02, 0.03, 0.05, 0.08]
def best(k):
    def loss(e):
        return mse(lambda X, y, xq: gd_predict(X, y, xq, e, k))
    return min(etas, key=loss)

rows = [("predict zero", lambda X, y, xq: 0.0)]
for k in (1, 3, 10, 30):
    e = best(k)
    rows.append((f"GD, {k:>2} steps, eta {e}",
                 lambda X, y, xq, k=k, e=e: gd_predict(X, y, xq, e, k)))
ols = lambda X, y, xq: np.linalg.lstsq(X, y, rcond=None)[0] @ xq
rows.append(("least squares", ols))
for name, f in rows:
    print(f"{name:<24} mean squared error {mse(f):.4f}")

predict zero             mean squared error 4.7878
GD,  1 steps, eta 0.05   mean squared error 1.8477
GD,  3 steps, eta 0.05   mean squared error 0.8381
GD, 10 steps, eta 0.05   mean squared error 0.3114
GD, 30 steps, eta 0.03   mean squared error 0.0832
least squares            mean squared error 0.0000

The first line shows the two routes give the same number, to six places. The table shows what "more layers" would buy: with the step size chosen on 2,000 training prompts for each count, the error falls from 4.79 (predict zero) to 1.85 after one step, 0.84 after three, 0.31 after ten, and 0.08 after thirty, against zero for least squares, which is exact here because the data has no noise and 10 examples exceed the 5 dimensions. This is a construction in plain NumPy, not a trained transformer, so it shows what the von Oswald et al. argument says a layer could compute. It does not show that any trained model does. Their paper reports that trained models resemble it on regression tasks, and also links the mechanism to induction heads, the copy-based heads mentioned in chapter 23. The papers I read study small transformers on synthetic function-learning tasks; they do not establish what a frontier language model does with a prompt.

Analogy: the apprentice and the workshop

A learned optimiser is a master craftsperson whose training is judged by how good the apprentices' first pieces are. In-context learning is the same master's habit, so ingrained that shown three sample pieces, the apprentice starts producing similar ones the same afternoon without changing anything about themselves.

Where it breaks down: a person who adapts in an afternoon keeps the lesson, but a model that learns in context forgets it when the prompt ends, because no weights changed.

Why a builder of self-improving loops should care

Three ties to the rest of the path. First, the two-level structure is the structure of Artifact 4: the outer agent that rewrites an inner agent is a learned optimiser whose "parameters" are code and prompts (A7 chapter 21). The lessons carry over directly: score the outer loop on held-out problems, give it a fixed budget, and compare with a tuned hand-made baseline. Second, a prompt that shows an agent worked examples is in-context learning at work, which is why the choice of examples in A4 chapter 4 moves results. Third, if a forward pass can contain an optimiser, then "the model was not updated" does not mean "nothing was learned during the episode", which matters when you measure whether an agent improves within a run (A12 chapter 5).

Systems connection

A learned optimiser resembles a database query planner whose cost model was fitted on one workload: excellent there, and prone to surprises when the workload shifts. In-context learning resembles a function that takes its configuration as an argument at call time: behaviour changes with the input, nothing on disk changes, and the state is gone when the call returns.

Key takeaways

  • A learned optimiser is a small model that maps gradients to updates, trained by an outer loop that scores it on the loss the inner training run ends with.
  • It can beat a tuned hand-made optimiser on its training family, as in the script, and it can fail just outside it. Always score on problems it did not see.
  • In-context learning means a trained network behaves like a learner when given examples, with no weight update.
  • One gradient step on a regression loss equals a linear attention read; von Oswald et al. argue that trained transformers can implement this and report that trained models resemble it on regression tasks.
  • The outer-and-inner structure here is the same one that Artifact 4 measures.

Further reading

  • Metz et al., "VeLO: Training Versatile Learned Optimizers by Scaling Up" (2022). A large-scale learned optimiser, with released code and benchmark.
  • Brown et al., "Language Models are Few-Shot Learners" (2020). Where in-context learning at scale became widely visible.
  • Garg et al., "What Can Transformers Learn In-Context? A Case Study of Simple Function Classes" (2022). Transformers trained from scratch to learn function classes in context.

Check your understanding

In a learned optimiser, what does the outer loop change, and what score does it use?

  1. The task model's weights, scored on the training loss at each step
  2. The optimiser's own parameters, scored on the task loss after a fixed number of inner steps, averaged over many problems
  3. The data, scored on its diversity
  4. The learning rate only, scored on gradient size
The inner loop trains the task model. The outer loop treats the whole inner run as one evaluation and edits the optimiser to improve its end result. Changing the task weights is the inner loop's job.

The learned optimiser scored 0.0051 on new problems from its training family and diverged on curvatures up to 12. What is the right reading?

  1. The outer loop had a bug
  2. Momentum SGD is always safer than learned optimisers
  3. The tuned baseline also failed, so nothing was learned
  4. The gain is specific to the problem family, and even the tuned baseline fails just outside it
Both optimisers diverged at 12, so the family boundary is the issue, not a bug. The learned one was worse there (1.27e+06 against 1.91e+05), but the lesson is distribution shift, not that the baseline is safe.

Why does one gradient step from zero weights on squared error look like attention?

  1. The prediction is a sum of the values yi, each weighted by the dot product of its input with the query input, which is a linear-attention read
  2. Gradient descent computes a softmax over the examples
  3. Attention stores the weights of the regression
  4. Both use the same number of parameters
The step gives weights η ∑ yi xi, so the prediction is η ∑ yi (xi · xq). There is no softmax in this form, which is why it is linear attention, not the usual kind.

An agent improves its answers over several turns of a conversation although its weights never change. Which statement is most accurate?

  1. Impossible, since learning requires a weight update
  2. It proves the model implements gradient descent
  3. Something learner-like happens in the forward pass; the mechanism is a separate question the cited papers study only on small synthetic tasks
  4. The improvement must come from a hidden fine-tuning step
In-context learning is well documented as behaviour. Which algorithm a particular large model runs is open; the gradient-descent account is demonstrated for simple regression settings, not established for frontier models.
