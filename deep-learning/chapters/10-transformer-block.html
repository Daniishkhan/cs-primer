The Transformer Block

A Transformer is one small design repeated: a block with an attention sublayer that moves information between positions, an MLP sublayer that computes within each position, and a residual connection and normalisation around each. This chapter assembles the block from the parts of chapters 03 and 09, explains what each part contributes, runs it, tests it, and counts its parameters against the published sizes of real models.

Why this matters

Nearly every language model you will use, train or serve is N copies of this block between an embedding table and an output layer. The block's shape decides the model's parameter count, where its compute goes, how much memory it needs per token, and what a configuration line such as n_layer=12, n_head=12, n_embd=768 means. If you can write the block, you can read nanoGPT or a model's technical report as ordinary code, predict its size from three numbers, and see which of the many "improvements" published since 2017 change this block and which change what is around it. After this chapter you can implement the block in NumPy with correct shapes, show with a test that it respects causality, derive 12C² weights per block, and reproduce the 124,439,808 parameters of GPT-2 small from its configuration. Chapter 12 trains a model made of exactly these blocks.

One block, two jobs

Chapter 09 built attention: every position reads a weighted average of the other positions' values. That operation is communication: it moves information between token positions. It is also almost entirely linear. The weights depend nonlinearly on the inputs (through the softmax), but what is mixed, the value vectors, is a linear function of the input, so a stack of attention layers alone can only blend and re-blend what it started with. A network needs computation too: nonlinear processing of the information each position has gathered. That is the job of the second sublayer, a small MLP (multi-layer perceptron, the layers of chapter 01) applied to each position separately.

The Transformer block is these two sublayers, each wrapped in the two devices of chapter 03: a normalisation layer in front and a residual connection around. In the pre-norm arrangement used by nearly all current models, with x of shape (B, T, C):

x ← x + MultiHead( LN1(x) )     then     x ← x + MLP( LN2(x) ).

The shape in and out is the same, (B, T, C), which is what lets blocks be stacked as many times as you like. Each sublayer computes a correction and adds it to what is already there; neither replaces the input. Step through one block below; the vertical line is the stream of activations, and the boxes branch off it and write back into it.

Step through

One pre-norm block, from input to output

  1. The stream comes in. The block receives x of shape (B, T, C): one vector of C numbers for each of T tokens in each of B sequences. This running state is the residual stream. The line is drawn once and stays; everything below happens beside it.
  2. Normalise a copy. LN 1 rescales each token's vector to zero mean and unit variance and applies a learned gain and offset (chapter 03). The stream itself is untouched; only the copy that goes into the sublayer is normalised.
  3. Attention reads across positions. The normalised copy is projected to queries, keys and values, scored, masked and mixed (chapter 09). This is the only step in the block where one token's vector affects another token's output.
  4. Add the result back. The attention output, projected by WO to C numbers per token, is added to the stream. The old content stays; attention has appended a correction. Gradients flow straight through this addition.
  5. Normalise again. LN 2 prepares a second copy of the updated stream for the next sublayer.
  6. The MLP computes per token. The same two-layer network, C → 4C → C with a nonlinearity between, is applied to each position independently, with no communication across T. This is where most of the block's weights live.
  7. Add the result back. The MLP output joins the stream the same way.
  8. The stream goes out. The shape is unchanged, (B, T, C), so the next block can take it directly. Only a final normalisation and an output layer remain after the last block.

One more point of vocabulary. The design above is called a decoder block when the attention is causally masked. The 2017 paper had two kinds: encoder blocks (unmasked self-attention and an MLP) and decoder blocks (masked self-attention, then cross-attention to the encoder's output, then an MLP) for translation. GPT-style language models keep only the masked kind with the cross-attention removed, and are called decoder-only. The code in this chapter is that block.

The MLP sublayer

The MLP is two linear layers with a nonlinearity between them. With x of shape (B, T, C), W1 of shape (C, dff) and W2 of shape (dff, C):

MLP(x) = φ( x W1 + b1 ) W2 + b2,    typically dff = 4C.

The matrix product treats (B, T) as batch axes, so every one of the B · T token vectors goes through the identical function. This is why the MLP is called position-wise (or "feed-forward"). It cannot move information between tokens; it can only transform what attention has already gathered at each position. The hidden layer is four times wider than the stream: the vector is expanded to 4C numbers, bent by the nonlinearity φ, and projected back to C.

Why an expansion, and what the MLP stores

The factor of four is a convention from the original paper (dmodel = 512, dff = 2048), kept ever since because it works well and because the matrix shapes suit GPUs. Geva, Schuster, Berant and Levy ("Transformer Feed-Forward Layers Are Key-Value Memories", 2020) offered a useful reading: look at W1 by columns and W2 by rows. Each of the 4C hidden units has a column of W1 that acts like a key (it responds strongly to a particular pattern in the incoming vector) and a row of W2 that acts like a value (what gets written to the stream when that pattern is present). The hidden activations are then match strengths, and the output is their weighted sum, the same shape of operation as attention, except that the keys and values are fixed weights rather than other tokens' vectors. They found that the keys in trained language models respond to interpretable text patterns and the values lean towards predicting plausible next tokens. A common informal summary, to be treated as a useful picture rather than a theorem, is that attention routes information and the MLPs hold much of the model's stored knowledge.

Choosing the nonlinearity

Chapter 01 introduced ReLU. The original Transformer used it; GPT-2 and BERT use the GELU (Gaussian error linear unit; Hendrycks and Gimpel, 2016), which multiplies each input by the probability that a standard normal variable is below it: GELU(z) = z Φ(z). It looks like a ReLU with a smooth corner and a small negative dip. Many recent models use a gated linear unit (GLU) in the MLP, following Shazeer ("GLU Variants Improve Transformer", 2020). A GLU uses two parallel projections of the input and multiplies them element by element, one of them passed through a nonlinearity that acts as a gate. With the SiLU (also called Swish) nonlinearity this is SwiGLU:

MLPSwiGLU(x) = ( SiLU(x Wgate) ⊙ (x Wup) ) Wdown,    SiLU(z) = z σ(z).

It has three weight matrices rather than two, so to keep the parameter count unchanged the hidden width is reduced from 4C to about 8C/3. LLaMA (Touvron et al., 2023) states exactly this: it replaces ReLU by SwiGLU and "use[s] a dimension of 2/3 4d instead of 4d as in PaLM". The script compares the activation functions and checks the parameter budget.

The two GELU columns agree to the three decimals shown; the "tanh" version is the cheaper approximation GPT-2 used. Both are nearly zero for large negative z and nearly z for large positive z, like ReLU, with a gentle dip below zero around z = −1. At C = 768 a standard MLP has 2 · 768 · 3072 = 4,718,592 weights; a SwiGLU MLP with hidden width 2,048 has 3 · 768 · 2048 = 4,718,592, exactly the same. Shazeer reports that several gated variants beat ReLU and GELU at matched cost in his experiments; the paper offers no explanation for why, and none is firmly established.

The MLP is not optional

If attention already mixes information, why not stack attention layers alone? Dong, Cordonnier and Loukas ("Attention is Not All You Need: Pure Attention Loses Rank Doubly Exponentially with Depth", 2021) showed that without residual connections and MLPs, repeated attention drives all token representations towards the same vector. Intuitively, each layer replaces every token by a weighted average of the tokens, and averages of averages become indistinguishable. The experiment below makes that visible. It pushes 16 random token vectors through 24 randomly initialised layers and measures the mean cosine similarity between different tokens (0 means unrelated directions, 1 means identical).

import numpy as np
rng = np.random.default_rng(0)
T, C, h, L = 16, 64, 4, 24
d_k = C // h
softmax = lambda a: np.exp(a - a.max(-1, keepdims=True)) / np.exp(a - a.max(-1, keepdims=True)).sum(-1, keepdims=True)
gelu = lambda x: 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x**3)))
def ln(x): return (x - x.mean(-1, keepdims=True)) / np.sqrt(x.var(-1, keepdims=True) + 1e-5)

def attn(x, W):                                   # one sequence, no mask: x is (T, C)
    q, k, v = np.split(x @ W["qkv"], 3, axis=-1)
    sp = lambda t: t.reshape(T, h, d_k).transpose(1, 0, 2)
    p = softmax(sp(q) @ sp(k).transpose(0, 2, 1) / np.sqrt(d_k))
    return (p @ sp(v)).transpose(1, 0, 2).reshape(T, C) @ W["o"]

def mean_cos(x):                                  # average cosine similarity between different tokens
    u = x / np.linalg.norm(x, axis=-1, keepdims=True)
    G = u @ u.T
    return (G.sum() - T) / (T * (T - 1))

Ws = [dict(qkv=rng.normal(size=(C, 3 * C)) / np.sqrt(C), o=rng.normal(size=(C, C)) / np.sqrt(C),
           w1=rng.normal(size=(C, 4 * C)) / np.sqrt(C), w2=rng.normal(size=(4 * C, C)) / np.sqrt(4 * C)) for _ in range(L)]
x0 = rng.normal(size=(T, C))
variants = {
    "attention only":          lambda x, W: attn(x, W),
    "+ residual":              lambda x, W: x + attn(x, W),
    "+ residual + LN + MLP":   lambda x, W: (lambda y: y + gelu(ln(y) @ W["w1"]) @ W["w2"])(x + attn(ln(x), W)),
}
print(f"{'mean cosine similarity between tokens':<40}" + "".join(f"{'after '+str(d):>10}" for d in (0, 1, 6, 12, 24)))
for name, f in variants.items():
    x, row = x0, [mean_cos(x0)]
    for l in range(L):
        x = f(x, Ws[l])
        if l + 1 in (1, 6, 12, 24):
            row.append(mean_cos(x))
    print(f"{name:<40}" + "".join(f"{v:>10.3f}" for v in row))

Pure attention collapses within a handful of layers: by layer 6 the tokens are numerically identical. Adding the residual connection slows the collapse but does not stop it with these random weights. The full block (residual, LayerNorm and MLP) is slowest, but even it drifts towards similarity by layer 24. Two cautions. These are random, untrained weights, so the experiment shows a tendency of the architecture, not the behaviour of a trained model, which learns weights that keep tokens distinct for the task. And the result is one reason the pieces of the block are not independent options: removing any of them changes how information survives depth.

The residual stream

It pays to change how you picture the block. Instead of "data flows through attention, then through the MLP", picture a shared workspace of C numbers per token, the residual stream, that every sublayer reads from and writes to. Elhage et al. ("A Mathematical Framework for Transformer Circuits", 2021) made this view precise. Unrolling the additions, the stream after N blocks is just

xN = x0 + ∑l=1N ( attnl + mlpl ),

the embedding of the token plus the sum of every sublayer's contribution. A sublayer reads by normalising the stream and multiplying by its input weights; it writes by adding its output. Nothing is ever overwritten, only added to. Layer 10 can read what layer 2 wrote, directly, with no intermediate layers in the way, and the final output layer reads the sum of everything. The width C is then the bandwidth of this shared channel: all information any later layer will need about a token has to fit in C numbers at that position.

Analogy: a shared whiteboard

Imagine a whiteboard with one column per word of the sentence. In turn, each sublayer looks at the board, does some work on a scratch pad, and writes its result into the columns by adding to what is already written. The attention steps may copy things between columns; the MLP steps work on one column at a time. At the end, the answer is read off the last column. The board is never wiped, so early notes stay legible to every later step.

Where it breaks down: a whiteboard has unlimited room, while the stream has a fixed width C, so contributions overlap and interfere in the same coordinates, and a later layer can only "erase" something by writing its negative. Real layers do not read tidy notes either: each one reads a rescaled mixture of directions that no human labelled.

Assembling and testing a block

The script below is the complete block in NumPy, using the pieces we have: LayerNorm (chapter 03), causal multi-head attention (chapter 09, with the three input projections stored as one (C, 3C) matrix, as in nanoGPT), the GELU MLP, and the two residual additions. The residual-branch output matrices Wo and W2 are scaled by 1/√(2L), the GPT-2 rule from chapter 03, so that six blocks do not inflate the stream. It runs six blocks on random inputs and prints the size (root mean square) of each sublayer's contribution and of the stream, then runs two tests.

import numpy as np
rng = np.random.default_rng(0)
B, T, C, h, L = 2, 8, 64, 4, 6          # batch, tokens, width, heads, layers
d_k = C // h

def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

def layernorm(x, g, b, eps=1e-5):                     # normalise over the last axis (C)
    mu, var = x.mean(-1, keepdims=True), x.var(-1, keepdims=True)
    return (x - mu) / np.sqrt(var + eps) * g + b

def gelu(x):                                          # tanh approximation used by GPT-2
    return 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x**3)))

def init_block(rng):
    w = lambda *s: rng.normal(size=s) / np.sqrt(s[0])
    p = dict(Wqkv=w(C, 3 * C), Wo=w(C, C) / np.sqrt(2 * L), W1=w(C, 4 * C), W2=w(4 * C, C) / np.sqrt(2 * L))
    p.update(g1=np.ones(C), b1=np.zeros(C), g2=np.ones(C), b2=np.zeros(C))
    return p

def attention(x, p, causal=True):                     # x: (B, T, C)
    q, k, v = np.split(x @ p["Wqkv"], 3, axis=-1)     # each (B, T, C)
    sp = lambda t: t.reshape(B, T, h, d_k).transpose(0, 2, 1, 3)   # (B, h, T, d_k)
    q, k, v = sp(q), sp(k), sp(v)
    s = q @ k.transpose(0, 1, 3, 2) / np.sqrt(d_k)    # (B, h, T, T)
    if causal:
        s = np.where(np.triu(np.ones((T, T), bool), 1), -np.inf, s)
    o = softmax(s) @ v                                # (B, h, T, d_k)
    return o.transpose(0, 2, 1, 3).reshape(B, T, C) @ p["Wo"]

def mlp(x, p):                                        # the same function at every position
    return gelu(x @ p["W1"]) @ p["W2"]                # (B, T, C) -> (B, T, 4C) -> (B, T, C)

def block(x, p, causal=True):
    a = attention(layernorm(x, p["g1"], p["b1"]), p, causal)
    x = x + a                                         # write attention's result into the stream
    m = mlp(layernorm(x, p["g2"], p["b2"]), p)
    return x + m, a, m                                # write the MLP's result into the stream

blocks = [init_block(rng) for _ in range(L)]
x = rng.normal(size=(B, T, C))                        # stand-in for token embeddings
rms = lambda t: np.sqrt((t**2).mean())
print(f"{'layer':>5} {'|attn out|':>10} {'|mlp out|':>10} {'|stream|':>9}")
print(f"{'in':>5} {'':>10} {'':>10} {rms(x):>9.2f}")
y = x
for i, p in enumerate(blocks):
    y, a, m = block(y, p)
    print(f"{i + 1:>5} {rms(a):>10.2f} {rms(m):>10.2f} {rms(y):>9.2f}")
print("shape in/out:", x.shape, y.shape)

def run(x, causal=True):
    for p in blocks:
        x = block(x, p, causal)[0]
    return x

# test 1: causality. Change the LAST token; all earlier outputs must be identical.
x2 = x.copy(); x2[:, -1] += 1.0
d = np.abs(run(x) - run(x2)).max(axis=(0, 2))
print("per-position change after editing the last token:", np.round(d, 3))

# test 2: with no mask and no positional information, shuffling tokens just shuffles outputs
perm = rng.permutation(T)
print("permutation equivariant without mask:", np.allclose(run(x, False)[:, perm], run(x[:, perm], False)))
print("...and with the causal mask:", np.allclose(run(x)[:, perm], run(x[:, perm])))

The table shows the stream view in numbers. The stream starts with RMS 1.00 and every sublayer adds a contribution of about 0.2, so the stream grows slowly (to 1.21 after twelve additions) rather than exploding, which is what the 1/√(2L) scaling was for. Both sublayers contribute comparable amounts at initialisation; in a trained model their sizes differ by layer and by token.

The two tests are the kind you should write for any block you implement.

  • Causality. Add 1.0 to every feature of the last token and compare the outputs of the whole six-block stack. Positions 0 to 6 change by exactly 0 and only position 7 changes. Information can flow from earlier to later positions, never the reverse, through all the layers. If any earlier position moved, there would be a leak: a missing mask, a mask applied after the softmax, or normalisation over the T axis instead of C.
  • Permutation behaviour. With the mask removed and no position information anywhere, shuffling the input tokens simply shuffles the outputs (True): the block treats its input as an unordered set and cannot tell "dog bites man" from "man bites dog". With the causal mask the same shuffle does change the result (False), because the mask itself carries an ordering. Chapter 11 is about supplying order explicitly.

Common misconception

"A Transformer is basically attention; the MLP is a minor add-on." By weight count the opposite holds. Per block, attention has 4C² weights and the MLP has 8C², so two thirds of the block's parameters are in the MLP (the next section shows this in real models), and in the original paper's wording the MLP is as much a part of the block as attention. Removing it does not give a slimmer Transformer; it gives the collapsing stack of the previous experiment. The name of the 2017 paper describes its novelty (attention replacing recurrence), not the proportions of the finished network.

From blocks to a model

The block is the repeating unit; around it sit three more pieces, shown in the figure. An embedding table of shape (V, C) turns each token id into its row vector (chapter 06); position information is added at the bottom (chapter 11). After the last block comes a final normalisation, needed because in a pre-norm model the stream has never been normalised on the skip path (chapter 03), and then an output head, a linear map from C to V, that produces one logit (an unnormalised score) per vocabulary entry at every position. A softmax over those V numbers is the model's prediction of the next token, and cross-entropy against the actual next token is the training loss (chapter 14). Chapter 12 assembles and trains exactly this.

The embedding and the head are the only places where the vocabulary size V enters. For GPT-2, V = 50,257 and C = 768, so the table holds 38.6 million numbers, which is a large share of a small model and a rounding error in a large one. The 2017 paper also shared this matrix between the input and output of the model, and GPT-2 followed; many modern large models leave the two untied.

Counting parameters

Everything above has weight matrices of known shapes, so the size of a model is arithmetic. Count one pre-norm GPT-2 block with biases:

  • Attention: the fused Wqkv is C × 3C and Wo is C × C, together 4C², plus biases 3C + C = 4C.
  • MLP: W1 is C × 4C and W2 is 4C × C, together 8C², plus biases 4C + C = 5C.
  • Two LayerNorms: a gain and a bias each, 4C.

The total is 12C² + 13C per block. The ∑ over layers adds the embeddings (V · C for tokens, Tmax · C for learned positions) and a final norm of 2C. The terms linear in C are small: at C = 768 the 12C² term is 7,077,888 and the rest is 9,984. So a good estimate for any standard block is about 12 C² per layer, and about 12 L C² for the body of the model. The script applies the exact formula to the four published GPT-2 sizes.

# Parameter count of a GPT-2-style decoder: learned positions, biases, tied output head.
def gpt2_params(C, L, V=50257, T=1024):
    attn = 4 * C * C + 4 * C                    # W_qkv (C x 3C) + W_o (C x C) and their biases
    mlp = 8 * C * C + 5 * C                     # C x 4C and 4C x C, plus biases 4C and C
    norms = 2 * 2 * C                           # two LayerNorms, each with gain and bias
    block = attn + mlp + norms                  # = 12 C^2 + 13 C
    embed = V * C + T * C                       # token table (shared with the output head) + position table
    return block, embed, L * block + embed + 2 * C      # final LayerNorm adds 2C

for name, C, L in (("GPT-2 small", 768, 12), ("GPT-2 medium", 1024, 24), ("GPT-2 large", 1280, 36), ("GPT-2 XL", 1600, 48)):
    b, e, tot = gpt2_params(C, L)
    print(f"{name:<12} {C:>5} {L:>6} {b:>12,} {e:>12,} {tot:>15,}")

The same formula, adapted for the SwiGLU MLP (three C × dff matrices, no biases, RMSNorm gains only, untied embeddings), reproduces LLaMA-7B's 6,738,415,616 weights from the published configuration of 32 layers, width 4,096 and hidden width 11,008 (the 8C/3 = 10,923 rounded up to a multiple of 256; the paper's Table 2 lists these as 6.7B parameters, 4096, 32 heads and 32 layers). What changed since 2017

The block in this chapter is GPT-2's. The 2017 original differs in a few places, and most models since differ in a few more, always in the same small set of choices. The table lists them; each row is a change to something described above.

ChoiceOriginal Transformer (2017)GPT-2 style (2019)LLaMA style (2023)
Normalisation positionAfter the addition (post-norm)Inside the branch (pre-norm), plus a final normPre-norm
Normalisation typeLayerNormLayerNormRMSNorm (no mean subtraction, no offset)
MLP activationReLU, hidden 4CGELU, hidden 4CSwiGLU, hidden about 8C/3
Position informationFixed sinusoids added at the inputLearned table added at the inputRotary (RoPE) applied to queries and keys in every layer
BiasesYesYesTypically none in the linear layers
Attention headsMulti-head, h key/value setsMulti-headMulti-head in the first LLaMA; grouped-query in the larger LLaMA 2 models

The first row is the chapter-03 story, now with context: Xiong et al. (2020) showed that pre-norm trains reliably without a learning-rate warmup phase where post-norm does not. GPT-2 states the changes explicitly: layer normalisation moved to the input of each sub-block, an extra one after the final block, and residual-layer weights scaled at initialisation by 1/√N. RMSNorm (Zhang and Sennrich, 2019) drops the mean subtraction and the offset, saving a little time and memory with similar quality. The positional row is chapter 11. A few other variations deserve a name:

  • Parallel blocks. Compute attention and the MLP from the same normalised input and add both: x + Attn(LN(x)) + MLP(LN(x)). GPT-J and PaLM did this to fuse two matrix products into larger, faster ones, at some cost in expressiveness that appeared small for large models.
  • QK-norm. Normalise queries and keys before the dot product to keep the attention logits bounded (chapter 09's "Go deeper").
  • Grouped-query and sliding-window attention. Changes inside the attention sublayer for cheaper inference (chapter 19).
  • Mixture of experts. Replace the single MLP by many MLPs plus a router that picks a few per token, so parameters grow without the compute per token growing (chapter 20).

State of play, October 2026

The "LLaMA-style" column describes the recipe that the 2023 LLaMA paper documented and that many open-weight models have followed or adapted since: pre-norm with RMSNorm, SwiGLU MLPs, rotary positions and no biases. Published technical reports from 2024 and 2025 describe frontier and open models mostly as variations on it, with changes concentrated in attention (key/value sharing, mixtures of local and global layers), in the MLP (mixture of experts), and in normalisation of queries and keys. Several newer architectures replace some attention layers by recurrent or state-space layers (chapter 22). I could not verify the full internal design of closed models and do not describe them here. Check a model's own report for its exact block, and treat any list of "the standard recipe" as a snapshot.

Systems connection

The two sublayers stress hardware differently. The MLP and the projections are large matrix multiplications that keep a GPU's arithmetic units busy when many tokens are processed together, as in training and in prompt processing. Normalisation, GELU and the residual additions do almost no arithmetic per number they touch, so they are limited by memory bandwidth (Zero to Systems chapter 21); real implementations fuse them with neighbouring operations into one kernel to avoid writing the stream to memory and reading it back (A3 chapter 04). When one token is generated at a time, every weight of every block must be read from memory to produce a single token, which is why decoding is memory-bound and why the parameter count in this chapter translates directly into bytes read per token (A3 chapter 18). Spreading a model over several GPUs follows the block's structure: heads and the 4C hidden units of the MLP can be split across devices because they are independent columns (A3 chapter 03), and activations of every block must be kept for the backward pass, a cost examined in chapter 16.

Key takeaways

  • A block is two residual sublayers with a normalisation in front of each: x ← x + Attn(LN(x)), then x ← x + MLP(LN(x)). Shape in equals shape out, (B, T, C), so blocks stack.
  • Attention communicates across positions; the MLP computes within each position, identically for all of them. Only attention can move information between tokens.
  • The MLP expands to 4C, applies a nonlinearity (GELU, or SwiGLU with hidden width about 8C/3 for equal cost) and projects back. It holds two thirds of each block's weights and works like a key-value memory.
  • The residual stream is a shared workspace: xN = x0 + the sum of all sublayer outputs. Sublayers read through a normalisation and write by addition.
  • A block has about 12C² parameters (exactly 12C² + 13C with biases). GPT-2 small, with C = 768, 12 layers and 50,257 tokens, has 124,439,808.
  • Test the block: earlier outputs must not change when a later token does (causality); without a mask and positions it cannot tell token order (permutation equivariance).

Check your understanding

A GELU MLP has C = 1024 and the standard hidden width 4C. Ignoring biases, how many weights does one MLP have?

  1. About 4.2 million
  2. About 1.05 million
  3. About 8.4 million
  4. About 16.8 million
W1 is 1024 × 4096 = 4,194,304 and W2 is 4096 × 1024 = 4,194,304, together 8,388,608 = 8C². The first option counts only one of the two matrices. The fourth squares the expansion factor.

Which operations in a pre-norm decoder block can make the output at position i depend on the input at some other position j?

  1. Only the attention sublayer
  2. Attention and the MLP
  3. Attention and LayerNorm
  4. Attention, the MLP and both residual additions
LayerNorm normalises each token over its own C features, the MLP acts on each position separately with shared weights, and the residual addition is element-wise at each position. Attention is the only operation that reads other positions. That is also why the causal mask need only be applied there.

You replace a GELU MLP (hidden width 4C) with SwiGLU, which has three weight matrices, and want the same number of weights in the layer. For C = 512, roughly what hidden width should SwiGLU use?

  1. 2,048, unchanged
  2. 1,024
  3. 683
  4. 1,365
Three matrices of C × dff give 3C·dff, which must equal 8C², so dff = 8C/3 = 1,365 for C = 512 (implementations round to a hardware-friendly multiple). Keeping 2,048 would raise the weights by half. 683 is C·4/3 divided by two: the arithmetic slips by a factor of two.

In a LLaMA-7B-style model (32 layers, C = 4096, SwiGLU hidden width 11,008, 32,000-token vocabulary, untied head), which share of the parameters is in the MLPs?

  1. About 17%
  2. About 64%
  3. About 32%
  4. About 4%
MLPs: 32 × 3 × 4096 × 11,008 ≈ 4.33 billion of 6.74 billion, about 64%. Attention is 32% (4C² per layer), embeddings and head about 4%. The 32% option is attention's share, a tempting confusion for anyone who thinks of a Transformer as attention.

Your causal Transformer passes a unit test with a causal mask, but a second test shows that editing the last token changes outputs at earlier positions. You then notice that your LayerNorm computes its mean and variance over the T axis. Why does this explain the leak?

  1. LayerNorm over T changes the number of parameters
  2. LayerNorm over T disables the residual connection
  3. The statistics at every position would include the later tokens, so information from the future enters each position
  4. It makes the softmax inputs too large
Mean and variance over T are computed from all positions, including future ones, and are used to rescale every position, so the earlier output depends on the later token. The mask only constrains attention weights; it cannot constrain a normalisation that mixes positions. LayerNorm over C touches only one token at a time, which is why it is the right choice (chapter 03).

Which description of the residual stream is accurate?

  1. Each sublayer replaces the stream with its own output, passing the input only through the skip connection
  2. Each sublayer reads a normalised copy of the stream and adds its output to the stream, so the final stream is the embedding plus the sum of all sublayer outputs
  3. The stream is the attention weights, passed from layer to layer
  4. The stream grows in width by C with every block
The stream keeps its width C throughout; sublayers add to it and never overwrite it, so every later layer can read what earlier ones wrote. Replacing the stream would make the skip path meaningless. The stream is not the attention weights, which are (T, T) tables internal to attention.
