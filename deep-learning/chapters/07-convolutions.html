Convolutions & Images

A photograph has hundreds of thousands of numbers, and a dense layer would give each its own weights. Convolution replaces that with a small filter that slides over the image and is reused at every position. This chapter builds the operation, trains small networks that show what weight sharing buys and what it does not, and traces the ideas that vision gave to every architecture since.

Why this matters

Convolutional networks ended the long argument over whether deep learning worked (the AlexNet case), and most of the habits you use in deep learning were invented or popularised for them: stacking small layers, skip connections, batch normalisation, pretrained backbones, data augmentation. Even where Transformers have taken over, the first layer of a vision-language model is often a convolution in disguise, and speech and audio models still begin with convolutions. This chapter gives you the operation, the reasoning behind its design (an assumption about images that you can state and test), and an honest experiment on where that assumption helps and where it quietly fails.

Why dense layers do not scale to images

An image is a grid of pixels, each with a few channel values (red, green, blue). A modest 224 × 224 colour photo is 150,528 numbers. A dense layer connects every input to every output. If you wanted it to produce a feature map of the same spatial size with 64 channels, every one of the 150,528 inputs would need its own weight to every one of 3,211,264 outputs. Here is the arithmetic, next to a convolutional layer that does the same kind of job:

# Parameters and multiply-adds for one layer applied to a 224 x 224 RGB image.
H = W = 224; Cin = 3

dense_in, dense_out = H * W * Cin, H * W * 64             # a dense layer producing a 224 x 224 x 64 output
print(f"dense layer, same input and output size:  {dense_in * dense_out + dense_out:,} parameters")

def conv(cin, cout, k, hout, wout):
    params = cout * cin * k * k + cout
    return params, params * hout * wout - cout * hout * wout   # multiply-adds: one per weight per output position

The dense layer would need 483 billion weights, about 2.8 times the 175 billion parameters of the whole of GPT-3 (Brown et al., 2020), in a single layer; the convolution needs 1,792. The gap is not a trick: it comes from two assumptions about pictures that a dense layer ignores.

  • Locality. The meaning of a pixel is mostly determined by its neighbours. An edge, a corner or a patch of fur is a pattern over a few pixels, so a feature detector does not need to look at the whole image at once.
  • Translation structure. A pattern that is useful in one place is useful in another. If a detector for "vertical edge" works at the top left, the same detector should work at the bottom right. So there is no reason to learn separate weights for each position: learn once, reuse everywhere. This reuse is called weight sharing.

These assumptions are not facts about nature; they are a bet about how images behave, built into the architecture so that the network does not have to rediscover them from data. Machine-learning people call such built-in assumptions an inductive bias. When the bet is right, you need far fewer parameters and far less data. When it is wrong, the model is limited in ways that more data may not fix. Keep that trade in mind for the whole chapter.

The convolution operation

A filter (or kernel) is a small grid of weights, commonly 3 × 3. To apply it, lay it over a patch of the image, multiply each weight by the pixel beneath it, and add up the nine products. The sum is one number. Slide the filter one step and do it again, until the whole image is covered. The grid of sums is a feature map: it records how strongly the pattern the filter looks for is present at each position.

This is the whole operation. A short function written with two loops shows how little there is to it, and a numerical check shows that the efficient form used in practice gives the same numbers:

import numpy as np

img = np.zeros((6, 6)); img[:, :3] = 1.0                 # bright left half, dark right half: one vertical edge
k = np.array([[1, 0, -1], [1, 0, -1], [1, 0, -1]], dtype=float)   # responds to "bright on the left, dark on the right"

def conv2d_loops(x, k, stride=1, pad=0):
    x = np.pad(x, pad); n, m = k.shape
    H, W = (x.shape[0] - n) // stride + 1, (x.shape[1] - m) // stride + 1
    out = np.zeros((H, W))
    for i in range(H):
        for j in range(W):
            patch = x[i * stride:i * stride + n, j * stride:j * stride + m]
            out[i, j] = (patch * k).sum()                 # multiply patch by kernel, add up: that is all a convolution is
    return out

out = conv2d_loops(img, k)
print("image (6x6):\n", img.astype(int))
print("feature map (4x4), no padding:\n", out.astype(int))
print("feature map with padding 1 (6x6):\n", conv2d_loops(img, k, pad=1).astype(int))
print("shapes: no padding", out.shape, " pad 1", conv2d_loops(img, k, pad=1).shape, " stride 2", conv2d_loops(img, k, stride=2).shape)

# Same answer from the vectorised form used in practice (every patch at once):
from numpy.lib.stride_tricks import sliding_window_view
fast = np.einsum("ijkl,kl->ij", sliding_window_view(img, (3, 3)), k)
print("vectorised version agrees:", np.allclose(fast, out))

# Shift the image one pixel to the right: the feature map shifts with it (equivariance).
shifted = np.roll(img, 1, axis=1); shifted[:, 0] = 1.0
print("edge column before:", np.nonzero(out.any(0))[0], " after the image moves one pixel right:", np.nonzero(conv2d_loops(shifted, k).any(0))[0])

def out_size(n, k, s=1, p=0): return (n + 2 * p - k) // s + 1

Four things to take from the output.

  1. The filter finds the edge. The feature map is zero over flat regions and 3 in the two columns where the window straddles the boundary.
  2. Shapes follow a formula. With input size n, kernel size k, padding p and stride s, the output has floor((n + 2p − k)/s) + 1 positions per side. Padding adds a border of zeros so that edge pixels are visited as often as central ones; stride moves the window more than one pixel at a time, shrinking the output (stride 2 halves it, as in the first layer of ResNet).
  3. Padding has side effects. In the padded version the leftmost column holds −3: the zero border looks like a dark strip next to the bright image, so the filter reports an edge that is not in the picture. Frameworks do this by default, so remember it when you see odd border behaviour.
  4. Shift in, shift out. When the image moves one pixel right, the feature map's active columns move from {1, 2} to {2, 3}. This property is called translation equivariance: shifting the input shifts the output by the same amount. It is the formal version of "the same detector works everywhere".

A technical footnote: what deep-learning libraries call "convolution" is strictly cross-correlation. True convolution flips the kernel before sliding it. Because the weights are learned, it makes no difference to what the network can represent, and nobody flips.

Channels, depth and learned filters

Real images have channels, and real layers apply many filters. A convolutional layer takes an input with Cin channels, so each kernel is a stack of Cin small grids (one per input channel) whose products are all summed into one output value. A layer with Cout such kernels produces Cout output channels. So a layer has Cout × Cin × k × k weights plus Cout biases, however large the image is. The shapes follow the convention (B, C, H, W) for a batch of B images.

Two special cases are worth recognising. A 1 × 1 convolution (the last row of the table above) looks at a single position and mixes channels: it is a dense layer applied independently at every pixel, and the same thing as the position-wise MLP in a Transformer block (chapter 10). And stacking matters: each 3 × 3 layer lets a unit see two more pixels in each direction, so L stacked layers see a (2L + 1) × (2L + 1) region, called their receptive field. Two 3 × 3 layers cover the same 5 × 5 patch as one 5 × 5 layer with 73,728 weights instead of 102,400 (for 64 channels, as printed above) and an extra non-linearity in between. That observation drove VGG (Simonyan and Zisserman, 2014), a network built almost entirely from 3 × 3 convolutions.

What do the learned filters detect? In the first layer, typically edges, colour contrasts and simple textures. Deeper layers combine them: textures, then parts such as eyes or wheels, then whole objects. Zeiler and Fergus ("Visualizing and Understanding Convolutional Networks", 2013) made this hierarchy visible by projecting activations back to pixel space, and the idea that depth builds features from simple to complex is the picture you will see again in language models.

Pooling, and the difference between equivariance and invariance

After a feature map has said "an edge is here", later layers often care only that an edge appeared somewhere in a neighbourhood. Pooling summarises each small window with one number: max pooling keeps the largest value in each 2 × 2 block, average pooling the mean. It halves the spatial size (cutting later computation), enlarges the receptive field, and gives some tolerance to small shifts, because moving a feature by a pixel inside a window does not change the window's maximum. Global pooling collapses an entire feature map to one number per channel (for example, "the strongest response to this filter anywhere in the image"), after which a position no longer exists.

Common misconception

"Convolutional networks are translation invariant." Convolution is translation equivariant: shift the input and the feature maps shift. Invariance (the output does not change at all when the input shifts) has to come from something that discards position, such as global pooling at the end. The experiment below separates the two. And even invariance is only approximate in practice: strided layers and pooling sample the image on a grid, so a shift by one pixel can change the result. Azulay and Weiss ("Why do deep convolutional networks generalize so poorly to small image transformations?", 2018) documented large changes in classifier output from shifts of a pixel or two.

Build it and test the inductive bias

To test the bet rather than just assert it, we need a convolutional layer that trains. In chapter 05 we built a small autograd engine; adding a new operation means writing its forward pass and its local derivative, which the engine chains with the rest. Here are convolution, pooling and a convolution module. The backward pass is the interesting part: the gradient of a filter weight is the sum, over every position the filter visited, of (input patch × output gradient), which is exactly what weight sharing implies.

import numpy as np
from numpy.lib.stride_tricks import sliding_window_view
from tinytorch import Tensor
from nn import Module

def conv2d(x, w, b, pad=1):
    """x: (B, Cin, H, W), w: (Cout, Cin, k, k), b: (Cout,). Stride 1. Returns (B, Cout, H, W) when pad = k // 2."""
    k = w.data.shape[-1]
    xp = np.pad(x.data, ((0, 0), (0, 0), (pad, pad), (pad, pad)))
    win = sliding_window_view(xp, (k, k), axis=(2, 3))                       # (B, Cin, H', W', k, k): every patch, no copy
    out = np.einsum("bchwij,ocij->bohw", win, w.data) + b.data[None, :, None, None]
    def back(g):                                                             # g: (B, Cout, H', W')
        dw = np.einsum("bchwij,bohw->ocij", win, g)                          # each filter sums over every position it visited
        dxp = np.zeros_like(xp); H, W = g.shape[2:]
        for i in range(k):
            for j in range(k):                                               # scatter gradient back to the pixels each tap touched
                dxp[:, :, i:i + H, j:j + W] += np.einsum("bohw,oc->bchw", g, w.data[:, :, i, j])
        dx = dxp[:, :, pad:dxp.shape[2] - pad, pad:dxp.shape[3] - pad]
        return dx, dw, g.sum((0, 2, 3))
    return Tensor.make(out, (x, w, b), back, "Conv2d")

def max_pool2d(x, s=2):                                                      # non-overlapping s x s windows
    B, C, H, W = x.data.shape
    blocks = x.data.reshape(B, C, H // s, s, W // s, s)
    out = blocks.max(axis=(3, 5))
    mask = (blocks == out[:, :, :, None, :, None]); mask = mask / mask.sum(axis=(3, 5), keepdims=True)   # share ties equally
    return Tensor.make(out, (x,), lambda g: ((mask * g[:, :, :, None, :, None]).reshape(B, C, H, W),), "MaxPool")

def global_max_pool(x):                                                      # (B, C, H, W) -> (B, C): strongest response anywhere
    B, C, H, W = x.data.shape
    out = x.data.max(axis=(2, 3)); mask = (x.data == out[:, :, None, None]); mask = mask / mask.sum(axis=(2, 3), keepdims=True)
    return Tensor.make(out, (x,), lambda g: (mask * g[:, :, None, None],), "GlobalMaxPool")

def flatten(x): return reshape(x, (x.data.shape[0], -1))
def reshape(x, shape):
    old = x.data.shape
    return Tensor.make(x.data.reshape(shape), (x,), lambda g: (g.reshape(old),), "Reshape")

class Conv2d(Module):
    def __init__(self, cin, cout, k, rng):
        bound = 1 / np.sqrt(cin * k * k)
        self.weight = Tensor(rng.uniform(-bound, bound, (cout, cin, k, k)), requires_grad=True)
        self.bias = Tensor(rng.uniform(-bound, bound, cout), requires_grad=True)
        self.pad = k // 2
    def forward(self, x): return conv2d(x, self.weight, self.bias, self.pad)

Before trusting it, compare its gradients with finite differences on a small stack of convolution, ReLU, pooling and a classifier:

import numpy as np
from tinytorch import Tensor, cross_entropy
from nn import Linear
from convops import Conv2d, max_pool2d, global_max_pool

rng = np.random.default_rng(3)
conv1, conv2, fc = Conv2d(1, 3, 3, rng), Conv2d(3, 4, 3, rng), Linear(4, 3, rng)
X = Tensor(rng.standard_normal((2, 1, 6, 6))); y = np.array([0, 2])
def forward(): return fc(global_max_pool(conv2(max_pool2d(conv1(X).relu()).relu())))

forward_loss = lambda: cross_entropy(forward(), y)
forward_loss().backward()

for name, p in params.items():                          # autograd against finite differences, every number

Agreement to about 10-10 for every parameter tensor, so the backward pass is right. Now the experiment. The task is to classify a 5 × 5 shape (horizontal bar, vertical bar, hollow square or plus sign) placed on a 12 × 12 noisy canvas. The twist: during training, shapes only ever start in the three leftmost columns. We then test on shapes in the same region and on shapes placed in columns never seen. Three models learn from the same 600 examples: a dense network on the flattened pixels, a convolutional network followed by a flatten and linear layer, and a convolutional network that ends in global max pooling.

import numpy as np
from tinytorch import Tensor, cross_entropy, no_grad
from nn import Linear, ReLU, Sequential, Module, Adam
from convops import Conv2d, max_pool2d, global_max_pool, flatten

S = 12                                                   # canvas size; every shape is 5 x 5
def shape_img(kind):
    m = np.zeros((5, 5))
    if kind == 0: m[2, :] = 1                            # horizontal bar
    if kind == 1: m[:, 2] = 1                            # vertical bar
    if kind == 2: m[0, :] = m[4, :] = m[:, 0] = m[:, 4] = 1       # hollow square
    if kind == 3: m[2, :] = m[:, 2] = 1                  # plus sign
    return m

def make(n, cols, rng, noise=0.3):                       # shapes placed at a random row and a column drawn from `cols`
    X = np.zeros((n, 1, S, S)); y = rng.integers(0, 4, n)
    for i in range(n):
        r, c = rng.integers(0, S - 4), rng.choice(cols)
        X[i, 0, r:r + 5, c:c + 5] = shape_img(y[i])
    return X + noise * rng.standard_normal(X.shape), y

class Net(Module):
    def __init__(self, layers): self.layers = layers
    def forward(self, x):
        for f in self.layers: x = f(x)
        return x
def mlp(rng):      return Net([flatten, Linear(S * S, 32, rng), lambda t: t.relu(), Linear(32, 4, rng)])
def cnn_flat(rng): return Net([Conv2d(1, 8, 3, rng), lambda t: t.relu(), max_pool2d, Conv2d(8, 8, 3, rng), lambda t: t.relu(), max_pool2d, flatten, Linear(8 * 3 * 3, 4, rng)])
def cnn_gmp(rng):  return Net([Conv2d(1, 8, 3, rng), lambda t: t.relu(), max_pool2d, Conv2d(8, 8, 3, rng), lambda t: t.relu(), global_max_pool, Linear(8, 4, rng)])
def params(net): return [p for l in net.layers if isinstance(l, Module) for p in l.parameters()]

def accuracy(net, X, y):
    with no_grad(): return float((net(Tensor(X)).data.argmax(1) == y).mean())

rng = np.random.default_rng(0)
Xtr, ytr = make(600, [0, 1, 2], rng)                     # training: shapes only ever start in columns 0 to 2 (left side)
Xseen, yseen = make(400, [0, 1, 2], rng)                 # test: same region
Xnew, ynew = make(400, [4, 5, 6, 7], rng)                # test: columns 4 to 7, never seen in training
print(f"{'model':28s}{'parameters':>11s}{'train acc':>11s}{'seen region':>13s}{'new region':>12s}")
for name, build in [("MLP (flatten, dense)", mlp), ("CNN + flatten + linear", cnn_flat), ("CNN + global max pool", cnn_gmp)]:
    net = build(np.random.default_rng(1)); opt = Adam(params(net), lr=0.01)
    for epoch in range(25):
        order = rng.permutation(len(Xtr))
        for i in range(0, len(order), 50):
            idx = order[i:i + 50]; loss = cross_entropy(net(Tensor(Xtr[idx])), ytr[idx])
            opt.zero_grad(); loss.backward(); opt.step()
    n = sum(p.data.size for p in params(net))
    print(f"{name:28s}{n:11d}{accuracy(net, Xtr, ytr):11.1%}{accuracy(net, Xseen, yseen):13.1%}{accuracy(net, Xnew, ynew):12.1%}")
model                        parameters  train acc  seen region  new region
MLP (flatten, dense)               4772     100.0%        69.5%       27.8%
CNN + flatten + linear              956      99.7%        95.5%       23.2%
CNN + global max pool               700     100.0%        99.8%       96.8%

Read this table slowly, because it contains the chapter's main lesson. All three models fit the training set (about 100% training accuracy). The dense network has the most parameters (4,772) and the worst generalisation: 69.5% even in the region it trained on, and 27.8% elsewhere, barely above chance. It memorised pixel patterns instead of learning "bar" or "square", and it has no notion that the same shape in a new place is the same thing. The first convolutional network has about a fifth of the parameters and is much better in the seen region (95.5%), because it learned shape detectors, but collapses to 23.2% in the new region. Why? Its filters would have found the shapes anywhere, but the final flatten-and-linear layer gives each position its own weights, and only the left positions were ever trained. Convolution gave equivariance, and the flatten threw it away. The last network, with global max pooling, keeps no position at all: it asks only whether a bar or corner detector fired anywhere. It has the fewest parameters (700) and reaches 96.8% in the unseen region.

Analogy: a stamp pressed along a page

Imagine a rubber stamp that prints a small pattern. Rather than carving a different stamp for every spot on the page, you carve one and press it everywhere. The page of ink marks it leaves behind (the feature map) shows where the pattern matched. Using many stamps at once gives many maps, and the next layer reads those maps with new stamps, so the patterns they find are built from the earlier ones.

Where it breaks down: a stamp has no idea where on the page it is, which is the point of weight sharing but also its limit. If position carries meaning (a face has eyes above a mouth, a chest X-ray has a heart on the left), a plain stack of convolutions finds the parts but needs help, from deeper layers with large receptive fields, positional information or attention, to reason about their arrangement.

From LeNet to ResNet

Convolutional networks for images go back to LeCun and colleagues, who applied backpropagation to handwritten zip-code recognition in 1989 and described LeNet-5 for document recognition in 1998 ("Gradient-Based Learning Applied to Document Recognition"): convolutions, subsampling, then dense layers. They worked on small, clean problems. The break came in 2012. Krizhevsky, Sutskever and Hinton ("ImageNet Classification with Deep Convolutional Neural Networks") trained a network with five convolutional layers and three dense ones, 60 million parameters in all, on 1.2 million labelled images using two GPUs for five to six days. It used ReLU activations, dropout (chapter 04) and crop-and-flip augmentation. It reached a top-5 error of 15.3% in the ILSVRC-2012 contest against 26.2% for the second-best entry, according to the paper. The full story is in case study 1.

The following years pushed depth. VGG (2014) showed that stacks of 3 × 3 filters reach high accuracy. But very deep plain networks became harder to train, not easier, which chapter 03 explained with vanishing signals. He, Zhang, Ren and Sun ("Deep Residual Learning for Image Recognition", 2015) solved it with the residual connection: each block computes its output as the input plus a learned correction,

y = x + F(x)

so the block only has to learn what to change, and gradients flow straight through the addition. They trained networks up to 152 layers (8 times deeper than VGG, they note) and an ensemble reached 3.57% top-5 error on the ImageNet test set, winning ILSVRC 2015. The residual block is in every Transformer you will build in Part 3.

What carried over

The architectures differ, but the ideas travelled. A reading list in table form:

Idea from visionWhere it appears later

1 × 1 convolution (per-position mixing)The MLP inside each Transformer block (chapter 10)

Convolution and attention are two answers to the question "which other positions should this position look at, and with what weights?". A convolution answers with a fixed, local window whose weights are learned and shared. Attention (chapter 09) answers with a window that covers the whole sequence and whose weights are computed from the content. The first has a strong inductive bias and learns well from less data; the second has a weaker bias, so it needs more data and more compute but is more flexible. Dosovitskiy et al. found exactly that trade-off: ViT, with less image-specific inductive bias, was weaker than comparable ConvNets when trained on ImageNet alone, and matched or exceeded them when pretrained on far larger datasets; they summarise it as "large scale training trumps inductive bias".

State of play, October 2026

The competition between the two families has not ended in a winner. Liu et al. ("A ConvNet for the 2020s", 2022) took a standard ResNet and modernised it step by step using Transformer-era recipes; the resulting ConvNeXt family reached 87.8% ImageNet top-1 accuracy and compared favourably with Swin Transformers on detection and segmentation, which suggests that part of the gap between the families came from training recipes and design details rather than from attention itself. In practice the choice follows data size, latency budget and hardware: convolutions remain attractive for small datasets, real-time and edge deployment, while Transformer-based vision encoders dominate large-scale pretraining and multimodal models. Verify current benchmark standings before relying on any single number; they move quickly.

Systems connection

GPUs are built for large matrix multiplications, so a convolution is usually turned into one: lay out every window as a row of a big matrix (the "im2col" transformation) and multiply by the filter matrix. The cost is memory, since overlapping windows are duplicated, which is why optimised libraries use cleverer algorithms. Tensor layout matters for speed: (B, C, H, W) versus (B, H, W, C) changes which memory accesses are contiguous. And image models are often limited before the GPU: JPEG decoding and augmentation run on CPU workers, so a slow input pipeline starves the accelerator, the same producer and consumer imbalance as in chapter 05.

Key takeaways

  • Convolution slides a small shared filter over the input. It exploits locality and translation structure, cutting parameters by orders of magnitude (1,792 against 483 billion in our example).
  • Output size is floor((n + 2p − k)/s) + 1. Padding keeps size but can create fake edges at borders; stride and pooling reduce size and enlarge the receptive field.
  • Convolution is translation equivariant. Invariance requires discarding position, for instance by global pooling, and even then it is approximate.
  • The inductive bias is a bet. Our experiment showed it paying (96.8% in an unseen region against 27.8% for the dense net) and being thrown away by one flatten layer (23.2%).
  • Ideas from vision that outlived the architecture: weight sharing, residual connections, normalisation, augmentation, pretraining, and patching the input.
  • Convolution (fixed local window) and attention (content-based global window) are two points on one spectrum; more bias means less data needed and less flexibility.

Check your understanding

A 3 x 3 convolution with 32 input channels and 64 output channels is applied to a 100 x 100 image. How many weights (ignoring biases) does the layer have?

  1. 3 x 3 x 100 x 100 x 64, because every position has its own weights
  2. 32 x 64, because only channels matter
  3. 3 x 3 x 32 x 64 = 18,432, independent of the image size
  4. 100 x 100 x 32 x 64, because the output must be as large as the input
Weight sharing means the same kernel set is used at every position, so the count is kernel size squared times input channels times output channels: 9 x 32 x 64 = 18,432. The image size changes the compute (how many positions), not the number of weights. Counting per position describes a dense or "locally connected" layer.

A 7 x 7 convolution with stride 2 and padding 3 is applied to a 224 x 224 image. What is the output size per side?

  1. 112
  2. 111
  3. 224
  4. 109
floor((224 + 2 x 3 - 7) / 2) + 1 = floor(223 / 2) + 1 = 111 + 1 = 112. Option 2 forgets the +1; option 3 would need stride 1; option 4 ignores the padding.

In the shifted-position experiment, the CNN with a flatten and linear layer scored 95.5% on seen positions but 23.2% on new ones. What explains the collapse?

  1. Convolution only works on the left half of an image
  2. The filters had too few parameters to detect the shapes
  3. The noise level was higher in the right-hand region
  4. The linear layer after the flatten learned separate weights for each position, which were only trained for the left-hand positions
The convolutional filters share weights and would find shapes anywhere, but flattening keeps the position of each feature map entry and the linear layer gives each its own weights, so the right-hand weights never got a training signal. Global pooling removes position and fixed it (96.8%). The noise was the same everywhere and the same filters scored well on seen positions, so the other options are wrong.

Which statement about convolution and pooling is correct?

  1. Convolution is translation invariant, so pooling is never needed
  2. Convolution is translation equivariant: shifting the input shifts the feature map; invariance needs something that discards position, such as global pooling
  3. Max pooling makes a network exactly invariant to any shift
  4. Equivariance and invariance are different names for the same property
Equivariance means the output moves with the input; invariance means the output does not change. Convolution gives the first; pooling (especially global) gives approximate versions of the second. Strided sampling breaks exact invariance, which is why the last two statements are false.

A residual block computes y = x + F(x). Why does this make very deep networks easier to train?

  1. It halves the number of parameters in each block
  2. It forces F to be linear, which is easier to optimise
  3. The gradient has a direct path through the addition, and the block only needs to learn a correction to its input
  4. It removes the need for non-linear activations
The identity path carries gradients back unchanged (the derivative of x + F(x) with respect to x includes a 1), which avoids vanishing signals, and learning a small correction is easier than learning the whole mapping. It does not reduce parameters, it does not make F linear, and activations are still used inside F.

Vision Transformers cut an image into 16 x 16 patches and project each one with the same matrix. Which operation does this equal?

  1. A convolution whose kernel size and stride are both 16
  2. A max-pooling layer of size 16
  3. A global average pooling followed by a dense layer
  4. A 1 x 1 convolution with stride 1
Applying one linear map to every non-overlapping 16 x 16 patch is the same as a convolution with a 16 x 16 kernel and stride 16, and that is how many implementations write it. A 1 x 1 convolution mixes channels at one pixel and would not combine a patch, and the pooling options discard information instead of projecting it.
