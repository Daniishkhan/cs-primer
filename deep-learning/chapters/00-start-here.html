Start Here

A language model is a long chain of matrix multiplications whose numbers were adjusted, billions of times, to predict the next piece of text. This chapter says what deep learning is, what changed in 2012 and again in 2017, and what the next twenty-two chapters build, step by step, until you have trained a small GPT yourself.

Why this matters

Every system in the rest of the path, from fine-tuning to agents to retrieval, sits on top of a neural network that somebody trained. If that network is a black box, you will misread its failures: you will blame the prompt for a tokenisation bug, or trust a number on a model card without knowing what it counts. This course opens the box. By the end you can explain, with shapes and numbers, what happens between a string going in and a probability distribution coming out, and you can estimate what a model costs to train and to hold in memory.

What deep learning is

In A1 you fitted models to examples: a linear model, a decision tree, a boosted ensemble. In almost every case a person decided what the model would look at. For house prices that meant columns such as floor area and postcode; for churn it meant "days since last login". This hand-made description of an example is called a feature, and a great deal of classical machine learning is the craft of choosing good ones.

Deep learning is machine learning in which the model learns the features as well. It stacks many simple, adjustable steps, called layers, so that each layer builds a new description of the example from the output of the one before. Early layers learn something crude (in an image model, patches of edge and colour; in a text model, which letters tend to go together), and later layers combine those into more abstract descriptions (a wheel, a face; a noun phrase, a negation). The word "deep" refers to the number of layers, nothing more mysterious.

Three ingredients make this work, and the course returns to each of them:

  • A flexible function with many numbers in it. A network is a function from an input to an output with up to trillions of adjustable numbers, called parameters (or weights). Chapters 01 and 02 build this function from scratch.
  • A way to measure being wrong. A loss function turns "how bad was this prediction?" into one number, as in A0 chapter 13.
  • A way to improve. Backpropagation computes how the loss changes when each parameter changes (A0 chapter 09 built the idea; chapter 02 here applies it to whole layers), and an optimiser such as AdamW (A0 chapter 10) takes a small step downhill.

None of these three was invented recently. What changed was that, around 2012, there was enough data and enough compute to make them work at a useful size, and in 2017 someone found an architecture that used that compute far better.

Two dates and a road

2012: data, GPUs and a convolutional network

ImageNet, a collection of over a million labelled photographs in a thousand categories, gave researchers a benchmark large enough to need a big model. In 2012 Krizhevsky, Sutskever and Hinton entered "ImageNet Classification with Deep Convolutional Neural Networks" (AlexNet) in the annual competition. The paper reports a network with about 60 million parameters, trained on graphics processors (GPUs) because they multiply matrices far faster than CPUs, and a top-5 error of 15.3% against 26.2% for the runner-up. Hand-engineered features had been improving by a point or two a year; this was a ten-point jump. Within a few years almost every vision team had switched. Case study 1 reads the paper closely.

2017: attention replaces recurrence

Language was handled differently. Through the early 2010s the standard tool for text was the recurrent network, which reads one word at a time and carries a summary forward (chapter 08). It is inherently sequential, so it cannot use thousands of GPU cores at once on a single sentence. Vaswani and colleagues at Google, in "Attention Is All You Need" (2017), proposed the Transformer: every word looks directly at every other word through an operation called attention, and all positions are processed at the same time. Their translation results beat the previous best, 28.4 BLEU on English to German, with a big model trained for 3.5 days on eight GPUs for the English to French task (as the abstract reports). More important than the score was the shape of the computation: big, regular matrix multiplications that scale on hardware. Case study 2 follows that paper.

The road since

Once the architecture could absorb compute, the recipe became: take a Transformer, predict the next token of a huge amount of text, make it bigger. The GPT line from OpenAI (2018 to 2020) and the scaling-law papers (Kaplan et al., 2020; Hoffmann et al., 2022, "Chinchilla") showed that loss falls smoothly and predictably with model size, data and compute (chapter 18), and that new abilities appear along the way (case 3). Everything you meet in A3 (fine-tuning, preference optimisation, serving) starts from such a pretrained model.

State of play, October 2026

The core recipe above, a decoder-only Transformer trained on next-token prediction and then post-trained, is still the backbone of the large language models whose designs are public. Several things move quickly and are kept out of this course's main text: which models lead which benchmarks, parameter counts of closed models (rarely disclosed), and how much of a frontier model is a mixture of experts or a hybrid with non-attention layers (chapters 20 and 22 explain the ideas, not the current league table). When a chapter quotes a figure from a paper, it names the paper and year so you can check how old it is.

A first taste: predicting the next character

The central trick of this course fits in a few lines. A language model assigns a probability to what comes next, given what came before. The simplest possible one only looks one character back: count how often each character follows each other, and turn counts into probabilities. This is a bigram model. The script below does that for sixteen first names, using a full stop to mark the start and end of a name.

import numpy as np

names = ["emma", "olivia", "ava", "isabella", "sophia", "mia", "amelia", "harper",
         "evelyn", "abigail", "emily", "ella", "elizabeth", "camila", "luna", "sofia"]
chars = ["."] + sorted(set("".join(names)))          # "." marks start and end
ix = {c: i for i, c in enumerate(chars)}
V = len(chars)                                         # vocabulary size
N = np.zeros((V, V))
for n in names:
    seq = ["."] + list(n) + ["."]
    for a, b in zip(seq, seq[1:]):
        N[ix[a], ix[b]] += 1                           # count how often b follows a
P = (N + 1) / (N + 1).sum(1, keepdims=True)            # add-one smoothing, rows sum to 1

row = P[ix["a"]]
top = np.argsort(-row)[:4]
print("after 'a':", ", ".join(f"{chars[i]} {row[i]:.2f}" for i in top))

nll = [-np.log(P[ix[a], ix[b]]) for n in names for a, b in zip(["."] + list(n), list(n) + ["."])]
print(f"average loss: {np.mean(nll):.3f} nats  (uniform guess: {np.log(V):.3f})")

rng = np.random.default_rng(3)
for _ in range(5):
    c, s = ".", ""
    while True:
        c = chars[rng.choice(V, p=P[ix[c]])]
        if c == ".": break
        s += c
    print("sampled:", s)
after 'a': . 0.30, b 0.10, m 0.07, v 0.05
average loss: 2.219 nats  (uniform guess: 3.045)
sampled: a
sampled: sobilaobhlimpyfprf
sampled: zfgvnis
sampled: ohamycogsretpptisvasilamfveminbessoycuczoozttabbegubflvzrcmpamhnppmlbiafmri
sampled: iaoigyigglahynsyustuflhemgonachpbemiogcyeeigcmyabpvzbly

Three numbers matter here and recur throughout the course. The row for "a" is a probability distribution over the next character. The average loss, 2.219 nats, is the average of −log of the probability the model gave to the character that actually came next; a model that guessed uniformly among the 21 symbols (20 letters and the full stop) would score ln 21 = 3.045, so this one has learned something (A0 chapter 14 explains why this is cross-entropy). And the samples show the limit of looking back one character: short strings that are name-like in places and nonsense in others. With only sixteen names and add-one smoothing the table is also very noisy.

Deep learning replaces the table with a network that can look at a long stretch of text, shares what it learns between similar contexts, and is trained by gradient descent on the same loss. Here is the whole machine in one picture, which the later parts fill in.

Systems connection

Deep learning is unusually dependent on hardware. A network is mostly matrix multiplication, which is why GPUs matter: Zero to Systems chapter 21 explains SIMD, Amdahl's law and memory bandwidth, and chapter 22 shows how to measure where time goes. Serving a model is a systems problem too: Designing with ML & LLMs covers the surrounding architecture. Whenever this course says "this is expensive", it will give you the number of floating-point operations or bytes so you can reason about it.

  • Read the sources. Andrej Karpathy's Neural Networks: Zero to Hero lectures and his nanoGPT repository are the spiritual ancestor of Parts 1 to 3; they are cited where relevant, and the explanations here are written independently.

Common misconception

"Deep learning works like the brain." Artificial neurons are a loose mathematical idea borrowed from a 1940s sketch of nerve cells, and they have diverged from biology ever since. A network is a differentiable function fitted by gradient descent. Thinking of it that way, rather than as a tiny mind, will make its failures easier to diagnose: bad data, a wrong loss, a numerical overflow, a tokeniser quirk.

Try it yourself

Run the bigram script, then change it. First, replace the sixteen names with another list you type in (cities, species, product codes). Second, change the add-one smoothing (N + 1) to N + 0.01 and re-run: the average loss on the training names falls, but a name containing a pair never seen in the list would now get a probability near zero, and a loss of many nats for that pair. Third, think about how you would make the model look two characters back. How big does the table become for a vocabulary of 21? For 50,000 tokens? That blow-up is the reason the rest of the course exists.

$ python3 bigram.py

Key takeaways

  • Deep learning is machine learning where the model learns its own features through many stacked layers, trained by gradient descent on a loss.
  • The ingredients are old; 2012 (AlexNet) supplied data and GPU compute, and 2017 (the Transformer) supplied an architecture that scales on that hardware.
  • A GPT is: token ids, embeddings, a stack of identical blocks, logits over the vocabulary, a sampled next token, repeated.
  • The notation (B, T, C, h, d_k, V) and the habit of writing shapes are used in every chapter.
  • The course builds up to a trained GPT (Part 3), then to the arithmetic of scale (Part 5) and modern variants (Part 6).

Check your understanding

What does the "deep" in deep learning refer to?

  1. The model needs a very large amount of training data
  2. The model stacks many layers, each building a new description from the previous one
  3. The model reasons about abstract concepts
  4. The model is trained for many days
Depth is the number of stacked layers. Large data and long training often accompany it, but they are not what the word means. Whether a network "reasons" is a separate question that the word does not address.

Why was the Transformer a better fit for modern hardware than the recurrent networks it replaced?

  1. It has fewer parameters
  2. It needs no training data labels
  3. It uses simpler arithmetic than matrix multiplication
  4. It processes all positions of a sequence at once, as large regular matrix multiplications
A recurrent network must finish step t before it starts step t+1, which wastes thousands of parallel GPU cores on a single sequence. The Transformer's attention lets every position be computed at the same time. It does not have fewer parameters as a rule, and it is trained on unlabelled text with next-token labels that come from the text itself, which recurrent models can also do.

The bigram script reports an average loss of 2.219 nats against 3.045 for a uniform guess over 21 symbols. What does the gap tell you?

  1. The model puts more probability, on average, on the characters that really followed than a uniform guess would
  2. The model is correct 2.219 out of every 3.045 times
  3. The model will generate realistic names
  4. The model has a vocabulary of 2.2 characters
Loss is the mean of −ln(probability assigned to the true next character), not an accuracy. A lower value means the model concentrated more probability on the truth. The samples in the output show that a lower loss than uniform does not by itself mean realistic output.

A teammate says a model card's parameter count is "just a label". Which view is closest to this course's approach?

  1. Agree: only benchmark scores matter
  2. Agree: parameter counts cannot be computed from the architecture
  3. Disagree: parameters, FLOPs and bytes can be counted from the architecture and determine what fits in memory and what training costs
  4. Disagree: parameter count alone determines quality
Part 5 teaches you to count parameters, FLOPs and memory exactly, so the number carries meaning. Quality depends on data and training too (chapter 18), so the last option overstates it, which is the tempting wrong answer.
