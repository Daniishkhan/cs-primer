Sequences & Recurrent Networks

Language, speech, sensor logs and code arrive one item at a time, in an order that matters and in lengths nobody fixed in advance. A recurrent network reads such a sequence with one small cell applied again and again, carrying a summary forward. This chapter builds that idea, shows why it forgets, how the LSTM's gates slow the forgetting, and why squeezing everything into one hidden state is the bottleneck that attention was invented to remove.

Why this matters

Part 3 of this course replaces recurrence with attention, and the replacement only makes sense once you have seen what it replaced. For about five years (roughly 2013 to 2017) recurrent networks were the state of the art for translation, speech recognition and language modelling, and nearly every idea in the Transformer is a response to one of their weaknesses: the single hidden state, the strictly step-by-step computation, and the fading of gradients over long distances. You will also meet recurrence again in chapter 22, where newer models revive it. After this chapter you can write an RNN and an LSTM, explain from the numbers why they forget, and state in one sentence what attention changes.

Sequences are different

The networks so far take a fixed-size input: a vector for an MLP, an image of fixed size for a CNN. Sequences break that mould in two ways. They have variable length (a tweet and a contract), and their order carries meaning ("dog bites man" is not "man bites dog"). Treating a sentence as a bag of words discards the order. Cutting it into a fixed window of the last few words, as Bengio and colleagues did in their 2003 neural language model, keeps a little order but cannot see beyond the window, and its input layer grows with the window size.

A recurrent neural network (RNN) handles both problems with the same trick as a convolution (chapter 07): weight sharing, but along time instead of along space. One cell, with one set of weights, is applied at every step. The cell reads the current input xt and a vector ht−1 called the hidden state, which summarises everything read so far, and produces a new hidden state ht. In the simplest form, due to Elman (1990):

ht = tanh( xt Wx + ht−1 Wh + b )

Shapes, in this course's notation: for a batch of B sequences, each xt has shape (B, Cin), Wx is (Cin, H), Wh is (H, H) and ht is (B, H), where H is the hidden size. The input xt is typically an embedding (chapter 06); in our code the input is a one-hot vector, and multiplying it by Wx is the embedding lookup. The cell's parameter count does not depend on the sequence length T, so the same network reads ten tokens or ten thousand.

To feel what the state does, take the smallest possible RNN: one unit, Wx = 1, Wh = 0.5, b = 0, and watch how the last state depends on the first input.

import numpy as np
wx, wh, b = 1.0, 0.5, 0.0                         # a one-unit RNN: h_t = tanh(wx * x_t + wh * h_{t-1} + b)

def run(xs):
    h, trace = 0.0, []
    for x in xs:
        h = np.tanh(wx * x + wh * h + b); trace.append(round(float(h), 4))
    return trace

print("inputs [ 1, -1,  1]  states:", run([1, -1, 1]))
print("inputs [-1, -1,  1]  states:", run([-1, -1, 1]), " <- only the first input changed")
print("inputs [ 1, -1, -1]  states:", run([1, -1, -1]), " <- only the last input changed")
print("\nTen steps later, does the first input still matter?")
for first in (1, -1):
    print(f"  first input {first:+d}, then nine zeros -> final state {run([first] + [0] * 9)[-1]:+.6f}")

Change the first input and the last state moves (from 0.6198 to 0.5076); change the last input and it moves a lot more (to −0.8552). The most recent input dominates. The final test shows the extreme: after nine further steps of silence, the signal from the first input has shrunk from about 0.76 to 0.0014, a factor of roughly 500. The hidden state is a lossy, recency-weighted summary, and with these weights it forgets quickly. Whether it forgets quickly or slowly is decided by the recurrent weights, and the rest of the chapter is about that.

Training: backpropagation through time

Because an unrolled RNN is just a deep network with shared weights, training needs nothing new. You run the forward pass over the whole sequence, compute a loss (at every step, or only at the end), and backpropagate through the unrolled graph (chapter 02). The gradient for each shared weight is the sum of its gradients at every step. This is backpropagation through time (BPTT). In the autograd engine from chapter 05 it falls out of building the graph in a Python loop and calling backward() once.

The problem is in the chain rule. The gradient of the state at step T with respect to the state at step 0 is a product of one Jacobian per step, each equal to diag(1 − ht2) · WhT for a tanh cell. A product of T such matrices tends to shrink towards zero or grow without bound, exponentially in T. Hochreiter (1991) and Bengio, Simard and Frasconi (1994) analysed this, and Pascanu, Mikolov and Bengio ("On the difficulty of training Recurrent Neural Networks", 2012) gave the modern treatment. Here are the actual numbers for a 32-unit tanh RNN whose recurrent matrix is a random orthogonal matrix times a scale, which would preserve vector lengths if the tanh were not there:

import numpy as np
H, Ts = 32, (1, 5, 10, 20, 50, 100)
rng = np.random.default_rng(0)
Q, _ = np.linalg.qr(rng.standard_normal((H, H)))         # a random orthogonal matrix: it neither grows nor shrinks vectors by itself
Wx = rng.standard_normal((H, H)) * 0.5
xs = rng.standard_normal((max(Ts), H))

Look at the top block. With recurrent weights of scale 0.5 to 1.5, a change in the state at step 0 has an effect of between 10-6 and 10-2 on the state 10 steps later and effectively none after 50. That is the vanishing gradient: the loss cannot tell the early weights how they affected a late outcome, so the network cannot learn dependencies that span many steps. The tanh's slope (at most 1, and smaller when saturated) makes it worse even at scale 1.0. With larger weights, in the 3.0 row, the early response grows to about ten within five steps before tanh saturation stops it. The textbook exploding gradient occurs when such growth is not stopped, and it appears as sudden loss spikes and NaNs. The standard defence is gradient clipping (Pascanu et al.): if the norm of the whole gradient exceeds a threshold, rescale it to that threshold. It limits the size of a step without changing its direction (chapter 17 returns to this for large models). Vanishing has no such cheap fix, which is what motivated gated cells.

For long sequences, BPTT over the whole sequence also costs memory proportional to T (every intermediate state must be kept for the backward pass). Truncated BPTT processes the sequence in chunks of, say, 100 steps, carrying the hidden state across chunk boundaries but stopping gradients there. It bounds memory and means the network never gets a learning signal for dependencies longer than the chunk.

The LSTM: a memory with an additive path

The long short-term memory cell (Hochreiter and Schmidhuber, 1997) attacks the vanishing product directly. It keeps a second vector, the cell state ct, updated by addition rather than by squashing through a matrix and a tanh, and it uses learned gates, numbers between 0 and 1 produced by a sigmoid, to control what is erased, written and read. All four computations read the same inputs, [xt, ht−1]:

  • forget gate ft = σ(…): how much of each entry of the old memory to keep (the forget gate was added by Gers, Schmidhuber and Cummins in 2000);
  • input gate it = σ(…): how much of the new candidate to write;
  • candidate gt = tanh(…): the proposed new content;
  • output gate ot = σ(…): how much of the memory to expose.
ct = ft ⊙ ct−1 + it ⊙ gt      ht = ot ⊙ tanh(ct)

where ⊙ is the elementwise product.

The effect on gradients is visible in the second block of the table above. Along the cell-state path, the derivative of ct with respect to ct−1 is just ft (elementwise). If a forget gate stays near 1, the memory and the gradient to it pass through almost untouched: Hochreiter and Schmidhuber called this a constant error carousel. If f is 0.95 the signal is still 0.077 after 50 steps; at 0.73 it is 10-7. So the network can learn to keep a fact for as long as it chooses, by holding the right forget gate near 1 and the input gate near 0. A common trick (Jozefowicz, Zaremba and Sutskever, 2015) is to initialise the forget-gate bias at 1 or higher so that training starts with long memory instead of having to discover it. The GRU (gated recurrent unit; Cho et al., 2014) merges the cell and hidden state and uses two gates instead of three, with similar behaviour at lower cost.

The code

Both cells in the autograd engine of chapter 05, with a few extra operations (sigmoid, concatenation, column slicing) and the clipping function. Note how small the cells are: a step is a handful of lines, and the loop over time is ordinary Python.

import numpy as np
from tinytorch import Tensor
from nn import Module

def sigmoid(x):
    s = 1 / (1 + np.exp(-x.data))
    return Tensor.make(s, (x,), lambda g: (g * s * (1 - s),), "Sigmoid")

def concat(a, b):                                       # join along the feature axis
    n = a.data.shape[1]
    return Tensor.make(np.concatenate([a.data, b.data], 1), (a, b), lambda g: (g[:, :n], g[:, n:]), "Concat")

def cols(x, i, j):                                      # slice columns i:j
    def back(g):
        d = np.zeros_like(x.data); d[:, i:j] = g; return (d,)
    return Tensor.make(x.data[:, i:j], (x,), back, "Slice")

def attend(hs, q):
    """Softmax attention over a list of states hs (each (B, H)) using query q (B, H): returns sum_t a_t h_t."""
    Hs = np.stack([h.data for h in hs], 1)                        # (B, T, H)
    s = np.einsum("bth,bh->bt", Hs, q.data); s -= s.max(1, keepdims=True)
    a = np.exp(s) / np.exp(s).sum(1, keepdims=True)               # attention weights over time, (B, T)
    ctx = np.einsum("bt,bth->bh", a, Hs)
    def back(g):                                                  # g: (B, H)
        da = np.einsum("bh,bth->bt", g, Hs)
        ds = a * (da - (a * da).sum(1, keepdims=True))            # softmax backward
        dH = a[:, :, None] * g[:, None, :] + ds[:, :, None] * q.data[:, None, :]
        return tuple(dH[:, t] for t in range(Hs.shape[1])) + (np.einsum("bt,bth->bh", ds, Hs),)
    return Tensor.make(ctx, tuple(hs) + (q,), back, "Attend"), a

def param(rng, *shape, scale=None):
    scale = scale if scale is not None else 1 / np.sqrt(shape[0])
    return Tensor(rng.uniform(-scale, scale, shape), requires_grad=True)

class RNNCell(Module):                                   # h_t = tanh(x_t Wx + h_{t-1} Wh + b)
    def __init__(self, n_in, n_h, rng):
        self.Wx, self.Wh, self.b = param(rng, n_in, n_h), param(rng, n_h, n_h), Tensor(np.zeros(n_h), requires_grad=True)
        self.n_h = n_h
    def init_state(self, B): return (Tensor(np.zeros((B, self.n_h))),)
    def step(self, x, state):
        (h,) = state
        h = (x @ self.Wx + h @ self.Wh + self.b).tanh(); return h, (h,)

class LSTMCell(Module):                                  # gates i, f, g, o computed together from [x_t, h_{t-1}]
    def __init__(self, n_in, n_h, rng):
        self.W = param(rng, n_in + n_h, 4 * n_h); b = np.zeros(4 * n_h); b[n_h:2 * n_h] = 1.0   # forget-gate bias starts at 1
        self.b = Tensor(b, requires_grad=True); self.n_h = n_h
    def init_state(self, B): return (Tensor(np.zeros((B, self.n_h))), Tensor(np.zeros((B, self.n_h))))
    def step(self, x, state):
        h, c = state; H = self.n_h
        z = concat(x, h) @ self.W + self.b
        i, f, g, o = sigmoid(cols(z, 0, H)), sigmoid(cols(z, H, 2 * H)), cols(z, 2 * H, 3 * H).tanh(), sigmoid(cols(z, 3 * H, 4 * H))
        c = f * c + i * g                                 # additive memory update
        h = o * c.tanh(); return h, (h, c)

def clip_grad_norm(params, max_norm):
    total = np.sqrt(sum(float((p.grad ** 2).sum()) for p in params if p.grad is not None))
    if total > max_norm:
        for p in params:
            if p.grad is not None: p.grad = p.grad * (max_norm / total)
    return total

A gradient check confirms that backpropagation through five time steps gives the right derivatives for both cells (the check also covers an attention read-out used later in the chapter):

import numpy as np
from tinytorch import Tensor, cross_entropy
from nn import Linear
from seqops import LSTMCell, RNNCell, attend, param

rng = np.random.default_rng(5)
for Cell in (RNNCell, LSTMCell):
    cell, head = Cell(3, 4, rng), Linear(4, 3, rng)
    q = param(rng, 4, 4); W = param(rng, 4, 4)
    X = [Tensor(rng.standard_normal((2, 3))) for _ in range(5)]; y = np.array([1, 2])
    def loss():
        state, hs = cell.init_state(2), []

        return cross_entropy(head(ctx), y)

            num[idx] = (up - dn) / 2e-6

An experiment: how long can a cell remember?

The task is the simplest test of memory. A sequence of T symbols from {0, 1, 2, 3} is read one at a time, the first symbol carries a "start" flag, and at the end the network must say what the first symbol was. Distractors come from the same alphabet, so the network has to learn to write the first symbol into its state and ignore the rest. Chance is 25%. All models have 32 hidden units, are trained for 1,500 steps of Adam with gradient clipping at 1.0, and are scored on 1,000 fresh sequences; the table is the mean over three seeds.

import numpy as np
from tinytorch import Tensor, cross_entropy, no_grad
from nn import Linear, Adam
from seqops import RNNCell, LSTMCell, clip_grad_norm

K = 4                                                    # four possible symbols; input has one extra "start" flag channel
def batch(B, T, rng):
    X = rng.integers(0, K, (B, T)); y = X[:, 0].copy()   # distractors come from the SAME alphabet as the answer
    onehot = np.zeros((B, T, K + 1)); onehot[np.arange(B)[:, None], np.arange(T)[None, :], X] = 1; onehot[:, 0, K] = 1
    return onehot, y

def run(Cell, T, steps, seed=0, H=32, fb=None):
    rng = np.random.default_rng(seed); cell, head = Cell(K + 1, H, rng), Linear(H, K, rng)
    if fb is not None: cell.b.data[H:2 * H] = fb         # forget-gate bias: sigmoid(1) = 0.73, sigmoid(5) = 0.99
    ps = [v for v in vars(cell).values() if isinstance(v, Tensor) and v.requires_grad] + head.parameters()
    opt = Adam(ps, lr=0.01)
    for _ in range(steps):
        X, y = batch(32, T, rng); state = cell.init_state(32)
        for t in range(T): h, state = cell.step(Tensor(X[:, t]), state)
        loss = cross_entropy(head(h), y)
        opt.zero_grad(); loss.backward(); clip_grad_norm(ps, 1.0); opt.step()
    X, y = batch(1000, T, np.random.default_rng(99)); state = cell.init_state(1000)
    with no_grad():
        for t in range(T): h, state = cell.step(Tensor(X[:, t]), state)
        return float((head(h).data.argmax(1) == y).mean())

Read it as a story with three parts, and resist the neat version. Up to T = 10 everything works. The vanilla RNN fails slowly and erratically: the means of 85% and 81% at T = 20 and 40 hide seeds that succeeded next to seeds that did not (at T = 40 the three seeds scored 100%, 49% and 93%). At T = 80 it is near chance. The LSTM is not automatically better. With the forget-gate bias at 1 (a gate value of 0.73 at the start) it did worse than the plain RNN at T = 40, because 0.7340 is tiny and the network had to learn to raise the gate within the training budget. With the bias at 5 (a gate value of 0.99) it reaches 100% at T = 40 and 49% at T = 80. The gate is a mechanism; initialisation and training time decide whether it is used. Even the best cell here struggles beyond a few dozen steps in 1,500 steps of training, and real language has dependencies that are subtler than copying a symbol.

Common misconception

"An LSTM solves the vanishing gradient problem, so it remembers arbitrarily long contexts." What the cell state gives is a path along which the gradient can survive; whether the network learns to use it depends on initialisation, optimisation and data. The experiment above shows the same architecture succeeding or failing at T = 40 depending on one bias value. A second point: the hidden state has a fixed size H, so it can hold only so much, however well the gates work. Remembering the first token of a sentence is easy; remembering all fifty tokens in order is a capacity question, which the next section measures.

Sequence to sequence, and the bottleneck

Many tasks map one sequence to another: translating a sentence, summarising, answering a spoken question. In 2014 Sutskever, Vinyals and Le ("Sequence to Sequence Learning with Neural Networks") and Cho et al. ("Learning Phrase Representations using RNN Encoder-Decoder for Statistical Machine Translation") proposed the encoder-decoder design. One RNN, the encoder, reads the source sentence and the final hidden state becomes a summary of it. A second RNN, the decoder, starts from that summary and generates the target sentence one token at a time, each token fed back as the next input. Sutskever et al. reported a BLEU score of 34.8 on WMT'14 English-to-French using deep LSTMs, against 33.3 for a phrase-based baseline system, and noted that reversing the source sentence helped by shortening the distance between corresponding words.

The design has an obvious weakness: whatever the decoder needs to know about the source must pass through one vector of fixed size, whether the source is three words or three hundred. Cho et al. ("On the Properties of Neural Machine Translation: Encoder-Decoder Approaches", 2014) found that translation quality was good on short sentences and degraded as sentences got longer. Bahdanau, Cho and Bengio ("Neural Machine Translation by Jointly Learning to Align and Translate", 2014) conjectured that "the use of a fixed-length vector is a bottleneck" and proposed letting the decoder look back at all the encoder's states at each output step, with learned weights that decide which source positions matter for the word being produced. That is attention.

We can measure the bottleneck directly. The task: read T digits (each tagged with its position), then answer a question, "what digit was at position q?", where q is chosen after the sequence ends. Two models share the same LSTM with 16 hidden units. One answers from the final hidden state alone. The other answers from an attention read-out over all of the LSTM's states, using the question to choose which state to read (the operation is the weighted sum of the figure; chapter 09 derives it properly).

import numpy as np
from tinytorch import Tensor, cross_entropy, no_grad
from nn import Linear, Adam
from seqops import LSTMCell, attend, param, clip_grad_norm

V = 10                                                   # digits 0-9

def batch(B, T, rng):                                    # read T digits, then answer: "which digit was at position q?"
    digits = rng.integers(0, V, (B, T)); q = rng.integers(0, T, B); y = digits[np.arange(B), q]
    X = np.zeros((B, T, V + T + 1))
    X[np.arange(B)[:, None], np.arange(T)[None, :], digits] = 1                    # the digit
    X[:, np.arange(T), V + np.arange(T)] = 1                                       # and which position it is at
    return X, q, y

def run(kind, T, steps=2000, H=16, seed=0):
    rng = np.random.default_rng(seed)
    cell, head, Wq = LSTMCell(V + T + 1, H, rng), Linear(H, V, rng), param(rng, T, H)
    ps = [cell.W, cell.b] + head.parameters() + ([Wq] if kind == "attention" else [])
    opt = Adam(ps, lr=0.01)

    def forward(X, q):
        B = len(q); state = cell.init_state(B); hs = []
        for t in range(T):
            h, state = cell.step(Tensor(X[:, t]), state); hs.append(h)
        ask = np.zeros((B, V + T + 1)); ask[np.arange(B), V + q] = 1; ask[:, -1] = 1   # the question arrives as one more input
        h, _ = cell.step(Tensor(ask), state)
        if kind == "final state": return head(h)                    # everything must pass through one H-sized vector
        ctx, _ = attend(hs, Tensor(np.eye(T)[q]) @ Wq)              # look back at ALL states, weighted by relevance
        return head(ctx)
    for _ in range(steps):
        X, q, y = batch(64, T, rng); loss = cross_entropy(forward(X, q), y)
        opt.zero_grad(); loss.backward(); clip_grad_norm(ps, 1.0); opt.step()
    X, q, y = batch(1000, T, np.random.default_rng(99))
    with no_grad(): return float((forward(X, q).data.argmax(1) == y).mean())

if __name__ == "__main__":
    print(f"mean of 3 seeds, hidden size 16, chance 10%   {'T=4':>6s}{'T=8':>6s}{'T=16':>6s}")
    for kind in ("final state", "attention"):
        print(f"{kind:45s}" + "".join(f"{np.mean([run(kind, T, seed=s) for s in range(3)]):6.0%}" for T in (4, 8, 16)))

final state                                     95%   45%   31%
attention                                      100%  100%  100%

With four digits both approaches work (the final-state model gets 95%, since 4 digits of about 3.3 bits fit in 16 numbers). As T grows the final-state model degrades to 45% at 8 digits and 31% at 16, because the single vector must hold every digit in case it is asked about. The attention model scores 100% at every length: the information is kept in the T states, and the question decides where to look. Note what this does and does not show. The final-state model could do better with more hidden units or more training, so the point is not that its failure is absolute but that its capacity is a fixed budget set before the question is known. The attention model's memory grows with the input, at a price: it must keep all T states and compare against them.

Why recurrence gave way

Attention solved the bottleneck inside the encoder-decoder RNN. Vaswani et al. (2017, "Attention Is All You Need") then asked whether the recurrence was needed at all. Their argument against it was about computation, not accuracy. In an RNN, step t cannot start until step t − 1 finishes, because it needs ht−1. They write that this "sequential nature precludes parallelization within training examples, which becomes critical at longer sequence lengths". A GPU has thousands of cores and an RNN offers them only a batch dimension to work with. Their Table 1 compares the layer types:

Layer typeSequential operationsLongest path between two positionsCompute per layer (sequence length n, width d)
RecurrentO(n)O(n)O(n · d2)
Self-attentionO(1)O(1)O(n2 · d)

Read it as follows. In an RNN, information from position 1 reaches position n only by passing through n updates, each one a chance to fade; in self-attention any position can read any other directly. The RNN needs n steps in sequence; attention does the whole layer as a few large matrix multiplications that parallelise well. The price is the n2 term: attention compares every pair of positions, which is what makes long contexts expensive (chapter 19). RNNs have one real advantage that the table hides. At inference an RNN needs only its fixed-size state to continue, so memory per token generated does not grow; a Transformer keeps a growing cache of past keys and values.

State of play, October 2026

Transformers dominate language modelling and most sequence tasks, but recurrence has not disappeared. Newer architectures, discussed in chapter 22, revive a fixed-size state with designs that can still be trained in parallel, motivated by the cost of attention on very long inputs. Lightweight LSTM or GRU models remain in use where latency, memory and streaming matter on small devices. Treat claims about which architecture "wins" as dated: the evidence shifts with scale and with the task, and the clean statement that survives is the trade-off in the table above.

Analogy: reading with one sticky note

Imagine you may read a long document only once, and after each sentence you must rewrite a single sticky note that is all you will carry forward. The note can hold a few facts. Early in the document you write down the main character's name; ten pages later the note has been rewritten so many times that the name has been squeezed out unless you made a point of keeping it. A gate is a rule of the form "never overwrite this part of the note".

Where it breaks down: a person decides deliberately what to keep and can glance back at the page; the network's rule is learned by gradient descent, gets no hint about what will matter later, and in the plain version has no way to look back. Attention is, in effect, permission to reread the document.

Systems connection

A step-by-step dependency is a serial fraction in the sense of Amdahl's law: extra GPU cores cannot speed up work that must happen in order. RNN training therefore parallelises across the batch but not across time, which is why batching sequences (padding them to a common length, or packing similar lengths together) matters so much for utilisation. At serving time the RNN's hidden state is per-session state, the kind of thing you must store, route and recover (by replaying a log, for example), while a Transformer's equivalent is the key-value cache whose size grows with the conversation. The same trade-off, small constant state against large growing state, shows up in the design of services that hold sessions.

Key takeaways

  • An RNN applies one cell with shared weights at every step, carrying a fixed-size hidden state. Unrolled, it is a deep network, trained by backpropagation through time.
  • Gradients through T steps are products of T Jacobians, so they shrink or grow exponentially. Clipping cures explosions; vanishing limits what plain RNNs can learn over long ranges.
  • The LSTM keeps a cell state updated additively under learned gates, giving the gradient a path that can survive. It helps only if initialised and trained to use it: in our test the same cell failed or succeeded at T = 40 depending on the forget-gate bias.
  • An encoder-decoder squeezes the source through one fixed-size vector. Our measurement showed accuracy falling from 95% to 31% as the amount to remember grew, while an attention read-out stayed at 100%.
  • RNNs gave way to attention because of sequential computation, long paths between positions and the bottleneck, at the price of quadratic cost; their constant-size state is why they are being revisited.

Weight sharing across time means the cell has an input matrix (50 x 128) and a recurrent matrix (128 x 128), reused at every step regardless of T. Counting per step would describe an unshared deep network.

In the one-unit RNN example, why does the final state react more to a change in the last input than to a change in the first?

  1. The last input is multiplied by a larger weight
  2. The influence of earlier inputs passes through repeated squashing by W_h and tanh, so it shrinks at every step
  3. The network is trained to ignore its first input
  4. The first input is always normalised away
The same weight multiplies every input; what differs is how many times the contribution is passed through the recurrence (a factor w_h and tanh slope each time), so older inputs fade. Nothing in the example is trained, so the third option is wrong.

Which statement about the forget gate of an LSTM is correct?

  1. When it is near 1, the cell state and its gradient pass from step to step almost unchanged along the additive path
  2. When it is near 0, the cell keeps all of its memory
  3. It is a hyperparameter you set once and cannot learn
  4. It controls how much of the output is shown to the next layer
The cell update is c_t = f * c_(t-1) + i * g, so the derivative along the memory path is f; near 1 it keeps both memory and gradient. Near 0 it erases memory. It is learned like any other gate, and the output gate (not the forget gate) controls what is exposed.

In the memory experiment, an LSTM with forget bias 1 got 24% at T = 40 while the same LSTM with bias 5 reached 100%. What is the best explanation?

  1. The model with bias 5 has more parameters
  2. Bias 1 makes the LSTM unable to use its cell state at all
  3. A gate value of 0.73 shrinks the memory by a factor of millions over 40 steps unless training raises it, while 0.99 starts with a long memory
  4. Bias 5 effectively raises the learning rate, so the model trains faster
sigmoid(1) = 0.73 and 0.73^40 is about 3 x 10^-6, so at initialisation the memory and gradient vanish; sigmoid(5) = 0.993 keeps most of the signal. The parameter counts are identical, and the cell state can be used with bias 1; it just has to be learned within the budget.

A decoder RNN is given only the final hidden state of an encoder with 16 units. Which prediction about accuracy at recalling arbitrary digits from the source is best supported?

  2. It declines as the number of digits to remember grows, because the state has a fixed capacity

  4. It depends only on the learning rate
A fixed-size vector can hold only a limited amount of information, and in the experiment accuracy fell from 95% at four digits to 31% at sixteen. The attention read-out kept all T states and stayed at 100%. Longer inputs add to the demand without adding capacity.

Which is the main reason Vaswani et al. gave for dropping recurrence?

  1. Recurrent models cannot represent word order
  2. Recurrent models were less accurate on every benchmark
  3. Recurrent layers need more parameters than attention layers
  4. Each step depends on the previous one, so training cannot be parallelised across positions, and information must travel through many steps
Their argument is about sequential computation and path length (Table 1). RNNs can represent order perfectly well, and the parameter count of the recurrent layer was not the issue. Accuracy claims were part of the paper's results but not the stated reason for removing recurrence.
