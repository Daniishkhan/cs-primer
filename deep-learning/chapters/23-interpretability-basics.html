Interpretability Basics

A trained transformer is a pile of numbers that works. Interpretability asks what those numbers compute. This chapter gives you four basic tools: probes, attention patterns, activation patching and sparse autoencoders. It also gives the picture of the residual stream that ties them together, and one warning: finding a feature is not the same as showing the model uses it.

Why this matters

This is reading for the literacy pack, not a step of any artifact. It helps most alongside Artifact 3 (the evaluator-hardening kit), where you must say whether a grader is doing what its outputs suggest. It also helps with Artifact 2, where a score alone rarely says why a search agent behaved as it did. You will not become an interpretability researcher here. You will be able to read a post that says "we found a feature for X" and ask three questions: how was it found, was it tested by intervention, and on what data?

The residual stream is a shared channel

In chapter 10 every block added its output to its input rather than replacing it. Followed through all the layers, this gives one running vector per token position, called the residual stream. The token embedding writes the first version of it. Each attention head and each MLP (multilayer perceptron, the feed-forward part of the block) reads the current stream, computes something, and adds the result back. At the end the unembedding reads the stream and produces the next-token scores.

Elhage et al. (2021, "A Mathematical Framework for Transformer Circuits") describe this as a shared communication channel: components "communicate with each other by reading and writing to different subspaces of the residual stream". A subspace here is a direction, or a few directions, in the vector. If one head writes along one direction and a later MLP reads along that same direction, the two have a private wire inside the shared bus, even though no weight connects them directly.

This picture lets interpretability talk about features. A feature is a property of the input (the token is a name, the sentence is in French) that the model represents as a direction in the stream. It also says where to look. To ask "what does the model know at layer 6?", read the stream at layer 6. To ask "which component produced that?", find the component whose write moved it.

Linear probes: is the information there?

The cheapest tool is a linear probe. Freeze the model and collect the residual-stream vectors at one layer for many inputs. Then train a linear classifier to predict a label (say, whether the sentence is true) from them. Alain and Bengio (2016, "Understanding intermediate layers using linear classifier probes") proposed monitoring each layer with classifiers trained separately from the model. They found on image networks that linear separability generally increases with depth. ARENA (the Alignment Research Engineer Accelerator, a London bootcamp whose public curriculum this chapter follows) has a probes section (1.3.1) that trains probes to detect deception in a model playing the game Coup.

The script builds the smallest version of the whole story. A 16-dimensional "stream" carries two binary features, A and C, along orthogonal random directions, plus noise. C copies A 90% of the time, and the downstream readout reads only the A direction. The script trains a probe for each feature and for a shuffled-label control, then runs the second tool, activation patching, which the next section explains.

"""Probe versus patch: a probe finds a feature, patching asks if it matters.

Synthetic residual stream: width D = 16. Two binary features are written
along fixed random directions: A (used by the downstream readout) and C
(a copy of A 90% of the time, but never read downstream).
"""
import numpy as np

rng = np.random.default_rng(0)
D, N = 16, 2000                                  # stream width, examples

# ── 1. Build the residual stream ───────────────────────────────────────
dirA, dirC = rng.normal(size=D), rng.normal(size=D)
dirC -= (dirC @ dirA) / (dirA @ dirA) * dirA     # make C orthogonal to A
dirA, dirC = dirA / np.linalg.norm(dirA), dirC / np.linalg.norm(dirC)
a = rng.integers(0, 2, N)                        # feature A, 0 or 1
c = np.where(rng.random(N) < 0.9, a, 1 - a)      # feature C: 90% agrees
noise = 0.5 * rng.normal(size=(N, D))
resid = 2.0 * np.outer(a, dirA) + 2.0 * np.outer(c, dirC) + noise
readout = dirA                                   # downstream reads A only

# ── 2. Train a logistic probe by gradient descent ──────────────────────
def train_probe(X, y, steps=500, lr=0.5):
    w, b = np.zeros(D), 0.0
    for _ in range(steps):
        p = 1 / (1 + np.exp(-(X @ w + b)))
        w -= lr * X.T @ (p - y) / len(y)
        b -= lr * np.mean(p - y)
    return w, b

def acc(X, y, w, b):
    return np.mean(((X @ w + b) > 0) == y)

tr, te = slice(0, 1500), slice(1500, N)
for name, y in (("A", a), ("C", c), ("shuffled A", rng.permutation(a))):
    w, b = train_probe(resid[tr], y[tr])
    a_ = acc(resid[te], y[te], w, b)
    print(f"probe for {name:<10} held-out accuracy {a_:.2f}")

# ── 3. Patch: swap one feature's component, watch the downstream score ─
def score(X): return X @ readout                 # what the next layer reads

def patch(X, direction, donor):
    """Replace X's component along `direction` with the donor's."""
    out = X.copy()
    out += np.outer(donor @ direction - X @ direction, direction)
    return out

clean = resid[te]
corrupt = clean[::-1]                            # run on other prompts
for name, d in (("A direction", dirA), ("C direction", dirC)):
    shift = np.mean(np.abs(score(patch(clean, d, corrupt)) - score(clean)))
    print(f"patching {name}: mean change in downstream score {shift:.2f}")
probe for A          held-out accuracy 0.98
probe for C          held-out accuracy 0.99
probe for shuffled A held-out accuracy 0.49
patching A direction: mean change in downstream score 1.31
patching C direction: mean change in downstream score 0.00

Both probes reach about 98 to 99% on held-out examples, and the shuffled-label control sits at chance (0.49), which is the check that the probe is finding structure rather than memorising. A probe, then, tells you that the information is linearly readable at that point. It does not tell you the model reads it.

Activation patching: does it matter?

Activation patching asks the causal question. Run the model on a clean input and on a corrupted one. Then copy one activation (a layer, position, head or direction) from one run into the other and see whether the output moves. Heimersheim and Nanda (2024, "How to use and interpret activation patching") give a tutorial on it that covers the variants and how to read the results. They also show how the choice of metric can mislead.

The last two lines of the probe output show it. Swapping the component along A changes the downstream score by 1.31 on average. Swapping the component along C changes it by 0.00, although a probe reads C almost perfectly. C is a feature that is represented, correlated with the real one, and unused. A probe alone could not have told these apart.

Common misconception

"If a probe can decode it, the model uses it." A probe measures what a different classifier could read. A large residual stream holds many readable things (here, a copy of A) that no later layer touches. Patching, ablation or steering tests the other direction: change the activation and see whether behaviour changes. Good interpretability results report both, and say which one a claim rests on.

Attention patterns: where information moves

The attention weights of chapter 9 are the most directly visible internals: for each head and each position, a row of weights over earlier positions. Plotted as a grid, they show where that head looks. Heads often specialise: one attends to the previous token, another to the start of the sentence, another to an earlier copy of the current token. The pattern tells you what a head reads, but the OV circuit is a separate question. This is the output-value path, which sets what the head writes into the stream. A head can attend strongly to a place and write almost nothing useful. Attention patterns are therefore a good place to form a hypothesis and a poor place to stop. ARENA's section 1.2 uses TransformerLens to extract activations, apply hooks and find important attention heads, and section 1.4.1 reverse-engineers a full circuit, the indirect object identification circuit in GPT-2 small (OpenAI's 2019 generative pre-trained transformer, GPT). In the next chapter you will meet induction heads again, as one proposed mechanism for in-context learning.

Sparse autoencoders: finding the directions

Probes need a label you chose in advance. What if you want the model's own features? The obstacle is superposition: Elhage et al. (2022, "Toy Models of Superposition") show in a toy model that a network can store more sparse features than it has dimensions by packing them into overlapping directions. This makes single neurons polysemantic, responding to several unrelated things, so reading neuron activations does not read features.

A sparse autoencoder (SAE) is trained on the activations of one layer. It expands each activation vector into a much wider vector of non-negative codes, penalised so that only a few are non-zero for any input, then reconstructs the original from them. Each column of the decoder is a candidate feature direction. Cunningham et al. (2023, "Sparse Autoencoders Find Highly Interpretable Features in Language Models") report that, by automated measures, the features found this way are more interpretable and more monosemantic than those from alternative methods. They also pinpoint which features causally drive behaviour on the indirect object identification task. The same caution applies as for probes: a feature that looks meaningful in its top-activating examples is a hypothesis until an intervention (patching or steering) shows it matters. ARENA covers this in sections 1.3.3 (SAEs), 1.4.2 (SAE circuits) and 1.5.4 (superposition and SAEs).

Analogy: a shared whiteboard

Picture the residual stream as one whiteboard that every employee in a building reads and writes in turn. A probe is a visitor who photographs the board at 3 p.m. and checks whether the word "invoice" is legible. Patching is rubbing out one corner and watching whether the next employee's work changes. An SAE is an attempt to work out, from many photographs, which short notes people habitually write, even though they overwrite each other in the same space.

Where it breaks down: a whiteboard keeps notes in separate places, but the residual stream stores features as overlapping directions in the same numbers, which is exactly why decomposing it is hard.

Systems connection

Interpretability tooling is observability for a model. A hook that records an activation is a trace span; a probe is a monitor that reads a metric; patching is fault injection, replacing one component's output to see what depends on it. The same lesson holds in distributed systems: a metric that correlates with a failure is not yet its cause, and you confirm a dependency by perturbing it.

Key takeaways

  • The residual stream is a shared channel: every component reads from it and adds to it, and features are directions in it.
  • A linear probe shows information is readable at a layer; use a shuffled-label control, and do not read it as "the model uses this".
  • Activation patching tests use: copy an activation between runs and measure the output. In the example, a perfectly decodable feature had zero effect.
  • Attention patterns show where a head reads, not what it writes, so they suggest hypotheses rather than settle them.
  • Sparse autoencoders try to recover the model's own feature directions despite superposition; their features still need causal tests.

Check your understanding

A probe for the feature "the subject is plural" reaches 97% held-out accuracy at layer 8. What can you conclude?

  1. The model uses that feature to choose verb forms
  2. The feature is stored in a single neuron
  3. The information is linearly readable from layer 8, but whether the model uses it is untested
  4. The probe has memorised the training set
High held-out accuracy shows the information is linearly decodable. Use is a causal claim and needs an intervention such as patching. Held-out accuracy argues against memorisation, and a linear probe says nothing about single neurons.

In the script, patching the C direction changed the downstream score by 0.00 while patching the A direction changed it by 1.31. Why?

  1. The downstream readout depends on A and ignores C, so overwriting C changes nothing it reads
  2. The C probe was less accurate than the A probe
  3. C is noisier than A
  4. Patching only works on the first feature written
The readout is the dot product with the A direction, and C was made orthogonal to it. The C probe was actually slightly more accurate (0.99 against 0.98), so probe accuracy cannot explain the gap.

Why are individual neurons often a poor unit for finding features?

  1. Neurons are too slow to record
  2. Each neuron is connected to only one other neuron
  3. Neurons store features only in the final layer
  4. With superposition a network packs more sparse features than it has dimensions into overlapping directions, so a neuron responds to several unrelated things
This is the polysemanticity result of the toy-models paper, and the reason sparse autoencoders look for directions instead of neurons. The other options are not claims the literature makes.

A head's attention pattern looks sharply focused on the previous token. What is the safest statement?

  1. The head copies the previous token into the output
  2. The head reads the previous token's stream position; what it writes needs a separate check
  3. The head is unimportant because the pattern is simple
  4. The model cannot attend further back
The pattern shows the read side only. The OV circuit decides what is written, and ablation or patching decides whether it matters. Simplicity of a pattern says nothing about importance.
