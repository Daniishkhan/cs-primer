The Language-Modelling Objective

Every large language model is trained on one number: the average surprise of the next token. This chapter derives that number from probability, shows why its gradient is so simple, translates it between nats, bits, perplexity and bits per byte, measures what a model has learned at each step up a ladder of simple baselines, and explains what a low loss does and does not tell you.

Why this matters

The loss is the one metric available at every step of every training run, it is the quantity scaling laws predict, and it is what you will watch when a run misbehaves. But it is easy to misread: perplexity numbers from different tokenisers cannot be compared, a masked loss is a different loss, and a loss that looks superb may come from a leak. After this chapter you can derive the cross-entropy objective and its gradient, convert any reported loss into bits per byte so that models with different tokenisers can be compared, explain what a given perplexity means, use n-gram baselines to judge whether a model has learned anything, and say what the objective teaches a model and what it leaves open. It builds on chapter 12's model and the information-theory background of A0 (the A0 chapters on maximum likelihood and on entropy and KL divergence), restated here so the chapter stands alone.

Language as a chain of predictions

A language model should say how probable any piece of text is. Write a text as tokens x1, x2, …, xN. The chain rule of probability, which is an identity and not a modelling assumption, says that the probability of the whole sequence is the product of each token's probability given everything before it:

p(x1, …, xN) = p(x1) · p(x2 | x1) · p(x3 | x1, x2) · … · p(xN | x1, …, xN−1) = ∏t p(xt | x<t).

So a model that can predict the next token from the previous ones, which is all a GPT does, defines a probability for every possible text, with no approximation. That is the justification for next-token prediction as an objective: it is a complete description of a distribution over sequences, split into steps the network can learn one at a time. The other factorisations exist (predict a masked word from both sides, as BERT does; predict a sequence from another sequence, as translation models do), but the left-to-right one is the one that also lets you sample text, by drawing one token, appending it and repeating (chapter 15).

The trained chapter-12 model can score a string with this product. The script below sums the log-probabilities of every character of a line given the characters before it, and does the same for two scrambled versions of the line: one with the words shuffled and one with the characters shuffled. Using logarithms turns the product into a sum and avoids numbers too small to store.

import math, numpy as np
from gpt_model import CFG, forward
p = dict(np.load("gpt.npz"))
text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
val = text[int(0.9 * len(text)):]

def log_prob(s):                                           # ln p(s) by the chain rule, from one forward pass
    ids = np.array([[stoi[c] for c in s]])
    lg = forward(p, ids[:, :-1], CFG)[0].astype(np.float64)
    z = lg - lg.max(-1, keepdims=True); lp = z - np.log(np.exp(z).sum(-1, keepdims=True))
    return float(lp[np.arange(len(s) - 1), ids[0, 1:]].sum())          # the first character is given, not predicted

line = "Yet read the gamut of Hortensio.\n"
rng = np.random.default_rng(0)
words = line.split(" ")
variants = {
    "the real line": line,
    "words shuffled": " ".join(rng.permutation(words)),
    "characters shuffled": "".join(rng.permutation(list(line))),
}
for name, s in variants.items():
    lp = log_prob(s)
    print(f"{name:20s} {s!r:40s} ln p = {lp:7.1f}   per character {-lp / (len(s) - 1):.2f} nats")

characters shuffled  'rif t mre.eYHo h\ntaeoo un sgdetta'     ln p =  -168.0   per character 5.25 nats

The real line costs 72.4 nats in total, 2.26 per character. Shuffling the words keeps the spelling but breaks the grammar, and the cost rises to 84.4: the model has learned something about word order, even at this tiny scale. Shuffling the characters keeps only the letter frequencies, and the cost jumps to 168 nats, 5.25 per character, which is worse than guessing uniformly (ln 65 = 4.17). The model is confident about structure that is not there, and confident predictions that turn out wrong are punished hard, as the next section shows.

Cross-entropy: the loss

We want the model's probabilities to be high for the text that actually occurs. The standard criterion is maximum likelihood: choose the weights θ that maximise the probability the model assigns to the training text. Maximising a product is the same as maximising its logarithm, and it is conventional to minimise rather than maximise, so we minimise the negative log-likelihood, averaged over the N predictions so that its size does not depend on how much text we use:

Plug in numbers. Four positions with the probabilities the model gave to the true next token. Each line is one step above, ending with perplexity.

The idea

  1. P_TRUE: the probability given to the true next token at each position
  2. cost per position ← −ln p
  3. L ← (sum of the costs) ÷ N, in nats
  4. perplexity ← eL; anchor: uniform over 50,257 tokens
"""Cross-entropy and perplexity for four predictions."""
import math

# ── 1. The probability the model gave the token that really came next ────
P_TRUE = [0.5, 0.25, 0.1, 0.8]    # p(x_t | x_<t), one per position
N = len(P_TRUE)

# ── 2. The cost of each position: -ln p ──────────────────────────────────
costs = [-math.log(p) for p in P_TRUE]
for t, (p, c) in enumerate(zip(P_TRUE, costs), start=1):
    print(f"position {t}: p = {p:<4}  -ln p = {c:.3f} nats")

# ── 3. Sum over positions, then average over the N predictions ───────────
total = sum(costs)
loss = total / N
print(f"sum = {total:.3f}, N = {N}, L = {loss:.3f} nats")

# ── 4. Perplexity: e^L, the effective number of equally likely choices ───
print(f"perplexity = e^{loss:.3f} = {math.exp(loss):.2f}")

# ── 5. Anchor: a model that guesses uniformly over 50,257 tokens ─────────
V = 50257
print(f"uniform over V = {V}: L = ln V = {math.log(V):.2f} nats")
position 1: p = 0.5   -ln p = 0.693 nats
position 2: p = 0.25  -ln p = 1.386 nats
position 3: p = 0.1   -ln p = 2.303 nats
position 4: p = 0.8   -ln p = 0.223 nats
sum = 4.605, N = 4, L = 1.151 nats
perplexity = e^1.151 = 3.16
uniform over V = 50257: L = ln V = 10.82 nats

This is the cross-entropy loss. For each position the network outputs logits z (one real number per vocabulary entry); the model's distribution is the softmax pj = ezj / ∑k ezk; and the loss at that position is −ln py where y is the true next token. A probability of 1 costs nothing, 0.5 costs 0.69, 0.1 costs 2.3, and the cost grows without bound as the probability approaches zero. Step through one position with five candidate words.

Step through

One prediction: from logits to loss to gradient

  1. The network's scores. After "the cat sat on the" the network gives each candidate a logit: a raw score, positive or negative, with no meaning until normalised.
  2. Exponentiate. ez makes every score positive and magnifies differences: a gap of 1 in the logits becomes a factor of 2.7. The five values add up to 13.124.
  3. Normalise: the softmax. Dividing by the sum gives probabilities that add to 1: "mat" 0.563, "cat" 0.207, and so on. This is the model's belief about the next word.
  4. Look up the truth. The text actually continued with "mat". Only this one probability enters the loss; the model gets no direct credit for how it spread the rest.
  5. Take −ln. The loss is −ln 0.563 = 0.574 nats (0.83 bits). Had the model given "mat" probability 0.99 the loss would be 0.01; at 0.01 it would be 4.6.
  6. The gradient. The derivative of this loss with respect to each logit is simply p minus the one-hot target: −0.437 for "mat" (raise its logit) and +p for every other word (lower them, in proportion to how much probability they hold). The gradients add up to zero.

Here is the same example in code, with the checks that matter: the gradient against finite differences, the numerical trap in softmax, and the relation between per-token loss, sequence probability and perplexity.

import math
import numpy as np

# Context: "the cat sat on the ___"; the true next word is "mat".
words = ["mat", "hat", "cat", "dog", "the"]
logits = np.array([2.0, 0.5, 1.0, -1.0, 0.0])
target = 0

z = logits - logits.max()                      # subtracting the max changes nothing and prevents overflow
probs = np.exp(z) / np.exp(z).sum()
loss = -math.log(probs[target])
grad = probs.copy(); grad[target] -= 1         # d loss / d logits = p - onehot
show = lambda a, f=".3f": "  ".join(f"{w} {x:{f}}" for w, x in zip(words, a))
print("probs   ", show(probs))
print(f"loss = -ln p(mat) = {loss:.4f} nats = {loss / math.log(2):.4f} bits;  perplexity of this one prediction = {math.exp(loss):.3f}")
print("gradient", show(grad, "+.3f"), "  (sums to %.1f)" % grad.sum())

# numerical check of that gradient
eps, num = 1e-6, []
for i in range(len(logits)):
    lp, lm = logits.copy(), logits.copy(); lp[i] += eps; lm[i] -= eps
    f = lambda l: -(l[target] - np.log(np.exp(l).sum()))
    num.append((f(lp) - f(lm)) / (2 * eps))
print("numerical", show(num, "+.3f"))

# Why the loss is computed from logits, not from probabilities
big = np.array([1000.0, 999.0, 0.0])
with np.errstate(all="ignore"):
    naive = np.exp(big) / np.exp(big).sum()
    print("\nnaive softmax of [1000, 999, 0]:", naive, "-> log:", np.log(naive))
zb = big - big.max()
print("log-sum-exp form             :", np.round(zb - np.log(np.exp(zb).sum()), 4).tolist())

# A whole sequence: the loss is the mean of per-token losses, the sequence probability is their product
p_correct = np.array([0.30, 0.55, 0.10, 0.80, 0.25])        # the model's probability for each true next token
nll = -np.log(p_correct)
print("\nper-token losses:", nll.round(3), " mean:", round(float(nll.mean()), 4))
print("probability of the whole sequence:", round(float(p_correct.prod()), 5), " = exp(-sum) =", round(float(np.exp(-nll.sum())), 5))
print("perplexity exp(mean loss):", round(float(np.exp(nll.mean())), 3), " = 1 / geometric mean of the probabilities:", round(float(1 / p_correct.prod() ** (1 / 5)), 3))

# Loss masking: score only the positions that matter (here the last three), ignore the rest
mask = np.array([0, 0, 1, 1, 1], bool)
print("masked mean over the 3 answer positions:", round(float(nll[mask].mean()), 4), " (all five:", round(float(nll.mean()), 4), ")")

Three observations. The numerical gradient matches p − one-hot to three decimals, which is the gradient chapter 12 used at the start of its backward pass. The naive softmax of logits [1000, 999, 0] returns NaN (exp(1000) overflows), while the log-sum-exp form, which subtracts the maximum first, is exact; this is why every framework offers a fused cross_entropy(logits, targets) and why you should never apply log(softmax(x)) by hand (A0 chapter 11 covers the numerics). And for a sequence, the mean per-token loss is 1.1428, whose exponential is the perplexity 3.135.

Go deeper: why the gradient is p − y, and what the loss really measures optional derivations

The gradient. With one-hot target y the loss is L = −zy + ln ∑k ezk. The derivative with respect to zj has two terms. The first is −1 if j = y and 0 otherwise. The second is ezj / ∑k ezk = pj. So ∂L/∂zj = pj − 1[j = y]. Averaging over N positions divides by N. This is a general fact for softmax outputs trained with cross-entropy: the error signal is the predicted distribution minus the target distribution.

Entropy and KL divergence. Let the true next-token distribution at some context be p and the model's be q. The expected loss is the cross-entropy H(p, q) = −∑ pj ln qj. It splits exactly as H(p, q) = H(p) + KL(p ‖ q), where H(p) = −∑ pj ln pj is the entropy of the real distribution and KL(p ‖ q) = ∑ pj ln(pj/qj) ≥ 0 is the extra cost of using q instead of p. Two consequences. The loss can never go below the entropy of the data: some text is genuinely unpredictable (what name comes next in a list of strangers?) and no model can remove that part. And minimising the loss is the same as minimising the KL divergence from the true distribution to the model's, which is why the KL divergence reappears in every post-training method (A3 chapters 08 and 12), where it keeps a fine-tuned model close to the original.

Why not accuracy? Accuracy, the fraction of positions where the top prediction is right, is not differentiable and ignores confidence: a model that gives the right answer 0.51 and one that gives it 0.99 have the same accuracy. The log-loss rewards calibrated probabilities, is smooth, and is a proper scoring rule: its expected value is minimised exactly when the model's probabilities equal the true ones.

Units: nats, bits, perplexity and bits per byte

The same quantity is quoted in several units, and confusing them is a common source of bad comparisons.

  • Nats per token. The natural logarithm, what frameworks compute. The loss of a model that guesses uniformly over V tokens is ln V.
  • Bits per token. The same loss divided by ln 2 = 0.693. The loss is the average number of bits an ideal compressor using the model's probabilities would need per token (arithmetic coding makes this literal), which is why information theory describes it.
  • Perplexity, exp(L). It is the inverse geometric mean of the probabilities given to the true tokens, and has a readable meaning: the model is as uncertain as if it were picking uniformly among exp(L) equally likely options at each step. A perplexity of 65 over a 65-character vocabulary means the model knows nothing; 5.3 means it narrows each prediction down to about five characters. The example in ce_demo.py has perplexity 3.1.
  • Bits per byte (bpb) or bits per character: the total bits needed, divided by the number of bytes or characters of the original text, not the number of tokens.

The last unit exists because perplexity per token depends on the tokeniser. A model that predicts bigger chunks (longer tokens) has fewer, harder predictions and a higher per-token perplexity, even if it is no worse at predicting the text. To compare models with different tokenisers you convert to a per-byte figure: bits per byte = (loss in nats per token × tokens) / (bytes × ln 2). The next script trains simple count-based models at two granularities on Shakespeare and compares them in both ways. The model family is the same (an interpolated n-gram model, defined in the next section) at the character level and at the level of the 768-token BPE vocabulary of chapter 13.

import math
from collections import defaultdict, Counter
import numpy as np
from bpe import train_bpe, encode

text = open("input.txt", encoding="utf-8").read()
cut = int(0.9 * len(text)); train_t, val_t = text[:cut], text[cut:]

def wb_loss(train, val, V, hist_len):
    """Mean negative log-likelihood (nats per symbol) of an interpolated (Witten-Bell) model."""
    ctx = [defaultdict(Counter) for _ in range(hist_len + 1)]
    for i in range(len(train)):
        for k in range(min(hist_len, i) + 1):
            ctx[k][tuple(train[i - k:i])][train[i]] += 1
    tot = [{h: sum(c.values()) for h, c in d.items()} for d in ctx]
    nll = 0.0
    for i in range(len(val)):
        p = 1.0 / V
        for k in range(min(hist_len, i) + 1):
            h = tuple(val[i - k:i]); cnt = ctx[k].get(h)
            if cnt is None: break
            p = (cnt[val[i]] + len(cnt) * p) / (tot[k][h] + len(cnt))
        nll -= math.log(p)
    return nll / len(val)

merges = train_bpe(train_t, 512)
rows = []
chars_tr = [ord(c) for c in train_t]; chars_va = [ord(c) for c in val_t]
tok_tr, tok_va = encode(train_t, merges), encode(val_t, merges)
nbytes = len(val_t.encode())
print(f"validation text: {nbytes:,} bytes; as characters {len(chars_va):,} symbols; as BPE tokens (V=768) {len(tok_va):,} symbols")
print(f"{'model':26s} {'loss/symbol':>11s} {'perplexity':>11s} {'bits per byte':>14s}")
for name, tr, va, V, hl in [("characters, bigram", chars_tr, chars_va, 65, 1), ("characters, 5-gram", chars_tr, chars_va, 65, 4),
                            ("BPE tokens, unigram", tok_tr, tok_va, 768, 0), ("BPE tokens, bigram", tok_tr, tok_va, 768, 1)]:
    l = wb_loss(tr, va, V, hl)
    print(f"{name:26s} {l:11.3f} {math.exp(l):11.1f} {l * len(va) / nbytes / math.log(2):14.3f}")

The character 5-gram has perplexity 5.3 per character, the BPE-token bigram 48.0 per token. Judged by perplexity the second is nine times worse, which is nonsense: its tokens are about twice as long. In bits per byte the two are 2.41 and 2.65, a fair comparison that says the character model with four characters of context is a little better than a token model with one token (about 2 bytes) of context. This is why the Pile benchmark (Gao et al., 2020) reports bits per byte for its evaluation sets, and why a published perplexity is meaningful only next to its tokeniser and test set.

What the model learns from predicting the next token

An informal way to measure what a model has learned is to compare it with simple models that use less context. Count-based n-gram models predict the next character from the previous n−1 characters by counting how often each followed that history in the training text. The script computes them with interpolated (Witten-Bell) smoothing, which mixes each order with the order below it so that unseen contexts do not get probability zero, and scores them on the same held-out text as the trained chapter-12 GPT, in three ways.

import math
from collections import defaultdict, Counter
import numpy as np
from gpt_model import CFG, forward, cross_entropy

text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text)); V = len(chars)
n = int(0.9 * len(text)); train, val = text[:n], text[n:]

# ---- count-based models: interpolated n-grams (Witten-Bell smoothing) ----
N = 6
ctx = [defaultdict(Counter) for _ in range(N)]            # ctx[k][history of k characters][next char] = count
for i in range(len(train)):
    for k in range(min(N, i + 1)):
        ctx[k][train[i - k:i]][train[i]] += 1
tot = [{h: sum(c.values()) for h, c in d.items()} for d in ctx]

def prob(c, hist, order):                                  # order = number of history characters used
    p = 1.0 / V
    for k in range(order + 1):
        h = hist[len(hist) - k:] if k else ""
        cnt = ctx[k].get(h)
        if cnt is None: break
        types = len(cnt)
        p = (cnt[c] + types * p) / (tot[k][h] + types)
    return p

print("model                       val loss (nats/char)   bits/char   perplexity")
print(f"{'uniform over 65 characters':27s} {math.log(V):10.3f} {math.log(V)/math.log(2):15.2f} {V:12.1f}")
for order in range(0, N):
    loss = -np.mean([math.log(prob(val[i], val[max(0, i - order):i], order)) for i in range(len(val))])
    name = {0: "unigram", 1: "bigram (1 char of context)"}.get(order, f"{order + 1}-gram ({order} chars of context)")
    print(f"{name:27s} {loss:10.3f} {loss/math.log(2):15.2f} {math.exp(loss):12.1f}")

# ---- the trained Transformer on the same val text, scored in three ways ----
p = {k: v.astype(np.float64) for k, v in np.load("gpt.npz").items()}

    x = np.stack([v[s:s + T] for s in starts]); y = np.stack([v[s + 1:s + T + 1] for s in starts])
    out = []

        lp = z - np.log(np.exp(z).sum(-1, keepdims=True))
        out.append(-np.take_along_axis(lp, y[i:i + 64, :, None], -1)[..., 0])
    return np.concatenate(out)                             # (windows, T) per-character losses

The ladder shows the general pattern of what next-token prediction teaches. With no context the best strategy is the letter frequencies (4.17 to 3.35). One character of context captures spelling's local constraints, such as "q" being followed by "u" and "th" being followed by a vowel (3.35 to 2.49). Two and three characters capture syllables and short words (2.05, 1.77). By five characters or so, a table of counts runs out of data: the 6-gram, with 655 possible contexts, is worse than the 5-gram. A neural model does not keep a table, so it can share statistical strength between similar contexts, which is its advantage as the context and the data grow. Beyond spelling, a larger model trained on more text must predict words, sentences and arguments, and each of these costs a little of the remaining loss: grammar, facts, style, arithmetic, how a character in a story would react. This is the claim of the whole field: a good enough predictor of text has to model much of what the text is about. The claim is empirical and gets stronger with scale; at 108,352 weights the model has only learned spelling and layout.

Two of the three numbers at the bottom of the output deserve a comment. The 1.738 is the loss on non-overlapping windows of 64 characters, which is how estimate evaluates. In such a scheme the early characters of each window have little context. Scoring only the last 16 positions of windows slid forward 16 characters at a time (every scored character has at least 48 characters of context) gives 1.712, a more honest figure for what the model can do. This sliding-window evaluation is standard practice for perplexity with a fixed context length (the Hugging Face documentation on "perplexity of fixed-length models" explains it); using non-overlapping windows overstates the loss. And the row of numbers for positions shows the effect directly.

For a model that is large enough to use its context, the curve keeps falling for hundreds or thousands of positions, which is how Kaplan et al. (2020) describe larger Transformers. That decline is exactly what a longer context window buys, and what measures whether a long-context model really uses its context.

Where the surprise is

The average hides the structure. The script below computes the surprisal (−log2 p, in bits) of every character in 120 held-out characters, giving each character up to 64 characters of context, and the figure shows it as a bar under each character.

import math, numpy as np
from gpt_model import CFG, forward
p = dict(np.load("gpt.npz"))
text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
val = text[int(0.9 * len(text)):]
T = CFG["T"]

start = val.index("\n\n", 20000) + 2                       # a stretch of held-out text
snippet = val[start:start + 120]
ids = np.array([stoi[c] for c in val[start - T:start + 120]])
bits = []
for j in range(T, len(ids)):                               # score each character given up to T before it
    lg = forward(p, ids[None, max(0, j - T):j], CFG)[0, -1].astype(np.float64)
    z = lg - lg.max(); logp = z - np.log(np.exp(z).sum())
    bits.append(-logp[ids[j]] / math.log(2))               # surprisal of the true character, in bits
bits = np.array(bits)

print(f"{len(snippet)} held-out characters, mean surprisal {bits.mean():.2f} bits "
      f"(median {np.median(bits):.2f}, maximum {bits.max():.1f})")
print("cheapest:", ", ".join(f"{snippet[i]!r} {bits[i]:.1f}" for i in np.argsort(bits)[:4]), "bits")
print("dearest :", ", ".join(f"{snippet[i]!r} {bits[i]:.1f}" for i in np.argsort(-bits)[:4]), "bits")
start_bits = [b for i, b in enumerate(bits) if i == 0 or snippet[i - 1] in " \n"]
other_bits = [b for i, b in enumerate(bits) if not (i == 0 or snippet[i - 1] in " \n")]
print(f"first letter of a word or line: {np.mean(start_bits):.2f} bits;  all other characters: {np.mean(other_bits):.2f} bits")
np.save("snip_bits.npy", bits); open("snip.txt", "w").write(snippet)
120 held-out characters, mean surprisal 2.60 bits (median 2.39, maximum 7.7)
cheapest: '\n' 0.0, '\n' 0.0, '\n' 0.0, ' ' 0.0 bits
dearest : '.' 7.7, 'u' 7.5, 'u' 7.4, 'H' 7.4 bits
first letter of a word or line: 4.28 bits;  all other characters: 2.20 bits

The mean is 2.60 bits, but the median is 2.39 and the range runs from nearly 0 to 7.7. The first letter of a word or line averages 4.28 bits against 2.20 for all other characters: once a word has started, it mostly finishes itself. Notice "HORTENSIO" in the second speaker line: after "HORTE" the remaining letters cost 0.1 bits each, because that name occurs often in the training text and the model has memorised it. But "gamut" costs 7.4 bits at its "u" the first time and 7.5 bits the second time it appears a line later; a model of this size does not copy from its own context. Larger Transformers do (this is what induction heads implement), and the loss they achieve on repeated material drops accordingly.

Analogy: the guessing game

Shannon (1951) estimated the information in English by asking people to guess the next letter of a text, one at a time: a good guess means little information, a wrong guess means a lot. Cross-entropy is this game with the model as the player and the logarithm as the score: you score high for being sure and right, and heavily negative for being sure and wrong. A player who spreads their guesses evenly scores badly, but never disastrously.

Where it breaks down: a human gets to try letters until they find the right one, and the number of tries is the measurement. The model must put all its bets down at once, as probabilities, before the answer is revealed, and cannot take back an overconfident bet.

Training details that change the loss

Teacher forcing

In training, the model at position t is always given the true previous tokens, not its own earlier guesses. This is called teacher forcing. It is what lets all positions be computed in parallel with a mask, and it gives each position a clean learning signal. The cost is a mismatch: at generation time the model feeds on its own outputs, which can contain errors it never saw in training, so errors can compound (the repetition loops of chapter 15 are one form of this).

Masking the loss

The loss need not include every position. In practice, positions are excluded by an ignore index or a mask: padding (empty slots in a short sequence), the prompt in supervised fine-tuning (the model is trained to produce the answer but not to predict the question; A3 chapter 10), and in some pipelines the tokens of tool results. The last lines of ce_demo.py show the effect: averaging only over the last three of five positions gives 1.30 instead of 1.14. Two warnings follow. A masked loss is a different quantity, so compare losses only if their masks match. And the mean must be taken over the unmasked positions only, or a batch with more padding appears to have a smaller loss. Both are easy bugs.

Packing and boundaries

Pretraining text consists of documents of very different lengths. The usual practice is to concatenate them with a separator token (the end-of-text token of chapter 13) and cut windows from the stream. A window can then span two unrelated documents, and the model at the start of the second must predict from the first. Cheap implementations accept this; careful ones mask attention across document boundaries. Either way, the separator token must be present at boundaries in training data, or the model never learns what the end of a document looks like and cannot stop.

Evaluation protocol

A reported loss depends on the data and on the procedure: which held-out set; whether it was filtered for overlap with the training data; which tokeniser; the context length and whether windows overlap; whether the average is per token or per byte; and how many batches were averaged (a 20-batch estimate on a noisy stream is only good to a couple of hundredths of a nat). The chapter's estimate function reuses the same 20 batches each time, so that differences between lines of the log are due to the model rather than the sample. Test-set contamination can make a held-out loss artificially low (A6 chapter 07).

Common misconception

"A perplexity of 5 means the model gets the next token right one time in five", or "lower perplexity always means a better model." Perplexity 5 means the model is as unsure as a uniform choice among five options, on average, in a geometric-mean sense; it says nothing directly about how often its top guess is right (which can be much higher). And perplexity only ranks models fairly if they share the tokeniser and the test text. Compare bits per byte on the same held-out text, and be wary of any single number, however convenient.

What the loss does not tell you

The loss is the right training objective and an incomplete evaluation. Three limits matter in practice.

  • All tokens count equally. Predicting a space, a comma or "the" costs as much as predicting the answer to a question. A model can reduce its average loss a lot by getting better at common syntax while staying equally poor at the rare, hard tokens that carry the facts. Capabilities such as arithmetic, code or recall of facts may improve in steps that the average loss hides.
  • The loss measures the data, not the use. It is the cost of predicting web text. A model that must follow instructions, refuse requests or reason over several steps is shaped by later stages (A3: fine-tuning on demonstrations and preferences), and benchmarks of those behaviours do not track the pre-training loss in a simple way. Within a family of models trained the same way, though, loss is smooth and predictable, and it falls as a power law of compute, parameters and data, which is the basis of scaling laws (chapter 18).
  • A lower loss can be a bug. Chapter 12's masked-and-unmasked experiment gave 0.04 and 7.9 for the same weights. Always check a surprising improvement against a simple baseline from the ladder above.

The practical conclusion: use the loss to monitor training and to compare runs that differ in size, data and hyperparameters; evaluate behaviour with task-level tests as well (A6); and be explicit about the dataset and tokeniser behind every loss figure you quote.

State of play, October 2026

Shannon's guessing experiments (1951) bounded the entropy of printed English, using a 27-symbol alphabet of letters and space and up to 100 letters of context, between roughly 0.6 and 1.3 bits per letter (his Table of upper and lower bounds at N = 100: 1.3 and 0.6). Modern models are routinely quoted at around or below one bit per byte on large web corpora, but those figures depend on the corpus, the cleaning and the tokeniser, and I have not verified a specific current number against a primary source, so I give none. The Shakespeare figures in this chapter (2.4 to 2.5 bits per character) are for a 65-symbol alphabet with capitals and punctuation, a tiny model and a one-megabyte corpus: they should not be compared with Shannon's or with any web-scale figure. Pre-training loss is also no longer the only target: reasoning-oriented models are trained further with rewards on verifiable outcomes (A3 chapter 14), for which the next-token loss is only a starting point.

Systems connection

Treat the loss as a production metric with the same hygiene as any other. Training runs should log loss at every step and on held-out slices (by language, by domain, by source), because an average can stay flat while one slice degrades; chapter 17 lists what to watch, and the practices of monitoring (what to count, at what granularity, and how to avoid averages that hide tails) apply directly. The held-out set is a versioned artefact: change it and every historical loss is incomparable, the way changing a dashboard's query breaks a trend line. Evaluation pipelines should report the tokeniser version and units alongside every number (A6 chapter 02). The per-token loss also gives you a cheap anomaly detector for data pipelines: a sudden rise in the loss of new training data against a model trained on the old data signals a change in format, language or quality upstream, long before a human reads the text.

Key takeaways

  • The chain rule makes next-token prediction a complete description of a distribution over text: p(x) = ∏ p(xt | x<t). It also allows sampling.
  • The loss is the average negative log probability of the true next token (cross-entropy, maximum likelihood). Its gradient with respect to the logits is softmax minus one-hot, divided by N. Compute it from logits with the log-sum-exp form, never as log(softmax(x)).
  • Expected cross-entropy equals the data's entropy plus the KL divergence from truth to model, so there is a floor set by irreducible unpredictability, and the rest is model error.
  • Nats, bits, perplexity (exp of the loss) and bits per byte are the same quantity in different units. Perplexity per token depends on the tokeniser; compare bits per byte on the same text. Chapter 13's BPE bigram has a perplexity nine times the character 5-gram's yet is only 0.24 bits per byte worse.
  • Models learn the statistics of text in order of context length. The chapter's tiny GPT (1.73 nats) sits just above a 5-gram table (1.67) on held-out Shakespeare; surprise is concentrated at the starts of words and names.
  • Teacher forcing, masks, packing and the evaluation protocol all change what a loss number means. A masked loss is a different loss; sliding-window evaluation gives lower, fairer losses than non-overlapping windows (1.712 against 1.738 here).
  • The loss is a smooth, predictable training signal, not a complete measure of capability: all tokens count equally, and later stages and task benchmarks decide usefulness.

Check your understanding

A model gives the true next token probability 0.25 at every one of 1,000 positions. What are its loss in nats and its perplexity?

  1. 0.25 and 4
  2. 1.39 and 0.25
  3. 1.39 and 4
  4. 0.25 and 1.39
The loss is −ln 0.25 = 1.386 at each position, and the perplexity is exp(1.386) = 4: as unsure as a uniform choice among four options. The first option mixes the probability with the loss; the other two swap the quantities.

At one position the softmax gives the true token probability 0.02 while another token gets 0.9. Which statement about the gradient with respect to the logits is correct?

  1. The true token's logit gets gradient about −0.98 (push it up strongly), and the 0.9 token's logit gets +0.9 (push it down)
  2. Only the true token's logit receives a gradient
  3. All logits get the same gradient
  4. The true token's logit gets +0.02
The gradient of the loss is p minus the one-hot target: 0.02 − 1 = −0.98 for the true token and +p for every other token. Gradient descent moves against the gradient, so the true logit rises and the overconfident wrong one falls. Every logit receives a gradient, in proportion to its probability.

Model A uses a 50,000-token vocabulary and reports perplexity 20 per token on a test set. Model B uses characters and reports perplexity 5 per character on the same set, which has 4.2 characters per A-token. Which comparison is valid?

  1. B is better, because 5 is less than 20
  2. A is better, because its vocabulary is larger
  3. They are equal, because both are perplexities
  4. Convert both to bits per character: A has ln(20)/4.2/ln 2 = 1.03 bits per character, B has log2(5) = 2.32, so A is better
Perplexities per token and per character are not comparable. Converting to a common unit, A's 20-perplexity per token spread over 4.2 characters is about 1.03 bits per character, against 2.32 for B, so A predicts the text better. Vocabulary size alone says nothing about quality.

You fine-tune with the prompt tokens masked out of the loss and notice the reported loss is lower than for the same model without masking. Which explanation is most plausible?

  1. Masking removes gradient noise, so the model is better
  2. The masked loss averages only over the answer positions, which are a different (here easier) set of predictions; the numbers are not comparable
  3. The model has overfitted to the prompts
  4. Masking changes the softmax
A masked loss is a different quantity: it is the mean over a different set of positions. Prompts are often harder to predict than formulaic answers, or the reverse, so the two numbers say nothing about which model is better. Masking changes which positions count, not the softmax, and it says nothing about overfitting by itself.

On held-out text, a 5-gram model reaches 1.67 nats per character and a 6-gram model reaches 1.70, although the 6-gram has strictly more context. What explains this?

  1. The 6-gram is implemented incorrectly
  2. More context always hurts in language models
  3. Most 5-character contexts have been seen too few times, so the counts are unreliable even with smoothing
  4. The test set contains no 6-character words
The number of possible contexts grows exponentially with their length, so counts become sparse and noisy: the model memorises training accidents. Smoothing softens this but cannot remove it. More context is useful in principle, and neural models can use it because they share parameters across contexts. Nothing in the setup suggests a bug.

You are told that a new model's validation loss is "much better" than the previous version's. Which check would you run first?

  1. Retrain with a larger learning rate
  2. Switch the units to bits per byte
  3. Compute perplexity instead of loss
  4. Check that the validation text, tokeniser, masking and context handling are the same as before, and that the held-out text does not overlap with training data
An apparent improvement is often a change in the measurement: a different tokeniser or test set, a changed mask, or contamination of the held-out data. Changing units or perplexity relabels the same number, and a larger learning rate tests nothing. Only after confirming that the comparison is like for like do the numbers mean anything.
