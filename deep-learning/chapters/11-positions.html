Positional Information

Attention treats its input as an unordered set: shuffle the tokens and the outputs shuffle with them. Yet word order carries meaning. This chapter shows exactly why order is invisible to attention, then follows the four answers the field has given: learned position tables, sinusoids, relative biases, and rotary embeddings (RoPE), with code that proves the key property of each.

Why this matters

"The dog bit the man" and "the man bit the dog" contain the same tokens. A model that cannot tell them apart cannot read. The way a model represents position also sets a hard-looking limit, the context length: a model with a table of 1,024 learned positions has nothing to say about position 1,025, and a model trained with rotary embeddings on 4,096 tokens may degrade quickly beyond them. Extending context windows, a major product feature, is largely an exercise in manipulating positional encodings, and a wrong convention in a position routine produces a model that loads and runs but quietly gets worse. After this chapter you can explain why attention needs positions, write sinusoidal and rotary encodings, prove that RoPE makes attention depend on relative distance, and read a model card line such as "RoPE base 500,000" or "YaRN-extended to 128k".

Attention cannot see order

Look again at chapter 09's formula. The score between token i and token j is built from qi = xiWQ and kj = xjWK. Those depend on which token sits at i and j, never on the numbers i and j. The output for token i is a weighted sum over the set of value vectors; sums do not care about order. So if you permute the input tokens, each token still gets exactly the same output as before, just moved to its new row. This property is called permutation equivariance. The script puts "dog bites man" and "man bites dog" through one unmasked attention layer and prints the output at the word "bites".

import numpy as np
np.set_printoptions(precision=3, suppress=True)
rng = np.random.default_rng(0)
C, vocab = 8, ["dog", "bites", "man"]
emb = rng.normal(size=(3, C))                           # one embedding per word
Wq, Wk, Wv = (rng.normal(size=(C, C)) / np.sqrt(C) for _ in range(3))

def softmax(a):
    e = np.exp(a - a.max(-1, keepdims=True)); return e / e.sum(-1, keepdims=True)

def self_attention(x):                                  # x: (T, C), no mask
    q, k, v = x @ Wq, x @ Wk, x @ Wv
    return softmax(q @ k.T / np.sqrt(C)) @ v

def sinusoid(T, d):
    pos = np.arange(T)[:, None]
    freq = 10000.0 ** (-np.arange(0, d, 2) / d)
    pe = np.zeros((T, d)); pe[:, 0::2] = np.sin(pos * freq); pe[:, 1::2] = np.cos(pos * freq)
    return pe

a = emb[[0, 1, 2]]                                      # "dog bites man"
b = emb[[2, 1, 0]]                                      # "man bites dog"
print("without positions, output at 'bites':")
print(" dog bites man:", self_attention(a)[1])
print(" man bites dog:", self_attention(b)[1])
pe = sinusoid(3, C)
print("with sinusoidal positions added:")
print(" dog bites man:", self_attention(a + pe)[1])
print(" man bites dog:", self_attention(b + pe)[1])

Without positions, "bites" gets an identical output vector in both sentences, so no later layer could ever tell who bit whom. After adding a sinusoidal position code to each embedding (explained below) the two vectors differ. Chapter 10 found the same thing at block level: with no mask and no positions a block is permutation-equivariant.

The causal mask of chapter 09 is one source of order, because token 0 can only see itself and token 7 can see eight tokens. Haviv et al. ("Transformer Language Models without Positional Encodings Still Learn Positional Information", 2022) found that causal language models trained with no positional encoding at all still reach respectable quality, and Kazemnejad et al. ("The Impact of Positional Encoding on Length Generalization in Transformers", 2023) found, in small-scale experiments, that such models can generalise to longer sequences than some explicit encodings. These results are interesting, but practical models still use explicit positions, because they help quality and give the designer control over how position is represented.

What a position code should do

A position encoding has to give the network enough information to distinguish "where", and the design questions are these:

  1. Distinct. Every position within the context length gets a different signal.
  2. Usable by attention. The model must be able to compute things like "the token two before me" or "the start of the document" from it with a few matrix products.
  3. Relative. Language is mostly about nearness. A rule such as "an adjective modifies the noun just after it" should work at position 7 and at position 7,000 alike.
  4. Length-robust. It should behave sensibly beyond the lengths seen in training, or at least be extensible cheaply.
  5. Cheap. Few parameters, little extra computation and no obstacle for fast kernels.

No scheme gets all five perfectly. Each of the following trades some away.

Learned absolute embeddings

The simplest design is a table. Make a matrix of shape (Tmax, C), one learned row per position, and add row i to the token embedding at position i: xi = E[tokeni] + P[i]. The table is trained by gradient descent like any other weight. GPT-2 uses Tmax = 1,024 positions, BERT uses 512. In GPT-2 small the table has 1,024 × 768 = 786,432 parameters, about 0.6% of the model.

It is easy and works well inside its range. Its limits follow directly: position 1,025 has no row at all, so the context length is fixed at training time; row 700 is learned separately from row 701, so nothing tells the model that they are neighbours except what training discovers (and rarely used late positions are trained less); and the encoding is purely absolute, so "two tokens back" has to be rediscovered at every position.

Sinusoidal encodings

Vaswani et al. (2017) used a fixed formula instead of a table. For position p and an even number of dimensions d, pair up the dimensions and give pair i its own frequency:

PE(p, 2i) = sin( p / 100002i/d ),    PE(p, 2i+1) = cos( p / 100002i/d ).

The first pair oscillates quickly (wavelength 2π ≈ 6.3 positions), the next more slowly, and the last very slowly (up to 10000 · 2π positions). Each position gets a vector of sines and cosines at many speeds. The figure draws four of the pairs.

Analogy: clock hands and an odometer

Telling the time needs several hands. The second hand moves fast and identifies the moment within a minute, the minute hand identifies the minute within the hour, and the hour hand the hour within the day. No single hand is unique over a day, but the three together are. The sinusoids are a clock with many hands running at geometrically spaced speeds: the fast ones separate neighbouring positions, the slow ones separate distant regions.

Where it breaks down: a real clock repeats every twelve hours, whereas the slowest sinusoid has a wavelength of tens of thousands of positions, so the code is effectively unique for any practical length, and the model does not read the hands one by one: attention compares whole vectors with dot products.

Why sines and cosines in pairs? Because shifting a position is then a rotation. For one pair with frequency ω, the vector (sin(pω), cos(pω)) at position p+k equals the vector at p rotated by the angle kω, and that rotation does not depend on p. So PE(p+k) is a fixed linear function of PE(p), for every p: the offset k is something a linear layer could, in principle, read off. The authors say this is the reason for the choice, and report that a learned table gave nearly identical results in their experiments. The script verifies both consequences numerically with d = 8.

import numpy as np
np.set_printoptions(precision=3, suppress=True, linewidth=120)
d, T = 8, 64
pos = np.arange(T)[:, None]
freq = 10000.0 ** (-np.arange(0, d, 2) / d)             # one frequency per sin/cos pair
pe = np.zeros((T, d)); pe[:, 0::2] = np.sin(pos * freq); pe[:, 1::2] = np.cos(pos * freq)
print("frequencies:", freq, " wavelengths:", 2 * np.pi / freq)
print("PE for positions 0, 1, 2:\n", pe[:3])

# property 1: PE(p + k) is a fixed rotation of PE(p), the same for every p
k = 5
def shift_matrix(k):                                    # block-diagonal rotation by k * freq
    R = np.zeros((d, d))
    for i, w in enumerate(freq):
        c, s = np.cos(k * w), np.sin(k * w)
        R[2*i:2*i+2, 2*i:2*i+2] = [[c, s], [-s, c]]
    return R
R = shift_matrix(k)
err = max(np.abs(R @ pe[p] - pe[p + k]).max() for p in range(T - k))
print(f"max |R(5) PE(p) - PE(p+5)| over all p: {err:.1e}")

# property 2: the dot product of two codes depends only on how far apart they are
dots = lambda p, q: pe[p] @ pe[q]
print("PE(3).PE(8) =", round(dots(3, 8), 6), "  PE(40).PE(45) =", round(dots(40, 45), 6), "  (offset 5)")
print("PE(3).PE(4) =", round(dots(3, 4), 6), "  PE(3).PE(30) =", round(dots(3, 30), 6), "  (offset 1 and 27)")

The rotation matrix R(5) maps PE(p) to PE(p+5) for all p with an error of 10−15, and the dot product between two codes (3.159983) is the same for the pairs (3, 8) and (40, 45) since both are 5 apart. The dot product also shrinks as the offset grows (3.54 at offset 1, 0.77 at offset 27), which is a pleasant built-in notion of "nearness". But notice what the model actually receives: the code is added to the token embedding at the input, once, before the first layer. Attention then has to disentangle word from position inside the mixed vector, through its learned projections. The relative structure exists in the code but is only indirectly visible in the scores, which is a motivation for the methods below.

Relative position

If what matters is the distance j − i between two tokens, build that into the attention scores directly instead of the inputs. Shaw, Uszkoreit and Vaswani ("Self-Attention with Relative Position Representations", 2018) added a learned vector for each clipped distance to the keys (and values) inside the attention computation, and reported better translation quality than absolute encodings. Raffel et al. ("Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer", 2019) simplified this in T5, using one learned number per head per distance bucket, added to the score:

sij = qi·kj / √dk + bh( i − j ).

Distances beyond the largest bucket share one bias, so the scheme tolerates unseen lengths. Press, Smith and Lewis ("Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation", ALiBi, 2021) went further and used no learned parameters and no input encoding at all: the score is penalised linearly with distance, sij = qi·kj / √dk − mh(i − j), where each head h has a fixed slope mh (a geometric sequence such as 1/2, 1/4, …, 1/256 for eight heads). Close tokens are favoured; each head decays at its own rate. The authors report that models trained on short sequences keep working on longer ones. Both methods act on the scores and need an extra (T, T) matrix of biases, which complicates the fastest attention kernels slightly; today both are used less often than rotary embeddings.

Rotary position embeddings (RoPE)

Su et al. ("RoFormer: Enhanced Transformer with Rotary Position Embedding", 2021) asked for a cleaner property: find a position-dependent transformation f such that the attention score between a query at position m and a key at position n depends on the two vectors and only on the difference n − m:

f( q, m ) · f( k, n ) = g( q, k, n − m ).

In two dimensions the answer is a rotation. Rotate the query vector by an angle proportional to its position, mθ, and the key by nθ. A rotation preserves lengths and turns the angle between two vectors into (angle before) plus (n − m)θ. The dot product of two vectors is their lengths times the cosine of the angle between them, so only the difference of rotations matters. The figure shows two cases that give the same score.

For a head of width dk, split the dimensions into dk/2 consecutive pairs and rotate pair i by the angle mθi, with the same geometric spread of frequencies as the sinusoids:

θi = base−2i/dk,    base = 10000 in the paper,    i = 0, …, dk/2 − 1.

Written out, a pair (x2i, x2i+1) at position m becomes (x2i cos mθi − x2i+1 sin mθi,  x2i sin mθi + x2i+1 cos mθi). Four properties set it apart from the encodings above:

  • It is applied to queries and keys only, inside every attention layer, not added to the input once. Values are untouched, so what is read from a token does not depend on where it sits; only how strongly it is attended to does.
  • It has no parameters and costs a few elementwise multiplications per head.
  • The score is relative by construction, as the derivation below shows.
  • Different pairs see different scales. Fast pairs (θ near 1) distinguish adjacent tokens; slow pairs turn so little over thousands of tokens that they carry coarse position.
Go deeper optional: the proof that the score depends on n − m

Write R(a) for the 2 × 2 rotation by angle a, so that R(a)T = R(−a) and R(a)R(b) = R(a + b). For one pair, take the 2-vectors q and k, and rotate them to positions m and n: q' = R(mθ)q and k' = R(nθ)k. Then

q'·k' = qT R(mθ)T R(nθ) k = qT R(−mθ) R(nθ) k = qT R((n − m)θ) k.

The score of a whole head is the sum of this quantity over its dk/2 pairs, each with its own θi, so it depends on m and n only through n − m. The matrix R((n − m)θ) lies between q and k, so the model learns, through WQ and WK, which relative distances each pair should attend to. Su et al. also argue that, with the frequencies above, the contribution of each pair decays as the distance grows. They state this as a property of their choice of θi; do not assume that it makes far tokens unattendable, since the model can learn to counteract it.

A practical warning: libraries disagree on which dimensions form a pair. The paper pairs neighbours (2i, 2i+1), as in the code below; many implementations pair dimension i with dimension i + dk/2 (called "rotate half"). They are the same maths on permuted dimensions, but weights trained under one convention must be loaded under that same convention, which is why conversion scripts between libraries permute the query and key weights. Getting this wrong loads without errors and gives a model that is much worse.

The script implements RoPE for pairs of neighbouring dimensions on arrays of shape (..., T, dk), then tests the claim in three ways.

import numpy as np
rng = np.random.default_rng(0)
d_k, base = 8, 10000.0
theta = base ** (-np.arange(0, d_k, 2) / d_k)           # one angle per pair of dimensions, (d_k/2,)

def rope(x, pos):
    """Rotate each consecutive pair (x[2i], x[2i+1]) of x by pos * theta[i]. x: (..., T, d_k), pos: (T,)."""
    ang = pos[:, None] * theta[None, :]                  # (T, d_k/2)
    cos, sin = np.cos(ang), np.sin(ang)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = np.empty_like(x)
    out[..., 0::2] = x1 * cos - x2 * sin
    out[..., 1::2] = x1 * sin + x2 * cos
    return out

q = rng.normal(size=d_k); k = rng.normal(size=d_k)       # one query vector and one key vector
score = lambda m, n: rope(q[None], np.array([m]))[0] @ rope(k[None], np.array([n]))[0]
print("unrotated q.k          :", round(q @ k, 6))
for m, n in ((5, 2), (105, 102), (1005, 1002), (7, 2), (7, 9)):
    print(f"query at {m:>4}, key at {n:>4} (n-m = {n - m:>2}): score = {score(m, n):.6f}")
print("rotation keeps the norm :", np.allclose(np.linalg.norm(rope(q[None], np.array([37]))), np.linalg.norm(q)))

# a whole attention layer: shifting every position by the same amount leaves the output unchanged
T = 6
Q, K, V = rng.normal(size=(T, d_k)), rng.normal(size=(T, d_k)), rng.normal(size=(T, d_k))
def attn(Q, K, V, pos):
    s = rope(Q, pos) @ rope(K, pos).T / np.sqrt(d_k)
    s = np.where(np.triu(np.ones((T, T), bool), 1), -np.inf, s)
    e = np.exp(s - s.max(-1, keepdims=True)); return (e / e.sum(-1, keepdims=True)) @ V
o0 = attn(Q, K, V, np.arange(T))
o1 = attn(Q, K, V, np.arange(T) + 1000)
print("output unchanged when positions are shifted by 1000:", np.allclose(o0, o1))
print("max difference:", f"{np.abs(o0 - o1).max():.1e}")

Query at 5 with key at 2, query at 105 with key at 102, and query at 1005 with key at 1002 all give the score −1.586475, to the six digits shown: only the gap of −3 matters. Different gaps give different scores (−1.14, −1.38), the rotation preserves the vector's length, and an entire causal attention layer is unchanged to 10−15 when every position is shifted by 1,000. Positions matter, but only relative to one another: this is the property that made RoPE the default.

Common misconception

"RoPE is relative, so a model trained on 4,096 tokens works on 100,000." Relative does not mean length-independent. At training time the model only ever saw gaps up to 4,095, and for the slow dimension pairs the angles mθi only reached small values. At longer range the slow pairs take angle values the attention heads never saw, and the scores they produce are out of distribution; quality typically collapses well before the nominal limit unless the model is extended or retrained. Also: a model that accepts long input does not necessarily use it well. Even models trained for long contexts can retrieve a fact from the middle of a long prompt less reliably than from the ends (Liu et al., "Lost in the Middle", 2023), so claims about context length should be tested on your task.

Going past the trained length

Because context length is a product feature, extending it is a large topic. The cleanest way to see the problem is to ask how many positions each rotation pair needs to complete one full turn: its wavelength 2π · base2i/dk. The chart plots it for a head width of 128.

import numpy as np
d_k, trained, target = 128, 2048, 8192
for base in (10_000, 500_000):
    i = np.arange(d_k // 2)
    wavelength = 2 * np.pi * base ** (2 * i / d_k)       # positions needed for one full turn of pair i
    unseen = (wavelength > trained).sum()
    print(f"base {base:>7,}: wavelengths from {wavelength[0]:.1f} to {wavelength[-1]:,.0f} positions; "
          f"{unseen} of {d_k // 2} pairs never complete a turn within {trained:,} trained positions")

# position interpolation: squeeze the new positions back into the trained range
base = 10_000
theta = base ** (-np.arange(0, d_k, 2) / d_k)
lowest = theta[-1]
print(f"\nslowest pair, angle at position {trained - 1:,}: {(trained - 1) * lowest:.3f} rad (largest seen in training)")
print(f"slowest pair, angle at position {target - 1:,}: {(target - 1) * lowest:.3f} rad  <- never seen if used directly")
scale = trained / target
print(f"with interpolation (positions x {scale}): {(target - 1) * scale * lowest:.3f} rad  <- back inside the trained range")
fastest = theta[0]
print(f"fastest pair, adjacent tokens differ by {fastest:.2f} rad; after interpolation by {fastest * scale:.2f} rad (neighbours blur)")
base  10,000: wavelengths from 6.3 to 54,410 positions; 23 of 64 pairs never complete a turn within 2,048 trained positions
base 500,000: wavelengths from 6.3 to 2,559,196 positions; 35 of 64 pairs never complete a turn within 2,048 trained positions

slowest pair, angle at position 2,047: 0.236 rad (largest seen in training)
slowest pair, angle at position 8,191: 0.946 rad  <- never seen if used directly
with interpolation (positions x 0.25): 0.236 rad  <- back inside the trained range

With a base of 10,000, 23 of the 64 pairs never complete a turn inside a 2,048-token training window. Run at 8,192 tokens, the slowest pair reaches 0.946 radians, but training never took it above 0.236. Three families of fixes exist.

  • Position interpolation. Chen et al. ("Extending Context Window of Large Language Models via Position Interpolation", 2023) rescale the positions, so that 8,192 new positions are squeezed into the trained range (multiply by 2,048/8,192), then fine-tune briefly. They extended LLaMA models to 32,768 positions with fine-tuning of about 1,000 steps. The cost is visible in the last lines of the output: neighbouring tokens now differ by 0.25 radians where they used to differ by 1.00 in the fastest pair, so fine local distinctions blur, which is why a little fine-tuning is needed.
  • Frequency-aware scaling. Scale different pairs differently: keep the fast pairs (which have seen many turns and encode fine local order) and interpolate only the slow ones. Variants include "NTK-aware" scaling, which raises the base, and YaRN (Peng et al., 2023), which combines per-frequency interpolation with a temperature correction on the attention logits and fine-tuning.
  • A larger base from the start. If the model will be trained for long contexts, enlarge the base so the slow pairs span the target length. The Llama 3 report says it increases the RoPE base frequency to 500,000 to support longer contexts, citing Xiong et al. (2023) as showing that this value works for lengths up to 32,768. The chart shows the effect: at base 500,000, 35 of 64 pairs have wavelengths longer than 2,048 tokens.

State of play, October 2026

As far as published reports show, rotary embeddings (with a large base, often combined with a staged training schedule in which the context grows and a frequency-aware extension method is applied at the end) are the most common positional scheme in open-weight language models. Meta's April 2025 Llama 4 announcement describes an "iRoPE" design in which most layers use rotary embeddings and some interleaved attention layers use no positional encoding at all, with a temperature adjustment to the attention at inference time; other labs have published similar mixtures. Claims of million-token contexts are best read together with the evaluation they were measured on. Specific bases, scalings and context lengths change with each release, so read a model's own configuration (rope_theta and any rope_scaling entry in many open model files) rather than rely on a number remembered from here.

Systems connection

Position choices show up in serving. With RoPE, keys are rotated before they are stored in the KV cache (A3 chapter 18), so a cached key carries its absolute position in its angle. A cached prefix can be reused only if the tokens sit at the same positions as when it was computed, which is one reason prefix caching in serving engines is keyed on exact token prefixes (A3 chapter 20); shifting a cached block to a new position means re-rotating its keys. Context length also sets the memory bill: the cache grows linearly with it, and the attention work grows with its square (chapter 09), so lengthening the context window multiplies serving cost before it multiplies quality. Finally, positional bugs are silent. A test that feeds the same prompt at an offset, or a long input, and compares quality is the cheapest defence, in the spirit of the regression checks in A3 chapter 23.

Key takeaways

  • Self-attention is permutation-equivariant: without position information it cannot distinguish "dog bites man" from "man bites dog". The causal mask leaks only a weak, implicit notion of order.
  • Learned absolute tables are simple but cap the context length and are not relative. Sinusoids are parameter-free and have a rotation structure, but are added once at the input.
  • Relative methods put distance into the scores (T5 buckets, ALiBi's linear penalty).
  • RoPE rotates each pair of query and key dimensions by position times a pair-specific frequency, so the dot product depends only on the position difference: R(mθ)TR(nθ) = R((n − m)θ). It has no parameters and is applied in every layer to q and k, not to v.
  • Relative is not length-free: slow pairs reach angles never seen in training at longer range. Position interpolation, frequency-aware scaling (YaRN) and a larger base extend the context, each with trade-offs.
  • With RoPE, cached keys carry their absolute positions, and the pairing convention of dimensions must match the weights.

An unmasked self-attention layer receives the tokens of a sentence with no positional information, and then the same tokens in a different order. What does it output?

  1. The same matrix of outputs, in the same row order
  2. The same output vectors, but with rows permuted in the same way as the input
  3. Completely different vectors, because attention weights depend on position
  4. An error, because the sequence is not ordered
Each score depends on the two tokens' vectors, not on their indices, and the output for a token is a sum over all tokens, which is order-independent. So each token's output is unchanged and moves with its token. The first option would be true only if the layer ignored order and also did not move rows, which is not what permuting the input does.

A model has 1,024 learned absolute position embeddings. A user sends 1,500 tokens. What is the fundamental problem?

  1. The softmax overflows at that length
  2. Attention cost is quadratic, so it is too slow to run
  3. The model must be rerun with a larger vocabulary
  4. There is no learned vector for positions 1,024 to 1,499, so the model cannot represent them at all
The table has exactly 1,024 rows. Quadratic cost is a practical issue but would still allow the computation; the missing rows make it impossible without new parameters. Vocabulary size is unrelated to position.

In RoPE, a query at position 40 and a key at position 37 produce a score s. Where must a key sit for a query at position 1,040 to produce the same score s for the same vectors?

  1. Position 1,037
  2. Position 37
  3. Position 1,043
  4. Position 40
The score depends only on n − m, which is −3 here, so for m = 1,040 the key must be at n = 1,037. Keeping the key at 37 changes the gap to −1,003. Position 1,043 flips the sign of the gap (+3), which in general gives a different score.

Why does RoPE apply the rotation to queries and keys but not to values?

  1. Values are too small to rotate
  2. The values are rotated in the second layer instead
  3. Position needs to influence only how strongly a token is attended to; the content that gets read should not depend on where it sits, and the relative-score identity concerns only the q·k dot product
  4. Rotating values would make the attention weights negative
The relative-position identity is a statement about the dot product of a rotated q and a rotated k. Values are mixed after the softmax; rotating them would add absolute position into the output content (try it in the exercise). Attention weights come from a softmax, so they cannot become negative either way.

A RoPE model is trained at 2,048 tokens with base 10,000 and then run at 8,192 tokens with no changes. Which pairs of dimensions are most likely to produce out-of-distribution angles?

  1. The fastest pairs, since they rotate the most per token
  2. The slowest pairs, whose wavelengths exceed the training length, so longer positions reach angles never seen in training
  3. None: RoPE is relative, so length does not matter
  4. All pairs equally, because the rotation is the same for every pair
Fast pairs have completed many full turns during training, so any angle modulo 2π is familiar. A slow pair with a wavelength of, say, 50,000 positions moves through only a fraction of a turn in 2,048 positions; at 8,192 it reaches angles it never produced. That is the problem that interpolation and frequency-aware scaling address. The pairs have different frequencies, so the last option is wrong.

You convert a RoPE model checkpoint between two libraries. It loads without error, but outputs are much worse. Without changing any weights, what is the most likely cause?

  1. The softmax scale factor differs
  2. The vocabulary file is missing
  3. The two libraries pair dimensions differently for the rotation (neighbours versus first half and second half), so the queries and keys are being rotated in the wrong planes
  4. RoPE has to be disabled for conversions
Both conventions are valid, but a given set of weights was trained under one of them. Under the wrong pairing, each rotation mixes the wrong dimensions, so the scores change in a subtle way and the model degrades silently. A missing vocabulary file would fail loudly. The scale factor affects scores uniformly and would not be a library-dependent surprise.
