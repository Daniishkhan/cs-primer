A loop decides with a cheap number, the proxy, but what you care about is a slower number on data the loop never sees, the held-out score. Record both for every experiment but let only the proxy decide: if the held-out score decided, it would become one more thing the loop optimises and stop being a check.

run_experiment takes its seeds from experiment_seeds (given: fresh ones per experiment, so decisions do not share luck), decides with keep_or_revert, and reads the held-out scores through evaluate too. The held-out gain is best minus candidate, averaged over the same seeds; the gap is proxy gain minus held-out gain. research_loop works on a copy of start, never the module's BASELINE, and shows the proposer the best kept config, never a reverted one.

proxy gain +0.03, held-out gain -0.01: still kept (proxy decides)
gap = 0.03 - (-0.01) = +0.04, a change the proxy flattered
