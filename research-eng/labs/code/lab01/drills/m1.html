A research loop is only believable if every run it did is written down once, never edited, and findable by what was run. So each run gets a key made from its settings and seed, runs are appended to a file that is never rewritten, and a repeated request is answered from the file, not by training again.

config_hash fingerprints the settings: two dictionaries that mean the same thing must give the same hash whatever order their keys were written in. run_key (already written) joins that hash and the seed. append must refuse a stored key without touching the file. load must survive a crash in the middle of a write: a complete line always ends in a newline, so a last fragment without one is a torn write, to be ignored and cut off the file. evaluate trains only on a miss.

file: line h:1, line h:2, then {"key":"h:3","pr   (no newline)
load: keeps h:1 and h:2, cuts the file back to the end of h:2's line
