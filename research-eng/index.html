Research Engineering on Small Proxies

An automated research loop is only as trustworthy as its measurements. This course is opened while you build Artifact 1, autoresearch-rs: Karpathy's loop in which an agent edits a training script, runs it for a fixed budget and keeps the edit if one number improves. You learn the habits that make such a loop worth believing. The loop as a state machine under a budget. Noise floors, seeds and paired tests. Proxies that transfer, from scaling laws to μP. Ablations and run tracking. A Rust runner you can read and change. The two-to-six-page write-up a lab reviewer reads first.

How to use this course

🧪 Noise before claims

You measure how much a five-minute score moves on its own before you believe any improvement, and you keep a change only on a paired test.

🔍 Proxy against held-out

Every experiment logs the gain on the cheap proxy and on data the loop never saw, so overfitting to the proxy is measured, not assumed.

🦀 A runner you can read

The Python reference in Lab 1 is the specification for the Rust runner, sandbox and run store of Artifact 1.

Chapters are tagged Deep dive, Core or Quick intro so you know where to spend effort. The lab uses Python's standard library, a seeded toy training run and a seeded stand-in for the agent, so python3 check.py runs offline, for free, and gives the same answer every time. The workbench runs the real autoresearch script, cut down to a CPU, on the lab machine.
