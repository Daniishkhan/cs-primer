Workbench 1: A Real Judge, Calibrated

An LLM judge is a language model asked to grade another model's answers. Lab 2 calibrated a stand-in judge, a function with flaws built in. Here the judge is a real model small enough to run on your laptop. You measure how often it agrees with the people who labelled the answers, correct that for luck with Cohen's kappa, put honest error bars on every number, and test whether the order in which you show two answers changes its mind.

Why measure it

A judge always answers, and it always sounds sure. Nothing on a dashboard tells you when it is wrong. Calibrating a judge means checking its verdicts against labels made by people, and reporting how often it errs in each direction. With a stand-in the numbers are designed. With a real model they are not, and the first thing you find is usually a surprise. Write down what you expect, then measure.

What you need

  • A laptop with Python 3.10 or newer. The script uses only the standard library, plus the lab's data files in evals/labs/code/lab02.
  • A small model served locally. With Ollama: ollama pull qwen2.5:1.5b. Without it, any server with an OpenAI-compatible endpoint (a web address that accepts requests in the format OpenAI made popular) works, for example transformers serve. The Hugging Face copy of Qwen2.5-1.5B-Instruct is 3,087,467,144 bytes (about 2.9 GiB).
  • About 30 minutes. The 1.5B model grades a few hundred short prompts in a few minutes on a laptop.

Predict before you run

The yardstick is Cohen's kappa from chapter 5. It asks how much of the agreement that was not already guaranteed by chance the judge achieved:

κ = ( po − pe ) / ( 1 − pe )

Here po is the share of answers where judge and humans agree, and pe is the agreement two raters would reach by luck, each keeping their own PASS rate. Lab 2's 200 labelled answers are 101 PASS and 99 FAIL, so the humans' PASS rate is 0.505. Take a judge that says PASS to everything. It agrees on 101 of 200 answers, so po = 0.505. Its luck baseline is pe = 0.505 × 1 + 0.495 × 0 = 0.505. Then κ = (0.505 − 0.505) / (1 − 0.505) = 0. It is right half the time and has learned nothing.

The error bars come from chapter 4. A rate measured on n answers has a standard error of √(p(1 − p)/n). At 80 percent agreement on 74 answers that is √(0.8 × 0.2 / 74) = 0.047, so the 95 percent interval is about 80 ± 9 points. The script uses the Wilson interval, which behaves better near 0 and 100 percent, and a bootstrap for kappa.

The lab data has no policy text

The judge's rubric asks one question: does the answer state the correct figure? Lab 2's data holds questions, answers and human labels, but not the policy that says what the figure is. A real judge cannot know it. So the script rebuilds a reference from the humans. Each question has two answers (ids ending in a and b). If a person marked one of them PASS, its figure is the correct one, and the judge is told: "The correct figure is 15." The lab's own judge never needed this because it reads a hidden signal.

Three consequences, stated plainly. First, 15 of the 100 pairs have two FAIL answers, so no figure can be rebuilt, and they are left out of the runs that use a reference (85 pairs, 170 answers). Second, the labels define the reference, so a PASS answer matches its reference by construction. Agreement on PASS answers is therefore an easy test; the real test is whether the judge rejects a wrong figure. Third, this measures whether the model can compare an answer with a reference. It does not measure whether the model knows the policy. In a real project you would give the judge the policy document.

The script also splits the pairs in two, as chapter 3 advises. Even-numbered pairs are the development set, where you may read mistakes and edit the rubric. Odd-numbered pairs are the test set, which you run once at the end.

Your prediction

Write down four things before you run. (1) If the judge sees no reference, what will kappa be? (2) With the reference, will the 1.5B judge be weaker on TPR (good answers it fails) or on TNR (bad answers it passes)? (3) Will kappa on the test set be above or below the lab stand-in's, which scored about 0.7? (4) In the swap test, will it favour the first or the second slot when it has nothing to go on?

The author's predictions, written before the first run

(1) About 0, by the arithmetic above, if the judge says PASS to nearly everything, and not much higher if it guesses. (2) Weaker on TNR: small models are lenient and tend to approve whatever looks plausible. (3) Somewhat below 0.7. (4) The first slot, as the position bias in chapter 3 describes. The results show which of these held.

The idea

  1. read the 200 labelled answers; rebuild the correct figure from each pair's human PASS answer; split pairs into development and test
  2. ask the model "PASS or FAIL?" for each answer at temperature 0, with the reference and then without it
  3. count TPR and TNR with Wilson intervals; compute kappa, with a bootstrap that resamples whole pairs, not single answers
  4. swap test: for each pair with exactly one correct answer, ask "which is correct, A or B?" in both orders
  5. run the lab's stand-in judge on the same answers for comparison
"""A real judge, calibrated: a small local model grades evals lab 2's
200 labelled answers; measure agreement with the humans, Cohen's kappa with
an interval, and position bias with the swap test.

With Ollama (ollama pull qwen2.5:1.5b), from this folder:
    python real_judge.py --model qwen2.5:1.5b
Without Ollama: transformers can serve the same API (any OpenAI-compatible
server works), for example
    transformers serve Qwen/Qwen2.5-1.5B-Instruct --port 8766
    python real_judge.py --base-url http://127.0.0.1:8766/v1 \
        --model Qwen/Qwen2.5-1.5B-Instruct

Needs: lab 2's labelled.jsonl and judge_data.json (evals/labs/code/lab02).
Standard library only."""
import argparse
import json
import math
import random
import re
import sys
import urllib.request
from collections import defaultdict
from pathlib import Path

sys.dont_write_bytecode = True      # keep the lab folder clean

# ── 1. Settings ──────────────────────────────────────────────────────────
try:
    LAB = Path(__file__).resolve().parents[3] / "labs/code/lab02"
except NameError:                              # running as a notebook
    LAB = Path("../../../labs/code/lab02").resolve()
ap = argparse.ArgumentParser()
ap.add_argument("--base-url", default="http://localhost:11434/v1")
ap.add_argument("--model", default="qwen2.5:1.5b")
ap.add_argument("--lab", default=str(LAB))
ap.add_argument("--split", default="test",
                choices=["dev", "test", "all"])   # even pairs dev, odd test
ap.add_argument("--rubric", type=int, default=2, choices=[1, 2])
ap.add_argument("--errors", type=int, default=0)  # print N disagreements
ap.add_argument("--quick", action="store_true")   # reference grading only
ap.add_argument("--boot", type=int, default=2000)  # bootstrap resamples
args, _ = ap.parse_known_args()    # notebooks pass their own flags
LAB = Path(args.lab)


def ask(prompt, words):
    """One greedy reply from the model; return the first of `words` in it."""
    body = {"model": args.model, "temperature": 0, "max_tokens": 6,
            "messages": [{"role": "user", "content": prompt}]}
    req = urllib.request.Request(
        args.base_url.rstrip("/") + "/chat/completions",
        data=json.dumps(body).encode(), headers={
            "content-type": "application/json",
            "authorization": "Bearer ollama"})
    with urllib.request.urlopen(req, timeout=120) as r:
        said = json.loads(r.read())["choices"][0]["message"]["content"]
    hit = re.search(r"\b(" + "|".join(words) + r")\b", said or "", re.I)
    return hit.group(1).upper() if hit else None     # None: not an answer


# ── 2. The data, and a reference rebuilt from the human PASS answers ─────
FILLER = json.load(open(LAB / "judge_data.json"))["filler"]
rows = [json.loads(line) for line in open(LAB / "labelled.jsonl")]


def figure(answer):
    """The one number an answer states, once filler sentences are removed."""
    for sentence in FILLER + ["Good question."]:
        answer = answer.replace(sentence, "")
    return re.findall(r"\d[\d,]*", answer)[0]


pairs = defaultdict(list)                 # "L0000" -> its two answers
for r in rows:
    pairs[r["id"][:-1]].append(r)
pairs = list(pairs.values())
if args.split != "all":                    # dev: write the rubric on this
    pairs = pairs[args.split == "test"::2]  # test: look once, at the end
for p in pairs:       # the lab data has no policy text: use the PASS figure
    good = {figure(r["answer"]) for r in p if r["human"] == "PASS"}
    p.append(good.pop() if len(good) == 1 else None)        # reference
items = [(r, p[2]) for p in pairs for r in p[:2]]
print(f"split {args.split}, rubric {args.rubric}: "
      f"{len(items)} answers in {len(pairs)} pairs; "
      f"{sum(p[2] is not None for p in pairs)} pairs have a reference")

# ── 3. The judge: a binary rubric, with and without the reference ────────
RUBRICS = {1: ("You grade answers from a customer-support assistant.\n"
               "Question: {q}\n{ref}Answer: {a}\n\n"
               "Does the answer state the correct figure? "
               "Reply with one word: PASS or FAIL."),
           2: ("You grade answers from a customer-support assistant.\n"
               "Question: {q}\n{ref}Answer: {a}\n\n"
               "Find the figure the answer gives. If it is exactly the "
               "correct figure, reply PASS. If it is any other number, "
               "reply FAIL. Reply with one word: PASS or FAIL.")}
REF = "The correct figure is {n}.\n"


def judge(row, ref):
    prompt = RUBRICS[args.rubric].format(q=row["question"], a=row["answer"],
                           ref=REF.format(n=ref) if ref else "")
    return ask(prompt, ["PASS", "FAIL"]) or "FAIL"   # unparsed counts FAIL


# ── 4. Agreement with the humans (chapters 3 and 4, 5) ───────────────────
def wilson(k, n, z=1.96):
    """95% interval for a proportion that behaves at the edges."""
    if n == 0:
        return (float("nan"),) * 2
    p, d = k / n, 1 + z * z / n
    mid = (p + z * z / (2 * n)) / d
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return max(0.0, mid - half), min(1.0, mid + half)


def kappa(h, j):
    """Chapter 5's eq-kappa: (po - pe) / (1 - pe)."""
    n = len(h)
    po = sum(a == b for a, b in zip(h, j)) / n
    ph, pj = sum(a == "PASS" for a in h) / n, sum(b == "PASS" for b in j) / n
    pe = ph * pj + (1 - ph) * (1 - pj)
    return (po - pe) / (1 - pe) if pe < 1 else 0.0


def report(name, human, judged, groups, subset=None):
    tp = sum(h == j == "PASS" for h, j in zip(human, judged))
    tn = sum(h == j == "FAIL" for h, j in zip(human, judged))
    pos, neg = human.count("PASS"), human.count("FAIL")
    print(f"\n{name} ({len(human)} answers, judge says PASS "
          f"{judged.count('PASS') / len(judged):.0%})")
    for label, k, n in (("TPR", tp, pos), ("TNR", tn, neg),
                        ("accuracy", tp + tn, len(human))):
        lo, hi = wilson(k, n)
        print(f"  {label:<8} {k:>3}/{n:<3} = {k / n:5.1%}  "
              f"95% CI {lo:5.1%} to {hi:5.1%}")
    rng, ks = random.Random(0), []
    for _ in range(args.boot):        # resample whole pairs, not answers
        pick = [i for g in rng.choices(groups, k=len(groups)) for i in g]
        ks.append(kappa([human[i] for i in pick], [judged[i] for i in pick]))
    ks.sort()
    print(f"  kappa    {kappa(human, judged):.2f}  95% CI "
          f"{ks[int(.025 * len(ks))]:.2f} to {ks[int(.975 * len(ks))]:.2f}"
          f"  (bootstrap over {len(groups)} pairs)")

    misses = [(r, ref, h, j) for (r, ref), h, j in
              zip(subset or [], human, judged) if h != j]
    for r, ref, h, j in misses[:args.errors]:      # read the disagreements
        print(f"  miss: human {h}, judge {j}: figure {figure(r['answer'])}"
              f" vs reference {ref} | {r['answer'][:30]}")


def groups_of(subset):
    """Answers that share a question are one cluster (chapter 4)."""
    by = defaultdict(list)
    for i, (r, _) in enumerate(subset):
        by[r["id"][:-1]].append(i)
    return list(by.values())


def lab_standin(subset):
    sys.path.insert(0, str(LAB))
    import judge as standin                       # the lab's fake judge
    return [standin.judge_single(r["question"], r["answer"])
            for r, _ in subset]


with_ref = [it for it in items if it[1]]
for name, subset, use_ref in (
        ("model, WITH the reference", with_ref, True),
        ("model, WITHOUT a reference", items, False))[:1 if args.quick else 2]:
    verdicts = [judge(r, ref if use_ref else None) for r, ref in subset]
    report(name, [r["human"] for r, _ in subset], verdicts,
           groups_of(subset), subset)
if args.quick:
    sys.exit()
report("lab 2 stand-in judge, same answers as the first block",
       [r["human"] for r, _ in with_ref], lab_standin(with_ref),
       groups_of(with_ref))

# ── 5. Position bias: the swap test on pairs with one PASS, one FAIL ─────
SWAP = ("Question: {q}\nThe correct figure is {n}.\n\n"
        "Answer A: {a}\n\nAnswer B: {b}\n\n"
        "Which answer states the correct figure? Reply with one letter: "
        "A or B.")
SWAP_BLIND = SWAP.replace("The correct figure is {n}.\n", "")
mixed = [p for p in pairs if {r["human"] for r in p[:2]} == {"PASS", "FAIL"}]
print(f"\nswap test on {len(mixed)} pairs with exactly one correct answer")
for name, tmpl in (("WITH the reference", SWAP),
                   ("WITHOUT a reference", SWAP_BLIND)):
    first = right_first = right_second = consistent = wins = 0
    for p in mixed:
        good = [r for r in p[:2] if r["human"] == "PASS"][0]
        bad = [r for r in p[:2] if r["human"] == "FAIL"][0]
        pick = {}
        for order, (a, b) in (("good first", (good, bad)),
                              ("good second", (bad, good))):
            pick[order] = ask(tmpl.format(q=good["question"], n=p[2],
                                          a=a["answer"], b=b["answer"]),
                              ["A", "B"])
        first += (pick["good first"] == "A") + (pick["good second"] == "A")
        right_first += pick["good first"] == "A"
        right_second += pick["good second"] == "B"
        same = (pick["good first"] == "A") == (pick["good second"] == "B")
        consistent += same
        wins += same and pick["good first"] == "A"
    n = len(mixed)
    print(f"  {name}:")
    print(f"    picks slot A in {first / (2 * n):.0%} of {2 * n} verdicts "
          f"(no bias: 50%)")
    print(f"    right when the good answer is first {right_first}/{n}, "
          f"second {right_second}/{n}")
    print(f"    same answer in both orders {consistent}/{n}; "
          f"counted as correct {wins}/{n} = {wins / n:.0%}")

What you should see

  • With the reference: kappa 0.58, 95 percent interval 0.39 to 0.75. The judge passes every good answer (44 of 44) and 16 of 30 bad ones (TNR 53 percent, interval 36 to 70). Prediction (2) held: it is lenient. Agreement is 81 percent (71 to 88), which sounds respectable. Kappa, at moderate agreement, is the more honest number.
  • The stand-in scored higher, but the intervals overlap. On the same 74 answers the lab's stand-in has kappa 0.74 (0.57 to 0.89). The real judge's interval sits mostly below it, yet the two overlap between 0.57 and 0.75. With 37 pairs you cannot say which judge is better. Prediction (3) was right about the direction and wrong to sound sure.
  • Without a reference: kappa 0.00. The judge said PASS to all 100 answers, exactly the case worked out above. Its accuracy of 44 percent is just the humans' PASS rate. A judge that cannot see the policy cannot grade against it, and its confident "PASS" carries no information. Prediction (1) was exact because it was arithmetic.
  • Position bias shows up only when the judge is unsure. With the reference, the swap test is perfect: 30 of 30 pairs get the same correct answer in both orders, and it picks slot A in 50 percent of verdicts. Without a reference it picks slot A in only 35 percent of 60 verdicts. It leans towards the second slot, the opposite of my prediction (4). When the good answer was first it was right 13 of 30 times; when second, 22 of 30. Only 17 of 30 pairs gave the same answer in both orders, and 11 of 30 were counted as wins. A coin flip would give about 8 of 30 (half the pairs consistent, half of those correct), so there is a little real signal under the position effect.
  • The same model with the same reference scores 30 of 30 when it compares two answers and only 53 percent TNR when it grades one. Choosing between two options is easier than deciding if one answer clears a bar. Chapter 3 lists this as a reason to prefer pairwise comparison, when the task allows it.

A smaller judge, and more data

Qwen2.5-0.5B-Instruct, with the reference, same test pairs:

split test, rubric 2: 100 answers in 50 pairs; 37 pairs have a reference

model, WITH the reference (74 answers, judge says PASS 100%)
  TPR       44/44  = 100.0%  95% CI 92.0% to 100.0%
  TNR        0/30  =  0.0%  95% CI  0.0% to 11.4%
  accuracy  44/74  = 59.5%  95% CI 48.1% to 69.9%
  kappa    0.00  95% CI 0.00 to 0.00  (bootstrap over 37 pairs)

It says PASS to everything, even with the reference in the prompt: kappa 0.00, as for the no-reference case. At this size the model cannot do the comparison, and the numbers tell you so in one line. The interval "0.00 to 0.00" is not a precise measurement; every resample has the same all-PASS verdicts, so the bootstrap has nothing to vary.

What would more data do? Using all 85 pairs with a reference, with the same rubric:

split all, rubric 2: 200 answers in 100 pairs; 85 pairs have a reference

model, WITH the reference (170 answers, judge says PASS 77%)
  TPR      101/101 = 100.0%  95% CI 96.3% to 100.0%
  TNR       39/69  = 56.5%  95% CI 44.8% to 67.6%
  accuracy 140/170 = 82.4%  95% CI 75.9% to 87.3%
  kappa    0.61  95% CI 0.49 to 0.72  (bootstrap over 85 pairs)

The kappa interval narrows from 0.39 to 0.75 (width 0.36) to 0.49 to 0.72 (width 0.23), about as the square root of the sample size predicts: √(170 / 74) = 1.5, and 0.36 / 1.5 = 0.24. A warning: this run includes the development pairs, which are the ones the rubric was tuned on, so it is slightly optimistic. Report the test-set run, and use the larger one only to see how fast the error bars shrink.

Break it

  • Bootstrap the wrong unit. In groups_of, return one group per answer instead of one per pair. Predict: the kappa interval gets narrower, because the two answers to one question are not independent (chapter 4, "Related questions are not independent"). Then ask whether you believe the narrower one.
  • Pad the answers. Add the lab's filler sentences ("Thank you for getting in touch.") to wrong answers before judging, as lab 2's milestone 4 does. Predict how many verdicts flip towards PASS. The lab's stand-in was built to like long answers; a real model may or may not.
  • Remove the filler from the reference. The script strips filler sentences before extracting the figure. Break that, and see how often an answer's first number is not the figure.
  • Tune on the test set. Edit the rubric while looking at --split test misses until kappa rises, then run --split all. Predict whether the gain survives on the pairs you did not tune on (chapter 4, "Tuning on the test set").

Key takeaways

  • Report TPR, TNR and kappa with intervals, never accuracy alone. Here 81 percent agreement hid a judge that passed nearly half of the wrong answers.
  • A judge without the reference answer cannot grade facts: it agreed with the humans no better than "always PASS" does (kappa 0).
  • Write the rubric on a development set and report on a test set you looked at once. The rubric edit lifted kappa from 0.40 to 0.63 on development pairs and the test set gave 0.58.
  • With a few dozen pairs the error bars are wide enough that two judges cannot be told apart. Report the interval, and resample whole pairs.
  • Position bias is strongest when the judge is unsure, and the swap test is how you see it. Pairwise comparison was easier for this model than single grading.
