Grounding, Abstention & Confidence

The practical answer to hallucination is a system that answers only from evidence, says "I don't know" when the evidence is missing, and knows how sure it is. This chapter shows how to build and measure each of those three behaviours, and how a risk-coverage curve turns the trade between answering more and being wrong less into a threshold you can choose on purpose.

Why this matters

The previous chapter showed that some hallucination is structural: the facts are not in the model, and the scoring rewards a guess. You cannot prompt that away, but you can design around it. Every deployed question-answering system makes an implicit choice about when to answer. If you do not make it explicitly, the model makes it for you, in favour of answering. After this chapter you will be able to constrain a system to its evidence, test whether it declines the right questions, obtain a usable confidence signal, and set an answer-or-abstain threshold from the cost of errors, measured on held-out data rather than assumed.

Three tools for one goal

Three ideas work together, and it is worth separating them before combining them.

Grounding
Tying an answer to supplied evidence: the model is given the relevant documents or tool results and is asked to answer from them, ideally pointing to the passages it used.
Abstention
Declining to answer: "I can't find that in the documents", "I'm not sure", or "this needs a person to decide". Also called selective prediction in the machine-learning literature: the system chooses on which inputs to predict.
Confidence
A number (or ranking) that says how likely an answer is to be right. Abstention decisions are made by comparing confidence with a threshold.

Grounding reduces the number of questions the model must answer from memory. Abstention handles the questions that remain unanswerable. Confidence is the signal that tells the two apart. The next diagram shows where each gate sits in a pipeline of the kind built in RAG End to End.

Grounding: answering from evidence

A grounded system answers from supplied passages rather than from the model's memory. The retrieval half is the subject of A5 (RAG End to End, Grounded Answers & Citations). The generation half has a handful of techniques that reliably help, in rough order of strength:

  1. State the rule in the prompt and give an exit. "Answer only from the documents below. If they do not contain the answer, reply exactly: I can't find that in the documents." Without an explicit exit, the model's habit of completing the task wins.
  2. Separate evidence from instructions with clear delimiters and number the passages, so the answer can cite "[2]". Untrusted text in the evidence is also an injection channel (chapter 13).
  3. Quote first. Ask for the supporting quotation, then the answer. An answer that cannot be preceded by a quote from the evidence is a signal to abstain.
  4. Return structured output with fields for the answer, the cited passage identifiers and a verdict such as answerable: false, so that code, not prose, can act on abstentions.
  5. Verify afterwards. A second pass checks that each claim is entailed by the passage it cites (the subject of chapter 12 and Lab 5). This is Gate 2 in the diagram.

None of these is a guarantee, and the system's behaviour on missing evidence is the part most often left untested. The script below is a deliberately small grounded assistant: three policy documents, a retriever that scores each sentence by how many question words it shares, and an abstention rule that refuses when the best score is below 0.5. It is not a language model; it stands in for the retrieve-and-gate stages so that every behaviour is visible and reproducible. The eight questions include three whose answers are not in the documents.

import re

DOCS = {
 "returns.md": "Items can be returned within 30 days of delivery. Refunds are paid to the original payment method within 5 working days.",
 "shipping.md": "Standard delivery takes 3 to 5 working days. Express delivery takes 1 working day and costs 9 pounds.",
 "warranty.md": "Electrical goods carry a 2 year warranty. The warranty does not cover accidental damage.",
}
STOP = set("the a an of to in is are do does how what for and or my can i it be on with".split())
STEM = False
def stem(w): return re.sub(r"(ed|s)$", "", w) if STEM else w
def toks(s): return [stem(w) for w in re.findall(r"[a-z0-9]+", s.lower()) if w not in STOP]

def retrieve(q):
    """Best sentence by word overlap with the question: (score, doc, sentence)."""
    best = (0.0, None, None)
    for name, text in DOCS.items():
        for sent in re.split(r"(?<=\.)\s+", text):
            qs, ss = set(toks(q)), set(toks(sent))
            score = len(qs & ss) / len(qs) if qs else 0
            if score > best[0]: best = (score, name, sent)
    return best

def answer(q, min_support=0.5):
    score, doc, sent = retrieve(q)
    if score < min_support:
        return "I can't find that in the policy documents.", None
    return f"{sent} [{doc}]", doc

questions = [
    ("How long do I have to return an item", True),
    ("How long does express delivery take", True),
    ("How many years is the warranty on electrical goods", True),
    ("Does the warranty cover accidental damage", True),
    ("Can I return an item without a receipt", False),       # not in the documents
    ("Do you ship to Norway", False),                         # not in the documents
    ("What is the price of express delivery", True),
    ("Is gift wrapping available", False),                    # not in the documents
]

def run(label):
    tally = {"answered, answerable": 0, "answered, NOT in docs": 0, "abstained, not in docs": 0, "abstained, was in docs": 0}
    print(f"--- {label}")
    for q, in_docs in questions:
        a, doc = answer(q)
        key = ("abstained, was in docs" if in_docs else "abstained, not in docs") if doc is None else \
              ("answered, answerable" if in_docs else "answered, NOT in docs")
        tally[key] += 1
        if "return" in q: print(f"Q: {q}?\nA: {a}")
    print(tally)

run("exact word match")
STEM = True
run("with a crude stemmer (returned -> return)")

Read the two runs together. With exact word matching, the question about returning an item went unanswered because the document says "returned"; the question about returning without a receipt also went unanswered, which is the right outcome but for the wrong reason, as the same vocabulary mismatch caused it. A stemmer fixed the first and, in doing so, matched "return" and "item" in the receipt question to the 30-day sentence and answered it, with a citation, even though the documents say nothing about receipts. The abstention rule counted word overlap, and word overlap is not evidence of an answer. A production system uses better scoring than this toy, and the lesson transfers: retrieval relevance and answer support are different things, so Gate 1 should be tuned and tested separately from retrieval metrics (Relevance Metrics).

Build the test set with unanswerable questions

The standard way to test abstention is to include questions that have no answer in the provided material. Rajpurkar, Jia and Liang (2018, "Know What You Don't Know: Unanswerable Questions for SQuAD") added exactly this to a reading-comprehension benchmark: crowd workers wrote questions that look answerable but are not supported by the passage, and systems that had done well on the original benchmark did much worse because they answered anyway. For your own assistant, assemble a set with, say, 30% unanswerable items of several kinds: questions on topics the corpus does not cover, questions with a near-miss in the corpus (like the receipt example), questions whose premise is false, and questions that are ambiguous without a follow-up. Label each with the expected behaviour (answer, abstain, or ask a clarifying question) and treat the labels as carefully as any gold set (chapter 6).

Common misconception

"Telling the model to say 'I don't know' when unsure solves it." It changes behaviour, often usefully, but the model's sense of "unsure" is not calibrated to its error rate, and it may refuse answerable questions or answer unanswerable ones with a convincing quotation. Whether the instruction works is an empirical question about your system, answerable with a test set that has both kinds of questions and the four-cell table above.

Abstention as a measured behaviour

An abstention decision has two ways to be wrong, so a single accuracy figure is not enough. From the four cells of the table, define the quantities that matter.

QuantityDefinitionWhat it tells you
CoverageShare of all questions the system answersHow useful it is: low coverage means many refusals
Selective riskError rate among the questions it answersHow much to trust an answer when one is given
Unanswerable answer rateShare of unanswerable questions that it answers anywayThe hallucination risk on missing evidence
Needless abstention rateShare of answerable questions it declinesThe cost of caution

Selective risk is the key quantity: it is exactly the "wrong as a share of answered" rate of chapter 10, and a leading indicator for users' trust. Which of the four to prioritise depends on the application. A medical-information assistant will tolerate many needless abstentions to keep the unanswerable answer rate near zero; an internal search helper may accept the opposite. Abstention is also not one behaviour. Distinguish "I have no evidence" (retrieval empty), "the question is ambiguous" (ask), "this is outside my remit" (route elsewhere) and "this is something I will not do" (a policy refusal, covered with guardrails in chapter 15), because each wants different wording and different handling, and measuring them as one hides trade-offs.

Where a confidence signal comes from

To decide which questions to decline, the system needs a number that is higher when the answer is more likely to be right. There are several sources, with different costs and weaknesses.

  • Token probabilities. The probability the model assigned to its answer tokens. Cheap and often informative for short answers, but sensitive to phrasing (a correct answer can be written many ways, splitting probability across them), and post-training that favours confident styles tends to degrade calibration; the GPT-4 technical report (2023) reported that its pretrained model was better calibrated than the post-trained one.
  • Verbalised confidence. Asking the model to state a probability ("I am 80% sure"). Easy to display, and usually miscalibrated and clustered around a few round numbers unless it has been trained or tuned for calibration.
  • Self-evaluation. Kadavath et al. (2022, "Language Models (Mostly) Know What They Know") studied asking a model whether its own proposed answer is true, P(True), and training it to predict whether it knows the answer to a question at all, P(IK). They report that larger models are well calibrated on suitably formatted multiple-choice and true/false questions, that self-evaluation improves when the model sees several of its own samples, and that P(IK) generalises only partially to new tasks and is less well calibrated there.
  • Agreement across samples. Ask several times and see whether the answers mean the same thing; disagreement is a sign that the model is guessing. See the next subsection.
  • Retrieval and verifier signals. The top retrieval score and its margin over the second, the fraction of claims an entailment checker supports, the agreement between two retrievers. For grounded systems these are often stronger than anything the generator says about itself, because they measure the evidence.
  • Trained classifiers. A small model, trained on your labelled correct and incorrect answers, that takes the question, answer, evidence and the signals above and outputs a probability. This usually beats any single signal and needs the labels of chapter 5.

Agreement across samples: semantic entropy

If a model knows an answer, repeated samples agree; if it is guessing, they scatter. The catch is that agreement is about meaning, not wording: "Canberra", "It is Canberra." and "Canberra, ACT" are the same answer. Kuhn, Gal and Farquhar (2023) and Farquhar et al. (2024, in Nature, "Detecting hallucinations in large language models using semantic entropy") compute the entropy over clusters of equivalent meaning rather than over strings, and use it to flag confabulations: answers that are arbitrary and change from one sample to the next. The script below shows the idea on three questions, with scripted samples standing in for five draws at temperature 1. The "meaning" function is a crude stand-in for the entailment check that a real implementation uses to decide whether two answers say the same thing. The question about the bridge and the person are fictional.

import math, re
from collections import Counter

# Five sampled answers per question (scripted stand-ins for samples at temperature 1).
SAMPLES = {
    "Capital of Australia?":              ["Canberra", "canberra", "It is Canberra.", "Canberra, ACT", "Canberra"],
    "Year the Ashford bridge opened?":    ["1989", "In 1989", "1989", "1991", "1989"],
    "Date of birth of Dr R. Okafor?":     ["12 March 1961", "3 July 1958", "1 November 1964", "12 March 1961", "19 February 1960"],
}

def meaning(answer):
    """Stand-in for an entailment check: reduce an answer to a canonical claim."""
    a = answer.lower()
    if "canberra" in a:
        return "canberra"
    m = re.search(r"\d{1,2} \w+ \d{4}|\d{4}", a)
    return m.group(0) if m else a.strip(". ")

def entropy_bits(labels):
    n = len(labels)
    return max(0.0, -sum(c / n * math.log2(c / n) for c in Counter(labels).values()))

print(f"{'question':34s} distinct strings  distinct meanings  semantic entropy (bits)")
for q, samples in SAMPLES.items():
    strings = len(set(samples))
    clusters = [meaning(s) for s in samples]
    print(f"{q:34s} {strings:^16d}  {len(set(clusters)):^17d}  {entropy_bits(clusters):^.2f}")
question                           distinct strings  distinct meanings  semantic entropy (bits)
Capital of Australia?                     4                  1          0.00
Year the Ashford bridge opened?           3                  2          0.72
Date of birth of Dr R. Okafor?            4                  4          1.92

The first question has four different strings but one meaning, so its semantic entropy is zero: the model is consistent. The second splits between two years (0.72 bits). The third gives four different dates in five samples (1.92 bits): the model has nothing to retrieve and is generating a plausible-looking date each time. Counting distinct strings (4, 3, 4) would have ranked the capital question as nearly as uncertain as the birth date, which is why meaning matters. The cost is that you pay for several generations per question, so teams often apply it only to answers that other cheap signals have flagged.

Ranking is not calibration

For deciding what to answer you need the confidence to rank answers so that correct ones tend to sit above wrong ones; that is measured by the area under the ROC curve, or directly by the risk-coverage curve below. To display a percentage to a user, or to apply a threshold derived from costs, you need the number to be calibrated: among answers given 80% confidence, about 80% should be right. Calibration is checked with a reliability diagram (bin the confidences, plot stated confidence against actual accuracy) and summarised by the expected calibration error, the average gap weighted by bin size. The fundamentals of calibration are covered in Imbalance, Thresholds & Calibration; here the point is that a model can rank well and be badly calibrated, which a simple recalibration step (fit on held-out data) can repair without changing which questions are answered first.

Risk-coverage curves

Now combine confidence and abstention. Sort the questions by confidence from highest to lowest. The system with a threshold t answers the questions whose confidence is at least t. As t falls, coverage (the share answered) rises, and the risk (the error rate among those answered) usually rises too, because the added questions are the ones the system is less sure about. Plotting risk against coverage gives the risk-coverage curve, the standard tool of selective prediction (Geifman and El-Yaniv, 2017, "Selective Classification for Deep Neural Networks"). A perfect confidence signal would answer all correct questions first, keeping risk at zero until coverage reaches the accuracy; a useless one would give a flat line at the overall error rate. The area under the curve (AURC) summarises ranking quality in one number, lower being better.

The script simulates 2,000 calibration questions and 2,000 test questions from an overconfident, noisy model: true chance of being right p follows a skewed distribution, and the reported confidence is p plus 0.12 plus noise. It reports accuracy against mean confidence and calibration error, risk at several thresholds, and then picks the best threshold on the calibration split for four different penalties for a wrong answer (a correct answer scores +1, a wrong answer scores minus the penalty, abstaining scores 0) and evaluates it on the test split.

import random
rng = random.Random(21)

def make(n):
    rows = []
    for _ in range(n):
        p = rng.betavariate(2.2, 1.4)                 # true chance this answer is right
        conf = min(0.99, max(0.01, p + 0.12 + rng.gauss(0, 0.06)))   # model is overconfident and noisy
        rows.append((conf, rng.random() < p))
    return rows
calib, test = make(2000), make(2000)

def ece(rows, bins=10):
    tot = 0
    for b in range(bins):
        sel = [(c, ok) for c, ok in rows if b / bins <= c < (b + 1) / bins or (b == bins - 1 and c == 1)]
        if sel: tot += len(sel) * abs(sum(c for c, _ in sel) / len(sel) - sum(ok for _, ok in sel) / len(sel))
    return tot / len(rows)

def at_threshold(rows, t):
    ans = [ok for c, ok in rows if c >= t]
    cov = len(ans) / len(rows)
    risk = 1 - sum(ans) / len(ans) if ans else 0.0
    return cov, risk

print(f"overall accuracy {sum(ok for _, ok in test)/len(test):.3f}   mean confidence {sum(c for c,_ in test)/len(test):.3f}   ECE {ece(test):.3f}")
print("\nthreshold  coverage  error among answered")
for t in (0.0, 0.3, 0.5, 0.7, 0.8, 0.9):
    cov, risk = at_threshold(test, t)
    print(f"  {t:.1f}       {cov:6.1%}      {risk:6.1%}")

# Pick the threshold on the calibration split by expected score: +1 correct, -penalty wrong, 0 abstain.
def score(rows, t, penalty):
    return sum((1 if ok else -penalty) for c, ok in rows if c >= t) / len(rows)
print("\npenalty  best threshold (chosen on calib)  score calib  score test  answer-always score on test")
for penalty in (0, 1, 3, 9):
    best = max((t / 100 for t in range(0, 100)), key=lambda t: score(calib, t, penalty))
    print(f"  {penalty:2d}        {best:.2f}                           {score(calib,best,penalty):+.3f}      {score(test,best,penalty):+.3f}      {score(test,0,penalty):+.3f}")
overall accuracy 0.597   mean confidence 0.720   ECE 0.124

  0.3        95.3%       38.1%
  0.5        80.9%       33.1%
  0.7        57.8%       24.8%
  0.8        43.6%       20.1%
  0.9        28.4%       15.3%

Three things stand out in the output. First, at full coverage the error is 40%, and no threshold on this model's confidence brings it near zero while keeping most questions: at 0.9 confidence the error is still 15%. This is the signature of a model whose ranking is informative but not sharp. Second, the best threshold depends on the penalty: with no penalty answering everything is optimal (threshold 0.00); at a penalty of 1 the best cut is 0.54; at 3 it rises to 0.87; at 9 it is 0.98 and the score is essentially zero, which means the system should decline nearly everything, because it cannot reach the 90% precision that a penalty of 9 demands. Third, thresholds chosen on the calibration split carry over to the test split (for penalty 3: +0.146 on calibration, +0.118 on test), while the always-answer policy scores −0.614 there. If you choose the threshold on the same questions you report, the figure is optimistic, which is the held-out-set rule of What Learning Is: Generalisation again.

The threshold from the costs

If the confidence were perfectly calibrated, no search would be needed. Answering earns c − λ(1 − c) in expectation, which beats abstaining (score 0) exactly when c > λ/(1 + λ). A penalty of 1 gives a threshold of 0.5, a penalty of 3 gives 0.75 and a penalty of 9 gives 0.9. This is also the rule of Kalai et al. (2025) for scoring benchmarks fairly. The simulated model above is overconfident, which is why its empirical thresholds (0.54, 0.87, 0.98) sit above the theoretical ones (0.5, 0.75, 0.9): stated confidences are inflated, so the cut must be raised to compensate. Recalibrating first and then using the formula gets to a similar place, with an explanation you can defend.

Designing the abstention experience

An abstention is a user-facing event, and a bare "I don't know" wastes it. Good designs do four things. They say what is missing ("the documents I have cover returns and delivery, not gift wrapping"), which also lets the user judge whether the gap is in the question or the corpus. They offer a next step: a related answer they can give, a clarifying question, a link to the right team. They hand over to a person where the stakes justify it, with the conversation and evidence attached so the user does not start again. And they use tiers instead of one cut: above a high threshold answer directly; in a middle band answer with an explicit caveat and the sources; below a low threshold decline. A cascade is a variant: a cheap model answers what it is confident about and passes the rest to a stronger model or a person, which links to the cost trade-offs of chapter 19.

Operating the system is a measurement job. Track the abstention rate and the selective risk in production as service indicators, in the manner of SLIs, SLOs & Error Budgets: a target such as "error among answered questions at most 5%, with coverage at least 60%" is an SLO you can alert on. Audit a random sample of answered and abstained cases every week with human labels (the sampling and labelling of chapters 5 and 18), because thresholds drift when the corpus, the user mix or the model changes. After any of those changes, recalibrate on fresh labelled data before trusting the old cut. A rising abstention rate with stable risk usually means the corpus has a gap; a rising risk with stable abstention means the confidence signal has stopped tracking correctness.

Analogy: the triage nurse

A triage nurse does not treat everyone and does not refuse everyone. They sort: simple cases are handled at the desk, uncertain ones are escalated to a doctor, and a few are sent straight to emergency. The threshold between "handle" and "escalate" is set by the cost of a missed diagnosis against the cost of a doctor's time, and it is audited by reviewing cases afterwards. An answering system sorts questions the same way, and the same discipline applies.

Where it breaks down: a nurse can usually tell why they are unsure, and can ask the patient a question on the spot. A model's confidence is a statistical summary whose failure modes (overconfidence on topics it has seen often, miscalibration after post-training) are invisible to it, so the escalation rule has to be validated from outside.

State of play, October 2026

Benchmarks that grade by accuracy alone still dominate model announcements, which keeps rewarding guessing; Kalai et al. (2025) list many that give no credit for abstaining and argue for explicit confidence targets in the instructions. Factuality suites are increasingly split into parametric, search-based and grounded variants, with hidden test splits (seen through summaries of DeepMind's FACTS and SimpleQA Verified work; read the primary pages before citing figures). Provider APIs now commonly offer citation or grounding features and log-probability outputs, but their availability and semantics differ and change; read current documentation, and test any "confidence" field for calibration on your own labelled data before using it as a threshold.

Systems connection

Abstention is admission control for answers: under load or uncertainty the service declines some requests so that the ones it serves stay good, the idea in Overload, Load Shedding & Metastability. A refusal that routes to a person is a fallback path, and its capacity (can the human queue absorb the abstentions?) needs the same planning as any dependency. The threshold sweep is the precision-recall trade-off of Framing Problems & Choosing Metrics with a different name.

Key takeaways

  • Grounding, abstention and confidence are three parts of one design: constrain the answer to evidence, decline when evidence or confidence is insufficient, and use a signal that ranks answers by correctness.
  • Test with unanswerable questions, including near misses and false premises, and read all four outcomes: right answer, needless abstention, confident misanswer and correct abstention.
  • Retrieval relevance is not answer support. Word overlap, similarity or a high retrieval score can all sit beside a missing answer.
  • Confidence comes from token probabilities, verbalised numbers, self-evaluation, agreement across samples (semantic entropy), retrieval and verifier signals, or a trained classifier. Ranking is enough for choosing what to answer; calibration is needed to show percentages or apply cost-derived thresholds.
  • A risk-coverage curve shows the trade between answering more and being wrong less. Choose the threshold on a calibration split from the cost of a wrong answer, and report on a test split.
  • If the model cannot reach the precision the cost demands, no threshold fixes it: the correct policy is to decline most questions until the model or retrieval improves.
  • Design abstentions to help the user, and monitor abstention rate and selective risk in production, recalibrating after any change.

Check your understanding

A grounded assistant is tested only on questions whose answers are in its documents, and scores 95%. Why is that evidence insufficient for deployment?

  1. Because 95% is below the standard for question answering.
  2. Because the documents should have been shuffled before testing.
  3. Because it says nothing about what happens when the answer is absent, which is when guessing causes harm.
  4. Because grounded systems cannot exceed 90% accuracy.
Abstention behaviour only shows up on questions without supported answers: near misses, missing topics and false premises. A test set without them cannot reveal confident misanswers. The accuracy figure itself, and shuffling, are not the problem, and there is no such ceiling for grounded systems.

A calibrated system should answer only when its confidence exceeds λ/(1 + λ), where λ is the penalty for a wrong answer relative to the reward for a right one. If a wrong answer costs three times what a right one earns, what is the threshold?

  1. 0.75
  2. 0.50
  3. 0.33
  4. 0.90
With λ = 3 the break-even is 3/4 = 0.75: answering earns c − 3(1 − c) = 4c − 3, which is positive only above 0.75. A threshold of 0.5 corresponds to a penalty of 1 and 0.9 to a penalty of 9. If the model is overconfident, as in the simulation, the effective cut on its stated confidence has to be higher still.

Five samples of an answer to a question read "Canberra", "canberra", "It is Canberra.", "Canberra, ACT" and "Canberra". Which statement about semantic entropy is right?

  1. It is high, because there are four different strings.
  2. It is undefined, because the answers are not identical.
  3. It is low only if the temperature is 0.
  4. It is zero, because after grouping by meaning all five samples say the same thing.
Semantic entropy is computed over clusters of equivalent meaning, not over strings, so differences of wording do not count. All five answers entail "the capital is Canberra", giving a single cluster and zero entropy. At temperature 0 there would be no variation to measure.

You choose a confidence threshold by maximising the score on 2,000 labelled questions, then report the score on the same 2,000. What is wrong?

  1. Nothing; the threshold is optimal by construction.
  2. The reported score is optimistic, because the threshold was fitted to those questions; choose it on a calibration split and report on a separate test split.
  3. The threshold should be set to 0.5 regardless of the data.
  4. The score should be computed only on questions the system abstained on.
A threshold tuned on a set fits that set's noise, so its score there overstates future performance. Using a separate test split gives an honest estimate (in the chapter's simulation the test score was lower than the calibration score at penalties of 0, 1 and 3). Fixing it at 0.5 ignores costs, and scoring only abstentions is meaningless.

In the grounded-assistant script, adding a stemmer removed a needless abstention but created a confident answer to a question about receipts. What does this show?

  1. Stemming should never be used in retrieval.
  2. The test set was too small to be informative.
  3. Word overlap measures relevance, not whether the evidence answers the question, so the abstention gate needs its own test.
  4. The assistant should always abstain when the question contains a verb.
The retriever correctly found the nearest sentence; the failure is that "nearest" is not "answers". Stemming itself is a sound technique (option 1 overgeneralises), and the small test set was enough to reveal the trade. Gate 1 needs separate evaluation on answerable and unanswerable questions.

A model's confidence ranks answers well but is overconfident: answers given 90% are right only 70% of the time. What can be done without changing which questions are answered first?

  1. Nothing; ranking and calibration cannot be separated.
  2. Recalibrate the scores on held-out labelled data (for example by fitting a monotone mapping), then apply cost-derived thresholds to the corrected probabilities.
  3. Lower the sampling temperature to 0.
  4. Double the number of retrieved passages.
A monotone recalibration changes the numbers but not their order, so the ranking quality (and risk-coverage curve) is unchanged while stated confidences become honest. Temperature and passage count change the model's behaviour and are not calibration fixes.
