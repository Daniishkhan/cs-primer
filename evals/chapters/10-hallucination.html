Why Models Hallucinate

A language model will state a wrong date, an invented court case or a fee that does not exist in the same calm tone it uses for the truth. This chapter separates the different things people call hallucination, explains why they arise at each stage from pretraining to scoring, and shows how to measure them so that the number you track rewards honesty rather than confident guessing.

Why this matters

Hallucination is the failure that decides whether people can rely on an AI system at all. A lawyer who files a brief with cases that were never decided, or a customer told the wrong refund window, has been harmed by fluent text that nobody checked. The fixes in the next chapters (grounding and abstention, fact-checking and citation verification) only make sense once you know where the errors come from and what a good measurement looks like. After this chapter you will be able to classify a bad output, explain why a model that is "usually right" still invents facts, and design a measurement that does not reward guessing.

What counts as a hallucination

In everyday use hallucination means a model output that is fluent and plausible but not supported: not true in the world, or not supported by the material the model was given. The word covers several different failures that have different causes and different fixes, so the first skill is to name which one you are looking at. Huang et al. (2023, "A Survey on Hallucination in Large Language Models") organise the field around two families, and this chapter uses them.

  • Factuality hallucination: the output conflicts with facts about the world. Either the model fabricates something that does not exist (a case, a paper, a person, an API function) or it gets an attribute of something real wrong (the date, the dose, the fee).
  • Faithfulness hallucination: the output conflicts with what the user supplied. It may contradict or embellish a document it was asked to summarise (context inconsistency), ignore the instruction or the requested format (instruction inconsistency), or make reasoning steps that do not follow (logical inconsistency).

Examples from different fields make the families concrete.

Where hallucinations come from

It helps to follow a model's life. A pretrained model learns to predict the next token; post-training shapes it into an assistant; at serving time it samples a reply from its distribution; and in evaluation someone scores it. Each stage contributes a distinct cause.

1. Pretraining: plausible, not true

The pretraining objective rewards assigning high probability to text that looks like the training text. It does not contain a notion of truth. For patterns that are regular, such as spelling, grammar and arithmetic on small numbers, more data and scale remove errors because there is a rule to learn. For arbitrary facts there is no rule. A particular person's birthday, a particular case's docket number or a company's founding year cannot be inferred from anything else; the model can only have memorised it from text that stated it. If it never saw the fact, the best it can do is produce something of the right shape.

Kalai and Vempala (2024, "Calibrated Language Models Must Hallucinate") make this precise. They show, for a model whose confidence matches its accuracy (a calibrated model), that the rate of hallucination on arbitrary facts has a lower bound close to the fraction of facts that appear exactly once in the training data, a singleton rate in the style of the Good-Turing estimate of unseen events. The bound holds even if the training data contain no errors. The intuition is simple: a fact seen once looks, to the learner, no different from a fact it will be asked about that it never saw, so the same uncertainty applies to both. Facts that appear many times, and systematic ones like arithmetic, carry no such statistical necessity.

The simulation below builds a toy world with 20,000 facts (say, one birthday per person), where how often each is written about is heavy-tailed: a few people appear constantly and most almost never. It samples 12,000 training mentions, counts how often each fact was seen and then asks 5,000 questions drawn the same way. The numbers are illustrative; the shape is the point.

import random
from collections import Counter

rng = random.Random(5)
N_FACTS = 20000                       # e.g. one birthday per person in a made-up world
# Popularity is heavy-tailed: a few people are written about constantly, most almost never.
weights = [1 / (r + 1) ** 0.9 for r in range(N_FACTS)]
TRAIN_MENTIONS = 12000                # documents in the training corpus that state one fact each
corpus = rng.choices(range(N_FACTS), weights=weights, k=TRAIN_MENTIONS)
count = Counter(corpus)

singletons = sum(1 for f, c in count.items() if c == 1)
sing_rate = singletons / TRAIN_MENTIONS          # Good-Turing: estimate of mass on never-seen facts
print(f"distinct facts seen {len(count)} of {N_FACTS}; seen exactly once {singletons}")
print(f"singleton rate (singletons / mentions) = {sing_rate:.3f}")

# Test questions are drawn the same way. A fact never seen in training can only be guessed.
test = rng.choices(range(N_FACTS), weights=weights, k=5000)
seen_twice = sum(1 for f in test if count[f] >= 2)
never = sum(1 for f in test if count[f] == 0)
print(f"\nof 5000 test questions: seen >=2 times {seen_twice/50:.1f}%, seen once {100*sum(1 for f in test if count[f]==1)/5000:.1f}%, never seen {100*never/5000:.1f}%")
print(f"missing mass actually observed (never seen)  : {never/5000:.3f}   Good-Turing estimate: {sing_rate:.3f}")
print(f"if it always answers, errors on never-seen facts alone: {100*never/5000*(1-1/365):.1f}% of questions")

This is not an argument that hallucination cannot be reduced. It says the cause for this class is not a bug in the model's architecture but a property of the data: some questions have no learnable answer, and what matters is how the model behaves when it reaches one.

2. Post-training: teaching a model to answer anyway

Supervised fine-tuning (SFT) and preference training teach a model to produce helpful, complete answers. If the training examples contain answers the model could not have known, it learns the style of confident answering without the knowledge. Gekhman et al. (2024, "Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?") report in a controlled closed-book question-answering setup that examples introducing new facts are learned much more slowly than those matching existing knowledge, and that once they are learned the model's tendency to hallucinate rises in step. Their conclusion is that models mostly acquire factual knowledge in pretraining, and fine-tuning mainly teaches them how to use it, so fine-tuning on facts the model lacks is a risk. Preference training adds its own pressure: human raters and reward models tend to prefer confident, complete, agreeable answers (Reward Models & Reward Hacking), which discourages "I am not sure".

3. Scoring: guessing is rewarded

The most useful single idea in the recent literature is that how we score models makes guessing the best policy. Kalai, Nachum, Vempala and Zhang (OpenAI, 2025, "Why Language Models Hallucinate") argue that under binary grading, where a correct answer scores 1 and everything else scores 0, abstaining is strictly suboptimal: an answer of "I don't know" scores zero exactly like a wrong answer, so a guess that is right even occasionally beats it. The paper surveys common benchmarks and reports that several, including MMLU-Pro, GPQA, SWE-bench and Humanity's Last Exam, grade by accuracy with no credit for abstaining. A model optimised on such scores is in the position of a student on a multiple-choice exam with no penalty for wrong answers: it learns to bluff.

Work through a toy example. A model knows the answer to 40 of 100 questions. On the other 60 it has only a hunch, right one time in five. Compare an "always guess" policy with an "abstain when unsure" policy under three scoring rules.

# Two answerers on the same 100 questions. Facts they know: 40 (always right).
# The other 60 are questions where each has only a hunch that is right 1 time in 5.
def outcomes(policy):
    correct, wrong, idk = 40, 0, 0
    if policy == "always guess":
        correct += 60 * 0.2; wrong += 60 * 0.8
    else:                       # "abstain when unsure"
        idk += 60
    return correct, wrong, idk

def score(c, w, i, wrong_penalty): return c - wrong_penalty * w

print("policy              correct wrong  idk | accuracy-only  penalty 1/3 per error  penalty 1 per error")
for policy in ("always guess", "abstain when unsure"):
    c, w, i = outcomes(policy)
    print(f"{policy:19s} {c:6.0f} {w:5.0f} {i:4.0f} | {score(c,w,i,0):13.1f} {score(c,w,i,1/3):21.1f} {score(c,w,i,1):20.1f}")
policy              correct wrong  idk | accuracy-only  penalty 1/3 per error  penalty 1 per error
always guess            52    48    0 |          52.0                  36.0                  4.0
abstain when unsure     40     0   60 |          40.0                  40.0                 40.0

Under accuracy-only scoring the guesser wins, 52 to 40, although it is wrong on 48 questions and the other model on none. Penalise each error by one third of a point and the guesser's lead shrinks to a deficit (36 to 40); at one point per error the guesser scores 4 and the abstainer 40. The only thing that changed was the scoring rule. The paper's proposed rule is explicit: tell the model that mistakes cost t/(1 − t) points and "I don't know" costs nothing, so that answering pays only when its confidence exceeds t. With t = 0.5 the penalty is 1, with t = 0.75 it is 3 and with t = 0.9 it is 9.

Common misconception

"Hallucinations are random glitches that more scale, or temperature 0, will remove." Lowering the temperature makes the model repeat its single most likely continuation, which for an unknown fact is still a guess, now delivered consistently. Scale reduces errors on facts that appear often, and cannot create knowledge of facts that were never in the data. The structural causes above (the singleton tail, the pressure to answer, the scoring rule) remain.

4. Decoding, context and snowballing

Two further causes arise at serving time. First, a language model generates one token at a time and conditions on what it has already written. Zhang et al. (2023, "How Language Model Hallucinations Can Snowball") describe hallucination snowballing: a model commits to an early mistake and then generates further errors it would not otherwise have made, in order to stay consistent with its own earlier claim. They report that ChatGPT identified about 67% of its own mistakes and GPT-4 about 87% when asked about them separately, which means the knowledge to avoid the error was often present while the error was being produced. Long answers therefore have more room to go wrong, and the first error is often the one worth fixing, an idea familiar from the error analysis of chapter 1.

Second, supplying context does not guarantee faithfulness. If retrieval returns the wrong document, a stale one or a long one where the key sentence is buried, the model may ignore it or blend it with prior knowledge. How RAG Fails catalogues these cases. A particularly instructive incident is the one in Glue on Pizza, where search answers were faithful to a joke or satirical source and still wrong: being grounded in a bad source is not being true.

Measuring hallucination

You cannot reduce what you do not measure, and the measurement design decides whether you reward honesty. Three situations need three instruments.

Closed-book factual questions

The model answers without documents, and you compare with a trusted key. The SimpleQA benchmark (Wei et al., 2024, "Measuring short-form factuality in large language models") was built for this: questions were adversarially collected against GPT-4 responses so that they are hard, each has a single indisputable answer so grading is easy, and each answer is graded as correct, incorrect or not attempted. That three-way grade is the important design choice: it separates a wrong answer from a refusal, which accuracy alone cannot do. The benchmark states the ideal behaviour as answering as many questions correctly as possible while declining those the model is not confident about.

Long-form generation

A paragraph mixes true and false claims, so a single right-or-wrong grade loses information. FActScore (Min et al., 2023, "FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation") breaks a generation into atomic facts and computes the percentage supported by a reliable knowledge source. Applied to biographies, it found that ChatGPT scored 58%, and the authors report that an automated estimator built from retrieval and a strong language model had under 2% error against human-computed scores. The pattern, claim extraction then verification, is the subject of chapter 12.

Faithfulness to supplied documents

When the question is "does the answer stay within the source?", the reference is the document itself. Typical methods are human labelling of unsupported claims, entailment models that judge whether a passage supports a statement, and LLM judges with a rubric ("list every claim in the answer that the document does not state"), validated as in chapter 3. Because the reference travels with the question, this can be measured on your own production traffic, which makes it the most practical of the three.

Report the triple, and say which rate you mean

Whatever the instrument, record three outcomes per question: correct, wrong, and abstained. Then be precise about the rate. Two models on a 10-question quiz show why.

# Scoring answers to a 10-question closed-book quiz three ways.
runs = {
    "Model P (always answers)":       ["correct"] * 5 + ["wrong"] * 5,
    "Model Q (abstains when unsure)": ["correct"] * 4 + ["wrong"] * 1 + ["idk"] * 5,
}
for name, rec in runs.items():
    c, w = rec.count("correct"), rec.count("wrong")
    print(f"{name}")
    print(f"  accuracy {c/len(rec):.0%} | hallucination rate (wrong / all) {w/len(rec):.0%} | "
          f"precision when answering {c/(c+w):.0%} | score at -1 per error {(c-w)/len(rec):+.1f}")
Model P (always answers)
  accuracy 50% | hallucination rate (wrong / all) 50% | precision when answering 50% | score at -1 per error +0.0
Model Q (abstains when unsure)
  accuracy 40% | hallucination rate (wrong / all) 10% | precision when answering 80% | score at -1 per error +0.3

Model P has the higher accuracy (50% against 40%) and a hallucination rate of 50% (wrong answers as a share of all questions). Model Q abstains on half and is wrong on one question in ten; when it does answer it is right 80% of the time against P's 50%. Which is better depends on what a wrong answer costs. If one error costs as much as a correct answer earns (the last number), Q is ahead; if errors are cheap and abstentions are expensive, P may be. The quantity to report is the whole triple, with the denominator named (wrong / all versus wrong / answered), and a score under an explicit error penalty chosen from the cost of mistakes in your application. Chapter 11 turns the trade between answering and abstaining into a curve.

State of play, October 2026

The scoring-incentive argument of Kalai et al. (arXiv, September 2025) has become the standard framing: report error rates and abstention, not only accuracy. Key takeaways

  • Hallucination is a family of failures: factuality (fabrication, wrong attribute) and faithfulness (context conflict, instruction drift, logical error), plus misreported actions in agents. Name the kind first.
  • For arbitrary facts the learnable signal is thin: a calibrated model must hallucinate at roughly the rate of facts seen once in training, even from perfect data.
  • Post-training that teaches confident answering of facts the model lacks, and raters who prefer confident replies, strengthen the habit.
  • Binary accuracy scoring makes guessing the best policy. Score correct, wrong and abstained separately, with an error penalty chosen from the cost of mistakes.
  • Long answers can snowball from one early error. Temperature 0 and scale do not remove the structural causes.
  • Measure with the instrument that fits: closed-book QA with a not-attempted option, atomic-claim scoring for long text, and document-relative faithfulness checks on real traffic.
  • Always report the triple and name the denominator of any hallucination rate.

Check your understanding

A summarisation assistant, given a quarterly report, writes "Revenue grew 8%". The report says revenue grew 3% and profit grew 8%. Which kind of hallucination is this?

  1. Fabrication of a nonexistent entity.
  2. A faithfulness (context) hallucination: the output conflicts with the supplied document.
  3. A logical error in a multi-step derivation.
  4. Not a hallucination, because 8% appears in the report.
The model had the source and misreported it, which is a context inconsistency. Nothing was invented from nothing (option 1), no reasoning chain is at issue (option 3), and the presence of the number 8% in the document does not make attributing it to revenue correct (option 4).

In a clean training corpus, 30% of the facts about private individuals appear exactly once. According to the singleton-rate argument, roughly what is the lower bound on a calibrated model's hallucination rate on such facts?

  1. Close to 0%, because the data contain no errors.
  2. Close to 70%, the share seen more than once.
  3. Exactly 50%, since the model either knows or does not.
  4. Close to 30%, the fraction of singletons.
The bound is about the singleton fraction, a Good-Turing-style estimate of how much probability sits on facts the model cannot distinguish from unseen ones. Error-free data do not remove it (option 1), and facts seen many times are not subject to the same necessity (option 2).

A model knows 40 of 100 answers and has a one-in-five hunch on the rest. Under accuracy-only scoring it should always guess. At which penalty per wrong answer does abstaining on the 60 uncertain questions become the better policy?

  1. Any penalty above 0.25 per error, since a one-in-five guess has an expected value of 0.2 − 0.8λ, which is negative once λ exceeds 0.25.
  2. Only a penalty above 4 per error.
  3. Any penalty above 1 per error.
  4. There is no penalty at which abstaining wins, because the guesser answers more questions correctly.
The expected score of a guess with a 20% chance of being right is 0.2 − 0.8λ, which falls below the 0 earned by abstaining when λ > 0.25 (the break-even λ/(1+λ) = 0.2). Option 4 is the accuracy-only intuition the chapter warns about. Options 2 and 3 are well above the true break-even.

A team lowers the sampling temperature to 0 to "fix" invented facts. What is the most accurate expectation?

  1. Fabrications disappear, because randomness was the cause.
  2. Hallucinations double, because the model becomes more confident.
  3. Outputs become more repeatable, but a wrong most-likely answer to an unknown fact is simply repeated.
  4. Nothing changes at all, including run-to-run variation.
Temperature 0 picks the single most probable continuation, which makes outputs consistent. For a fact the model never learned, that continuation is still a guess. Sampling noise can add errors, so option 4 is also wrong, but it is not the main cause, so option 1 overstates the effect.

Two models are compared on 1,000 questions. Model R is right on 520 and wrong on 480, never abstaining. Model S is right on 480, wrong on 100 and abstains on 420. Which statement is best supported?

  1. R is better, because its accuracy is higher.
  2. Which is better depends on the cost of an error; S answers correctly 83% of the time when it answers, versus 52% for R, and has a much lower hallucination rate.
  3. S is better, because abstaining is always preferable to answering.
  4. They are equal, because both answer about half the questions correctly.
Accuracy (52% against 48%) favours R, but R is wrong on 48% of all questions against 10% for S. When errors carry a real cost, S's precision of 480/580 (83%) matters more. Abstaining is not always preferable (option 3): an assistant that abstains too often is useless. The point is to report the triple and choose using the cost of errors.

Which measurement is best suited to checking, on live traffic, whether a retrieval-based assistant's answers stay within the passages it retrieved?

  1. A closed-book factual benchmark such as SimpleQA.
  2. Accuracy against a fixed answer key written months earlier.
  3. Perplexity of the answers under the base model.
  4. A faithfulness check of each answer against its own retrieved passages, by human labelling, an entailment model or a validated LLM judge.
Faithfulness is relative to the supplied context, and that context is available for every production request, so the check can run on real traffic. A closed-book benchmark measures parametric knowledge, an old answer key will not match live documents, and perplexity says how predictable the text is, not whether it is supported.
