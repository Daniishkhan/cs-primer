Tuning a judge on the same labelled answers you report its agreement on flatters it, for the usual overfitting reasons. So split them: a development half to write and fix the rubric, and a test half you look at once, when the rubric is final.

split_items must be stratified: shuffle the PASS and FAIL items separately and give each the same share, so a lucky shuffle cannot leave a half with almost no failures. It must be deterministic for a seed and leave its input alone. bootstrap_rate_cis redraws items with replacement many times and reads the middle 95% of each rate. TPR is a proportion over human-PASS items only, so redraw only those; redraw the human-FAIL items separately for TNR, or the PASS count wobbles, which is not the uncertainty you want.
