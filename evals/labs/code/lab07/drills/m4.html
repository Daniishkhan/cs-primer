A regression case is a test built from a real failure, so the failure cannot return unnoticed. A raw trace is a poor test: it holds personal data, depends on a database that has since changed, and records the wrong answer rather than the behaviour you want.

  • trace_to_case redacts the input again, because older traces were captured before redaction existed.
  • It stores the successful reads as fixtures, recorded results keyed by tool name and arguments, so the case replays without the live service. It does not store the writes: the point is to see whether the candidate performs them itself.
  • It copies the assertions for the failure mode with copy.deepcopy, so editing one case cannot edit the others.
  • fingerprint hashes the mode plus the normalised input, so cases that differ only in order numbers collide; dedupe skips a case that matches an existing or earlier new one.
"Where is order A-77? Ring <PHONE>"  ->  "where is order #? ring"
A-9031 gives the same text, so the two cases collide.
