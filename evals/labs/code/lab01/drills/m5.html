Before building an eval you can ask how many independent questions it takes to see a gap, and after running it you must say what the interval for the gap lets you claim. Questions needed scale with the noise and with 1/gap², so halving the gap quadruples them.

In n_required, δ is the true gap to detect, ω² is the variance, across questions, of the gap between the systems' true pass rates, and σ² is answer-to-answer noise, divided by the answers per question (ka, kb). The factor (zα/2 + zβ)² is about 7.85. mde, the smallest gap that n questions can detect, is the same formula solved for δ, so the two are inverses. verdict reads an interval for B minus A: touching 0 means "cannot tell", which is not "equal". In compare, the verdict comes from a group bootstrap of the per-case differences, which keeps the pairing.

With ω² = 1/9 and σ² = 1/6 per system, one answer each: 5 points needs 1,395 questions, 1 point needs 34,884.
