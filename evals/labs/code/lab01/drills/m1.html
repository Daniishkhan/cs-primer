A test case is one input plus a list of small checks, kept as a line of data instead of code, so anyone who finds a failure can add a case without touching Python. A check turns a reply into pass or fail, and it must say why it failed, or nobody can debug it.

The case file comes from outside your code, so load_cases validates it and names the bad line in a ValueError. Besides missing fields, expect lines that are not JSON, or are JSON but not an object. In run_check, an unknown check type must raise, not pass: a typo in a case file would otherwise become a permanent false pass. grade returns the failure reasons, so an empty list means the case passed. For number_close, only the last number in the reply counts (the given _numbers strips thousands commas).
