A benchmark keeps changing, and a change must never silently alter what a score means. A content hash fingerprints the whole file, so a reader can check that two scores came from the same items, and a MAJOR.MINOR.PATCH version number promises how far old scores stay comparable.

content_hash must be canonical, so file order cannot matter, and complete, so changing any field, even a source name, changes it. diff_items sorts ids into added, removed, edited (the scored fields differ) and meta (only other fields differ); repeated ids make a diff meaningless, so raise ValueError. classify maps the diff to a level: a new scoring rule is major (earlier scores are void); any item added, removed or edited is minor (re-run before comparing); the rest is patch. The largest change wins. bump_version resets the lower fields and treats each field as an integer.

bump_version("1.0.3", "minor") -> "1.1.0"
bump_version("0.9.9", "patch") -> "0.9.10"
