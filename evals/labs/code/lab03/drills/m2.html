A coverage matrix counts items per category and difficulty, so you can see the holes. A split sends each item to dev (to tune on) or test (to report on), and it must be stable and grouped, or the dev set quietly teaches the test set.

  • coverage skips unknown labels and leaves empty cells out; thin_cells walks the full grid, so an empty cell counts as n = 0. A cell of one item can say "covered", never "measured".
  • split_of is stable: it depends on the group name alone, so adding items never moves one. It hashes the name with SHA-256 (Python's hash changes on every run), takes it mod 1000 and compares it with dev_share × 1000.
  • assign_splits is grouped: it uses source, not id, so items from one source stay together.
  • cross_split_duplicates catches what grouping misses: copies from different sources that landed on different sides. Reuse shingles and jaccard.

SHA-256 of code:5.2 mod 1000 is 203, below 300, so every code:5.2 item is dev, however the file grows.
