A benchmark file is long and every row looks plausible, so a validator reads it for you and lists the defects: a missing answer key, a label outside the allowed set, a repeated id, and a question that repeats an earlier one. To judge "repeats", split each question into shingles, the runs of k consecutive words, and compare the two sets with Jaccard similarity: the size of the overlap divided by the size of the union.

shingles builds on the given words; a text shorter than k words has none, and jaccard of two empty sets is 0.0, not an error. validate takes each item in file order and compares its question with every earlier item. An item gets at most one such report, for its best match, and the threshold is inclusive. If both golds exist and differ after norm, the pair is worse than a copy: no system can be right on both. A flag is a lead for a person, not a verdict.

"what is the fee"      -> {what is the, is the fee}
"what is the fee now"  -> adds {the fee now}: Jaccard 2/3
