The two cheapest defences read the text. A keyword guard blocks text that matches patterns, so it normalises the text first, because attackers control it; spotlighting blocks nothing and instead marks untrusted text as data.

normalise_for_scan applies its steps in order: NFKC (which folds full-width letters into plain ones), casefold, delete the four zero-width characters, collapse whitespace, strip. NFKC does not turn a Cyrillic о into a Latin o and knows nothing of 1337-speak (digits for letters); those gaps stay, and the checker expects them. KeywordGuard.screen returns (hit, 1.0 or 0.0). datamark strips the ends, then replaces each run of whitespace with the mark. Spotlight.present wraps only tool segments, as open tag, datamarked text, close tag; user and system text is shown unchanged, because the user's message is the instruction channel.

datamark("a b\n c")  ->  a^b^c
tool "Tenant in 6B"  ->  <untrusted-data>Tenant^in^6B</untrusted-data>
