Workbench 1: An Improver's Elasticity, Measured

A self-improvement loop turns money into score. The elasticity of the loop says how much score each extra percent of spending buys: an elasticity of 1 means doubling the spend doubles the gain, below 1 means returns are diminishing, above 1 means they compound. Chapter 3 derives it. Here you build a small improver that calls a language model through the API, run it at three budgets on the lab VM, fit gain against cost, and report the elasticity with its uncertainty.

Why measure it

Artifact 4 spends a fixed dollar budget, and the question a reviewer asks is what the next dollar would have bought. A single run gives one point on the gain-against-cost curve and no idea of its spread. This workbench gives you the habit Artifact 4 needs: several seeds per budget, a held-out score so the gain is not the loop grading itself, and an interval on the fitted exponent. It also serves the fair-baseline condition of chapter 1: you run a cheap stand-in proposer at the same budgets and see whether the model beat it. Write your prediction down, then measure.

What you need

  • The lab VM (16 vCPU, 64 GB; see Your lab machine). The script uses only the standard library, so there is nothing to install. It needs an OpenAI API key in the environment (on the lab VM, source ~/.config/lab.env). Never paste a key into the script or commit one.
  • Disk: a few megabytes for the reply cache. No model download: the proposer is a hosted model, gpt-5.4-nano.
  • Time: about three minutes for the default run (12 seeds, 32 proposals each, run in parallel). Re-running replays the cache in seconds.
  • Spend: see the dated box below.

State of play, October 2026

OpenAI's model page for gpt-5.4-nano (snapshot gpt-5.4-nano-2026-03-17), fetched on 15 October 2026, lists $0.20 per million input tokens, $0.02 per million cached input tokens and $1.25 per million output tokens, with a 400,000-token context window. The script charges the full input price and ignores the cached-input discount, so its costs are slightly high. All spending figures on this page come from those prices and the token counts the API returned; prices change, so check the model page before you reuse them. The four runs on this page (the main run, the stand-in, the wider budgets and the looser cap) used 1,344 API calls and cost $0.97 in total at these prices.

Predict before you run

The question is how the held-out gain G grows with cost c. Chapter 3 models it as a power law, and the exponent is the elasticity:

G(c) = a · cε, ε = d ln G / d ln c ≈ ln(G2 / G1) / ln(c2 / c1)

In words: ε is the slope of the gain-against-cost line when both axes are logarithmic. The right-hand form is how you estimate it from two budgets. The task is the online bin-packing problem of A7 Lab 3: items of size 20 to 60 arrive one at a time and each goes into a bin of capacity 100, and the loop edits one function, priority(item, rem), that scores each feasible bin. The loop starts from worst fit (rem - item, which prefers the loosest bin), keeps a proposed function only if it uses fewer bins on 10 training instances, and is scored on 30 held-out instances it never saw. Each instance has 200 items. The proposer is gpt-5.4-nano, and the budgets are 2, 8 and 32 proposals. Gain is measured in bins saved per instance relative to worst fit.

Your prediction

Work these out on paper before reading on. (1) Assume each proposal costs 700 input tokens and 350 output tokens at the prices above. What do 2, 8 and 32 proposals cost? (2) The tight-fit rule, item - rem (best fit), is an obvious improvement on worst fit that a language model should find within a few proposals. If plain best fit saves about 3.5 bins per instance, what should the gain be at 8 and at 32 proposals, and is ε closer to 0, to 1 or to 2?

Check your arithmetic

One proposal costs 700 × $0.20/106 + 350 × $1.25/106 = $0.00014 + $0.000438 = $0.000578. So 2 proposals cost $0.0012, 8 cost $0.0046 and 32 cost $0.0185. Across 12 seeds the 32-proposal runs cost about $0.22 in total.

For the gain: once the loop has found something close to best fit, there is little left to gain, because best fit is already a strong rule for this instance family. So the gain should rise steeply over the first few proposals and then flatten. Expect about 3.5 bins by 8 proposals and only a little more by 32. A flat curve on log axes means an elasticity near 0: between 0 and 0.3 is a reasonable guess. An elasticity near 1 or above would need a task where the gain is still growing in proportion to spend, and this one saturates.

Run it

The idea

  1. 10 train and 30 held-out instances per seed; the start is worst fit
  2. ask the model for one improved priority function, given the current one, its score and the last few failures
  3. check the reply against a whitelist, run it under a 2-second alarm, and score it on the train instances
  4. keep it only if it uses fewer bins; log the tokens and the dollars either way
  5. at 2, 8 and 32 proposals, score the incumbent on the held-out instances
  6. fit ln gain against ln cost; bootstrap the seeds for an interval

One seed is one trajectory of 32 proposals, and the 2- and 8-proposal points are read off the same trajectory when it reaches that step. That is how a loop with a stopping rule behaves: stopping at 8 is identical to the first 8 steps of a run that kept going. Twelve seeds run in parallel as separate processes. The script is code/w01/improver_elasticity.py, and the same code split into cells is improver_elasticity.ipynb.

Systems connection

Three ordinary reliability habits matter here. Every paid reply is appended to a cache file the moment it arrives, so a crash loses nothing and a re-run is free and exactly reproducible. API calls retry with exponential backoff on rate limits and server errors. And model-written code is untrusted input: it is checked against a whitelist of syntax-tree nodes, run with a timer that interrupts a hang, and any failure counts as a rejected proposal and never crashes the loop. This is the thin first layer of defence; for anything adversarial you would add the process and network isolation of sandboxes and permissions.

"""An improver's elasticity: how much held-out gain does each dollar buy?

A small API-driven improver edits one function (the priority rule of online
bin packing, starting from the poor "worst fit" rule), keeps a change only if
it packs the TRAIN instances into fewer bins, and is stopped after 2, 8 and
32 proposals. For each stopping point
we measure the dollars spent and the bins saved on HELD-OUT instances the
loop never saw, then fit gain = a * cost^e and report the elasticity e with
a bootstrap interval over seeds, for the whole range and for each step of it.

Lab VM (needs OPENAI_API_KEY; about 400 calls, well under 1 dollar):
    source ~/.config/lab.env && python3 improver_elasticity.py
No key, no cost (a random-constant stand-in instead of the model; it is
charged a fixed 600 + 250 pretend tokens a call so costs line up):
    python3 improver_elasticity.py --stub
Other sizes, or a looser cap on the length of a proposed function:
    python3 improver_elasticity.py --seeds 4 --budgets 4 16 64
    python3 improver_elasticity.py --max-chars 6000 --cache calls_long.jsonl

Standard library only. Replies are cached in calls.jsonl, so a re-run
replays the same trajectories at no cost."""
import argparse
import ast
import hashlib
import json
import math
import os
import random
import re
import signal
import statistics
import sys
import time
import urllib.error
import urllib.request
from concurrent.futures import ProcessPoolExecutor

# ── 1. Settings ──────────────────────────────────────────────────────────
ap = argparse.ArgumentParser()
ap.add_argument("--model", default="gpt-5.4-nano")
ap.add_argument("--seeds", type=int, default=12)
ap.add_argument("--budgets", type=int, nargs="+", default=[2, 8, 32])
ap.add_argument("--max-chars", type=int, default=2000)  # source cap
ap.add_argument("--stub", action="store_true")      # no API, no cost
ap.add_argument("--cache", default="calls.jsonl")
ap.add_argument("--boot", type=int, default=2000)   # bootstrap resamples
args, _ = ap.parse_known_args()   # notebooks pass their own flags

PRICE_IN = 0.20e-6        # dollars per input token (gpt-5.4-nano list price)
PRICE_OUT = 1.25e-6       # dollars per output token
CAP, ITEMS = 100, 200     # bin capacity; items per instance
N_TRAIN, N_HELD = 10, 30  # instances the loop sees / never sees
SEED_SRC = "def priority(item, rem):\n    return rem - item\n"  # worst fit
ALLOWED = (ast.Module, ast.FunctionDef, ast.arguments, ast.arg, ast.Return,
           ast.Assign, ast.AugAssign, ast.If, ast.IfExp, ast.While,
           ast.BinOp, ast.UnaryOp, ast.BoolOp, ast.Compare, ast.Call,
           ast.Name, ast.Constant, ast.Load, ast.Store, ast.Add, ast.Sub,
           ast.Mult, ast.Div, ast.FloorDiv, ast.Mod, ast.USub, ast.Not,
           ast.And, ast.Or, ast.Lt, ast.LtE, ast.Gt, ast.GtE, ast.Eq,
           ast.NotEq, ast.Break, ast.Pass)
BUILTINS = {"abs": abs, "min": min, "max": max}


# ── 2. The object level: pack items, score a candidate safely ────────────
def instances(seed, kind, n):
    """n instances of ITEMS item sizes in 20..60, fixed by (seed, kind)."""
    rng = random.Random(f"{kind}-{seed}")
    return [[rng.randint(20, 60) for _ in range(ITEMS)] for _ in range(n)]


def pack(items, priority):
    """Bins used when each item goes to the feasible bin of top priority."""
    rems = []
    for it in items:
        best, where = None, None
        for i, r in enumerate(rems):
            if r >= it:
                p = priority(it, r)
                if best is None or p > best:
                    best, where = p, i
        if where is None:
            rems.append(CAP - it)
        else:
            rems[where] -= it
    return len(rems)


def validate(src):
    """Parse src; allow one function, no imports, no attributes."""
    tree = ast.parse(src)
    if len(src) > args.max_chars:
        raise ValueError("too long")
    for node in ast.walk(tree):
        if not isinstance(node, ALLOWED):
            raise ValueError(type(node).__name__ + " is not allowed")
        if isinstance(node, ast.Call) and not (
                isinstance(node.func, ast.Name) and node.func.id in BUILTINS):
            raise ValueError("only abs, min and max may be called")
    fns = [n for n in tree.body if isinstance(n, ast.FunctionDef)]
    if len(fns) != 1 or fns[0].name != "priority" or len(tree.body) != 1:
        raise ValueError("exactly one function, named priority")
    return tree


class Timeout(Exception):
    pass


def _alarm(signum, frame):
    raise Timeout()


def mean_bins(src, insts, seconds=2.0):
    """Mean bins over insts, or None if src is rejected, crashes or hangs."""
    try:
        tree = validate(src)
        space = {"__builtins__": BUILTINS}
        exec(compile(tree, "<candidate>", "exec"), space)
        fn = space["priority"]
        signal.signal(signal.SIGALRM, _alarm)
        signal.setitimer(signal.ITIMER_REAL, seconds)
        try:
            total = sum(pack(items, fn) for items in insts)
        finally:
            signal.setitimer(signal.ITIMER_REAL, 0)
        return total / len(insts)
    except Exception:                    # a candidate never crashes the loop
        return None


# ── 3. The proposer: a model call, cached, with its cost ─────────────────
def prompt_for(src, bins, history):
    tried = "\n".join(f"- {h}" for h in history[-3:]) or "- (none yet)"
    return (
        "You improve a heuristic for online bin packing. Bins hold 100; "
        "items of size 20 to 60 arrive one at a time. Each item goes to "
        "the feasible bin (rem >= item) with the highest priority(item, "
        "rem), where rem is the space left in that bin. Fewer bins is "
        "better.\n\nCurrent function, using "
        f"{bins:.2f} bins per instance on average:\n```python\n{src}```\n"
        f"Recent attempts that did not help:\n{tried}\n\n"
        "Write ONE improved version. Use only arithmetic, comparisons, "
        "if/else, abs, min and max (no ** operator: write 1000000, not "
        "10**6). Reply with the full function in one "
        "```python block and a one-line comment saying what you changed.")


def key_of(seed, step, prompt):
    h = hashlib.sha256(prompt.encode()).hexdigest()[:16]
    return f"{seed}:{step}:{h}"


def load_cache(path):
    cache = {}
    if os.path.exists(path):
        with open(path) as f:
            for line in f:
                row = json.loads(line)
                cache[row["key"]] = row
    return cache


def call_api(prompt):
    """One chat completion; returns (text, tokens in, tokens out)."""
    body = json.dumps({"model": args.model, "messages": [
        {"role": "user", "content": prompt}],
        "max_completion_tokens": 1200}).encode()
    req = urllib.request.Request(
        "https://api.openai.com/v1/chat/completions", body, {
            "Content-Type": "application/json",
            "Authorization": "Bearer " + os.environ["OPENAI_API_KEY"]})
    for attempt in range(6):
        try:
            with urllib.request.urlopen(req, timeout=120) as r:
                data = json.load(r)
            u = data["usage"]
            return (data["choices"][0]["message"]["content"] or "",
                    u["prompt_tokens"], u["completion_tokens"])
        except urllib.error.HTTPError as e:
            if e.code not in (429, 500, 502, 503) or attempt == 5:
                raise
        except (urllib.error.URLError, TimeoutError):
            if attempt == 5:
                raise
        time.sleep(2 ** attempt)


def stub_reply(seed, step, src):
    """No model: nudge a few constants into a fixed template."""
    rng = random.Random(f"stub-{seed}-{step}")
    a, b, c = (round(rng.uniform(-3, 3), 2) for _ in range(3))
    return (f"```python\ndef priority(item, rem):\n    gap = rem - item\n"
            f"    return {a} * gap + {b} * abs(gap - 20) + {c} * rem\n```",
            600, 250)    # fixed pretend tokens: comparable cost axis, $0 spent


def extract(reply):
    m = re.search(r"```(?:python)?\n(.*?)```", reply, re.S)
    return m.group(1) if m else reply


# ── 4. One improver run: keep a change only if the TRAIN score improves ──
def run_seed(seed):
    """One trajectory of max(budgets) proposals. Returns checkpoints."""
    train = instances(seed, "train", N_TRAIN)
    held = instances(seed, "held", N_HELD)
    cache = load_cache(args.cache)
    inc, inc_bins = SEED_SRC, mean_bins(SEED_SRC, train)
    start_held = mean_bins(SEED_SRC, held)
    history, spent = [], 0.0
    out = {"seed": seed, "start_train": inc_bins, "start_held": start_held,
           "points": {}, "errors": 0, "accepts": 0}
    for step in range(1, max(args.budgets) + 1):
        prompt = prompt_for(inc, inc_bins, history)
        key = key_of(seed, step, prompt)
        if key in cache:
            row = cache[key]
        else:
            text, tin, tout = (stub_reply(seed, step, inc) if args.stub
                               else call_api(prompt))
            row = {"key": key, "reply": text, "tin": tin, "tout": tout}
            with open(args.cache, "a") as f:    # append at once: a crash
                f.write(json.dumps(row) + "\n")  # loses no paid reply
        spent += row["tin"] * PRICE_IN + row["tout"] * PRICE_OUT
        cand = extract(row["reply"])
        bins = mean_bins(cand, train)
        if bins is None:
            out["errors"] += 1
            history.append("a version that was rejected or crashed")
        elif bins < inc_bins:
            inc, inc_bins = cand, bins
            out["accepts"] += 1
            history = []
        else:
            history.append(f"a version using {bins:.2f} bins")
        if step in args.budgets:
            out["points"][step] = {
                "cost": spent, "train": inc_bins,
                "held": mean_bins(inc, held)}
    out["final_src"] = inc
    return out


# ── 5. Elasticity: fit gain = a * cost^e, interval by bootstrap ──────────
def slope(xs, ys):
    mx, my = statistics.fmean(xs), statistics.fmean(ys)
    return (sum((x - mx) * (y - my) for x, y in zip(xs, ys))
            / sum((x - mx) ** 2 for x in xs))


def elasticity(runs, budgets):
    """Slope of ln(mean gain) on ln(mean cost) over the budgets, or None."""
    gains = [statistics.fmean(r["start_held"] - r["points"][b]["held"]
                              for r in runs) for b in budgets]
    costs = [statistics.fmean(r["points"][b]["cost"] for r in runs)
             for b in budgets]
    if min(gains) <= 0 or min(costs) <= 0:
        return None
    return slope([math.log(c) for c in costs], [math.log(g) for g in gains])


def report(results):
    B = sorted(args.budgets)
    print(f"{'calls':>5} {'cost $':>8} {'train saved':>12} "
          f"{'held-out saved':>16} {'se':>6}")
    for b in B:
        g = [r["start_held"] - r["points"][b]["held"] for r in results]
        t = [r["start_train"] - r["points"][b]["train"] for r in results]
        c = [r["points"][b]["cost"] for r in results]
        se = statistics.stdev(g) / math.sqrt(len(g))
        print(f"{b:>5} {statistics.fmean(c):>8.4f} "
              f"{statistics.fmean(t):>12.2f} "
              f"{statistics.fmean(g):>16.2f} {se:>6.2f}")
    rng = random.Random(0)
    for label, bs in [("whole range", B)] + [
            (f"{a} to {b} calls", [a, b]) for a, b in zip(B, B[1:])]:
        e = elasticity(results, bs)
        boots, skipped = [], 0
        for _ in range(args.boot):
            v = elasticity([rng.choice(results) for _ in results], bs)
            if v is None:
                skipped += 1
            else:
                boots.append(v)
        boots.sort()
        if e is None or len(boots) < 100:
            print(f"e ({label}): undefined, a mean gain was not above zero")
            continue
        lo, hi = boots[int(0.025 * len(boots))], boots[int(0.975 * len(boots))]
        print(f"e ({label}) = {e:.2f}   95% bootstrap interval "
              f"{lo:.2f} to {hi:.2f}   ({skipped} of {args.boot} skipped)")
    tot = sum(r["points"][max(B)]["cost"] for r in results)
    errs = sum(r["errors"] for r in results)
    acc = sum(r["accepts"] for r in results)
    held = instances(1, "held", N_HELD)
    ref = results[0]["start_held"] - mean_bins(
        "def priority(item, rem):\n    return item - rem\n", held)
    print(f"reference: plain best fit saves {ref:.2f} bins on seed 1's "
          f"held-out set")
    what = "pretend spend (stub)" if args.stub else "total spend"
    print(f"accepts {acc}, rejected or crashed {errs} of "
          f"{len(results) * max(B)} proposals; {what} ${tot:.2f}")


# ── 6. Run all seeds in parallel, then report ────────────────────────────
if __name__ == "__main__":
    if not args.stub and "OPENAI_API_KEY" not in os.environ:
        sys.exit("set OPENAI_API_KEY (source ~/.config/lab.env) or --stub")
    with ProcessPoolExecutor(max_workers=min(args.seeds, 16)) as pool:
        results = list(pool.map(run_seed, range(1, args.seeds + 1)))
    report(results)
    best = max(results, key=lambda r: r["start_held"]
               - r["points"][max(args.budgets)]["held"])
    print(f"\nbest final function (seed {best['seed']}):")
    print(best["final_src"])

What you should see

  • calls and cost. The cost columns are means over 12 seeds. Eight calls cost $0.0036 and 32 cost $0.0196, a ratio of 5.4 for a call ratio of 4: each call gets dearer as the loop goes on. The prompt carries the incumbent's source, which grows as accepted rewrites add code, so this is consistent with the later calls being longer. Your prediction of $0.0185 for 32 calls (700 and 350 tokens) was within about 6 percent of the measured $0.0196; at 2 calls it overshoots, because early prompts are short.
  • train saved and held-out saved. Bins saved per instance relative to worst fit, on the instances the loop searched (train) and on the 30 it never saw (held-out). At 32 calls they are 3.78 and 3.76, so at this scale there is almost no gap between them: ten training instances of 200 items each are enough that the loop is not fitting noise. A larger gap would be the signature of overfitting to the search set, the failure the held-out column exists to catch. Chapter 1's third condition asks for exactly this comparison.
  • se. The standard error of the held-out mean across 12 seeds. At 2 calls it is 0.34, because a few seeds found nothing yet; by 8 calls it is 0.09.
  • reference. Plain best fit saves 3.50 bins on seed 1's held-out set. The loop's mean at 8 calls (3.46) is on the scale of that figure, which says that the model has mostly rediscovered best fit by then. The 32-call mean (3.76) is above it, but the reference is one seed's instances, so read this as "about 0.3 bins beyond best fit", not as a paired comparison.
  • elasticity. Over the whole range ε = 0.08, with a 95 percent bootstrap interval of 0.03 to 0.16: positive but small. Between 2 and 8 calls it is 0.10 and between 8 and 32 calls 0.05. Quadrupling the proposals from 8 to 32 multiplied the cost by 5.4 and the gain by 1.09. These are diminishing returns, as predicted, and the second step is flatter than the first.
  • accepts and rejected. 34 of 384 proposals were accepted. 87 were rejected or crashed (23 percent): the harness could not score them. Common misconception

"A fitted exponent is a property of the model." It is a property of the whole system measured: the model, the prompt, the task, the starting point and every limit in the harness. Start from a worse rule and the early gains are bigger; start from best fit and almost nothing is left to gain; change the length cap and the exponent moves (below). A number like ε = 0.08 describes this loop on this task. It is not a statement about gpt-5.4-nano.

Break it

1. Replace the model with random constants

Predict first: a stand-in with no language model fills a fixed three-parameter template with random numbers (the template contains best fit as one setting). Does gpt-5.4-nano beat it at 2, 8 and 32 proposals?

It does not, at this scale. The stand-in saves 3.76 bins at 8 proposals against the model's 3.46, and 3.79 against 3.76 at 32. Its elasticity from 8 to 32 calls is 0.01, with an interval that includes zero. The stand-in is charged a fixed 600 input and 250 output pretend tokens per call so the cost columns line up; no money is spent. This is a fair-baseline test in miniature (condition 1 of chapter 1), and an uncomfortable one: on this task, a search over a hand-written template with random constants matches the model at the same number of proposals, and costs nothing. The model's advantage, if it has one, is not visible here. A fair reading is that the task is too easy and the template too generous, and a harder task or a template that does not contain the answer would separate them. That is a finding about the experiment, not about the model.

Going from 32 to 128 proposals multiplies the cost by 5.2 ($0.0199 to $0.1041) and moves the held-out gain from 3.76 to 3.93 bins. The elasticity over that step is 0.03, and its interval touches zero (0.00 to 0.06). The 0.17-bin difference is about the size of one standard error of each mean (0.18), so with six seeds I would not claim a gain beyond the noise. One more thing to notice: 335 of 768 proposals were rejected or crashed, because longer runs make longer functions, and many hit the length cap. This is the bottom of a diminishing-returns curve, and it is why a fixed budget is something you choose for the question, not for the loop's convenience.

Key takeaways

  • Elasticity is the slope of ln gain against ln cost. Here it was 0.08 (95 percent interval 0.03 to 0.16): spending 5 times more bought about 9 percent more held-out gain.
  • Report an interval, not a point: seeds, not calls, are the sample, so run enough of them to bootstrap.
  • Gain must be measured on held-out instances, and the train and held-out columns side by side are the cheapest overfitting check.
  • A fair baseline can embarrass the model: random constants over a good template matched gpt-5.4-nano at equal proposals.
  • A harness limit moved the early gains and the exponent. State the limits next to the number.

A loop's held-out gain goes from 3.46 to 3.76 bins when its cost goes from $0.0036 to $0.0196. Which elasticity is closest?

  1. 1.0, because spending and gain both rose
  2. 0.05, because the gain rose by 9 percent while the cost rose by a factor of 5.4
  3. 0.5, because the gain rose by about half a bin
  4. 5.4, because that is the cost ratio
The elasticity is ln(3.76/3.46) divided by ln(0.0196/0.0036): 0.083 over 1.70, about 0.05. Both quantities rose, but what matters is the ratio of their logarithms. Using the absolute change in bins (0.3) or the cost ratio alone ignores that elasticity compares proportional changes.
