The Economics of a Loop

A self-improvement loop is a business with a cost per improvement and a return on each one. This chapter derives cost per accepted improvement, separates returns that fade from returns that compound, and reads two 2026 papers that name the quantity deciding which: a product of elasticities around the loop, and Burtsev's R_AI.

Why this matters

This chapter serves Artifact 4's budget and its ignition test. The artifact is capped at roughly $800 to $1,500 and must be reproducible for under $500, so you need to know what an accepted improvement costs, whether the next one will cost more or less, and what would make it cheaper. It also gives the ignition test its meaning: whether the loop's gains feed back into the loop is the question that separates a loop that fades from one that compounds. After this chapter you can compute cost per accepted improvement from a run log, tell diminishing from compounding returns by how that cost moves, read Burtsev's RAI and the economics paper's product of elasticities, and reproduce a published table from the model that generated it. Workbench 1 measures an elasticity on a real machine; chapter 01 says whether the loop improved at all.

The price of one accepted improvement

An outer loop is a process that buys proposals. Each step costs money (model calls for the proposal, compute for the evaluation) and produces either an accepted improvement, a rewrite that passed the gate, or a rejection. The quantity worth tracking is the cost per accepted improvement: dollars spent so far divided by improvements accepted so far. Two ingredients set it. The acceptance rate p is the share of steps that pass the gate, and the cost per step c is what each step costs. In steady state the cost per accepted improvement is c / p. Weco's post reports seven successive improved versions in 100 steps, so its observed acceptance rate was about 7 in 100 and each improvement took about 14 steps. Weco does not give a dollar cost per step in the post I read, so any dollar figure below is an assumption of mine.

This framing makes two questions answerable. If Artifact 4 costs $3,000 to reach a target, is that because steps are expensive (c is large) or because few steps pass (p is small)? The first is fixed by model choice and evaluation design; the second depends on how good the proposer is and how hard the problem has become. A log with a ledger from chapter 01 and a column for accept or reject is enough to compute both.

Returns that fade

Imagine a loop that improves an agent from a starting quality of 0 toward a ceiling of 1. Early on, easy wins are everywhere: a bad prompt, a missing retry, a crash. Later, the easy wins are gone. Two things then get worse together. The chance that a proposal helps falls, and the size of a help when it comes shrinks. Call the product of the two the frontier hardness effect: progress per step shrinks as capability rises. A model with this property is ẋ = r (1 − x)β, in which progress per unit time falls as x approaches 1. The script below is an expected-value version: the chance of acceptance is P0 × (1 − x)2, each acceptance adds 0.02 × (1 − x)2, and each step costs $4. All numbers are illustrative assumptions.

"""Cost per accepted improvement, with and without feedback.

Expected-value model, all numbers illustrative.

Run: python3 cost_per_accept.py
"""
import math

# ── 1. Assumptions ───────────────────────────────────────────────────────
DOLLARS_PER_STEP = 4.0   # one proposal plus its evaluations
P0 = 0.15                # chance a step is accepted when x = 0
GAIN = 0.02              # progress made by one accepted step when x = 0
BETA = 2                 # how fast good edits get scarcer: (1 - x)^BETA


def accept_prob(x, feedback):
    """Chance a step is accepted; feedback lets better agents propose better."""
    return min(1.0, P0 * (1 - x) ** BETA * math.exp(feedback * x))


def run(feedback, target=0.5):
    x, steps, accepts = 0.0, 0, 0.0
    marks = {0.1: None, 0.3: None, 0.5: None}
    while x < target and steps < 20000:
        p = accept_prob(x, feedback)
        x += p * GAIN * (1 - x) ** BETA      # expected gain of one step
        accepts += p
        steps += 1
        for m in marks:
            if marks[m] is None and x >= m:
                marks[m] = (steps, accepts)
    return marks


# ── 2. Dollars per accepted improvement as the loop climbs ───────────────
for feedback in (0.0, 6.0):
    print(f"feedback strength {feedback:g}")
    for level, (steps, accepts) in run(feedback).items():
        spent = steps * DOLLARS_PER_STEP
        print(f"  reach x={level}: {steps:>5} steps, ${spent:>8,.0f} total, "
              f"${spent / accepts:>6.1f} per accept so far")

  reach x=0.1:    42 steps, $     168 total, $  29.7 per accept so far
  reach x=0.3:   213 steps, $     852 total, $  39.7 per accept so far
  reach x=0.5:   777 steps, $   3,108 total, $  62.2 per accept so far
feedback strength 6
  reach x=0.1:    31 steps, $     124 total, $  22.0 per accept so far
  reach x=0.3:    81 steps, $     324 total, $  14.9 per accept so far
  reach x=0.5:   128 steps, $     512 total, $  10.3 per accept so far

With feedback strength 0, the first 0.1 of progress costs $168 and $29.7 per acceptance so far. The next 0.2 takes the average to $39.7, and by x = 0.5 the loop has spent $3,108 and the average has doubled to $62.2. Each further improvement costs more than the last, and this is what diminishing returns looks like in a log: a cost per accepted improvement that drifts upward even though nothing about the loop's price per step changed. The standard remedy is to switch to a harder-to-reach, larger-gain kind of edit (a new search policy rather than a prompt tweak), which restarts the curve, or to stop.

Returns that compound

The second block of output has the same loop with a feedback term. The better the agent has become, the better it is at proposing edits, so the acceptance probability is multiplied by e6x. Now the first 0.1 costs $124 and $22.0 per accept. By x = 0.3 the average is $14.9, and by x = 0.5 the loop has reached its target after 128 steps and $512, at $10.3 per accept so far. The same loop and the same price per step, and the cost per accepted improvement falls.

The sign of the trend in cost per accepted improvement is the empirical test of compounding versus fading, and it is what Weco's Level 3, inflection, asks for: "the gain each generation buys, at a fixed budget, grows instead of shrinking."

Analogy: a mine and its drill

A mine yields ore of falling grade as it deepens, so each tonne costs more. That is diminishing returns. Now suppose some of the ore is used to build a better drill. If the better drill lowers the cost of the next tonne by more than the falling grade raises it, the cost per tonne falls over time. Whether the mine fades or compounds depends on how strongly drill quality depends on ore, and how strongly ore output depends on drill quality, not on how rich the mine is.

Where it breaks down: a drill is a physical object that is used up in the improvement; a rewritten agent can be copied at almost no cost. But a rewritten agent also has to survive the gate, and the delay between making a better drill and getting its benefit is real, which is a point Burtsev's model puts at its centre.

The two blocks use one formula for the loop and differ only in the feedback strength, so which regime you are in is a number you can estimate. That number is what the two 2026 papers below try to pin down.

Burtsev's RAI: a threshold for amplification

On 31 August 2026 Mikhail Burtsev posted "Recursive Criticality of AI Self-Improvement" (arXiv 2609.00137). It borrows an idea from epidemiology. In a disease model, the basic reproduction number R0 says how many new cases one case causes. If it is above 1 the outbreak grows and if below 1 it dies. Burtsev defines a recursive reproduction number, RAI, for AI improvement: how many units of improvement one unit of improvement produces by feeding back into research. Above 1, improvements compound; below 1, they fade. The paper states that the threshold depends on the structure of the feedback loop, not on any particular capability level, so a system can enter a self-amplifying regime before the acceleration is visible. I fetched the paper's HTML page; the equations below are quoted from it.

The model describes capability growth as

dx/dt = r(t) f[x(t)] eΦ(x[t−τ(t)], t)

where x(t) is capability (the paper measures it as a resource-adjusted improvement), r is a baseline research-productivity scale from outside the loop, f(x) is the productivity of direct improvement as the frontier advances, Φ is a feedback potential, and τ is the delay between a capability gain and its return as research productivity. So the speed of progress is the baseline, times how easy direct progress still is, times an exponential boost from feedback. The three ideas in RAI follow from this.

Plug in numbers. The paper's worked example fixes f(x) = (1 − x/X)β, which gives σ(x) = β / (X − x), and a logistic closure χ(x) = 1 / (1 + e−kx). The script prints each build-up step at x = 0.3 with a = 3, then RAI across x for four values of a. I chose x = 0.3 and a = 3 for the first block; that RAI lands within a thousandth of 1 is a coincidence of those two numbers, which is useful.

The idea

  1. chi ← how much of the feedback reaches successors, 0 to 1
  2. g ← chi times a, the feedback that returns
  3. sigma ← beta / (X − x), how hard the frontier has become
  4. RAI ← g divided by sigma; compare with 1
"""Burtsev's R_AI = chi * a / sigma, one build-up step per printed line.

Reference shapes from the paper's worked example: f(x) = (1 - x/X)^beta, so
sigma(x) = beta / (X - x), and chi(x) = 1 / (1 + exp(-k x)).

Run: python3 r_ai.py
"""
import math

# ── 1. Reference parameters ──────────────────────────────────────────────
X, BETA, K = 1.0, 2.0, 10.0


def chi(x):
    """Operational closure: share of the gain that reaches successors."""
    return 1 / (1 + math.exp(-K * x))


def sigma(x):
    """Frontier hardness: how fast direct progress gets harder."""
    return BETA / (X - x)


# ── 2. The build-up at one point: x = 0.3, a = 3 ─────────────────────────
x, a = 0.3, 3.0
g = chi(x) * a
print(f"1. chi({x})            = {chi(x):.3f}")
print(f"2. g = chi * a          = {g:.3f}")
print(f"3. sigma({x})          = {sigma(x):.3f}")

Why RAI = 1 is the line

Go deeper optional: why speed turns exactly where R_AI crosses 1

Ignore the delay (τ = 0) for a moment. Then the speed is ẋ = r f(x) eΦ(x), so ln ẋ = ln r + ln f(x) + Φ(x). Differentiate with respect to x: d ln ẋ / dx = f′/f + Φ′ = −σ + g, because σ is defined as −d ln f / dx and Φ′ = g. So the speed of progress is rising with capability exactly when g > σ, which is RAI > 1, and falling when RAI < 1. The script below checks this on a fine grid: it finds the points where the speed turns around and prints RAI there.

"""Where does research speed peak?  Check that R_AI = 1 marks the peak.

No delay, so dx/dt = r (1 - x)^2 exp(Phi(x)) with Phi' = a * chi(x).
Then d ln(speed)/dx = g - sigma, so speed rises while R_AI = g / sigma > 1.

Run: python3 speed_peak.py
"""
import math

# ── 1. Same reference shapes as r_ai.py ──────────────────────────────────
R, K = 1 / 24, 10.0


def chi(x):
    return 1 / (1 + math.exp(-K * x))


def speed(x, a):
    """dx/dt at capability x for recursive gain a."""
    phi = a * (math.log1p(math.exp(K * x)) - math.log(2)) / K
    return R * (1 - x) ** 2 * math.exp(phi)


def r_ai(x, a):
    return a * chi(x) * (1 - x) / 2          # sigma = beta/(1-x), beta = 2


# ── 2. Find turning points of speed on a fine grid, and R_AI there ───────
grid = [i / 1000 for i in range(0, 990)]
for a in (0.5, 3.0, 6.0):
    ys = [speed(x, a) for x in grid]
    for i in range(1, len(grid) - 1):
        kind = None
        if ys[i] > ys[i - 1] and ys[i] >= ys[i + 1]:
            kind = "speed peaks"
        if ys[i] < ys[i - 1] and ys[i] <= ys[i + 1]:
            kind = "speed dips "
        if kind:
            print(f"a={a:<4} {kind} at x={grid[i]:.3f}  "
                  f"({ys[i] / R:.2f} x baseline)  "
                  f"R_AI there = {r_ai(grid[i], a):.3f}")
    print(f"a={a:<4} speed at x=0 is 1.00 x baseline, at x=0.9 "
          f"{speed(0.9, a) / R:.2f} x baseline")

a=3.0  speed dips  at x=0.109  (0.98 x baseline)  R_AI there = 1.000

For a = 3 the speed dips at x = 0.109 and peaks at 0.300, and RAI is 1.000 at both. Between them RAI is above 1, so speed rises, but it rises from a value 2% below the baseline to 1% below it: the "weak supercritical" loop never beats having no feedback at all. For a = 6 the speed peaks at x = 0.666 at four times baseline, with RAI = 1.001 there. With the delay the picture gets more complicated, and the paper linearises around a reference trajectory to find that the dominant growth rate near criticality is roughly vσ(RAI − 1) / (1 + vσRAIτ): the delay slows the build-up of any amplification.

Common misconception

"RAI above 1 means an intelligence explosion." The paper itself says a supercritical regime means local perturbations amplify, but total capability need not grow without bound. Rising research difficulty can end a self-amplifying period, which the plot above shows: every curve falls back toward zero as x nears the ceiling. Weco's post is similarly modest about its own system: "we believe we are not near an intelligence explosion with the current system."

Reproducing the paper's table

A model is only worth trusting if you can run it. Burtsev's Table 1 lists the years to cross two capability thresholds, which the paper labels AGI (x = 0.5) and ASI (x = 0.8), for five feedback strengths, under reference parameters X = 1, β = 2, k = 10, τ = 0.5 years and a baseline calibrated so that the no-feedback loop crosses x = 0.5 in 24 years (r = 1/24 per year, with t = 0 at 2026). The paper presents the table as conditional on its parameters, not as a forecast. The script below integrates the growth equation with Euler steps of 0.001 years, using a ring buffer for the delay, and prints my result next to the paper's.

"""Time to cross two capability levels, with and without feedback.

Model from Burtsev (arXiv 2609.00137, as read from the paper's HTML page):
    dx/dt = r (1 - x)^2 exp( Phi( x(t - tau) ) ),   Phi' = a * chi(x),
    chi(x) = 1 / (1 + exp(-k x)).
We integrate it ourselves with Euler steps; the paper's Table 1 is the check.

Run: python3 takeoff.py
"""
import math

# ── 1. Reference parameters from the paper ───────────────────────────────
R = 1 / 24             # baseline research productivity, per year
K = 10.0               # steepness of the closure curve chi
TAU = 0.5              # delay in years between a gain and its feedback
X_AGI, X_ASI = 0.5, 0.8
DT = 0.001             # Euler step, years


def phi(x, a):
    """Integral of a * chi from 0 to x, in closed form."""
    return a * (math.log1p(math.exp(K * x)) - math.log(2)) / K


def crossing_times(a, t_max=150.0):
    """Years until x first reaches X_AGI and X_ASI."""
    lag = int(TAU / DT)
    history = [0.0] * (lag + 1)        # x one delay ago, ring buffer
    x, t, hit = 0.0, 0.0, {}
    i = 0
    while t < t_max and len(hit) < 2:
        x_delayed = history[i % (lag + 1)]
        history[i % (lag + 1)] = x
        x += DT * R * (1 - x) ** 2 * math.exp(phi(x_delayed, a))
        t += DT
        i += 1
        for name, level in (("AGI", X_AGI), ("ASI", X_ASI)):
            if name not in hit and x >= level:
                hit[name] = t
    return hit.get("AGI"), hit.get("ASI")


# ── 2. Same five feedback strengths as the paper's Table 1 ───────────────
print(f"{'a':>5} {'T_AGI':>8} {'T_ASI':>8}   paper: T_AGI  T_ASI")
PAPER = {0: (24.00, 96.00), 0.5: (21.35, 74.13), 3: (12.90, 24.73),
         6: (8.40, 11.08), 15: (4.50, 4.95)}
for a, (p_agi, p_asi) in PAPER.items():
    agi, asi = crossing_times(a)
    print(f"{a:>5} {agi:>8.2f} {asi:>8.2f}   {p_agi:>12.2f} {p_asi:>6.2f}")
    a    T_AGI    T_ASI   paper: T_AGI  T_ASI
    0    24.00    96.00          24.00  96.00
  0.5    21.35    74.13          21.35  74.13
    3    12.90    24.73          12.90  24.73
    6     8.40    11.09           8.40  11.08
   15     4.51     4.96           4.50   4.95

My integration matches the paper's table to the printed precision for a = 0, 0.5 and 3, and to within 0.01 years for the other two (8.40 against 8.40, 11.09 against 11.08, 4.51 against 4.50), which is the size of an Euler step error. For the no-feedback row the closed form x(t) = rt / (1 + rt) gives x = 0.5 at t = 24 and x = 0.8 at t = 96 exactly. I did not need the authors' code: the equation in the paper and its reference parameters were enough, and that is the standard to hold a model paper to. The names the paper gives its scenarios are "smooth scaling" (a = 0.5), "weak supercritical" (a = 3), "transient takeoff" (a = 6) and "rapid transition" (a = 15). Under a = 3 the time between the two thresholds shrinks from 72 years to under 12, even though RAI exceeds 1 for only part of the path.

State of play, October 2026: what Burtsev's paper does and does not say

Burtsev's paper was submitted on 31 August 2026 as a single-author preprint (arXiv 2609.00137, cs.AI). I read its abstract page and the HTML text. Its numbers are outputs of chosen parameters, not estimates of the real world, and I found no independent evaluation. The paper proposes measurable properties (feedback strength, propagation into successor systems, cycle duration and difficulty growth) for distinguishing recursive amplification from rapid progress with other causes. It also finds that sharing improvements across organisations can make the wider research ecosystem self-amplifying even when no single actor is, with the criterion becoming the spectral radius of a matrix of gains. The abstract page and the HTML text differ in one place: a sentence in the body says effects weaken when RAI exceeds 1, whereas the paper's stability analysis and abstract say they weaken below 1. I have followed the stability analysis, which also matches the derivation above.

Loop elasticities from the economics paper

A second paper approaches the same question as an economist would. "The Economics of Recursive Self-Improvement" (Cunningham, Althoff, Halperin, Jabarian, Koh, Ramani, Trammell, Whitfill and Wu, arXiv 2609.15802, submitted 14 September 2026) models AI progress as a directed graph. Each node is the output of a production function (algorithmic efficiency is produced from human labour and AI capability; capability is produced from algorithmic efficiency and training compute) and each edge is the elasticity of an output with respect to an input: the percentage change in the output when the input changes by one percent. Its central result, in the abstract's words, is that "net acceleration in AI capabilities depends on the product of elasticities across each feedback loop".

The intuition is a chain of multipliers. Suppose a 1% rise in capability raises research productivity by e1% (the first edge), and a 1% rise in research productivity raises the next system's capability by e2% (the second edge). Going once round the loop turns a 1% gain into e1 × e2 percent. If that product is below 1, each round returns less than it started with and the gains die away; at 1 they repeat at a constant rate; above 1 they grow. The paper's models are richer, with bottlenecks and an economic loop in which output funds more compute and data. The script below is a stylised illustration of the product idea only, built on my own two-edge loop, and is not the equation of the paper.

"""A loop whose elasticities multiply: one cycle at a time.

A stylised illustration of the idea that net acceleration depends on the
PRODUCT of elasticities around a feedback loop.  It is not the equation of
any paper.  Run: python3 elasticity.py
"""
import math

# ── 1. Two edges in one loop ─────────────────────────────────────────────
# capability C raises research productivity P:   P = C ** E1
# productivity P raises next-cycle capability:   C_next = BASE * P ** E2
BASE = 1.2          # capability multiple a cycle gives with no feedback
CYCLES = 8


def trajectory(e1, e2):
    c, out = 1.0, []
    for _ in range(CYCLES):
        p = c ** e1
        c = BASE * p ** e2
        out.append(c)
    return out


# ── 2. The same loop with different elasticity products ──────────────────
print(f"{'E1':>4} {'E2':>4} {'E1*E2':>6}   capability after cycles 1, 4, 8")
for e1, e2 in ((0.6, 1.0), (0.8, 1.0), (1.0, 1.0), (1.2, 1.0)):
    t = trajectory(e1, e2)
    print(f"{e1:>4} {e2:>4} {e1 * e2:>6.2f}   "
          f"{t[0]:>7.2f} {t[3]:>9.2f} {t[7]:>12.2f}")

# ── 3. Growth of log-capability per cycle: shrinking, steady or rising ───
for k in (0.6, 1.0, 1.2):
    t = [1.0] + trajectory(k, 1.0)
    steps = [math.log(b) - math.log(a) for a, b in zip(t, t[1:])]
    print(f"product {k}: log-gain in cycles 1, 4, 8 = "
          f"{steps[0]:.3f}, {steps[3]:.3f}, {steps[7]:.3f}")
  E1   E2  E1*E2   capability after cycles 1, 4, 8
 0.6  1.0   0.60      1.20      1.49         1.57
 0.8  1.0   0.80      1.20      1.71         2.14
 1.0  1.0   1.00      1.20      2.07         4.30
 1.2  1.0   1.20      1.20      2.66        20.25

With a product of 0.60 the capability multiple creeps from 1.20 after one cycle to 1.57 after eight, and the log-gain per cycle falls from 0.182 to 0.005. At exactly 1.00 the log-gain is 0.182 every cycle: steady exponential growth. At 1.20 it rises each cycle (0.182, 0.315, 0.653) and capability reaches 20 times the start after eight cycles. The threshold sits at a product of one, as RAI sits at one: the two papers describe the same boundary from different directions.

Step through

Going once round a loop of two elasticities

  1. Two quantities. The loop connects a system's capability to the productivity of the research that builds its successor.
  2. First edge. An elasticity of 0.8 means a 1% rise in capability buys a 0.8% rise in research productivity.
  3. Second edge. An elasticity of 0.9 means a 1% rise in productivity buys a 0.9% rise in the next system's capability.
  4. Multiply. Going once round turns a 1% gain into 0.8 × 0.9 = 0.72%. The numbers are illustrative.
  5. Compare with one. 0.72 is below 1, so each round returns less than the one before and the loop fades. A product of 1 repeats the gain; above 1 it compounds.

State of play, October 2026: the economics paper's calibration

Cunningham et al. (arXiv 2609.15802, submitted 14 September 2026) report that, in their calibration, self-sustaining acceleration needs a one-unit increase in model capability (measured with the Epoch Capabilities Index) to raise AI research-and-development productivity by at least 15%. A rough back-of-the-envelope estimate based on reported AI-engineer uplift gives about 9% since coding agents launched. They conclude that feedback loops are "not currently strong enough" to generate self-sustaining acceleration, though they appear to be strengthening, and that political and regulatory constraints could slow deployment even if the technical conditions were met. These are the authors' estimates from reported figures, not measurements, and the 9% rests on self-reported uplift. I read the paper's HTML summary, which does not list the individual elasticity estimates or their sources; I did not read the technical boxes. The paper also lists measurements AI companies could share, and names three of the biggest unknowns: the growth rate of algorithmic efficiency in labs, the share of lab spending going to each input (people, data, experiment compute, inference for research), and direct measures of how much of the technical advances models produce.

If 15% marks the threshold and 9% is the estimate, then 9 / 15 = 0.6 is one way to read the distance: about 60% of the way to critical, if the effect scales in proportion. That is my arithmetic on the paper's two numbers, not a claim the paper makes, and it would be wrong if the relationship is not proportional. The product-of-0.6 row of the script above is what such a loop would look like.

What to measure in Artifact 4

The theory gives the artifact three measurements it can take at small scale, each from the run log.

  1. Acceptance rate against step number. Plot the share of steps accepted in windows of 20. A falling line is frontier hardness. Compare it with a hand-tuned baseline given the same steps (the fair baseline of chapter 01), because a baseline's acceptance rate falls as well.
  2. Gain per accepted step against step number. The same logic for size: do the later gains shrink?
  3. Cost per accepted improvement. Compute it from the ledger at every accept. A line that bends down means compounding; a line that bends up means fading. Report the dollars with the three seeds' spread.

The ignition test measures something close to the closure χ of Burtsev's model: how much of the improvement the loop found passes into the next version of the improver. A discovered agent that is no better as an improver than the one you started with has closure near zero for that loop, however good it is at the inner task. That is a reading of the two framings side by side, and it is an interpretation, not a result of either paper. Workbench 1 measures an improver's elasticity directly on the lab machine.

Systems connection

RAI is the loop gain of a feedback system. In control engineering, a loop with gain below 1 settles and a loop with gain above 1 oscillates or runs away; a delay in the loop lowers the gain at which it becomes unstable. The same arithmetic explains a retry storm: if each failed request triggers more than one retry, the load grows, and if it triggers fewer than one, the storm dies out.

Key takeaways

  • Cost per accepted improvement is c / p; read its trend in the log: rising means diminishing returns, falling means compounding.
  • Burtsev's RAI = χa / σ compares the feedback that returns with the headwind of a hardening frontier; above 1 progress speeds up with capability, and the turning points of speed sit exactly where it crosses 1.
  • I reproduced Burtsev's Table 1 from the paper's equation to the printed precision, give or take an Euler step.
  • The economics paper puts the threshold as a product of elasticities around each loop reaching 1, and estimates (rough, self-reported inputs) about 9% against a 15% threshold as of September 2026.
  • Both papers describe a regime that may begin before it is visible; neither says the world is there now.
  • In Artifact 4, report acceptance rate, gain per accept and cost per accept against step, and read the ignition test as a measure of closure.

With c fixed, a rising c / p means p is falling, which is frontier hardness. Compounding would show the opposite. The ledger could be wrong, but nothing in the description suggests it, and the baseline does not enter the cost of the loop.

In Burtsev's RAI = χa / σ, which change makes a loop more likely to be supercritical?

  1. A larger σ, because it means more progress is being made
  2. A smaller χ, because less feedback is easier to manage
  3. A longer delay τ, because it adds to the numerator
  4. A larger recursive gain a, or a larger share χ of it reaching successors
The numerator is the feedback that returns, so raising a or χ raises RAI. σ is the headwind in the denominator, so a larger one lowers it. The delay does not appear in RAI itself; it slows how fast amplification builds.

  4. The delay cancels the feedback
Speed turns down while RAI is below 1, up while it is above, and back down: for a = 3 the speed dips to 0.98 and peaks at 0.99 of baseline, which is a weak supercritical loop. The delay is not what causes this; the same turning points appear with no delay.
