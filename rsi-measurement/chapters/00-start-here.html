Artifact 4 asks you to claim that a loop improved itself, and then to defend the claim against the four tests a sceptical reader will apply. This page states the gate, the standards every artifact is held to, and which chapters of other courses to read first.

Why this matters

This course is the measurement behind Artifact 4, AIDE²-in-miniature, the capstone of the artifact track. Artifacts 1 to 3 each produce a number a researcher could cite. Artifact 4 asks whether a loop that improves an agent is really improving, and the answer is only worth publishing if the test is one a sceptic cannot dismiss. After this page you know what the artifact must deliver, the standards that every artifact (not only this one) is held to, which chapters to read before you start, and how the six chapters of this course map onto the build. After the course you can design the evaluation of a self-improving loop, run it, and write down honestly what it did and did not show.

The artifact in one paragraph

Artifact 4 replicates, at small scale, a 2026 result from Weco, a company that builds AI research agents. Weco's AIDE² system is an outer loop: an agent that rewrites another agent's code, tests the rewrite, and keeps it if it scores better on a hidden test. In your version, the outer agent rewrites the agent you built for Artifact 2 (the study of AIDE-style tree search, where AIDE is the "AI-driven exploration" code-search agent, covered in the A10 course). Your agent is scored on a mix of six tasks: three from FML-Bench (a benchmark of machine-learning research tasks), two autoresearch configurations from Artifact 1, and one KernelBench pair from Artifact 3. Scores come from private splits under a fixed dollar budget. The extension is to apply the four Level-1 conditions to your own loop, then run an ignition test: swap the discovered agent into the outer loop's seat and report whether it is a better improver than the one you started with.

The standards every artifact must meet

An artifact that fails any of these is not finished, because a reviewer will check exactly these points first. The first group applies to every claim of improvement; chapter 01 turns it into four tests.

Weco's four Level-1 conditions

A fair baseline with the same budget and attempts. A sustained trend, not one lucky accept. Scores on tasks the loop never saw. A fixed physical budget stated up front and never exceeded.

Evaluator hygiene

The evaluator lives outside the agent's write boundary. Public and private splits, and only private scores decide what is kept. Typed and attested tool results. Hacking rate reported next to every score.

Statistics

Three seeds at least. Means with confidence intervals and a paired test against the baseline. Report negative results.

The second group comes from Artifact 3 (the evaluator-hardening kit) and is why this course assumes you have read A10 chapter 03 and A11 chapter 00. A loop that rewrites itself is the strongest optimiser you will point at your own evaluator, so the evaluator has to be one that the loop cannot edit.

The write-up

Every artifact ships as code plus a write-up of two to six pages in the same shape, so a reviewer learns to read you fast: one sentence with the claim, its number and its budget; what was replicated, with your figure beside the original paper's; the extension as hypothesis, design and result; negative results and what you would try next; the hacking rate, seeds, cost and hardware; and a one-command reproduction. The write-up is the README, and raw logs live in a results/ folder. A9 chapter 06 teaches the format. For Artifact 4 the claim sentence will read something like: "On six tasks with private splits and a $X budget, the outer loop's discovered agent beat a hand-tuned baseline by Y points (95% interval Z) and failed to show ignition." Whether it passes or fails the tests is the finding.

Check your understanding

Which of these is part of the gate for Artifact 4?

  1. A leaderboard rank on MLE-Bench Lite
  2. A result someone else can reproduce for under $500
  3. An outer loop that has run for at least a month
  4. A paper accepted at a conference
The gate is a paper-style write-up with ablations and negative results, released code, and a result reproducible for under $500. A ranking, run length or acceptance is not asked for; the gate is a public result you control.

Why does Artifact 4 depend on the evaluator-hygiene rules from Artifact 3?

  1. Because the outer loop needs more compute than Artifact 3 provides
  2. Because the baseline must be written in Rust
  3. Because FML-Bench has no public split
  4. Because a loop that rewrites itself will search for any loophole in its scorer, so the scorer must sit outside what it can edit
A self-rewriting loop is the strongest optimiser pointed at your evaluator. The hygiene rules (outside the write boundary, private splits, attested results) keep the score meaningful. The other options are not reasons given anywhere in the artifact's definition.

The ignition test, as the artifact uses it, compares:

  1. The discovered agent in the outer loop's seat against the original outer agent, on how well each improves agents
  2. The discovered agent against a human baseline on the six tasks
  3. The public score against the private score of the discovered agent
  4. Three seeds against one seed
Ignition asks whether a successor is a better improver, so the swap happens in the outer seat. Comparing with a human baseline on the tasks is the Level-1 check, and comparing public with private scores belongs to the generalisation condition.

You finish the run and the discovered agent is not a better improver than the one you started with. What should the write-up do?

  1. Rerun until it is, then report that run
  2. Drop the ignition test and report only Level 1
  3. Report it as a negative result with the numbers and what you would try next
  4. Wait for a stronger model before publishing
The template has a section for negative results, and the gate asks for them. Rerunning until success is selection at a higher level, and Weco's own post reports that ignition was not demonstrated.
