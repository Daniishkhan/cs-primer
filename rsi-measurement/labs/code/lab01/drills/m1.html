A checker that trusts its input is a rubber stamp, so it reads a run log (one record per line: a header stating the budget up front, then one line per attempt, then report-time measurements) strictly. A line that cannot be used stops the checker, because a skipped line is a missing attempt that may hide a cost or a rejected proposal.

parse_log(text) returns the Run objects in header order, with steps and evals filled in, or raises LogError whose message starts line N:. Count lines from 1, blank ones included (they are skipped), so N matches an editor. A run line is the header and must come first for its run_id, the name its later lines carry. A step or eval line before it means the log was written after the fact, and a header lacking any key of HEADER_KEYS is refused too.

line 1 header, line 2 blank, line 3 {"type": "stp", "run_id": "a"}
-> LogError: line 3: unknown type
