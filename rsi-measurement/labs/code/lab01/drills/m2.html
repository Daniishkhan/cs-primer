A claim of improvement is a comparison, and it means something only if the baseline it beats had the same resources and really used them. The best of many noisy tries beats a single try even when no idea helps, so a short-changed baseline loses to the number of tries, not to the idea.

fair_baseline(improver, baseline) compares the loop under test with its baseline and returns a Verdict(passed, reason), checking in the docstring's order and stopping at the first failure. Fairness comes from what the two headers declare, with no judgement; the 80 percent rule catches a baseline that stopped early and so was not tried as hard. Only then must the improver's mean final score beat the baseline's. Use the given task_means(run, "final"), which averages the seeds inside each task, then average over tasks. A tie is not a win.
