The Glue: ARP, DHCP & ICMP

Three tiny helper protocols quietly fix the gaps between everything you've learned so far: how to find a MAC address from an IP address, how a laptop gets an IP address at all, and how the network reports problems. You use all three every time you join Wi-Fi.

Why this matters

Chapters 2 to 5 left some loose ends. Ethernet needs a MAC address, but IP gives us an IP address. A laptop needs an IP address before it can talk to anyone, but who gives it one? And when a packet is dropped, how would anyone know? These helpers answer those questions, and they show up constantly when you debug a network ("why can't I get an IP?", "why does ping say unreachable?").

ARP: from an IP address to a MAC address

Recall from chapter 3 that each hop uses a frame addressed to a MAC address, while the packet inside carries IP addresses. Your laptop wants to send a packet to its default gateway, 192.168.1.1 (chapter 5). It knows the IP address. But the Ethernet or Wi-Fi frame needs the gateway's MAC address, and nobody told the laptop what it is.

The solution is the Address Resolution Protocol (ARP). The laptop simply asks everyone on the local network:

The request is a broadcast: a frame sent to the special MAC address ff:ff:ff:ff:ff:ff, which every device on the local network accepts. Everyone reads it, but only the device that owns 192.168.1.1 replies, directly to the asker. The laptop stores the answer in its ARP cache (a small table of IP-to-MAC pairs that expires after a few minutes) so it doesn't have to ask for every packet.

Two things worth knowing. First, ARP only works within one local network, since broadcasts don't cross routers; this is exactly why a host only ever ARPs for the next hop (the gateway for anything off-LAN), never for a faraway server. Second, ARP has no security: any device can claim any IP address, and others will usually believe it. (IPv6 replaces ARP with a similar mechanism called NDP.)

Analogy: shouting in a room

You walk into a crowded room knowing you need to hand a note to "Sam, flat 4B". You don't know what Sam looks like. So you call out "Who is Sam?" and Sam waves back. You remember where Sam stands, so next time you walk straight over.

Where it breaks down: in real ARP nobody checks that the person waving is really Sam, and the "room" is limited to one local network.

DHCP: how you get an IP address in the first place

Before any of the above can work, your laptop needs an IP address, a subnet mask, a default gateway and the address of a DNS server (chapter 9). You didn't type any of them in when you joined the coffee-shop Wi-Fi. They were handed to you by the Dynamic Host Configuration Protocol (DHCP). Why four messages instead of two? Because there can be more than one DHCP server on a network. The client may get several offers, and the Request message announces which one it accepted so the others can take back their unused offers.

The address is not given away forever; it's leased. The ACK includes a lease time (say, 24 hours). Halfway through, the laptop quietly asks the server to renew. If a device leaves and never renews (you walked out of the café), the lease eventually expires and the address goes back in the pool for someone else. This is why a pool of 200 addresses can serve thousands of visitors over a day. If DHCP fails entirely, most systems fall back to a self-assigned 169.254.x.x address, which only works on the local link. If you ever see one of those, think "DHCP didn't answer".

Common misconception: "my IP address is mine"

For most devices, an IP address is a short-term loan from whoever runs the local network. It can change when you reconnect (and your public address, the one the wider Internet sees after NAT, is a loan from your ISP). Servers that need a fixed address are given a static one or a DHCP reservation.

ICMP: the network's messenger

IP just delivers packets on a best-effort basis, and it has no way to say "I couldn't deliver that". The Internet Control Message Protocol (ICMP) is IP's companion for exactly that: small messages carried directly inside IP packets (so no port numbers) that report errors and answer diagnostic questions. Three kinds matter most:

ICMP messageMeaningWhere you meet it
Echo request / echo reply"Are you there?" / "Yes."ping (you saw it in chapter 0)
Destination unreachable"I couldn't deliver this": no route to that network, the host didn't answer, the port is closed, or the packet was too big and not allowed to be fragmentedErrors like "Network is unreachable" or "Destination host unreachable"
Time exceeded"This packet's TTL hit 0 here."traceroute (chapter 5)

Notice that ICMP is how routers tell you something went wrong, but it's not a guarantee: many networks rate-limit or block ICMP for security reasons, so silence from a ping does not prove a host is down. And since a lost ICMP message is not retransmitted, it is a hint, never a promise.

How the glue fits together

Follow a freshly arrived laptop opening a website. DHCP gives it an address, a gateway and a DNS server. It sees the destination isn't on its LAN (chapter 4), so it uses the default route (chapter 5); ARP finds the gateway's MAC; the frame goes out; and at every hop ICMP is the way routers report trouble. None of these protocols carries your data, but without them your data would never leave the house.

Try it yourself

Look at your ARP cache and your DHCP lease

These are read-only, safe commands. arp -a works on macOS, Linux and Windows. For the DHCP lease, use ipconfig getpacket en0 on macOS (replace en0 with your Wi-Fi interface if different), or ipconfig /all on Windows (look for "DHCP Server" and "Lease Obtained"). On Linux, try nmcli device show or look in /var/lib/dhcp/.

$ arp -a
? (192.168.1.1) at a4:83:e7:aa:bb:cc on en0 ifscope [ethernet]
? (192.168.1.34) at 3c:22:fb:12:34:56 on en0 ifscope [ethernet]
? (192.168.1.255) at ff:ff:ff:ff:ff:ff on en0 ifscope [ethernet]     # broadcast address

$ ipconfig getpacket en0
op = BOOTREPLY
yiaddr = 192.168.1.20                          # "your" address: the one you were offered
siaddr = 192.168.1.1
options:
dhcp_message_type (uint8): ACK 0x5            # the A in DORA
server_identifier (ip): 192.168.1.1
lease_time (uint32): 0x15180                  # 0x15180 = 86400 seconds = 24 hours
subnet_mask (ip): 255.255.255.0
router (ip_mult): {192.168.1.1}               # your default gateway
domain_name_server (ip_mult): {192.168.1.1}   # your DNS server

Your output will differ. In the first command, the gateway you met in chapter 5 appears with its MAC address, which is ARP's work. In the second, you can see every field of the lease: address, mask, gateway, DNS server and lease time. Try ping -c 3 192.168.1.1 (on Windows ping 192.168.1.1) and run arp -a again: ping uses ICMP, and the first packet makes ARP fill in a cache entry.

Distributed systems connection

DHCP's lease is a pattern you'll see again and again in distributed systems: instead of granting something forever, a server grants it for a limited time, and the holder must renew it. If the holder crashes or gets cut off, the lease expires on its own and the resource is reclaimed, with no need to know whether the holder is really dead. Distributed locks, leader election and cluster membership use the same trick (chapters 16 and 20). ARP and DHCP also show another theme: even finding a neighbour needs a protocol.

Key takeaways

  • ARP turns a next-hop IP address into a MAC address by broadcasting a question on the LAN, then caching the answer.
  • DHCP gives a joining device its IP address, mask, gateway and DNS server via Discover, Offer, Request, Acknowledge (DORA).
  • DHCP addresses are leases that expire unless renewed.
  • ICMP carries network error and diagnostic messages: echo (ping), destination unreachable, and time exceeded (traceroute).
  • ARP and DHCP rely on broadcast, so they only work within a single local network.

Check your understanding

Your laptop wants to send a packet to a web server far away. Which MAC address does it ARP for?

  1. The web server's
  2. The default gateway's
  3. The DNS server's
  4. Nobody's: ARP isn't needed
MAC addresses only matter for the next hop on the local network. For a destination outside the LAN, the next hop is the default gateway, so that's the MAC the laptop needs.

Why does a brand-new laptop send its first DHCP message as a broadcast?

  1. Broadcasts are faster
  2. DHCP requires encryption
  3. To avoid using the router
  4. It has no IP address yet and doesn't know any server's address, so it asks everyone
With no address and no knowledge of the network, the laptop can only shout to the whole LAN and hope a DHCP server hears it.

What happens to a DHCP lease when the device vanishes and never renews it?

  1. It expires and the address returns to the pool
  2. The address is reserved forever
  3. The router crashes
  4. The ISP is notified
Leases are time-limited on purpose. If nobody renews, the server reclaims the address automatically, with no need to detect that the device left.

You ping a server and get no reply. What can you conclude?

  1. The server is definitely down
  2. The Internet is down
  3. Nothing for certain: the server may be down, or ICMP may be blocked or rate-limited somewhere
  4. Your DHCP lease expired
ICMP is a diagnostic hint. Firewalls often drop echo requests, and a lost reply isn't retransmitted. Silence is evidence, not proof.
