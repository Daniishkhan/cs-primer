IP Addresses & Subnets

An IP address is the postal address of a computer on the Internet. In this chapter you'll learn to read one in binary, carve networks out of address space with masks and slashes like /24, understand why your home devices all appear to the world as a single address, and see why the world is slowly moving to a much bigger address format.

Why this matters

Almost everything you configure or debug in networking involves IP addresses: firewall rules, cloud networks, container clusters, "why can't machine A reach machine B?". The subnet notation (10.0.0.0/16) is the language of cloud engineers, and NAT is the reason your home and your phone can reach the Internet at all. If you can do the binary arithmetic in this chapter by hand, a huge amount of jargon stops being scary.

Why a second kind of address?

In chapter 2 you met MAC addresses, which name a network card. Why do we need a different address at all? Why not route the whole Internet by MAC address?

Because MAC addresses are flat. They're assigned by manufacturers with no regard for where the device ends up. The MAC address of your laptop tells nobody in which country, city or building it is. A device that wanted to deliver a frame to a particular MAC address anywhere on Earth would need a table with an entry for every network card in existence, billions of rows, updated constantly as devices move.

IP addresses are hierarchical, like postal addresses. A street address is organised as country, then city, then street, then house number. A sorting office in Germany doesn't need to know every house in Brazil; it only needs "anything for Brazil goes on that plane". In the same way, an IP address has a network part (which "street") and a host part (which "house"). A router can forward a packet using the network part alone, and a single routing entry can stand for millions of addresses.

This also explains an important rule you saw in chapter 3: an IP address is tied to where you are attached to the network. Move your laptop from home to a café and it gets a different IP address; the MAC address stays the same.

IPv4 addresses in binary

The version of IP used almost everywhere for the first forty years is IPv4. An IPv4 address is 32 bits long, 4 bytes. Writing 32 bits is awkward, so we split them into four 8-bit groups called octets and write each octet as a decimal number from 0 to 255, separated by dots. This is the familiar dotted-quad notation.

Take 192.168.1.20. Using the place-value skill from chapter 1, convert each octet to binary:

So 192.168.1.20 is the 32-bit number 11000000.10101000.00000001.00010100. The dots are for human eyes only; the computer just sees 32 bits. To convert back, add up the place values of each octet's 1s.

Since each octet has 8 bits, the biggest is 11111111 = 255, so 192.168.1.256 or 300.1.1.1 are not valid addresses. And the total number of IPv4 addresses is 232 = 4,294,967,296, about 4.3 billion. Remember that number; it's going to cause trouble later in the chapter.

Network part and host part

Every IPv4 address is split into two parts by a boundary somewhere in the 32 bits. The bits to the left of the boundary identify the network and are the same for every device in that network. The bits to the right identify the individual host within it. The boundary is described by a subnet mask: a 32-bit number with 1s wherever the address bit belongs to the network part, and 0s for the host part.

Masks are always a block of 1s followed by a block of 0s, so we can describe one just by counting its 1s. That's CIDR notation (Classless Inter-Domain Routing, pronounced "cider"): write a slash and the number of network bits after the address. 192.168.1.20/24 means "this address, whose first 24 bits are the network part". The mask 255.255.255.0 and the prefix /24 say exactly the same thing. The number after the slash is called the prefix length.

History: why "classless"?

The original 1981 design fixed the boundary by the first few bits of the address: "Class A" networks had an 8-bit network part, "Class B" 16, "Class C" 24. That was too rigid: a company needing 300 addresses was too big for a Class C (254 hosts) and got a Class B with 65,000 addresses, wasting most of them. In 1993 CIDR let the boundary sit at any bit, which made allocation far more efficient and slowed the address shortage. You'll still hear "Class C" used loosely to mean "a /24".

Counting addresses in a network

If the host part is h bits long (that's 32 minus the prefix length n), the network contains 2h = 232−n addresses. Two of them are special:

  • The network address: all host bits 0. It names the network itself (like "Oak Street" rather than a particular house) and can't be given to a device.
  • The broadcast address: all host bits 1. A packet sent there is delivered to every host in the network. It can't be given to a device either.

So the number of usable host addresses is 232−n − 2. Here are the sizes you will meet most:

Worked example 1: a /26

What network does 10.1.77.130/26 belong to? Let's go step by step.

  1. Prefix: /26 means 26 network bits: the first three octets (24 bits) plus the top 2 bits of the last octet. The mask's last octet is 11000000 = 128 + 64 = 192, so the mask is 255.255.255.192.
  2. Block size: 6 host bits means 26 = 64 addresses per network, so the networks in the last octet start at 0, 64, 128, 192.
  3. Which block holds 130? 128 ≤ 130 < 192. So the network address is 10.1.77.128.
  4. Broadcast: the last address of the block, 128 + 63 = 191: 10.1.77.191.
  5. Usable hosts: 10.1.77.129 through 10.1.77.190, which is 62 addresses (64 − 2).

Check it in binary: 130 is 10000010; the mask is 11000000; the AND is 10000000 = 128 ✓. Setting all six host bits to 1 gives 10111111 = 191 ✓.

Worked example 2: when the boundary isn't in the last octet

What are the first and last addresses in 172.16.45.9/20?

  1. A /20 has 20 network bits: the first two octets (16 bits) plus the top 4 bits of the third. The third octet of the mask is 11110000 = 240, so the mask is 255.255.240.0.
  2. The 12 host bits mean 212 = 4,096 addresses. In the third octet the block size is 16 (the 4 host bits there are worth 0–15), so blocks start at 0, 16, 32, 48, …
  3. The third octet is 45, which lies in the block starting at 32 (32 ≤ 45 < 48). Network address: 172.16.32.0.
  4. Broadcast: the third octet runs up to 47 and the last octet to 255: 172.16.47.255.
  5. Usable hosts: 172.16.32.1 to 172.16.47.254, which is 4,096 − 2 = 4,094.

"Is this address in my network?" (AND)

Here's the most important thing a computer does with a subnet mask. Before sending a packet, your computer must decide: is the destination on my own LAN (deliver directly using ARP and Ethernet), or is it elsewhere (hand it to the router)? It answers with the bitwise AND operation: line up two bit strings and, for each position, output 1 only if both bits are 1. ANDing an address with the mask keeps the network bits and zeros out the host bits.

Suppose you are 192.168.1.20/24. Your network address is the AND of your address and the mask:

  192.168.1.20   = 11000000.10101000.00000001.00010100
  255.255.255.0  = 11111111.11111111.11111111.00000000
  AND            = 11000000.10101000.00000001.00000000  = 192.168.1.0

To test a destination, AND it with your mask and compare with your own network address:

The three private ranges are the key to home and data center networking. Because they are never routed on the public Internet, thousands of organisations can use 192.168.1.0/24 at the same time without clashing. The cost is that a device with a private address cannot be reached directly from outside, and its packets need translating on the way out. That's NAT.

Running out of addresses

In 1981 4.3 billion addresses looked like plenty. But every phone, laptop, TV, server and light bulb that connects needs one, and addresses were handed out unevenly. By 2011 the central pool of unallocated IPv4 blocks had run out, and the regional registries that hand addresses to providers have since exhausted their own supplies too (the details differ by region). Today IPv4 addresses are bought and sold, and a single address costs real money.

There are two answers. The long-term answer is IPv6, which has a vastly larger address space (see below). The practical answer that kept the Internet running for decades is to share: use private addresses inside, and let many devices take turns using one public address. That trick is NAT.

NAT: one public address, many devices

NAT (Network Address Translation) happens in your home router. Inside your home, every device has a private address like 192.168.1.20. The router has one public address on the Internet side (for our examples, 198.51.100.7). When a device sends something to the Internet, the router rewrites the packet's source address to its own public one. When the reply comes back, it rewrites the destination back again. To everyone outside, your whole household looks like a single computer.

But there's a puzzle. If two devices in your house both contact the same server, the replies all come back addressed to 198.51.100.7. How does the router know which device each reply is for? The answer: it also rewrites the source port (chapter 7 explains ports properly; for now, a port is a number that says which program on a computer a connection belongs to). Each outgoing connection is given a unique public-side port, and the router remembers the pairing in a NAT table. This flavour is sometimes called PAT or NAPT, but everyone just says NAT.

Walk through the laptop's request step by step:

  1. The laptop sends a packet from 192.168.1.20:51514 to the server 203.0.113.10:443.
  2. The router creates a table entry mapping that private pair to a free public port, here 198.51.100.7:40001. It rewrites the packet's source and recalculates the checksums, then forwards it.
  3. The server replies to 198.51.100.7:40001. It never sees 192.168.1.20.
  4. The router receives the reply, finds the entry for port 40001, rewrites the destination to 192.168.1.20:51514 and delivers it to the laptop.
  5. If the connection goes quiet for a while, the entry times out and is deleted to free the port.

Analogy: the office switchboard

A company has one public phone number but hundreds of staff with internal extensions. When someone calls out, the switchboard dials using the company's number, and notes "this outside call belongs to extension 214". When that outside party replies, the switchboard knows to route it to extension 214. Outsiders only ever see the one company number.

Where it breaks down: a switchboard can also be asked to ring extension 214 from outside; a NAT router has no idea which device an unsolicited incoming packet is for, as we discuss next.

Why inbound connections don't "just work"

NAT entries are created only when something inside sends traffic out. If a stranger on the Internet sends a packet to 198.51.100.7:8080 out of the blue, the table has no matching entry and the router has no idea which of your devices (if any) it is meant for, so it drops it. This is why you can browse any site from your home network, but can't run a web server on your laptop and have the world reach it.

The usual remedy is port forwarding: an administrator adds a permanent rule to the router such as "traffic arriving on public port 8080 goes to 192.168.1.50 port 80". Games, video-call apps and peer-to-peer software use cleverer tricks (like asking an outside helper server what public address and port the NAT assigned, then trying to connect from both sides simultaneously) to get through NAT without manual setup.

Common misconception: "NAT is a firewall, so I'm secure"

Because NAT drops unsolicited inbound packets, it incidentally blocks many attacks, but it was designed to conserve addresses, not to provide security. It does not inspect or limit what your devices send outward, and it does nothing about malware you download yourself. A real firewall is a separate concept. Equally, a private address isn't an "encrypted" or "hidden" address.

NAT has real costs. It breaks the original Internet idea that any machine can contact any other (the "end-to-end principle" from chapter 3), it complicates protocols that carry addresses inside their data, it needs per-connection state in the router, and each public address can only support a finite number of simultaneous connections (a port is a 16-bit number, so there are only up to about 65,000 to hand out). ISPs facing a shortage of addresses even put a second layer of NAT in their own network, called carrier-grade NAT (CGNAT), using the 100.64.0.0/10 block. If your router's "public" address starts with 100.64 to 100.127, you are behind one too, and you can't accept inbound connections even with port forwarding.

Go deeper: NAT breaks the layering rules optional

In chapter 3 we said each layer only reads its own header. A NAT device must edit the network layer (IP addresses) and the transport layer (port numbers), and then fix the TCP/UDP checksums, which include the IP addresses in their calculation. That is exactly the "layers aren't perfectly sealed" warning from chapter 3. It works, but it makes the Internet less transparent, which is one of the motivations for IPv6.

IPv6: the long-term fix

IPv6 was designed in the 1990s to solve the shortage for good. Its addresses are 128 bits long, so there are 2128 of them, roughly 3.4 × 1038, an unimaginably large number (enough to give every grain of sand on Earth its own enormous block). Writing 128 bits in dotted decimal would be hopeless, so IPv6 uses hexadecimal (chapter 1): eight groups of four hex digits, separated by colons.

2001:0db8:0000:0000:0000:ff00:0042:8329

Two shortening rules make this bearable. First, leading zeros inside a group can be dropped. Second, one run of all-zero groups can be replaced by :: (only once per address, otherwise it'd be ambiguous). The address above shortens to:

2001:db8::ff00:42:8329

The prefix idea works exactly as before: 2001:db8::/32 is a block (and happens to be the IPv6 documentation range). Typically a home gets a /56 or /64 from its provider, and a single LAN subnet is a /64, leaving 64 bits for hosts. A few special ones: ::1 is loopback (like 127.0.0.1) and fe80::/10 is link-local.

Why hasn't everyone switched? Because IPv4 and IPv6 are not compatible: a device with only an IPv4 address can't talk directly to one with only IPv6. Every operating system, router, firewall, monitoring tool and application must be able to handle both, and the benefit to any single organisation of switching early is small, since NAT keeps their IPv4 working. So the world is in a long transition where most networks run both side by side ("dual stack"), IPv6 traffic grows steadily, and IPv4 isn't going away any time soon. Large cloud and mobile networks have moved furthest.

The IP header

Every IP packet starts with a header. Following chapter 3's picture, this is the green envelope. IPv4's header is at least 20 bytes; here it is, 32 bits per row:

IHL4 bits
DSCP / ECN8 bits
Total length16 bits
Identification16 bits
Flags3 bits
Fragment offset13 bits
TTL8 bits
Protocol8 bits
Header checksum16 bits
Source IP address32 bits
Destination IP address32 bits
Options (rare) + the payload follows: a TCP segment, UDP datagram, …0 or more bytes
Version
4 for IPv4 (6 for IPv6, which has a different header).
IHL
Header length in 4-byte words, normally 5 (= 20 bytes), larger if options are present.
Total length
Size of the whole packet, header plus data, in bytes. The 16-bit field limits a packet to 65,535 bytes, though in practice they're capped by the link's MTU (1,500 on Ethernet).
Identification, flags, fragment offset
Used when a packet is too big and has to be split ("fragmented") and put back together. See the chapter 3 "go deeper" box.
TTL
Time to live: a counter that every router decrements by one. When it reaches 0 the packet is discarded. This prevents a packet from circling forever if routers are misconfigured. Typical starting values are 64 or 128. It's also how traceroute works (chapter 5).
Protocol
Which transport protocol is inside, so the receiver knows where to hand the payload: 6 = TCP, 17 = UDP, 1 = ICMP (chapter 6).
Header checksum
A checksum over the header only (chapter 1's idea). It must be recomputed at every router because TTL changes at each hop.
Source / Destination
The two 32-bit addresses this chapter is about. Routers look at the destination; the receiver replies to the source.

Try it yourself

Your private address versus your public address

Find the IP address your computer uses on your LAN, then the one the outside world sees. If they're different, you've just observed NAT at work.

$ ipconfig getifaddr en0             # macOS: your private address (Wi-Fi is usually en0)
192.168.1.20

$ curl -s https://ifconfig.me          # asks a website "what address did my request come from?"
198.51.100.7

$ curl -4 icanhazip.com                # another site that does the same, forcing IPv4
198.51.100.7

On Windows run ipconfig and read the "IPv4 Address" line; on Linux use ip -4 addr or hostname -I. (The addresses shown here are examples; yours will differ. If a command is missing or you're offline, you'll see an error rather than an address.)

The two answers differ because the first is your device's private address inside the LAN, and the second is your router's public address (or your provider's, if CGNAT is involved), the one the website saw after NAT rewrote your source address. Try running the second command from your phone on mobile data and from a friend's house: you'll get different public addresses even though your laptop's private address stayed the same. Also try ifconfig en0 | grep inet and use the calculator above to work out the network address and broadcast address of your own subnet from the netmask it shows. (Netmasks there are shown in hex, so 0xffffff00 means 255.255.255.0, i.e. /24.)

Distributed systems connection

Every service in a distributed system is ultimately found by an IP address and a port (10.0.3.17:8080). Cloud platforms hand you a private network (a "VPC") carved from a block like 10.0.0.0/16, which you then split into subnets (10.0.1.0/24 for web servers, 10.0.2.0/24 for databases), using exactly the arithmetic from this chapter. Choosing these blocks well matters: if two networks you later want to connect use overlapping ranges, they can't be joined without painful renumbering.

Inside the private network, servers talk freely; to the outside they go through NAT gateways (outbound) or load balancers (inbound, chapter 14), so the same NAT concepts reappear at data-center scale. And because machines are constantly created and destroyed, an IP address is a poor permanent name for a service: a replacement server gets a new address. That's why we use names (DNS, chapter 9) and service discovery: a layer of indirection that lets the address behind a name change without breaking anyone.

Key takeaways

  • MAC addresses are flat; IP addresses are hierarchical (network part + host part), so routers can summarise millions of addresses in one entry.
  • An IPv4 address is 32 bits, written as four decimal octets. Converting between binary and decimal uses place values (128, 64, 32, 16, 8, 4, 2, 1).
  • The subnet mask (or CIDR prefix like /24) marks the network bits. A /n network has 232−n addresses, of which 2 (network and broadcast) are not usable by hosts.
  • To test "same network?", AND the address with the mask and compare network addresses. Same: deliver locally. Different: send to the router.
  • Private ranges (10/8, 172.16/12, 192.168/16), loopback 127.0.0.1, link-local 169.254/16 and documentation ranges have special roles.
  • IPv4 has only ~4.3 billion addresses. NAT lets a router share one public address among many private devices by rewriting source address and port and keeping a translation table; it blocks unsolicited inbound traffic unless you port-forward.
  • IPv6 uses 128-bit hex addresses (with :: shortening). Adoption is gradual because it isn't compatible with IPv4.
  • The IP header carries version, length, TTL, protocol, checksum, source and destination.

Check your understanding

How many usable host addresses does a /26 network have?

  1. 64
  2. 26
  3. 62
  4. 126
A /26 leaves 32 − 26 = 6 host bits, so 26 = 64 addresses. Two (the network and broadcast addresses) can't be given to hosts, leaving 62. 126 would be a /25.

A computer at 192.168.1.20/24 wants to send a packet to 192.168.2.5. What does it do?

  1. Sends it to the router (default gateway), because 192.168.2.5 is in a different network
  2. Sends it directly to 192.168.2.5's MAC address
  3. Broadcasts it to the whole LAN
  4. Drops it, because 192.168.x.x addresses can't talk to each other
192.168.2.5 AND 255.255.255.0 = 192.168.2.0, which is not 192.168.1.0, so the destination is off-link. The computer addresses the frame to the router's MAC, and the router carries on from there.

What are the network and broadcast addresses of 172.16.45.9/20?

  1. 172.16.45.0 and 172.16.45.255
  2. 172.16.0.0 and 172.16.255.255
  3. 172.16.40.0 and 172.16.47.255
  4. 172.16.32.0 and 172.16.47.255
A /20 has blocks of 16 in the third octet. 45 falls in the block 32–47, so the network address is 172.16.32.0 and the broadcast address (all host bits 1) is 172.16.47.255. Blocks start at multiples of 16, so 40 can't be a boundary.

Your laptop and phone both open connections to the same website from behind one home router. How does the router tell the replies apart?

  1. By the MAC address in the reply
  2. By the public-side port number it assigned to each connection in its NAT table
  3. By the website sending a different IP address to each device
  4. It can't; one of the devices will lose its connection
The router rewrites each outgoing connection's source port to a unique value and remembers the mapping. Replies arrive addressed to that port, so the table says which private address and port to restore. The MAC addresses on the Internet side are for the router's own link and say nothing about your devices.

Why can't someone on the Internet simply connect to a web server running on your laptop at home?

  1. Because laptops can't run servers
  2. Because the laptop's MAC address is secret
  3. Because your router's NAT has no table entry for unsolicited incoming traffic, and the laptop's private address isn't routable on the Internet
  4. Because TTL expires before the packet arrives
NAT entries are created by outbound traffic. An unsolicited packet matches no entry, so the router drops it. Fixing this means port forwarding (or a relay service). The laptop is perfectly capable of being a server.

Which is a valid way to abbreviate the IPv6 address 2001:0db8:0000:0000:0000:0000:0000:0001?

  1. 2001:db8:1
  2. 2001:db8::1
  3. 2001::db8::1
  4. 2001:db8:0:1
Drop leading zeros in each group and replace one run of all-zero groups with ::. Using :: twice (option 3) is ambiguous and not allowed, and options 1 and 4 have too few groups to be complete without a ::.
