Plan-then-execute fixes the steps from the user's request alone, before any outside text is read, so an attacker's text cannot add a step. Ordinary code then moves strings between steps, and each value carries labels saying where it came from: untrusted if outside text influenced it, private if the vault did.

check_flow(to, body) is the policy. Refuse when the recipient is labelled untrusted, since an address pulled from a document is the attacker's choice even if it looks harmless. Refuse when the body is private and the recipient is not in ALLOWED_RECIPIENTS (compare in lower case). execute_plan interprets the steps: an argument starting with $ names an earlier step's output, anything else is a literal the trusted planner wrote. Labels are inherited, so join, summarise and extract_sender give their output the OR of their inputs' labels. Forgetting that launders private data into a clean-looking string.

v = search_vault(...)     private
s = summarise($v)         still private
send_email(to "x@example.org", body $s) -> refused: private body, outside
