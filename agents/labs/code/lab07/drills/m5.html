Plan-then-execute fixes the steps from the user's request alone, before any outside text is read, so an attacker's text cannot add a step. Ordinary code then moves strings between steps, and each value carries labels saying where it came from: untrusted if outside text influenced it, private if the vault did.

check_flow(to, body) refuses a recipient labelled untrusted: an address pulled from a document is the attacker's choice, even if it looks harmless. It also refuses a private body for any recipient not in ALLOWED_RECIPIENTS (compare in lower case). In execute_plan, an argument starting with $ names an earlier step's output, and anything else is a literal written into the plan from the user's own request. Labels are inherited: join, summarise and extract_sender give their output the OR of their inputs' labels. Forgetting that launders private data into a clean-looking string.

v = search_vault(...)     private
s = summarise($v)         still private
send_email(to "x@example.org", body $s) -> refused: private body, outside
