A permission rule is code that runs before a tool call, so unlike a filter or a prompt it does not rely on the model behaving. The rule of two lets one session use at most two of three risky legs, reading outside text, reaching private data and sending data out, because all three together are the recipe for data theft.

Keep the set of legs used so far, taken from TOOL_CLASS (a tool outside it has no leg). reset empties it at the start of every run, so nothing leaks from one task to the next, and observe records the leg of a call that has actually run. permit returns (False, reason) if this call would put all three legs in play, in whatever order they arrive, else (True, ""). It must not change state: asking is not doing, and a refused call would otherwise lock the policy.
