A permission rule is code that runs before a tool call, so unlike the defences so far it does not rely on the model behaving. The rule of two lets one session use at most two of three risky legs: reading text from outside, reaching private data and sending data out. All three together is the recipe for data theft.

Keep the set of legs used so far, taken from TOOL_CLASS. reset empties it at the start of every run. observe records the leg of a call that has actually run. permit returns (False, reason) if running this call would put all three legs in play, else (True, ""). Order does not matter: the call refused is whichever one would be the third leg. permit must not change state, because asking is not doing and a refused call would otherwise lock the policy. A tool outside TOOL_CLASS has no leg.
