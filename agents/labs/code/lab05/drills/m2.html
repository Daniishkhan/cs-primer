A restarted process has only the journal, so the next move must be a pure function of the events: one that depends on nothing else, so it is easy to test. A retried action also needs the same name every time, an idempotency key: a string that lets a service recognise a repeat and not act twice.

next_step(log) asks the model when nothing is pending, runs the calls of the last reply that have no result yet, and finishes when that reply asks for none. The trap: the same call, with the same id, can be made in two turns, as with two identical refunds, so a result counts only if it comes after the reply that asked for it. The key must be computable from the journal alone: no randomness, clocks or in-memory counters. In run_id:seq:tool_use_id each part keeps something apart: runs, turns, calls in one reply.
