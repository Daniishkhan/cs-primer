A journal is a file of events, one per line, only ever appended to, and after a restart it is all the agent has. Only the facts are stored; the message list is derived from them, so no second copy can disagree.

append writes one line as JSON, flushes, and calls os.fsync so the event is on the disk, not only in an operating-system buffer. A crash can leave a torn write: half a line with no newline. load treats a last line with no newline as never written, and append cuts that stump off first, or the new event glues onto it; a bad line before the last is real damage, so load raises CorruptJournal. rebuild(task, log) folds events into messages: the task, then each model event as an assistant message, with the result events after it gathered into one user message built with tool_result, in order. Other event types are skipped.

task, model(call a, call b), result a, result b, model(text)
-> user, assistant, user [result a, result b], assistant
