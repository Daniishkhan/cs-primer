The durable loop is the ordinary agent loop with one change: it keeps nothing in variables between iterations. Each pass loads the journal, asks for the next step, does one kind of work and appends what happened, so a restarted process picks up exactly where the last one died.

For run_tools, take each pending call in order, compute its key, call tools[name](input, key) and append the result. A ToolError or an unknown name becomes an error result the model can read. Any other exception, a Crash included, must propagate: swallowing it would turn a dead process into a live one in a state it cannot trust. For ask_model, raise BudgetExceeded if the journal already holds max_calls model events: count in the journal, because a local counter resets when the process dies. Call the module-level append and load: the checker swaps in versions that crash on purpose.
