A connection starts with a short negotiation: the client names the protocol version it wants and what it can do, the server answers with the version it will use and what it offers, and the client confirms with a notification. Until then the server serves almost nothing.

on_initialize checks its parameters (a bad one is -32602 and changes no state), moves the state to "initialising" and answers. Negotiation is a counter-offer, not a refusal: a version the server speaks (LEGACY_VERSIONS) is echoed back, any other gets the newest, so compare version strings for equality. on_notification completes the handshake only for notifications/initialized after a good initialize, and ignores every other notification. process is the gate: ping always works, nothing else but initialize works before the handshake is complete, and a second initialize is -32600.

tools/list before the handshake        -> -32600
initialize asking for "latest"         -> answered with the newest version
initialize, initialized notification   -> state ready, tools/list works
