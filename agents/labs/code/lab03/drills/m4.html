A resource is a piece of data with its own address, such as a file, a record or a schema, that the application, not the model, chooses to put in context. Errors split as with tools: a malformed request is a protocol error, and a well-formed address that names nothing is "resource not found".

The address is a URI. list_resources returns one descriptor per order, in ORDERS order, with uri, name, title and mimeType. read_resource returns contents whose text comes from describe_order, the text the tool also returns, so the two always agree. A missing or non-string uri is -32602, while a string that names no order, such as nothing after order://, is -32002 with data holding the uri, so the client can say which one. Whatever mistake arrives, every reply carries exactly one of result and error.

order://A-1002 -> contents: "A-1002: processing, 1999 cents, carrier none yet"
order://Z-9    -> error -32002, data {"uri": "order://Z-9"}
