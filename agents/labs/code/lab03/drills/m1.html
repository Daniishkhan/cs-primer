A pipe carries messages one per line, so a server must turn every line, however broken, into at most one reply line and never crash. Three kinds of message exist: a request (method and id) gets exactly one reply with the same id, a notification (method, no id) gets none, even for an error, and a response answers something you sent, so it gets none.

handle_line reads each line with parse_line and classify, then hands it to process or on_notification. A line that is not JSON is -32700 with a null id. JSON that is not one valid message is -32600, with the id if it can be read. An RpcError keeps its code, and any other exception becomes -32603 with a fixed message: the exception text goes to stderr, never to the client. encode must give a single line, and serve must flush (push buffered output out) after every reply, or the client waits for ever.

in   {"jsonrpc":"2.0","id":1,"method":"ping"}
out  {"jsonrpc":"2.0","id":1,"result":{}}
