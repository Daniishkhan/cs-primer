A tool is a function the model can ask for, and the part that needs care is that its errors have two readers: a protocol error goes to the client program, which has a bug, and a tool execution error goes to the model, which can read the text and try again.

Ask of each failure: could a model have avoided it by choosing differently? If not, it is a protocol fault, so raise an RpcError (-32602), as for an unknown tool. If the model could fix it on its next turn, return a normal result with isError true and a message saying how. Arguments that fail the given check_arguments go this way, and so does a ToolError, whose text passes through verbatim. Look tools up in TOOL_FUNCS when the call arrives, and make list_tools sort by name without handing out TOOLS itself.

order_lookup {"order_id": "1001"}  -> result, isError true (bad pattern)
refund_everything {}               -> error -32602 (unknown tool)
