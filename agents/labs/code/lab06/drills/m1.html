A planner turns a question into short queries that can be searched independently, and its reply is untrusted input, like a form field. Asked for a list, a model sends a bare list, one wrapped in a markdown code fence, a friendly sentence, duplicates, numbers among the strings, or nothing, so you parse, do not trust, and always end with a usable answer.

parse_json_list(reply) returns the list from a bare reply or from inside a fence, with or without the word json, and None for anything else: prose, an object, a truncated list, an empty string. It never raises. plan sends one user message, plan_prompt(question), and cleans the list: keep non-empty strings, stripped, drop duplicates that differ only in case or spacing (keeping the first spelling), keep the order and cap the count at max_queries. If nothing usable is left, search the stripped question itself.

["Pothole repairs", "pothole  repairs", 7, ""]  ->  ["Pothole repairs"]
prose, [] or only junk                           ->  [the question itself]
