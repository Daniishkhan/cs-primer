The final stage of a research pipeline turns a draft into a report a reader can trust and audit. A sentence that fails the audit is dropped, never repaired, because asking the writer to fix it invites a better-sounding invention, and disagreement between sources is stated, not smoothed.

assemble runs audit_draft, keeps the sentences that pass (the rest go in Report.dropped), and turns each run of claim markers such as [c1][c5] into source numbers such as [1][2]. Number sources by first use across the report, each document once per run, ascending within a run. Then it lays out the blocks exactly as the docstring shows, skipping any that would be empty. research wires the stages in order. One decision is easy to miss: filter out outdated claims before the writer sees them, because the audit cannot catch a claim that is real but out of date.
