Searching is cheap and reading is expensive, so a research agent searches widely at once, merges the hits into one relevance per document, and triages: it decides which few documents are worth opening.

search_all runs the searches on a pool of worker threads, so their waits overlap. It returns one result list per query, in query order whichever finishes first; a search that raises gives [] for its query and the others still count. Scores from different queries are not on a common scale, so merge divides each query's scores by that query's best, then keeps the highest value each document got. triage computes value = relevance x (0.5 + prior / 2), with the prior, a trust weight for the kind of source, from PRIOR[kind], keeps values reaching the threshold, reads the best max_docs, and returns both lists in natural_key order.
