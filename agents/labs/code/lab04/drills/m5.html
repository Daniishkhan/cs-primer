In orchestrator-workers a planning call decides the subtasks, a worker call handles each and a final call combines them. A model now chooses the number of workers, so cost is partly out of your hands, and limits in code, not advice in a prompt, keep it bounded.

check_budget runs before every call and raises BudgetExceeded with "calls", "tokens" or "usd", in that order, if the calls so far have already reached a limit that is set. So a token or dollar limit can be overshot by one call, but a call limit is exact. plan is one call on the large model tier whose reply must be a JSON list, else []. In orchestrate only the first max_subtasks subtasks run, and a worker the budget refuses is dropped while the others carry on. The answer must say what it left out: a summary that covers three of five subtasks reads like a summary of all five.
