A chain does a task in fixed steps, each model call working on the previous output, with a gate between steps: a check in plain code that decides whether to continue. A gate cannot make a step more accurate, but it turns a silent wrong answer into a loud, cheap one.

chain makes its calls with meter.ask, runs the five steps in its docstring and sends exactly what they say, so token counts are reproducible; a failed gate 1 means no later model call. For chain_outcomes, each step is independent: right with probability p_step, and if wrong, a gate catches it with probability catch, which stops the chain loudly, otherwise the chain goes on. "Correct" means every step was right, "detected" that a gate stopped the chain, "silent" that it finished with a wrong output inside. The three sum to 1.

p 0.9, 5 steps, no gates:   correct 0.590, silent 0.410
same chain, a perfect gate: correct 0.590, detected 0.410, silent 0
