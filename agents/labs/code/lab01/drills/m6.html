A text-only model cannot send structured tool calls, so it writes lines of text instead: its reasoning, then the tool to call and the arguments to give it. An adapter translates between that text and the tool-calling format, so the same loop, guards, validation and tracing work unchanged.

The lines are Thought: then Action: tool {json} (the arguments as one JSON object), or Final Answer: when done. parse_react(reply) turns one reply into a dict and never raises. It first cuts the reply at the first line starting Observation:, because anything after that is the model inventing what the tool would say; your code supplies the real one. to_transcript(messages) goes the other way and renders the history as text. ReActModel.complete builds the prompt, calls self.inner with react_system (already written), parses the reply and, on a format error, shows the model its mistake and asks again a limited number of times.

Action: get_order {"order_id": "A-1001"}
Observation: it shipped via FedEx        <- invented, cut off
parse_react -> action, tool get_order, input {"order_id": "A-1001"}
