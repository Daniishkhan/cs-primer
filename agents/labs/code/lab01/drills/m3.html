Left alone, a model may call tools forever: it cannot find the answer, or a tool keeps failing. A limit the model is asked to respect is only a request, so the code enforces limits itself, as plain bookkeeping that never calls a model or a tool.

The guard watches four numbers. Input tokens matter because every model call re-sends the whole history, so call 20 costs far more than call 2. Seconds matter because the user may give up first. Iterations (model calls so far) are the simple backstop, and the same tool with the same input again means the model is stuck. after_model_call records a finished call, before_model_call returns None or one reason to stop, and check_calls counts requests in self.seen, keyed by tool name plus input as JSON with sorted keys, so reordered keys cannot hide a repeat.

max_iterations=3: the 4th model call is refused
max_input_tokens=100: 100 used is fine, 101 stops the next call
max_repeats=2: the same call a 3rd time gives "repeated_call"
