When a run goes wrong, a record of what happened is the fastest way to diagnose it: the loop writes one event, a plain dictionary a program can count, per model call, per tool call and at the end. A summary turns the events into the few numbers you read first.

summarise(events) returns a dict with exactly the keys in its docstring, and the loop that writes the events is already in the file. The definition to get right is wasted_calls: a tool call that errored, or that repeats an earlier call of the same run, meaning the same tool with the same input. Each event counts once, even if it is both. Compare inputs, not ids, because a model that repeats itself gets a new id each time. Key each call by tool name plus its input as sorted JSON, as the stopping rules do.

get_order A-1OO1 (error), get_order A-1001, get_order A-1001 (again)
-> tool_calls 3, errors 1, wasted_calls 2
