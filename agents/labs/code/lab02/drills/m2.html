A model holds only what the user told it, such as an email address, and every extra call re-sends the whole conversation. Tools shaped around the user's task, not the database's tables, make the first step reachable, return only what the next step needs, and enforce safety in code, not in advice.

find_customer takes an email or a name: a miss comes back as a helpful sentence, not an exception, and two customers with one name both come back, because choosing is the model's job. account_summary joins customer, invoices and payments on the server into one small dict. issue_refund enforces the cap in Python and sends the backend an idempotency key (a token that makes repeating a request act like sending it once), built as the docstring says. Do not pre-check the amount: after a lost response the retry must still reach the backend, even if nothing is left to refund.

refund pay_88124, 4900: money moves, the reply is lost -> timeout error
same call again: same key -> "no money moved again", still one refund
