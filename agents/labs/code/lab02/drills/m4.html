One graded run is an anecdote, so every task is run several times (trials) under each design, and each run leaves one record: did it succeed, was it harmful, how did it end and what did it cost. A summary of those records is what lets two designs be compared.

run_metrics(messages) counts from the message list alone: model calls, tool calls, tool errors, tokens in tool results, and repeated calls (the same tool and input as an earlier call in the run). evaluate goes task by task in the order given, trials 0 upwards, calling run_one (already written), grade and run_metrics, and takes status and input tokens from the result. aggregate returns rates and means over all runs, a count per status, and per-task means over each task's trials in first-seen order. It raises ValueError for no records.

4 runs, 3 succeed, 1 stopped by the token budget
-> success_rate 0.75, statuses {"done": 3, "token_budget": 1}
